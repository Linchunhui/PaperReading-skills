# 从论文集合到专题报告

专题知识体系负责范围、取舍、跨论文关系与最终交付。论文理解 Agent 负责单篇、固定版本的结构化事实和定位。PaperStudio 系列串讲提供已有讲解与跨篇比较的组织方式。按下面的六步推进。

| 环节 | 操作与交接 |
| --- | --- |
| 01 范围与输入 | 明确研究问题、截至日期、纳入与排除规则、检索预算。盘点人工选篇、论文库、关系网、结构化记录、PDF 和旧串讲。人工指定的必读论文保留标记；若缺原文则写明待核。建立初始问题覆盖表，允许后续根据证据调整分类。 |
| 02 发现候选 | 先复用已有资料填覆盖表。获准联网时，让 GPT Researcher 针对缺口补经典、近期、竞争路线、评测或反例，保留实际查询与来源 URL，再优先定位论文原文。每轮设置预算，按覆盖缺口和新增有效候选数决定是否继续。[检索与覆盖](web-research.md) |
| 03 筛选论文 | 用 DOI、无版本后缀的 arXiv ID 去重，题名、年份和作者匹配用于提示待核；保留候选来源及具体版本。先用题名与一手摘要判断是否明显超范围。相关或拿不准时，优先拿已有 PDF；用论文理解 Agent 的 PDF 准备入口提取摘要、引言与关键页，并按需渲染，跑元数据或指定页任务。按问题匹配、方法是否属于该分支、相对已有材料新增什么、证据是否可核四项，给出初步纳入／待核／排除及一句理由。 |
| 04 核对原文 | 进入正文的论文复用同版本记录，或补齐方法、结果、消融和限制对应的页／章节。作者原摘要与生成摘要分别存放。数字、归因、传承、原图须有固定版本证据；仍缺材料时回到待核。用户还要单篇完整档案时，才运行全套价值评估、深读卡与参考文献分支。 |
| 05 构建知识 | 用「共同问题 → 各方法改了哪一步 → 可比结果 → 适用边界」组织各章。旧串讲可贡献章节骨架、贯穿算例、旧基线和待复核关系；同版且可回查的证据可直接复用，版本变化或来源不明时回到原文。补入新论文、对立路线、负结果及开放问题后再写跨篇综合。 |
| 06 生成交付 | 把核验结果映射到 `topic.json`，生成 SVG 问题树、章内方法树和离线 HTML。关键论文作者原图保留图号、文件页码、版本与来源。核对锚点、引文、数字与比较条件，明确未覆盖分支和需联网的 PDF 链接。[专题输入](input.md) |

## 交接与复用规则

- **候选清单**按论文记录 `paper_id`、版本、发现来源、问题分支、纳入状态、理由、证据状态与下一步。相关性和证据状态分别判断。摘要只支持初筛；需要保留的摘要级条目放在待核线索或明确标注证据等级。人工给定集合仍受用户的来源边界约束。
- **证据记录**按 `paper_id + document_version_id` 连接 `input.json`、`page-manifest.json`、已验证阶段 JSON 或 `paper-record.json`。每项结论保留 `fact_id → evidence_id → unit_id → 文件页码/章节/表图`；图片独有信息另记图像哈希、位置和复核结果。作者陈述、综合推断、教学算例分别标记。以解析设置、范围、模型与指令指纹判断阶段缓存是否可复用；版本或范围变化时分目录。
- **送入渲染器**时，元数据填条目的题名、日期及原文入口，方法证据填 `method`、`steps`、`boundary`，核验后的实验条件和数字填 `results`，定位与出处填 `evidence`。把候选、检索轨迹和证据记录另存，维持渲染契约与研究记录各自的结构。只有明确的引用或采用关系才写为传承；并行方法、互补方案和不同约束用文字或表格解释。
- **人工复核**集中在会影响纳入或结论的冲突上，例如预印本与会议版是否同一工作、图表文本与图片不一致、论文是否真做了所称消融、结果是否可比。缺口若需要查新，带着具体问题返回第 02 步。仅有本地资料时保留缺口，直接继续核验与综合。
