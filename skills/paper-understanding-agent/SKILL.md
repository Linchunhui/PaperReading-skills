# 论文理解 Agent

给一篇 PDF 或已解析论文和期望的交付范围，按阶段提取可回查的论文信息。Agent 负责确认原文范围、选择交付和说明缺口。调度脚本负责依赖、并发、重试、缓存、校验与合并。

1. 阅读[研究任务与证据交接](references/research-workflow.md)，选择 `screen` 初筛、`evidence` 专题取证或 `full` 完整解读。先复用同版本事实，专题默认走前两种；完整解读入口保留。
2. 阅读[输入与编排契约](references/routing.md)。只有 PDF 时使用[PyMuPDF 入口](references/pdf-input.md)。保留正文、参考文献、附录与图表的原始定位；由当前会话核对草稿范围、读序、章节和摘要跨度，再标记 reviewed，不要求用户手写范围 JSON。
3. 以 `run_agent.py --mode MODE --input INPUT --manifest PLAN --plan-only` 检查范围与依赖，再加 `--out OUT` 执行。使用可用的 Codex/VPF 后端；若没有后端，在当前会话按同一证据契约完成任务，明确执行方式，不伪造 runner 收据或模型调用统计。
4. 对关键证明、设置、消融和数值缺口，使用 `read_evidence.py` 按单元、页码或标签回查。附录先索引，按理由激活；核心图表、解析异常由当前会话的视觉能力查看，核对转写后才导入。未读不等于未报告。
5. 检查 `evidence-bundle.json` 的 review_queue，结合原文及必要页面图核验关键事实，写入有指纹的 reviews，再导出交接记录。区分来源定位、数字一致性与语义支持；自动检查通过不等于科学判断正确。
6. 根据 runner-report 的 ok、outputs 和实际覆盖交付。screen/evidence 输出可复用证据；full 另输出原有 paper-record、完整阅读卡和短卡。深读与评估并行，推荐理由由评估生成、交付时合并。错误按来源重解析、视觉核对、局部重跑或待核处理；用共享缓存复用未受影响的任务。

整篇综合检查原文覆盖，后续深读与评估优先读取理解结果和证据库，必要时通过运行器的有界请求读取原文。论文事实、已核对图像转写、作者对前作的转述、外部材料与综合判断分别标记。作者原始摘要逐字保留，生成摘要另存。只有允许联网且存在具体缺口时补外部证据，优先复用专题已有基线；记录查证时间与来源类型。

## 云端打包

本包只有这个顶层技能入口。`runtime/PROFILE.md` 与 `references/specialists/*/PROFILE.md` 是完整保留的内部专业指导，由运行脚本按阶段读取，无需分别安装。
