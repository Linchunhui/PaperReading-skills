# 十维评估字典

每个维度独立输出，不取一个均分替代证据判断。抽取事实通过 field_refs 关联下列字段；生成项写入 assessment.findings。

## B1 创新实质

相对已知工作，具体新在哪里？

抽取：

- B1.contribution_claims：作者声称的贡献及贡献类型：问题、方法、机制、理论、数据/评测、组合或洞见
- B1.closest_prior_work：具体前作、发表时间、已读版本与可定位内容；区分作者转述与独立取得的材料
- B1.mechanism_differences：前作与本文的操作、假设、目标或研究对象差异；沿用部分也保留

生成：

- novelty_delta：归纳实质差异及其作用，不以“作者声称首创”代替判断
- novelty_level：创新程度与类型；注明比较范围和未覆盖工作
- novelty_label：例如：机制创新明确 / 有价值的新组合 / 增量改进 / 新意待核查

证据：本文贡献段、方法、理论或数据协议；最接近前作的原文与有范围的文献检索记录；审稿人关于新颖性的具体比较及 rebuttal（辅助意见）。

判断规则：独立较强的新颖性判断须有具体前作比较。只读本篇时最多形成有范围的初步判断；向量距离与题目冷门不作为突破证据。

## B2 问题重要性

解决的是多重要的瓶颈，能影响什么？

抽取：

- B2.target_bottleneck：目标问题、现有能力限制、受影响的研究或应用环节
- B2.importance_evidence：需求、前作限制、理论意义或实证痛点的具体依据
- B2.affected_scope：可见的任务、用户、模型与条件范围；作者声称的远期影响另记

生成：

- problem_significance：研究意义与实际用途分别说明
- impact_scope：受益对象、影响范围与成立前提
- value_label：例如：关键瓶颈 / 专门场景有价值 / 影响范围待验证

证据：引言中的问题定义与有出处的需求；相关工作暴露的限制及实际问题证据；审稿 Motivation/Impact、Significance 意见。

判断规则：问题重要不自动说明本文已解决它。记录已验证影响与潜在影响；会议、机构、热度不代替单篇的重要性证据。

## B3 实质进展

相同问题和可比条件下，前进了多少？

抽取：

- B3.result_observations：本文和基线逐任务的原值、单位、指标方向、误差与理论保证
- B3.comparison_conditions：数据版本/split、规模、训练和推理预算、硬件、精度、采样与评价协议
- B3.capability_and_tradeoffs：新增能力、失败/退步、计算和数据成本；理论工作记录假设与界

生成：

- progress_profile：逐任务/指标的改善、持平、退化、新能力和成本收益
- magnitude_and_uncertainty：条件可比才计算绝对差值或相对提升，并注明单位、分母与不确定性
- progress_label：例如：同预算显著改善 / 效率收益明确 / 结果混合 / 暂不可比

证据：主结果表、完整评测设置、效率实验与误差报告；基线原文/协议、消融与负面结果；理论定理、假设、证明；审稿人的结果与比较意见。

判断规则：Q3 的可比性和 Q2 的主张支持程度约束进展结论。“最终效果好”必须带任务与条件；统计显著需检验依据。理论、数据集与系统按贡献类型适配。

## V1 可借鉴性

可以借鉴什么，谁能用，代价多大？

抽取：

- V1.reusable_assets：具体模块、训练配方、数据方法、评测协议、理论工具或经验发现
- V1.reuse_prerequisites：接口、数据、模型、理论假设、资源、许可和迁移限制
- V1.demonstrated_reuse：论文内或外部已报告的迁移/复用证据，区别于拟议用途

生成：

- reuse_plan：目标问题、保留/替换步骤、工作量、风险和待验证事项
- transferability：一般可借鉴程度；面向具体用户的适配另行计算
- reuse_label：例如：训练策略值得借鉴 / 评测方法可复用 / 迁移成本较高

证据：方法与实现细节、开源资源和迁移实验；前提、许可、资源成本与失败案例；专家/审稿人对用途的具体意见（辅助）。

判断规则：允许“创新一般但可借鉴性强”。没有迁移实验时，目标场景和收益标记为建议或预期，不生成“迁移已验证”。

## Q1 技术正确性

方法、推导和实现是否自洽？

抽取：

- Q1.method_and_assumptions：算法步骤、变量、损失、关键假设、实现与理论命题
- Q1.reported_issues：原文可定位的矛盾、推导疑点和审稿人质疑，保留提出者身份
- Q1.responses_and_checks：作者回应、修订和独立检查的结果与范围

生成：

- technical_assessment：在已检查范围内的自洽程度和未核实风险
- issue_severity：问题是否影响核心结论；区分明确问题与待查疑点
- correctness_label：例如：已读部分自洽 / 存在核心疑点 / 已确认关键问题

证据：方法、公式、算法、证明及相关代码；具体反例、可重复检查与纠错记录；Soundness/Correctness 评审和逐项作者回应。

判断规则：“未发现错误”不是形式化证明正确。审稿质疑先记为意见；确认错误需要直接依据。核心问题不以高新颖性抵消。

## Q2 主张证据充分度

每一项核心结论由什么支持？

抽取：

- Q2.claim_evidence_links：核心主张逐条映射实验、消融、证明、分析或数据证据
- Q2.controls_and_coverage：关键设计的对照、消融覆盖、重复实验和不确定性
- Q2.missing_support：缺失支持、负面结果、作者回应补充的实验及实际可见性

生成：

- support_matrix：每条主张：充分 / 部分 / 不支持 / 有反证 / 无法判断
- critical_gaps：影响核心结论的证据缺口及补证建议
- evidence_label：例如：主要结论支持充分 / 仅有初步证据 / 关键消融待补

证据：主结果、消融、误差、统计检验或证明；核心主张与实验设计之间的对应关系；Substance 意见、rebuttal 的新增证据与后续确认。

判断规则：有实验不等于核心主张已被支持；实验数量不直接等于证据强度。作者承诺补实验与已经可查的补充结果分开。

## Q3 比较有效与公平

基线和评测能支持优势结论吗？

抽取：

- Q3.baseline_selection：最接近、具有竞争力的基线及选择理由、时间范围和遗漏
- Q3.protocol_alignment：数据/split、模型规模、训练/推理预算、调参、硬件和评价规则
- Q3.comparison_confounds：可能混杂的因素、泄漏质疑的来源及可见检查结果

生成：

- comparability：每组比较：可比 / 有条件可比 / 不可比 / 信息不足
- fairness_gaps：基线和协议缺口可能如何改变结论
- comparison_label：例如：对照充分 / 基线偏弱 / 预算未对齐 / 条件不明

证据：实验设置、基线实现、数据划分与指标定义；前作协议或代码版本、额外公平对照；Meaningful Comparison 意见及对应回应。

判断规则：无法对齐时不生成无条件领先或 SOTA。怀疑泄漏不等于确认泄漏；若未取得所需设置，标记无法判断。

## Q4 稳健性与边界

结论在哪些变化下仍然成立？

抽取：

- Q4.tested_variations：数据、领域、规模、随机种子、扰动、分布外设置和敏感性分析
- Q4.failures_and_constraints：失败案例、性能波动、适用假设与不适用范围
- Q4.scope_claims：论文声称的泛化范围与实际测试范围

生成：

- robustness_scope：在已验证范围内是否稳定，哪些边界尚无证据
- scope_gap：主张范围是否超出测试/理论覆盖
- robustness_label：例如：多设置稳定 / 仅单场景验证 / 边界明确 / 泛化待验证

证据：跨设置实验、敏感性/误差分析、失败案例；理论适用假设及局限章节；审稿关于泛化、稳健性和过度主张的意见。

判断规则：单场景不能推成广泛泛化；缺少 OOD 实验不自动等于论文质量差，依据其实际主张与论文类型判断。

## Q5 可核查与复现准备

材料是否足以理解和复现？实际验证到哪一步？

抽取：

- Q5.reported_materials：算法细节、超参、数据协议、代码/权重/数据、依赖、运行命令
- Q5.access_and_cost：访问状态、版本、许可、环境和计算成本
- Q5.verification_records：谁在何时用何配置运行、得到何结果；没有执行记录则为空

生成：

- reporting_completeness：影响理解或复现的关键缺项
- verification_level：作者声明 / 链接可访问 / 实际运行 / 独立结果核验，分项记录
- reproducibility_label：例如：复现材料较齐 / 关键细节缺失 / 已运行 / 结果已独立核验

证据：正文、已覆盖的附录与补充材料；仓库文件、数据/权重、环境说明和许可；独立执行日志、结果对照及 Replicability 意见。

判断规则：资源完整度与实际复现状态分开；未开源不单独否定科学质量。Q5 与原推荐维度⑤共用判断，避免重复加分。

## Q6 表达完整与主张克制

读者能否理解研究，结论是否准确限定？

抽取：

- Q6.definitions_and_reporting：问题定义、术语、图表、算法、评测设置与关键解释
- Q6.claim_scope_and_limits：结论措辞、假设、局限和失败结果的报告位置
- Q6.communication_issues：审稿人指出的歧义、缺少说明及作者补充解释

生成：

- clarity_and_completeness：影响科学理解的缺项，与单纯语言润色分开
- claim_calibration：结论措辞是否与证据和边界相称
- reporting_label：例如：表达清楚且边界明确 / 关键解释不足 / 结论范围偏大

证据：定义、方法说明、图表说明、结论与局限；已取得的附录/补充说明和版本变化；Clarity/Presentation 评论及澄清记录。

判断规则：语言流畅不代表科学可靠；排版、拼写问题与影响结论理解的缺项分开。不把未读取的附录写成论文未报告。

## 类型适配

- 方法/系统：效果、预算、对照、消融、成本与稳健性
- 理论：命题、假设、证明、反例与相对已有界/结论的变化
- 数据/评测：覆盖、标注质量、任务价值、划分/泄漏检查、评价协议与使用边界
- 分析/综述：研究问题、证据选择、检索/纳入范围、分析有效性、综合洞见与局限
