# 深度解读与兼容粗读

默认 JSON 的 deep_read 采用下方总结版的讲解方式，abstract 单独存放，不在 deep_read 再复制摘要。兼容 cards/summary HTML 共用一份开头摘要。关键原图、公式和消融按输入可用性保留；缺图不阻断文字交付。

## 卡片版 `cards`

使用以下六类信息卡。标题写成具体结论或清楚的问题；每卡聚焦一件事，通常用一小段或几个短要点。无需强行保持等高、相同字数或固定卡数；方法复杂时按子问题拆卡，不能挤成术语墙。

| 卡片 | 必需内容 | 紧凑表达方式 |
| --- | --- | --- |
| 背景与问题 | 实际任务、一个必要场景、具体障碍及后果 | 一句场景 + 一句卡点 |
| 前人怎么做，还差什么 | 重要解法路线、已解决部分、剩余缺口、与本文的关系 | 小表格：路线 / 做法 / 缺口 |
| 本文怎么解决 | 核心切入点；输入到输出的关键步骤；设计理由；适用时的训练与推理 | 主图 + 编号步骤 + 核心公式白话解释；可拆多卡 |
| 主结果说明什么 | 评测对象、关键对照、指标与数字、必要成本 | 结论句 + 少量数据或关键结果截图 |
| 消融带走什么 | 关键设计选择的结果、必要数字与条件 | 简短结果要点，结论先行；不使用复杂表格 |
| 边界与可借鉴点 | 适用条件、未解决问题、值得验证的动作 | 短句区分论文观察与读者假设 |

卡片主体优先展示结论，证据定位放在句末或卡尾。正文与图注各司其职：正文讲机制，图注指出该看图中哪里，不将长段正文挪到图注伪装精简。

核心方法卡应让读者不打开原文也能走通：

> 输入是什么 → 每步改变了什么 → 怎样到下一步 → 输出是什么；关键设计如何对应前作的缺口。

对训练方法补充“数据/监督从哪里来、优化什么、哪些部分训练”；对推理方法补充“运行时有什么状态、何时更新、如何输出”。只保留解释方法和结果确实需要的细节，不强塞论文没有的阶段。

## 总结版 `summary`

接近 PaperStudio 的单篇解读，以连续讲解为主。用短段落形成理解链，读完能复述方法，不要求逐段带读全文。组织为：

1. **摘要入口。** 页面与单独摘要同标准；JSON 的 deep_read 不重复已有 abstract。
2. **背景与问题。** 用一个具体场景解释任务、失败点和影响。不要在后文反复重讲背景。
3. **已有解法与缺口。** 按思路说明重要前作做了什么、在哪些条件下有效、留下什么问题，以及本文继承或改变了哪里。
4. **本文方法。** 先给输入到输出的全貌，放关键主图，再沿机制展开。每个重要环节说明对象、操作、输出和理由；必要时沿同一个例子串起训练/推理及公式。
5. **主结果。** 解释实验在检验什么、对照是谁、结果说明什么；保留会改变解释的模型/数据/计算量条件。
6. **消融与可借鉴结论。** 先给清楚的实验结论；需要比较多项设置时再用下方表格，并解释最关键、反直觉或负向的发现。
7. **适用边界与收束。** 说明代价、失败条件、尚未解决的问题。可借鉴的动作应连接论文证据，不能泛写“可用于其他领域”。

方法是展开重点。与卡片相比，增加设计理由、必要例子和步骤之间的连接，不能只是同样的要点换成更长的句子。Q&A、文献金句、完整推导或复现配置仅在用户要求或理解确实需要时加入。

## 方法完整性自检与必要例子

写完后先只读生成结果，检查能否复述“输入 → 关键操作 → 输出”，以及关键设计回应了哪个前作缺口；再回源核对复述是否准确。两轮分别检查可理解性和事实依据，不能互相代替。

- 多阶段训练：核对每阶段的起始模型、数据来源、优化目标、训练或冻结的部分、产出模型，以及下一阶段接在哪里。只补影响理解的细节，不强塞完整复现配置。
- 推理过程：核对运行时输入与状态、更新或采样过程、停止条件和输出。输入输出的形态或维度影响机制时才展开。
- 非模型论文：按实际贡献复述数据如何构造、评测怎样执行，或假设怎样导出结论，不套用训练阶段。
- 发现断点就补回正文；默认不另附完整 Q&A。独立读者或另一模型检查可用于专项评测或复杂难点，不要求每次调用多个代理。

读者仍难以理解抽象机制时，用一个最小、可核对的小例子走过关键步骤；适合时沿用同一个例子解释后续模块。例子要对应真实操作，不能只给“像老师教学生”这类宽泛类比。自造输入或数值明确标为“讲解示例，非论文实验”；无需逐模块强制配例子，也不为贯穿而把不同机制硬套进一个场景。公式的数值例子与反事实解释见 [图像、公式与交付](html-delivery.md)。

## 消融：从结果变成可判断的经验

先扫描输入中全部消融、参数敏感性、诊断和失败分析，再选对理解贡献最重要的结论。涵盖关键设计、明显负结果、收益饱和以及成本权衡；重复支持同一结论的配置可合并。不要只挑有提升的行。

### 卡片版：直接列结果

在该节开头用简短列表呈现结论，再放必要原图。每点用“**明确结论**：关键观察或数字，附必要条件”的形式，通常一两句即可。相关结果可合并，优先让读者一眼看到哪种做法有效、无效或存在权衡。

不使用多列消融表，不逐点拆出“支持的判断 / 借鉴条件 / 下一步实验”；结论已经能说明借鉴意义时，不再补一段建议。必要限定直接写进结果句，图表/页码可在点末或列表后简短标注。保留关键负结果与成本，不靠省略条件换取简短。

### 总结版：按需解释对照与含义

需要同时比较设置、证据和适用条件时，可使用这五列；简单结果也可直接列点：

| 检验的问题/改变 | 观察结果 | 支持的结论 | 借鉴条件或下一步验证 | 证据 |
| --- | --- | --- | --- | --- |
| 改了哪个变量；与谁对照 | 原始值 → 改动值；指标方向 | 这组对照支持了什么 | 在什么条件下值得试；哪点尚待验证 | Table/Figure/页码 |

这行是写作字段说明，不能作为真实结果交付。

- 结果写到具体数值与条件；原文只给趋势时注明“作者报告/图中趋势”，不估造精确数字。
- 区分百分比、百分点、相对变化及原始分数；若增量是自己计算，注明“据表中数值计算”。
- 消融改动同时涉及模型规模、训练量等变量时，明确存在混杂，不能将差异全部归给某一模块。
- “在论文这组设置下有效”不等于“普遍有效”；没有重复实验/误差条时，不宣称差异有统计显著性。
- 结论要能指导选择，例如“扩大到这里收益已饱和，继续加预算未见增益”，而不是“证明各模块有效”。
- “值得借鉴”可以是实验结论本身，不必强行映射到用户项目。有确切项目上下文才补最小可验证动作，并标明迁移尚未验证。
- 主排行榜上的胜出属于主结果，不能充当组件消融。

## 论文类型与证据缺失

解释重点按论文贡献调整：方法论文讲操作链与设计理由；数据论文讲构造、标注、覆盖和质量验证；评测论文讲评测对象、协议、指标与代表性误差；理论论文讲假设、结论及成立边界；综述讲分类依据与路线关系。混合型论文按实际贡献组合，不强行归为唯一类型。选图对应这些重点，见 [配图规范](html-delivery.md)。

理论论文可用关键假设、定理与反例代替组件消融；数据集/评测论文可用采样、标注、评测协议的敏感性和误差分析；综述可用分类依据与代表性证据。明确是相应的分析证据，不将其改称作者做了消融。

确无消融时保留一句说明，例如“正文及附录未报告组件消融，因此不能从这篇论文判断各模块的独立贡献”。只看到了部分材料时应写“已获取材料中未找到，附录尚不可得”，不要断言整篇没有。

## 最后检查

- 卡片可快速扫读，总结可连续读懂；二者不能只在 CSS 上不同。
- 前人路线与缺口已说清，核心贡献和关键步骤没有遗漏。
- 主图、必要截图、公式都在相应讲解旁；读者知道图和式在解释哪一步。
- 消融结论可见、具体、有条件；没有用空泛启发替代结果。
- 重要未知、混杂和局限没有在压缩时被删掉。
