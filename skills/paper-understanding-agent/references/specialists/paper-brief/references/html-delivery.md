# 原图、公式与 HTML 交付

## 文件与依赖

只有用户要求页面时才生成 HTML。默认使用调用方输出目录（未指定时为任务工作目录）和输入文件 stem 或稳定 paper_id，附固定后缀：

| 模式 | 文件名示例（源为 `My Paper.v2.PDF`） |
| --- | --- |
| 摘要，需要保存时 | `My Paper.v2.abstract.md` |
| 卡片 | `My Paper.v2.cards.html` |
| 总结 | `My Paper.v2.summary.html` |
| 三层合并 | `My Paper.v2.brief.html` |

输入始终是解析文本/结构化记录和已提供的资产，不因为生成页面而下载源 PDF。原文链接仅使用输入提供的值。已有同名产物仅在本次属于更新请求时改写，否则保留并选独立输出目录。

自包含 HTML 中内联 CSS；图片为 base64，辅助 SVG 可内联；公式用原生 MathML 或完全内嵌的渲染资源。不得依赖 CDN 字体、脚本或样式才能阅读。普通来源链接仍可指向原论文。

优先使用简单的 `<img src="...">`、内联 `<svg>` 和 `<math>`。不使用 `srcset`、`picture/source`、iframe、音视频或外部样式导入，减少文件自包含失效的入口。

## 保留论文里的关键图

粗读先确定哪些原图支撑理解：通常包括方法/架构总览，以及必要的结果、消融、数据示例或失败案例截图。按论文内容选择，没有固定图数配额；摘要模式不强制带图。

| 论文贡献类型 | 优先选择能解释贡献的原图或必要截图 |
| --- | --- |
| 方法 / 架构 / 训练 | 方法或训练流程、关键模块、核心效果对比 |
| 数据 / 资源 | 数据构造与标注流程、代表样例、分布和质量验证 |
| 评测 / benchmark | 任务与评测协议、代表性结果、误差或失败案例 |
| 理论 / 分析 | 关键假设与结论、原文示意图、与理论相关的分析图 |
| 综述 | 分类体系、方法关系或演进图 |

以上是选图依据，不是必需图清单。混合型论文按贡献组合；论文没有对应图时不编造“原图”，必要的辅助解释图明确标为“解读示意”。

- 原文有关键主图时应保留，不能全换成自己重画的流程图。辅助示意图必须标注“解读示意”，不得冒充论文原图。
- 使用输入中提供的同版本图像或截图，核对资产定位和图注；需要裁切已有截图时保留子图、图例、坐标轴、箭头及数值。不得从未提供的 PDF 宣称提取了图片。
- 必要截图包括读者需要核对的关键表格行列、公式/算法或失败案例；不是按页堆整篇截图。截取表格局部时保留行列标题、单位及影响解释的脚注，并标明“局部”。
- 图注写清“Figure/Table 编号 + 来源页/节 + 该看哪里 + 支持什么结论”。原图图注可以简短转述，避免大段逐字复制。
- 提取后逐张查看，确认文字在实际展示尺寸可读。方法复杂时可保留全图并加必要局部放大。
- 优先合适格式和分辨率，再压缩；不能为了体积目标压糊关键小字。单图数百 KB 是优化参考，清晰度优先，不设硬性大小上限。
- 资产缺失或不可读时说明具体缺图；继续完成有依据的文字，不自动补抓远程图，不用生成图冒充。

配图分开核验两件事：**来源身份**（论文、版本、图表编号与正文结论对应）和**视觉质量**（裁切、图例、坐标、注释及实际显示尺寸的清晰度）。来源正确不代表图片可读，图片清楚也不代表引用正确。

如果用户指定 Markdown/对话输出，仍保留应有的图和来源，按宿主支持的方式引用；Markdown 文件使用随附资产目录，不能只交付会失效的临时路径。

## 核心公式与白话解释

保留决定方法行为的目标函数、状态更新、路由/采样或关键推理公式；数量由理解需要决定。只起背景作用的通用公式可省略，不强行为没有核心公式的论文造式子。

每条保留公式遵循：

1. 先说这条公式要解决哪一步的问题。
2. 展示准确公式与原文编号/位置。保留重要条件、期望分布、归一化、stop-gradient 等语义；简化时注明省略内容与成立条件。
3. 紧跟白话解释：变量在此任务中是什么；各项做什么；增大/减小意味着什么；为什么采用这个目标或操作。

不能只写“L 是损失，λ 是权重”；要解释权重如何影响哪两种目标。原文没有优化过程时，不硬套“最小化损失”的解释。复杂式子可分步解释，但符号和含义需与原式对齐。

仍抽象时，可用易核对的数值或极简输入演示一次运算，明确标为“讲解示例，非论文实验”，并保留公式成立条件。也可解释“去掉这一项会失去什么约束”或“增大权重会更强调什么”，但须区分公式含义推导与论文实际验证的消融结果；没有实验证据时不推断具体涨跌幅，也不假定效果必然改善或变差。简单公式无需额外凑例子。

HTML 应真正显示公式；仅放在代码块、裸 `$...$` 或公式截图中不能代替可读的数学表达。确因工具限制无法排版时明确说明，不宣称公式渲染已通过。

## 页面组织

- 开头放简短标题、论文身份、原文链接、版本与来源覆盖，然后直接给摘要。
- 卡片版使用清楚的信息分组和短标题；复杂方法、公式、原图可占满行，不为双列布局压缩可读宽度。
- 总结版以连续段落为主，可有轻量目录。两种版本的消融结论默认展开。
- `all` 按摘要、卡片、总结顺序组织并提供锚点导航；核心内容不依赖 JavaScript 才能展开。跨层适度重复用于独立阅读，事实与数值须一致。
- 正文字号约 16–18px、行距适中、避免过宽行。图像 `max-width:100%`，宽表格和长公式允许局部横向滚动，手机上不让整页溢出。

## 生成后验证

以下命令从本 skill 目录执行；其他工作目录下使用脚本绝对路径。

```bash
python3 scripts/embed_images.py "/path/My Paper.v2.cards.html" --in-place --no-remote
python3 scripts/validate_html.py "/path/My Paper.v2.cards.html" \
  --source-pdf "/path/My Paper.v2.PDF" --mode cards
```

`summary` 使用 `--mode summary`，三层合并使用 `--mode all`。对于当前解析输入，省略 `--source-pdf` 和 `--output-dir` 参数，直接给最终 HTML 绝对路径做资源检查；上方 source-pdf 参数只是兼容旧工作流的可选命名检查。

先将输入提供的本地图像整理到任务目录，再执行内嵌命令。辅助脚本保留上游能力，但本 skill 的推荐路径使用本地图像并禁止自动下载远程图。遇到已内嵌 HTML，重复执行应保持内容不变。

脚本检查命名、内嵌图片与常见外部运行依赖；它不证明图中数值正确、图片清晰、公式显示正确或全文阅读完整。随后通过本地 HTTP 预览服务打开 HTML，在桌面与窄屏检查图片、公式、表格和导航。无法进行视觉检查时如实说明，不能声称已浏览器验证。

检查对象必须包含最终交付的 HTML，而非只看临时裁图或构建模板。更换或重新裁切图片后重新嵌入、重新打开页面，核对最终显示的图片与已核验资产一致；存在同名多版本、缓存或旧 base64 风险时，解码实际嵌图并用 hash 比对。最终再次确认图注、来源和图像仍一一对应，不将旧截图或旧检查结果当作本次验证。

最终给可打开的文件路径、所选模式和必要的来源/验证限制；不自动附公众号稿或上传到外部服务。
