# 摘要：从全文提炼的最短完整解释

摘要既用于默认 JSON 的 `abstract`，也用于独立摘要及阅读页面开头。默认一段；信息关系复杂时可分成两小段，不强行凑句数。不要先加一句泛泛的领域介绍再进入正题。

## 必须闭合的内容链

| 内容 | 读者应知道什么 | 精简办法 |
| --- | --- | --- |
| 背景与任务 | 谁/什么系统要完成什么任务，在哪种场景有价值 | 用一个具体任务定位，避免行业历史 |
| 遇到的问题 | 当前障碍是什么，会造成什么后果 | 说明机制短板，避免只说效果不够好 |
| 前人思路与剩余缺口 | 相关工作怎样尝试解决，哪些部分奏效，什么仍未解决 | 按解法合并路线，保留理解差异必需的方法名 |
| 本文切入点 | 作者决定改变哪个环节，为什么可能补上缺口 | 用“因为卡在 X，所以改变 Y”建立因果连接 |
| 具体方法 | 对什么输入做什么关键操作，得到什么输出 | 给出最小操作链，说明核心组件各自作用 |
| 结果与范围 | 在什么任务/数据/比较条件下，取得什么主要结果 | 选最能说明贡献的数字或定性/理论结论 |

这些是内容职责，不要求六句或六个标题。两句可以合并背景与问题；复杂方法可以多用几句。多个独立核心贡献都要有位置，不为缩短而只留下标题里的一个。

写作骨架可参考：

> 在〔任务/场景〕中，〔具体问题及后果〕。已有方法通过〔前人解法〕缓解了〔部分问题〕，但仍受限于〔剩余缺口〕。本文据此〔核心切入点〕：先〔对输入做关键操作〕，再〔核心变换〕，最终〔输出/学习目标〕。在〔评测条件〕下，相比〔对照〕得到〔核心结果〕；〔会改变结论的必要边界〕。

这是内容顺序示意，交付时写成自然段，不输出方括号模板。理论、数据集、评测和综述论文按实际贡献解释“解法”和“结果”，不套用训练模型的叙述。

## 压缩顺序

1. 合并重复的背景与问题，删除“近年来”“提出了一种新颖框架”等无实义引导。
2. 将同类相关工作压成解法路线，不罗列作者名单；保留区别本文与最接近前作所需的信息。
3. 保留关键操作与因果关系，删次要实现细节、超参和外围贡献。
4. 主结果选最能支撑判断的一项或少数几项，不抄整张排行榜。
5. 最后逐句检查：删掉后是否丢失必要信息或理解连接？不丢就删。

不写消融列表、实验配置大全或长篇局限。不默认放公式与图；公式若是不可替代的贡献本身，可以保留最必要的一条并解释。对主结论必不可少的限制应简短写出。

## 让摘要的重点可扫读

独立摘要和粗读开头的摘要都使用选择性加粗。优先突出具体痛点或前作缺口、本文的关键操作、训练思路（确有必要时）和最重要的结果。读者只扫粗体，也应能连起“为什么做 → 怎么做 → 得到什么”。

- Markdown 用 `**重点短语**`，HTML 用 `<strong>重点短语</strong>`；普通加粗足够，不强制加背景色。
- 强调信息本身，例如方法的关键动作或带指标的结果，而不只是模型名、术语和“创新点”等标签。
- 每处尽量只覆盖必要短语；避免整段加粗、每句都加粗或把全部数字都标亮。
- 加粗后仍保留相邻的对照、任务和限定条件，不让醒目的数字脱离上下文。
- 通过排版提高可读性，不为高亮额外扩写正文或重复结论。

## 来源与边界

- 阅读输入中全部相关内容后再写；论文自带 Abstract 是定位入口，不是唯一依据。仅有 Abstract 或结构化摘要时注明范围，不补造方法、前作或实验。
- 来源尽量放在段后的一行，例如“依据：方法与实验段落，block IDs …”。给出的定位必须实际核对，不用这一行掩盖未读章节。
- Related Work 对前作的批评通常是本文作者的定位。未独立查前作时，不把它扩张成对整个领域的确定评价。
- 不把作者声称的“首次”“通用”“最佳”无条件照搬；准确表达论文真正覆盖的条件。
- 摘要不故意藏结论、不留营销式钩子。读者读完即可知道论文做了什么、为什么有效和证据在哪。
