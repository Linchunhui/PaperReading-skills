# 模式三 · 随笔 / digest

> 2–12 篇互相独立的论文 → 一份逐篇深读的自包含 HTML，默认附精简公众号版。主动发现论文的日报、周报和月报走 [`radar.md`](./radar.md)。

## 目标与分流

读完后，读者应能分别解释每篇的具体问题、核心变化、输入到输出的流程、支持证据和适用条件，并记得各篇差在哪。只记住论文名称、领域或几个高分不算完成。

- 只有 1 篇 → 单篇；有可靠演进或继承关系的 2–6 篇 → 系列；独立的多篇 → 随笔。
- “这几篇最近读的”“digest 一下”“整理 / 拢一拢 / 汇总成一份”触发随笔时，默认执行逐篇深读，无需额外要求“详细”。
- 开篇按领域导览，正文每篇独立解释，结尾建立便于回看的索引。论文间有可核实的机制联系可以说明，但不强造继承关系或跨不同协议的排行榜。
- 所有用户指定论文都应覆盖；内部可分批完成再合成一份文件。明确要求短版时才按要求压缩，不能仅因篇数多而降低后半部分的质量。

## 材料与回源

先列清每篇的标题、版本、领域、原文位置和已有笔记。可从同目录找同名 HTML；兼容历史文件时依次尝试大小写、空格/连字符/下划线差异，但必须核对身份，不能只按相似文件名认定同篇。

旧笔记用于复用已建立的解释和配图线索，核心方法、数字及限定条件仍以同版本原文为准。按共享深读规范补读 Method、主结果、消融或诊断、限制及必要上下文。已有笔记不完整时扩充它提供的材料，不能把其缺口带入新报告；本轮已核验的证据可直接复用。

正文可挂原单篇笔记链接，同时提供一手原文链接。只有链接确实可用且便于交付读者访问时才引用笔记；不能用“详见单篇笔记”替代当前报告的完整解释。全文无法取得时按共享规范标明覆盖范围，不冒充已读全文。

## 必备结构

### 1. 标题与本期导览

h1 使用 `Paper Digest · {YYYY-MM-DD}`；副标题给篇数、领域及实际主题，不堆论文名或宣传词。日期按用户时区计算。

开头 `<section id="overview">` 用约 150–250 字说明收录范围与阅读路线，然后用 CSS grid 给每篇一张导航卡：编号、简短名、领域、具体用途、为什么值得读。卡片点击跳到正文，不承担当篇解读。跨多个领域时可分组；领域分布图仅在有解释价值时添加，不能从几篇的构成直接推断整个领域升温。

编号、正文、TOC 和回顾保持一一对应。模板见 [`layout-patterns.md`](./layout-patterns.md)。模板中的占位句不构成论文证据。

### 2. 每篇独立深读章节

每篇使用 `<article class="chapter {color}" id="{shortname}">`，顶部给简短名、领域、版本与原文链接；`tagline` 说明本篇具体改变，`p.hook` 可用一句有依据的话说明入选理由。入选理由写不清时回材料核对，不靠“颠覆”“首次”等词制造亮点。

正文按共享规范包含：

| 锚点 | 内容 |
| --- | --- |
| `#{shortname}-mot` | 具体输入输出、贯穿例子、相关旧方案与卡点 |
| `#{shortname}-met` | 完整路线及分步骤展开、训练与推理、关键公式与段落论证 |
| `#{shortname}-exp` | 主结果、消融/诊断或对应论证，比较条件与证据边界 |
| `#{shortname}-limits` | 成本、适用条件、未证明部分及已核验的开放状态 |
| `#{shortname}-recall` | 80–150 字左右的带条件回顾，让人能复述并区分本篇 |

这些是内容职责，不要求标题逐字照抄。方法通常拆成 4–7 个有内容的小节，每步解释状态变化与设计理由；论文类型按共享规范适配。核心正文全部展开。

默认每篇约 1800–3000 字，其中核心方法或论证通常约 900–1500 字，复杂工作可更长；取消屏数上限。先把理解链补完整，再删重复和外围枝节。不能从旧笔记机械蒸馏成 mot/met/exp 三小段，也不能用多一张图代替缺失的机制解释。

### 3. 结尾回顾

`<section id="recap">` 按编号每篇给一条索引式提醒，包含具体问题、方法变化和一个边界；不原样复读开头的宣传式 hook。

可增加有证据的共同观察或阅读建议，例如两篇方法解决相似约束但付出不同成本。没有可靠共同线索时，独立回顾即可。各篇的限制已在正文交代，不再硬加泛泛的“未来展望”。

### 4. 可选 Q&A

用户要求或确有助于理解时，按篇给少量实质问题和参考答案，用 `<details>` 折叠。Q&A 不替代正文机制解释；没有互动带读要求时，不逐题等待用户回答。

## 配图与视觉

- 沿用共享 CSS，每篇一种主色用于左边框、编号和领域标签，正文保持统一颜色。排版服务连续阅读，避免整页小卡片挤压正文。
- 按类型选择承重视觉：模型方法图、数据或评测流程、理论推理图、综述分类图；按原文与教学作用决定，不强迫所有论文配模型架构图。
- 图旁解释阅读顺序、关键箭头及结论。结果可用小表或 SVG 对比，但每个数字和比较条件必须核实；无可靠数据不硬画柱状图。
- 公式紧跟白话解释并能离线渲染；图片全部内嵌，按共享深读规范平衡清晰度与体积。
- TOC 至少覆盖总览、各篇及其方法/证据/边界、回顾。移动端表格可横向滚动，section 边界清晰，便于后续 HTML 切图。

## 工作流与输出

1. 列出所有输入，确认采用独立论文组织，核对篇目与版本。
2. 读取旧笔记线索并核验一手原文，为每篇补齐共享深读记录。
3. 先写每篇的问题、机制、证据与边界，再提炼 hook、回顾和全期导览；不要先凭摘要定结论后找材料凑。
4. 逐篇做内容验收，后半部分按同样标准检查。全部完成后合成 HTML，嵌入图片，检查公式与版式。
5. 运行下列交付校验，再视觉检查桌面与移动端；脚本通过不代表内容检查通过。

```bash
python3 scripts/embed_images.py "{输出.html}" --in-place
python3 scripts/validate_html.py "{输出.html}"
```

默认输出 `{YYYY-MM-DD}-digest.html` 和同 stem 的 `.wechat.md`。PDF 同目录时可放同目录；分散材料优先使用用户指定位置，其他环境遵守其持久化交付规则。临时截图嵌入后不作为 HTML 路径依赖。

公众号版按 [`wechat-markdown.md`](./wechat-markdown.md) 从同一证据重新组织，逐篇保留问题、连续机制、关键证据和条件；不复制导航卡墙与折叠 Q&A，不把公众号压缩目标套到 HTML。用户明确只要 HTML 时省略伴随文件。

## 验收

- 所有用户指定论文有对应正文，编号、目录、原文链接和回顾一致。
- 每篇通过 [`per-paper-deep-read.md`](./per-paper-deep-read.md) 的逐篇验收；旧笔记已回源核验，材料缺口已明确。
- 每篇能独立解释问题、走通方法、理解证据和边界；后几篇没有缩水为短卡。
- 论文类型、图表和公式适配，不虚构架构、数字或因果结论。
- 每篇回顾包含这篇特有的对象、操作与条件，读者能凭它恢复核心认识。
- 独立论文未被硬串成演进线，跨篇比较保留协议差异。
- HTML 文件、图片自包含、公式渲染、导航及移动端检查通过；默认公众号版覆盖同一批论文。
