# 模式三 · 随笔 / digest

> 2-12 篇**互相独立**的精选论文 → 一份 digest HTML。主动抓取的日报 / 周报走 [`radar.md`](./radar.md)。
>
> 触发：用户一次性给出 ≥ 2 篇互相独立的论文（不是一个系列、不是一个模型家族），说"这几篇我最近读的"/"今天的论文"/"本周精选"/"帮我 digest 一下"/"整理一下"/"拢一拢"/"汇总成一份"，或在 prompt 里指定模式关键词 **随笔** / **digest**。
>
> 读一个系列（模式二）是把论文**串成一条线**；读一批**独立的**精选论文，是给它们**一人一个展位**——每篇自己讲自己的故事，开篇和收尾各做一次"这几篇分别是什么领域、用来干嘛"的导览，让读者一眼看清本期读了什么。

## 总目标（随笔特有）

输出一份让外行也能跟下来的本期 digest HTML，并默认附一份 `{YYYY-MM-DD}-digest.wechat.md` 精简公众号版，让读者读完能说三件事：

1. 这一期收了哪几篇、分别属于什么领域、各是用来干嘛的（开头总览 + 结尾回顾各讲一遍）
2. 每篇论文自己在解决什么问题、用了什么招数、最关键的发现是什么（每篇一张独立卡片）
3. 哪几篇最值得回头看 / 这一期整体印象是什么（结尾回顾）

如果读者读完只知道"这几篇都挺厉害"却说不出"哪篇是哪个领域、各自干了啥"——这份 digest 就失败了。

## 与单篇 / 系列的关系

| 项目 | 单篇（single-paper） | 系列（series） | **随笔（digest）** |
|------|------|------|------|
| 输入 | 1 篇 | 2-6 篇**同系列** | 2-12 篇**独立**精选 |
| 论文之间的关系 | — | 演进 / 继承 / 同一脉络 | **互相独立，无关系** |
| 核心叙事 | 单篇深度解剖 | 贯穿演进线 + 每代差异 | 领域总览 + 每篇独立亮点 |
| 跨论文可视化 | — | 时间线 / 对照矩阵 / 贯穿线 SVG | 概览卡墙（按领域分组）+ 可选领域分布 |
| 输出文件名 | `{PDF 原 basename}.html` | `{系列名}.html` | `{YYYY-MM-DD}-digest.html` |
| 红线 / 写作原则 | 12 条 + 4 原则 | 沿用 | 沿用 |
| 公式 / SVG 准则 | 沿用 | 沿用 | 沿用 |

**随笔相对系列，删掉了**：贯穿线（`#threads`）、时间线 SVG、横向对照矩阵、"共享核心思想"（`#core`）。原因很直接——独立论文之间没有演进关系，硬串成线就是流水账；跨领域也没法在同一组维度上对照。

**随笔相对系列，新增了**：开头总览（`#overview`，按领域分组）、每篇卡片开头的**亮点 hook**、结尾回顾（`#recap`）、**按论文类型适配配图**。

### 复用而非重读（核心规则）

这是随笔模式最重要的一条工作方式——**先找现成的笔记，找到了就直接用，不要回去啃 PDF**：

对用户给的每一个 PDF：

1. 看它**同目录**下有没有对应的 `.html` 笔记。新版本单篇必然严格同名；旧笔记可按从严到宽三级兼容：
   - *严格同名（优先）* —— `DeepSeek-R1.pdf` ↔ `DeepSeek-R1.html`
   - *大小写不同* —— `GDN2.pdf` ↔ `gdn2.html`（macOS 文件系统不区分大小写，直接命中）
   - *分隔符不同* —— `Gated Attention.pdf` ↔ `gated-attention.html`（把空格 / 连字符 / 下划线统一成同一种再比）
2. **有** → 这个 HTML 就是单篇模式的产物。直接读这份 HTML、蒸馏成本 digest 里这篇的 mot/met/exp 三段。**不要重新去读 PDF**。
3. **没有** → 才去读 PDF 本身（走简化版单篇：只精读 Abstract / Method / Experiments 关键段，够支撑三段即可，不必做完整单篇解读）。

后两级只用于兼容历史产物。PaperStudio 2.0 新生成的单篇 HTML 必须与 PDF 严格同名。如果某份旧 HTML 拿不准是不是同一篇，宁可读 PDF，不要把不相关的笔记硬套上去。

为什么这么干：*省时间*——已有的笔记比现啃 PDF 快十倍，而且你已经把那篇想明白了；*保一致*——同一篇论文在单篇笔记和 digest 里说法不会打架；*优先级*——**HTML 笔记 > PDF 原文**。

header 里给每篇挂一个指向原笔记的链接（`<a href="./xxx.html">单篇笔记</a>`），让读者想深入时能跳过去。这个规则和系列的"复用而非重读"是一回事，只是随笔把检测条件写死了：**同目录、同名、`.html`**。

## 触发判断

- 用户一次性给出 ≥ 2 篇**互相独立**的论文，说"这几篇我最近读的" / "今天的论文" / "本周精选" / "帮我 digest 一下"
- 用户指着一批散落的 PDF / arxiv 链接说"整理一下"、"拢一拢"、"汇总成一份"
- 用户每天的固定动作："把今天看的几篇弄成一份"

**和系列的分流**：

- 论文之间有明确的演进 / 继承关系（V-JEPA → V-JEPA 2、π₀ → π₀.₅）→ **走系列模式**
- 论文之间只是"最近都看到了、都挺有意思"，没有脉络 → **走随笔模式**

只有 1 篇 → 走单篇模式。

## HTML 大标题怎么写

朴素直接，带日期——日期就是 digest 的"系列名"，因为独立论文唯一的共同点就是"我在这一天 / 这一周读了它们"。

- `Paper Digest · {YYYY-MM-DD}`（默认）
- `Paper Digest · {YYYY} 年 {M} 月 {D} 日`（中文日期）
- 如果本期恰好有个松散主题（如"本周的几篇推理论文"），可在副标题点一下，但 h1 主体仍然是日期

**不要**在 h1 里堆论文名、不要"惊人发现"、不要二次创作——和单篇 / 系列一样朴素就够。

模板：

```
<h1>Paper Digest · {YYYY-MM-DD}</h1>
<p class="subtitle">{N} 篇 · {领域1} · {领域2} · {领域3} … — {一句话点出本期整体调性，可选}</p>
<p class="meta">{阅读日期} · {N} 篇论文整合 · 独立笔记：<a href="...">论文名1</a> · <a href="...">论文名2</a> …</p>
```

## 必备结构（按出现顺序）

这份 HTML 的*骨架*——按这个顺序写，别打乱。

### 1. 开头总览（`<section id="overview">`）

让读者在进入任何一篇之前，先有一张"本期地图"。两件东西：

**(a) 导读段（100-200 字）**：这批论文是哪来的、为什么放一起、整体扫一遍什么印象。一句话点出本期跨了哪几个领域、有没有哪篇特别亮眼。末尾留个钩子。

**(b) 概览卡墙**：每篇一张迷你卡（CSS grid，不用 SVG），卡片内容固定四件套：

```
┌──────────────────────────────────┐
│ ①  DeepSeek-R1              [RL] │  ← 编号 + 论文简短名 + 领域 tag（该篇主色）
│ 用纯 RL 让模型自己长出推理        │  ← 一句话用途（这篇用来干嘛）
│ ✦ 亮点：不需要 SFT 冷启动也能训   │  ← 亮点 hook（为什么值得看）
└──────────────────────────────────┘
```

- *按领域分组* —— 如果本期跨 ≥ 3 个领域，或某个领域有 ≥ 2 篇，就用领域小标题把卡墙分组（如「强化学习」「视觉语言」「评测」）。只跨 1-2 个领域就平铺。
- 每张迷你卡的编号 ①②③ 要和后面正文章节卡片的编号、TOC、结尾回顾**全程一一对应**。
- 领域 tag 用该篇主色填充，是整份 digest 的视觉锚点。
- 点迷你卡能跳到对应正文（`href="#{shortname}"`）。

*可选*：如果本期领域分布有意思（比如 5 篇里 3 篇都是 RL），在导读下加一张小的"领域分布" SVG（几个色块 + 篇数）。不强求——卡墙分组本身已经表达了。

概览卡墙 / 领域分布的模板见 [`layout-patterns.md`](./layout-patterns.md)。

### 2. 每篇论文的独立卡片（`<div class="chapter {color}">`）

每篇 1 张卡片，沿用系列的彩色章节卡片样式（`border-left` 用该篇主色）。卡片内部：

- *卡片顶部* —— 编号 + 论文简短名 + 领域 tag + 一行 `tagline`（一句话讲这篇的"差异化定位"，和系列一样）
- *亮点 hook*（随笔特有，系列没有）—— 紧跟 tagline 下面，用 `<p class="hook">` 标出，一句话回答"**为什么这篇入选本期精选**"。这是 digest 的灵魂——读者扫到这张卡，第一眼就知道值不值得细读。
- 三个子 section（沿用系列）：
  - `#{shortname}-mot` 出发点（这篇在解决什么问题，2-4 段，回到一个具象场景）
  - `#{shortname}-met` 方法详解（配图 + 分步骤 + 公式白话翻译，要求见下）
  - `#{shortname}-exp` 关键发现（1-3 个最有冲击的数字 + 一张承重图）
- *可选* `#{shortname}-takeaway` —— 一句话"读完这篇带走什么"。轻量，门槛远低于单篇的 Insight——digest 里给一句"so what"就够，没有就省略，**不要硬挤**。

#### 复用单篇笔记时的蒸馏标准

如果这篇有现成的单篇 HTML → 从那份蒸馏到 mot/met/exp 三段（**不碰 PDF**）。蒸馏标准同系列：原笔记 8-15 屏 → 这里 1-3 屏，**但 met 子节的配图 / 分步骤 / 公式翻译不能因为压缩而丢**。

#### 配图策略（按论文类型适配——这是随笔和系列的关键差异）

系列强求每篇 met 都配架构截图，因为系列论文基本都是架构型。随笔的论文跨领域，**按类型决定配什么图**：

| 论文类型 | 配什么图 | 例子 |
|---------|---------|------|
| 架构 / 方法型 | **架构截图**（沿用系列截图规范，从原论文 Figure X 截，配自己写的 figcaption）| 新模型、新训练框架 |
| 评测 / benchmark 型 | **主结果表 / leaderboard 截图**，或 **SVG bar chart**（关键对比）| 新基准、能力评测 |
| 理论 / 分析型 | **关键定理 / 分布的概念图**（SVG 重画，或论文里的示意图截图）| 表征分析、收敛性证明 |
| 综述 / 调研型 | **分类树 / 时间线 SVG**（论文自己的 taxonomy 图，或自己重画）| survey、分类法 |
| 纯经验 / 数据型 | **数据分布 SVG** 或 **关键数字 bar chart**| 数据构造、scaling 实验 |

底线：**每篇 met 至少一张承重图**（截图或 SVG 二选一），但**不强求是架构截图**——配论文真正承重的那张图。截图规范（边界完整 / 清晰 / 单张 ≤ 300 KB）和 SVG 数据准确性红线全部沿用 [`foundation.md`](./foundation.md) / [`series.md`](./series.md)。

#### 公式白话翻译（沿用）

每条 LaTeX 后紧跟 `<p class="note"><strong>白话翻译</strong>：...</p>`，解释符号 + 设计意图，不能是公式复读。沿用红线 10、系列同款要求。

### 3. 结尾回顾（`<section id="recap">`）

收尾。两件东西：

**(a) 一句话列表回顾**：把开头总览再讲一遍，但这次是"**读完之后**"的视角——每篇一行：领域 + 用途 + 印象最深的一点（不是开头那句用途的复读，是读完后的 takeaway）。

```
① DeepSeek-R1  [RL]  —— 用纯 RL 长出推理；最反直觉的是冷启动反而拖后腿
② OneVL        [VLM] —— 物理预测当辅助监督；那个 +0.87 vs +0.31 的对比记得最牢
③ ...
```

**(b) 本期收获（可选，1-3 句）**：读完这一批的**总体感受**——不是硬挤的 insight，而是"这几篇放一起看，我注意到 XX"。比如"本期 5 篇里有 3 篇都在搞 RL + 推理，这个方向明显在升温"。没有就省略，不要写"本期收获颇丰"这种空话。

写完回顾就结束。**不要再续"未来展望 / 留下的问题"**——那是系列已经删掉的坑，随笔同样不要。

### 4.（可选）Q&A（`<section id="qa">`）

只在用户特别要求、或某篇特别需要深挖时才加。沿用单篇 / 系列的 accordion 格式（`<details>` 展开，保证 HtmlToSlides 能切）。digest 里 Q&A 通常**按篇分组**（每篇 2-3 题），而不是像单篇那样 5-10 题堆一起。

## 视觉风格规范

继承单篇 / 系列的字体 / 配色 / KaTeX / 双语引用块 / TOC 设定，**额外约定**：

### 配色：每篇一种主色 + 领域 tag

- 每篇论文分配一种主色（相邻但区分度够的色相，参考系列的 JEPA / π 配色示例）
- 主色用在：章节卡片 `border-left`、概览卡墙的领域 tag、TOC 编号
- 领域 tag（`[RL]`、`[VLM]`）用该篇主色填充白字，是 digest 跨论文的视觉锚点
- **正文颜色不要染**——只染结构性位置

### 新增样式（在系列 `style.css` 基础上加）

- `.overview-grid` / `.overview-card` —— 概览卡墙（grid + 单卡，左侧色条）
- `.field-tag` —— 领域 tag（小圆角 pill，主色填充）
- `p.hook` —— 亮点 hook（左侧暖色条 + 浅黄底，区别于正文）
- `.recap-list` —— 结尾回顾列表（编号 + 领域 tag + 一句话）

完整起手式见 [`../assets/style.css`](../assets/style.css)（在系列的基础上加了上面四组）。

详见 [`layout-patterns.md`](./layout-patterns.md)。这里只列模板清单：

## 工作流

### Step 1: 收齐材料 + 判断关系

- 把用户给的 PDF / 链接 / 已有笔记列清楚：标题、领域、PDF 路径、**同目录有没有同名 `.html`**（单篇产物）
- 确认这批论文**互相独立**（不是系列）——是系列就走系列模式
- 给每篇定：简短名、领域 tag、主色、编号

### Step 2: 复用 vs 读（对每篇）

- 同目录有同名 `.html` → 读那份 HTML 蒸馏（**不碰 PDF**）
- 没有 → 读 PDF，走简化版单篇，够支撑 mot/met/exp 即可

### Step 3: 找亮点 + 定领域

对每篇问自己：①这篇属于什么领域？（定 field tag）②这篇最值得看的那一点是什么？（定亮点 hook）③这篇配什么图最承重？（按上面的类型适配表）

这一步决定 digest 的"展位"质量——hook 写不出来说明你没看出这篇好在哪，回去再读。

### Step 4: 排版 + 配色

- 按领域给卡墙分组（或平铺）
- 每篇分配主色
- 收集 / 截取每篇的承重图（截图边界完整 / 清晰 / 单张 ≤ 300 KB）

### Step 5: 写 HTML

按"必备结构"1-3（+可选 4）顺序写。每写完一节在脑子里过一遍 12 条红线，再继续下一节。

### Step 6: 验收

运行：

```bash
python3 scripts/embed_images.py "{输出.html}" --in-place
python3 scripts/validate_html.py "{输出.html}"
```

两个步骤通过后，再按下面的检查清单逐条过。

随后按 [`wechat-markdown.md`](./wechat-markdown.md) 生成公众号版：导语先给本期判断，每篇压成 500–900 字短卡，结尾只留本期共同信号；不复制概览卡墙、TOC 或大表。

## 输出路径

- *主输出 HTML*：
  - 多篇 PDF 在**同一目录** → 放该目录，命名 `{YYYY-MM-DD}-digest.html`
  - PDF **分散**或来自**链接** → 放用户指定的输出目录；未指定时放当前工作目录
- *配图*：截图文件只作临时资产；压缩后嵌入 base64，不保留相对路径或远程图片 URL
- 日期用 `date +%Y-%m-%d` 取当天

## 验收清单（随笔）

- *h1 带日期* — `Paper Digest · {YYYY-MM-DD}`，朴素；副标题点出领域分布 + 整体调性
- *开头总览齐全* — 导读段 100-200 字 + 概览卡墙（每篇一张迷你卡：编号 / 简短名 / 领域 tag / 一句话用途 / 亮点 hook）；跨 ≥ 3 领域时按领域分组
- *每篇卡片完整* — `border-left` 用该篇主色；含亮点 hook（`p.hook`，digest 灵魂）+ mot/met/exp 三子节；每篇 1-3 屏
- *亮点 hook 真的是亮点* — 每篇那句"为什么值得看"是**读完之后**抽出来的，不是 abstract 客气话、不是方法步骤
- *配图按类型适配* — 每篇 met 至少一张承重图，但不强求架构截图；架构型配架构截图，评测 / 理论 / 综述型配对应承重图；截图边界完整 / 清晰 / ≤ 300 KB，最终以 base64 嵌入
- *公式必有白话翻译* — 每条 LaTeX 后紧跟 `<p class="note">` 段；不复读公式
- *复用单篇笔记* — 同目录有同名 `.html` 的，从那份蒸馏（**不碰 PDF**）；header 挂原笔记链接
- *结尾回顾* — 一句话列表回顾每篇（领域 + 用途 + 读完印象），不是开头总览的复读；可选"本期收获"
- *没有硬串线* — 没有 `#threads` / 时间线 / 对照矩阵（那是系列的活）；独立论文就是独立展位
- *SVG 数据准确* — 每个数字有出处；末尾标 `Source: ...`
- *公式都渲染* — 打开 HTML 肉眼确认 KaTeX 没报错、没有 `$...$` 裸露
- *TOC 完整* — 桌面端固定右侧；包含 overview + 每篇（带编号）+ recap
- *外行能跟* — 不懂这些领域的聪明人读完能复述：本期 N 篇各是哪个领域、各自干了啥、哪篇最值得回头看
- *零割裂感* — 读完像一个人在跟你讲"我最近读了这么几篇，各有各的意思，给你挨个说说"
- *可被 HtmlToSlides 切* — section 边界清晰、Q&A 用 `<details>`、SVG 不跨切点（让 digest HTML 也能被 HtmlToSlides 切成图分享）
- *图片无路径依赖* — `validate_html.py` 通过；所有 `<img src>` 都是 base64 `data:image`
