# 雷达：逐篇讲通，再合并报告

适用于多篇雷达的写作与检查。发现范围、时间和候选来源遵守 [radar.md](radar.md)，共同内容遵守 [paper-storyline.md](paper-storyline.md)。不新增阅读模式，也不要求安装其他技能或启动模型后端。

默认读者具备机器学习基础，但不了解论文的新机制。每篇的目标是让读者能解释关键操作、设计理由和实验判断，并知道它改变了研究问题的哪个环节。写作长度由这些连接决定，不按报告总长度、论文数量或统一模板分配篇幅。

## 固定正文结构

日报、周报、月报及给定候选雷达，每篇正文的六个主栏目固定为 **背景 → 问题 → 思路 → 方法 → 结果 → 总结**，标题与顺序保持一致。论文身份、方向、版本及来源覆盖放篇首。每个栏目有独立职责：

| 栏目 | 内容职责与展开重点 |
| --- | --- |
| 背景 | 交代任务、对象与必要场景，保持紧凑 |
| 问题 | 说明旧办法、具体瓶颈及后果，与背景分开 |
| 思路 | 说明改变哪个环节及设计动机，具体操作留给方法 |
| 方法 | 重点展开输入到输出的操作、步骤衔接、设计理由，适用时区分训练与推理；必要例子、公式与原图在相应难点处解释 |
| 结果 | 重点展开关键比较的目的、条件、观察与支持范围；主结果与关键消融/分析分别用小节呈现，保留负结果、成本及比较限制 |
| 总结 | 简明收束贡献、可借鉴内容与适用边界，避免重述全部流程和分数 |

方法、结果内部可用贴合论文的小标题，不能用自由叙事标题替换这六个主栏目，或将背景/问题、思路/方法合并。扩写主要用于方法和关键结果，其他部分不随之平均拉长。重排旧稿时按段落职责移动内容，不能只换标题而把推理操作继续留在结果中。材料不足的指定条目仍按六栏说明已知与缺口，不能为填满结构编造机制或实验；用户明确要求其他格式时遵从。

## 1. 固定篇目与实际材料

发现与筛选后保存篇目清单，记录身份、版本、方向、纳入理由、来源覆盖及状态。正式收录、用户指定但材料不足、观察或边界条目分别标记；不能为缩短报告静默删除已入选论文。报告末尾核对实际出现的篇目，不以导航卡数量代替正文覆盖。

初筛与取证分开。摘要可以支持相关性判断；进入正式讲解后，核对方法、主实验、关键分析及必要附录。已有同版本 evidence-bundle 可复用其定位与核验记录；也可由当前会话按同样要求备课，无需为雷达运行完整单篇档案的所有分支。

## 2. 每篇一份轻量工作记录

在任务工作目录按论文身份保存记录与正文，格式可为 Markdown 或既有结构化记录，不要求额外交付 JSON。至少保留：

| 记录 | 用途 |
| --- | --- |
| 核心贡献与理解问题 | 从材料中找出读懂贡献必须回答的问题；多项独立贡献不能只留标题卖点 |
| 方法路线与设计理由 | 输入、状态、操作、输出去向；适用时包含训练、监督和推理差异 |
| 前作与变化 | 最相关旧办法具体做什么，本文改变哪一步，哪些组件沿用 |
| 结果与分析证据 | 关键主结果、消融/诊断、负结果、成本及比较条件 |
| 定位与原图 | 原始版本、页/节/式/表/图，实际查看范围，适用核心原图或真实例外 |
| 未解问题 | 标明证据缺口或解释缺口，以及下一步与最终处理结果 |

证据缺口指材料不足以确定操作或结论，需要定向回读原文、附录或图表。解释缺口指证据已经有了，但讲解缺少过渡、变量含义、例子或设计理由，需要重写相应段落。两者分别处理；不能用扩写推测补证据，也不能以增加来源链接代替讲解。

复用旧报告时记录它是上游解读，不能把其中“已核验”的措辞转写成当前会话已读原文。用户要求对照改写且本轮只取得旧报告时，可以在该材料范围内改善表达：在报告范围和各篇注明“基于既有解读改写，原论文未重新核验”，保留原记录的来源定位但标明其来源，不新增未经支持的机制、结果或原文引用。这种比较仅检验讲解变化，不能宣称完成新一轮全文取证或全部改进来自技能。需要原文才能补足的关键细节继续记缺口；示意例子必须标为教学构造。

## 3. 先写方法与实验，再写入口

先从工作记录写方法和实验证据，再补背景、问题、思路与总结，最后提炼篇首摘要和推荐理由。写作顺序不必暴露给读者；最终正文始终按六个主栏目排列。内部状态、检查清单和任务日志不混进普通阅读正文。

围绕核心操作形成连续讲解：交代进入什么对象，发生什么变化，结果交给谁，以及这一步回应了哪个问题。多阶段训练解释阶段产物如何进入下一阶段；推理循环解释运行状态、更新、停止条件和输出。因果动机若来自作者解释或讲解者推测，分别归因。

抽象机制按理解需要使用一个对应真实操作的小例子，沿关键步骤推进。例子应让读者看出变化，不只提供泛泛比喻；自造数值标为教学示例，不能混进实验结果。必要公式先说明用途，再解释变量与操作；对决定理解的局部关系可展开推演。不得凭常识补写材料没有给出的公式、监督、实现、阶段或配置。

关键实验先让读者知道检验的问题、改变和保持的条件，再解释观察与结论。主榜回答整体表现；分析实验帮助判断设计、代价和失败条件。结果中存在混杂、负向变化或反直觉现象时，解释其意义，而不是只堆原始值与一句限定语。按论文类型使用理论假设、反例、数据质量或评测协议分析。

## 4. 逐篇复述与证据检查

先只看正文进行可理解性检查，记录简短复述及具体断点，再回材料做事实核对。可以在工作记录中完成，无需给每篇附上一套读者 Q&A，也不要求普通生成每次都调用额外代理。

复述至少触及本篇适用的问题：

- 什么输入或条件使旧方案遇到困难，本文改变了哪个环节？
- 一个输入或状态怎样经过关键操作成为输出？阶段切换、参数更新、训练/推理差异能否接起来？
- 为什么需要关键设计？其解释是作者主张、受控证据还是讲解者推断？
- 一项承重实验比较了什么，观察支持什么，又不能证明什么？
- 在什么前提下可借鉴，本篇与同问题的其他路线有什么关系？未取得关系证据时能否明确说出未知？

合格复述要出现本篇具体对象、动作、控制条件与结论，不能以“方法清楚、八项齐全、通过”等自评替代。证据检查再确认复述没有超出原材料，数字、版本、原图与条件一致；反向暴露的正文跳步应补回正文，不只留在检查记录。

每次补读或重写针对一个可定位断点，并记下新证据或改动。连续两轮没有新增证据或有效修复时，保留未解状态与原因，继续处理无关条目；材料状态改变后可恢复。缺失材料可诚实交付已知部分，但不能将未能恢复的核心机制计为完成独立解读。用户指定条目仍保留，观察项不冒充全文解读。

检查结束，保存本篇正文、实际覆盖及仍存缺口。保留中间文件以便恢复任务；下一篇不能只依赖上一批聊天中的摘要。

## 5. 从保存的正文合并

逐篇完成后，将保存的正文作为合并输入。合并主要处理标题、唯一锚点、来源、共享背景和导航；不重新要求模型把整批论文压成一个总长受限的答案。若需要调整某篇，更新该篇正文并复核受影响内容，再重新合并。

导览与阅读顺序从最终正文提炼，整期保留总览、方向分组、逐篇正文和期末回顾。每篇保持六栏结构、可独立理解且默认展开；详细方法不隐藏在等高卡片、默认折叠或固定高度里。所有正式条目执行 [core-figures.md](core-figures.md)，教学 SVG 只作辅助。公众号伴随稿从同一证据与完成的正文生成，保留相同篇目、六栏顺序和关键连接，不反向限制 HTML。

合并后按篇目清单核对正文、来源、原图和伴随稿，检查六个主栏目及顺序，并核对每栏实际职责；尤其确认方法没有混入结果、主结果没有吞掉消融。检查首、中、末段条目是否保留原有解释与条件。对每篇检查内容，而不是只统计总字数或只抽查 Top picks。生成限制通过继续保存后续批次解决，不靠静默删篇或降级解决。

## 6. 把单篇放回问题中

在既定方向内按有证据的共同问题联系论文。先对齐任务、输入输出、假设、预算与指标，再说明它们改变了哪个环节。分别表达直接继承、同条件竞争、互补或不同约束下的替代方案；没有支持时保留并列，不强造路线图或统一排名。

周报强调当期新增的机制与证据；月报复用同版本已核验材料，补充跨周的路线关系和有依据的认识变化。跨期旧文只作明确标注的背景，不计入当期发现。单篇正文仍然完整，跨篇回顾不代替每篇总结，也不把少数收录论文外推为全领域趋势。

## 7. 改写对照与验收记录

用户要求评估改动时，先保存基线及篇目、版本、原材料和生成条件，再生成候选。提供可逐篇访问的新旧正文与具体差异，例如补通了哪一步、补读了哪个来源、改正了哪项比较。相同材料的解释改进、新增证据和事实修正分别说明；文字增加量只作辅助观察，不当质量分数。

技能更新按 [skill-iteration.md](skill-iteration.md) 独立生成和评审。复杂机制与多篇负载案例检查关键步骤是否可恢复、实验是否可判断、中后段是否完整，以及扩写是否增加无依据内容。不同生成环境或新增来源会影响比较，记录这些条件；未经实际评审，不预先宣布新版胜出。
