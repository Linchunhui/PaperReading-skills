# 逐篇核心原图契约

## 选择与证据

每篇正式解读（单篇、串讲、雷达均适用）先核查原论文的图与图注。存在有助恢复核心方法的架构、流程或任务总览图时，必须保留至少一张清晰完整的原图，放在方法首次展开处；复杂机制可补子模块特写。不能用排行榜、装饰图、全报告导航图或别篇配图充当本篇方法主图。

理论、数据、评测、综述论文不强造架构图：优先选择承载贡献的原始任务/协议/数据流程/分类或分析图；核查后确无适用图才记不适用。保留图号、版本与来源，并用自己的短图注解释看哪里、输入输出如何连接、哪些属于训练或推理，不照抄长原图注。

在来源授权范围内优先取官方 HTML 独立图源；失败时尝试已可得 PDF 页面定位和清晰裁图。先看实际像素再保留，检查边界、小字、箭头与来源一致性。不得为补图虚构、生成或冒充作者原图；教学 SVG 明确标为教学示意，仅作辅助，不能无说明替代可得原图。

逐篇保留三种状态之一：
- `embedded`：已嵌入适用原图，明确图号、来源位置与读图导引。
- `unavailable`：材料未提供原图、访问或提取失败；写明已核查的版本/材料位置、实际尝试与尚未完成的步骤，不把未取得写成论文没有图。严格只用给定材料时不越界搜索。
- `not-applicable`：已经核查相应图/材料，说明为何没有承载本篇贡献的适用原图。不能仅以“理论论文”或“报告太长”作理由。

例外必须在该篇正文可见。只有文字材料、无链接时写出材料名与章节即可，不伪造URL。候选观察项/边界项不是正式全文解读，明确其身份与缺口，不靠降级正式条目逃避主图门槛。明确聊天短答或纯文本请求不强制图片产物，但不得声称原图已展示。

## HTML 标记与验收

每篇正式正文根节点使用 `data-paper-body="true"`、唯一 `id` 与 `data-core-figure-status`。单篇也标记其正文容器。多篇中保留 `data-status="formal"`；观察/边界项明确为 `watch` / `boundary`。不用标记导航卡。

```html
<article id="paper-a" data-paper-body="true" data-status="formal" data-core-figure-status="embedded">
  <figure data-figure-role="original-core">
    <img src="data:image/png;base64,..." alt="论文A的核心流程原图">
    <figcaption>原论文 Figure 2：先看输入与状态更新，再看训练支路。
      <a href="https://example.org/paper#figure2">原文 Figure 2</a>
    </figcaption>
  </figure>
</article>
```

无适用原图/未取得时，在同一正文用可见 `class="core-figure-exception"` 段落解释，并通过 `data-source` 记录真实来源位置（URL或给定材料名/章节）；如有可用原文链接也保留。例如只给文本时：

```html
<p class="core-figure-exception" data-source="给定材料 papers.md，论文A §3">主图未取得：本任务仅提供 §3 方法文本，没有图像资产或PDF；未进行范围外搜索，以下示意不是作者原图。</p>
```

运行 `validate_html.py output.html --require-core-figures`，再人工逐篇核对“原图/明确例外”的覆盖。文件校验只验证标记、资源与说明存在，不能证明图像真实性、例外合理性或读图清晰度；必须回源和查看桌面/手机实际显示。最终审计分开报告正式篇数、含核心原图篇数、例外篇数及教学SVG数，不能把整报告的图片总数冒称逐篇主图覆盖。

图片数量和体积服从逐篇承重内容，不设全报告3–6张/2MB硬限制。公众号版使用同一证据，按阅读用途保留主图或在该篇标明图的省略范围，不能反向删减HTML主图。
