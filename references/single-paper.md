# 单篇精读：结构化理解与教学带读融合

默认把完整阅读记录与受李沐论文精读方法启发的原创讲解融为一套流程。无须额外开启 limu，不调用其他 skill；旧写法 `single-limu` 仅作为 `single` 的兼容别名。不冒充李沐本人，不编造他的原话或评价。

## 备课与记录

完整读取共享 foundation 与 paper-storyline。默认面向有编程和机器学习基础、但不熟悉该方向的读者，沿用用户已说明的背景。用户限定章节、只讲方法、逐段讲解或仅对话时遵守范围；只有明确要求互动才暂停等待回答。

1. 核对标题、作者、日期、版本、论文类型与来源覆盖。用户指定版本时不混入新版结果。记录实际看过的正文、附录与官方实现，冲突分别说明。
2. 先扫摘要、结论、总览图和主表，再读方法、训练流程、实验、消融与限制，最后回查承重段落。备课顺序不必成为正文顺序。
3. 建立轻量阅读记录：八项主线、方向/任务、关键词、问题签名、贡献、最相关前作、关键发现、证据位置、成本与缺口。摘要最后写，不把 Abstract 翻译当成解读。
4. 对每项重要主张记录“主张—出处—比较条件—支持范围”。区分作者主张、实验观察、自己的推导与待验证判断。
5. 原文不可得时保留用户指定论文，写清材料范围和无法判断的部分；不要凭常见做法补齐训练细节。摘要级材料只能支持摘要级理解。

## 组织完整讲解

以下是推荐的理解顺序，允许自然合并或拆分标题。八项主线都须有内容，不能为了固定十节或固定篇幅削掉核心环节。

### 导览与摘要

给朴素标题、论文身份、方向/关键词和来源链接。用读过全文后重写的摘要交代背景、问题、核心变化、操作路线、主要结果与成立条件。随后说明值得读的具体贡献；结果不要留到结尾才揭晓。摘要、贡献亮点和正文承担不同作用，不重复三遍同一段。

问题签名用一句可检索的短语保存“任务/对象＋限制条件＋瓶颈＋目标”；它帮助以后找到相近问题，不是另造术语。

### 背景、问题与前作

先给具体输入和期望输出，以及实际约束。区分部署输入、训练监督、中间表示与最终输出。前置知识在用到时解释，不堆领域通史。

选一个能贯穿方法的例子，优先论文实例；自造例子标“教学示例”。沿最相关前作解释：以前如何做、在哪一步卡住、为何造成代价、本篇想改变哪一步。区分直接继承、同期竞争、互补组件和仅相关背景，引用不等于继承。比较创新落到新增问题、机制、数据、协议、理论或经验发现，避免泛称“首次”“全面领先”。

### 解决思路

先解释作者的切入点及其可能有效的原因，再引出组件名称。分清核心新机制、沿用组件和工程配套。作者未说明的动机只能标为自己的解释，不编心理活动。把“为什么改这一点”与后文“实际如何操作”区分开。

### 具体方法

先给最小完整路线，再用同一个样本走过关键操作。每步讲输入对象、执行操作、输出去向与必要性。核心机制可长讲，熟悉组件可回指，不能只给模块名或箭头图。方法细则见下一节。

### 结果、消融与边界

把主实验与关键消融/诊断分开讲。主实验回答整体有没有收益，分析实验检验设计解释。保留负结果、收益饱和、失败场景和成本；具体要求见“读懂实验”。

### 总结与可借鉴内容

带条件回答解决了什么、改变了什么、证据到哪里、何时值得借鉴。总结不设三句话上限，不用泛泛“未来可探索”收尾。个人项目建议、额外 Insight 与 Q&A 可以按需要追加；共同总结和迁移条件不可因这些附加栏目缺乏素材而省略。

## 方法、公式与原文

对学习方法分别解释：
- **训练**：起始模型、样本与监督来源、目标、更新/冻结对象、阶段产物及下一阶段怎么用。
- **推理**：可用输入、保留模块、状态/缓存、更新或采样、停止条件和最终输出。

不涉及训练的论文改为相应链条：理论的假设—推导—结论，数据的采集—标注—质检—用途，评测的输入—协议—评分—误差。论文未给的维度、采样规则、预算和超参保持未知。

公式先说明要解决什么问题，再给已核实的表达式和出处；紧跟白话解释变量对象、操作、目标与条件。必要时用玩具维度或数字演示，并标为教学构造。区分表达能力、优化是否能找到解、实验是否获益，不能把公式当性能保证。HTML 使用原生 MathML 或完整嵌入的离线渲染器，不能留无法显示的 LaTeX。

在关键定义、方法推导或实验段落处穿插原文带读：给小节/页码/图表锚点，解释该段在定义什么、提出什么假设、用什么证据、为何接到下一步。以释义为主，仅保留必要短引文。普通精读不要求逐段复印；用户点名逐段读某节时覆盖那一节全部段落。全文缺少段落材料时不能编锚点。

先解释图看哪里，再放已核实的原图或清楚标注的教学示意，图注讲输入、关键箭头和输出。图与正文相互补充；没有原图不阻塞文字理解，也不强造“原论文架构”。

## 读懂实验

对承重结果按“看哪里—比较什么—观察到什么—支持到哪里”解释：
- 核对任务、数据划分、指标方向/单位、模型规模、训练和推理预算、评测协议及基线。不可比的数值并列说明，不排统一榜。
- 保留原始精度与 Table/Figure/小节位置；分清百分点、相对百分比、倍数和错误率下降。模糊曲线不捏造精确值。
- 核心正负结果都覆盖，不能只摘最好 benchmark。平均提高不等于每类任务提高，训练省算力不等于推理更快。

为关键消融给出改变因素、保留条件、结果和结论。解释它排除了哪些替代解释，还有哪些没有排除。多因素同时变化时限制归因；未重复实验或无统计检验时不宣称统计显著。单篇可用小表，随后讲出结论，不把整张表抄来代替分析。

缺失状态要准确：已检查相关正文/附录但未报告、仅当前材料未见、因论文类型改用理论/质量/协议分析，三者不同。主榜领先不能代替组件消融。成本未披露就说明无法评估那项成本。

## 总结与迁移

将创新性、效果、可借鉴性、研究价值和应用价值写成有证据的判断，不强制打分：
- 相对哪个前作的哪个环节有变化；证据支持哪些能力、成本或认识。
- 可借鉴的具体对象是算法、数据构造、训练安排、评测协议还是负结果。
- 迁移需要什么输入、监督、数据分布、算力/延迟与工具条件；哪些条件不满足就不适合。
- 若用户需要复现建议，提出最小样本、必要对照与观察量，标“建议验证”；没有执行就不能写“已验证”。

保留清楚的结论与尚未解决的问题，避免把未验证应用说成落地成果。没有真实个人项目也可以总结一般迁移价值。

## 表达与交付

允许长篇。篇幅按理解难度分配，不设总字数、屏数、方法步骤或每节配额；删除重复，保留关键连接。自然中文、一段推进一个理解步骤、稳定术语、具体名词与动词。提问服务推理，不每段套问答，不以“颠覆/碾压”代替证据。

默认自包含 HTML 和同 stem 的公众号 Markdown；用户格式优先。HTML 标题可为“{论文简称} 阅读笔记”；源 PDF 文件名原样保留，只换扩展名。目录跟随实际章节，图、公式、来源都可回看。Q&A 只在确有易错点或用户需要时提供，用折叠附录且不默认互动。Markdown 精简重复和附录，保留八项主线、主要数字与条件。

## 验收

读者只看产物能否说明任务、旧方案卡点、本文切入点、输入到输出、训练与推理、主结果、关键消融和带条件总结？能否区分创新与沿用、实测与推测、适用与不适用？逐项回源检查，然后执行 HTML/伴随稿交付检查。标题齐全或篇幅很长都不代表通过。
