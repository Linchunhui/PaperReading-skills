> 一篇论文 → 一份深度的结构化 HTML 阅读笔记。
>

## 总目标（单篇特有）

输出一份*可直接当笔记长期保存*的结构化解读 HTML，并默认附一份 `{PDF stem}.wechat.md` 精简公众号版，让一个**不懂这个领域的聪明人**读完能复述三件事：

1. 论文在解决什么问题（具体到一个例子）
2. 作者用什么招数解的（机制 + 设计选择的理由）
3. 核心发现是什么（包括最反直觉的副发现，往往是论文里最 fascinating 的部分）

*可选*：Insight（七）、启发（八）、关键引用（九）三节都是<em>可选加分项</em>，默认全部略过。只有在论文确实满足各自的硬门槛时才写——硬挤这三节比不写更糟。

如果输出在前三件事上让外行卡住，就是失败。

## HTML 大标题（h1）怎么写

朴素直接：`{论文简短名} 阅读笔记` 即可。不追求凝练、不追求金句、不需要"灵魂句"——读者扫一眼就知道这是哪篇论文的笔记，就够了。

**模板**：

```
<h1>{论文简短名} 阅读笔记</h1>
<p class="subtitle">{论文原标题} — {第一作者等}, {年份}</p>
<p class="meta">{阅读日期} · <a href="{源链接}">原文</a> · <a href="{PDF 路径}">PDF</a></p>
```

**简短名怎么取**：

- 优先用论文里出现的*方法名 / 模型名*，保留原大小写：`SenseNova-U1`、`PreRL`、`LenVM`、`DeepSeek-R1`、`GPT-5`
- 如果论文没有方法名，用一个 2-4 词的英文核心概念：`Mixture of Experts Survey`、`Speculative Decoding`
- 如果是中文论文，可以直接用论文中文简称
- 不要在 h1 里加形容词、不要"惊人发现"、不要二次创作

简短名只用于 h1 和正文定位，**不参与输出文件命名**。文件名严格由源 PDF 的 basename 推导：`paper.pdf → paper.html`。

**正例**：`SenseNova-U1 阅读笔记`、`DeepSeek-R1 阅读笔记`、`Speculative Decoding 阅读笔记`

**反例**：
- ✗「无中介，方一体」（过度凝练，看不出是哪篇）
- ✗「关于多模态统一架构的探索性研究阅读笔记」（学术腔且重复）
- ✗「SenseNova-U1：把 VE/VAE 全拆掉的统一模型 阅读笔记」（方法描述塞进标题）

标题的核心职责是*定位*——让读者半年后翻笔记能一眼找到想看的那篇。思想的凝练交给 Insight 章节去做。

## 完整解读：十节结构化笔记

笔记的*完整解剖学*——产出一份让外行能跟、半年后还能查的结构化解读。每节用大白话，避免学术腔；该长就长，不要为了"短"砍掉读者真正需要的铺垫。

### 摘要（这篇工作在讲什么）

200-300 字的整体介绍，让读者*在进入 Motivation 之前先有一张全景地图*。这不是论文 abstract 的翻译，是你读完之后用大白话给一个聪明外行做的导览。

包含四个要点（不一定按顺序，融在自然行文里）：

1. *做了什么* — 这篇论文提出 / 研究的是什么（用一句话定位：「这是一篇关于 XX 的工作」）
2. *解决什么问题* — 一句话点出针对的核心痛点（细节留给 Motivation 展开）
3. *核心方法* — 用一句话概括方法机制（细节留给方法详解展开）
4. *关键结果* — 主要发现 / 提升 / 反直觉结论（细节留给实验结果展开）

写作要求：
- *不剧透洞见* — 摘要只给"这篇做了什么"。即使最后真写了 Insight，也放到第七节再揭开；摘要不剧透
- *不堆术语* — 必须出现的术语首次落地解释；外行扫一遍能跟上
- *200-300 字* — 短了讲不清全貌，长了就成了 Motivation 的预演
- *自带钩子* — 末尾留个让人想往下读的引子（「但作者发现……」「有意思的是……」）

写完后回头检查：单读摘要这一段，能不能让人对论文产生*三句话级别*的认知？「哦，这是做 XX 的，他们发现 YY，效果是 ZZ。」能 → 通过；不能 → 重写。

### 一、Motivation（这工作为什么值得做）

三段大白话，每段一个具体场景，不要写"为提升 XX 性能"这种空话：

1. *现实痛点* — 当前要解的是什么真实问题？给一个具象场景，让读者"看见"痛点。例：「你让模型写一篇 100 字的产品介绍，它写了 800 字还在收不住——明明任务描述写了字数」
2. *前人卡在哪* — 之前的工作做到了什么、卡在哪？卡点的*本质*是什么——是数字差，还是思路上的盲区？
3. *作者的入口* — 本论文从哪个角度切进来？为什么这个角度有戏？

这一节立的具象场景就是后面*所有节的锚点*。换锚点 = 读者前面建立的直觉全丢。

### 二、现存问题（前作的具体短板）

列 3-5 个前作的具体问题，每个一句话「问题是什么 → 后果是什么」：

- 问题 A：xxx → 导致 yyy
- 问题 B：xxx → 导致 yyy

不要泛泛说"已有方法效果不好"——必须落到具体机制上的具体短板。

### 三、相关工作翻译

挑论文 Related Work 里最重要的 3-5 个先驱方法，每个 2-3 句翻译解释：谁做的、做了什么；解决了什么、留下了什么；和本论文的关系（继承？反对？补充？）。用大白话重写，不照搬论文措辞。

### 四、方法详解

按论文章节结构展开（一般是 Section 3 / Method）。每个子模块讲清三件事：

1. *做什么* — 模块的输入输出
2. *怎么做* — 核心机制；必要时用 LaTeX 公式辅助（行内 `$L = ...$`、块级 `$$...$$`）。写完公式后*必须用一句中文翻译*这个公式在做什么（公式书写与渲染规范见 [`foundation.md`](./foundation.md) 的 KaTeX 节）
3. *为什么这么做* — 设计选择背后的考量。这一条最容易被忽略，但最值钱

*配图嵌入*：从配图提取步骤里拿到的图，按论文结构嵌入对应位置，并全部转成 base64 `data:image`。不要使用相对路径、绝对路径或远程图片 URL；不要堆图，每张图都要在正文里被讲到。

*SVG 流程图*（推荐）：方法整体的数据流、模块连接，用 SVG 画一张总览图放在本节开头。让读者先看到全貌再看细节。

每个子模块用类比和大白话，回到 Motivation 的锚点场景上讲：「在我们刚才那个场景上，这个模块在做什么？」

### 五、实验结果

*主结果一句话* — 在哪些 benchmark 上、达到什么水平、相对 baseline 提升多少。

*关键消融一两句话* — 重点是提炼"什么动作带来什么收益"的因果链：哪个组件最关键？（去掉它掉多少点）什么配置下效果最佳？什么情况下方法失效？

*SVG 可视化*：把表格里最有冲击的对比抽成 SVG bar chart——见 [`foundation.md`](./foundation.md) 的 SVG 节。一张消融对比 SVG 比把整个 LaTeX 表格搬过来有用十倍。

目标是给读者*启发性结论*——读完应该能脱口说出"哦原来 X 这么做能涨这么多"。

### 六、总结

三句话以内：①这篇论文最核心的贡献 ②它打开了什么新可能 ③它留下了什么未解的问题（如果作者自己提了 limitation，转述；没提，自己看）。

### 七、Insight（默认略过；只有真有结晶才写）

读完一篇论文先问自己：「这篇带走了一个什么具体的想法？」 大多数论文（尤其是工程改进、SOTA 推进、benchmark report）没有这种结晶——它们在已知方向上把数字推得更远，但没有打开认知层面的新东西。这种情况就*略过这一节*——不要在 HTML 里放一个空的或硬挤出来的 Insight 节。

不要把"论文 abstract 里讲的 contribution"当 insight。Contribution 是作者自己说自己做了什么；insight 是你读完之后自己*看见*的那个东西——往往论文里没直接讲、但逻辑指向它，而且*可以脱离这篇论文继续传播*。

**三条全部满足才写 Insight**：

1. **能用一句话说清楚**——不是一段话、不是几个 bullet、就一句话
2. **脱离论文还立得住**——把这句话抽出来贴墙上，对没读过这篇论文的人也有冲击力或启发
3. **不只是论文结论的复述**——必须是你的"再观察"，超出论文显式讲的内容

三条里任一不满足，就略过这一节。强行升华一个空洞的 insight 比不写糟得多。

如果你确实写了 Insight，可以选择性地把 h1 的 subtitle 调整一下让它和 insight 呼应（可选，不必须）。h1 主标题仍然是朴素的 `{论文简短名} 阅读笔记`。

### 八、启发（默认略过；门槛比 Insight 还高）

**这一节的默认状态是不写**。只有在论文里真有一个对你*手头正在做的某件事*的"立刻能动手"连接时，才写。

别把这一节当成"必须填充的笔记仪式"。读完觉得"挺有意思"、"以后说不定能用"、"值得思考"——这些<em>全部不够</em>，全部略过。

**三道自检题全部 Yes 才写**：

1. **具体到一个动作** — 你能说出一句"今天 / 明天我就可以做 X"——X 是 1-3 步可以开始的行动，不是"考虑一下"、"研究研究"、"也许将来"
2. **针对一个真实存在的项目** — X 是接到你正在做的某个具体项目 / 系统 / 代码上的，不是假设
3. **论文里真有这个连接** — X 是论文的某个机制 / 数据 / 设计选择*直接*驱动出来的，不是你借论文为引子讲自己的想法

三道里有一道答 No → 略过整节，连"暂无可直接迁移的启发"这种敷衍话都不要写——空着就是答案。

如果三道全过，给一到两条（不要超过两条），每条按"动作 + 论文里驱动它的具体机制"的格式写：

```
* 我可以试试在自己的 GUI agent 里加一个"+1 步屏幕预测"的 latent loss——OneVL 的
  visual auxiliary decoder 设计直接告诉我：这种物理性监督比纯语言 latent 监督
  有效得多（论文实测 +0.87 vs +0.31）。
```

绝大多数论文不会触发任何启发，这是正常的——而且<em>恰恰证明你的判断标准是健康的</em>。每十篇论文里能有一两次写出真正能动手的启发，已经是非常好的命中率。

### 九、关键引用（默认略过；只在论文里真有"贴墙上"的句子时才写）

很多论文通篇都是程序性描述、客气话、方法步骤——没有任何一句话值得被单独抽出来贴到墙上。这种情况就*略过这一节*。

**判断标准只有一句话**：这篇论文里有没有<em>至少一句话，单独抽出来贴在墙上，能让没读过这篇论文的人也读完愣一下、记住一年</em>？没有 → 整节略过。

如果有，挑 1-3 处（不超过 3 处），原文 + 中文翻译并列。挑选时三类常见诱惑必须避开：

- ✗ **abstract 里的客气话**："We propose a novel..." / "Extensive experiments demonstrate..."
- ✗ **方法描述的程序性段落**："The encoder takes X as input and outputs Y..."
- ✗ **实验数字陈述**："Our model achieves X% on Y benchmark"

只算：作者真正给出*新视角、新断言、新隐喻、对自己 limitation 的诚实声明*的句子。论文里这种句子通常 0-3 句。

格式：

```
[Section X.Y] "Original verbatim quote here..."
译文：xxx（用大白话翻译，不要直译）
```

HTML 里这部分用左侧色条 + 浅底色突出（`blockquote.quote`），原文与译文上下排列。

### 十、Q&A

模拟一个对这个方向有研究的面试官，审视读者是否真懂这篇论文。*5-10 道就够*——挑论文里最值得深挖的几个点出题，不必凑数，宁可少而精。

问题主要围绕以下几类（哪类适用就出哪类，不必每类都覆盖）：

- *模型结构* — 模型整体长什么样？由哪些模块组成？模块之间怎么连？
- *输入输出* — 输入是什么形态？输出又是什么？维度、形态、含义？
- *训练数据* — 用了什么数据？数据从哪来？怎么收集 / 构造 / 清洗 / 标注？规模多大？
- *训练流程* — 训练分几个阶段？每个阶段做什么？为什么要分阶段？阶段间怎么衔接？
- *训练策略* — 用了哪些关键策略（loss 设计、采样策略、数据配比、学习率调度、正则手段、奖励建模）？每个解决什么问题？
- *具体方法* — 论文的核心方法是什么？*怎么理解*这个方法在做的事（用类比、用直觉、用变形）？为什么这么设计？
- *实验细节* — 在什么数据上评测？baseline 选了哪些？关键超参怎么设？硬件 / 算力规模？训练多长时间？复现需要注意什么坑？
- *实验结果引发的思考* — 某个数字反映了什么本质问题？某个对照实验意外地证明 / 推翻了什么？哪个结果让人意外、意味着什么？

也可以包含一些开放性的延伸问题：方法什么时候会失效？哪个假设最薄弱？能迁移到 XX 场景吗？和 YY 方法结合会怎样？

每个问题都给*参考答案*——不是标答，是引导思路。答案要扎实、能站住脚，不能含糊敷衍。开放性问题给出*作者自己的思考方向*而非"见仁见智"。

HTML 里 Q&A 推荐做成可折叠（accordion）：点击问题展开答案，鼓励读者先想再看。格式 `*Q1*：xxx？` / `*A*：xxx`。

## HTML 结构模板

```
<header>
  <h1>{论文简短名} 阅读笔记</h1>
  <p class="subtitle">{论文原标题 / 必要时中文兜底} — {作者}, {venue}</p>
  <p class="meta">{日期} · <a href="{源链接}">原文</a> · <a href="{PDF 路径}">PDF</a></p>
</header>

<main>
  <section id="abstract">摘要（200-300 字全景导览）</section>
  <section id="motivation">一、Motivation</section>
  <section id="problems">二、现存问题</section>
  <section id="related">三、相关工作翻译</section>
  <section id="method">四、方法详解（含配图、SVG、公式）</section>
  <section id="experiments">五、实验结果（含 SVG 对比图）</section>
  <section id="summary">六、总结</section>
  <section id="insight">七、Insight（默认略过）</section>
  <section id="inspiration">八、启发（默认略过）</section>
  <section id="quotes">九、关键引用（默认略过）</section>
  <section id="qa">十、Q&A（accordion）</section>
</main>

<aside id="toc">侧边目录（桌面端固定，移动端折叠）</aside>
```

## 执行流程

1. **获取内容** — 见 [`foundation.md`](./foundation.md) 的「获取内容」节：拿标题/作者/摘要/Related Work/Method/Experiments/Limitation；提取承重配图
2. **完整解读** — 按上面十节结构写正文（七、八、九默认略过）
3. **过红线** — 见 [`foundation.md`](./foundation.md) 的「过红线」节
4. **生成 HTML** — 直接生成单文件 HTML；如果当前环境提供前端设计技能，可调用它协作。CSS 起手式用 [`../assets/style.css`](../assets/style.css)。保存到 `Path(pdf_path).with_suffix(".html")`
5. **嵌入图片** — `python3 scripts/embed_images.py "{输出.html}" --in-place`
6. **硬校验** — `python3 scripts/validate_html.py "{输出.html}" --source-pdf "{源.pdf}"`；失败就修到通过
7. **公众号版** — 按 [`wechat-markdown.md`](./wechat-markdown.md) 从同一证据生成 `{PDF stem}.wechat.md`；只保留问题、核心机制、关键发现与边界，不照搬十节目录

## 验收清单（单篇）

- *h1 朴素* — `{论文简短名} 阅读笔记`，副标题给完整原标题 + 作者 + 年份
- *文件严格同名* — HTML 与 PDF 位于同目录，basename 完全一致，只把 `.pdf/.PDF` 换成 `.html`
- *摘要先行* — 正文最前面一段 200-300 字，覆盖"做了什么 / 解决什么 / 核心方法 / 关键结果"，不剧透洞见
- *锚点贯穿* — Motivation 立的具象场景在方法详解里被反复回到，没有换地图
- *Motivation 落地* — 用具体场景而非"为提升性能"等空话；前作短板讲到机制层
- *方法详解配图齐* — 关键架构 / 流程图已提取并嵌入；每张结构图边界完整、清晰可读、单张 ≤ 300 KB；公式后必有中文翻译
- *SVG 数据准确* — 每个数字都能在论文 Table/Figure 里找到对应单元格；末尾标 "Source: ..."；不四舍五入、不混淆 open-source / closed-source 对比段
- *实验有 SVG* — 至少一张承重 SVG（消融对比 / 主结果 / 流程图），不是把表格搬过来
- *Insight 默认略过* — 七节默认不写。只有三条全满足（一句话、脱离论文立得住、不只是结论复述）才写；工程改进 / SOTA 推进类论文绝大多数应略过
- *启发门槛更高* — 八节默认不写，三道自检题全 Yes 才写；连"暂无可迁移启发"都不要写，空着就是答案
- *Q&A 5-10 道、围绕实质问题* — 覆盖模型结构 / 输入输出 / 训练数据 / 训练阶段策略 / 具体方法 / 实验细节 / 实验结果思考（哪类适用出哪类），每题有扎实参考答案
- *关键引用默认略过* — 九节默认不写。判断标准是"有没有至少一句贴墙上能让人记住一年的话"——没有就整节空着。有则挑 1-3 处原文 + 中文翻译
- *外行能跟* — 不懂这个领域的聪明人读完能复述三件事：问题（具体到一个例子）/ 解法（机制+设计理由）/ 核心发现（含反直觉副发现）
- *公式都翻译 + 都渲染* — 每条 LaTeX 后有一句中文白话说明；*打开 HTML 肉眼确认所有公式正常渲染*，没有 `$...$` 裸露、没有红色报错
- *HTML 可读、不臃肿* — 单文件可独立打开，所有 `<img src>` 为合法 base64 `data:image`，SVG 内联，Q&A 折叠展开，移动端不破版；总大小最好 ≤ 2 MB
- *零割裂感* — 读完像一个人在跟你说「我读了篇论文，发现了个有意思的事」
