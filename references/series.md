# 模式二 · 系列（series）

> 2-6 篇**同系列**论文 → 一份串成一条线的演进综述 HTML。
>
> 触发：用户一次性给出 ≥ 2 个明确属于同一系列的论文（V-JEPA + V-JEPA 2 + ...、π₀ + π₀.₅ + ...、GPT-3 + GPT-4 + ...、DeepSeek-V2 + V3 + R1），或说「总结一下 XX 系列」「梳理 XX 演进」「汇总」「编年史」「从 X 到 Y」「evolution」，或在 prompt 里指定模式关键词 **系列**。
>
> 这个模式建立在 [`foundation.md`](./foundation.md)（共享的红线 / 原则 / SVG / KaTeX / 截图 / 获取内容规范）和 [`single-paper.md`](./single-paper.md) 的肩膀上：单篇论文的解读规范、12 条红线、4 条写作原则、KaTeX 公式准则、截图规范、per-paper 彩色卡片样式**全部沿用**，不重复声明。本文件只补充「多篇 → 一篇综述」特有的部分。

## 总目标（系列特有）

读一个系列不是把每篇笔记拼起来，是把它们**串成一条线**——让读者一眼看到从第一篇到最后一篇之间，作者一步步在叠加什么、推翻什么、绕过了什么。

输出一份让外行也能跟下来的系列演进 HTML，并默认附一份 `{系列名}.wechat.md` 精简公众号版，让读者读完能说三件事：

1. 这个系列在解决什么大问题（一句话）
2. 每一代叠加 / 推翻了什么（用一张对照表 + 一条时间线 + 每篇彩色卡片就能讲完）
3. 整条演进的"贯穿线"是什么

如果读者读完只能复述每篇做了什么、却说不出"从 A 到 B 这一步关键差异是什么"——这份笔记就失败了。

典型成品可以覆盖 JEPA（V-JEPA → V-JEPA 2 → V-JEPA 2.1 → LeJEPA）或 π（π₀ → π₀.₅ → π₀.₆ → π₀.₇）这类四代演进。

## 与单篇的关系

| 项目 | 单篇（single-paper） | 系列（series） |
|------|------|------------------|
| 输入 | 1 篇论文 | 2-6 篇同系列论文 |
| 输出文件 | `{PDF 原 basename}.html` | `{系列名}.html`（如 `JEPA.html`、`pi-series-evolution.html`） |
| 章节焦点 | 单篇的 Motivation/Method/实验 | 系列的演进叙事 + 每篇精简版的 Mot/Met/Findings |
| 核心可视化 | 单图一个 insight | 时间线 + 横向对照表 + 演进矩阵 |
| 文字密度 | 该展开就展开（外行能跟） | 每篇压到 1-3 屏；整体读时长 ≈ 一篇精读 |
| 红线 / 写作原则 | 12 条红线 + 4 条原则 | **沿用，不重复声明** |
| 公式 / SVG 准则 | KaTeX + 数据准确性 | **沿用** |

**复用而非重读**：如果系列里某些论文用户已经有单篇笔记（HTML 或 markdown），直接读那份并蒸馏，不要重新去啃 PDF——节省时间也保证一致性。

## 触发判断

只有 1 篇 → 走单篇模式。2 篇但话题不相关 → 拒绝合并，分别走单篇模式（或者若互相独立，走随笔模式）。下面这些信号出现，就用系列模式：

- 用户一次性给出 ≥ 2 个明确属于同一系列的论文
- 用户说"总结一下 XX 系列 / 梳理 XX 演进 / 汇总 / 编年史 / 从 X 到 Y"
- 用户指着已有的几份单篇笔记说"合成一份综述"

## HTML 大标题怎么写

朴素直接，三种格式任选最合身的：

- `{系列名} 系列阅读笔记`（如 `JEPA 系列阅读笔记`）
- `{系列名} 演进汇总`（如 `π 系列演进汇总`）
- `{系列名}：{第一篇} → {最后一篇}`（突出范围时用）

副标题给出所覆盖论文的简明列表 + 时间范围。**不要**在 h1 里加形容词、不要"惊人发现"、不要二次创作——和单篇一样朴素就够。

模板：

```
<h1>{系列名} 系列阅读笔记</h1>
<p class="subtitle">{论文1} · {论文2} · {论文3} · {论文4} — {作者/团队}, {年份范围}</p>
<p class="meta">{阅读日期} · {N} 篇论文整合 · 来源 PDF 见 ...
  · 独立笔记：<a href="...">{论文1}</a>·<a href="...">{论文2}</a>...
</p>
```

## 必备结构（按出现顺序）

下面是这份 HTML 的*骨架*——按这个顺序写，别打乱。每一节都讲清"为什么必须有"。

### 1. 摘要 / 导读（`<section id="intro">`）

200-300 字 + 一张**时间线 SVG**。

- 文字部分：先一句话定位系列要解决什么大问题；再一句话给出*整条演进的金句概括*（如 `π` 的"π₀ 把 VLM 接上动作输出；π₀.₅ 让它走出实验室；π₀.₆ 用真机经验突破示教天花板；π₀.₇ 让一个通用模型吃下所有脏数据"）；最后一句话留钩子。
- 时间线 SVG：横轴时间、每个节点是一篇论文，节点下面挂 3-5 行小字（机型 / 数据 / 关键变化）。底部再画 N 个"叠加块"显示*每一步在原有基础上加了什么*。

时间线模板见 [`svg-patterns.md`](./svg-patterns.md)。

### 2. 横向对照表（`<section id="table">`）

一张 `<table class="cmp">`，行=维度（8-12 行），列=论文（2-6 列）。

必备维度（按论文性质增删）：发布时间、模型主干 / 参数规模、数据（量级 + 来源 + 处理方式）、训练方式 / 阶段、核心招数（一句话）、关键能力 / benchmark 数字、（可选）超参 / 推理速度 / 关键限制。

**写作要求**：
- 每个单元格 ≤ 30 字，长则拆 `<br>`；
- 第一列加粗作"维度名"，列头用彩色 `pill` 标论文名；
- 不要把所有数字塞进来——挑*最能体现差异*的；
- 沿用了上一代的写"沿用 X"或"同 X"，不要重复抄一遍。

### 3.（可选）共享的核心思想（`<section id="core">`）

只有当所有论文都建立在某个共同基石上时才写（例：JEPA 系列全部基于"特征空间预测"；π 系列全部基于"VLM + flow matching"）。**一节 200-400 字 + 一张概念图 SVG**。如果系列内部已经分叉、没有共同基石，直接跳过这节。

### 4. 每篇论文的彩色章节卡片（`<div class="chapter {color}">`）

每篇 1 张卡片，卡片内部 3 个子 section：
- `#{shortname}-mot` 出发点（2-4 段，每段一个具体场景）
- `#{shortname}-met` 方法详解（**必含架构 SVG + 分步骤讲解 + 公式带白话翻译**，见下方硬要求）
- `#{shortname}-exp` 关键发现（最有冲击的 1-3 个数字 + 1 张承重 SVG 或表格）

**章节卡片样式**（CSS 见 [`../assets/style.css`](../assets/style.css)）：
- `border-left: 6px solid var(--{color})` 让一眼看出第几代
- 卡片顶部一行 `tagline`：用一句话概括这篇的"差异化定位"
- 内部子标题统一 `<h3>`，颜色用 `--accent` 即可（不要每个子标题再换色，会乱）

**复用单篇笔记**：如果用户已有这篇的单篇产物，*从那份笔记蒸馏到这三段*，而不是回去读原 PDF。蒸馏标准：原单篇笔记 8-15 屏，蒸馏到这里 1-3 屏，**但方法详解（met）这一段不能压得太狠**——架构图、结构讲解、公式翻译这些都得留，只能删"为什么这么做的次要理由""相关工作背景"这类外围内容。

#### 方法详解（met 子节）的硬要求

写系列综述最容易出问题的就是 met 子节——很多人把方法压成几句话「用了 XX 架构 + XX 训练」，读者读完只知道<em>名词</em>不知道<em>样子</em>。met 子节的目标是：**让没读过原文的人读完能在脑子里"画出"这个模型**。三个硬要求：

**(a) 必含一张架构图，<u>优先用原论文截图</u>，不是自己画 SVG**

每篇 met 子节的<strong>开头第一件事</strong>就是放一张架构图。**默认从原论文里截一张** Figure X 当架构图——理由很简单：原图是作者亲自画的，参数规模 / 维度 / 模块名 / 数据流向都对，没有臆造风险；截图能让读者直接和论文 PDF 对上号；自己画的 SVG 容易在"画好看"和"忠实"之间偏向前者，反而失真。

**怎么截**（沿用 [`foundation.md`](./foundation.md) 的截图规范，再加这些）：
- 用 `pdftoppm -png -r 200 -f {N} -l {N} {paper}.pdf {prefix}` 把目标页转成 200 dpi PNG
- 用 Pillow / sips 裁切到只剩"架构图 + caption"——caption 是论文作者写的文字说明，必须保留；论文正文、页眉页码必须排除
- 输出 JPEG quality 85-90，目标单张 100-250 KB
- 临时命名可用 `{shortname}-arch.jpg`；生成 HTML 时转成 base64，不保留路径引用
- HTML 引用模板：
  ```html
  <figure>
    <img src="data:image/jpeg;base64,{BASE64_PAYLOAD}" alt="{模型名} 架构图">
    <figcaption>{模型名} 架构（原论文 Figure {N}）：{一句话讲清这张图的<em>看点</em>——
    输入怎么进，主干由谁组成，模块之间怎么连，输出怎么出，训练/推理差别在哪}</figcaption>
  </figure>
  ```
- **figcaption 必须自己写**，不要照抄论文的 caption；论文 caption 通常是「Figure 4: Model Architecture of X. The model takes ...」这种学术腔，你要写成「这张图的看点是什么、和上一代差在哪」这种导读语气

**截图质量红线**（满足才能用）：完整（图里所有元素都裁进来）、干净（没有正文/页眉/脚注/页码/其他 figure）、清晰（200 dpi 起步，文字看得清）、带 caption（原论文 figure caption 一起截进来）。

**什么时候才自己画 SVG**（例外情况，少用）：原论文没画架构图（罕见）；原论文图太复杂、信息密度太低；你要画的是"跨论文的对照图"（如 4 代架构演进矩阵）——这种本来就不属于"某一篇的架构图"，放 `#threads` 节而不是 met 节，画 SVG 是合理的。

详细的「转页 → 裁切 → autotrim → 压缩」脚本和截图质量逐条检查见 [`svg-patterns.md`](./svg-patterns.md) 的「模型架构图」一节。

**(b) 必含分步骤讲解（h4 拆分）**

架构图下面用 `<h4>` 把方法拆成 4-7 个小节，每个 h4 对应架构图里的一个模块或一个机制：

```
<h4>(1) 整体结构：XXX</h4>      ← 对应架构图的解读
<h4>(2) 模块 A：XXX</h4>        ← 主干怎么工作
<h4>(3) 模块 B：XXX</h4>        ← 关键创新点
<h4>(4) 训练目标</h4>           ← loss 公式 + 白话翻译
<h4>(5) 训练 / 数据 / 推理 trick</h4>  ← 看篇幅
```

每个 h4 段落 100-300 字，扎实讲清那一块"在干什么、为什么这么干、和上一代/同期方法的差别"。不要写「该模块的作用是 XX」这种学术腔总结句——直接讲清楚机制。

**(c) 公式必有白话翻译**（沿用红线 10）

每条 LaTeX 公式后必须紧跟一段中文白话翻译，<strong>必须用 `<p class="note">` 包起来加粗"白话翻译"开头</strong>：

```html
<p>$$\mathcal{L} = ...$$</p>
<p class="note"><strong>白话翻译</strong>：第一项让 XX 学 XX；第二项让 YY 学 YY；
$\lambda$ 控制 XX；……</p>
```

翻译要求（详见 [`foundation.md`](./foundation.md) 的 KaTeX 节）：不复述公式；解释每个符号实际指什么；解释公式的设计意图；必要时给"如果去掉某项会怎样"的反事实。

如果系列里多篇都用同一个公式范式（比如大量用 flow matching），后面几篇可以简短带过「沿用 XX 的 flow matching loss，区别只在 $\lambda$ 调到 XX」，但<em>第一次出现时必须完整翻译</em>。

**配图策略**：
- *架构图 = 原论文截图*（met 子节开头那张）。每篇 1 张是基本盘；如果论文同时给了"整体架构 + attention mask"或"训练/推理对照"这种关键副图，可以再加 1 张
- *承重图 = 原论文截图或 SVG 重画*（exp 子节里展示数字差距用）。如果论文里有干净的 bar chart 可以直接截，否则用 SVG 重画（这样能配章节主色、能聚焦"和上一代差多少"）
- *跨论文对照图 = SVG*（贯穿线节）。多篇之间的演进矩阵、Scale 散点这类图原论文本来就不会有，必须自己画 SVG
- 截图先以临时文件处理；JPEG quality 85-90，单张 100-300 KB；最后全部嵌入为 base64，最终 HTML 最好 ≤ 2 MB

### 5. 贯穿线（`<section id="threads">`）

把系列里 2-4 条*贯穿所有代际*的演进线索单独抽出来讲。每条一段：

- **线 X：XXX 的演化** —— 描述这条线在 4 代之间是怎么演变的
- 可选：每条线配一张 SVG（如"参数规模 vs 数据规模"散点 / "架构 + 损失对照矩阵"）

JEPA 系列的例子：线 1 Scale 路线 / 线 2 架构+损失的演化（横向对照矩阵 SVG）/ 线 3 从经验工程到理论闭环。
π 系列的例子：线 1 数据从干净示教 → 失败/rollout/人类视频 / 线 2 训练范式 SFT → 异构 co-training → RL → prompt expansion / 线 3 架构单模型 → 高层+低层 → 加世界模型。

### 6. 三句话总结（`<section id="summary">`）

字面上的三句话：①这个系列在做什么 ②它走到了哪里 ③它的核心方法论是什么。短、准、能引用。这是收尾——写完它就结束，<strong>不要再续"反直觉发现 / 留下的问题 / 未来工作"</strong>。

### 7.（可选）Q&A（`<section id="qa">`）

只在用户特别要求或系列特别复杂时才加。沿用单篇的 accordion 格式与出题原则。

> **过去版本里的 "反直觉发现" 和 "留下的问题" 两节已删除。** 这两节常常变成硬挤、流水账或臆测未来；正文里的 met / threads / summary 已经能承担全部叙事职责。如果某条反直觉的洞察非常承重，把它<em>融入到对应论文的 exp 子节或贯穿线段落里</em>，不要单独立节。

## 视觉风格规范

继承单篇的字体 / 配色 / KaTeX / 双语引用块设定，**额外约定**：

### 配色：每篇一种主色

为系列里每篇论文分配一种主色——RGB 选*相邻但区分度够*的色相：

JEPA 系列示例：`--vj: #6b8fbf`（蓝灰）/ `--vj2: #62b88f`（绿）/ `--vj21: #e08e45`（橙）/ `--le: #c4636e`（玫红）。
π 系列示例：`--pi0: #5b8def` / `--pi05: #62b88f` / `--pi06: #e08e45` / `--pi07: #c4636e`。

主色用在：章节卡片 `border-left`、时间线节点、对照表的 `pill` 列头、章节里小标记。**正文颜色不要染**——只染*结构性*位置，否则页面眼花。

### 布局

正文主列 max-width 880px；右侧 TOC `position: fixed; width: 220px`（≥1240px 显示，否则隐藏）；TOC 两级（lvl1 加粗、lvl2 缩进）；正文行距 1.78，字号 17px。

### 代码块（展示 ASCII 时间线或公式片段时）

必须用 `.code-block` 类（深色背景），不能裸贴。见 [`../assets/style.css`](../assets/style.css)。

## SVG 模板（必画的三张）

详见 [`svg-patterns.md`](./svg-patterns.md)。必画清单：

1. **时间线 SVG**（在 `#intro`）—— 横轴时间，节点 = 论文；底部"叠加块"显示每代加了什么
2. **横向对照矩阵 SVG**（在 `#threads`，可选）—— 行 = 维度，列 = 论文，单元格用绿色 `+新增` / 红色 `−推翻` / 灰色 `沿用` 标记
3. **至少一张承重 SVG**（在每篇的 `#{shortname}-exp` 里）—— 把"和上一代相比涨了多少"用 bar chart 抽出来

**数据准确性红线和单篇一样**：每个数字必须能在论文里找到出处；末尾标 `Source: Table N of paper X`；不四舍五入；不混 closed/open-source 对比段。

## 工作流

### Step 1: 识别系列并收齐材料

- 用户给的论文 / 已有笔记，挨个确认它们*属于同一系列*——不属于的拒绝合并（独立则考虑随笔模式）
- 列出每篇的：标题、年份、PDF 路径、是否已有单篇产物（HTML / md）
- 选定系列简称（`JEPA`、`pi`、`DeepSeek-V` 等），决定输出文件名

### Step 2: 复用 vs 读

对每篇：
- 已有单篇产物 → 读那份 HTML / md 蒸馏（不要回去啃 PDF）
- 没有产物 → 走简化版单篇：只精读 Abstract / Method / Experiments 的关键段，目标是支撑这里 3 段（出发点 / 方法 / 发现）即可

### Step 3: 找演进叙事

三个问题问自己：①这个系列在解决的*那个大问题*是什么？（一句话）②第一篇到最后一篇之间，*关键的跨步*在哪几步？每一步是叠加、推翻、还是绕过？③有没有 2-4 条贯穿线？

这一步*非常重要*——叙事不出来就硬写综述，写出来的就是流水账。必要时回去翻论文里的 "Discussion" 或 "Related Work" 部分找作者自己怎么定位差异。

### Step 4: 画对照表

8-12 行 × N 列。先列维度，再逐列填。原则：差异显著的维度才进表；沿用显式标"沿用 X"；数字精确到论文原文（不四舍五入）。

### Step 5: 选配色 + 收集配图

- 每篇分配一种主色，相邻论文用相邻但区分度够的色相
- 每篇最多挑 1 张论文截图（架构图或最有冲击的图）
- 截图必须边界完整、清晰可读、单张 ≤ 300 KB

### Step 6: 写 HTML

按上面"必备结构"的 1-6（+可选 7）节顺序写。每写完一节先在脑子里过一遍 12 条红线，再继续下一节。

写完运行 `python3 scripts/embed_images.py "{输出.html}" --in-place`，把所有截图路径替换成 base64。

### Step 7: 验收

先运行 `python3 scripts/validate_html.py "{输出.html}"`，再按下面的检查清单逐条过。

### Step 8: 公众号版

按 [`wechat-markdown.md`](./wechat-markdown.md) 把演进线压成 4–6 节：大问题、关键代际跨步、最新一代、整条线的结论与边界。默认输出 `{系列名}.wechat.md`，不搬运横向大表。

## 输出路径

- *主输出 HTML*：放在源 PDF / 已有单篇笔记同目录，文件名 `{系列简称}.html`
  - 例：`./JEPA.html`
  - 例：`./pi-series-evolution.html`
- *若来源全是 arXiv URL*：放到用户指定的输出目录；未指定时放当前工作目录，命名 `{系列简称}.html`

## 验收清单（系列）

- *h1 朴素* — `{系列名} 系列阅读笔记` 或类似格式；副标题列出所覆盖论文 + 时间范围
- *摘要 + 时间线 SVG* — 导读段 200-300 字概述整条演进；时间线 SVG 节点完整、底部"叠加块"清晰
- *对照表完整* — 8-12 行 × N 列；沿用项显式标"沿用"；数字精确到论文原文；列头用彩色 `pill`
- *每篇彩色卡片* — `border-left` 用该篇主色；卡片内三个子 section（mot / met / exp）齐全；每篇 1-3 屏，不超 5 屏
- *每篇 met 子节必含架构图，<u>默认用原论文截图</u>* — 不是流程图，是<em>架构图</em>，要看清输入/主干模块/连接方式/输出/训练-推理差别。先去原论文截一张 Figure X（200 dpi、裁切到只剩"图 + caption"、单张 100-300 KB），用 `<figure><img><figcaption>` 引用并把图片嵌入 base64，figcaption 自己写导读语。只有原论文确实没架构图或图太烂时才退而求其次自己画 SVG
- *每篇 met 子节按 h4 分步骤展开* — 4-7 个 h4 小节，每个对应架构图里的一块；不允许把方法压成几句话就完事
- *公式必有白话翻译* — 每条 LaTeX 公式后紧跟 `<p class="note"><strong>白话翻译</strong>：...</p>` 段；翻译必须解释符号含义、设计意图，不能是公式的复读；沿用红线 10
- *复用单篇笔记* — 系列里已有单篇产物的，*从那份蒸馏*；header 里给出原笔记的 `<a href>` 引用。注意：蒸馏可以压缩篇幅，但 met 子节的架构图 / 分步骤讲解 / 公式翻译三项不能因为压缩而丢
- *贯穿线 2-4 条* — 每条一段；必要时配一张 SVG
- *三句话总结* — 字面上的三句话，短、准、能引用；写完它就结束，不要再续"反直觉发现 / 留下的问题 / 未来工作"
- *SVG 数据准确* — 每个数字能在论文里找到出处；末尾标 `Source: ...`
- *配图限额* — 架构图全部从原论文截（met 子节开头，每篇 1 张）；exp 子节的承重图可截可画；贯穿线节的跨论文对照图必须自己画 SVG；所有位图 base64，最终 HTML 最好 ≤ 2 MB
- *代码块独立样式* — 用 `.code-block` 类（深色背景），不能裸贴
- *公式都渲染* — 打开 HTML 肉眼确认 KaTeX 没有报错、没有 `$...$` 裸露
- *TOC 完整* — 桌面端固定右侧；包含所有 lvl1（导读 / 对照表 / 每篇 / 贯穿线 / 总结）+ lvl2（每篇的 mot/met/exp）
- *外行能跟* — 不懂这个领域的聪明人读完能复述：系列在做什么 / 每代叠了什么 / 整条线的方向是什么
- *零割裂感* — 读完像一个人在跟你讲「这一系列我读完了，给你串一串」
