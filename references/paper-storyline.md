# 论文主线：覆盖一致，展开程度按模式调整

单篇、同方向串讲和雷达的每篇正式解读，都保留下面八项信息。模式改变讲解深度与组织方式，不改变应回答的问题。总览导航卡、首页摘要和明确要求的仅摘要输出只负责入口，不冒充完整解读。

## 八项必备信息

| 内容 | 应回答的问题 | 最小完整表达 |
| --- | --- | --- |
| 背景 `background` | 什么任务或场景使这项工作值得做？ | 给必要情境和任务对象，不写领域通史。 |
| 方向 `direction` | 本篇贡献属于什么方向、具体任务或子问题？ | 在元信息或开头给有依据的方向与任务；不能因相关工作提到 RL 就标成 RL。 |
| 问题 `problem` | 旧方案怎么做，具体卡在哪里，造成什么后果？ | 连起前作做法、剩余缺口与本文目标；不把方法名当问题。 |
| 解决思路 `approach` | 作者决定改变哪个环节，为什么可能缓解瓶颈？ | 解释切入点及与最相关前作的变化；作者解释与讲解者推断分开。 |
| 具体方法 `methods` | 输入经过哪些关键操作成为输出？ | 走通操作链，解释各步对象、变换、衔接与必要性；适用时区分训练与推理。 |
| 主结果 `results` | 得到了什么，证据在什么条件下成立？ | 给任务/数据、对照、指标方向、关键原始值或定性/理论结果、必要预算与来源位置。 |
| 消融或分析结论 `ablations` | 哪些设计有效、无效、饱和或存在代价，证据支持到哪里？ | 单独呈现关键结论及必要数字、对照条件；没有相应证据时明确状态。 |
| 总结 `summary` | 最终解决了什么，核心变化是什么，还受什么限制？ | 带条件收束问题、机制和发现；指出可借鉴内容与成立条件，不复写摘要。 |

这些是内容职责，不强制八个标题或八张等高卡。背景与问题可以合讲，方向可以放标签，思路可以引出方法；主结果与消融须能分别找到，总结不能被总报告的 recap 代替。多项独立核心贡献都保留，不只挑标题里的卖点。

摘要由已读材料提炼“背景/任务—问题与前作缺口—切入点—操作链—主结果与范围”，不藏结论，不堆消融清单。消融放在正文自己的位置；有摘要不等于八项正文已经完成。

## 内容完整与深度的区别

| 模式 | 保留的共同内容 | 重点展开 | 可以压缩 |
| --- | --- | --- | --- |
| 单篇精读（融合版） | 八项主线与证据边界 | 贯穿例子、方法各环节与设计理由、训练/推理、必要公式、原文论证、主结果与消融 | 已讲清的熟悉组件、重复结果和无关配置 |
| 同方向串讲 | 每篇的八项主线 | 共同问题下的演进、竞争或互补路线，以及各自取舍 | 共享背景与沿用机制，可明确回指后突出变化 |
| 雷达发现 | 每篇的八项主线 | 最小完整方法、关键结果、关键消融结论、可复述总结 | 完整文献史、逐段带读、完整推导、配置大全、重复 benchmark |

默认雷达比单篇紧凑，但不能退化成“问题一句＋方法名＋最好分数”。复杂核心机制仍须展开；用户指定深读时，增加例子、推导与对照解释。Top picks 表示阅读顺序，不能成为其他篇缺项的理由。篇幅随复杂度增加，不设总字数、单篇字数、屏数或方法步骤数的默认配额；用户明确的短版与范围限制优先。

## 方法要讲到哪里

先用一句话说明解决思路，再走完整操作链；箭头流程是路线图，不能替代步骤解释。用必要的段落或编号步骤说明：

- 对训练方法：各阶段的起始模型、数据/监督、目标、训练或冻结对象、产出及下一阶段如何使用；只写影响理解的部分。
- 对推理方法：运行时输入与状态、关键更新/采样、停止条件及输出。
- 核心公式有助于理解目标、状态更新或评分时保留，并解释变量、操作和成立条件；不为技术感加装饰公式。
- 读者仍不能恢复操作时补一个最小例子。自造数值标为教学示例，不作为实验结果。
- 只读产物，先复述输入到输出，再回源核对。可理解性检查和事实检查不能互相代替。

## 消融要产出结论

先检查可得的消融、敏感性、诊断与失败分析，再挑决定理解的发现，兼顾关键设计、负结果、收益饱和和成本。主排行榜上的胜出不能充当组件消融。

雷达用短要点，结论先行：**哪种设计在什么条件下有效/无效**，随后给改变的因素、必要原始值、保持不变的条件及 Table/Figure 定位。简单结论无需复杂表格。单篇可进一步解释实验为何这样设、它排除了什么替代解释。

“证明各模块有效”“提升明显”不算消融结论。同时变化的数据、参数规模或预算必须写出，不能将收益全部归给一个组件；没有重复实验或统计检验，不宣称统计显著。

消融缺失时，分别处理：

- 已核对相关正文和附录，未报告组件消融：说明无法据此判断独立组件贡献。
- 只获得部分材料：写“已获取材料未见，相关章节/附录未核对”，不能断言论文没做。
- 理论、数据、评测或综述论文：使用对应的假设/反例、质量验证、协议敏感性、误差分析或分类证据，并明确这是相应分析，不伪称组件消融。

## 总结、迁移和证据

总结必需；额外 Insight、个人项目行动和金句可选。可借鉴性可以来自方法、数据构造、评测或负结果，不要求一定对应一个马上动手的个人项目。写清哪些条件满足时值得试、哪些尚未验证；没有支持就说明判断受限，不硬造用途。创新性和效果判断落到具体前作与证据，研究价值与应用条件可以自然融入，不强制每篇打分。

先建一份轻量阅读记录，再生成不同篇幅：论文身份/版本、来源覆盖、八项内容、关键定位和缺失项。已有结构化输入可复用这些字段；生成摘要不能自动升级为已亲自核对原文。缺失区分未提供、论文明确未报告、材料覆盖不足和信息冲突。

这是一份内部内容契约，不要求额外输出 JSON，也不依赖其他 skill。PaperStudio 的雷达仍按用户范围主动发现与核验来源；用户限定只分析附件时遵守该范围。不得把上游“只处理给定解析文本”的限制套到主动发现任务上。

## 逐篇交付检查

对每篇逐项记下“已有内容与定位 / 不适用并解释 / 证据缺失并解释”：

1. 八项信息都有可找到的内容或诚实的缺失说明；方向、思路、消融、总结没有被相邻字段吞掉。
2. 背景到问题、问题到思路、思路到方法、方法到结果能够连起来；没有用术语串掩盖步骤断点。
3. 主结果与消融分别给出了有条件的判断；未知与混杂未在压缩时消失。
4. 每篇总结能区分这篇与相邻论文，后面的论文没有降级为只有摘要。
5. 同一内容在摘要、图注、方法和回顾中没有反复换词扩写。
6. 导航卡对应完整正文；显式仅摘要和观察项按实际材料标注，不计为完成的全文解读。

HTML 校验器只验证文件规则；字数、标题数、图数和字段存在性都不能证明这份内容检查通过。

## 可检索信息与价值判断

每篇在元信息或开头保留有证据的方向/分类、任务、关键词和问题签名。问题签名用“任务/对象＋约束＋瓶颈＋目标”的短语表达；不要用标签数量或关键词堆积替代理解。来源没有支持的标签不强填。

在摘要/导览给主要贡献和关键发现，在正文解释与最相关前作的关系。创新性、效果表现、可借鉴性、研究与应用价值须落到具体机制、对照证据和迁移条件；可自然融入方法、证据与总结，不强制额外评分表或重复栏目。
