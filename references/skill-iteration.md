# Skill 更新与回归迭代

仅在修改 PaperStudio skill 包时执行。普通论文阅读不触发自改，也不创建后台任务。本流程借鉴 [SkillAdam](https://github.com/ruc-datalab/SkillAdam) 的任务反馈、失败记忆、局部修订和验收门；不是安装或运行其优化器，不声称复现其分数或自适应超参。

## 一次更新的闭环

1. **冻结**：修改前保存完整基线，记录来源版本；固定本轮原始材料、用户任务、生成环境与评审口径。既测主 SKILL，也测它引用的资源；不能只把 SKILL.md 喂给生成器。
2. **生成**：运行下方 prepare，再把每份 task.md 作为真实用户任务交给独立新上下文。生成器只能看到指定 skill、任务和原始材料，看不到评审标准、已知问题、基线答案或其他产物。默认对四个内置案例分别生成基线与候选，共八份结果；radar 结果包括 HTML 和伴随稿。可并行独立生成，不能让一个生成器替自己评分。
3. **检查**：先跑文件校验，再由独立评审逐个对照原始材料。检查语义覆盖、操作链、数字/条件、分析归因、范围/关系、可读性与交付。仅有标题、关键词或字数不算通过。证据不足和理论类型按对应状态评判，不强造实验。HTML 还检查桌面和手机实际显示。
4. **记录**：保存任务、材料、产物、哈希、评审与失败。每个问题记录触发条件、输出摘录、原材料位置、根因假设、修订、复测结果及是否复发。历史失败不删除，不把未运行记为通过。公开记录只使用合成或可公开材料。
5. **局部修订**：先修反复出现或影响事实/机制的根因；一次只改相关规则。若新问题或退步增加，缩小修改范围；不要给每个案例增加特殊答案，不通过改低评分标准消除失败。证据不足允许不改。
6. **复测与接受**：修订后在新上下文重生成受影响案例，并复测受保护案例；当前包的全部四个案例必须有有效结果。比较同一组任务的基线与候选，保护项不能退步。所有候选检查通过才可标完成。没有可测改善时如实记“本组未观察到退步”，不宣称性能提升。
7. **保存**：在实际个人 skill 目录跑 quick_validate，保存改动与 evals/history 中的轻量结果/问题记录，按环境规则持久化。更新公开镜像时也保留可复核记录。当前对话里的临时测试目录不算最终问题记忆。

默认最多三轮局部修订；仍失败就停止扩大改动，保留已完成内容并明确剩余问题，不能把无限迭代当作完成。不要为测试改生产系统或使用私有凭据。受网络、模型能力或渲染环境限制时记录 blocked，不虚构测试。

## 执行方式

```bash
python3 scripts/run_regression.py prepare \
  --baseline /path/to/baseline-snapshot \
  --candidate /path/to/current-paper-studio \
  --run-dir /path/to/new-run
```

脚本冻结包、材料和任务，产出 manifest.json 与各 case/task.md。**脚本本身不调用模型**；由当前更新 skill 的 agent 自动派发新上下文执行这些任务。无独立上下文能力时可用用户已有模型运行器；没有可用运行器就报告生成测试未完成，不能降级成只查文件后称通过。不要自动安装付费服务。

独立评审读取 evals/rubric.json，针对每个版本写 `baseline-review.json` 与 `candidate-review.json`，格式见 rubric。输出哈希由实际文件计算。评审必须看正文及伴随稿，不只读生成器的完成声明。

```bash
python3 scripts/run_regression.py check --run-dir /path/to/new-run
```

check 检查案例集合、记录结构、实际文件哈希、独立评审证据、候选保护项及成对退步，输出 gate.json。它检查记录的一致性，**不能自动证明评审判断正确**。检查生成器/评审者是否同上下文由编排者保证并记录。

## 常驻案例与扩展

内置合成材料覆盖：两阶段学习与条件推理、正负结果、混杂消融、收益饱和、并行路线且协议不兼容、固定集合雷达中材料不足条目、理论假设与反例、HTML/Markdown一致性。不得把合成论文当真实研究传播。

每次内容更新至少执行这四个案例；对本轮缺陷补一个新的原始材料变体或保留样例，避免只适配固定数值。涉及发现脚本、日期、外部源或视觉资源的改动，另加相应实际工具测试；本组给定材料测试不能证明网络发现、调度或真实 PDF 裁图可靠。未覆盖范围列在记录中。
