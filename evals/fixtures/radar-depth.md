# R1：SlotWrite — Updating Object Memory in Streaming Visual Question Answering

## R1 §1 任务与背景

输入是按时间到达的室内视频帧以及任意时刻提出的物体状态问题，输出当前状态及支持它的帧号。场景中同一物体可能被移动，多帧中的“杯子在桌上”和“杯子在架子上”会先后成立。前作 AppendBank 保存每帧的文字描述，回答时检索相似的三条描述；历史更长时，它可能同时取回两个时刻的状态。SlotWrite 使用同一视觉语言编码器与检索器，修改记忆记录和更新方式。

## R1 §2 方法

视觉编码器对每帧输出物体 ID、属性、属性值、置信度以及证据帧号。物体 ID 由本基准随帧提供的跟踪器给出。记忆键为“物体 ID＋属性”，值为“属性值、证据帧号、置信度”。只有置信度达到 0.7 的新观测才写入该键；写入会替换旧值，其他键不变。未通过阈值的观测保留在原始帧日志中，不进入回答用记忆。

问题解析器把问题转换为物体与属性查询。回答器读取对应键及该值记录的原帧；键不存在时返回“没有足够观测”，不使用最近一次低置信度值。系统不训练编码器、解析器或回答器。阈值在开发集上确定，测试期间固定。不同物体拥有相同名字时，界面要求问题选择具体 ID；跨摄像头身份匹配不在本任务内。

## R1 §3 实验

表 R1-1 使用 RoomShift 的 200 条视频，每条 120 帧、10 个当前状态问题，模型与输入帧相同。状态准确率越高越好，回答延迟为单 GPU、batch=1 的平均端到端时间。

| 配置 | 状态准确率 | 错引旧帧比例 | 回答延迟 |
| --- | ---: | ---: | ---: |
| AppendBank | 74.0% | 18.0% | 84 ms |
| SlotWrite | 82.5% | 7.0% | 61 ms |
| SlotWrite，不设写入阈值 | 78.0% | 6.5% | 60 ms |

表 R1-2 只评估问题“物体刚才在哪”，SlotWrite 为 42.0%，AppendBank 为 70.0%。该组测试仍使用回答用记忆，不允许额外搜索完整帧日志。对 30 条遮挡严重的视频，SlotWrite 回答“没有足够观测”的比例为 22%，完整测试集为 8%。没有报告跨跟踪器或多次独立运行的结果。

# R2：SpanVote — Aggregating Overlapping Evidence for Document Questions

## R2 §1 任务与背景

输入是一份已完成 OCR 的多页文档和一个问题，输出答案及文档页码、字符区间。前作 TopWindow 对检索得分最高的文本窗口直接回答；第二个基线 MaxAnswer 在四个窗口各产生答案，取答案概率最高者。SpanVote 关注相邻窗口重复包含同一段文字时的证据计数，未修改 OCR 模型。

## R2 §2 方法

文档按 256 token 切窗，相邻窗口重叠 128 token。检索器返回四个窗口，冻结的回答模型在每窗输出答案字符串、置信度和原文证据跨度。系统把跨度换算为原文页码及字符区间。来自同一页、字符区间交并比大于 0.5 的跨度归为同一个证据簇。

每个证据簇对同一答案最多提供一票，票权取簇内该答案的最大置信度。按规范化答案字符串累加各簇票权，返回权重最高的答案；相同总权重时选最早出现的证据页。缺少可定位跨度的候选不参与投票。答案规范化只移除两端空白和统一英文字母大小写，不合并“1200”和“1.2k”。所有模型冻结，无新增训练。

## R2 §3 实验

表 R2-1 的 SheetQA-v2 测试集含 3,000 题，同一 OCR 文本、检索器与回答模型，答案精确匹配率越高越好。

| 配置 | 精确匹配率 | 引用跨度正确率 | 每题回答模型调用 |
| --- | ---: | ---: | ---: |
| TopWindow | 68.0% | 71.0% | 1 |
| MaxAnswer | 72.0% | 73.5% | 4 |
| SpanVote | 75.2% | 79.0% | 4 |
| SpanVote，不聚类跨度 | 73.1% | 75.0% | 4 |

在需要将两个单元格数值相加的 180 道题上，SpanVote 为 49.0%，MaxAnswer 为 51.0%。系统只聚合候选答案，不执行新的跨窗口计算。表 R2-2 的“单份证据被三个重叠窗口命中”子集上，去掉跨度聚类的精确匹配率为 67.0%，完整配置为 76.0%。未报告端到端延迟、OCR 误差分层或非英文文档结果。

# R3：BranchQuota — Allocating Candidate Generation to Search Branches

## R3 §1 任务与背景

输入是一个形式化算术任务、八种固定的首步策略和可执行的最终答案验证器，输出一个通过验证的答案，或在预算耗尽后返回失败。前作 Uniform64 对每种策略各采样八个完整候选。BranchQuota 在同样的候选数上限内改变各分支获得的次数。生成模型冻结，本文没有策略训练。

## R3 §2 方法

第一轮为每个分支采样两个完整候选，共 16 个。每个候选先经过格式检查和任务约束检查；最终答案正确时立即返回。没有成功时，按“通过格式与任务约束检查、但最终答案仍错误”的候选数量给分支记分，分数只能是 0、1、2。

剩余 48 次采样中，24 次均分给八个分支，每枝三次；另 24 次按第一轮分数比例分配。整数配额先向下取整，剩余额度按小数余数从大到小补齐，同余时按固定分支编号。全部分数为零时，额外 24 次也均分。第一轮分数不随第二轮结果更新。第二轮依分支编号执行各自配额，成功即停止，64 次是上限而非每题实际固定消耗。

## R3 §3 实验

表 R3-1 在 CalcTree 的 1,000 道未见题上使用同一个 1B 模型和相同温度。调用生成一个完整候选，最大输出长度均为 128 token。成功率越高越好。

| 配置 | 成功率 | 平均实际采样数 | 平均总生成 token |
| --- | ---: | ---: | ---: |
| Uniform64 | 61.0% | 43.2 | 3,310 |
| BranchQuota | 66.5% | 39.8 | 3,290 |
| 全部剩余额度按第一轮分数分配 | 64.0% | 38.1 | 3,180 |

在“唯一可成功分支在第一轮记零分”的 90 道题上，完整 BranchQuota 成功率为 37.8%，取消均分额度后为 0%。第一轮与第二轮采样独立。每种配置只运行一个采样种子。没有报告 GPU 时延、策略数变化或自由文本问答结果。

# R4：CounterScene — Testing Whether an Agent Uses a Changed Observation

## R4 §1 评测目标

该工作提供评测协议，测量视觉行动 Agent 在环境发生变化后是否利用新观测。普通任务成功率可能无法区分“看到变化后调整”与“原计划碰巧仍然成功”。CounterScene 从同一环境状态派生一对任务：保持场景不变，或将目标物体移动到新位置。评测使用模拟器的离散导航与抓取动作，不提供连续机器人控制器。

## R4 §2 数据与执行

每个任务在 Agent 完成第一次导航后保存模拟器状态、随机种子和 Agent 的文字历史。复制为两条分支；一条不改场景，另一条移动目标物体，其他物体不动。两条分支都发送各自的新图像，沿用相同文字历史，再允许最多十次动作。每条分支单独运行，Agent 无法读取另一分支的图像或答案。

成功由模拟器物体状态判定。指标分别为不变分支成功率、移动分支成功率，以及成对成功率：同一任务的两条分支都成功才记一分。数据包含 400 对任务，任务模板在开发集和测试集间分离；同一房间布局可同时出现在两者。评测对象为两个固定模型与一个脚本策略，未训练新模型。

## R4 §3 结果

| 策略 | 不变分支成功率 | 移动分支成功率 | 成对成功率 |
| --- | ---: | ---: | ---: |
| 模型 U | 86.0% | 52.0% | 47.0% |
| 模型 V | 80.0% | 68.0% | 61.0% |
| 始终执行初始计划的脚本 | 90.0% | 20.0% | 20.0% |

表 R4-2 对模型 V 保持模型、历史和动作预算不变，只把移动分支的新图像替换为移动前图像，其移动分支成功率从 68.0% 降为 24.0%。评测还记录了新图像到第一次改道动作的步数，但未给出推理时延。没有新房间布局测试或真人实验。

## R4 §4 材料范围

协议、指标定义、结果和上述图像替换分析均已提供。该基准不要求 Agent 在文字中显式描述移动，也不把描述正确作为任务成功条件。

# R6：BridgeLatent — Transferring Answer Representations into a Prompt-only Prior

## R6 §1 任务与前作

输入 x 是问题和检索得到的文本证据，输出 y 是固定长度 32 token 的答案；不足长度以结束符补齐，评测忽略结束符后的内容。前作 PlainMask 从 32 个 mask 开始，用双向语言模型经过四轮揭示全部 token。每轮能同时访问所有当前 token，但起始时没有已生成答案的语义线索。

BridgeLatent 在所有轮次加入同一个低维条件向量。可用的冻结教师编码器能够读取完整的 [x,y]，产生反映整句答案的表示；生成时只有 x。该工作分别训练从 x 预测条件的网络，以及使用条件进行掩码恢复的模型。研究不涉及视频、图像或开放长度输出。

## R6 §2 教师目标与第一阶段

训练集有 50,000 个问题、证据和正确答案三元组。冻结教师编码器 E 读取 [x,y]。将编码器输出经固定投影 W 降为 16 维，再按训练集统计的逐维均值和标准差标准化，得到目标 z*。W 来自在同一训练集编码器输出上拟合的主成分；开发集和测试集不参与投影与统计量计算。

先训练网络 Pψ，仅输入 x，预测一个 16 维均值 μψ(x)，目标是最小化 ||μψ(x)−z*||²。教师 E、投影 W 与下文的掩码模型保持冻结。该阶段结束后固定 Pψ，定义提示条件的采样规则 zₚ=μψ(x)+0.1ε，其中 ε 为 16 维标准高斯噪声。这里没有再训练方差预测网络。

## R6 §3 第二阶段：让掩码模型使用两种条件

对一个训练答案随机遮住其中 25%、50%、75% 或 100% 的位置，得到 yₜ。选择条件时按概率 r 使用教师向量 z*，按概率 1−r 使用 zₚ；这是二选一采样，不是两个向量加权平均。训练进度前半程，r 从 1 线性降至 0，后半程保持 0。zₚ 来自已经冻结的 Pψ。

可训练的线性投影 A 把 16 维条件变成与模型隐藏状态等宽的向量，加在每个 token 的输入表示上；随后进入双向 Transformer。主干权重冻结，只更新 A 和注意力层 LoRA。交叉熵只计算被遮住位置的正确 token；未遮位置作为上下文，不计入该次损失。梯度不进入 E、W 或 Pψ。所有样本都执行同一组训练阶段，没有按问题难度单独选择阶段。

## R6 §4 推理过程

输入 x 后调用 Pψ 一次并采样一次 zₚ，此后四轮都复用该向量。初始答案为 32 个 mask。每轮预测全部仍被遮住的位置，各位置提出概率最高的 token；在仍被遮住的位置中，选最大 token 概率最高的八个揭示。已揭示位置后续不再改动；四轮后返回完整序列。教师编码器、正确答案 y、训练用的 z* 都不参与推理。r 是训练阶段的调度参数，推理时不采样教师／提示来源。

## R6 §5 主实验

表 R6-1 在 FactChain-test 的 4,000 题上测试同一个 600M 主干。训练数据、四轮推理、每轮揭示数和硬件相同；PlainMask 不使用额外教师编码器产生的表示。准确率按归一化答案精确匹配计算。batch=1 延迟包括提示先验网络和全部解码轮次，不包含检索。

| 配置 | 准确率 | 每题延迟 | 训练 GPU 小时 |
| --- | ---: | ---: | ---: |
| PlainMask | 63.0% | 42 ms | 18 |
| BridgeLatent | 71.5% | 46 ms | 27 |
| PlainMask，八轮、每轮揭示四个 | 70.0% | 78 ms | 18 |

八轮基线沿用同一训练结果，只改变推理揭示日程。另一个开放回答测试 FreeFact 不限制输出长度，其结果未在本文报告。

## R6 §6 分析实验

表 R6-2 除列出的改动外，均使用相同数据、主干和四轮推理。

| 第二阶段训练条件／推理条件 | 准确率 |

| 全程教师 z*／提示 zₚ | 62.0% |
