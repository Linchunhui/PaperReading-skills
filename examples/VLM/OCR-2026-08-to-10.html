01TeleOCR

先把弯曲页面与结构标签做对，再训练识别器。

1.2B论文 · 权重公开

论文 · 模型

出发点：这个问题为什么还没解决

一张拍弯的书页，会同时打破三个假设：文字不再沿直线排列，区域边界不再是整齐矩形，表格的几何线条也不再等于逻辑单元格。只给识别器更多清晰扫描件，很难补上这些缺口。

TeleOCR 把问题放回几何与数据：页面先经过结构处理，再由 1.2B 视觉语言模型识别。它值得接在上一篇的数据引擎之后读，因为它追问的不是“再加多少图”，而是“监督信号是否真的描述了这张图”。

方法：把处理过程走通

(1) 把多模型一致性当作筛选器

多个识别系统先为同一页面生成候选，再按文本、表格和公式各自的相似度寻找一致结果；低一致性样本进入额外检查。自判别模型还会比较原图与标签渲染图，用受控扰动构造的错误学习找问题。这里的一致性只是降低坏标签概率：几位老师可能一起看错，因此不能把“大家都同意”直接当真值。

(2) 让点和区域共同表达变形

模型不仅看文字内容，还学习页面控制点和区域边界。边界简化会保留曲率大的位置，避免用均匀采样抹平折角；点级、区域级变形监督再配合图像增广，让几何变化有明确的训练对象。它改变的是如何描述空间，而不是假定后面的语言模型能凭语义补回所有形变。

(3) 先学骨架，再填内容

四阶段依次建立文档能力、适应变形、解耦内容与结构，最后做任务奖励优化。结构阶段把表格拓扑与单元格内容拆开，公式也先强调语法骨架。想象一个带合并表头的表格：先弄清哪一格跨了两列，再识别格内数字，比让同一串文本同时承担两类错误更容易诊断。

(4) 让奖励跟输出对象对应

最终阶段分别用文本编辑距离、表格 TEDS 与公式 CDM 等信号训练。NED 关注字符序列，TEDS 关注表格树结构，CDM 关注公式呈现；三者不是可以随意互换的“正确率”。主干结合 Qwen2.5-VL 视觉部分、Qwen3-0.6B 语言部分和连接模块，完整系统仍是一条带几何处理的解析流水线。

02WeVisDoc

从更多样本，转向把监督 token 花在仍然不会的地方。

2B / 4B论文 · 权重公开

论文 · 代码与模型

出发点：这个问题为什么还没解决

两个数据桶各有一万条样本，看起来很均衡；一个桶每条只输出十几个字，另一个桶每条输出整页 Markdown，实际参与优化的 token 数却相差很远。样本配比并不等于学习预算配比。

WeVisDoc 用两阶段 SFT 回答这件事：第一阶段获得广泛能力，第二阶段根据残留错误重新安排数据。它没有把“后训练”自动等同于 RL，而是认真研究监督训练还能怎样用得更准。

方法：把处理过程走通

(1) 先覆盖完整的文档空间

基于 Qwen3-VL 的 2B／4B 模型，先学习约 4000 万条记录，包含整页、区域、表格和公式。数据构造关注内容、结构和语言覆盖，合成页面保留可验证标签，退化图也要保证标签仍可从图像读出。这一步的作用是形成底盘，否则后续只追难例，容易得到一个会处理少数异常、却丢掉日常能力的模型。

(2) 用独立探针定位薄弱模式

第二阶段先在与训练挖掘池、最终评测分离的探针集上，观察模型在哪些视觉或结构模式持续出错，再把问题聚成簇。错误检查也要排除标签本身不对的样本。探针决定“接下来多学哪一类”，训练池负责提供实例，二者分离能减少把某些已见样本的偶然表现当成通用短板。

(3) 定向补齐，而不是只重复错题

难例检索、审计后的失败样本与页面程序合成共同补充第二阶段约 500 万条记录；原有数据还会回放。一个跨行表头错误簇，可以通过改变表头层数、文本长度和版式得到更多实例。这里的关键是围绕失败模式扩展分布，而不是把同一张错题多训练十遍。

(4) 按输出 token 分配预算

最终优化预算按监督 token 而不是记录数约束；某类样本的平均输出越长，为达到同样的 token 份额，就需要更少的采样次数。第二阶段冻结视觉编码器、更新语言部分，仍然使用 SFT。这提供了一个很实际的研究变量：固定训练预算后，是否真的把更多学习机会给了当前的薄弱能力？

03Xiaomi-OCR-0

标签先取得可靠共识，训练任务再随能力增长逐步加入。

0.8B论文 · 权重公开

论文 · 模型

出发点：这个问题为什么还没解决

小模型被错误标签反复教过之后，再加复杂奖励未必救得回来。另一种常见失败是过早混入复杂 VQA：识别基本功还没稳定，模型已经开始为“回答问题”优化。

Xiaomi-OCR-0 因而同时控制两件事：进入训练的数据是否可信，进入每个阶段的任务是否合时宜。它与 WeVisDoc 的联系是课程安排；差别在于它把共识标注、空间对齐和 Mix-RL 连成完整训练路线。

方法：把处理过程走通

(1) 先由专家池给标签找证据

多个 OCR 专家为同一输入生成候选，系统按任务相似度排序，选出高一致性的三个结果，再用其中的代表答案作为标签。高共识样本可直接接受，低共识样本进入渲染核对与修正；修正结果还要重新回到共识检查，不能因“更大的老师改过了”就自动放行。共识因此是入库规则，而不是事实正确性的数学保证。

(2) 用 Q-Mask 先建立文字与位置的联系

在 Qwen3.5-0.8B 上先做文字锚定：给定文本查询，辅助掩码分支学习对应的图像区域，结合语言预测、掩码交叉熵与 Dice 损失。它让模型先知道某段文字在图上哪里，降低只靠语言先验续写的倾向。这个辅助分支服务于早期训练，后续 OCR 继续预训练并不保留它作为部署必需模块。

(3) 区域、整页、问答按阶段推进

OCR 继续预训练逐步引入更完整的页面上下文和理解任务，同时保留单个 MTP 预测头。作者的阶段实验很关键：在能力较早时加入 VQA 会降分，到了中期却能帮助完整页面解析。课程并非“越复杂越好”，而是先让视觉识别足够稳，再用理解任务帮助组织已经读出的内容。

(4) Mix-RL 对不同对象分别记账

最后采用带 DAPO 风格调整的策略优化，包括 token 级聚合、非对称裁剪与过滤无有效奖励差异的组。文本、表格、公式分别评分，整页奖励还需对齐元素并组合；因此不能简单理解成对整段 Markdown 求一个编辑距离。论文的实现没有显式 KL 惩罚，不能把其他 GRPO 配方的默认项自动补进来。

04PolyOCR-Venus

学生需要老师时再蒸馏，而且先确认老师真的更可靠。

2B / 9B论文 · 权重未公开

论文 · 官方仓库

出发点：这个问题为什么还没解决

假设一页有一千个字符，几次采样都只错一个数字，归一化奖励都接近 0.999。总分看起来很好，GRPO 却几乎看不到组内差别；恰恰是最需要修正的那个数字，得不到有方向的训练信号。

直接请老师逐 token 指导也不保险：老师可能把这个数字看错。PolyOCR-Venus 的 CGPO 同时判断“老师答得有多好”和“它是否比学生更好”，让 RL 与蒸馏在样本层面分工。

方法：把处理过程走通

(1) 先用课程 SFT 建立多任务底盘

框架覆盖识别、定位、文档结构、信息抽取、格式转换和推理。SFT 中感知、结构、理解及通用对齐任务的比例随阶段变化；后续 CGPO 从这个共同起点出发。论文另有面向多语种文档解析的 2.7B 配置，不能把它的指标直接贴到 2B／9B 主模型名下。

(2) 把绝对能力和相对优势分开

系统缓存老师的可验证任务得分，在线估计学生得分；离线校准器分别估计老师的绝对可靠性和老师胜过学生的概率。校准时分开用于构造统计量与评估目标的数据，降低噪声导致的自我确认。关键不是一个“差多少分”的硬阈值，而是对噪声和任务差异进行校准后再决定指导力度。

(3) 用停止梯度的门控决定蒸馏权重

如果老师没有更可能取胜，蒸馏权重归零；如果老师与学生都很差，即使老师略好，绝对可靠性也会压低其影响。门控不通过当前训练损失反向学习，避免模型把路由器当成降低目标值的捷径。下面是论文机制的紧凑写法：

α = stopgrad[q̂T · max(2p̂win − 1, 0)]
L = LGRPO + λ α LOPD

出发点：这个问题为什么还没解决

方法：把处理过程走通

(1) 用两种损失归一化处理长度失衡

在广泛继续预训练之后，SFT 数据按任务重新平衡，但平衡样本数仍不够：信息抽取样本可以很多，输出 token 却很少。作者分别训练按 token 平均和按样本平均的分支再融合。前者更接近每个预测位置同权，后者更接近每个训练实例同权；这与 WeVisDoc 的 token 预算问题相通，处理的位置却不同。

(2) 让领域老师沿学生路径指导

五个 4B 领域老师分别经过 SFT 与 RL，再指导共享学生。蒸馏使用学生 rollout 上的前缀，在选定的 top-k 支持集内归一化分布、计算受控的反向 KL 信号。重要的是老师要看到学生实际走到的位置；只学习老师的完整标准答案，遇到学生自己的错误前缀时可能缺少纠偏经验。

(3) Mix-RL 不强求所有任务共享一种奖励

解析、普通 OCR、KIE、图像描述和跨页表格各自定义奖励，再共同训练。KIE 需要检查字段路径、遗漏、空值和绑定关系；跨页表格先检查是否认对续表关系，再评重建结构。这种先决条件能避免模型在“拼错了两张表”的情况下，仍靠局部表格形状获得较高奖励。

(4) 跨页重建采用相邻页递归

同一模型先独立解析页面，再结合相邻页面图像及已有结果识别续表并恢复完整表格。多页表格从后向前递归合并，更新后的内容可以重渲染后继续参与下一对页面处理。它把大问题拆为可反复执行的局部步骤，不等于一次把整本书的所有视觉 token 放进上下文。

出发点：这个问题为什么还没解决

第十页的标题究竟属于第一章，还是开启了一个新章节？第十一页的第一行是上一页表格的延续，还是独立正文？单页识别得再准，也不会自动得到整本文档的树。

Logics-ParsingV3 选择显式保留结构状态。与不断扩展上下文相比，它更像边读边维护一个目录栈：当前仍打开哪些标题，最近结束了什么，哪些内容还在等待下一页接续。

方法：把处理过程走通

(1) 窗口输入同时携带上一轮状态

文档被切成不重叠的页面窗口，示意图每窗三页。模型读当前图像与紧凑状态：开放标题路径、最近关闭的标题、跨窗口内容尾部。状态不是全文逐字副本，它优先保存下一步组织结构需要的信息。于是页数增长主要增加执行轮数，而不是强迫每次推理回读全部历史。

(2) 输出要告诉系统怎样接回文档树

窗口输出除页面内容之外，还含标题层级、续接标记、图与说明文字的关联。普通 Markdown 很容易让这些信息隐含在格式里，而专门的结构表示把它们变成后处理可执行的依据。对于一个跨页段落，系统需要知道“续到哪里”，不能仅仅把两页文本按顺序拼接。

(3) 更新状态与累计输出分开处理

已完成的页面结果累积为文档输出；下一窗只携带更新后的有限状态。这种区分很重要：保存整份解析结果，不意味着必须把它全部重新送进模型。标题层级和关联随后通过结构解析重建为文档级表示。下面是对官方图的概括：

(yt, St+1) = Parse(Wt, St)

白话翻译：Wt 是当前几页，St 是带来的结构记忆；本轮产生内容 yt，同时更新交给下一窗的记忆。公式说明接口，不宣称公开了训练目标。

(4) 把结构状态当成需要验证的压缩

官方已经公开流程、接口和模型，尚未给出足以重建 V3 训练过程的独立论文。因此可以讨论状态如何流动，却不应补写它的奖励、数据配比或状态压缩损失。我们的推论是：状态若漏掉关键父标题，错误可能传到后续窗口；应以标题树和跨页续接评测验证，而非只看最终文本是否完整。

出发点：这个问题为什么还没解决

上一篇介绍 R-SWA 时，最容易产生的误解是“滑动输出窗口之后，所有缓存都与页数无关”。需要补上一个条件：旧方法仍保留视觉上下文，页面越来越多时，这部分仍会增长。

第二代从两层处理这个瓶颈：一次解码只检索少量相关视觉块；整本文档只保留当前活动分块的缓存。这里的“无限”指可以持续处理的流程，不是每一步都无损访问全部历史页面。

方法：把处理过程走通

(1) Page Gate 先限定当前该看哪一页

图像经 DeepEncoder 压缩后成为视觉 token。SR-SWA 在局部文本窗口之外增加稀疏视觉引用：Page Gate 先把查询限制到目标页面相关的候选块。页位置使用有界编码并保留页内顺序，避免文档越长，位置索引越超出训练范围。首先找对页，再在页内选证据，能降低跨页误取的机会。

(2) Token Sieve 再选择少量视觉块

每块先用摘要 key 与查询匹配，经稀疏概率映射和 top-k 选择进入注意力。块概率还作为注意力先验参与计算，让语言任务损失可以影响选择过程。可用下面的概念式理解其预算：

可见集合 = 最近 w 个文本 token ∪ 最多 k 个视觉块
每步工作集大小 ≲ w + k · b

白话翻译：b 是每块大小；固定 w、k、b，就限制了每步直接使用的证据数量。这是工作集预算的解释，不等于全模型显存恒定，也不保证所有历史信息都被保留。

(3) 分块处理还要明确何时释放缓存

Unlimited-Horizon Decoding 把页面流切为定长块，边界保留一页重叠，复用边界图像 KV 与必要文本尾部，再释放非活动分块。单有稀疏注意力，不会自动让历史 KV 消失；缓存的生命周期管理才让持续解析成为可能。每个新活动块的视觉编码和 prefill 仍要付出计算代价。

(4) 训练长序列，检验更长的真实文档

报告用单页与多页数据训练，冻结视觉编码器和连接部分、更新语言模型，训练长度上限为 64K；推理再依靠分块机制向更长文档延伸。它与 Logics 的互补关系由此清楚：前者重点约束注意力和缓存，后者重点维护结构状态，解决的不是完全相同的记忆问题。

方法：把处理过程走通

(1) 共享感知骨干，保留模态入口

视觉 patch 与音频特征先经过各自入口，再进入共享感知 Transformer，通过连接模块交给语言解码器。时、空位置用统一坐标体系组织，但这不意味着每种输入都具有相同预处理。文档场景的重点是让感知特征支持细粒度内容与位置；“Omni”还覆盖其他模态，不能把所有能力提升都归因于 OCR 数据。

(2) OmniSchema 约束对象如何表达

(3) 参考条件教师只在训练时获得答案

OSAD 先让学生自行生成，通过格式与质量门禁后，在同一前缀上比较学生与教师的分布。冻结教师额外看到参考答案，学生没有这一权限；教师由此提供受参考约束的指导。这里的答案属于训练监督，不能推导为推理时模型也需要答案，更不能把教师的特权输入误当成学生能力。

(1) 两种模式，共用一个识别模型

客户端提供普通 OCR 和带布局定位的 grounding 模式；后者在内容中加入区域类别和坐标，图表转成表格，其他图像可附短描述。紧凑标记减少额外结构 token。图示表示的是公开输入输出协议，不声称三个尺寸采用完全相同的内部主干；尺寸不同、初始化不同，应分别看实验。

(2) 把转录与几何证据对齐后再做标签

标注流程先获得一致的转录，再融合词、行和块级检测，用文本匹配与阅读顺序约束完成对齐，审计缺漏、重复和几何冲突。图表数据及图片描述另行生成、验证，不可靠结果重做或拒绝。这里值得迁移的原则是：文字看起来正确，并不等于它已经绑定到正确区域。

(3) 让漏框、重复框和错类别都会付出代价

RL 按监督类型选择奖励：grounding 页衡量同类区域的空间匹配，合成页运行内容测试，空页要求及时结束。区域匹配一对一，得分按预测与真值中较大的框数归一化。因此多画框不能凭空提高分数，错类别不能用位置接近蒙混过关；这是比只奖励平均 IoU 更完整的目标设计。

(4) 输出规范也会影响吞吐与评分

官方同时公开格式转换和评测归一化代码。对同一可见内容，HTML、Unicode 与 LaTeX 的不同表达可能造成编辑距离差异；更短的表示也减少解码工作量。因此衡量新模型时，要把识别是否正确、输出是否等价、序列是否更短分开，不能把所有得分或速度变化都归到视觉理解。

Qwen3-VL-2B论文 · 代码与权重公开

论文 · 代码 · 模型

出发点：这个问题为什么还没解决

一页左右两栏互不相关的文字，为什么右栏必须等左栏最后一个字符生成完？普通自回归把整页串成一个序列，顺序很清楚，却把很多可并行的工作也串行化了。

PaDoc 延续上一篇并行解析的方向，但把布局生成与内容生成组织成树：主干继续报区域，内容从各自的 fork 位置分出去。关键问题因此从“每次多预测几个 token”变成“哪些内容根本不必互相等待”。

方法：把处理过程走通

(1) 共享整页视觉前缀，再按布局开分支

模型只需建立整页视觉表示，主序列依次生成区域布局；某区域就绪后，fork token 开启该区域的内容分支，主序列继续处理后面的布局。与裁块流水线不同，内容分支仍可访问整页视觉证据，避免每个区域都重新编码；与普通整页解码不同，多个区域的内容不必完全串行。

(2) 注意力只开放到合法祖先

区域分支可看图像、自己的布局祖先与自身已有内容，不能随意读取其他内容分支。训练用树形监督表达这种可见性，推理则共享已有前缀。它相当于把条件依赖显式改写：在布局与视觉证据足够时，内容分支近似独立。若一段内容必须依赖另一分支刚生成的语义，这个假设就需要特别检查。

(3) 用常规预测目标训练树形序列

方法不额外增加草稿模型或预测头，继续使用 next-token 目标；实现通过树状可见性与变长注意力组织虚拟序列。理想情况下，完成时间受最长分支而非全部内容长度之和支配：

串行长度 ≈ 所有区域内容之和
并行关键路径 ≈ maxk［到区域 k 的布局前缀 + 区域 k 的内容］

白话翻译：分出更多独立工作，能够缩短必须等待的链；但一个特别长的区域仍会拖慢完成时间，调度与显存开销也不会从公式中自动消失。

(4) 让服务框架承担分支调度

vLLM 实现把各条流组织成请求，利用前缀缓存共享已完成的 KV 块；尚不能共享的尾部仍可能需要 prefill。训练的树结构与在线服务的物理执行并不等价，因此必须看实测并发。高并发下 GPU 已经繁忙，进一步拆分请求不一定按分支数量线性加速。

3.4B / MoE论文 · 权重公开

论文 · 模型

出发点：这个问题为什么还没解决

PaDoc 通过区域独立性减少等待；但一段连续文字内部，仍要一个 token 接一个 token 地生成。能否让便宜的小模块先猜一段，再由可靠的大模块快速确认？

Jina-OCR-v1 的 FastMTP 就在这一层工作。它还有完整的数据与后训练方案，不过最值得与同批工作对照的是：推测解码的收益，如何随推理引擎优化而改变。

方法：把处理过程走通

(1) 压缩视觉证据，保留局部高分辨率

模型沿用 DeepSeek-OCR 路线的 DeepEncoder 与 MoE 解码器，全局图压缩为少量视觉 token，再按需要增加局部切片。全局视野负责页面组织，局部块帮助读小字。这与后面的 FastMTP 是两层优化：前者减少视觉上下文负担，后者减少文本生成过程里的大模型步数，不能把两者混成一个加速来源。

(2) 一个共享草稿块递归生成多个位置

FastMTP 不是把三个互不相关的分类头接在主干上，而是让同一个轻量块递归接收隐藏状态和已预测 token。训练时冻结验证模型，结合 token 监督、分布对齐和隐藏状态拟合，使草稿尽量贴近最终验证模型。学生每深入一步都可能累积误差，较远位置的接受率通常会下降。

(3) 验证最长匹配前缀，保持贪心结果

验证器一次检查草稿，接受连续匹配的前缀并补上验证器给出的下一 token；一旦某位置不匹配，后面的草稿不再直接提交。在论文使用的贪心协议下，这使加速后的输出跟随原验证器，而不是无条件信任草稿。接受率高仍不必然快，因为草稿与验证本身都有时间成本。

(4) 先定最终模型，再拟合加速头

模型先完成监督训练、鲁棒性训练和任务奖励优化，奖励关注内容、结构与重复等因素；论文的优势估计使用采样结果相对贪心基线的差值，不能机械套成标准组内标准差归一化。最终验证模型确定后再训练 FastMTP，能减少主干更新使草稿分布失配的问题。

12GravityOCR

GLM-OCR 0.9B 底座论文 · 权重公开

论文 · 代码 · 模型

出发点：这个问题为什么还没解决

外接草稿模型增加了需要训练、存储和适配的组件。GravityOCR 进一步问：识别器本身能否换一种注意力模式，同时猜出一块 token，然后切回自回归模式检查自己？

它保留 PP-DocLayoutV3 加区域识别的流水线，主要改造 GLM-OCR 识别器的训练和解码。理解这一点，才能看清论文里的解码提速为什么远大于完整页面提速。

方法：把处理过程走通

(1) 一套网络，学习两种可见性

训练同时包含干净的自回归流与互补掩码流，共享视觉前缀、解码器和输出头，只增加掩码 token 的表示。掩码块内部可双向看，前面的已确认内容保持因果可见；自回归流则保留逐 token 预测能力。这种联合训练的目的，是让并行草稿与可靠验证共存，避免只会去噪却失去稳定的验证路径。

(2) 先并行填一个块，再按原顺序核验

推理把边界 token 与一块 mask 送入模型，一次产生多个候选；随后以自回归可见性核验，保留最长匹配前缀并补一个验证 token。它不是反复多轮掩码细化后直接提交，而是单次并行起草加严格验证。被拒绝位置的缓存需要丢弃，接受部分的缓存则来自有效验证路径。

(3) 联合损失先保护验证器

自回归与扩散目标共同优化，防止训练只提高草稿并行生成能力却损害最终识别准确性。论文对移除 AR 损失的实验提供了直接证据：每次前向提交的 token 数变化不大，识别质量却下降。也就是说，“一次能吐出更多 token”并不等于“最终读得更好”。

(4) RL 沿自回归路径更新共享权重

后训练仍在可准确计算概率的 AR 路径上进行，任务奖励再影响共享参数；草稿路径因共享权重也随之变化，需要重新检查接受效率。部署收益则取决于区域长度、批量和调度。完整页面还包含布局、图像处理、prefill 和后处理，任何只优化解码的方案都会受到这些环节的约束。

两种 OCR 都给出格式正确的表格，其中一个把 8 看成 3。没有真值时，单凭格式检查无法选出正确结果；让识别器自己说“我很有把握”也未必可靠。

Jev 是专门的质量评估器，评价对象是“原图与某份候选结果是否相符”。它在系统中的位置和 OCR 不同：识别器产生答案，评估器帮助决定接受、换候选还是交给人检查。

方法：把处理过程走通

(1) 原图、候选文本和候选渲染一起输入

每次评估一个文本、公式或表格区域；候选不只有字符串，还会渲染成图像，与原始区域对应。这样模型既能读内容，也能比较结构呈现。输入必须指向同一块区域；如果原图裁剪范围和候选内容不匹配，低分可能来自边界错配，而非识别器真正读错。

(2) 把生成头换为二分类头

Jev 基于 Qwen3.5-2B，保留视觉和语言骨干，将语言模型输出头替换为二分类头，产生 0–1 质量分数。公开机制到这里已经足以说明它为什么是评估模型；但没有独立论文时，不应补写未知的原始训练数据规模、负例配比或校准方法。可用的微调教程不等于原始训练完整披露。

(3) 先检查评分是否成功，再谈阈值

官方服务区分评分成功、预检查失败、渲染失败等状态。只有有效完成评分的结果才可进入排序；错误状态附带的固定返回值不是模型判断。对多个解析器的候选，应在同一个区域内比较，再保留来源、坐标和待复核标记，这样后续才能定位它为什么被选中或拒绝。

(4) AUROC 回答排序能力，不直接给验收阈值

AUROC 衡量正确候选是否通常排在错误候选之前；它不表示“分数 0.9 就有 90% 概率正确”。部署时仍要用目标文档标注集检查阈值、误放行率和复核量。Best-of-N 也有上限：若 N 个候选都错，评估器最多选出其中更像正确的一个，不能凭评分制造缺失的真值。

16OXR1.0

布局模块可替换，失败样本再进入数据改进循环。

1.3B模型发布 · 论文 Coming Soon

官方项目 · 评测说明 · 模型

出发点：这个问题为什么还没解决

同一份报表，在档案系统里可以按段落切块，在财务系统里却要把表头、印章和金额区域单独处理。布局定义变了，不应迫使识别模型整个重训。

OXR 把布局模块做成可替换组件，同时让自身负责内容识别与阅读顺序；训练侧公开了递归自改进的数据循环。模型已经可获取，技术论文尚待发布，下面以官方流程图和可核实评测为边界。

方法：把处理过程走通

(1) 布局独立，但阅读顺序仍由 OXR 负责

官方 pipeline 把布局分析放在模型之外，布局结果分别送到内容识别与阅读顺序处理。识别覆盖文字、公式、表格、化学结构等类型，各自转成适合下游的表示。布局可替换意味着接口灵活，不意味着替换后效果不变：区域类型和边界改变，仍可能影响模型接到的任务分布。

(2) 多次预测帮助暴露不确定样本

RSI 从现有模型预测出发，由通用 VLM 辅助区分正确、错误和不确定情况；多个 rollout 的分歧也是难点线索。随后对失败原因做逐样本归因和聚类。这里的“自改进”需要模型、判别与数据构造共同工作，不应简化成模型只阅读自己的输出就自然变强。

(3) 围绕错误原因合成新页面

归因簇形成训练计划，再用真实样本作为风格参考生成图像与标签，送回训练。它与 WeVisDoc 的定向补弱有联系：都把失败模式转成数据供给。不过官方尚未完整披露每轮筛选阈值、数据规模与独立消融，我们只能确认循环的公开结构，不能替它补齐未知的算法配方。

(4) 把可复现的评测协议一并读完

官方评测文档给出了页数、版本、排除集合和硬件。准确率使用完整或明确筛选后的数据，速度则取固定 100 页子集；decode tok/s 排除了首 token 与 prefill，而 pages/s 才按整体墙钟时间计算。原生 tokenizer 不同也会改变 token 计数，因此“token/s 更大”不能直接推出“同一份 PDF 更快”。

17IndraOCR1.1

先利用文档已有文字，再用轻量 CPU OCR 处理真正需要识别的部分。

默认网络共 7.3M模型 / 工程发布 · 无独立论文

官方项目 · 模型

出发点：这个问题为什么还没解决

一份数字 PDF 已经有可靠文本层，还把每页渲染后送进大 VLM，往往是在重复做同一件事。另一方面，普通清晰印刷件也不一定需要十亿参数模型才能读。

Indra 提供另一条部署路线：文本层检查、轻量检测与识别、脚本路由和可选数学识别，在 CPU 上组合工作。它不是本篇其他 VLM 的缩小版，评价它应该从工作负载和成本约束出发。

方法：把处理过程走通

(1) 先选择 text、ocr 或 hybrid 路径

系统先判断数字 PDF 的文本层是否可用；合格内容直接提取，必要时再识别嵌入图片中的文字，扫描件则进入 OCR。结果明确标注来源，帮助排查哪里来自文本层、哪里来自视觉识别。正因存在这条捷径，auto 模式的速度和准确率不能被宣传成“全部页面都经过像素 OCR”的结果。

(2) 把不同文字交给合适的小识别器

轻量模型以 ONNX 运行，按行判断文字系统，再路由到拉丁／西里尔／希腊、CJK、RTL 或其他文字模型；不确定时可增加候选比较。主拉丁识别器约 1.25M 参数，默认模型合计约 7.3M，二者不能混称为整个系统的参数量。方向与版式处理也会影响最终阅读顺序。

(3) 数学作为可选成本项

开启数学模式后，先找出可能包含公式的行，再用专门识别器输出带 LaTeX 的内容。这个开关提高数学能力，却会增加运行时间，且可能把表格里的数字误判成数学内容。它展示了模块化系统的一个优点：可以按文档类型付出成本，而不是每个页面都启用最大模型。

(4) 按困难类型决定何时升级处理

官方明确列出复杂合并表格、退化扫描和手写等弱项。实际系统可以先记录来源、耗时和低置信区域，再把不适合轻量 OCR 的页面送到更强解析器；这是本文的系统设计推论，并非官方已经验证的统一路由器。能否节省总成本，要同时计算复核与第二遍处理。

把四条路线接起来

这些工作不是在竞争一个单一开关。它们分别改造学习信号、文档记忆、解码依赖和运行决策；只有先确定当前系统在哪一环出错，实验才会有解释力。

线索一：数据质量逐渐变成“谁来决定下一步学什么”

TeleOCR 与 Xiaomi 先解决标签和监督是否可信；WeVisDoc 将残留错误转成预算分配；PolyOCR 决定何时相信教师；OvisOCR3 处理多任务、不同长度和多教师的协调；OXR 把错误归因接回数据生成。共同变化是反馈更具体了，但每一层反馈本身也需要校验，不能把自动闭环等同于正确闭环。

线索二：长文档有两类记忆，不能互相替代

Unlimited-OCR 2 限制每步视觉引用与活动 KV，解决运行成本；Logics V3 维护标题和续接状态，解决结构连续性；OvisOCR3 的相邻页重建，则把续表压成局部递归任务。由此可以推论，计算记忆与语义状态值得分别设计、分别消融；现有资料尚不能证明某一种方案已经覆盖所有远距离依赖。

线索三：速度需要先说清楚省掉哪一段等待

PaDoc 缩短区域之间的串行链；Jina、GravityOCR 和 OCRia 减少区域内文本生成的昂贵验证步数；MiniCPM 将加速接进整条 SDK；LightOn 还说明更紧凑的输出格式可以减少解码负载。下面的分解只是诊断框架，实际流水线中的并行环节需要按关键路径计时，不能机械相加。

页面耗时涉及：读取与渲染、布局、视觉编码 / prefill、文本解码、结构组装
先测端到端，再定位关键路径，最后检验组件加速是否传到了页面。

白话翻译：解码快四倍，整页也可能只快三成；被优化的部分占总等待的比例，以及它能否与其他工作重叠，决定用户实际感受到的收益。

线索四：评价器和廉价路径改变的是系统分工

Jev 适合比较同区域的已有候选，Indra 适合先利用可靠文本层与轻量识别；它们不必在所有页面上取代更强解析器。一个可研究的组合是先分流，再识别，再评分，最后对不可靠结果升级处理。这个组合是本文的设计推论，尚不是已被这些论文联合验证的成品。
