1. CrossView：多摄像头不是“多放几张图”

跨视角推理空间 grounding评测集2026-08-16

为什么重要。多数 VLM 默认世界只有一台摄像机；真实的车、机器人和监控系统却同时接收多个视角。问题不只是 token 变多，而是模型必须判断哪些视角重叠、哪个视角最有信息、一个对象是否在不同镜头中重复出现，并把互补甚至冲突的证据拼成同一个场景。

方法与评测

CrossView 从 nuScenes、MEVA、Ego‑Exo4D 与 AgiBot 构建时空场景图，再程序化生成 6,000 道问题，覆盖自动驾驶、安防、ego–exo 活动和机器人四个域。每道题可接收 2–8 路同步视频，任务包括计数、空间关系、时间顺序、事件排序、全局总结和最佳摄像头选择。

6,000问题
2–8同步摄像头
4真实场景域
11受测 VLM

代表实验

作者测试 Qwen、InternVL、Gemma 与 GPT‑5.2。没有一个模型在四个域上稳定领先；最依赖视角整合的任务最难：Ego‑Exo4D 的最佳摄像头识别仅约 20%–35%，MEVA 与 nuScenes 的跨视角计数多落在 11%–48%。把多摄像头按同一时间点拼成一张 tiled image，在 nuScenes 上让 Qwen2.5‑7B 的计数提升 10.5 点、事件排序提升 15.2 点；MEVA 空间推理提升 16.6 点，但在更简单的 AgiBot 上反而略降，说明“如何组织多视角”本身就是任务相关的模型设计问题。

上一期留下的问题视觉推理虽然更强，但大多仍在一张图或一条视频里 grounding。本月新增答案真正部署时，grounding 还要决定“证据来自哪个视角、多个视角是否指向同一实体”。

局限

问题由结构化元数据和 GPT‑5.2 表述生成，并没有逐题人工验证；部分题仍是多选题。它准确暴露了“多视角缺口”，但暂时不能回答哪种专门训练或架构能系统性解决这个缺口。

一手来源：论文 · 作者项目页 / 数据与代码入口

2. StreamArena / StreamMind：实时交互与长期记忆必须拆开

小时级流主动触发多模态记忆2026-08-06

为什么重要。短视频选择题很容易给模型“作弊通道”：只看最近几帧也可能猜对，选项还会泄露语言先验。StreamArena 把任务改成平均 88.8 分钟的连续音视频流、开放式答案和严格的因果访问，并同时测实时感知、历史回溯、工具使用和主动提醒。

243完整长视频
88.8 min平均时长
3,646人工核验任务
4部署能力

方法

StreamMind 不是一个新的 end-to-end VLM，而是一套两层系统。Front Worker 决定直接回答、委派历史检索，还是启动独立 Monitor；Memory Writer 持续把音视频写成微事件—宏事件—超级事件层级，同时保留实体关系和关键帧；Router、Recall、Search Workers 在查询到来后并行找历史证据或外部信息。关键思想是：把持续感知和记忆构建移出响应关键路径，但不把历史视觉证据压成纯文本。

代表实验

StreamMind 在四项能力上的准确率分别为 44.5%（实时感知）、34.9%（历史回溯）、56.1%（工具使用）和 11.6%（主动交互）。相对每项最强的流式基线，论文报告的相对提升为 58.4%、53.7%、228.1% 和 54.7%。同样使用 Qwen3.5‑397B‑A17B 时，汇总查询响应延迟从 81.4 秒降到 27.5 秒，减少 66.2%，同时保留离线方案 89.7% 的汇总准确率。

不要误读：StreamMind 的 streaming baseline 多使用更小 backbone，跨方法增益同时混入模型规模和系统设计差异。更可信的隔离证据是同 backbone 的离线—流式延迟对比，以及不同历史间隔上的退化曲线。
上一期留下的问题Mage‑VL 和 MOSS‑VL 说明模型可以边看边处理，但长期记忆、主动触发、外部搜索仍像分散功能。本月新增答案要把它们组合成可用系统，应把响应前端与异步认知后端解耦，而不是让一个解码循环包办所有工作。

局限

最强结果依赖 397B MoE backbone，主动准确率仍只有 11.6%，30 分钟以上的历史回溯显著下降。官方仓库当前公开了 benchmark、runner、judge 与评测驱动，但论文完整 StreamMind agent 标为后续开放；因此工程可复现性仍不完整。

3. VideoGAIA：视频理解开始按 Agent 任务来考

视觉在环 Agent工具调用开放世界证据2026-08-12

为什么重要。Video‑MME 一类传统评测已经接近饱和，但“看完视频回答一道题”并不等于能用视频完成现实任务。VideoGAIA 要求模型先从视频中识别多个锚点，再网页搜索、打开页面、重看选定时间段，最后把视觉证据与外部事实拼起来。

评测协议

271 道任务来自 10 万候选视频，覆盖文化、地理、日常生活、历史、技术和经济。每题必须包含至少两个视频锚点、至少两次网页检索或页面抽取、至少三步推理，并经三名人工标注者独立核验。统一 ReAct harness 先提供 20 帧粗采样，模型随后可调用网页搜索、页面访问，以及“thinking with videos”（从自选时间段再采最多 20 帧），总预算 40 步。

271人工核验任务
20前沿模型
58.30%最高总体准确率
36.8–48.0%失败源于视频感知

代表实验

20 个模型全部低于 60%；最高的是 Seed2.0‑Pro 58.30%，Qwen3.7‑Plus 为 56.09%，Kimi‑K3 为 54.61%，GPT‑5.5 为 53.14%。错误分析更有价值：在五个代表模型的失败轨迹中，36.8%–48.0% 的主因是视频感知，20.3%–31.0% 是网页检索，14.2%–28.6% 是证据推理，而答案格式只占 2.4%–3.3%。这说明工具再多也救不回错误视觉锚点；Agent 首先必须知道自己看到了什么、哪里不确定、下一步该补哪条证据。

上一期留下的问题DeepVoyager‑VL 把搜索绑回视觉，但缺少统一、可诊断的开放世界视频任务。本月新增答案VideoGAIA 把“观察—检索—重看—交叉验证”做成评测协议，并能把失败拆成感知、检索、推理、执行五类。

局限

271 题规模不大，主要是英语，音频依赖弱；统一的简单 ReAct harness 不能代表更成熟 Agent 系统的上限。评价使用 LLM judge，虽然任务经过人工验证，最终模型分数仍可能受 judge 偏差影响。

4. Clue‑OPSD：让“知道该看哪里”的老师教全视频学生

长视频训练OPD / OPSD特权视觉条件2026-08-26

关键观察。对同一个模型，给它完整长视频不一定比给相关的 10 秒线索更好。在 CG‑Bench 的 1,000 道题上，Qwen3.5‑2B / 4B / 9B 只看标注线索区间，比看全视频分别高 13.30、13.60、14.96 个点；平均输入帧从 1,024 降到 68.15。模型并不缺“更多画面”，它缺的是对相关画面的聚焦。

方法

训练时，student 接收完整视频并从当前策略采样回答；EMA self‑teacher 接收同一问题，但视觉输入只包含标注的 clue interval。两条分支沿 student 自己生成的前缀计算 next-token 分布，再用 Jensen–Shannon divergence 做逐 token 对齐。teacher 和 student 不是大小模型关系，差异只来自视觉条件。

L = average_t JSD( p_student(next token | full video, student prefix), p_teacher(next token | clue interval, same prefix) )

白话翻译：老师不是直接告诉学生标准答案，而是在学生自己可能走错的每一步上，用“已经看见关键片段后的概率分布”给密集提示。模型因此学习从全视频里形成更接近线索聚焦后的判断。

代表实验

在 Qwen3.5‑4B 上，Clue‑OPSD 相对原模型把 MLVU 从 68.45 提到 76.68，LVBench 从 54.45 提到 59.87，LongVideoBench 从 61.58 提到 66.62，MMVU 从 63.84 提到 66.99；并在这四项上超过同数据的 SFT、GRPO 和普通 OPSD。消融中，把 teacher 换成随机同长度片段，MLVU 从 76.68 跌到 52.32；只在文本里告知线索时间而仍看全视频，则为 73.66。核心收益确实来自“视觉上聚焦相关时间段”。

上一期留下的问题主动视觉通常在推理时通过 crop、zoom 或视频工具多轮寻找证据，效果好但延迟高、链路复杂。本月新增答案Clue‑OPSD 把“该看哪里”作为训练期特权信息蒸馏进去，推理仍保持标准全视频 VLM，不增加定位模块。

局限

它把人工 clue interval 的成本从推理期移到训练集制作期，并没有消除标注需求；主要评测仍是长视频多选题，能否迁移到开放式、流式或工具型任务尚未验证。论文未给出公开代码仓库，复现状态弱于本期其他工作。

5. STITCH：把视频先切成可复用的“语义时间线”

训练免费语义分块帧选择2026-08-28

为什么重要。事件边界检测、文本定位和长视频选帧看起来是三种任务，其实都先要回答“有意义的时刻发生在哪里”。STITCH 试图把这一步独立出来：同一条视频只编码一次，得到一组可复用的语义 chunk，之后再按任务读取。

方法

默认设置把视频切成 2 秒窗口，每窗均匀采 4 帧，用冻结的 InternVideo2‑Stage2‑1B 得到归一化 embedding。Kernel change-point detection 在整段 embedding 轨迹上找变化点，随后合并过短 chunk。整个分块与查询无关、无需训练；文本检索用 query embedding 给 chunk 打分，VLM 选帧则用 chunk-aware MMR 同时兼顾相关性和多样性。

代表实验

同一套前端跨三类任务工作：Kinetics‑GEBD / TAPOS 的平均 F1 为 83.9 / 44.8；ActivityNet Captions / QVHighlights 的 R@1@0.5 为 32.9 / 64.6；在 LLaVA‑OV‑7B 只看 8 帧时，相对均匀采样在 MLVU、LongVideoBench、VideoMME 上分别提升 8.5、2.8、3.0 点。它不总赢过专门训练的方法，但证明一个不针对具体任务训练的时间结构也能跨任务复用。

上一期留下的问题流式编码和 Agent 检索各自维护视频状态，容易重复编码、重复搜索。本月新增答案STITCH 提出“视频侧先生成一次通用时间线”，后续定位、检索和 VLM 选帧共享同一结构。

局限

质量受冻结 embedding 限制：细微动作可能被漏掉，无关运动会造成过分切割；单尺度 chunk 不能同时覆盖动作、事件和故事弧。当前实现是离线分块，并非真正在线的因果 streaming memory；代码链接仍是匿名评审仓库。

一手来源：论文 · 作者随论文提供的匿名代码仓库

把五篇串起来：8 月的三条贯穿线

一、评测在拆除旧捷径

CrossView 拆掉单摄像头假设；StreamArena 拆掉短片段、选择题和“等用户问了再看”的假设；VideoGAIA 拆掉视频内部证据自包含的假设。新评测不再只问“模型能不能回答”，而是问：它是否在正确时间、正确视角找到正确证据；证据不足时，是否知道下一步该观察还是搜索。

二、长视频的主问题从“能塞多少”变成“留下什么”

StreamMind 保存事件层级、实体关系和关键帧；Clue‑OPSD 用训练期线索教模型忽略无关画面；STITCH 把稠密帧变成可复用语义 chunk。三种做法分别作用于系统、训练和推理，但都拒绝“把更多帧均匀塞入上下文”这条单一路径。

三、Agent 能力受制于最前面的视觉锚点

VideoGAIA 中最大错误源是视频感知，而不是答案格式；StreamArena 的工具任务也必须先从画面 grounding 实体，再做外部检索。这与上一期 Thinking with Visual Grounding、DeepVoyager‑VL 的结论相互印证：如果第一步视觉证据错了，后面的搜索和长链推理只会把错误包装得更完整。

对实际 VLM 系统最有用的四点

  1. 先做证据预算，再做 token 预算。对长视频或多图输入，记录每个答案真正依赖的时间段、视角和区域；否则只看总 token 数，很难判断压缩是否丢了关键信息。
  2. 训练数据中加入“特权证据”。如果已有 OCR bbox、目标框、关键帧或人工线索区间，可以借鉴 Clue‑OPSD：让 teacher 看聚焦证据、student 看原始输入，用 on-policy 分布对齐传递“该看哪里”。
  3. 把视频记忆设计成多模态索引。只存文本摘要会丢小字、颜色、几何和身份线索；至少保留事件摘要、实体关系、时间戳与关键帧的可追溯映射。
  4. 评测 Agent 时单独统计第一步视觉错误。把失败拆成视觉 grounding、检索、证据整合、工具协议和答案生成；VideoGAIA 的结果说明，单看最终正确率会掩盖真正瓶颈。
下月值得盯的信号：跨视角训练而不只是 benchmark；能在线更新的语义 chunk / 多模态记忆；用小模型复现 StreamMind 式解耦；以及把视觉证据奖励直接纳入 Agent RL。若没有这些，更多“超长上下文 VLM”很可能只是输入上限变长，证据利用率并未同步提升。

为什么没有把每条能力线都塞一篇论文？
本月主动观察与实时基础模型的新增候选，要么是应用特化，要么没有形成相对 ActiveVision、Mage‑VL、MOSS‑VL 的明确方法增量。报告因此把它们标为“无承重新工作”，而不是用弱相关论文补齐六格。StreamArena 同时覆盖主动触发与实时系统，但它的核心贡献更接近评测和系统解耦，而不是新的 end-to-end foundation model。
跨论文数字能否直接比较？
不能。五篇论文的数据集、输入预算、backbone、答案格式与 judge 都不同。本报告只在同一论文的同表或受控消融内计算增量；跨论文只比较问题设定和方法方向，不据此宣布“模型 A 强于模型 B”。
