Kimi K3：把开放模型的两条扩展轴同时推到前沿

Kimi K3: Open Frontier Intelligence

一句话判断：真正值得看的不是 2.8T 这个数字，而是 KDA、跨层残差、极稀疏 MoE 与百万 token Agent RL 如何被装进同一套训练—推理系统。

0 · 为什么值得看

Kimi K3 是本月最像“完整基座模型工程学”的报告：2.8T 总参数、104.2B 激活参数、93 层、原生视觉与 1M 上下文，同时把长程 Agent 训练做到数百至数千次工具调用。价值不在刷新规模纪录，而在于它明确承认开放模型若只做推理时扩展、预训练底座却停留在相近规模，能力会趋同；因此同时扩预训练规模与测试时推理。

1 · 出发点：作者真正卡在哪里

传统全注意力在百万 token 上代价过高，普通串行残差又让深层信息逐层衰减；MoE 若把专家数推得很高，还会出现路由失衡和通信空转。K3 把这三个瓶颈分别映射到序列、深度和宽度三条轴，而不是用单个“新层”解释全部收益。

2 · 方法拆解：三条扩展轴如何接起来

先抓住整条链：K3 同时沿三条轴扩展信息流：KDA 与 Gated MLA 管 token 轴的长短程记忆，LatentMoE 管 channel 轴的稀疏宽度，Attention Residuals 管 layer 轴的跨层回读；后训练再把多种策略合回同一模型。

关键公式 · 论文 Eq. (1)

St=(I−βtktktT)Diag(αt)St−1+βtktvtTo~t=StTqt

白话翻译：KDA 先按通道保留上一时刻状态，再用当前 key/value 做一次带写入强度 β 的修正，最后用 query 从更新后的状态读出。α 决定每个通道忘多快；它把百万 token 历史压进递归状态，却也需要周期性全局层补回精确内容寻址。

(1) 文本与视觉统一到因果序列

文本直接 token 化，图像与视频先经 MoonViT‑V2 变成视觉 token，再进入统一因果序列；预训练和后训练最终都落在统一 next-token 接口上。 MoonViT-V2 只负责把图像和视频压成可被语言主干消费的 token，之后所有模态共享 next-token 接口。统一接口让长上下文和 MoE 架构复用到视觉任务，但视觉时间结构是否保留仍取决于编码器与位置表示。

(2) KDA 递归记忆配合周期性全局校正

每个 block 用 3 层 Kimi Delta Attention 维护递归状态，避免百万 token 全量展开 KV；第 4 层 Gated MLA 周期性做全局内容交互，纠正纯递归记忆可能累积的局部偏差。 KDA 把历史压进固定递归状态，适合百万 token 的持续记忆；每隔一层插入的 Gated MLA 则重新访问显式上下文，纠正递归状态可能遗忘的精确细节。3:1 的交替不是重复模块，而是在常数状态效率与内容寻址精度之间分工。

(3) Attention Residuals 跨层选择信息

Attention Residuals 为当前层构造 pseudo-query，对 embedding 与多个早期 block 学习权重 α，再组合成输入。白话说，深层不必只接上一层，而能有选择地回读较浅表征。 普通残差只把上一层送给下一层，AttnRes 用当前层的 pseudo-query 给 embedding 与多个早期 block 分配权重。深层可绕过已经被过度变换的中间层，直接取回浅层词法或视觉信息；代价是额外跨层缓存和路由稳定性要求。

(4) Stable LatentMoE 扩宽而不激活全部参数

Stable LatentMoE 每 token 从 896 个路由专家中激活 16 个，并固定启用 2 个共享专家；quantile balancing 抑制热点专家和通信空转，使极稀疏宽度仍能训练稳定。 每 token 从 896 个路由专家中选 16 个，再固定启用 2 个共享专家：路由专家提供容量，共享专家承接普遍模式。quantile balancing 约束热点与冷门专家的负载分位数，目标不仅是均匀计数，还要减少 all-to-all 通信中的慢卡拖尾。

(5) 多域 RL 与蒸馏合并部署策略

预训练后分别做通用、代码、Agent 与多推理强度 RL，再以多教师 on-policy distillation 合并。推理输出是文本与工具轨迹，百万 token 状态由 KDA cache、持久 rollout 和可恢复沙箱共同维持。 通用、代码、Agent 与不同推理强度的 RL 分别产生专门策略，再用多教师 on-policy distillation 把这些行为压回单一 checkpoint。部署时还依赖 KDA cache、持久 rollout 和可恢复沙箱，因此报告能力是模型架构、后训练与系统状态共同形成的。

3 · 关键证据：主实验和消融是否支撑结论

Figure 1 / Table 6 中，K3 在 ProgramBench 得 77.8，超过 GPT‑5.6 Sol 的 72.9 与 Fable 5 的 71.7；Terminal‑Bench 2.1 为 88.3，接近 GPT‑5.6 Sol 的 88.8。Figure 7 的外推 scaling-law 曲线给出相对 Kimi K2 约 2.5× 的综合 scaling efficiency；但这是架构、数据和训练 recipe 的合并结果，论文没有提供足以把 KDA、AttnRes、LatentMoE 各自贡献完全隔离的消融。

4 · 边界：哪些结论不能外推

报告自己的总评仍低于最强闭源模型；不同 benchmark 使用不同 Agent harness，也会混入框架效应。训练数据只披露 Web、代码、数学、知识与视觉大类，无法复建语料。完整推理权重已发布，但约 1.56TB 的 MXFP4 checkpoint 远非消费级部署；开放的是推理底座，不是训练数据、优化器状态和全训练流水线。

5 · 复现判断：先验证三条信息流

外部团队不现实地重训 2.8T 模型，最有价值的是固定公开 checkpoint 与同一 Agent harness，分别记录 KDA state/KV 占用、Gated MLA 周期层的长程检索误差，以及 LatentMoE 的专家负载和 all-to-all 等待时间；再在 32K→1M 上画准确率、首 token 延迟与 decode 吞吐曲线。权重约 1.56TB，部署前还需核对分片、量化格式、MoonViT 输入和沙箱持久状态是否与官方配置一致。这样能复核架构是否按报告工作，但不能重现训练数据带来的能力。

Orca：把世界模型的中心对象从像素改成“状态”

Orca: The World is in Your Mind

一句话判断：它不是给视频生成换一个名字，而是让冻结的世界 latent 同时接受语言、未来图像与机器人动作三种 readout 检验。

0 · 为什么值得看

Orca 值得看，因为它给“世界基础模型”提出了可证伪的接口：同一冻结 latent 必须能读出语言解释、动作条件下的未来视觉状态与机器人动作。这样，模型是否真的学到状态转移，不再只靠好看的视频样例判断。

1 · 出发点：作者真正卡在哪里

next-token、next-frame 与 next-action 都把目标绑在一种输出模态上，局部结果可以逼真，却未必形成可迁移的环境状态。Orca 因此把目标改成 Next-State-Prediction：先从多模态信号抽象状态，再学习状态在隐式动力学与显式事件条件下如何前后转移。

2 · 方法拆解：状态怎样从观察中长出来

先抓住整条链：Orca 不直接规定最终输出模态，而是先训练一个可转移的 world latent：连续观察教自然动力学，事件文本教关键变化，VQA 保证状态可被语言查询；冻结后再用三类 readout 检验它是否真有用。

关键公式 · 论文 Eq. (1)

St+Δ∼pΘ(St+Δ|St,zt,ct),Δ∈Z≠0

白话翻译：Orca 的核心对象是状态 S：给定当前状态、观测/动作信号 z 与语义条件 c，它学习任意非零时间偏移 Δ 的状态分布。Δ 可正可负，因此同一 latent 同时承担未来预测与事件前后状态恢复。

(1) 用三种数据描述同一世界状态

连续视频提供稠密观察，事件文本指出有语义的变化，VQA 要求状态可被语言查询；库存含 125K 小时视频、160M 事件与 11.5M VQA，当前训练约使用十分之一视频。 视频给稠密但未标注的连续变化，事件给稀疏而有语义的转折，VQA 把状态转换成可查询事实。三者覆盖频率、语义密度和监督形式不同，组合的目的不是扩大样本数，而是减少只靠像素邻近或只靠语言描述的偏差。

(2) 把多模态观察压进共享 latent

预训练 VLM 把视觉和语言投到共享 latent，不强制 latent 立即生成某种具体模态，从而给环境状态与转移关系保留中间表达空间。 预训练 VLM 提供初始视觉语言对应，Orca 把观察编码为不绑定某个 decoder 的中间状态。不给 latent 立即承担高保真像素生成，可把容量优先用于对象、关系和转移；但这也意味着状态质量必须靠下游探针而非生成样例验证。

(3) 无意识与有意识学习怎样互补

“无意识学习”从相邻观察吸收连续、稠密但未标注的自然转移；“有意识学习”用事件与问题标记稀疏却关键的因果变化，补足仅靠像素邻近难以发现的语义事件。 “无意识”分支从相邻观察学习普遍、连续的环境演化，“有意识”分支用事件条件突出开门、拿起、碰撞等语义变化。前者覆盖广，后者因果指向清晰；只保留任一分支都会让 latent 在连续性或关键事件上失衡。

(4) 三项目标共同约束状态转移

observation-only transition 学隐式动力学，event-conditioned transition 学显式条件转移，VQA generation 保证 latent 能被语言读取；三项目标共同约束同一状态空间。 observation-only transition 学没有显式事件文本时的隐式动力学，event-conditioned transition 学给定事件后的状态变化，VQA generation 要求 latent 能被语言读出。三项损失不是三个独立模型，而是把同一状态空间同时约束为可预测、可操控、可解释。

(5) 冻结 encoder 后用 readout 做压力测试

评测时冻结 encoder，分别挂轻量文本头、图像预测头和 Action Expert。如果同一 latent 能支持解释、未来视觉和机器人动作，才说明表示超越单一输出模态。 评测时冻结 encoder，文本头测试语义读出，图像头测试未来视觉，Action Expert 测试控制迁移。保持 probe 轻量和容量一致很关键，否则某个强 decoder 可能在下游重新学习任务，掩盖 world latent 本身是否携带状态。

3 · 关键证据：主实验和消融是否支撑结论

Table 1 中，Orca‑4B 在 MVBench、TemporalBench、3DSRBench、SWITCH 的综合分为 51.8，高于同规模 Qwen3.5 的 46.7；Table 4 的真实机器人 OOD 汇总里，rule-based 进度得分 32.4，高于 π0.5 的 29.4，并有更好的 drawdown recovery。Table 5 消融最有信息量：三目标齐全平均 48.0；去掉 VQA、保留 observation+event 为 44.6，去掉任一状态转移项也会让某个 readout 不可用或明显失衡。

4 · 边界：哪些结论不能外推

模型目前主要依赖视觉和语言，缺少触觉、力、音频与本体感觉；视觉状态还被预训练 ViT 空间限制。实验只在 0.8B/4B，并且多数事件是分钟级短视野；PRICE‑V0.1 规模和交互丰富度也有限。项目页、代码仓库与部分资源已开放，但完整 125K 小时库存没有全部用于训练，外部复现仍难覆盖同等数据条件。

5 · 复现判断：冻结 latent 再做三种探针

最小验证不必重建 125K 小时库存：先用开放主干或较小替代数据训练 observation、event、VQA 三目标，再完全冻结 encoder，分别训练文本 readout、未来图像头和 Action Expert。关键是保持探针容量一致，并同时做“去掉一个目标”的对照；若某个 readout 只在增加对应大头后变好，就不能归功于共享 world latent。机器人侧还应把 OOD 初始状态、恢复阶段进度和最终成功分开记录，避免平均进度掩盖未完成任务。

ABot‑World‑0：世界模型开始按“交互延迟”而非采样步数交卷

ABot-World-0: Infinite Interactive World Rollout on a Single Desktop GPU

一句话判断：动作条件、闭环 rollout、长时分布漂移和单卡实时部署同时被测，因而符合世界模型而非普通视频生成的口径。

0 · 为什么值得看

ABot‑World‑0 把世界模型落到可操作的系统指标：按键到首帧、持续 FPS、显存、动作忠实度与长时漂移。它以过去帧和未来动作预测下一段视频，并不断把生成结果反馈为新历史，因此核心是闭环交互动力学，不是一次性视频合成。

1 · 出发点：作者真正卡在哪里

双向视频 diffusion 可以借未来上下文得到高画质，却不能在线响应；改成因果生成后又会积累误差。即使把去噪压到少数几步，VAE、KV cache、注意力、RoPE 与模型常驻仍可能让系统达不到实时。论文把“模型漂移”和“系统瓶颈”分开处理。

2 · 方法拆解：从双向教师到单卡闭环 student

先抓住整条链：ABot 先用能看完整片段的双向 diffusion teacher 学画质与动作，再把知识迁到因果 student；ODE 蒸馏减少去噪步数，LongForcing 专门校正闭环自生成分布，系统优化把它压到单卡实时。

关键公式 · 论文 Eq. (11)

LODE=E[∥fθ(zsc,s,Ct)−sg(z0c)∥2]

白话翻译：student 在噪声时刻 s 直接预测干净因果 latent，目标是 teacher 从同一条件积分到零噪声得到的结果；sg 表示 teacher 分支停止梯度。这样多步扩散轨迹被压成 few-step 映射，直接降低交互延迟。

(1) 把历史、动作与身份记忆分开编码

LongStraw：长上下文 RL 的瓶颈其实是“状态活多久”

LongStraw: Long-Context RL Beyond 2M Tokens under a Fixed GPU Budget

一句话判断：它把 GRPO 的共享超长 prompt 从 autograd 图中剥离，只让当前 response branch 带梯度存活，从而把显存峰值从组大小中解耦。

常规 autograd 会让整段 prompt 与所有 response 图同时常驻；checkpointing 仍需在 backward 重建超长 attention 与 MoE 路由。Agent 轨迹又天然共享大量前缀。若能把 prompt 视为只读边界状态，内存应由短 response 而非 prompt+group 总长度决定。

2 · 方法拆解：让超长 prompt 退出 autograd 生命周期

先抓住整条链：LongStraw 不改 GRPO 数学目标，而是重排状态生命周期：超长 prompt 先在 no-grad 下编码成边界状态，old/reference 只评分，policy responses 逐条恢复边界并回放短分支，最后才统一更新参数。

Lpolicy=−1G∑i=1G1Ri∑t=1Rimin(ρi,tAi,clip(ρi,t,1−ε,1+ε)Ai)

白话翻译：每条 response 仍按 importance ratio ρ、组内优势 A 与 PPO clipping 计算同一个 GRPO 目标；LongStraw 没有改这条数学定义。它改变的是求梯度的顺序：prompt 只捕获一次，response 按成员串行回放，最后再合并梯度。

(1) 识别 GRPO 中真正共享的超长前缀

一个多百万 token 的共享 prompt 与同组 rollout responses；GRPO 仍比较组内答案，变化只发生在执行图怎样保留状态。 组内多个 rollout 共享同一 prompt，传统实现却为每条 response 保留一份长前缀计算图。LongStraw 把优化对象限定为 response-only loss，因而可以把共享 prompt 视为只读状态，而不是每条分支都要反传的序列。

(2) 把 prompt 编码成可恢复的边界状态

prompt 在 no-grad 下运行一次，只保存后续 response 真正需要的架构状态：Qwen3.6‑27B 保留 GDN 递归状态与 CP8 分片 KV page；GLM‑5.2 保存 MLA latent 和 DSA index key。 no-grad 前向只保存架构真正需要继续解码的状态：GDN 递归状态、CP8 KV page，或 MLA latent 与 DSA key。边界必须足以从 response 起点恢复精确前向；保存太少会改变 log-prob，保存太多又失去内存优势。

(3) 让评分分支退出 autograd

GLM 的超长索引状态可放在 CPU，反向时按层搬回；old policy 与 reference model 只计算 log-prob，不构建反向图，因此不会与所有 response 梯度同时常驻。 old policy 和 reference model 只提供 KL/比率所需 log-prob，不参与参数更新，因此无需构建反向图。GLM 的大索引状态还能驻留 CPU、按层搬回，把显存峰值换成传输和 replay 时间。

(4) 逐条回放 response 并累积梯度

policy 分支逐个恢复同一个 prompt 边界，把当前短 response 重新前向并 backward；每条 response 的梯度累积后，再统一做 distributed finalize 与 optimizer step。 policy 每次只恢复一个 response 的边界，重算短分支并立即 backward，随后释放激活；多个 response 梯度累积后再做分布式 finalize 与 optimizer step。峰值显存因此不随组大小线性涨，但总时间仍随串行回放成员增加。

(5) 处理更新后的 stale-state 边界

目标仍是 response-only GRPO，输出是更新后的 policy adapter。optimizer step 后旧边界状态已与新参数不一致，必须重捕获或显式评估 stale-state 误差，不能无限复用。 optimizer step 后参数已变化，旧 prompt state 不再等价于新模型对同一 prompt 的编码。实现必须重捕获边界或量化短期复用的 stale-state 误差，否则省下的前缀时间会悄悄改变 RL 目标。

pθ,ψ(V,z|I0,c)=pθ(z|I0,c)pψ(V|I0,z)

白话翻译：先由 θ 根据初始观察与动作条件预测离散 physical tokens z，再由 ψ 把这些符号渲染成未来视频 V。分解把“世界将如何变化”与“像素长什么样”拆开，因而可以单独检查推理错还是渲染错。

第一帧与未来视频提供真实状态序列，文本描述动作意图；视频先进入 latent 空间，避免 tokenizer 直接在高维像素上寻找离散词。 首帧保存对象外观和场景背景，相邻 latent 的差异提供运动、接触和视角变化。tokenizer 只看转移能减少静态纹理占用词表，让同一符号有机会跨外观表达相似动力学。

(2) 把变化压成离散 physical language

Physical Language Tokenizer 比较相邻 latent 状态，transition-level Q‑Former 只汇聚“发生了什么变化”，再量化为 256 个离散符号，让静态外观尽量留在首帧。 transition-level Q-Former 聚合“发生了什么变化”，再量化到 256 个离散码；离散瓶颈使动力学可被自回归 reasoner 建模，也便于查看符号复用。码本太小会丢细节，太大又可能退化成外观压缩，因此 decoder 重建是必要约束。

(3) 用 diffusion decoder 约束符号可渲染

预训练 diffusion decoder 接收第一帧和 physical tokens 重建未来视频；tokenizer 同时优化重建、量化与纯噪声 warm-up，防止离散瓶颈丢掉可渲染的运动细节。 diffusion decoder 接收首帧和 physical tokens，从噪声恢复未来视频；重建、量化与 pure-noise warm-up 共同训练 tokenizer。decoder 承担高频外观，token 承担状态变化，这种分工让 reasoner 无需直接预测像素。

Direct‑OPD：蒸馏的不是弱教师，而是 RL 改变它的方向

Weak-to-Strong Generalization via Direct On-Policy Distillation

一句话判断：用同一弱模型 RL 前后的 log-ratio 作为密集隐式奖励，避开“学生比教师强却被模仿拉低”的悖论。

0 · 为什么值得看

RLVR 每换一个更大的目标模型都要重新 rollout，成本随模型放大。Direct‑OPD 提出一个很有复用价值的观点：一对弱模型的 RL 前后 checkpoint 就像“奖励压缩包”，记录了哪些 token 被 RL 提高或压低概率，可以在强学生自己的状态上重新展开。

1 · 出发点：作者真正卡在哪里

直接 OPD 模仿 post-RL 弱教师会同时继承它的能力上限。论文示例中 R1‑Distill‑7B 起点 56.7 已高于 JustRL‑1.5B 教师 51.3，vanilla OPD 反而把它拖到约 50。需要剥离的不是教师输出，而是 RL 相对教师自身 base 造成的变化。

2 · 方法拆解：把 RL 前后差异还原成密集奖励

先抓住整条链：Direct-OPD 不让强学生模仿弱教师答案，而是在学生自己的 prefix 上比较教师 RL 前后概率；两 checkpoint 的 log-ratio 提取出“RL 把哪些 token 往上或往下推”，再作为密集奖励更新学生。

关键公式 · 论文 Eq. (10)

rt(v)=logπT(v|st)−logπTref(v|st)

白话翻译：在学生自己的 prefix 状态 st 上，若 RL 后教师比 RL 前参考模型更偏好 token v，奖励为正，反之为负。监督来自“策略被 RL 改了多少”，而不是要求学生照抄教师生成的答案。

(1) 先由强学生产生 on-policy 状态

每个 prompt 由强学生自己生成 on-policy rollout；另有同一弱教师的 pre-RL 与 post-RL checkpoint。教师不负责产出学生要模仿的完整答案。 prompt 和 rollout 都来自当前强学生，使蒸馏发生在它真正访问的状态，而不是弱教师偏好的轨迹。教师只负责给这些 prefix 的候选 token 打分，不要求生成整条可用答案。

(2) 在同一 prefix 上比较 RL 前后教师

在学生实际访问的每个 prefix 上，两教师对 top-k 候选 token 分别打 log probability；post 减 pre 的 log-ratio 为正表示 RL 鼓励该 token，为负表示抑制。 pre-RL 与 post-RL checkpoint 架构相同、差别主要来自强化学习，因此 post 减 pre 能抵消大量基座偏好。top-k 候选把比较集中在当前真正可能采样的 token 上，也控制两次大词表打分成本。

(3) 把 log-ratio 解释成隐式 token reward

在 KL-regularized RL 假设下，这个 log-ratio 等价于缩放后的隐式 dense reward。白话说，两个 checkpoint 共同记录“RL 想把策略往哪里推”，而不是“弱模型最终有多强”。 若 RL 采用 KL 正则，最优策略相对初始策略的 log 概率位移与奖励成正比；因此 log-ratio 为正表示该 token 被 RL 鼓励，为负表示被压制。这里蒸馏的是策略更新方向，而不是教师最终概率本身。

(4) 用低方差 policy gradient 与自适应 KL 更新

Rao–Blackwellized top-k policy gradient 用密集 token reward 减少采样方差，同时 KL 项把学生锚定在初始策略；adaptive KL 根据 batch 奖励符号调节约束，避免无界追逐位移。 Rao-Blackwellization 对 top-k 候选求期望，减少只采一个 token 带来的方差；KL 项把强学生锚在原策略附近，adaptive KL 根据 batch 奖励符号调节约束。三者共同避免密集奖励把学生推向教师未验证的极端区域。

白话翻译：对当前 prompt x，在候选 block size 中选择期望接受 token 数 τ 最大的那个。BlockPilot 学的不是答案内容，而是这个 argmax 决策；预测特征必须来自 target prefill，才能提前估计“草稿能被接受多长”。

3 · 关键证据：主实验和消融是否支撑结论

Table 2 在 Qwen3‑4B、temperature=1 的 Math/Code/Chat 平均中，最佳固定 DFlash 为 3.80×，BlockPilot 4.20×，平均 acceptance length 5.92。temperature=0 时也从固定 DFlash(16) 的约 3.99×提高。Table 4 的 k 消融：GSM8K k=1/2/3 分别 4.67/4.76/4.64×，HumanEval 4.44/4.46/4.39×，说明更宽候选集并不持续增益；Table 5 的输入预处理相对 softmax 在 GSM8K 4.55→4.76×，支持 prefill 分布确实含有决策信号。

4 · 边界：哪些结论不能外推

最优标签生成需要每样本执行多个 block；32B 模型默认五候选约 25 秒/样本，成本只是离线却不小。策略整段生成只预测一次，无法适应生成中途不确定性变化；实验主要是 Qwen3 与 Llama、数学/代码/聊天，长文与多轮工具场景尚未证明。代码已在 AMAP‑ML/BlockPilot 开放。

5 · 复现判断：把标签成本计入总收益

用开放代码复现时应固定目标/草稿模型、GPU、temperature 和生成长度，先枚举所有候选 block 得到 oracle speedup，再比较固定 B、BlockPilot 与 oracle；同时记录 predictor 7.34ms 开销、接受长度和 target verification 次数。离线标签生成也应折算为总 GPU 小时，计算需要服务多少请求才能回本。为了检验“一次决策”边界，可把长回答分段重新预测 block size，与只在 prefill 后预测一次比较，观察自适应频率增加是否值得额外开销。

HunyuanOCR‑1.5：轻量 OCR 的下一步是长输出加速与长尾数据闭环

HunyuanOCR-1.5: Making Lightweight OCR VLMs Faster and Better

一句话判断：不换主干，用 DFlash 把长表格/公式的解码并行化，再用 Agentic Data Flow 从模型弱点反推数据生产任务。

0 · 为什么值得看

HunyuanOCR‑1.5 没用“换更大 backbone”解决问题，而是在已验证的 0.5B 语言主干上同时处理部署与长尾：长结构输出用 diffusion draft 加速，古文字、低资源语言、多页 QA 等缺口则交给 Agentic Data Flow 构造针对性数据。

1 · 出发点：作者真正卡在哪里

端到端 OCR VLM 在密集文档、HTML 表格和公式上要自回归生成很长序列，token-by-token 解码成为主延迟；另一方面，真实 OCR 远不止单页 Markdown parsing，手工扩充 331 语言、古籍字体、跨页证据的流水线成本极高。

2 · 方法拆解：轻量主干、扩散草稿与数据闭环

先抓住整条链：HunyuanOCR-1.5 保留自回归主模型负责能力，把一个 5 层 block-diffusion 小模型放在旁路草拟 16 token；训练端用多 anchor 并行构造局部任务，数据端则围绕失败模式持续补长尾样本。

关键公式 · 论文 Eq. (2)

LDFlash=1Z∑j=1K∑k=1B−1wk(j)[−logpθ(yk(j)|h<aj,m1:B(j))]

白话翻译：一条长答案同时抽 K 个 anchor，每个 anchor 都生成一个 B-token 局部草拟任务；权重 w 对靠近 anchor、有效且非首位的 token 更大，Z 负责归一化。一次序列前向因此能并行训练多个局部草稿，而不用逐块重复主干。

(1) 原生比例图像进入轻量 OCR 主干

原生比例最高 4K 图像、多图和最长 128K context 经 HunyuanViT、adaptive MLP connector 进入 Hunyuan‑0.5B LLM，主模型继续自回归输出文本与结构。 HunyuanViT 保留高分辨率版面，adaptive connector 把视觉 token 对齐 0.5B LLM；多图与 128K context 主要服务多页解析和问答。主模型仍按标准自回归顺序产生文字与结构，是质量分布的最终裁判。

(2) 旁路 DFlash 一次草拟 16 token

旁路约 90.7M、5 层 block-diffusion draft model 一次预测 16-token block；冻结 target LLM 批量验证所有位置并接受最长正确前缀，因而保持 target 分布。 约 90.7M 的 5 层草稿模型并行预测一个 16-token block，冻结 target LLM 一次验证整块并接受最长正确前缀。草稿错时由 target 接管，因此旁路只影响速度，不应改变识别结果分布。

(3) 多 anchor 训练提高草拟效率

每条 target 序列随机取 16 个 anchor，用 block-diagonal FlexAttention mask 同时构造多个局部草拟任务；距离 anchor 越远的 token loss 指数衰减，强调更可能被接受的近端位置。 一条 target 序列随机选 16 个 anchor，block-diagonal FlexAttention 让这些局部草拟任务在一次前向中互不泄漏。离 anchor 越远越难被接受，指数衰减 loss 把训练重点放到更高价值的近端 token。

(4) 从失败模式反推长尾数据生产

系统先分析古文字、331 语言、多页 QA 等失败模式，再把缺口拆成材料搜索、字体核验、脚本开发、样本清洗和人机复审任务，生成可进入训练的针对性数据。 系统先按古文字、331 语言、多页 QA 等维度统计失败，再把缺口拆成搜索材料、核验字体、开发脚本、清洗和人工复审。这里的数据闭环不是简单合成更多页面，而是让每批样本对应一个已测出的模型缺陷。

(5) 主干能力训练与草稿加速分工

新增数据进入 pretrain→SFT→RL 流水线，最终输出解析、公式、表格、文字定位与文档问答；DFlash 只负责加速长序列，能力扩展主要来自主干后训练与数据闭环。 新增数据经过 pretrain、SFT 和 RL 提升解析、公式、定位与问答能力；DFlash 只压缩长输出的解码时间。复现时必须分别做“固定主干换草稿器”和“固定草稿器换数据”的对照，才能区分能力增益与加速收益。

3 · 关键证据：主实验和消融是否支撑结论

Table 2 在 OmniDocBench、batch=1：Transformers 延迟 34.850→5.474s，6.37×；vLLM 3.032→1.408s，2.14×，token/s 466.9→1002.3。Table 12 的 OmniDocBench v1.6 overall 为 94.74。输出长度诊断显示 vLLM 在 0–256 token 仅 1.31×，2048+ token 达 2.30×；表格页的 Transformers speedup 7.81×、有效接受长度 10.40，符合“结构重复越强越适合并行草拟”。论文没有提供足以隔离 Agentic Data Flow、4K/128K 扩展、SFT 与各类 RL 贡献的完整消融证据。

4 · 边界：哪些结论不能外推

OmniDocBench 的多行公式匹配协议与模型完整 LaTeX 输出不完全一致；速度是单 accelerator、指定框架和 930 样本设置，跨系统 tokenizer 不同，token/s 不可直接横比。未来仍需减少高分辨率 visual token 冗余并提高长复杂输出可靠性。论文写“将发布”权重与训练代码；当前 Hugging Face 与 GitHub 已有项目入口，使用者应以仓库实际版本核对 1.5 资产是否齐全。

5 · 复现判断：能力、草稿接受率和框架速度分开核对

先以仓库实际发布版本核对 1.5 权重、DFlash draft 与训练代码是否齐全，再在同一 930 页上分别跑 Transformers 和 vLLM，保存输出 token 数、有效接受长度、target calls、首 token 与总延迟。能力评测必须使用一致的 LaTeX/HTML 归一化，避免协议差异制造分数。Agentic Data Flow 的贡献还需固定主干，逐类加入古文字、低资源语言和多页 QA 数据；若没有这种分项消融，就只能确认完整系统有效，不能把 94.74 单独归因于数据代理。
