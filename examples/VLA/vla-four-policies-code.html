2.1 网络结构

图 2-1　OpenVLA-OFT 数据流：占位 token → 取 hidden → MLP → 连续动作

关键模块

  • 主干：Qwen2.5-VL（保留原 LM head 但不用，仅取 hidden state）
  • Action Head：L1RegressionActionHead MLP_ActionHeader.py:60
    • MLPResNet：LayerNorm → Linear(in→hidden) → ReLU → 2× ResBlock → LayerNorm → Linear(hidden→action_dim)
    • 默认形状 input_dim=2048, hidden_dim=4096, action_dim=7, NUM_ACTIONS_CHUNK=8

def __init__(self, config=None, **kwargs):
    # ─── Step 0：父类 nn.Module 必须先 super().__init__() ───────────────
    # 不写这一句的话，self._parameters / self._modules 字典都还没建好，
    # 后面 self.xxx = nn.Linear(...) 不会被 PyTorch 注册成可训练参数。
    super().__init__()

    # ─── Step 1：合并外部 yaml 配置 与 默认配置 ───────────────────────
    # merge_framework_config 把用户 yaml 里写到的字段覆盖默认值，
    # 没写的字段就保留 QwenOFTDefaultConfig 的默认。结果是一个嵌套
    # OmegaConf 对象，可以用 self.config.framework.action_model.xxx 访问。
    self.config = merge_framework_config(QwenOFTDefaultConfig, config)

    # ─── Step 2：构造 VLM backbone（Qwen2.5-VL / Qwen3-VL）─────────────
    # qwen_vl_interface 是一个 wrapper，里面挂了 .model（HF 模型本体）、
    # .processor（图像+文本 tokenizer）和 build_qwenvl_inputs() 工具。
    self.qwen_vl_interface = get_vlm_model(config=self.config)

    # ─── Step 3：把 action head 的输入维度自动对齐到 VLM 输出维度 ─────
    # OFT 的核心思路是"取 VLM 最后一层 hidden_state 当 action query"，
    # 所以 head 的 input_dim 必须 == VLM hidden_size。
    # Qwen2.5-VL-3B → 2048；Qwen3-VL-4B → 2560，写死会出 bug，所以这里
    # 直接读模型的 config.hidden_size 覆盖配置。
    self.config.framework.action_model.action_hidden_dim = \
        self.qwen_vl_interface.model.config.hidden_size

    # ─── Step 4：构造 Action Head（这里是 L1RegressionActionHead）─────
    # 进 head 的形状是 (B, K, H)，出 head 是 (B, K, action_dim)。
    self.action_model = get_action_model(config=self.config)

    # ─── Step 5：动作 chunk 长度 ────────────────────────────────────
    # action_horizon 是"一次预测多少步动作"的唯一真理源（例如 8）。
    # 旧 yaml 用 future_action_window_size，share_tools 已经规范化，
    # 这里直接读新字段就行。
    self.action_horizon = int(self.config.framework.action_model.action_horizon)
    self.chunk_len = self.action_horizon                  # 别名，方便阅读

    # ─── Step 6：定义"动作占位 token" ──────────────────────────────
    # OFT 不用真的让 LM 生成 token，而是把"🔍" 这个 emoji 重复 K 次塞进
    # prompt，再把这 K 个位置在最后一层 hidden_state 中的向量"挑出来"
    # 当成 K 条 action query，喂给 MLP 回归出动作。
    # 选 emoji 的好处：它在所有 BPE tokenizer 里都是单 token，不会被切碎。
    self.action_token = "🔍"

    # 把 emoji 编码成它在 Qwen tokenizer 里的整数 id（后面用来定位）。
    # add_special_tokens=False：不要前后自动加 <bos>/<eos>。
    # 取 [0]：tokenizer 返回 list[int]，单字符就只有一个 id。
    self.action_token_id = self.qwen_vl_interface.processor.tokenizer(
        "🔍", add_special_tokens=False
    )["input_ids"][0]

    # ─── Step 7：训练目标——L1 回归 ───────────────────────────────
    # 即 mean(|pred - gt|)，对动作量纲不敏感、抗 outlier。
    self.l1_loss = nn.L1Loss()

③ 训练前向 — QwenOFT.py:138

def forward(self, examples, **kwargs):
    # examples 是一批样本 list，每个 dict 都有 image / lang / action / (state)。
    # 这里用列表推导式把同一字段抽出成一个 batch 列表，方便后续打包。
    batch_images = [e["image"]  for e in examples]   # 长度 B 的 list，每项是 PIL.Image
    instructions = [e["lang"]   for e in examples]   # 长度 B 的 list[str]
    actions      = [e["action"] for e in examples]   # 长度 B 的 list，每项形状 [T_full, D]

    # 不是每个数据集都有 proprioceptive state（机械臂关节角等）。
    # 用第 0 条样本"嗅探"一下有没有 state 这个 key 即可。
    state = [e["state"] for e in examples] if "state" in examples[0] else None

    # ─── π0.5 风格的 state 注入 ───────────────────────────────────
    # 把连续 state 离散化（每维分箱 256 桶），转成形如 "[STATE] 12 87 ... [/STATE]"
    # 的字符串拼到 prompt 里。让 VLM 自己用文字读懂关节状态，无需额外 encoder。
    if state is not None:
        instructions = self.add_discretized_state_to_instruction(instructions, state)

    # ─── 关键：拼接 K 个动作占位符 ─────────────────────────────────
    # "🔍" * 8 → "🔍🔍🔍🔍🔍🔍🔍🔍"。
    # 注意：emoji 之间不能有空格——空格会被 BPE 切成额外 token，导致计数错乱。
    action_tokens = self.action_token * self.chunk_len

    # 把占位符夹在 <action>...</action> 标签里，让模型一眼能看出"动作区间"。
    # 对 BPE 而言这就是一段普通文本，并不需要词表扩展。
    prompt_suffix = (
        f" Please predict the next {self.chunk_len} robot actions: "
        f"<action>{action_tokens}<action>."
    )
    instructions = [ins + prompt_suffix for ins in instructions]

    # ─── 调 VLM backbone ──────────────────────────────────────────
    # build_qwenvl_inputs 内部做了三件事：
    #   1) 把 PIL 图像走 image processor → pixel_values
    #   2) 把 instruction 走 tokenizer  → input_ids / attention_mask
    #   3) 按 Qwen-VL 的对话模板拼起来
    qwen_inputs = self.qwen_vl_interface.build_qwenvl_inputs(
        images=batch_images, instructions=instructions
    )

    # bfloat16 跑前向：节省一半显存，Qwen-VL 在 bf16 下数值非常稳。
    with torch.autocast("cuda", dtype=torch.bfloat16):
        qwenvl_outputs = self.qwen_vl_interface(
            **qwen_inputs,
            output_attentions=False,        # 不要注意力图，省内存
            output_hidden_states=True,      # 要中间层 hidden_states（OFT 只用最后一层）
            return_dict=True,
        )
        # hidden_states 是 tuple(num_layers + 1)，[-1] 即最后一层输出。
        # 形状 [B, L, H]：B=batch，L=token 总数（包含图像 token），H=隐藏维度
        last_hidden = qwenvl_outputs.hidden_states[-1]

    # ─── 回归用 fp32 ──────────────────────────────────────────────
    # bf16 的尾数只有 7 bit，做小幅度 L1 回归会出现量化误差；
    # head 的参数量很小，强行升 fp32 显存代价可忽略。
    with torch.autocast("cuda", dtype=torch.float32):
        input_ids = qwen_inputs.get("input_ids", None)

        # 在 [B, L, H] 中找出 K 个 "🔍" 位置的向量 → [B, K, H]。
        # 内部用 mask + topk + sort 做"取最后 K 个并按时间序排列"，下面单独讲。
        action_queries = self._gather_action_token_embeddings(
            last_hidden, input_ids, action_token_id=self.action_token_id
        )

        # 喂给 MLPResNet：reshape 成 (B*K, H) 过 MLP，再 view 回 (B, K, D)。
        pred_actions = self.action_model.predict_action(action_queries)  # [B, K, D]

        # 把 actions（list of np.ndarray）→ torch.Tensor，对齐 device / dtype。
        actions = torch.tensor(np.array(actions),
                               device=pred_actions.device, dtype=pred_actions.dtype)

        # 数据集里每条 trajectory 可能有 T_full = past + future 步动作；
        # 这里只取最后 action_horizon 步作为监督目标（GT 与 pred 形状对齐）。
        actions_target = actions[:, -self.action_horizon:, :]            # [B, K, D]

        # mean(|pred - gt|)：对每个维度、每步都求均值再总平均。
        action_loss = self.l1_loss(pred_actions, actions_target)

    # 训练 loop 拿这个 dict 去做 backward。
    return {"action_loss": action_loss}

@torch.inference_mode()                  # 比 no_grad 更彻底——还会关掉 version counter，速度更快
def predict_action(self, examples, **kwargs):
    # 部署时通常一帧一调用，传进来可能是单 dict 而非 list。
    # 统一包成 batch=1，这样后面所有代码都和训练共享。
    if type(examples) is not list:
        examples = [examples]

    # to_pil_preserve：把 numpy / tensor / 路径统统转成 PIL.Image，但保留分辨率与色彩空间。
    batch_images = [to_pil_preserve(e["image"]) for e in examples]
    instructions = [e["lang"] for e in examples]
    state = [e["state"] for e in examples] if "state" in examples[0] else None

    # 与训练保持一致：state 注入 → prompt 后缀。否则训练/推理分布会偏。
    if state is not None:
        instructions = self.add_discretized_state_to_instruction(instructions, state)

    # ─── 推理图像分辨率必须与训练一致 ─────────────────────────────
    # 训练时常 224×224 / 384×384，部署相机可能给 720p。
    # 这里读训练时的 obs_image_size，把图统一 resize，避免 patch 数量错位。
    train_obs_image_size = getattr(self.config.datasets.vla_data, "obs_image_size", None)
    if train_obs_image_size:
        batch_images = resize_images(batch_images, target_size=train_obs_image_size)

    # 训练里怎么拼 prompt，这里就怎么拼，一字不差——这是 OFT 不出 OOD 的关键。
    action_tokens = self.action_token * self.chunk_len
    prompt_suffix = (
        f" Please predict the next {self.chunk_len} robot actions: "
        f"<action>{action_tokens}<action>."
    )
    instructions = [ins + prompt_suffix for ins in instructions]

    qwen_inputs = self.qwen_vl_interface.build_qwenvl_inputs(
        images=batch_images, instructions=instructions
    )

    # bf16 forward，省显存
    with torch.autocast("cuda", dtype=torch.bfloat16):
        qwenvl_outputs = self.qwen_vl_interface(
            **qwen_inputs, output_hidden_states=True, return_dict=True
        )
        last_hidden = qwenvl_outputs.hidden_states[-1]    # [B, L, H]

    # head 用 fp32，跟训练对齐
    with torch.autocast("cuda", dtype=torch.float32):
        # 同样的 mask+topk 取 K 个 query
        action_queries = self._gather_action_token_embeddings(
            last_hidden, qwen_inputs.get("input_ids"),
            action_token_id=self.action_token_id,
        )                                              # [B, K, H]

        # 一次前向直接拿到完整动作 chunk——OFT 的核心卖点：parallel decoding，无自回归。
        pred_actions = self.action_model.predict_action(action_queries)

    # 部署 pipeline 习惯吃 numpy；后处理（反归一化）一般在框架外面做。
    return {"normalized_actions": pred_actions.detach().cpu().numpy()}

⑤ 取 query 的核心：topk + 时间排序 — QwenOFT.py:278

def _gather_action_token_embeddings(self, last_hidden, input_ids, action_token_id):
    """
    目标：在长长的 input_ids 序列里，定位 K 个 "🔍" 的位置，把 last_hidden 里
         对应的 K 条向量"原地拎出来"，并保证按时间顺序排列。

    last_hidden: [B, L, H]   B=batch  L=token 数  H=隐藏维度
    input_ids:   [B, L]      每个位置一个整数 token id
    返回:        [B, K, H]   K = chunk_len = self.action_horizon
    """
    device = input_ids.device
    B, L, H = last_hidden.shape

    # ─── Step 1：构造 mask（[B, L] 的 bool）──────────────────────
    # 记号：True 表示这个位置是 "🔍"，需要被挑出来。
    # 兼容两种调用：
    #   action_token_id=42         （单值）
    #   action_token_id=[42, 99]   （多值，例如有多套占位符）
    if isinstance(action_token_id, (list, tuple, set)):
        id_list = torch.tensor(list(action_token_id),
                               device=device, dtype=input_ids.dtype)
        # torch.isin：input_ids 中元素是否落在 id_list 集合里
        mask = torch.isin(input_ids, id_list)
    else:
        mask = (input_ids == action_token_id)         # 元素级比较，结果是 bool [B, L]

    # ─── Step 2：防御式校验 ──────────────────────────────────────
    # 如果哪个样本的占位符数量小于 K，直接报错——拼 prompt 的环节肯定哪里写漏了。
    counts = mask.sum(dim=1)                          # [B] 每条样本里 True 的个数
    if (counts < self.chunk_len).any():
        raise RuntimeError(f"insufficient action tokens, counts={counts.tolist()}")

    # ─── Step 3：把"位置下标"在非占位处置为 -1 ────────────────────
    # 思路：我们想要"序列中最靠后的 K 个 🔍 位置"。
    # 先生成一份 [B, L] 的下标矩阵 0,1,2,...,L-1；
    # 再用 mask 把"非 🔍"的位置改成 -1（任何 ≥0 的下标都比它大）。
    idx = torch.arange(L, device=device).unsqueeze(0).expand(B, L)   # [B, L]
    masked_pos = torch.where(mask, idx, torch.full_like(idx, -1))

    # ─── Step 4：topk 取最大的 K 个 → 即"最靠右"的 K 个 🔍 位置 ────
    # topk 默认 sorted=True，但它按"值大小"排，不是"下标大小"。这里恰好
    # 我们的"值"就是下标，所以"值最大" == "位置最靠右"。但顺序还可能乱。
    topk_pos = masked_pos.topk(k=self.chunk_len, dim=-1).values      # [B, K] 可能乱序

    # 再 sort 一次，保证按时间升序——这样第 i 列对应的就是动作的第 i 步。
    selected_pos = topk_pos.sort(dim=-1).values                      # [B, K] 升序

    # ─── Step 5：用 gather 把对应位置的 hidden 向量挑出来 ─────────
    # gather 沿 dim=1 取，要求 index 与 src 维度数一致：
    #   src   形状 [B, L, H]
    #   index 形状 [B, K, H]（把每个位置 id 在 H 维上 broadcast 复制）
    # 结果形状 [B, K, H]：第 b 个样本、第 k 个动作步、对应的 H 维特征向量。
    expanded_index = selected_pos.unsqueeze(-1).expand(-1, -1, H)
    action_queries = last_hidden.gather(dim=1, index=expanded_index)
    return action_queries

class MLPResNetBlock(nn.Module):
    """
    一个标准的"Pre-LayerNorm 残差块"——和 GPT、ViT 里的 FFN 子层是同款配方。
    数学：out = x + Linear(ReLU(LayerNorm(x))) ↑↑↑ 残差让深层网络好训练
    """
    def __init__(self, dim):
        super().__init__()
        # nn.Sequential 里写的顺序就是 forward 的顺序
        self.ffn = nn.Sequential(
            nn.LayerNorm(dim),    # 先归一化（pre-norm 风格，比 post-norm 更稳）
            nn.Linear(dim, dim),  # 一层全连接，维度不变
            nn.ReLU(),            # 非线性激活
        )

    def forward(self, x):
        # 残差连接：把输入直接加到 ffn 输出上。
        # 即便 ffn 全是 0，整个 block 也等价于恒等映射，不会拖累网络。
        return x + self.ffn(x)


class MLPResNet(nn.Module):
    """
    把若干 MLPResNetBlock 串起来，前后各加一段"投影 + 归一化"。
        input_dim → hidden_dim → ... → hidden_dim → output_dim
    OFT 这里用：input=2048/2560(VLM hidden), hidden=2*input, output=7(action_dim).
    """
    def __init__(self, num_blocks, input_dim, hidden_dim, output_dim):
        super().__init__()
        # 入口归一化 + 升维到 hidden（让中间块在更宽的空间里"思考"）
        self.layer_norm1 = nn.LayerNorm(input_dim)
        self.fc1   = nn.Linear(input_dim, hidden_dim)
        self.relu  = nn.ReLU()

        # ModuleList 里的子模块会被 PyTorch 自动注册成可训练参数（用普通 list 不会！）
        self.mlp_resnet_blocks = nn.ModuleList(
            [MLPResNetBlock(dim=hidden_dim) for _ in range(num_blocks)]
        )

        # 出口归一化 + 投影到动作维度（如 7：xyz + rpy + gripper）
        self.layer_norm2 = nn.LayerNorm(hidden_dim)
        self.fc2   = nn.Linear(hidden_dim, output_dim)

    def forward(self, x):
        # x: (N, input_dim)，N 在 OFT 里 = B*K
        x = self.layer_norm1(x); x = self.fc1(x); x = self.relu(x)   # (N, hidden_dim)
        for block in self.mlp_resnet_blocks:
            x = block(x)                                              # 形状不变
        x = self.layer_norm2(x); x = self.fc2(x)                      # (N, output_dim)
        return x


class L1RegressionActionHead(nn.Module):
    """
    OFT 的 head 主体：把 K 条 query 向量回归成 K 步 action。
    设计选择：完全没有时序耦合——K 步动作每一步独立预测，
              依赖 VLM 的注意力把上下文已经聚合到每个 🔍 位置上。
    """
    def __init__(self, input_dim=2048, hidden_dim=4096,
                 action_dim=7, NUM_ACTIONS_CHUNK=8):
        super().__init__()
        self.action_dim = action_dim

def forward(self, examples, **kwargs):
    # 跟 OFT 一样的"按字段抽列"
    batch_images = [e["image"]  for e in examples]   # list[PIL]，长度 B
    instructions = [e["lang"]   for e in examples]   # list[str]，长度 B
    actions      = [e["action"] for e in examples]   # list[ndarray (T, D)]，长度 B

    # ─── Step 0：连续动作 → FAST 整数 token 序列 ───────────────────
    # encoder_action2fastoken 内部三步：
    #   ① np.stack 把 list 变 (B, T, D) 整块矩阵
    #   ② DCT 沿 T 轴变换成稀疏频域系数（光滑动作 → 大部分系数接近 0）
    #   ③ 量化 + BPE，把系数序列编成"变长"的整数 id 列表
    # 返回形状为 List[List[int]]：第 i 条样本的 token 个数可能不同！
    batch_fast_tokens = self.action_model.encoder_action2fastoken(actions)

    # ─── Step 1：整数 id → "<robot_action_{id}>" 字符串 ───────────
    # FAST 的 id 范围 0~2047；我们用字符串模板把它们包成"特殊 token 文本"。
    # 之所以走字符串而不是直接拼 id：tokenizer 已经把这些字符串注册成
    # special tokens，pipeline 还能保留普通文本流的 build/log 逻辑。
    vlm_action_tokens = [
        self.map_fast_token_to_vlm_action(fast_tokens)
        for fast_tokens in batch_fast_tokens
    ]

    # ─── Step 2：把动作 token 通过 solutions= 拼到对话末尾 ─────────
    # build_qwenvl_inputs 看到 solutions= 时会做两件事：
    #   ① 把 instruction + answer 拼成完整对话
    #   ② 给 input_ids 同步生成 labels：prompt 部分置 IGNORE_INDEX(-100)，
    #      只对 answer（即 action token）那段算 CE。
    # 这样 loss 就只惩罚"模型预测动作 token"的错误，文本部分不参与 loss。
    qwen_inputs = self.qwen_vl_interface.build_qwenvl_inputs(
        images=batch_images,
        instructions=instructions,
        solutions=vlm_action_tokens,
    )

    # ─── Step 3：标准 LM 前向，loss 由 HF 内部计算 ─────────────────
    # FAST 完全复用 LM head：模型自动按 labels 算 next-token CE。
    # 我们不需要 hidden_states（不像 OFT 要拎 query 出来），关掉省显存。
    with torch.autocast("cuda", dtype=torch.bfloat16):
        qwenvl_outputs = self.qwen_vl_interface(
            **qwen_inputs,
            output_attentions=False,
            output_hidden_states=False,
            return_dict=True,
        )

    vlm_action_loss = qwenvl_outputs.loss

    # ─── 兜底：防 NaN 反传 ────────────────────────────────────────
    # 极端情况下，labels 整段都是 IGNORE_INDEX（例如 batch 里全是空动作），
    # HF 会返回 loss=None 或 NaN。这里替换成 0 张量，让 backward 安全。
    if vlm_action_loss is None or torch.isnan(vlm_action_loss):
        vlm_action_loss = torch.tensor(0.0, device=self.qwen_vl_interface.model.device)

    return {"action_loss": vlm_action_loss}

def _extract_action_token_ids(self, generated_ids):
    """
    从 generate() 的整段输出里，把"动作 token"挑出来。

    generated_ids: torch.LongTensor [B, L]
        每个位置一个 VLM 词表 id；包括对话模板、EOS、用户输入回显、模型自回归生成的全部内容。
    return: List[List[int]]，长度 B；每条是该样本里出现过的动作 id（保持原顺序）。
    """
    # 词表里"动作 token"的 id 区间，例如 [151000, 153047]
    act_min = self.qwen_vl_interface._ACTION_TOKEN_MIN
    act_max = self.qwen_vl_interface._ACTION_TOKEN_MAX

    # & 是按位与，配合 ≥/≤ 两端做"区间内"判断。结果是 bool [B, L]。
    mask = (generated_ids >= act_min) & (generated_ids <= act_max)

    results = []
    for b in range(generated_ids.size(0)):
        # nonzero 返回所有 True 的位置；as_tuple=False → 返回 (n, 1) 张量，再 flatten 成 (n,)
        idx = mask[b].nonzero(as_tuple=False).flatten()
        if idx.numel() == 0:
            # 模型有时会"复读 prompt"或直接 EOS，导致没有动作 token。返回空列表。
            results.append([]); continue
        # 按出现顺序取出来，再转成 Python list[int]，方便后续做整数减法
        results.append(generated_ids[b, idx].tolist())
    return results


def _decode_action_tokens(self, batch_vlm_tokens):
    """
    扣掉 offset：FAST 自身的词表是 0~2047，但被映射到 VLM 词表的高位区间。
    例如 VLM 词表里 151000=<robot_action_0>、151001=<robot_action_1> ...
    所以要取回 FAST id，只需 token - act_min。
    """
    act_min = self.qwen_vl_interface._ACTION_TOKEN_MIN
    return [
        [t - act_min for t in seq] if seq else None    # 空序列保留为 None，让下游 decode 知道"无动作"
        for seq in batch_vlm_tokens
    ]


def map_fast_token_to_vlm_action(self, tokens):
    """
    训练阶段用的反向映射：FAST id → 字符串。
    例如 [3, 12, 87] → "<robot_action_3><robot_action_12><robot_action_87>"。

    前提：VLM tokenizer 在 vocabulary 扩展时已经把这些字符串登记为 single special token，
          否则 BPE 会把 "<robot_action_3>" 切成多段普通字符。
    """
    return "".join([f"<robot_action_{token}>" for token in tokens])

class Fast_Action_Tokenizer(nn.Module):
    """
    一个"看起来是网络其实没参数"的 nn.Module 包装器。
    继承 nn.Module 只是为了能挂到 framework 里、被 .to(device) 等递归遍历，
    内部实际只是 HuggingFace AutoProcessor 的薄包装。
    """
    def __init__(self, fast_tokenizer_name="playground/Pretrained_models/fast"):
        super().__init__()

        # AutoProcessor.from_pretrained 加载的是 physical-intelligence/fast：
        #   它把 (T, D) 连续动作 → DCT 频域 → 量化 → BPE 编码 → 整数 id 序列；
        #   反之亦然。trust_remote_code=True 是因为该 processor 自带 Python 文件。
        self.fast_tokenizer = AutoProcessor.from_pretrained(
            fast_tokenizer_name, trust_remote_code=True
        )

    def encoder_action2fastoken(self, raw_actions):
        """连续动作 → 整数 id 序列。"""
        # raw_actions: List[ndarray (T, D)]，长度 B
        batch_actions = np.stack(raw_actions, axis=0)        # (B, T, D)
        # 直接调 processor.__call__：内部走 DCT + 量化 + BPE，输出 List[List[int]]
        batch_fast_tokens = self.fast_tokenizer(batch_actions)
        return batch_fast_tokens

    def decoder_action(self, generated_ids):
        """
        整数 id 序列 → 连续动作。
        注意：传进来的 generated_ids 应该是"VLM 词表中的 id"，
              这里再次减一遍 _ACTION_TOKEN_MIN 才能丢回 FAST tokenizer。
        """
        pred_actions = self.fast_tokenizer.decode(
            [generated_ids - self._ACTION_TOKEN_MIN]
        )
        return pred_actions

    def fit_tokenizer_on_datasets(self, action_dataset, datasets_path="..."):
        """
        可选步骤：在自家数据集上重新拟合 BPE 词表，提升压缩率。
        多数情况下用 physical-intelligence/fast 默认词表已经够好。
        """
        # 如果之前已经 fit 过并保存，直接 load 就行
        if os.path.exists(datasets_path):
            self.fast_tokenizer = AutoProcessor.from_pretrained(
                datasets_path, trust_remote_code=True
            ); return

        # 否则在新数据集上 fit BPE，然后存盘以备下次复用
        new_tokenizer = self.fast_tokenizer.tokenizer.fit(action_dataset)
        self.fast_tokenizer = new_tokenizer
        self.fast_tokenizer.save_pretrained(datasets_path)

def forward(self, examples, **kwargs):

        batch_images, instructions

    # 流匹配 loss 涉及 (1-t)*noise + t*action 的细微数值，bf16 会有抖动；
    # head 参数量小，升 fp32 代价可忽略。

        actions = torch.tensor(np.array(actions),
                               device=base_hidden.device, dtype=base_hidden.dtype)
        actions_target = actions[:, -self.action_horizon:, :]    # [B, 16, D]

        # ─── Step 3：repeated_diffusion_steps 配方 ──────────────
        # 思想：每个样本在流匹配里采的 t、noise 都是随机的，"看一眼这个样本"
        # 提供的信号有限。把同一份 vl_embs/action 复制 N 份，每份会在 head 里
        # 采不同的 t 和 noise → 等价于"VLM 跑 1 次、DiT 训练 N 次"，
        # 显存只多 N 倍 batch（DiT 比 VLM 小很多），却能极大丰富训练信号。
        repeated_diffusion_steps = (
            self.config.framework.action_model.get("repeated_diffusion_steps", 4)
            if self.config and hasattr(self.config, "framework") else 4
        )
        repeated_diffusion_steps = 2          # π0 的 DiT 已经很大，2 份够用；GR00T 用 8

        # repeat(N, 1, 1) 在 dim0 上重复 N 次，其它维度不变
        actions_target_repeated = actions_target.repeat(repeated_diffusion_steps, 1, 1)
        # 每层 vl_embs 都要同步重复，否则 cross-attn 维度对不上
        vl_embs_list_repeated   = [h.repeat(repeated_diffusion_steps, 1, 1)
                                   for h in vl_embs_list]
        if backbone_attention_mask is not None:
            # repeat(N,1) 对 [B,L] 在 dim0 上重复；DiT cross-attn 需要 bool 类型
            backbone_attention_mask = backbone_attention_mask.repeat(
                repeated_diffusion_steps, 1
            ).to(dtype=torch.bool)

        state_repeated = None
        if state is not None:
            state = torch.tensor(np.array(state),
                                 device=base_hidden.device, dtype=base_hidden.dtype)
            state_repeated = state.repeat(repeated_diffusion_steps, 1, 1)

        # ─── Step 4：调 head forward → 直接拿到 loss ────────────
        # head 内部会采 t、采 noise、做 (1-t)*noise + t*a → DiT → MSE。
        # 注意 head 的 forward 直接 return loss，不返回 pred_actions（节省一次 reshape）。
        action_loss = self.action_model(
            vl_embs_list_repeated,
            actions_target_repeated,
            state_repeated,
            encoder_attention_mask=backbone_attention_mask,
        )

⑥ Action Head：核心 forward — LayerwiseFM_ActionHeader.py:288

def forward(self, vl_embs_list, actions, state=None, encoder_attention_mask=None):
    """
    一次"采样 + DiT 前向 + 算 loss"的完整流程。

    vl_embs_list: List[Tensor]，长度 = DiT 层数 N，每张 (B, L, D_vlm)
    actions:      (B, action_horizon, D_action)
    state:        (B, 1, state_dim) or None
    encoder_attention_mask: (B, L) or None
    """
    device = actions.device
    B, L, D = vl_embs_list[0].shape

    # ─── ① 流匹配的随机采样 ─────────────────────────────────────
    # 思路：把"从噪声 ε 走到真 action a"看成一条直线
    #         x_t = (1-t) ε + t a，   t ∈ [0, 1]
    # 训练时随机选一个 t 和 ε，让模型学会预测速度 v = a - ε。
    noise = torch.randn(actions.shape, device=device, dtype=actions.dtype)   # ε
    t = self.sample_time(B, device=device, dtype=actions.dtype)              # (B,)
    t = t[:, None, None]                                                     # (B,1,1) 广播

    noisy_trajectory = (1 - t) * noise + t * actions     # x_t，shape (B,T,D)
    velocity         = actions - noise                   # v(x_t,t) = a − ε（解析目标）

    # ─── ② 时间离散化 + action 编码 ─────────────────────────────
    # DiT 的 timestep encoder 用整数 bucket 做 embedding lookup，
    # 所以这里把 t ∈ [0, noise_s] 映射到 [0, num_timestep_buckets-1]。
    t_discretized   = (t[:, 0, 0] * self.num_timestep_buckets).long()         # (B,)
    # action_encoder：对 (x_t, t) 一起编码，输出 (B, T, hidden)
    action_features = self.action_encoder(noisy_trajectory, t_discretized)

    # ─── ③ proprioceptive state（机械臂关节角等，可选）─────────
    state_features = self.state_encoder(state) if state is not None else None

    # ─── ④ 为 action 序列加可学习 PE，让 DiT 知道时间顺序 ────────
    if self.config.add_pos_embed:
        pos_ids = torch.arange(action_features.shape[1], dtype=torch.long, device=device)
        # nn.Embedding lookup → (T, hidden)，再 unsqueeze(0) 广播到 (1, T, hidden)
        action_features = action_features + self.position_embedding(pos_ids).unsqueeze(0)

    # ─── ⑤ 拼接成 DiT 的输入 sa_embs ────────────────────────────
    # 顺序：[state(可选) | future_tokens | action_features]
    # future_tokens 是 32 个可学习"规划占位"，给 DiT 提供"额外思考空间"。
    future_tokens = self.future_tokens.weight.unsqueeze(0).expand(B, -1, -1)   # (B, 32, w)
    sa_embs = (
        torch.cat((state_features, future_tokens, action_features), dim=1)
        if state_features is not None
        else torch.cat((future_tokens, action_features), dim=1)
    )

    # ─── ⑥ 逐层 cross-attention（π0 vs GR00T 的核心差异）────────
    # 把 t_discretized 编码成 AdaLN 用的 timestep embedding
    temb = self.model.timestep_encoder(t_discretized)

    # 关键循环：DiT 第 i 层 ←→ VLM 第 i 层 hidden state 做 cross-attention。
    # 这样动作策略可以"逐层吸收"VLM 的不同抽象级别（早期视觉特征、中段语法、末层语义）。
    model_output = sa_embs
    for layer_idx, layer in enumerate(self.model.transformer_blocks):
        model_output = layer(
            hidden_states=model_output,                       # 自身（query）
            encoder_hidden_states=vl_embs_list[layer_idx],    # 来自 VLM 第 i 层（key/value）
            encoder_attention_mask=encoder_attention_mask,
            temb=temb,
        )

    # ─── ⑦ 解码 → 流匹配 MSE ────────────────────────────────────
    # MLP(input_embedding_dim → action_dim)
    pred = self.action_decoder(model_output)
    # 取"动作段"——前缀的 state/future_tokens 不参与 loss
    pred_actions = pred[:, -actions.shape[1]:]
    # 流匹配 loss = ||v_pred − v_target||²
    loss = ((pred_actions - velocity) ** 2).mean()
    return loss

@torch.no_grad()
def predict_action(self, vl_embs_list, state=None, encoder_attention_mask=None):
    """
    推理时的 N 步 Euler 积分。
    思想：训练学到的速度场 v_θ(x, t) 把"噪声"沿 t 方向推到"真 action"，
    所以推理只需要从纯噪声起步，按 dt 步长积分若干次就够。
    """
    B = vl_embs_list[0].shape[0]
    device = vl_embs_list[0].device

    # ─── Step 1：初始化为纯噪声 x_0 ~ N(0, I) ───────────────────
    # 注意：这里随机初值会导致每次推理结果略有不同（"采样多样性"）。
    # 想要复现可调用 torch.manual_seed()。
    actions = torch.randn(
        size=(B, self.action_horizon, self.action_dim),
        dtype=vl_embs_list[0].dtype, device=device,
    )

    num_steps = self.num_inference_timesteps    # 默认 4
    dt = 1.0 / num_steps                        # 每步前进 0.25
    # state 在循环外只编码一次——它在 N 步里都不变
    state_features = self.state_encoder(state) if state is not None else None

    # ─── Step 2：N 步循环，每步做一次"DiT forward + 欧拉前进" ──
    for t in range(num_steps):
        # 当前位置 t_cont ∈ {0, 0.25, 0.5, 0.75}
        t_cont = t / float(num_steps)
        t_disc = int(t_cont * self.num_timestep_buckets)
        # 整 batch 共享同一个 t（不像训练每条样本独立采）
        timesteps_tensor = torch.full((B,), t_disc, device=device, dtype=torch.long)

        # ─── Step 3：组装 sa_embs，与 forward 完全一致 ────────
        action_features = self.action_encoder(actions, timesteps_tensor)
        if self.config.add_pos_embed:
            pos_ids = torch.arange(action_features.shape[1], device=device, dtype=torch.long)
            action_features = action_features + self.position_embedding(pos_ids).unsqueeze(0)
        future_tokens = self.future_tokens.weight.unsqueeze(0).expand(B, -1, -1)
        sa_embs = (
            torch.cat((state_features, future_tokens, action_features), dim=1)
            if state_features is not None
            else torch.cat((future_tokens, action_features), dim=1)
        )

        # ─── Step 4：逐层 cross-attn → 拿速度场预测 ────────────
        temb = self.model.timestep_encoder(timesteps_tensor)
        model_output = sa_embs
        for layer_idx, layer in enumerate(self.model.transformer_blocks):
            model_output = layer(
                hidden_states=model_output,
                encoder_hidden_states=vl_embs_list[layer_idx],
                encoder_attention_mask=encoder_attention_mask,
                temb=temb,
            )
        pred = self.action_decoder(model_output)
        pred_velocity = pred[:, -self.action_horizon:]    # (B, T, D_action)

        # ─── Step 5：欧拉法前进一步 ────────────────────────────
        # 数学：x_{t+dt} = x_t + dt · v(x_t, t)
        # 经过 num_steps 步后，x ≈ 真 action。
        actions = actions + dt * pred_velocity

    return actions

def sample_time(self, batch_size, device, dtype):

    流匹配的关键超参——决定训练时模型"经常看到 t 的哪个区域"。
    """
    # 1) 从 Beta(1.5, 1.0) 采 batch_size 个 ∈ (0, 1)；多数靠近 1.0。

def forward(self, vl_embs, actions, state=None, encoder_attention_mask=None):
    """
    vl_embs: (B, L, D_vlm)              ← ★ 单个 tensor（注意：π0 是 list）
    actions: (B, action_horizon, D)
    """
    # ─── ① 流匹配采样（与 π0 一字不差） ────────────────────────
    # 训练目标：让模型学会"在条件 vl_embs 下，从噪声推回真 action"的速度场。
    noise = torch.randn(actions.shape, device=actions.device, dtype=actions.dtype)
    t = self.sample_time(actions.shape[0], device=actions.device, dtype=actions.dtype)
    t = t[:, None, None]                                  # (B,1,1) 广播

    # 直线插值轨迹：噪声起点 ε，终点 a，t∈[0, noise_s]
    noisy_trajectory = (1 - t) * noise + t * actions      # x_t
    velocity         = actions - noise                    # v_target = a - ε

    # ─── ② 离散化 t + action / state 编码 ───────────────────────
    # ActionEncoder 输出 (B, T, w)；state 通过 MLP → (B, 1, w)
    t_discretized   = (t[:, 0, 0] * self.num_timestep_buckets).long()
    action_features = self.action_encoder(noisy_trajectory, t_discretized)
    state_features  = self.state_encoder(state) if state is not None else None

    # ─── ③ 给 action 序列加 PE ─────────────────────────────────
    # 让 DiT 知道"第 0 步 / 第 1 步 / ..."的顺序信息。
    if self.config.add_pos_embed:
        pos_ids = torch.arange(action_features.shape[1], device=actions.device, dtype=torch.long)
        action_features = action_features + self.position_embedding(pos_ids).unsqueeze(0)

    # ─── ④ 拼接 sa_embs ────────────────────────────────────────
    # 顺序：[state(可选) | future_tokens | action_features]
    # future_tokens：(1, 32, w) → expand 到 (B, 32, w) 不实际复制内存
    future_tokens = self.future_tokens.weight.unsqueeze(0).expand(vl_embs.shape[0], -1, -1)
    sa_embs = (
        torch.cat((state_features, future_tokens, action_features), dim=1)
        if state_features is not None
        else torch.cat((future_tokens, action_features), dim=1)
    )

    # ─── ⑤ DiT 一次调用 ─────────────────────────────────────────
    # 关键：encoder_hidden_states=vl_embs（单 tensor）。
    # DiT 内部循环 self-attn / cross-attn / FFN，每一层都用"同一个 vl_embs"做 cross-attn。
    # return_all_hidden_states=False：不需要中间层输出（FLARE 才用）。
    model_output = self.model(
        hidden_states=sa_embs,
        encoder_hidden_states=vl_embs,                # ★ 单一来源（vs π0 的 list）
        encoder_attention_mask=encoder_attention_mask,
        timestep=t_discretized,
        return_all_hidden_states=False,
    )

    # ─── ⑥ 解码 → 取 action 段 ─────────────────────────────────
    # action_decoder：MLP 把 DiT hidden 投回 action_dim
    pred = self.action_decoder(model_output)
    # 序列里前面是 state/future_tokens，只取末尾 action 段才是真正的速度场预测
    pred_actions = pred[:, -actions.shape[1]:]

    # ─── ⑦ MSE 流匹配 loss（与 π0 完全相同公式） ──────────────
    loss = ((pred_actions - velocity) ** 2).mean()
    return loss

@torch.no_grad()
def predict_action(self, vl_embs, state=None, encoder_attention_mask=None):
    """
    GR00T 推理 = N 步 Euler 积分（默认 N=4）。
    与 π0 predict_action 唯一差别：传给 DiT 的 encoder_hidden_states 是单 tensor。
    """

    # ─── Step 1：从纯噪声起步 ────────────────────────────────────
    actions = torch.randn(
        size=(B, self.action_horizon, self.action_dim),
        dtype=vl_embs.dtype, device=device,
    )
    num_steps = self.num_inference_timesteps     # 默认 4
    dt = 1.0 / num_steps                         # 每步前进 0.25
    state_features = self.state_encoder(state) if state is not None else None

    # ─── Step 2：循环 N 步 ───────────────────────────────────────
    for t in range(num_steps):
        # 当前 t_cont ∈ {0, 0.25, 0.5, 0.75}，离散化成 bucket 给 DiT 的 timestep_encoder
        t_cont = t / float(num_steps)
        t_disc = int(t_cont * self.num_timestep_buckets)
        timesteps_tensor = torch.full((B,), t_disc, device=device)

        # ─── 组装 sa_embs（与训练 forward 一致） ──────────────
        action_features = self.action_encoder(actions, timesteps_tensor)
        if self.config.add_pos_embed:
            pos_ids = torch.arange(action_features.shape[1], device=device, dtype=torch.long)
            action_features = action_features + self.position_embedding(pos_ids).unsqueeze(0)
        future_tokens = self.future_tokens.weight.unsqueeze(0).expand(B, -1, -1)
        sa_embs = (
            torch.cat((state_features, future_tokens, action_features), dim=1)
            if state_features is not None
            else torch.cat((future_tokens, action_features), dim=1)
        )

        # ─── DiT forward 拿速度场 ───────────────────────────────
        model_output = self.model(
            hidden_states=sa_embs,
            encoder_hidden_states=vl_embs,            # 整 N 步循环都用同一份 vl_embs
            encoder_attention_mask=encoder_attention_mask,
            timestep=timesteps_tensor,
        )
        pred = self.action_decoder(model_output)
        pred_velocity = pred[:, -self.action_horizon:]   # 只要 action 段（去掉 state/future_tokens）

        # ─── 欧拉积分一步：x ← x + dt · v ─────────────────────
        actions = actions + dt * pred_velocity

    return actions

class ActionEncoder(nn.Module):
    """
    把"带噪动作 + 当前时间 t"编码成一串 token，送给 DiT 当 query。
    直觉：DiT 要预测速度场 v(x_t, t)，所以输入必须同时包含 x_t 和 t 两件事。
    这里采用"分别投影 + 拼接"的写法——比直接把 t append 在 action 维度更稳。
    """
    def __init__(self, action_dim, hidden_size=1024):
        # ─── Step 0：父类必须先 super().__init__() ─────────────────────
        # 不写这一句，self.layer1 = nn.Linear(...) 不会被注册成可训练参数。
        super().__init__()
        self.hidden_size = hidden_size      # w，DiT 的 token 维度（默认 1024）
        self.action_dim  = action_dim       # 7 = 6 DoF + 1 gripper（典型值）

        # ─── Step 1：三层投影 ─────────────────────────────────────────
        # layer1：把动作维 d 投到 token 维 w（升维）
        # layer2：把 [a‖τ] 这个 2w 维向量再压回 w 维（融合）
        # layer3：再过一层非线性的"打磨"，输出 w 维 token
        self.layer1 = nn.Linear(action_dim,      hidden_size)        # a:    d → w
        self.layer2 = nn.Linear(2 * hidden_size, hidden_size)        # [a‖τ]: 2w → w
        self.layer3 = nn.Linear(hidden_size,     hidden_size)        # 后处理: w → w

        # ─── Step 2：时间 t 用经典 sin/cos PE ─────────────────────────
        # 不用 nn.Embedding 是因为 t 是连续值（0~num_timestep_buckets），
        # sin/cos 能自然外推、平滑表示，而 Embedding 表只能查整数索引。
        self.pos_encoding = SinusoidalPositionalEncoding(hidden_size)

    def forward(self, actions, timesteps):
        """
        actions:   (B, T, action_dim) —— 一段动作序列（带噪 x_t 或推理时的 actions）
        timesteps: (B,)                —— 每个样本一个标量 τ，整段动作共享
        returns:   (B, T, hidden_size) —— 给 DiT 当 query 的 token 序列
        """
        B, T, _ = actions.shape

        # ─── Step 1：把 (B,) 的 t 沿时间轴广播成 (B, T) ──────────────
        # 同一段动作里的所有时间步共享同一个 τ（流匹配里 t 是 trajectory-level 的）
        # .expand(-1, T) 是 zero-copy 广播，不会真的复制内存
        if timesteps.dim() == 1 and timesteps.shape[0] == B:
            timesteps = timesteps.unsqueeze(1).expand(-1, T)        # (B,) → (B,1) → (B,T)
        else:
            raise ValueError("timesteps must be (B,)")

        # ─── Step 2：动作分支 —— 升维 ──────────────────────────────
        a_emb = self.layer1(actions)                                # (B, T, w)

        # ─── Step 3：时间分支 —— 编码后转成与 a_emb 同 dtype ────────
        # .to(dtype=...) 防止 bf16 训练时 PE 默认 fp32 导致 cat 报错
        tau_emb = self.pos_encoding(timesteps).to(dtype=a_emb.dtype) # (B, T, w)

        # ─── Step 4：拼接 → 投影 → swish 激活 ─────────────────────
        # 这里用 swish (x·sigmoid(x)) 而非 ReLU，参考 PaLM/GLU 系列经验：
        # 流匹配里 swish 比 ReLU 更平滑，对连续目标拟合更稳。
        x = torch.cat([a_emb, tau_emb], dim=-1)                     # (B, T, 2w)
        x = swish(self.layer2(x))                                   # (B, T, w)

        # ─── Step 5：再过一层 Linear，输出最终 token ──────────────
        x = self.layer3(x)                                          # (B, T, w)
        return x

    背景：多本体训练时（人形 / 双臂 / 单臂...）每个机器人 action_dim 不同、
    动作分布也大相径庭，用同一份 nn.Linear 会被强行拉平。
    解决方案：把权重多复制一份维度 C（机型数），forward 时按 cat_id 索引。
    """
    def __init__(self, num_categories, input_dim, hidden_dim):
        super().__init__()
        self.num_categories = num_categories

        # ─── Step 1：注册成 nn.Parameter，自动加入 model.parameters() ──
        # shape=(C, in, hidden)：第 0 维 C 是"机型轴"，按 cat_id 选一片。
        # 0.02 标准差是 GPT-2/BERT 系列经验值，太大会发散，太小会饱和。
        self.W = nn.Parameter(0.02 * torch.randn(num_categories, input_dim, hidden_dim))
        # 偏置初始化为 0：常见做法，避免训练初期产生人为的输出偏移。
        self.b = nn.Parameter(torch.zeros(num_categories, hidden_dim))

    def forward(self, x, cat_ids):
        """
        x:       (B, T, in)   —— 这一 batch 的输入
        cat_ids: (B,)         —— 每个样本属于哪个机型
        return:  (B, T, hidden)
        """
        # ─── Step 1：按 cat_ids 把 W 第 0 维"花式索引"出来 ────────
        # PyTorch 张量的 high-dim indexing：W[cat_ids] 等价于 W.index_select(0, cat_ids)
        selected_W = self.W[cat_ids]                 # (C,in,h) → (B,in,h)
        selected_b = self.b[cat_ids]                 # (C,h)    → (B,h)

        # ─── Step 2：batch matmul：每个样本走自己的权重 ───────────
        # bmm 输入要求 (B, n, m) × (B, m, p) → (B, n, p)，正好对应这里
        # selected_b.unsqueeze(1)：(B,h) → (B,1,h)，沿 T 轴广播加上去
        return torch.bmm(x, selected_W) + selected_b.unsqueeze(1)


class MultiEmbodimentActionEncoder(nn.Module):
    """
    多机型版 ActionEncoder：把 W1/W2/W3 都替换成 CategorySpecificLinear。
    forward 多接一个 cat_ids 参数，让 batch 里不同机型走各自权重。
    用途：GR00T N1.5 或任何"一份模型同时训多种机器人"的场景。
    """
    def __init__(self, action_dim, hidden_size=1024, num_embodiments=8):
        super().__init__()
        # 三层都是 CategorySpecificLinear；总参数量 ≈ 普通版 × num_embodiments
        self.W1 = CategorySpecificLinear(num_embodiments, action_dim,    hidden_size)  # d → w
        self.W2 = CategorySpecificLinear(num_embodiments, 2*hidden_size, hidden_size)  # 2w → w
        self.W3 = CategorySpecificLinear(num_embodiments, hidden_size,   hidden_size)  # w → w

        # PE 是确定性函数，不需要 per-embodiment 权重，所有机型共享
        self.pos_encoding = SinusoidalPositionalEncoding(hidden_size)

    def forward(self, actions, timesteps, cat_ids):
        """
        actions:   (B, T, action_dim)
        timesteps: (B,)
        cat_ids:   (B,)
        return:    (B, T, hidden_size)
        """
        B, T, _ = actions.shape

        # 跟普通 ActionEncoder 一样：把 (B,) 的 t 广播成 (B, T)
        timesteps = timesteps.unsqueeze(1).expand(-1, T)

        # 关键差异：W1/W2/W3 调用都多传一个 cat_ids，让权重按机型选
        a_emb   = self.W1(actions, cat_ids)                          # (B, T, w)
        tau_emb = self.pos_encoding(timesteps).to(dtype=a_emb.dtype) # (B, T, w)
        x = torch.cat([a_emb, tau_emb], dim=-1)                      # (B, T, 2w)
        x = swish(self.W2(x, cat_ids))                               # (B, T, w)
        x = self.W3(x, cat_ids)                                      # (B, T, w)
        return x

class MLP(nn.Module):
    """
    教科书级两层 MLP：input → hidden → output。
    在 head 里出现 N 次（state_encoder、action_decoder、project_layers...），
    所以单独抽出来做一个最简实现。
    GR00T 版必须传 hidden_dim；π0 版默认 hidden_dim=1024（见前面文件 LayerwiseFM_ActionHeader.py:51）。
    """
    def __init__(self, input_dim, hidden_dim, output_dim):
        super().__init__()
        # ─── Step 1：第一层 Linear —— 升维（或调维） ────────────
        # nn.Linear 内部会自己初始化 weight（Kaiming 默认）和 bias=0
        self.layer1 = nn.Linear(input_dim,  hidden_dim)

        # ─── Step 2：第二层 Linear —— 投到目标维度 ──────────────
        self.layer2 = nn.Linear(hidden_dim, output_dim)

    def forward(self, x):
        # ReLU 是最快、最稳的非线性；放在两层之间产生非线性变换。
        # 写成单行只是为了简洁：layer2(relu(layer1(x))) ≡ layer2(F.relu(layer1(x)))
        return self.layer2(F.relu(self.layer1(x)))

7.4 future_tokens — 可学习"规划"占位

给 DiT 一组与具体动作无关的 query token，attention 时它们去 cross-attend 视觉特征，相当于"想一想再写动作"。

# 在 head __init__ 里：
# ─── Step 1：声明 32 个可学习的 query token ─────────────────────
# 把 nn.Embedding 当成"一张可训练查找表"：32 行，每行 w 维。
# 它本质就是 nn.Parameter(torch.empty(32, w))，只是 nn.Embedding 帮你做了
# 索引语法 (table[i]) 和 .weight 访问的封装。
self.future_tokens = nn.Embedding(
    config.num_target_vision_tokens,    # 默认 32：DiT 多 32 个"思考槽"
    self.input_embedding_dim,           # = w，DiT 的 token 维度
)
# ─── Step 2：用 N(0, 0.02²) 初始化（GPT-2 同款）──────────────
# 默认 Embedding 初始化是 N(0, 1)，对 Transformer 来说太大；改成 0.02 更稳。
nn.init.normal_(self.future_tokens.weight, mean=0.0, std=0.02)


# 在 forward 里：
# ─── Step 1：把同一份 future_tokens 复制到整个 batch ────────────
# .weight 形状 (32, w)；先 unsqueeze(0) → (1, 32, w)，再 expand → (B, 32, w)
# 注意：用 expand 而不是 repeat，前者是 zero-copy 视图，后者会真复制内存。
# 全 batch 共享同一份参数 → 32 个 token 是"全局可学常量"，不依赖具体样本。
future_tokens = self.future_tokens.weight.unsqueeze(0).expand(B, -1, -1)

# 之后在 head forward 里会被拼到 sa_embs 中段：
#   sa_embs = cat([state_features, future_tokens, action_features], dim=1)
# DiT cross-attn 时这 32 个 token 也能 attend 到 vl_embs，
# 相当于给模型"在写动作前先想 32 步"的额外计算预算。

7.5 SinusoidalPositionalEncoding — Transformer 标准 PE

头部公用的 timestep 编码（不是 nn.Embedding 而是固定 sin/cos）。swish 是 x · sigmoid(x)。两者都从 flow_matching_head/action_encoder.py 导入。

# ─── 从 flow_matching_head 模块导入两个共享小工具 ─────────────

from starVLA.model.modules.action_model.flow_matching_head.action_encoder import (
    # SinusoidalPositionalEncoding —— Vaswani et al. 2017 的经典 sin/cos PE
    #   - 给 timestep（0~num_timestep_buckets）一个连续、可外推的向量表示
    #   - 不用 nn.Embedding：避免训练表 + 支持训练时未见过的 t 平滑插值

7.7 share_tools.add_discretized_state_to_instruction — π0.5 风格 state 注入

OFT / π0_v3 都会在指令文本前先拼一段离散化 state（伪 prompt）。

# 传统流匹配 head 单独喂 state（关节角/末端位姿）给 DiT 的 state_encoder，
# 多了一条数据通路、对齐起来麻烦，而且 VLM 也"看不见"机器人当前姿态。

#   - VLM 走 tokenizer + embed 时把这些 <bxx> 当成普通词汇
#   - 视觉、语言、本体感知三条信息共享同一个文本流 → 更"端到端"
#   - 代价：text 长度变长，attention 算力 ↑

设计轴的代码体现

1
动作表示是一条 if-else：动作要么是连续 (actions: float Tensor)，要么是离散 (action_token_ids: long Tensor)。前者三种实现，后者一种 (FAST)。
2
耦合方式 = forward 签名：
- OFT 不需要单独 head 的 vl_embs，靠 action_token 占位
- FAST 同理，靠词表 ID
- π0 head 接 vl_embs_list: List[Tensor]
- GR00T head 接 vl_embs: Tensor
3
Loss 选择 = 一行：L1Loss、CE、MSE(pred − velocity)，三选一。
4
chunk vs token-stream：连续动作天然是定长 chunk，token 动作是变长流（FAST 唯一）。

§9容易踩的点

  1. OFT 的"action token"不是真生成：它只是占位，借助 attention 把 VLM 上下文聚到这些位置；最后用 hidden state 走 MLP，不经过 LM head，不算自回归。
  2. FAST 的 token 长度不固定：因为 DCT 后用 BPE，所以 chunk 越简单 token 越少；训练/推理都要做 ID 区间过滤再 decode。
  3. π0 的"逐层"必须 framework 配合：QwenPI.py 里要求 output_hidden_states=True，并把 hidden_states 列表喂给 head；DiT 层数 = 提取的 VLM 层数。
  4. π0 vs GR00T 的 repeated_diffusion_steps：同一份 vl_embs 配多份噪声训练，对深 DiT 收敛尤为关键 —— 这也是为什么 π0 用 2、GR00T 用 8。
  5. Loss 的 t 调度：Beta(1.5, 1.0) 后取 0.999·(1−x) → t 偏向 0.999 附近，意味着模型更经常看到"接近真实 action"的 noisy 输入，对在线推理 4 步 Euler 友好。
  6. 预测速度场而非噪声：velocity = actions − noise，所以 Euler 步是 x ← x + dt · v_pred，对应 rectified flow 的直线插值，不是 DDPM 的反向去噪。DiTActionHeader.py 才是经典 Gaussian diffusion（预测 noise + MSE），目前不是四个 framework 的默认。
  7. Qwen3-VL 的隐藏层数：在 π0 配置里 DiTConfig.num_layers=36 是 qwen2.5-vl 的默认；如果换成 qwen3-vl-4b（28 层）或 qwen3-vl-8b（36 层），需要同步改 diffusion_model_cfg.num_layers，否则 vl_embs_list[layer_idx] 会 IndexError。
最后一句 四种 policy 的差异本质上是 "动作的语义被多大程度卷进 VLM 的注意力图"。OFT 只让 VLM 给出特征，FAST 让 VLM 直接说出动作 token，π0 让 DiT 逐层吸收 VLM 的中间状态，GR00T 把 DiT 解耦成独立小模型。这个谱系也解释了 π 系往 π0.5 的演化方向 —— 把 state 推回 prompt，把更多结构信息收回到语言侧。
