通用Agent一旦进入具体任务，动作、反馈和成功标准就必须落地。软件修复需要可执行补丁，GUI任务需要正确终态，数据分析需要可复算结果，开放探索需要可复用技能。

Agentless、OSWorld、DS-Agent与Voyager给出经典结构；较新的SWE-Fixer、SWE-Exp、UI-Voyager、OSWorld2.0和SWE-Effi继续追问训练、经验复用、长程纠错及预算内完成质量。

01

问题 01

如何定位与修复？

从文件召回到补丁验收，经验与训练改变不同步骤。

仓库级任务先要找到相关文件和依赖，再修改正确行为。定位率、程序可运行和真实修复率是不同指标；先建立最小复现，才能辨认改动是否切中问题。

同一导出需求可由固定流水线、训练检索编辑模型或带历史经验的搜索解决。比较时固定仓库commit、issue和测试，防止环境漂移与答案泄漏。

贯穿任务：为一份数据生成可复算报告。仓库导出脚本把日期当字符串排序，需要查代码、修复、回归，再把新报告交付。

Agentless: Demystifying LLM-based Software Engineering Agents

2024-07-01

先分层定位，再生成、过滤并排序补丁。

  1. Agentless把修复问题拆成分层定位与候选补丁选择。先由目录结构找文件，再用类和函数骨架缩小范围，最后阅读局部代码定位编辑位置；生成多个补丁后过滤语法错误和回归失败，再按多数投票排序。
  2. 原始v1的SWE-bench Lite 300题、GPT-4o设置下，完整系统修复82题（27.33%），平均每题成本0.34美元。单样本为70题，多样本加投票为78题，再加入测试过滤为82题（Table1/3）。

定位正确不保证补丁正确，候选中存在正确补丁也不代表排序器能选中它。v1的Lite结果不能与后来Verified版本或其他模型的结果直接拼榜。

SWE-Fixer: Training Open-Source LLMs for Effective and Efficient GitHub Issue Resolution

2025-01-09

BM25与训练的检索器定位，再由编辑模型生成补丁。

  1. SWE-Fixer将文件检索和代码编辑分别训练。BM25先取30个相关文件，再由较小检索模型读骨架筛选；编辑模型读取所选文件并输出文件路径、原始代码块与替换代码块，随后转换为补丁。
  2. SWE-Fixer-72B在SWE-bench Verified上为30.2%，加入P2P回归测试过滤后为32.8%（Table1）。Qwen2.5-7B检索消融中，10k训练数据和64k上下文的骨架输入Recall为67.3%，加入文件全文后为60.3%（Table3）。

检索需要的信息粒度与编辑不同：更多原始代码可能干扰文件筛选。训练数据、模型规模和测试选择共同影响成绩，不能把结果只归因于流程简化。

SWE-Exp: Experience-Driven Software Issue Resolution

2025-07-31

从成功与失败轨迹提炼经验，指导后续定位和编辑。

  1. SWE-Exp先收集修复轨迹，再提炼问题理解经验和代码修改经验，组成跨任务经验库。新问题经检索与LLM重排取得经验，由Instructor指导理解和策略，由Assistant执行修改。
  2. SWE-bench Verified、DeepSeek-V3-0324下，Pass@1为42.0%，同表SWE-Agent为38.8%、SWE-Search为35.4%。去掉经验抽取后为36.0%，去掉双Agent后为39.8%（Table1–2）。

“不抽取经验”变体用原始问题和gold patch作示例，并非完全没有示例信息。经验表示、检索和协作都在起作用，不能把42%只解释为多Agent收益。

02

问题 02

怎样定位与纠错？

截图、控件树、动作表示与失败轨迹训练。

GUI屏幕只是状态的部分投影；同一位置点击可能因窗口、焦点或弹框变化产生不同效果。操作后必须获取新观察，不能把一串预测动作当作执行完成。

可访问性树提供控件和坐标，截图保留视觉布局；移动与桌面动作空间不同。完整任务评测比单步点击命中更贴近交付。

读图前的算例 · 教学示意

用表格软件检查报告并另存为CSV：观察对话框、选择编码、验证文件路径。失败轨迹若误选选项，可在相同界面分叉处学习纠正。

OSWorld: Benchmarking Multimodal Agents for Open-Ended Tasks in Real Computer Environments

2024-04-11

用真实应用初始状态与执行检查衡量完整任务。

  1. OSWorld把电脑任务做成可重置的虚拟机环境：配置初始文件与应用状态，Agent接收截图或可访问性树，执行动作后由脚本读取最终工件并评分。评测对象是任务完成，而非鼠标动作是否像人。
  2. 原始369任务、最多15步的Table5中，GPT-4V截图输入成功率5.26%，截图加可访问性树为12.17%，人工为72.36%。实验用温度1.0、top-p0.9并保留近期3组观察和动作。

观察接口会改变可获得的信息，比较模型时必须说明截图、可访问性树或标记界面。15步原始设置不能与后来数百步协议直接比较。

UI-Voyager: A Self-Evolving GUI Agent Learning via Failed Experience

2026-03-25

筛成功轨迹后，定位成功与失败的分叉做自蒸馏。

  1. UI-Voyager先做多轮拒绝微调：每个任务采样多条轨迹，以规则验证器保留成功样本。随后进行GRSD，在成功与失败轨迹间用SSIM寻找分叉状态，把成功动作蒸馏到失败轨迹的历史上下文中，再混合训练。
  2. AndroidWorld上，4B模型报告64个随机种子的平均成功率81.0%；Table2列出的Qwen3-VL-4B为45.3%，MAI-UI-235B为76.7。后两者取自既有论文，而非本实验统一重跑。

64种子自测与引用基线的协议差异限制了强排名结论。截图相似并不自动保证内部应用状态等价，规则验证器和训练分布仍决定修正信号质量。

03

问题 03

怎样复算分析？

案例检索与执行反馈服务于数据、模型和口径。

数据分析要先确定schema、目标、单位、缺失值与数据划分，再执行SQL或程序。执行成功只证明程序可运行，不能证明统计口径、因果或泛化正确。

中间产物需保留输入hash、代码、随机种子、切分、验证结果和图表；用户才可以复算并看清适用边界。

读图前的算例 · 教学示意

清洗日期和货币后，做训练/验证划分并生成结果表。若模型效果差，要区分数据错误、方案不适合、程序Bug和随机波动。

DS-Agent: Automated Data Science by Empowering Large Language Models with Case-Based Reasoning

2024-02-27

检索经验案例，按执行反馈重排、修订并保留。

  1. DS-Agent用案例推理支持数据科学：从Kaggle经验库检索案例，结合执行日志重新排序，生成实验方案与代码，调试并运行，再保留表现好的方案。开发阶段反复改进，部署阶段复用成功案例。
  2. 12个数据科学任务、5次重复试验、GPT-4设置下，Table1平均Mean Rank为5.0，ResearchAgent为9.8。独立的Table2消融以Average Best Rank计，完整系统2.08，去ReviseRank为2.58，去CBR为3.41；排名越低越好。

Mean Rank和Best Rank是不同统计量，表间也不能直接作百分点差。方法依赖案例质量和真实执行反馈，检索相似文本本身不足以构成有效实验经验。

04

问题 04

怎样积累技能？

开放环境中先观察、设目标，再组合已验证技能。

开放世界没有固定唯一答案；当前库存和环境决定哪些子目标可完成。探索不是随意行动，需要把发现新信息、掌握技能和最终目标区分。

可执行技能要有前置条件、完成判据和失败反馈，检索到的旧技能还要检查新环境是否适用。

读图前的算例 · 教学示意

将“清洗一列日期”视为小技能，先验证再组合进报告流程。Minecraft中的采集/制造仅作为不同环境的原始证据，不把工作流类比当作者实验。

Voyager: An Open-Ended Embodied Agent with Large Language Models

2023-05-25

课程提目标，技能代码随反馈修正并积累。

  1. Voyager用自动课程提出与当前能力匹配的新目标，以可执行代码表示技能，并把验证成功的程序放入技能库。下一项任务检索相关程序，再结合环境反馈、代码错误和自我验证迭代改进。
  2. MineDojo/Mineflayer的GPT-4实验中，每种方法进行3次试验，最多160次提示。获得铁工具所需平均提示次数为21±7，无技能库为29±11，AutoGPT为135±103；三者铁工具阶段均3/3成功。

这里衡量的是Minecraft中的探索和技能复用；3次试验不足以支撑广泛环境的稳定性结论。学习积累在代码技能库和上下文中，不是模型权重训练。

05

问题 05

怎样完整验收？

跨应用约束、隐含状态与最终工件共同决定成功。

任务可能跨数小时、多应用和多条信息流。局部步骤分数很高，最后仍会因漏约束、未交付或误用版本而失败。

验收需同时保留最终成功、部分完成、恢复次数和成本；独立检查器和完整轨迹能帮助定位问题，而不是只看模型最后的宣告。

读图前的算例 · 教学示意

从修脚本、分析、GUI核对一直到交付：每个阶段都有工件和检查点。若中途用户改口径，旧结果要标旧版本，最终交付必须对应新条件。

SWE-Effi: Re-Evaluating Software AI Agent System Effectiveness Under Resource Constraints

2025-09-11

用预算内成功曲线衡量资源效能。

  1. SWE-Effi在成功率之外，测量解决任务随资源消耗的变化，并以归一化曲线面积表达预算内效能。它分别限制token、美元、CPU时间和推理时间，避免一个最终成功率掩盖昂贵失败。
  2. 评测涵盖5种框架与3种模型组合；框架采用各自默认迭代限制，SWE-agent另设每题1美元上限，并关闭并行处理。推理时间由token数量的回归模型归一化估计。

它比较的是明确预算与配置下的效能；归一化推理时间不是实际网络延迟。框架默认限制不同，也不能据此声称所有系统使用相同搜索机会。

OSWorld2.0: Benchmarking Computer Use Agents on Long-Horizon Real-World Tasks

2026-06-28

长程跨工具工作流，用完整和部分完成分开验收。

  1. OSWorld2.0把电脑评测延伸到长程专业工作流，加入连贯的初始工件、可控自托管服务、任务内用户澄清和动态消息，并同时报告严格完成率与细粒度部分得分。
  2. release v2026.06.24、108任务、500步预算、截图观察下，Claude Opus4.8最高思考等级的批量动作设置为20.6%二元完成率、54.8%部分得分；单动作设置为18.5%与49.3%（Table3）。

完成了多数子目标仍可能未完成整项任务。批量与单动作设置的每步工具调用量不同；部分得分、二元完成率和token成本应分别解释。

PDF第4,8页；机制与所列实验 ↗

OSWorld2.0把部分进展与完整完成分开，SWE-Effi把成功与所耗资源联系起来。一个可用Agent既要交付合格产物，也要控制失败尝试的成本；单一成功率或单一平均步数都不够。

待解决问题

  • 任务版本、模型、工具、步数与测试可见性不同的结果不能直接合并排名。
  • 局部进展、候选可解率和最终任务成功是不同指标；成本应包含失败试验。
