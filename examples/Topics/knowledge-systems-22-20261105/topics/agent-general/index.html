Agent的基本闭环是：根据目标和当前观察选择动作，接收环境反馈，再更新下一步判断。ReAct、Toolformer和Reflexion分别奠定交互推理、工具学习与反思记忆的基础。

2025—2026年的重点转向长期记忆与协作：记忆如何更新而不过度压缩，图结构何时值得额外成本，不同执行角色如何交接，以及团队失败究竟发生在哪一步。

01

问题 01

如何闭环规划？

观察更新计划，工具调用需要学会选择与解释。

Agent面对的不是一张静态题纸：工具会报错，数据schema会不同，网页和文件会改变。目标需要被分成子步骤，且每个动作都要检查反馈。

提示示范可以教会交互格式，训练轨迹和可执行反馈则会改变模型的选择能力。二者应区分，不能把更多训练或更强工具当作纯提示收益。

读图前的算例 · 教学示意

固定“读取数据、修复分析脚本并交付可复算报告”的任务。CSV含货币符号和异常日期；先观察，再清洗、计算和核验。以下机制都接着这一任务解释。

ReAct: Synergizing Reasoning and Acting in Language Models

2022-10-06

把思考、工具行动与环境反馈交替组织。

  1. ReAct把推理与环境动作交替安排。模型既能生成用于规划的语言，也能执行查询或交互动作；后者带回真实观察，使后续推理能够修正先前假设。
  2. 思想文字本身不改变环境，工具动作才产生新观察；这一点把自言自语和实际获取信息区分开来。原始实验通过少样本提示使用冻结模型。
  3. PaLM-540B的HotpotQA设置中，ReAct EM为27.4，CoT为29.4；结合两者的ReAct→CoT-SC为35.1。WebShop的500个测试任务上，ReAct成功率40.0%，Act为30.1%。

检索接地有收益也有代价：无信息的检索和反复推理仍会使系统失败，ReAct并非在每种任务都优于无工具CoT。不同任务指标不能直接合并。

Toolformer: Language Models Can Teach Themselves to Use Tools

2023-02-09

采样调用、执行、按预测损失筛选，再训练模型。

  1. Toolformer让模型学习何时调用工具：先在文本上采样候选API调用，执行后取得结果，再比较插入结果能否降低后续文本预测损失，只把有帮助的调用加入微调数据。
  2. 过滤比较带结果调用与不调用、无结果调用的损失差，因此训练目标关注工具结果对后续预测的帮助，而不只是模仿API语法。
  3. GPT-J 6.7B的原始实验在每个输入上最多调用一次API。SVAMP准确率为29.4%，禁用工具时为6.3%，原始GPT-J为5.2%（Table4）；评测采用论文指定的数值抽取规则。

这套数据构造说明工具使用可通过自监督筛选学习，但单次API调用评测不等于长程多工具规划能力。预测损失改进也不是任意真实任务奖励。

ReAct调整行动闭环，Toolformer训练调用决策。前者并未替代工具schema和结果校验，后者的单调用实验也不等同长程规划。

02

问题 02

怎样从失败学习？

反馈先转成具体可执行经验，再检查下轮是否改善。

一次失败轨迹可能告诉Agent哪里出了问题，也可能只是偶然错误。反思必须绑定实际观察和可改变步骤，泛泛的自我批评无法指导行动。

评价要区分单次成功率、固定预算成功率、累计解决率和跨任务迁移；这些数字不能混写。

读图前的算例 · 教学示意

日期被字符串排序后图表错乱。记录失败原因、修订步骤和下次检查，再在相同原始输入上重试；保留原失败轨迹供复查。

Reflexion: Language Agents with Verbal Reinforcement Learning

2023-03-20

失败后写可复用反思，再重置环境重试。

  1. Reflexion把失败后的反馈写成语言反思，并在下一次尝试中保留。它调整的是上下文中的经验，而不是更新模型权重：执行任务、检查结果、生成反思、重置环境后重试。
  2. 记忆保存有限条反思，启发式检测包括重复行为和总动作数；下一轮利用这些记录避开已见错误。
  3. ALFWorld的134个环境、GPT-3.0与共同少样本提示设置下，初始成功率63%，经过12次试验后的累计成功率97%。该数字包含多次重试。

累计12次试验的成功率不能当成一次执行成功率。语言反思若没有可靠环境反馈，仍可能把错误解释写入记忆。

反思是上下文更新，不等于权重学习。反馈准确性、重试预算及迁移范围决定它的实用边界。

03

问题 03

怎样保存与取用？

写入、冲突更新与主动检索是不同环节。

完整会话越来越长，全部读回很贵，直接截断又会丢偏好和关键事实。长期记忆要解决“存什么、如何更新、问时取什么”。

事件、稳定事实、当前偏好和可执行经验不宜混为一种记录；来源、时间和过期条件决定记忆是否仍适用。

读图前的算例 · 教学示意

同一报告跨几次会话完成：用户先用美元后改欧元。系统要取当前偏好，还要能回查旧版本的依据；解释原因时可继续检索相关事件。

Mem0: Building Production-Ready AI Agents with Scalable Long-Term Memory

2025-04-28

提取候选事实，和旧记忆比较后增删改。

  1. Mem0将长对话记忆分为抽取和更新两阶段。新消息结合对话摘要与近期上下文提出候选记忆，再检索相似旧记忆决定添加、更新、删除或保持不变；图版本进一步用实体与关系组织信息。
  2. 记忆压缩并非越复杂越好。LoCoMo的Temporal LLM-judge分数由Mem0的55.51升至图版本58.13，但Multi-hop由51.15降至47.19（Table1）。
  3. Table2的整体Judge分数和p95总延迟分别为：完整上下文72.90与17.117秒；Mem0为66.88与1.440秒；图版本68.44与2.590秒。它展示质量与延迟权衡，而非无损压缩。

图结构对部分关系问题有益，却可能降低其他子任务表现。结果绑定LoCoMo和论文实现，不能视为所有长期记忆系统的统一排名。

Memory is Reconstructed, Not Retrieved: Graph Memory for LLM Agents

2026-06-04

用线索与标签引导多轮图记忆重构。

  1. MRAgent用Cue→Tag→Content的关联结构把情节、语义和主题联系起来。查询不是一次性取回固定片段，而是在图中正向与反向遍历，按需重构当前可用记忆，并累积已探索信息。
  2. LLM选择下一步遍历与重构动作，状态区分当前激活信息与累计历史，直到获得足够证据再回答。
  3. Gemini骨干的LoCoMo整体Judge分数为84.21，Mem0为68.31；但Multi-hop F1为43.69，低于Mem0的45.17。LongMemEval每样本构建加检索为118k tokens/586.11秒，Mem0为245k/533.29秒（p7）。

更少token不必然更低延迟；更高总体Judge分数也不保证每个子任务的F1更高。关联记忆与检索控制的联合设计仍需按任务拆开检验。

事实压缩与图重构各有成本和质量取舍。需要同时检查漏存、冲突、时效性、证据召回和最终任务收益。

04

问题 04

怎样分工协作？

角色、动作空间和共享状态一起影响协作。

单Agent可以多次采样，多Agent也会引入通信、重复和冲突。收益可能来自更多预算、专门工具或角色分工，应尽可能分开归因。

协调者需要能看到任务当前状态，执行者需要具体可操作上下文；交付物和验证结果比自然语言完成声明更可靠。

读图前的算例 · 教学示意

代码执行者批处理数据，GUI执行者检查桌面产物，协调者保存路径、状态和验收条件。若两者同时改同一文件，要先解决版本与合并。

Why Do Multi-Agent LLM Systems Fail?

2025-03-17

沿执行轨迹区分设计、协作与验收失败。

  1. 该研究从真实多Agent执行轨迹归纳失败模式：开放编码、持续比较和标注者讨论反复修订分类，再验证标注一致性。v1的MASFT将14类失败归为系统规格、Agent间失配、任务验证与终止三组。
  2. 研究初始分析150多条轨迹，覆盖5个系统；标注一致性Cohen’s κ为0.88。它把“最后答错”拆成可定位的协作过程问题。

这是基于所选系统和任务的经验分类，不是证明多Agent必然无效。分类一致性衡量标注口径，不是系统任务成功率；后续版本扩展数据与命名，应分版本引用。

CoAct-1: Computer-using Agents with Coding as Actions

2025-08-05

协调者按子任务选择代码或GUI执行者。

  1. CoAct-1用Orchestrator协调Programmer和GUI Operator。两名执行者分别使用代码与图形界面，并维护独立对话；协调者接收摘要和截图再分派子任务，本身不直接操作操作系统。
  2. 代码适合批量、结构化处理，GUI适合依赖视觉或只能交互访问的操作；混合动作空间让系统按子任务选择执行方式。
  3. 论文Table3–4中，o3协调者、o4-mini程序员与CUA4o GUI组合成功率60.76%；代码单独35.73%、GUI单独50.68%，混合60.76%，平均步数分别1.14、11.20、10.15。

这些设置同时改变动作空间与协作架构，不能把全部增益单独归因于Agent数量。代码和GUI的单步含义不同，步数也不是统一成本。

CoAct-1展示代码与GUI角色的动作互补，失败分类研究则提醒：角色增加以后，信息交接、规格遵守和终止验证会形成新的失败点。组织结构应按这些具体职责评估，不能只数Agent个数。
