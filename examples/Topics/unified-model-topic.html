背景、问题、方法与实验。时间线采用首次公开日期，正文方法及实验链接保留具体论文版本。

理解需要把无关像素变化压缩成稳定语义，生成需要恢复颜色、纹理和局部布局。两者放进同一个模型后，主要问题是怎样表示视觉、共享哪些参数、用什么目标优化，以及怎样验证两类能力没有互相牺牲。

贯穿教学任务：给出红杯在左、蓝杯在右的图片，先回答位置关系，再生成“交换两杯、保持桌面不变”的图，最后扩展为一个短视频。这个教学任务用于解释数据流，不是论文实测案例或额外基准。

前四章分别讨论离散早期融合、不同输出目标、解耦视觉前端和参数专家分工。时间线用于定位所用版本，不把论文在某分支的位置等同于严格继承或淘汰。

下面的章节沿具体问题展开；最后进一步讨论统一能力怎样超越两张独立榜单。

01

问题 01

统一序列与离散视觉表示

一个词表能否兼顾视觉语义与像素细节？

把图像压成离散码，可以复用语言模型的序列训练和生成接口，也方便图文交错输出。但图像码如果只为重建优化，未必能突出对象关系；如果只保语义，又难以重建纹理。

早期融合提供清楚的统一协议，其代价包括长视觉序列、量化损失与跨模态优化稳定性。这些是后续分工设计的出发点。

读图前的算例 · 教学示意

先把原布局转成视觉码，再在同一序列输出文字与目标视觉码；检查红蓝属性是否被正确绑定，而非只评价图片美观。

Chameleon: Mixed-Modal Early-Fusion Foundation Models

2025-03-21

把图像和文字都离散成一个混合序列，用早期融合自回归模型学习理解与生成。

  1. 文本用子词token，图像由VQ tokenizer转换为可重建的离散码；一张512×512图对应1024个视觉token。两种token从主干底层起共同参与注意力。
  2. 训练目标统一为下一个token预测，图文交错文档成为原生训练样本；输出图像时预测视觉码，再由图像解码器复原像素。架构简洁，但量化码既要保存语义又要保存纹理。
  3. 论文还调整归一化、query-key范数和logit稳定性，处理视觉token与文本token竞争带来的训练不稳定。统一词表并非只是在现有LLM后接一个图片解码器。
  4. 接着算例：用户给红杯在左、蓝杯在右的图片，要求“描述关系，再画交换后的布局”。输入图像先成为1024个码，描述是文字token，交换后的图继续作为同一序列中的图像码生成。

02

问题 02

同一主干中的不同生成目标

文字按序生成，视觉能否并行去掩码或预测连续流？

文字的自然序列结构适合下一个token预测，二维图像并没有唯一必需的扫描顺序。强制所有视觉位置逐个生成，会扩大序列延迟，也可能约束视觉建模方式。

保留共享上下文的同时，为文字与视觉使用不同注意力和训练目标，是另一种统一方式。离散去掩码与连续流都需要调度和步数预算，不能因并行更新位置就省略迭代成本。

读图前的算例 · 教学示意

交换杯子的目标图里，杯子和桌面可以同时被修复。比较离散mask恢复与连续潜变量流，分别记录位置、颜色绑定和推理步数。

Show-o: One Single Transformer to Unify Multimodal Understanding and Generation

2025-09-08

在一个Transformer中让文本自回归、图像做离散去掩码，注意力规则随输出类型变化。

  1. 图像经MAGVIT-v2量化为网格码，文本仍用语言token。Omni-attention对文本保持因果性，对同一图像的视觉token允许完整相互注意，从而适应不同生成顺序。
  2. 文本端预测下一个token，图像端对随机掩码的码进行恢复；推理生成图像时，从全mask开始并行填充，再按调度逐步确定视觉位置。理解任务则条件化于输入图像预测文字。
  3. 接着算例：生成交换杯子的图片时，不再按左上角到右下角逐码完成整张图，而让多处杯子与背景一起被修复；如果先把“红/蓝”绑定错，后续去掩码仍可能稳定到错误画面。
  4. 该版本另比较离散与连续视觉输入。理解表示、输出码、掩码调度和注意力是不同决策，不应把“一个模型”误解为全部模态必须使用相同损失。
L = LAR(text) + λ·Lmask(image)

目标分工的教学简写：语言预测下一个token，图像预测被mask的离散码。λ与采样调度依训练实现，不是宣称两个损失天然等价。

Show-o2: Improved Native Unified Multimodal Models

2025-09-22

用连续时空潜变量和双路径表示统一语义与细节，支持图像、视频理解与生成。

  1. 先用3D causal VAE编码图像或视频，得到可重建的连续视觉潜变量。一条语义路径由SigLIP视觉层初始化，另一条投影路径保留低层视觉信息，再沿通道融合并归一化。
  2. 文本和融合视觉表示进入带因果/全注意力的统一主干；语言头做自回归文字预测，Flow头做连续视觉速度预测。噪声调度与流匹配为图像/视频提供不同于离散码的生成机制。
  3. 接着算例：先读两杯图，再描述交换，最后生成交换后的短视频。语义路径负责“红杯/蓝杯/左右”，低层路径保存材质与外观，3D潜变量把时间也纳入视觉接口。
  4. 相较Show-o，改变了离散视觉码、生成目标和时空表示，不能把版本差值只归于某一个双路径模块。统一能力需要分别测量图像、视频、编辑和混合输出。
xt = t·x1 + (1−t)·x0；Lflow = E||vθ(xt,t,c)−(x1−x0)||²

按原文线性插值方向书写：x0为噪声，x1为视觉潜变量，c是文字/视觉条件。流场逐步把噪声移向目标视觉表示，文本仍采用另一套自回归目标。

03

问题 03

解耦视觉前端与训练配方

理解与重建用不同接口，语言主干仍然共享。

同一张图片作为“被问到的证据”和“要生成的目标”时承担不同角色。理解希望语义稳定，生成希望细节可逆，二者不必被迫经过同一个有损瓶颈。

解耦前端可以缓解目标冲突，后续还需要合理的数据质量、任务比例和阶段安排。架构有效并不说明任意混合比例都能同时提升两端。

读图前的算例 · 教学示意

读取原图用语义编码，绘制交换图才使用可重建码。进一步保持架构不变升级训练，以区分接口与配方的作用。

Janus: Decoupling Visual Encoding for Unified Multimodal Understanding and Generation

2024-10-17

为理解和生成保留不同视觉编码器，共享语言主干与自回归生成协议。

  1. 视觉理解需要对类别与关系敏感、对像素微扰不太敏感；可重建图像则需要保存颜色、纹理与局部细节。要求同一视觉码同时满足两种目标，会产生表示冲突。
  2. 输入理解图片用SigLIP特征，生成图片用VQ码；两套适配器映射到共享Transformer。回答文字走原语言头，输出图片走专门视觉码预测头，再由VQ解码器还原。
  3. 三阶段训练先对齐接口，再混合预训练，最后指令微调。主干共享没有要求视觉前端完全共享，输入图像也不必先经过有损量化。
  4. 接着算例：判断红杯在左时用语义特征；画交换布局时才预测重建码。改变的是同一图片在不同任务中的表示接口，仍需要训练数据教会“交换”对应哪种变换。

Janus-Pro: Unified Multimodal Understanding and Generation with Data and Model Scaling

2025-01-29

沿用解耦视觉编码，把数据质量、混合比例与训练阶段扩大到更强的统一模型。

  1. 结构延续Janus，主要变动在训练与数据：延长接口预训练、调整第二阶段的图像生成数据安排、增加真实/合成高质量视觉样本，以及扩大语言主干。
  2. 第三阶段混合多模态理解、纯文本和文生图，作者采用5:1:4的数据比例；这在保留语义能力和提升生成质量之间重新分配梯度预算。
  3. 接着算例：接口不变，仍从语义编码读图、从视觉码画图。更多高质量成对描述让“交换两杯且保持桌面”这种组合约束更可能被学到；这是配方进展，不是新增显式场景图执行器。
  4. 将1B档和7B档分别比较，避免把模型扩容与配方收益混为一项。评测还要分别看数量、颜色绑定、位置与文字渲染，而非只看总体均值。

04

问题 04

专家分工、交错预训练与推理预算

既缓解梯度冲突，又不切断理解与生成的信息交换。

即使前端不同，共享全部Transformer参数仍可能让语义预测与低层流场目标竞争。反过来，完全独立的理解器和生成器又会经过摘要接口丢失细节。

参数专家通过共享注意力形成较细粒度的信息交换；大量交错数据教会模型描述、观察变化和编辑。测试时思考与提示改写则是另一层，必须独立计入预算。

读图前的算例 · 教学示意

描述中明确交换哪只杯子，生成专家直接访问相同上下文。对比直接画图、先思考再画、改写提示再画，不能将三种设置混成同一模型分数。

Emerging Properties in Unified Multimodal Pretraining

2025-07-27

理解与生成使用Transformer专家分工，通过共享注意力维持细粒度交互，并扩大交错多模态预训练。

  1. 理解侧用语义视觉编码，生成侧用连续VAE潜变量；两套Transformer专家对各自token进行参数化处理，但都参与同一多模态自注意力，减少仅通过少量摘要token传递的瓶颈。
  2. 文本自回归，图像用rectified flow预测速度；大量网页、图文和视频转换为交错序列，训练模型观察变化、理解编辑意图并生成后续视觉状态。
  3. 接着算例：模型先读原布局，文字描述“交换红蓝杯”，生成专家通过共享上下文访问杯子属性和桌面细节，再预测目标图像的连续流场。文字推理可在输出图之前加入，但会消耗额外预算。
  4. 区分专家设计、数据扩展和测试时提示改写。原文1.5B的Dense/MoE/MoT损失曲线支持分工降低优化冲突；大模型榜单不是同一受控实验。

问题 05

统一能力怎样超越两张独立榜单？

同时检验理解与生成的协同，以及编辑过程中的来源身份。

理解分数高、生成分数高，仍可能在一次连续任务中失败。例如模型答对哪只杯子是红色，却在编辑时改变了另一只杯子或桌面。

MME-Unify

2025-04-04

分别评估理解、生成和混合任务，要求模型在同一任务里给出相互对应的文字与图像输出。

  1. 传统任务统一格式和评测口径；另设编辑并解释、常识问答配图、几何辅助线、找不同、视觉步骤推演等五类协同任务。
  2. 协同任务检查文字选项，并以生成图像与正确及干扰图像的CLIP相似度关系判断图像选择是否正确。

图像评分依赖候选集合与CLIP相似度；此协议不等价于对每个像素、身份细节和编辑保持区域的完整检验。

§1–2；HTML行43–111；v1 ↗

MIE-UMM

2026-01-09

用可学习分隔符和正弦图像索引，明确告诉生成模块每个视觉词元属于哪张参考图。

  1. 分隔符在潜空间标记图像边界；同一图像的词元共享索引嵌入，让模型区分跨图引用并外推输入图像数量。
  2. 从高质量目标图反向构造源图和参考图，以减少目标伪影，形成可实现的多图编辑监督。

这里针对MLLM与扩散生成器组成的混合架构及多图引用一致性；不能把图像索引编码本身等同于全面的理解生成统一。

§1–3.1；HTML行45–93；v1 ↗

MME-Unify检查理解和生成能否在同一任务中协作；MIE-UMM处理协作时参考图身份容易混淆的问题。共享主干、明确图像身份与联合任务评测是不同层面的设计，选型时应把能力、表示和验收协议分别对应起来。
