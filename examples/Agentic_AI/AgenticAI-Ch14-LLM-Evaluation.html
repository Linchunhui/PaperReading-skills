第14章：LLM Evaluation

大语言模型评估——从方案设计、数据收集到指标体系的完整方法论

来源：Agentic AI · 第14章（pp. 274–289） · 阅读笔记

章节摘要

本章系统性地介绍了LLM评估的完整技术栈。从评估方案设计（内在vs外在、自动vs人工）出发，覆盖数据收集方法论（人工标注管线、标注者一致性度量）、合成数据生成范式（Self-Instruct、Evol-Instruct、Constitutional AI），到三大类评估指标体系：排名指标（ELO、Bradley-Terry、TrueSkill）、生成指标（BLEU、ROUGE、BERTScore、Perplexity、Pass@k）、智能体指标（TSR、轨迹效率、SWE-bench、WebArena），最后深入LLM-as-Judge方法论和评估陷阱（基准泄露、Goodhart定律）。本章为构建可靠的LLM评估管线提供了从理论到实践的完整指导。

14.1 Evaluation Scheme Design

在采集任何数据之前，必须先决定测什么和怎么测。一个有原则的分类法可以避免"按方便程度选指标"这一常见错误。

14.1.1 评估类型分类（Taxonomy）

内在评估 vs 外在评估

内在评估（Intrinsic）：在不参考下游应用的情况下，度量模型输出本身的属性。例如困惑度（Perplexity）、BLEU分数、Pass@k。优点是便宜、可复现，缺点是与真实效用相关性往往较弱。

外在评估（Extrinsic）：度量模型对真实任务或系统的影响。例如"集成LLM后工单升级率降低了多少？""编码助手是否提高了开发速度？"优点是直接度量关注点，缺点是昂贵且慢。

内在-外在差距：内在指标便宜可复现，但常与真实效用弱相关——困惑度更低的模型不一定更有用。成熟的评估策略是：用内在指标做快速迭代，用外在指标做最终验证。

自动评估 vs 人工评估

自动评估使用确定性函数（BLEU、精确匹配）或学习模型（BERTScore、LLM-as-Judge）打分。人工评估由标注者对输出评分或排序。

类型成本速度可复现性有效性
自动（规则型）极低极快完美低–中
自动（模型型）低快高中–高
众包人工中天级中中
专家人工高周级低–中高
外在/A/B测试极高月级低极高

基于参考 vs 无参考评估

Reference-Based（BLEU、ROUGE、BERTScore）：将模型输出与一个或多个金标准参考进行比较。

Reference-Free（困惑度、LLM-as-Judge、人类偏好）：无需参考即可评估质量。当输出空间太大（如开放对话），无参考方法不可或缺。

14.1.2 When to Use What

决策框架：

  • 任务有明确正确答案（数学、代码、事实QA）→ 使用精确匹配或执行型指标
  • 任务开放但有参考输出 → 使用 Reference-Based 指标作为下界 + LLM-as-Judge 补充
  • 任务主观（有用性、语气、创意）→ 使用人工评估或校准过的LLM Judge
  • 任务涉及多步Agent行为 → 使用任务成功率 + 轨迹效率（见14.6节）

对话助手评估策略示例：

  • 开发阶段：自动指标（PPL、ROUGE、Pass@k），每夜运行标准Benchmark（MMLU、HellaSwag、HumanEval）
  • 发布前阶段：人类偏好研究 + LLM-as-Judge 在多样prompt集上做可扩展的pairwise比较
  • 发布后阶段：监控外在指标（用户满意度、任务完成率），关注分布漂移

14.2 Data Collection for Evaluation

高质量评估数据是可信基准测试的基础。本节覆盖人工标注管线设计、标注质量统计度量，以及众包与专家标注的选择。

14.2.1 人工标注管线（Human Annotation Pipeline）

一个稳健的标注管线包含五个阶段：

  1. 任务定义：精确指定标注任务——评什么、用什么尺度、用什么标准。此阶段的模糊性会传播为噪声标签。
  2. 指南开发：编写含边界案例的标注指南，先用小型试点组迭代改进。
  3. 标注者招募与培训：选择有相关背景知识的标注者，进行校准会议（标注相同样本并讨论分歧）。
  4. 质量控制：在标注队列中嵌入已知标签的金标准样本，标记准确率低于阈值的标注者。
  5. 聚合：用多数投票、取平均或概率模型（如Dawid-Skene）合并多个标注。

14.2.2 标注者一致性（Inter-Annotator Agreement）

原始一致率（所有标注者均同意的项目比例）不够好，因为它没有扣除随机一致。两种标准的校正度量：

Cohen's Kappa（两个标注者）：

$$\kappa = \frac{p_o - p_e}{1 - p_e}$$

$p_o$ 为观测一致率，$p_e$ 为独立假设下的期望一致率。$\kappa$ 范围 $[-1, 1]$：0 表示随机一致，>0.6 通常可接受，>0.8 为强一致。

其中：

$$p_o = \frac{1}{N}\sum_{i=1}^{N}\mathbf{1}[\text{annotator 1 agrees with annotator 2 on item } i]$$ $$p_e = \sum_{c=1}^{k} p_{1c} \cdot p_{2c}$$

$p_{jc}$ 为标注者 $j$ 将项目分配到类别 $c$ 的比例。

Fleiss' Kappa（多个标注者）：对 $n$ 个标注者标注 $N$ 项到 $k$ 类，设 $n_{ij}$ 为将第 $i$ 项分到第 $j$ 类的标注者数：

$$\bar{P}_i = \frac{1}{n(n-1)}\sum_{j=1}^{k}n_{ij}(n_{ij}-1), \quad \bar{P} = \frac{1}{N}\sum_{i=1}^{N}\bar{P}_i$$ $$P_e = \sum_{j=1}^{k}\left(\frac{1}{Nn}\sum_{i=1}^{N}n_{ij}\right)^2$$ $$\kappa_F = \frac{\bar{P} - P_e}{1 - P_e}$$

Fleiss' Kappa 推广到多标注者场景，衡量超出随机水平的一致程度。

Kappa局限性：当某一类别占绝对优势时，即使原始一致率高，kappa 也可能很低（"kappa悖论"）。对于序数量表（如1-5 Likert），应使用加权kappa（按分歧距离加权惩罚）。LLM评估中应始终报告加权kappa。

14.2.3 标注指南设计

有效标注指南的特性：

  • 操作化标准：用具体行为替代模糊用语，如将"有帮助"改为"回答直接解决用户问题并提供完成任务所需的全部信息"。
  • 实例：每个评分等级至少提供两个示例，包括边界案例。
  • 决策树：对复杂任务提供流程图，引导标注者通过二元决策序列减少认知负担。
  • 明确范围：声明不应考虑什么（如"不要因文体偏好扣分，仅关注事实准确性"）。

14.2.4 众包 vs 专家标注

维度众包专家标注
单项成本低（$0.01–$0.10）高（$1–$50）
吞吐量极高低
领域知识低高
一致性不稳定高
适用任务简单偏好、流畅度技术准确性、安全性
质量控制金标样本、注意力检查校准会议、同行评审

对于安全关键评估（检测有害输出、评估医疗建议），专家标注不可替代。对于大规模偏好收集（构建奖励模型训练集），严格质控的众包往往是唯一可行选项。

14.3 Synthetic Data Generation for Evaluation

人工标注昂贵且慢。合成数据生成利用LLM自身大规模生产评估数据。

14.3.1 LLM-as-Judge 校准

当使用LLM生成评估标签时，校准至关重要：Judge 的分数必须与人类判断对齐。

期望校准误差（ECE）：

$$\text{ECE} = \sum_{b=1}^{B}\frac{|B_b|}{n}\left|\text{acc}(B_b) - \text{conf}(B_b)\right|$$

$B_b$ 为第 $b$ 个置信度桶，$\text{acc}(B_b)$ 为桶内judge与人类一致的比例，$\text{conf}(B_b)$ 为桶内judge平均置信度。良好校准意味着 $E[\hat{h}_i | \hat{h}_i = p] = p$。

校准可通过温度缩放（Temperature Scaling）改善：将judge的原始logit $z$ 替换为 $z/T$，其中 $T$ 在校准集上调优以最小化负对数似然。

14.3.2 Self-Instruct

Self-Instruct 从少量人工种子任务引导生成大量指令遵循数据：

  1. 维护一个用 175 个种子任务初始化的任务池
  2. 从池中采样 8 个任务作为 few-shot 示例，提示LLM生成新任务
  3. 过滤：去除近似重复（ROUGE-L > 0.7）、分类任务/非分类任务分类、生成输入-输出实例
  4. 将通过的任务加入池
  5. 重复直到池达到目标规模

14.3.3 Evol-Instruct

Evol-Instruct 通过迭代重写使指令变得更复杂或更多样：

  • 深度进化（In-depth）：添加约束、增加推理步骤、具象化抽象、加深领域知识要求
  • 广度进化（In-breadth）：在相关但不同的话题上生成新指令，增加话题多样性

通过淘汰过滤器：进化后的指令不能是简单复制，不能包含拒绝语句（如"I'm sorry"），不能比原始更短。

14.3.4 Constitutional AI 数据生成

Constitutional AI（CAI）让模型根据一组原则（"宪法"）批评并修正自己的输出：

  1. 监督学习阶段：采样有害prompt → 生成初始回复 → 提示模型按宪法原则批评并修正 → 修正后的回复作为SFT目标
  2. RL阶段：生成回复对（原始 vs 修正）→ 模型标注哪个更合宪 → 训练偏好模型 → 用偏好模型作RLHF奖励信号

这种方法无需人类标注有害内容，减少了标注者接触令人不安材料的暴露。

14.3.5 蒸馏生成评估数据

使用强大的教师模型（如GPT-4）生成高质量评估数据来训练小型judge：

  1. 收集多样的prompt和模型回复
  2. 教师生成详细判断（分数 + 理由）
  3. 在（prompt, response, judgment）三元组上微调小模型
  4. 在独立人工标注集上验证学生judge

蒸馏偏差：学生judge继承教师的偏见——冗长偏好、自我增强偏差（如果教师同时是被评估模型）、位置偏差。始终需要用独立人工标注进行验证。

14.3.6 Arena-Style 对战生成

Chatbot Arena 通过众包对战平台生成评估数据：用户提交prompt，对两个匿名模型回复投票。关键设计：

  • 匿名化：隐藏模型身份，防止品牌偏好
  • 用户提交prompt：确保多样性和真实世界相关性
  • 平局处理：用户可声明平局或"两个都差"
  • 去重：过滤近似重复prompt防止过度代表常见查询

14.4 Metrics for Ranking Tasks

当目标是对模型排名时，成对比较数据比绝对分数更可靠。本节推导LLM评估中主要的排名系统。

14.4.1 ELO Rating System

ELO系统最初为国际象棋开发，为每个模型分配标量评分 $R$：

期望得分：

$$E_A = \frac{1}{1 + 10^{(R_B - R_A)/400}}$$

模型A对阵模型B的期望得分。400分差对应 10:1 胜率。

ELO概率模型（基于logistic分布）：

$$P(A \succ B) = \sigma\left(\frac{R_A - R_B}{s}\right) = \frac{1}{1 + e^{-(R_A - R_B)/s}}$$

$s = 400/\ln(10) \approx 173.7$ 为缩放参数。

评分更新：每场比赛结果 $S_A \in \{0, 0.5, 1\}$（负/平/胜）后：

$$R_A \leftarrow R_A + K(S_A - E_A), \quad R_B \leftarrow R_B + K(S_B - E_B)$$

$K$ 为K因子，控制学习率。Chatbot Arena中使用 $K=4$。ELO本质上是logistic模型观测结果对数似然的随机梯度下降更新。

置信区间：因ELO取决于比赛处理顺序，通过Bootstrap重采样（$B=1000$次）计算95%置信区间。

14.4.2 Bradley-Terry 模型

给定 $n$ 个模型，强度参数 $\beta_1, \ldots, \beta_n > 0$，模型 $i$ 胜过模型 $j$ 的概率：

$$P(i \succ j) = \frac{\beta_i}{\beta_i + \beta_j}$$

Bradley-Terry（BT）模型是ELO的最大似然替代方案。

对数似然：给定成对结果 $\{(i_k, j_k, y_k)\}_{k=1}^M$，$y_k = 1$ 表示 $i_k$ 胜：

$$\ell(\beta) = \sum_{k=1}^{M}\left[y_k \log\frac{\beta_{i_k}}{\beta_{i_k}+\beta_{j_k}} + (1-y_k)\log\frac{\beta_{j_k}}{\beta_{i_k}+\beta_{j_k}}\right]$$

通过迭代缩放或梯度上升求MLE。BT模型只在乘法常数下可辨，通常归一化为 $\sum_i \log\beta_i = 0$。

取对数空间 $\theta_i = \log\beta_i$：

$$P(i \succ j) = \sigma(\theta_i - \theta_j)$$

等价于以item为截距的逻辑回归。BT模型在完整比赛历史可用时优于ELO，因为它同时使用所有数据而非顺序处理。

14.4.3 TrueSkill

TrueSkill 是贝叶斯技能评分系统，将每个玩家的技能建模为高斯随机变量：

$$s_i \sim \mathcal{N}(\mu_i, \sigma_i^2), \quad p_i = s_i + \epsilon_i, \quad \epsilon_i \sim \mathcal{N}(0, \beta^2)$$

$s_i$ 为技能，$p_i$ 为比赛中的表现（技能 + 比赛噪声）。$i$ 胜 $j$ 当且仅当 $p_i > p_j$。

后验更新（观测到 $i \succ j$ 后，通过期望传播）：

$$\mu_i \leftarrow \mu_i + \frac{\sigma_i^2}{c} \cdot v\left(\frac{\mu_i - \mu_j}{c}\right)$$ $$\sigma_i^2 \leftarrow \sigma_i^2\left[1 - \frac{\sigma_i^2}{c^2} \cdot w\left(\frac{\mu_i - \mu_j}{c}\right)\right]$$

其中 $c = \sqrt{2\beta^2 + \sigma_i^2 + \sigma_j^2}$，$v(t) = \phi(t)/\Phi(t)$ 和 $w(t) = v(t)(v(t)+t)$ 为截断高斯校正因子（$\phi, \Phi$ 为标准正态PDF和CDF）。

优势：TrueSkill 的不确定度估计 $\sigma_i$ 特别适合识别需要更多评估数据的模型。

14.4.4 Win Rate 与置信区间

最简排名指标：胜率 $\hat{p} = w/n$。Wilson Score置信区间（优于Wald区间，在$p$接近0或1时覆盖率更好）：

$$\text{CI} = \frac{\hat{p} + \frac{z^2}{2n} \pm z\sqrt{\frac{\hat{p}(1-\hat{p})}{n} + \frac{z^2}{4n^2}}}{1 + \frac{z^2}{n}}$$

$z = 1.96$ 对应95%区间。多方比较时，应对固定基线模型计算胜率以确保可比性。

14.4.5 Chatbot Arena 方法论

Chatbot Arena 整合以上要素为生产级评估系统：

  1. 用户提交prompt，收到两个匿名模型的回复
  2. 用户投票选择偏好（或平局）
  3. 使用BT模型聚合投票生成排行榜
  4. 报告每个模型分数的Bootstrap置信区间
  5. 置信区间重叠的模型视为统计上不可区分

截至2024年，Chatbot Arena已收集超过100万人类偏好投票，是最大的公开LLM偏好数据集。

14.5 Metrics for Generation Tasks

生成指标量化有参考答案或明确正确性标准的任务中模型输出的质量。

14.5.1 BLEU

BLEU（Bilingual Evaluation Understudy）度量假设 $h$ 与参考 $R$ 之间的n-gram精确率：

$$\text{BLEU} = \text{BP} \cdot \exp\left(\sum_{n=1}^{N} w_n \log p_n\right)$$

$p_n$ 为修正n-gram精确率，$w_n = 1/N$ 为均匀权重，BP为简短惩罚。

简短惩罚（Brevity Penalty）：

$$\text{BP} = \begin{cases} 1 & \text{if } |h| > |r| \\ e^{1 - |r|/|h|} & \text{if } |h| \le |r| \end{cases}$$

$|r|$ 为最接近参考的长度。防止过短的翻译获得虚高精确率。

修正n-gram精确率（每个n-gram计数裁剪到参考中最大出现次数）：

$$p_n = \frac{\sum_{\text{ngram} \in h} \min(\text{count}(\text{ngram}, h), \max_{r \in R}\text{count}(\text{ngram}, r))}{\sum_{\text{ngram} \in h} \text{count}(\text{ngram}, h)}$$

裁剪避免单个n-gram重复匹配多次，提高精确率估计的准确性。

BLEU局限性：设计用于有多个参考的机器翻译。对于单参考的开放式生成，BLEU常接近零。不能捕获语义相似性，惩罚合理改写，对分词敏感。仅在有多个多样参考且任务输出多样性低时使用。

14.5.2 ROUGE

ROUGE-N（面向召回的n-gram度量，为摘要设计）：

$$\text{ROUGE-N} = \frac{\sum_{r \in R}\sum_{\text{ngram} \in r}\min(\text{count}(\text{ngram}, h), \text{count}(\text{ngram}, r))}{\sum_{r \in R}\sum_{\text{ngram} \in r}\text{count}(\text{ngram}, r)}$$

ROUGE-1 和 ROUGE-2 分别度量unigram和bigram召回率。

ROUGE-L（基于最长公共子序列）：

$$\text{ROUGE-L} = \frac{\text{LCS}(h, r)}{|r|}$$

LCS捕获句子级结构。F-measure变体平衡精确率和召回率：$\text{ROUGE-N}_F = \frac{(1+\beta^2) \cdot P \cdot R}{\beta^2 P + R}$，$\beta=1$ 为等权。

14.5.3 BERTScore

BERTScore 使用预训练BERT的上下文嵌入计算token级相似度：

$$R_{\text{BERT}} = \frac{1}{|x|}\sum_{x_j \in x}\max_{\hat{x}_i \in \hat{x}}\frac{\hat{e}_i^\top e_j}{\|\hat{e}_i\|\|e_j\|}$$ $$P_{\text{BERT}} = \frac{1}{|\hat{x}|}\sum_{\hat{x}_i \in \hat{x}}\max_{x_j \in x}\frac{\hat{e}_i^\top e_j}{\|\hat{e}_i\|\|e_j\|}$$ $$F_{\text{BERT}} = 2 \cdot \frac{P_{\text{BERT}} \cdot R_{\text{BERT}}}{P_{\text{BERT}} + R_{\text{BERT}}}$$

$\hat{x}$ 为假设tokens，$x$ 为参考tokens，$\hat{e}_i, e_j$ 为对应嵌入。BERTScore对同义改写比BLEU/ROUGE更鲁棒。IDF加权版进一步提升相关性：$R_{\text{BERT}}^{\text{idf}} = \frac{\sum_{x_j} \text{idf}(x_j) \max_{\hat{x}_i} \cos(\hat{e}_i, e_j)}{\sum_{x_j}\text{idf}(x_j)}$

14.5.4 METEOR

METEOR 通过 F-score + 碎片化惩罚解决 BLEU 的召回盲区：

$$\text{METEOR} = F_{\text{mean}} \cdot (1 - \text{Pen})$$

$F_{\text{mean}} = \frac{10PR}{R+9P}$（召回加权调和均值）。碎片化惩罚 $\text{Pen} = 0.5 \cdot (c/u_m)^3$，$c$=块数，$u_m$=匹配的unigram数。额外支持词干还原和同义词匹配。

14.5.5 Perplexity（困惑度）

$$\text{PPL}(w_{1:T}) = \exp\left(-\frac{1}{T}\sum_{t=1}^{T}\log P_\theta(w_t | w_{1:t-1})\right)$$

越低越好——表示模型对测试文本的预测能力越强。注意：不同分词器/词表的模型不能直接比较PPL。主要用途：健全性检查和检测分布漂移。

14.5.6 Pass@k（代码生成）

通过执行测试用例验证功能正确性：

$$\text{pass@}k = \mathbb{E}_{\text{problems}}\left[1 - \frac{\binom{n-c}{k}}{\binom{n}{k}}\right]$$

$n$=每个问题生成的总样本数，$c$=通过所有测试的样本数。这是一个无偏估计量，避免了朴素方法（恰好采样$k$个解）的高方差。实践中生成 $n=200$ 样本，报告 pass@1、pass@10、pass@100。

import numpy as np
from scipy.special import comb

def pass_at_k(n: int, c: int, k: int) -> float:
    """Pass@k的无偏估计量"""
    if n - c < k:
        return 1.0
    return 1.0 - comb(n - c, k, exact=True) / comb(n, k, exact=True)

# 示例：200样本中15个通过
for k in [1, 10, 100]:
    print(f"pass@{k}: {pass_at_k(200, 15, k):.4f}")
# pass@1: 0.0750, pass@10: 0.5391, pass@100: 0.9999

14.5.7 Exact Match 与 F1

用于抽取式问答（如SQuAD）：

  • Exact Match (EM)：归一化后（小写化、去除冠词和标点），预测与任一金标答案完全匹配的二值指标。
$$F1 = \frac{2 \cdot |\text{pred} \cap \text{gold}|}{|\text{pred}| + |\text{gold}|}$$

将预测和金标答案视为token袋，计算token级F1。多答案设置中，报告所有金标答案上的最大F1。

14.6 Metrics for Agentic Tasks

智能体LLM在环境中操作、执行动作序列、完成多步任务。标准生成指标不够用——需要捕获任务完成度、效率和中间步骤质量。

14.6.1 Task Success Rate（任务成功率）

$$\text{TSR} = \frac{1}{|\mathcal{T}|}\sum_{\tau \in \mathcal{T}}\mathbf{1}[\text{goal}(\tau) \text{ achieved}]$$

Agent任务的首要指标。目标达成通常由确定性oracle验证（数据库状态、文件系统状态、测试执行）。

带部分分的分级成功率：

$$\text{TSR}_{\text{graded}} = \frac{1}{|\mathcal{T}|}\sum_{\tau \in \mathcal{T}}\text{score}(\tau) \in [0, 1]$$

对可部分完成的任务，用连续分数替代二值指标。

14.6.2 Trajectory Efficiency（轨迹效率）

$$\eta = \frac{L^*}{L_{\text{agent}}}$$

$L^*$ 为最短成功轨迹长度（由oracle或人工专家计算），$L_{\text{agent}}$ 为agent实际动作数。$\eta \in (0, 1]$，$\eta=1$ 表示最优。失败轨迹 $\eta=0$。互补指标：冗余率=agent动作中不出现在任何最优轨迹中的比例。

14.6.3 Tool-Use Accuracy（工具使用准确率）

$$\text{TUA} = \frac{\#\text{ correct tool calls}}{\#\text{ total tool calls}}$$

正确工具调用 = (a) 选对工具 + (b) 参数有效 + (c) 在轨迹适当位置调用。可为正确选择但参数错误的情况给部分分。

14.6.4 Multi-Step Reasoning Accuracy

$$\text{SRA} = \frac{1}{|\mathcal{T}|}\sum_{\tau \in \mathcal{T}}\frac{1}{|S_\tau|}\sum_{s \in S_\tau}\mathbf{1}[s \text{ is correct}]$$

$S_\tau$ 为轨迹 $\tau$ 中的推理步骤集。步骤正确性可由过程奖励模型（PRM）或人工标注验证。

14.6.5 SWE-bench

SWE-bench 在真实软件工程任务上评估LLM：给定GitHub issue描述和代码库，模型生成修复补丁。

  1. 模型获得issue描述和相关代码上下文
  2. 模型生成补丁（unified diff格式）
  3. 补丁应用到仓库
  4. 执行测试套件——所有测试通过则成功

主要指标：% Resolved（补丁通过所有测试的issue比例）

  • 完整基准：2,294 任务，12个流行Python仓库
  • 最佳开源Agent：~43%（SWE-bench Verified）
  • 人类表现：~87%（每任务15分钟）
  • 评估成本：~$0.25/任务（API模型）

WebArena 在沙箱化浏览器环境中评估Agent的真实Web导航任务（812任务，5个Web应用）。评估方式：

14.7 LLM-as-Judge

LLM-as-Judge 使用有能力的LLM评估其他（或同一）LLM的输出，无需人工标注即可扩展到大规模评估集，并能提供详细理由。

14.7.1 Setup 与 Prompt Templates

三种常见格式：

1. Pointwise Scoring（绝对打分）：

POINTWISE_PROMPT = """
You are an expert evaluator. Rate the following response 
on a scale of 1-10 for helpfulness, accuracy, and clarity.
[Question] {question}
[Response] {response}
Reasoning: <step-by-step analysis>
Score: <integer from 1 to 10>
"""

2. Pairwise Comparison（成对比较）：

PAIRWISE_PROMPT = """
You are an expert evaluator. Compare the two responses 
and determine which is better.
[Question] {question}
[Response A] {response_a}
[Response B] {response_b}
Output exactly one of: [[A]], [[B]], or [[C]] (tie).
Reasoning: <your analysis>
Verdict: <[[A]], [[B]], or [[C]]>
"""

3. Reference-Guided Scoring（参考引导打分）：为judge提供参考答案，相对于参考评分。对事实性任务特别有用。

14.7.2 Position Bias Mitigation

LLM judge展现位置偏差——系统性偏好出现在特定位置的回复，偏差可达10-15个百分点。缓解策略：

  1. 交换增强：每对在两种顺序下评估（A vs B 和 B vs A）。一致判断接受；不一致记为平局。
  2. 校准提示：显式指示judge"评估不应受回复呈现顺序影响"。
  3. 集成判断：使用多个judge，不同位置顺序，聚合判决。
  4. 强制思维链：要求judge在判决前产生详细理由，减少对表面位置线索的依赖。

冗长偏差（Verbosity Bias）：LLM judge 系统性偏好更长回复，即使额外内容无关或重复。缓解：指示judge惩罚不必要长度、关注信息质量而非数量；或在评判前将回复截断到固定长度。

14.7.3 Multi-Judge Panels

单个judge可能有系统偏差。来自不同模型族的judge面板提供更鲁棒的评估。$J$ 个judge的判决 $v_1, \ldots, v_J \in \{A, B, \text{tie}\}$，面板判决由多数投票决定。面板一致率：

$$\text{Agreement} = \frac{1}{\binom{J}{2}}\sum_{i < j}\mathbf{1}[v_i = v_j]$$

三judge面板中：全票一致=高置信；2-1 分裂=中置信；三方平局=低置信。

14.7.4 Agreement Metrics for LLM Judges

验证LLM judge时，将其判决与保留集上的人类标注比较。关键指标：

  • Agreement rate：judge与人类一致的项目比例
  • Cohen's κ：机会校正一致率（公式14.1）
  • Spearman's ρ：judge分数与人类分数的秩相关，适用于序数评分
  • Kendall's τ：更鲁棒的秩相关（对平局更稳健）

可靠性门槛：$\kappa > 0.6$ 且 agreement rate > 80%。

14.7.5 G-Eval Framework

G-Eval 是使用思维链提示 + token概率加权的结构化LLM评估框架：

  1. 生成评估步骤：提示LLM为评估任务生成详细rubric
  2. 概率加权打分：对每个分数值 $s \in \{1,2,3,4,5\}$，获取对数概率
  3. 归一化：映射到 $[0,1]$
$$\text{G-Eval score} = \sum_{s=1}^{5} s \cdot \frac{e^{\log P_\theta(s)}}{\sum_{s'=1}^{5} e^{\log P_\theta(s')}}$$

概率加权平均而非强制离散选择。这等价于在judge信念下计算期望分数（后验均值而非众数），捕获了judge的不确定性。G-Eval在连贯性和一致性等细微维度上与人类判断的相关性显著高于直接提示。

为什么G-Eval有效：标准提示要求judge输出单个token（如"4"），丢弃了模型不确定性。G-Eval读取所有分数token上的概率分布，有效计算judge信念下的期望分数——类比于使用后验分布的均值而非众数。

14.8 Evaluation Pitfalls

即使精心设计的评估管线也可能产生误导性结果。本节分类最常见的失败模式。

14.8.1 Benchmark Contamination（基准泄露）

当评估数据出现在模型训练集中——直接（逐字包含）或间接（改写或语义相似），导致虚高分数不反映真正泛化能力。

检测方法：

  • n-gram重叠：计算评估样本与训练语料的高n-gram重叠比例（如 ROUGE-L > 0.8）
  • 成员推断攻击：估计每个评估样本在训练集中的概率
  • 金丝雀字符串：在评估样本中嵌入唯一随机字符串，检查模型能否补全
  • 时间保留：使用模型训练截止日期之后创建的评估数据

缓解：

  • 维护从不公开的私有测试集
  • 定期用新样本刷新基准
  • 报告训练数据截止日期和去污染流程

14.8.2 Overfitting to Benchmarks

即使没有直接泄露，模型也可能通过反复评估和超参调优被隐式优化到特定基准——一种适应性过拟合：基准通过模型开发决策泄露信息。

基准生命周期：基准的效用随时间退化。MMLU曾是世界知识的挑战性测试，现在模型接近人类表现，但仍在新颖知识任务上失败。新基准应被视为临时信号源，而非永久地面真值。

14.8.3 Goodhart's Law in Evaluation

Goodhart定律："当一个度量变成目标时，它就不再是好的度量。"在LLM评估中的体现：

  • 奖励攻击：RLHF训练的模型学会利用奖励模型而非真正改善——产生冗长、自信但事实错误的回复
  • 指标博弈：针对BLEU/ROUGE微调的模型可能分数高但对人类用处小
  • Judge博弈：用LLM-as-Judge反馈训练的模型可能学会judge的偏见（如冗长偏好）

防御策略：

  1. 指标多样性：使用不同族的多个指标——博弈一个不太可能同时博弈全部
  2. 保留评估：维护不用于训练或模型选择的评估指标
  3. 人工抽检：定期抽样人工审查，独立于自动指标
  4. 对抗评估：主动探测自动指标遗漏的失败模式
  5. 外在验证：定期用外在结果验证内在指标

14.8.4 Additional Pitfalls

  • Prompt敏感性：LLM性能可因评估prompt的微小变化剧烈波动（如添加"Think step by step"或改变答案格式）。应报告确切prompt并考虑跨多个prompt变体评估。
  • 聚合伪影：跨不同难度/分数分布的任务取平均可能误导——擅长简单任务但失败于难题的模型可能与均匀表现的模型有相同平均分。
  • 人工评估的选择偏差：标注者不是终端用户的随机样本——众包平台标注者可能有不同偏好、文化背景和领域知识。
  • 评估-部署不匹配：评估prompt通常更短、更干净、更规范；模型可能在基准上表现好但在生产中的嘈杂、模糊、多轮对话中显著退化。

核心要点总结

  • 评估方案设计应先明确内在/外在、自动/人工、有参考/无参考的维度，再选指标
  • Cohen's κ和Fleiss' κ是度量标注者一致性的黄金标准，必须扣除随机一致
  • 合成数据生成（Self-Instruct、Evol-Instruct、CAI、蒸馏）可规模化替代人工标注
  • 排名任务用Bradley-Terry模型（全数据MLE）优于ELO（顺序处理），TrueSkill提供不确定度
  • 生成指标中BERTScore与人类判断相关性最高，Pass@k是代码评估的标准
  • Agent评估需要TSR + 轨迹效率 + 工具使用准确率的组合
  • LLM-as-Judge必须处理位置偏差和冗长偏差，G-Eval通过概率加权显著提升可靠性
  • Goodhart定律警告：指标一旦成为优化目标就会失效——用多指标+人工抽检+对抗评估防御

复习问答

Q1：为什么内在指标（如Perplexity）往往不能反映模型的真实有用性？

内在指标度量模型输出本身的属性（如预测下一个token的能力），不参考下游应用。困惑度更低的模型不一定更有帮助——它可能在生成流畅但不相关的文本上表现很好。内在-外在差距意味着需要用外在指标（如用户满意度、任务完成率）做最终验证。

Q2：Cohen's Kappa 相比原始一致率有什么优势？什么时候应该用加权Kappa？

原始一致率没有扣除随机一致——即使两个标注者随机标注，也有一定概率恰好一致。Cohen's κ 通过 $(p_o - p_e)/(1 - p_e)$ 扣除了随机期望一致率。当评分量表是序数的（如1-5 Likert），应使用加权kappa，因为"4 vs 5"的分歧应比"1 vs 5"的分歧惩罚更轻。

Q3：Bradley-Terry 模型相比ELO有什么优势？

BT模型是最大似然估计，同时使用所有比赛数据而非像ELO那样顺序处理。ELO的评分取决于比赛处理顺序，引入不必要的变异性。当完整对战历史可用时（如Chatbot Arena），BT模型是更优的选择。在对数空间中，BT等价于以模型为截距的逻辑回归。

Q4：Pass@k使用无偏估计量有什么好处？

朴素方法是恰好生成$k$个解并检查是否有通过的——这方差很高。无偏估计量先生成 $n=200$ 个样本，统计通过数 $c$，再用组合公式 $1 - \binom{n-c}{k}/\binom{n}{k}$ 计算。这利用了所有200个样本的信息，大幅降低方差，且结果对$k$的各种值都可用。

Q5：LLM-as-Judge的位置偏差有多严重？有哪些缓解策略？

位置偏差可达10-15个百分点。缓解：(1) 交换增强——每对两种顺序评估，不一致记为平局；(2) 校准提示——显式指示不受顺序影响；(3) 集成判断——多个judge不同顺序取聚合；(4) 强制思维链——先产生详细理由再判决。

Q6：G-Eval为什么比直接提示judge输出分数更可靠？

直接提示要求judge输出单个token（如"4"），丢弃了不确定性。G-Eval读取所有分数token的概率分布，计算概率加权期望分数——这是后验均值而非众数。均值利用了judge的完整信念分布，在连贯性和一致性等细微维度上与人类判断相关性显著更高。

Q7：如何检测基准泄露（Benchmark Contamination）？

四种方法：(1) n-gram重叠——计算评估样本与训练语料的ROUGE-L >0.8的比例；(2) 成员推断攻击——估计样本在训练集中的概率；(3) 金丝雀字符串——嵌入唯一随机串检查模型能否补全；(4) 时间保留——使用训练截止日期后创建的数据。

Q8：Goodhart定律在LLM评估中如何体现？

三种体现：(1) 奖励攻击——RLHF模型学会利用奖励模型的弱点产生冗长自信但错误的回复；(2) 指标博弈——针对BLEU/ROUGE微调的模型分数高但实用性低；(3) Judge博弈——学会LLM judge的偏见（如偏好长回复）。防御：指标多样性 + 保留评估 + 人工抽检 + 对抗评估 + 外在验证。

Q9：TrueSkill相比ELO和BT模型的独特优势是什么？

TrueSkill是贝叶斯方法，不仅估计技能均值 $\mu$，还维护不确定度 $\sigma$。这允许：(1) 识别需要更多评估数据的模型（$\sigma$ 大的模型）；(2) 区分高置信和低置信的排名差异；(3) 在少量比赛后就给出有意义的不确定度区间。ELO和BT不提供这种原生的不确定度估计。

Q10：评估-部署不匹配的风险是什么？如何缓解？

评估prompt通常更短、干净、规范，而生产中的用户查询嘈杂、模糊、多轮。模型可能在基准上表现良好但在真实场景中退化。缓解：(1) 使用真实用户query构建评估集；(2) 包含多轮、模糊、噪声prompt；(3) 监控生产中的外在指标检测退化；(4) 定期用A/B测试验证基准分数与真实效果的相关性。
