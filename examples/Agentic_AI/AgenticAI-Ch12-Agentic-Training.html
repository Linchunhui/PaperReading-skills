12.1 动机：从聊天机器人到自主智能体

现代 LLM 正从单轮对话助手演变为自主 Agent——能与外部工具、API、数据库和环境进行多步交互。这种范式转变带来了全新的 RL 挑战。

为什么标准 RLHF 不够用？

挑战维度传统 RLHFAgentic RL 需求
交互步数单轮生成10–100+ 步工具调用链
反馈来源人类偏好打分真实环境执行结果（测试通过、编译成功、网页加载）
动作空间纯文本 token结构化输出（JSON 工具调用、API payload、代码块）
奖励信号即时密集长时间跨度、稀疏终端奖励
错误恢复不需要轨迹中途自我纠正、从工具报错中恢复
状态复杂度固定格式可变长上下文（1K–128K tokens/状态）

传统 RLHF 只管"一问一答写得好不好"，而 Agent 必须在复杂环境里"一步步做事做到底"——这就像从考试写作文升级到真正去完成一个项目。Agent 需要规划多步骤的执行路径、在中途处理不确定性、在失败时回溯修正。

12.2 轨迹缓冲区（Trajectory Buffer）

在经典 RL 中，经验回放缓冲区存储低维数值元组 $(s, a, r, s')$。对于 LLM Agent，这个结构升级为高维文本序列：

$$\tau = (e_0, e_1, \ldots, e_T), \quad e_t = (S_t, A_t, R_t, S_{t+1})$$
解释：一条完整轨迹 $\tau$ 由 $T$ 步经验组成。每步经验 $e_t$ 包含：
• $S_t$：完整上下文状态 = 系统提示 + 用户目标 + 对话历史 + 环境变量（HTML源码、目录结构等）
• $A_t$：Agent 输出 = 思维链推理文本 + 结构化工具调用 JSON
• $R_t$：来自外部执行环境的评估信号（单测通过数、编译结果、API 响应码）
• $S_{t+1}$：更新后的上下文（追加了工具输出文本或错误日志）

动作的数学定义（Agent 每步的输出结构）：

$$A_t = \{\underbrace{\text{text}_{\text{reasoning}}}_{\text{Chain-of-Thought}},\; \underbrace{\text{json}_{\text{tool\_call}}}_{\text{结构化工具调用}}\}$$
每个动作由两部分组成：一段内部推理文本（帮助模型在行动前规划），加上一个结构化的工具调用（JSON格式，指定调用哪个工具、传什么参数）。

轨迹缓冲区 $B$ 的作用：存储历史轨迹，根据不同操作范式用于：

  • SFT 微调（成功轨迹作为正样本）
  • GRPO/DPO 训练（对比好坏轨迹）
  • RAG 检索（向量化后作为 few-shot 示例）
  • 自我修正（失败轨迹用于生成反思）
具体例子：代码调试轨迹
Step 1: read_file("main.py") → 观测到代码内容 → $R_1 = 0$（中间步骤）
Step 2: think("第42行存在off-by-one错误") → $R_2 = 0$
Step 3: edit_file("main.py", line=42, ...) → $R_3 = 0$
Step 4: run_tests() → 6/6 通过 → $R_4 = +1.0$ （稀疏终端奖励）

12.3 三大操作范式

根据轨迹缓冲区的使用方式，Agentic Training 分为三大互补的操作范式：

A. 自我修正与思维改进（Self-Correction）

核心思想：Agent 失败后生成文本批评，修正后成功的轨迹用于更新模型权重。

$$\text{Critique} \leftarrow \text{LLM}_{\text{reflect}}(S_{\text{failed}}, A_{\text{failed}}, R{=}0, \text{error\_msg})$$
让模型对自己的失败轨迹进行"反思写作"，生成自然语言形式的错误诊断和改进建议。修正后成功的轨迹可用 SFT 或 GRPO 更新权重。

工作流程：

  1. Agent 执行任务 → 失败（$R = 0$）
  2. 将完整失败轨迹传给 Reflection LLM → 生成文本批评
  3. Agent 带着批评信息重试 → 成功（$R = 1$）
  4. 成功轨迹（含批评修正过程）加入 $D_{\text{pass}}$ 用于训练

代表方法：STaR（权重更新）、Reflexion（纯上下文，无梯度）

B. 离策略探索（Off-Policy Exploration）

核心思想：Agent 进行大量自主探索，缓冲区充当过滤器——只保留成功且高效的轨迹用于训练。

$$D_{\text{train}} = \{\tau \in B : R(\tau) \geq \theta_{\min} \;\land\; \text{len}(\tau) \leq L_{\max} \;\land\; \text{diversity}(\tau, D_{\text{train}}) > \delta\}$$
训练数据 = 缓冲区中满足以下条件的轨迹：① 奖励超过阈值（成功）；② 步数不超过上限（高效）；③ 与已有数据足够不同（多样性）。多样性条件防止模式坍塌。

代表方法：ReAct + GRPO 过滤、大规模探索+筛选

C. 非参数上下文学习（RAG over Experiences）

核心思想：不修改模型权重，将轨迹缓冲区当向量数据库，检索相似历史成功经验作为 few-shot 示例。

$$E_{\text{retrieved}} = \underset{e \in B, R(e)>0}{\arg\text{top-}k} \;\text{sim}\bigl(\text{Embed}(G_{\text{new}}),\; \text{Embed}(e.\text{goal})\bigr)$$
给定新任务 $G_{\text{new}}$，从缓冲区中检索目标最相似的 top-k 条成功经验，将它们注入 prompt 作为 few-shot 示例。零训练、即时适应。

代表方法：Voyager 技能库（可复用代码函数的向量检索）

12.5.1 STaR：自学推理器（Self-Taught Reasoner）

动机：如果模型偶尔能正确解题，它就能从自己的成功中学习，无需人工标注推理过程。核心洞察是利用"自举"（bootstrapping）——用模型当前能力生成训练数据来提升自身。

算法流程（迭代 k=1,2,...）

  1. 生成（Generate）：对每个问题 $x_i$，采样推理轨迹 $z_i \sim \pi_{\theta_k}(\cdot|x_i)$ 得到答案 $\hat{y}_i$
  2. 过滤（Filter）：只保留正确轨迹 $D_{\text{pass}} = \{(x_i, z_i, y_i^*) : \hat{y}_i = y_i^*\}$
  3. 合理化（Rationalization）——关键创新：对失败问题，生成以正确答案为条件的轨迹： $$z_i^{\text{rat}} \sim \pi_{\theta_k}(\cdot \mid x_i, y_i^*)$$ 即让模型学会"已知答案，反推推理过程"
  4. 微调（Fine-tune）：SFT 更新参数 $\theta_{k+1}$
  5. 迭代（Iterate）：用改进后的模型重复步骤1
$$\theta_{k+1} = \arg\min_\theta \;-\!\sum_{(x,z,y) \in D_k^{\text{pass}} \cup D_k^{\text{rat}}} \log \pi_\theta(z, y \mid x)$$
每轮迭代的训练目标：在成功轨迹和合理化轨迹的并集上最大化对数似然。初始正确率 30% → 经过 3–5 轮迭代 → 正确率可达 70–90%。

适用场景：有明确正确答案的任务（数学推理、逻辑题、代码生成）；模型已有一定基础能力（至少 >10% 初始正确率）。

局限：① 需要 ground-truth 答案做过滤；② 对开放性任务（写作、创意）不直接适用；③ 合理化可能引入"歪打正着"的虚假推理。

变体：Quiet-STaR（隐式思维 token，不显式生成推理文本）；V-STaR（增加验证器过滤歪打正着的轨迹）；ReST（简化版，去掉合理化步骤）。

12.5.2 Reflexion：文字强化学习

动机：许多实际场景中模型权重不可修改（如 API 调用 GPT-4），但仍需让 Agent 从失败中学习。Reflexion 实现了"不更新权重的 RL"——通过自然语言自我批评存入情景记忆来改进行为。

完整架构（5个组件）

  1. Actor $\pi$：执行动作的 LLM Agent
  2. Evaluator：二元信号（任务成功/失败）或标量启发式评分
  3. Self-Reflection Generator：对失败轨迹生成反思文本
$$r_{\text{text}} = \text{LLM}_{\text{reflect}}(\tau_{\text{fail}},\; \text{feedback},\; \text{task\_description})$$
  1. Episodic Memory $M$：滑动窗口存储最近反思 $M = [r_1, r_2, \ldots, r_m]$（通常 $m \leq 3$）
  2. Retry Loop：下次尝试时将记忆注入 prompt
$$a_{t+1} \sim \pi(\cdot \mid \text{task},\; M,\; \text{current\_state})$$

适用场景：冻结 API 模型（GPT-4, Claude）；需要快速迭代的原型场景；可解释性要求高（人类可读反思）。

局限：① 受限于上下文窗口（记忆 $m$ 很小）；② 无法泛化到未见任务（经验不写入权重）；③ 依赖模型已有的错误识别能力——基座模型太弱时连有用的反思都写不出来；④ 每次重试都需要完整 rollout，累积成本高。

实验结果：HumanEval pass@1 从 80% 提升到 91%（3次反思迭代）；AlfWorld 成功率从 75% 提升到 97%（6次反思）。

12.5.3 ReAct：推理 + 行动交替

动机：传统 Agent 要么只思考不行动（纯推理），要么只行动不思考（直接工具调用）。ReAct 统一了两者——在单个生成流中交替进行显式推理和环境动作，建立了工具使用 Agent 的主导范式。

轨迹形式定义

$$\tau = (t_1, a_1, o_1,\; t_2, a_2, o_2,\; \ldots,\; t_n, a_n, o_n)$$
  • $t_i$：Thought——内部推理，不执行，创造"内心独白"帮助规划
  • $a_i$：Action——工具调用，在环境中执行
  • $o_i$：Observation——环境响应，追加到上下文供下步使用

为什么有效：Thought 帮助模型在行动前规划，减少冲动的工具调用；Observation 提供真实反馈，纠正推理偏差。RL 训练目标（当与 GRPO 结合时）：

$$r(\tau) = r_{\text{task}} - \lambda_{\text{format}} \cdot \sum_{i}\mathbb{1}[\text{format\_violation}_i] - \lambda_{\text{length}} \cdot \text{num\_steps}$$
奖励 = 任务奖励 − 格式违规惩罚 − 步数效率惩罚。只有 Action 步骤接收直接奖励信号，Thought 通过策略梯度被隐式优化。典型设置：$\lambda_{\text{format}} = 0.1$，$\lambda_{\text{length}} = 0.02$。

适用场景：几乎所有工具使用 Agent；知识密集型问答（结合搜索工具）；交互式任务（网页导航、代码编写）。

局限：① 贪心解码，单一路径，无回溯机制；② 容易陷入循环（反复调用相同工具）；③ 推理质量受限于基座模型能力。

12.5.4 LATS：语言智能体树搜索

动机：ReAct 是贪心的——每步只选一个动作，无法回溯。LATS 将蒙特卡洛树搜索（MCTS）应用到 LLM Agent 的动作选择上，用推理计算换取显著更好的轨迹质量。

算法步骤（每个决策点）

  1. Selection：从根节点（当前状态）用 UCB1 公式选择路径向下遍历树
$$\text{UCB}(s, a) = \bar{Q}(s, a) + c\sqrt{\frac{\ln N(s)}{N(s, a)}}$$
  1. Expansion：在叶节点用 LLM 采样 $k$ 个候选动作（$k$=3–5）
  2. Simulation (Rollout)：对每个候选执行快速 rollout（贪心解码到 episode 结束）
  3. Backpropagation：将终端奖励沿祖先节点反向传播更新 $\bar{Q}$ 和 $N$
  4. Repeat：运行 50–200 次 MCTS 迭代
  5. Action Selection：选择根节点访问次数最多的子节点作为最终动作
UCB 公式解释：$\bar{Q}(s,a)$ 是动作 $a$ 在状态 $s$ 的平均回报（exploit），$c\sqrt{\ln N(s)/N(s,a)}$ 鼓励探索少被访问的动作（explore）。$c$ 通常设为 $\sqrt{2}$ 或任务调优。
性能提升：
• WebShop 成功率：ReAct 40% → LATS 75%（+35%）
• HumanEval pass@1：68% → 94%（+26%）
• 代价：10–50× 推理计算量（每个动作需要多次 LLM 采样）

适用场景：高价值任务（愿意花计算换质量）；作为训练数据生成器（为 DPO/SFT 提供高质量轨迹）；离线评测/竞赛。

局限：① 推理成本极高（10–50× 基线）；② 实时交互场景延迟不可接受；③ 需要环境支持"回退"（或无状态可重放）。

12.5.5 AgentQ：轨迹级 DPO

动机：将 DPO（Direct Preference Optimization）从单轮对话扩展到多步 Agent 轨迹。核心创新：在轨迹级别构造偏好对，让模型学会"哪种解题路径更好"。

Pipeline（在线迭代）

  1. 采样：对每个任务执行 $N$ 条轨迹（用 MCTS 引导探索，增加多样性）
  2. 评分：用执行结果对每条轨迹打分 $r(\tau_i)$
  3. 构造偏好对：配对 $(\tau_w, \tau_l)$，其中 $r(\tau_w) > r(\tau_l)$
  4. DPO 更新：最大化赢者概率相对于输者的优势
  5. 迭代：更新后的策略生成更好的轨迹 → 更好的训练数据 → 良性循环
$$\mathcal{L}_{\text{AgentQ}}(\theta) = -\mathbb{E}_{(\tau_w, \tau_l)}\left[\log\sigma\!\left(\beta\left[\log\frac{\pi_\theta(\tau_w)}{\pi_{\text{ref}}(\tau_w)} - \log\frac{\pi_\theta(\tau_l)}{\pi_{\text{ref}}(\tau_l)}\right]\right)\right]$$
轨迹级 DPO 损失函数：让策略 $\pi_\theta$ 相对参考策略 $\pi_{\text{ref}}$ 更倾向于生成赢者轨迹 $\tau_w$ 而非输者轨迹 $\tau_l$。$\beta$ 控制偏离参考策略的程度。
关键区别：这里的 $\pi_\theta(\tau)$ 是对整条轨迹的概率，而非单个回复。

实验结果：WebShop 上经过 3 轮迭代 DPO：成功率从 50% → 82%（+32%）。

适用场景：有二元成功/失败判定的任务；计算资源充足（需 MCTS 生成多样轨迹）；需要精确的偏好学习。

局限：① 轨迹级概率计算复杂度高（整条 20 步轨迹的联合概率）；② 偏好对构造的质量直接决定性能——垃圾轨迹配对无信息量。

12.5.6 Voyager：终身学习技能库

动机：大多数 Agent 方法都是"一次性"的——每个任务从零开始。Voyager 引入组合式技能积累——Agent 构建一个不断增长的可复用代码函数库作为高级动作，实现跨任务知识迁移。

三大组件

  1. 自动课程（Automatic Curriculum）：LLM 根据当前技能清单 + 环境状态提出逐步更难的任务
  2. 技能生成与验证：
    • 为每个任务写一个可执行代码函数（Python/JavaScript）
    • 在环境中执行验证——成功则加入技能库，失败则迭代修改（最多 3 次）
  3. 技能库（Skill Library = 向量数据库）：
    • 每个技能存储：函数代码 + 函数签名 + 描述嵌入 + 依赖关系 + 使用示例
    • 新任务时检索 top-k 相关技能并组合
$$\text{solution} = \text{LLM}\bigl(\text{task},\; \underbrace{\text{retrieve}(\text{SkillLib}, \text{Embed}(\text{task}), k{=}5)}_{\text{检索最相关的5个已有技能}}\bigr)$$
新任务的解法 = LLM 基于任务描述 + 检索到的 5 个最相关已有技能来组合生成新方案。技能复用让 Agent 能解决越来越复杂的任务。

适用场景：开放世界环境（Minecraft 等游戏）；长期运行的 Agent（持续积累经验）；任务之间有明显共性的领域。

局限：① 技能库质量依赖验证环境的覆盖度；② 技能组合的搜索空间随库大小指数增长；③ 不修改模型权重，核心推理能力不提升。

12.5.7 RLEF：执行反馈强化学习

动机：人工标注奖励昂贵且有噪声，LLM-as-judge 可被 hack。RLEF 使用最简单有效的范式——确定性执行结果作为奖励信号。

$$r(\tau) = \frac{\#\text{tests\_passed}}{\#\text{total\_tests}} \in [0, 1]$$
奖励 = 通过测试数 / 总测试数。部分通过（如 $r=0.6$）比纯二元更信息丰富。

为什么执行反馈是 RL 的理想奖励？

  • 零噪声：确定性结果，无人工标注的随机性
  • 无限规模：可程序化生成无限任务+测试用例
  • 不可 hack：测试不会被"欺骗"（vs. LLM Judge 可被讨好式文本骗过）
  • 密集信号：部分通过提供梯度方向（vs. 纯二元 0/1）
  • 自动化：无需人在回路，可 24/7 训练

适用场景：代码生成（单元测试）；数学推理（答案验证）；网页自动化（DOM 状态验证）；任何有确定性验证标准的任务。

局限：① 需要高质量测试用例（覆盖边界情况）；② 不适用于主观任务（写作、翻译质量）；③ 可能过拟合测试用例（学到通过测试的 trick 而非真正理解）。

12.6.8 生产部署经验教训

  1. SFT 质量是地板：RL 只能在 SFT 提供的能力基础上改进。如果 SFT 模型连有效 API 调用语法都不会，RL 也无法发现正确策略。
  2. Reward Hacking 不可避免：Agent 会找捷径（创建空文件假装完成、回复"Done"但没做事）→ 需要多层验证（存在性 + 内容 + 语义正确性）。
  3. API 限速必须模拟：生产环境有 429 限流（每分钟 60 请求），训练时不模拟会导致部署后大量失败。
  4. 上下文窗口是瓶颈：20 步轨迹 + 丰富 API 响应轻松超 80K tokens → 需要观测摘要化策略（只保留关键信息）。
  5. 用户意图常常模糊：训练 Agent 适时提问澄清（奖励适当澄清 +0.05，惩罚过度提问 −0.03）。
  6. 从简单开始：先 Outlook 单应用 → 再 Excel → 再跨应用组合，逐步扩大能力边界。

12.8 SOTA RL for LLM Agents

12.8.1 GRPO for Agents（当前标准方法）

由 DeepSeek-R1 推广的 GRPO 正在成为 Agentic Training 的事实标准。核心思想：对同一个任务采样一组轨迹，用组内相对排名代替 Critic 网络估计优势。

$$\hat{A}_i = \frac{r(\tau_i) - \frac{1}{N}\sum_{j=1}^N r(\tau_j)}{\text{std}\bigl(r(\tau_1), \ldots, r(\tau_N)\bigr)}$$
优势值 = (该轨迹奖励 − 组内平均奖励) / 组内标准差。无需单独训练 Critic 网络，直接用组内统计量归一化。当 $N$ 足够大时（$N \geq 8$），统计量稳定。

GRPO 策略梯度目标：

$$\mathcal{L}_{\text{GRPO}}(\theta) = \frac{1}{N}\sum_{i=1}^N \left[\min\!\left(\rho_i \hat{A}_i,\;\text{clip}(\rho_i, 1{-}\epsilon, 1{+}\epsilon)\hat{A}_i\right)\right] - \beta\, D_{\text{KL}}\!\left(\pi_\theta \,\|\, \pi_{\text{ref}}\right)$$
其中 $\rho_i = \pi_\theta(\tau_i|q) / \pi_{\theta_{\text{old}}}(\tau_i|q)$ 是重要性采样比。clip 操作限制策略更新幅度（$\epsilon=0.1$），KL 散度项（$\beta=0.04$）防止策略过度偏离参考模型。
为什么 GRPO 主导 Agentic Training？
• 省 50% GPU 内存：无需 Critic 网络——Agent 轨迹已消耗 32K–128K tokens，再加 Critic 会爆内存
• 天然匹配：Agent 任务常有二元/可验证奖励（测试通过/失败），适合组内归一化
• 自然探索：每任务采样 N 条多样轨迹，自动探索不同工具使用策略
• 实现简单：无需额外 value network 的训练和同步，工程复杂度低

12.8.2 PPO for Interactive Agents

PPO 在高度随机环境（工具输出不可预测、网络延迟变化大）中仍有独特价值——Critic 提供逐步优势信号。

$$\hat{A}_t^{\text{GAE}} = \sum_{l=0}^{T-t-1} (\gamma\lambda)^l \delta_{t+l}, \quad \delta_t = r_t + \gamma V(s_{t+1}) - V(s_t)$$
GAE（Generalized Advantage Estimation）利用 Critic 网络 $V(s)$ 计算每一步的优势，$\lambda$ 控制 bias-variance 权衡。
优势：每个 action 都有独立的 advantage 信号，比 GRPO 的 episode-level 信号更精细。
代价：需要训练一个 Value Head（2× 内存），且 Value 估计对长轨迹容易不准。

PPO 仍优于 GRPO 的场景：

  • 环境高度随机（同一动作可能产生不同结果）
  • 需要精细逐步 credit assignment（如 GUI 导航中每个点击都重要）
  • 短轨迹（<10步）——Critic 准确度高，GRPO 的 N 难以取够大

12.8.3 细粒度 Turn-Level Credit Assignment

核心问题：如果 Agent 执行 20 个动作最终失败，终端奖励 $R=0$ 会等比例惩罚所有动作——这极不公平！可能前 15 步都完全正确，只有第 16 步出了问题。

解法 1：RLVR（Reinforcement Learning from Verifiable Rewards）

在确定性中间检查点给予奖励信号：

  • Bash 命令编译成功: +0.1
  • 浏览器成功定位目标 DOM 元素: +0.2
  • SQL 查询返回非空结果: +0.1
  • API 调用返回有效数据: +0.05
  • 最终测试全部通过: +1.0

效果：比纯稀疏终端奖励加速学习 3–5×。

解法 2：Multi-Turn Trajectory Slicing

思路：找到轨迹中第一个"出错点"，只对该步施加惩罚。

  1. 回放成功前缀：找到步骤 1–k 是正确的
  2. 识别首个发散点：步骤 $k+1$ 是导致失败的关键错误
  3. 差异化奖励分配：
    • 步骤 1–k（正确前缀）：中性或正奖励
    • 步骤 k+1（出错点）：强负奖励
    • 步骤 k+2 及之后：忽略（已被错误污染）

→ 实现外科手术式策略更新：只修正出错的行为，不退化已正确的能力。

12.8.4 方法全景对比

方法奖励粒度内存开销核心优势最佳适用
GRPO序列/终端级低（无 Critic）省内存、实现简单、自然探索长轨迹 + 可验证奖励
PPO逐步（GAE）高（需 Critic）精细 credit assignment随机环境 + 短轨迹
Iterative STaR稀疏二元最低（仅 SFT）简单可扩展、避免 RL 不稳定有 ground-truth 的推理任务
DPO (AgentQ)序列级偏好中等无需显式奖励设计难以定义标量奖励的任务
LATS反向传播高（树展开）每任务最佳质量高价值任务、数据生成

关键要点总结

  1. Agent 训练的核心难题是稀疏奖励 + 长时间跨度 + 结构化动作空间，传统 RLHF 完全不够用。
  2. 三大范式互补：自我修正（快速迭代、无需梯度）、离策略探索（大规模数据过滤）、非参数 RAG（零训练即时适应）。
  3. GRPO 正在成为 Agentic Training 的事实标准——省 50% 内存、天然适配二元可验证奖励、自带多样探索。
  4. RLEF 确立了最简有效范式：确定性执行结果（零噪声、无限规模、不可 hack）作为奖励信号。
  5. Reward Hacking 不可避免——必须多层正交验证（格式 + 内容 + 执行 + 语义正确性）。
  6. Credit Assignment 是关键瓶颈：RLVR（中间检查点）比纯稀疏快 3–5×；Trajectory Slicing 实现精确归因。
  7. SFT 质量是地板——RL 只能在好的 SFT 基础上改进，无法从零创造全新能力。
  8. 课程学习至关重要：从简单单步任务开始，成功率 >70% 再升级难度，防止训练崩溃。
  9. 领域趋势：更多推理计算（LATS/搜索/重试）往往胜过更多训练计算（Inference-Time Scaling Law）。
  10. 安全设计是一等公民：硬约束（环境级即时拒绝）+ 软约束（奖励惩罚）+ 确认协议三层防护。

Q&A

Q1: 为什么 GRPO 比 PPO 更适合训练 Agent？

三个关键原因：

  1. 内存效率：GRPO 不需要 Critic 网络，节省 50% GPU 内存。Agent 轨迹本身已消耗 32K–128K tokens，再加一个同等规模的 Critic 会爆内存。
  2. 奖励特性匹配：Agent 任务通常有清晰的二元可验证奖励（测试通过/代码编译/目标达成），非常适合组内相对归一化——不需要学一个 value function 来估计"进展"。
  3. 自然探索：每个任务采样 N 条轨迹（如 N=8），天然探索不同的工具使用策略和解题路径，无需额外的 entropy bonus 或 ε-greedy。

PPO 仍有价值的场景：环境高度随机、需要精细逐步 credit assignment、短轨迹（Critic 估值准确度高）。

Q2: Reflexion 不更新权重怎么能算 RL？

Reflexion 是"文字 RL"（Verbal RL）——通过自然语言自我批评存入情景记忆来改变未来行为。类比人类的"经验总结"：失败后写下"下次注意XXX"，下次就会做得更好。

从 RL 理论看，情景记忆是"策略条件"的一部分——虽然 $\theta$ 不变，但有效策略 $\pi(\cdot|\text{task}, M)$ 因为 $M$（记忆内容）的变化而改变了。这等价于在一个扩展的状态空间中进行优化。

局限：受限于上下文窗口（$m \leq 3$ 条反思），无法积累无限经验；且依赖模型已有的自我诊断能力。

Q3: STaR 的"合理化"(Rationalization) 为什么是关键创新？

解决冷启动问题：模型初始正确率只有 30%，纯靠成功轨迹学习数据量太少且偏向简单题。

合理化的做法：给定正确答案 $y^*$，让模型"事后诸葛亮"生成推理过程 $z^{\text{rat}} \sim \pi(\cdot|x, y^*)$。好处：

  1. 大幅扩充训练数据（70% 的失败题也能产生样本）
  2. 教会模型"答案→推理"的反向映射
  3. 生成的推理仍是模型自己的语言风格，比人写的更容易内化

风险：可能产生"歪打正着"的虚假推理 → V-STaR 用验证器过滤。

Q4: 如何系统性防止 Reward Hacking？

常见 hack 手段和对策：

  • 创建空文件假装完成 → 多层验证（文件存在 + 内容非空 + 语义正确）
  • 回复"Done"但没做事 → 环境级验证函数检查真实状态变化
  • 伪造实验结果 → 验证执行日志 vs 报告数字的一致性
  • 写长文本刷分 → Efficiency reward + 长度惩罚
  • 学会讨好 LLM Judge → 轮换 judge 模型 + 定期人工抽查

根本原则：任何单一奖励都会被 hack，必须组合多个正交信号，且至少一个基于确定性执行结果。

Q5: LATS 的高计算开销值得吗？

值得的场景：单次任务价值高（生产部署/竞赛/难题），或作为训练数据生成器（AgentQ 用 LATS 生成高质量偏好对给 DPO）。

不值得：大量简单任务批处理、实时交互（延迟敏感）。

实践中的黄金方案：LATS 生成高质量数据 → 蒸馏到快速单 pass 模型。把推理时间的计算投资转化为持久的模型能力。

Q7: 什么是 Turn-Level Credit Assignment？为什么关键？

问题：20 步轨迹最终失败，终端 $R=0$ 等比例惩罚所有步骤——但可能只有第 16 步出错。

后果：正确步骤被连带惩罚 → 策略退化到保守行为（"什么都不敢做"）。

解法：① RLVR 在中间检查点给奖励（加速 3–5×）；② Trajectory Slicing 找首个出错点只惩罚它（外科手术式更新）。两者可结合使用。

Q8: 从零训练 Agent 的最小可行方案？
  1. 选有确定性奖励的任务（代码：测试通过/失败）
  2. SFT 阶段：收集 200+ 成功轨迹做 SFT（教会工具调用语法）
  3. GRPO 训练：RLEF 奖励 + N=4–8 组内归一化
  4. 简单课程：easy → medium → hard（成功率 >70% 升级）
  5. ReAct 格式：Thought + Action + Observation 统一格式

不需要：Critic 网络、人工偏好标注、复杂 reward model、MCTS 搜索。核心循环就是：采样轨迹 → 执行得奖励 → GRPO 更新 → 重复。
