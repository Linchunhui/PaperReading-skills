第6章 阅读笔记：DPO — Direct Preference Optimization

Direct Preference Optimization: Your Language Model is Secretly a Reward Model

来源：The Hitchhiker's Guide to Agentic AI by H. Roitman · 第145–157页 · 笔记生成：2026-06-25

核心思想：DPO 将 RLHF 的"训练奖励模型 → 强化学习优化策略"两阶段流程，压缩为单阶段的监督学习问题。关键洞见是：在 KL 约束奖励最大化目标下，最优策略有闭式解——将其代入 Bradley-Terry 偏好模型后，可以推导出一个直接作用于偏好数据对的损失函数，完全绕过显式奖励模型和 RL 循环。

6.1 Motivation（动机）

RLHF/PPO 的四大痛点

  1. 显存开销巨大：需要同时加载策略模型（Policy $\pi_\theta$）、参考模型（Reference $\pi_{\text{ref}}$）、奖励模型（Reward Model $r_\phi$）、价值头（Value Head $V_\psi$）共 4 个模型。对 7B 参数模型来说，FP16 下仅模型参数就需要 $4 \times 14\text{GB} = 56\text{GB}$，加上优化器状态和激活值，单节点 80GB GPU 无法训练。
  2. 工程复杂：需要完整的 RL 基础设施——rollout 采样、GAE 优势估计、PPO clip 目标、KL 惩罚系数自适应等，代码量是标准 SFT 的 3-5 倍。
  3. 训练不稳定：Reward Hacking（模型找到奖励模型的 OOD 漏洞获得虚高奖励）、KL 爆炸（策略偏离参考太远后无法回收）、PPO 特有的 value loss 抖动等问题频发。
  4. 超参敏感：PPO 的 clip 范围 $\epsilon$、GAE $\lambda$、KL 惩罚系数 $\beta_{\text{KL}}$、mini-batch 大小、rollout 长度等超参之间相互耦合，调参成本极高。

DPO 的解题思路

既然 RLHF 的目标是"让策略在 KL 约束下最大化奖励"，而这个约束优化问题有解析解，那为什么不直接用解析解来构造损失函数，跳过 RL？

DPO 的关键洞见：

  • 最优策略 $\pi^*$ 与奖励函数 $r$ 之间存在一一对应的映射关系
  • 将这个映射代入 Bradley-Terry 偏好模型后，配分函数 $Z(x)$ 在 chosen/rejected 做差时被完美消去
  • 最终得到的损失函数只需要策略模型和参考模型的 log 概率，无需显式奖励模型

结果：从 4 个模型简化为 2 个模型（策略 + 参考），从复杂 RL 循环简化为标准监督训练。

6.2 Mathematical Derivation（数学推导）

以下是从 RLHF 目标出发，经由最优策略闭式解、奖励重参数化、Bradley-Terry 消元，最终得到 DPO 损失函数的完整推导。

Step 1：RLHF 目标函数

$$\max_{\pi_\theta} \; \mathbb{E}_{x \sim \mathcal{D},\, y \sim \pi_\theta(\cdot|x)}\big[r(x,y)\big] - \beta \, D_{\mathrm{KL}}\big[\pi_\theta(\cdot|x) \,\|\, \pi_{\mathrm{ref}}(\cdot|x)\big]$$
含义：在给定 prompt $x$ 下，让策略 $\pi_\theta$ 生成的回复获得尽可能高的奖励 $r(x,y)$，同时通过 KL 散度惩罚项确保策略不会偏离参考模型 $\pi_{\text{ref}}$ 太远。超参数 $\beta > 0$ 控制惩罚强度——$\beta$ 越大，策略被"拴"在参考模型附近越紧。

Step 2：展开 KL 散度

将 KL 散度展开为对数概率比的期望：

$$D_{\mathrm{KL}}\big[\pi_\theta \| \pi_{\mathrm{ref}}\big] = \mathbb{E}_{y \sim \pi_\theta}\bigg[\log\frac{\pi_\theta(y|x)}{\pi_{\mathrm{ref}}(y|x)}\bigg]$$

将其代入 Step 1，目标变为：

$$\max_{\pi_\theta} \; \mathbb{E}_{y \sim \pi_\theta}\bigg[r(x,y) - \beta\log\frac{\pi_\theta(y|x)}{\pi_{\mathrm{ref}}(y|x)}\bigg]$$

Step 3：推导最优策略（闭式解）

这是一个函数空间上的变分问题。对 $\pi_\theta(y|x)$ 取变分导数并令其为零，同时施加归一化约束 $\sum_y \pi(y|x) = 1$，可以得到最优策略的解析形式：

$$\pi^*(y|x) = \frac{1}{Z(x)} \cdot \pi_{\mathrm{ref}}(y|x) \cdot \exp\!\left(\frac{r(x,y)}{\beta}\right)$$
其中 $Z(x) = \sum_y \pi_{\mathrm{ref}}(y|x) \exp\!\left(\frac{r(x,y)}{\beta}\right)$ 是配分函数（partition function），确保概率归一化。
直觉：最优策略就是参考模型按照奖励值做指数"加权倾斜"——奖励越高的回复，概率被提升得越多。

Step 4：用策略重参数化奖励（关键！）

将 Step 3 的公式两边取对数并反解出 $r(x,y)$：

$$r(x,y) = \beta\log\frac{\pi^*(y|x)}{\pi_{\mathrm{ref}}(y|x)} + \beta\log Z(x)$$
核心洞见：奖励函数可以用"最优策略相对于参考模型的对数概率比"来表达。$\beta\log Z(x)$ 是一个只依赖于 prompt $x$ 的常数，与具体回复 $y$ 无关。

Step 5：代入 Bradley-Terry 偏好模型

Bradley-Terry 模型描述了人类偏好的概率：

$$P(y_w \succ y_l \,|\, x) = \sigma\big(r(x,y_w) - r(x,y_l)\big)$$
其中 $\sigma(z) = 1/(1+e^{-z})$ 是 sigmoid 函数。人类选择 $y_w$ 而非 $y_l$ 的概率，由两者奖励差的 sigmoid 决定。

将 Step 4 的奖励表达式代入：

$$r(x,y_w) - r(x,y_l) = \beta\log\frac{\pi^*(y_w|x)}{\pi_{\mathrm{ref}}(y_w|x)} + \cancel{\beta\log Z(x)} - \beta\log\frac{\pi^*(y_l|x)}{\pi_{\mathrm{ref}}(y_l|x)} - \cancel{\beta\log Z(x)}$$
关键消元：$\beta\log Z(x)$ 在做差时完美抵消！这正是 DPO 能绕过难以计算的配分函数的数学巧妙之处。DPO 不需要知道 $Z(x)$，只需要两个回复之间的相对奖励差。

Step 6：得到 DPO 损失函数

用可训练的 $\pi_\theta$ 替代最优 $\pi^*$，构造最大似然目标：

$$\mathcal{L}_{\text{DPO}}(\pi_\theta;\pi_{\text{ref}}) = -\mathbb{E}_{(x,y_w,y_l)\sim\mathcal{D}}\left[\log\sigma\left(\beta\log\frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \beta\log\frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)}\right)\right]$$
大白话：DPO 损失要求模型对 chosen 回复 $y_w$ 的"隐式奖励"（相对参考模型的提升幅度）严格大于对 rejected 回复 $y_l$ 的。margin 越大，sigmoid 值越接近 1，$\log\sigma$ 越接近 0，loss 越小。

隐式奖励（Implicit Reward）

定义隐式奖励函数：

$$\hat{r}_\theta(x,y) = \beta\log\frac{\pi_\theta(y|x)}{\pi_{\text{ref}}(y|x)}$$
这是模型学到的"内在奖励信号"——衡量当前策略相比参考模型"更看好"某回复多少。策略提升了某回复的概率 → 隐式奖励为正；降低了 → 为负。DPO 损失等价于让 $\hat{r}_\theta(x,y_w) > \hat{r}_\theta(x,y_l)$。
推导总结路径：RLHF 目标 → KL 展开 → 最优策略闭式解 → 奖励重参数化 → 代入 Bradley-Terry → $Z(x)$ 消去 → DPO Loss

6.3 Gradient Analysis（梯度分析）

对 DPO 损失求梯度，可以深入理解其训练动态：

$$\nabla_\theta \mathcal{L}_{\text{DPO}} = -\beta \cdot \underbrace{\sigma\big(-\hat{r}_\theta(x,y_w) + \hat{r}_\theta(x,y_l)\big)}_{\text{自适应权重 } w} \cdot \Big[\underbrace{\nabla_\theta\log\pi_\theta(y_w|x)}_{\text{推高 chosen}} - \underbrace{\nabla_\theta\log\pi_\theta(y_l|x)}_{\text{压低 rejected}}\Big]$$

梯度三要素解析

  1. 方向：$\nabla_\theta\log\pi_\theta(y_w|x) - \nabla_\theta\log\pi_\theta(y_l|x)$——同时做两件事：增大 chosen 概率、减小 rejected 概率。这是一个"对比方向"。
  2. 自适应权重 $w = \sigma(-\hat{r}_w + \hat{r}_l)$：
    • 当模型目前更偏好 rejected（$\hat{r}_l > \hat{r}_w$）→ $w$ 接近 1 → 学习信号最强
    • 当模型已经正确偏好 chosen（$\hat{r}_w \gg \hat{r}_l$）→ $w$ 接近 0 → 几乎无梯度
  3. 缩放因子 $\beta$：控制整体梯度幅度。$\beta$ 越大，要求更大的 margin 才能让 $w$ 衰减，训练更保守。

核心直觉：DPO 自动将学习精力集中在"还没搞清楚"的数据对上，对已经正确分类的对自动降低权重，类似 focal loss 的思想。

数值示例

Prompt："向10岁小孩解释量子纠缠"

Chosen $y_w$：用"两个魔法硬币"类比（生动易懂）
Rejected $y_l$：用学术语言（正确但晦涩）

6.4 TRL Implementation（TRL 实现）

基于 HuggingFace TRL 库的最小可运行 DPO 训练示例（Llama-3.1-8B + LoRA）：

import torch
from trl import DPOConfig, DPOTrainer
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import LoraConfig
from datasets import load_dataset

# 1. 加载模型
model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-3.1-8B-Instruct",
    torch_dtype=torch.bfloat16,
    attn_implementation="flash_attention_2",
)
tokenizer = AutoTokenizer.from_pretrained("meta-llama/Llama-3.1-8B-Instruct")

# 2. LoRA 配置（使用 LoRA 时，ref_model 自动为基础权重）
lora_config = LoraConfig(
    r=16, lora_alpha=32, lora_dropout=0.05,
    target_modules=["q_proj","k_proj","v_proj","o_proj"],
    task_type="CAUSAL_LM",
)

# 3. DPO 训练配置
dpo_config = DPOConfig(
    beta=0.1,                        # KL 正则强度（核心超参）
    loss_type="sigmoid",             # 标准 DPO sigmoid loss
    learning_rate=5e-7,              # 极低学习率，防止过拟合
    max_length=2048,                 # 最大序列长度
    max_prompt_length=1024,          # prompt 截断长度
    per_device_train_batch_size=2,   # 受限于显存
    gradient_accumulation_steps=8,   # 有效 batch = 2×1×8 = 16
    num_train_epochs=1,              # DPO 极易过拟合，只训 1 epoch！
    warmup_ratio=0.1,               # 10% warmup
    bf16=True,
    logging_steps=10,
    precompute_ref_log_probs=True,   # 预计算 ref log-prob，节省显存
    output_dir="./dpo-llama3.1-8b",
)

# 4. 加载偏好数据集（标准格式：prompt, chosen, rejected）
dataset = load_dataset("HuggingFaceH4/ultrafeedback_binarized", split="train_prefs")

# 5. 创建 Trainer 并训练
trainer = DPOTrainer(
    model=model,
    ref_model=None,        # LoRA 时无需单独 ref_model
    args=dpo_config,
    peft_config=lora_config,
    train_dataset=dataset,
    tokenizer=tokenizer,
)
trainer.train()
关键监控指标：
  • train/rewards/chosen — 应持续上升（chosen 隐式奖励增加）
  • train/rewards/rejected — 应持续下降（rejected 隐式奖励减少）
  • train/rewards/margins — 应稳步增大但不爆炸（过大意味着 sigmoid 饱和）
  • train/rewards/accuracies — 模型正确排序 chosen > rejected 的比例
异常信号：如果 rewards/chosen 也在下降 → likelihood collapse → 需切换到 NCA 或 RPO。

6.5 How DPO Works: Full Mechanics（完整训练机制）

6.5.1 序列级对数概率

$$\log\pi_\theta(y|x) = \sum_{t=1}^{T}\log\pi_\theta(y_t \mid x, y_{<t})$$
整条回复的 log 概率 = 每个 token 位置条件 log 概率之和（自回归分解）。
注意：这是求和而非平均，意味着更长的序列天然有更低的 log 概率（负值累加）。这是长度偏差的来源。

6.5.2 损失分解与隐式奖励差

定义"隐式奖励差"（implicit reward margin）$h_\theta$：

$$h_\theta(x,y_w,y_l) = \underbrace{\log\frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)}}_{\text{chosen log-ratio}} - \underbrace{\log\frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)}}_{\text{rejected log-ratio}}$$

则 DPO 损失可以简洁地写为：

$$\mathcal{L}_{\text{DPO}} = -\log\sigma(\beta \cdot h_\theta)$$
每一条训练样本贡献一个标量 $h_\theta$，乘以 $\beta$ 后过 sigmoid 再取 log。$h_\theta > 0$ 意味着模型正确偏好 chosen，越大 loss 越小。

6.5.3 Forward Pass 详细步骤

  1. 数据拼接：将 prompt+chosen 拼成 $[x; y_w]$，prompt+rejected 拼成 $[x; y_l]$，各自作为完整序列
  2. 策略模型前向：分别对两条序列计算每个位置的 logits $\in \mathbb{R}^{T \times V}$
  3. 提取 log-probs：在每个 response 位置 $t$，计算 $\log\text{softmax}(\text{logits}_t)[y_t]$
  4. Label Masking：只保留 response token 的 log-probs，prompt token 和 padding token 被 mask 掉
  5. Token 求和：$\log\pi_\theta(y_w|x) = \sum_{t \in \text{response}} \log p(y_t^w | \cdot)$，rejected 同理
  6. 减去参考 log-probs：得到 $\text{ratio}_w = \log\pi_\theta(y_w|x) - \log\pi_{\text{ref}}(y_w|x)$，$\text{ratio}_l$ 同理
  7. 计算损失：$L = -\log\sigma\big(\beta \cdot (\text{ratio}_w - \text{ratio}_l)\big)$
  8. 反向传播：梯度从 loss → ratio → token 级 logits → 模型参数

6.5.4 Token 级梯度流

$$\frac{\partial \mathcal{L}}{\partial \text{logits}_t^{(w)}} = -\underbrace{\sigma(-\beta \cdot h_\theta)}_{\text{全序列共享的缩放因子}} \cdot \beta \cdot \frac{\partial \log\pi_\theta(y_t^w | \cdot)}{\partial \text{logits}_t^{(w)}}$$
关键观察：
• 缩放因子 $\sigma(-\beta h_\theta)$ 是一个全序列共享的标量，作为自适应学习率
• $h_\theta$ 小（模型分不清好坏）→ 缩放 ≈ 0.5 → 每个 token 都受到强梯度推动
• $h_\theta$ 大（已经判断正确）→ 缩放 ≈ 0 → 几乎无梯度，自动停止学习
• 对 chosen tokens：$\log\pi$ 的梯度方向为增大概率
• 对 rejected tokens：梯度方向为减小概率（前面有负号）

6.5.5 长度归一化（Length Normalization）

问题根源：$\log\pi(y|x) = \sum_t \log p(y_t|\cdot)$，每个 token 的 log 概率 $\in (-\infty, 0]$，加得越多（序列越长），总和越负。如果 chosen 远长于 rejected，其 log-prob 天然更低，模型可能无法正确排序。

策略公式特点使用者
标准 DPO$\sum_t \log\pi(y_t|\cdot)$隐式惩罚冗长，实际部署更常用原版 DPO
长度归一化$\frac{1}{|y|}\sum_t \log\pi(y_t|\cdot)$公平对待不同长度的回复SimPO
长度加权$\frac{1}{|y|^\alpha}\sum_t \log\pi(y_t|\cdot)$$\alpha \in (0,1)$ 提供连续调节ORPO 变体
实践建议：如果偏好数据中 chosen 和 rejected 长度相近（差异 < 2×），标准 DPO 即可；若长度差异大，考虑使用 SimPO 或手动裁剪数据。

6.5.6 Label Masking（标签遮盖）

Token 类型参与 log-prob 计算？有梯度？说明
Prompt tokens ($x$)❌❌只提供上下文，不计入序列 log-prob
Chosen response ($y_w$)✅✅梯度方向：推高概率

6.5.7 参考模型的角色与管理

$\pi_{\text{ref}}$ 在 DPO 中的作用：

  • 锚点：提供"基线"log 概率，隐式奖励 $\hat{r} = \beta\log(\pi_\theta/\pi_{\text{ref}})$ 衡量策略相对锚点的偏移
  • 正则化：防止策略跑得太远导致语言能力退化
  • 最佳选择：用 SFT checkpoint（而非 base model）作为 $\pi_{\text{ref}}$，确保初始 KL ≈ 0

管理策略：

  • 静态参考（默认）：$\pi_{\text{ref}}$ 全程冻结，可预计算 log-probs
  • EMA 更新（TR-DPO）：定期用策略 EMA 更新参考，适合长训练
  • 去除参考（SimPO）：用长度归一化 log-prob 替代，节省显存

6.5.8 常见陷阱与解决方案

  1. 忘记遮盖 prompt：如果 prompt token 也参与 log-prob 求和，模型会优化 prompt 似然（无意义），且等效 $\beta$ 出错。解决：严格用 label mask。
  2. mean vs sum 不一致：$\pi_\theta$ 用 mean 而 $\pi_{\text{ref}}$ 用 sum（或反之），导致隐式长度惩罚不匹配。解决：保持完全一致。
  3. 参考模型过时：若用 base model 而非 SFT checkpoint 作 $\pi_{\text{ref}}$，初始 KL 过大 → sigmoid 饱和 → 梯度消失。解决：始终用 SFT checkpoint。
  4. $\beta$ 太大：放大 log-prob 差异 → sigmoid 饱和 → 梯度接近零。解决：从 0.1 开始调。
  5. $\beta$ 太小：梯度 $\propto \beta \cdot \sigma(\cdot)$ 本身极小 → loss 平坦 → 收敛极慢。解决：不低于 0.01。
  6. 训练过多 epoch：DPO 容易在 1 epoch 后过拟合偏好数据。解决：默认 1 epoch，监控 eval loss。
  7. 数据长度失衡：chosen 和 rejected 长度差异 > 3× 时，标准 DPO 的隐式长度偏差会主导梯度。解决：数据预处理裁剪或使用 SimPO。

6.6 DPO Variants and When Each Fails（变体与失效场景）

DPO 的五大失效模式

  1. 分布偏移（Distribution Shift）：偏好数据来自旧模型（或人类），当前策略生成的文本分布已经大不相同 → 在"无关"样本上优化 → 策略漂移到未覆盖区域。
  2. 无探索（No Exploration）：DPO 是纯离线方法，无法发现训练数据集中不存在的行为。如果最优回复不在数据集中，DPO 永远学不到。PPO 通过在线采样可以探索新区域。
  3. Likelihood Collapse：DPO 只关心 chosen 与 rejected 的隐式奖励差值。模型可以通过同时降低两者的绝对概率（但让 rejected 降得更多）来满足 loss——chosen 的生成质量也在退化。
  4. 参考模型不匹配：$\pi_{\text{ref}}$ 太强（如 RLHF 后的模型）→ 策略无法移动；$\pi_{\text{ref}}$ 太弱（如 base model）→ 初始 KL 过大，失去正则化效果。
  5. 数据质量依赖：噪声标签直接毒害训练。DPO 逐对记忆数据，不像 PPO 可以跨样本平均奖励信号来平滑噪声。
什么时候应该用 PPO 而非 DPO？当需要在线探索（如代码生成中发现新的解题路径）、数据极少但环境反馈丰富（如 RLHF 中可以动态调用奖励模型评分）、或任务本质需要试错学习时，PPO 仍有不可替代的优势。

6.7 β Selection Guide（β 选择指南）

$\beta$ 是 DPO 最重要的超参数，控制 KL 惩罚强度。它直接影响模型允许偏离参考的程度。

$\beta$ 值体制适用场景风险
0.01极激进数据极干净 + 需要大幅偏离参考可能破坏语言能力
0.05激进数据质量高，希望明显优于 SFT baseline过拟合噪声标签
0.1标准（推荐起点）质量与稳定性的平衡，大多数场景首选相对安全
0.2保守数据有噪声，或模型已接近目标行为学习缓慢
0.5极保守安全微调，绝不能破坏已有能力几乎不变化

$\beta$ 对训练动态的影响

  • 梯度幅度：$|\nabla_\theta \mathcal{L}| \propto \beta \cdot \sigma(-\beta h_\theta)$。$\beta$ 太小 → 梯度本身小；$\beta$ 太大 → $h_\theta$ 被放大使 sigmoid 饱和 → 梯度也小。存在最优区间。
  • 隐式奖励量纲：$\hat{r} = \beta \cdot \text{log-ratio}$，$\beta$ 决定了 margin 的绝对数值尺度
  • 收敛行为：小 $\beta$ → 收敛快但不稳定；大 $\beta$ → 收敛慢但平稳

动态调节策略

实践中可以使用 $\beta$ schedule：

  • 训练初期用较小 $\beta$（如 0.05）快速建立 margin
  • 中后期提升到 0.1-0.2 防止过拟合
  • 或监控 KL 散度，当 $D_{\text{KL}} > $ 阈值时自动增大 $\beta$

6.8 Batch Size Configuration（批大小配置）

DPO 训练中，批大小（batch size）的配置直接影响梯度估计质量、训练稳定性和硬件利用率。由于 DPO 每条数据包含一个 preference pair（chosen + rejected），其显存需求天然高于标准 SFT，因此需要更精细的配置策略。

6.8.1 Global Batch Size Target（全局批大小目标）

DPO 的全局批大小 $B_{\text{global}}$ 存在一个经验最优区间：

$$B_{\text{global}} \in [32, 128] \quad \text{(preference pairs per update)} \tag{6.12}$$
$B_{\text{global}}$ 的单位是 preference pairs —— 即每次梯度更新所使用的偏好对数量。每个 pair 包含同一 prompt 的 chosen 和 rejected 两条回复。

理论依据

下界 $B_{\text{global}} \geq 32$ 的原因：

  • 梯度噪声：DPO 的梯度来自 $\sigma(-\beta h_\theta)$ 这一 sigmoid 函数的输出。当 batch 过小时，个别"异常"pair（如标注噪声、chosen/rejected 质量相近的困难样本）会导致梯度方向剧烈波动。
  • 多目标平衡：实际偏好数据通常包含 helpfulness、safety、honesty 等多维度信号。小 batch 中这些维度的梯度可能相互冲突，导致策略在不同维度之间震荡（oscillation between helpfulness and safety objectives）。
  • 经验验证：Anthropic 和 Meta 的实验表明，$B < 32$ 时训练 reward accuracy 的方差增大 2-4 倍，且最终模型质量不稳定。

上界 $B_{\text{global}} \leq 128$ 的原因：

  • 收敛效率递减：批大小与收敛速度的关系近似 $\text{speedup} \propto \sqrt{B}$（线性扩展仅在小 batch 区间成立）。从 128 增大到 256 带来的收敛加速仅约 $\sqrt{2} \approx 1.4$ 倍，但通信/显存开销翻倍。
  • 分布式通信开销：更大的 $B_{\text{global}}$ 意味着更多 GPU 参与 AllReduce，通信延迟占比上升。
  • 数据效率：偏好数据通常较为稀缺（几千到几万对），过大 batch 意味着每 epoch 的更新步数过少，模型无法充分学习。
经验法则：对于 7B-70B 规模模型的标准 DPO 训练，$B_{\text{global}} = 128$ 通常是最佳甜点（sweet spot）。这一配置提供了足够的梯度平滑，同时保持合理的更新频率和硬件利用率。对于数据量 < 10k 的小规模训练，可降至 $B_{\text{global}} = 64$ 以增加更新步数。

6.8.2 Mathematical Decomposition（数学分解）

全局批大小由三个可配置因子乘积构成：

$$B_{\text{global}} = B_{\text{micro}} \times N_{\text{GPUs}} \times K_{\text{accum}} \tag{6.13}$$
• $B_{\text{micro}}$：单 GPU 单次前向/反向的 micro-batch 大小（受 VRAM 物理约束）
• $N_{\text{GPUs}}$：数据并行 GPU 数量（DDP/FSDP 横向扩展）
• $K_{\text{accum}}$：梯度累积步数（gradient accumulation steps）

DPO 的配对倍数效应：DPO 中每个 preference pair 会产生两条前向序列（chosen + rejected），因此实际送入 GPU 的序列数量为：

$$T_{\text{sequences}} = 2 \times B_{\text{micro}} \tag{6.14}$$
这意味着 DPO 的显存消耗约为同等 $B_{\text{micro}}$ 下 SFT 的 2 倍。配置批大小时必须考虑这个乘数效应：如果 SFT 在同一硬件上能跑 $B_{\text{micro}} = 4$，DPO 通常只能跑 $B_{\text{micro}} = 2$。

6.8.4 VRAM Optimization: Pre-computing Reference Log-Probabilities（显存优化：预计算参考 Log-Probs）

核心观察：在标准 DPO 中，参考模型 $\pi_{\text{ref}}$ 全程冻结（不更新参数），其对任何输入的输出是确定性的。这意味着 $\pi_{\text{ref}}$ 不需要在训练期间常驻 GPU 显存——可以预先计算其所有输出并缓存。

预计算三步策略

将参考模型的显存开销从"训练全程占用"转化为"一次性前向推理"：

$$\text{Cache}(x, y) = \log\pi_{\text{ref}}(y|x) = \sum_{t=1}^{|y|} \log p_{\text{ref}}(y_t | x, y_{
对每条数据 $(x, y_w, y_l)$，预计算并缓存两个标量：$\log\pi_{\text{ref}}(y_w|x)$ 和 $\log\pi_{\text{ref}}(y_l|x)$。
  1. Step 1 — 预计算阶段（Pre-compute）：
    • 训练前加载 $\pi_{\text{ref}}$ 到 GPU，对全部训练数据逐条做前向推理
    • 计算每条数据的 $\log\pi_{\text{ref}}(y_w|x)$ 和 $\log\pi_{\text{ref}}(y_l|x)$
    • 将结果（两个 float32 标量/条）缓存到磁盘（Arrow/Parquet 格式）
    • 该阶段仅需前向推理（无反向传播），速度约为训练的 3-5 倍
  2. Step 2 — 驱逐参考模型（Evict）：
    • 预计算完成后，从 GPU 和 CPU 内存中完全卸载 $\pi_{\text{ref}}$
    • 释放的显存可重新分配给策略模型的更大 batch 或更长序列
  3. Step 3 — 缓存训练阶段（Cached Training）：
    • 训练循环中，DataLoader 从缓存读取预计算的 ref log-probs
    • DPO loss 计算仅需策略模型的在线前向 + 缓存的 ref 值，无需第二个模型
    • 显存中仅保留单个模型（$\pi_\theta$）+ 优化器状态 + 激活值

• 不适用于 TR-DPO：TR-DPO（Trust Region DPO）会周期性用策略模型的 EMA 更新 $\pi_{\text{ref}}$，使缓存失效。此时必须保留在线参考模型。
• 不适用于 Online DPO：在线 DPO 会动态生成新的 preference pairs，预计算只能覆盖静态数据集。
• 磁盘空间：缓存开销极小——每条数据仅存储 2 个 float32（8 bytes），100k 条数据仅需 ~800 KB。

6.9 DPO Extensions（DPO 扩展变体）

以下介绍 8 种重要的 DPO 变体，每种都解决了标准 DPO 的某个特定痛点。

6.9.1 f-DPO — 广义 f-散度 DPO

动机：标准 DPO 隐含使用逆向 KL 散度（reverse KL），具有 mode-seeking 特性——倾向于将概率质量集中到少数高奖励回复上，牺牲多样性。f-DPO 将 KL 约束推广到任意 f-散度，允许在多样性与质量集中之间灵活权衡。

$$\mathcal{L}_{f\text{-DPO}} = -\mathbb{E}_{(x,y_w,y_l)}\left[f'\!\left(\frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)}\right) - f'\!\left(\frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)}\right)\right]$$
其中 $f'$ 是凸函数 $f$ 的导数。不同的 $f$ 对应不同的散度度量。
散度类型$f(u)$$f'(u)$特点适用场景
Reverse KL（标准DPO）$u\log u$$\log u + 1$Mode-seeking有明确正确答案（数学、事实QA）
Forward KL$-\log u$$-1/u$Mode-covering创意写作、多样性任务
Jensen-Shannon$u\log\frac{2u}{u+1}$$\log\frac{2u}{u+1}$对称、平衡通用场景
$\alpha$-Divergence$\frac{u^\alpha - 1}{\alpha(\alpha-1)}$$\frac{u^{\alpha-1}}{\alpha-1}$连续可调需要精细控制多样性

实践指导：对创意任务（故事生成、诗歌创作），使用 Forward KL 的 f-DPO 可保持输出多样性；对精确任务（代码、数学），标准 Reverse KL 更优。

6.9.2 Robust DPO — 抗噪声标签 DPO

问题：人类标注不完美——标注员疲劳、主观偏差、任务歧义导致约 5-20% 的偏好标签被翻转。标准 DPO 会忠实地记忆这些噪声标签，导致模型学到错误偏好。

建模：假设每条标注以概率 $\epsilon$ 被翻转（chosen 和 rejected 互换）。

$$\mathcal{L}_{\text{Robust}} = \frac{(1-\epsilon)\,\mathcal{L}_{\text{DPO}}(y_w, y_l) - \epsilon\,\mathcal{L}_{\text{DPO}}(y_l, y_w)}{1 - 2\epsilon}$$
直觉：如果 $\epsilon$ 比例的标签是反的，那么标准 DPO loss 中有 $\epsilon$ 的部分在"做反方向的优化"。Robust DPO 通过减去翻转方向的 loss 贡献来"对冲"噪声。
• $\epsilon = 0$：退化为标准 DPO（分子 = $\mathcal{L}_{\text{DPO}}$，分母 = 1）
• $\epsilon = 0.5$：纯随机噪声，分母为 0，不可学习
• 实践中 $\epsilon \in [0.05, 0.15]$ 已覆盖大多数标注噪声

TRL 配置：

DPOConfig(loss_type="robust", label_smoothing=0.1)  # epsilon = 0.1

6.9.3 TR-DPO — Trust Region DPO

问题：标准 DPO 的 $\pi_{\text{ref}}$ 全程固定。随着策略持续优化，$D_{\text{KL}}[\pi_\theta \| \pi_{\text{ref}}]$ 不断增大，KL 惩罚越来越强，最终主导 loss，阻碍进一步优化——表现为 loss 过早进入平台期。

解决方案：用指数移动平均（EMA）定期更新参考模型，让"信任域"跟随策略移动：

$$\pi_{\text{ref}}^{(t+1)} \leftarrow \alpha \cdot \pi_\theta^{(t)} + (1-\alpha) \cdot \pi_{\text{ref}}^{(t)}$$
每 $T_{\text{sync}}$ 步执行一次更新。$\alpha$ 越大，参考模型追踪策略越快（信任域越"宽松"）。
• 推荐：$\alpha \in [0.5, 0.9]$，$T_{\text{sync}} \in [256, 1024]$ 步

TRL 配置：

DPOConfig(
    sync_ref_model=True,
    ref_model_mixup_alpha=0.6,
    ref_model_sync_steps=512,
)

适用场景：长训练（多 epoch）、loss 过早平台期、迭代式 DPO 管线。

注意：TR-DPO 不兼容 precompute_ref_log_probs=True，因为参考模型在变化。

6.9.4 EXO — Exact Optimisation

问题：DPO 的理论推导基于 reverse KL 约束，但实际优化的目标等价于在 reward 空间中做 forward KL 匹配——方向搞反了。这导致 DPO 在某些分布下不是最优的。

解决方案：EXO 直接优化正确方向的 KL 散度：

$$\mathcal{L}_{\text{EXO}} = -\mathbb{E}_{(x,y_w,y_l)}\left[\log\sigma\left(\beta\log\frac{\pi_{\text{ref}}(y_w|x)}{\pi_\theta(y_w|x)} - \beta\log\frac{\pi_{\text{ref}}(y_l|x)}{\pi_\theta(y_l|x)}\right)\right]$$
注意 $\pi_\theta$ 和 $\pi_{\text{ref}}$ 在分数中的位置相比标准 DPO 互换了！
标准 DPO：$\log(\pi_\theta / \pi_{\text{ref}})$
EXO：$\log(\pi_{\text{ref}} / \pi_\theta)$
EXO 实现了理论上正确的 reverse KL 概率匹配目标。

TRL 配置：DPOConfig(loss_type="exo_pair")

适用场景：需要理论保证的场景，或标准 DPO 出现异常行为时的替代方案。

6.9.5 NCA — Noise Contrastive Alignment

问题：Likelihood Collapse——DPO 的 loss 只关心 $\hat{r}_w - \hat{r}_l$ 的差值。模型可以通过同时降低两者的绝对似然（但让 rejected 降得更多）来最小化 loss。结果：chosen 的生成质量也在退化。

$$\mathcal{L}_{\text{NCA}} = -\log\sigma(\hat{r}_w) - \frac{1}{2}\log\sigma(-\hat{r}_w) - \frac{1}{2}\log\sigma(-\hat{r}_l)$$
三项各有分工：
• 第一项 $-\log\sigma(\hat{r}_w)$：鼓励 chosen 有高隐式奖励（推高 $y_w$ 的绝对概率）
• 第二项 $-\frac{1}{2}\log\sigma(-\hat{r}_w)$：惩罚 chosen 的隐式奖励过高（防止策略在 $y_w$ 上过度自信）
• 第三项 $-\frac{1}{2}\log\sigma(-\hat{r}_l)$：惩罚 rejected 的隐式奖励过高（压低 $y_l$）
关键差异：NCA 不仅关心差值，还关心绝对值，从根本上防止 collapse。

TRL 配置：DPOConfig(loss_type="nca_pair")

实践建议：使用较小的 $\beta$（如 0.01-0.05），让绝对似然项占主导。当监控到 train/rewards/chosen 持续下降时，应切换到 NCA。

6.9.6 SLiC-HF — Hinge Loss 替代方案

动机：标准 DPO 使用 log-sigmoid，即使 margin 已经足够大，loss 仍然为正且持续给梯度。这导致模型在已经"学会"的样本上继续优化，浪费计算资源并可能过拟合。

解决方案：用 Hinge Loss（合页损失）替代——当 margin 超过阈值 $\delta$ 时，loss 直接为 0。

$$\mathcal{L}_{\text{SLiC}} = \max\!\left(0,\; \delta - \beta\log\frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} + \beta\log\frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)}\right)$$
• $\delta > 0$：目标 margin 阈值（通常取 1.0）
• 当隐式 margin 超过 $\delta$ → loss = 0 → 不再更新
• 更简单、更快收敛，对"容易样本"自动跳过
• 类比 SVM 的 hinge loss：只有支撑向量（困难样本）贡献梯度

TRL 配置：DPOConfig(loss_type="hinge")

适用场景：数据集中有大量"明显"的偏好对（如 safety 数据），希望模型快速学会后聚焦困难样本。

6.9.7 Iterative RPO — 推理偏好优化

问题：标准 DPO 训练模型区分好坏回复（判别能力），但不保证模型能生成好的回复（生成能力）。对推理任务（数学、代码），光能判断对错而不能自己写出正确推理链，在推理阶段毫无用处。

$$\mathcal{L}_{\text{RPO}} = \lambda_1 \cdot \mathcal{L}_{\text{DPO}}(y_w, y_l) + \lambda_2 \cdot \mathcal{L}_{\text{NLL}}(y_w)$$
在 DPO 损失之外，加上标准的负对数似然（NLL）项——即对 chosen response 做 SFT。
• $\mathcal{L}_{\text{NLL}}(y_w) = -\sum_t \log\pi_\theta(y_t^w | x, y_{<t}^w)$
• $\lambda_1$ 控制偏好学习强度，$\lambda_2$ 控制生成能力保持
• 确保模型不仅知道哪个好，还能生成好的回复

"Iterative" 含义：

  1. 用当前策略生成多个 rollouts
  2. 用验证器（如数学答案检查器）标注 win/lose
  3. 用 RPO loss 训练
  4. 重复以上步骤（on-policy 数据刷新）

TRL 配置：DPOConfig(rpo_alpha=1.0)（$\lambda_2 = \text{rpo\_alpha}$）

适用场景：数学推理、代码生成、逻辑推理；DPO 训练后生成质量/流畅度明显下降时。

6.9.8 SimPO — Simple Preference Optimization（无参考模型）

核心创新：完全去掉参考模型 $\pi_{\text{ref}}$，用长度归一化的平均 log-prob 作为隐式奖励。

隐式奖励定义

$$r_{\text{SimPO}}(y|x) = \frac{\beta}{|y|}\log\pi_\theta(y|x) = \frac{\beta}{|y|}\sum_{t=1}^{|y|}\log\pi_\theta(y_t|x, y_{<t})$$
奖励 = 当前策略的平均 token log 概率（乘以 $\beta$）。长度归一化确保不同长度的回复公平比较。

SimPO 损失函数

$$\mathcal{L}_{\text{SimPO}} = -\mathbb{E}_{(x,y_w,y_l)}\left[\log\sigma\left(\frac{\beta}{|y_w|}\log\pi_\theta(y_w|x) - \frac{\beta}{|y_l|}\log\pi_\theta(y_l|x) - \gamma\right)\right]$$
• $\gamma > 0$：目标 reward margin（超参数），强制 chosen 的奖励严格高于 rejected 至少 $\gamma$
• 无需 $\pi_{\text{ref}}$ → 显存减半，前向推理次数减半
• 长度归一化 → 不偏好长回复或短回复

关键要点总结

  1. DPO = 无 RL 的偏好对齐：利用 KL 约束最优策略的闭式解，将 RLHF 转为单阶段监督学习，只需策略 + 参考模型。
  2. 完整推导链：RLHF 目标 → 最优策略 $\pi^* \propto \pi_{\text{ref}} \exp(r/\beta)$ → 奖励重参数化 → Bradley-Terry 消元（$Z(x)$ 抵消）→ DPO Loss。
  3. 隐式奖励：$\hat{r}(x,y) = \beta\log(\pi_\theta(y|x)/\pi_{\text{ref}}(y|x))$，策略相对参考的提升即为奖励。
  4. 自适应梯度：梯度权重 $\sigma(-\beta h_\theta)$ 自动聚焦困难样本，已学好的对自动停止。
  5. $\beta$ 是核心超参：控制 KL 约束强度，推荐从 0.1 开始。太大 → sigmoid 饱和；太小 → 梯度微弱。
  6. DPO 极易过拟合：通常只训 1 epoch，学习率 5e-7 级别，务必监控 eval loss。
  7. 预计算 ref log-prob：对静态 $\pi_{\text{ref}}$ 可释放约一半 GPU 显存，大幅提升训练效率。
  8. Likelihood Collapse 是最常见失效：监控 chosen reward 趋势，若下降则切换 NCA 或 RPO。
  9. 变体选择口诀：噪声 → Robust，平台 → TR-DPO，collapse → NCA，推理 → RPO，省显存 → SimPO，多样性 → f-DPO，快收敛 → SLiC-HF。

Q&A（点击展开）

Q1：DPO 相比 PPO 最核心的优势和劣势分别是什么？

优势：简洁性（2 模型 vs 4 模型）、稳定性（无 reward hacking、KL 爆炸）、工程简单（标准 SFT 框架即可）、超参少（主要就是 $\beta$）。

劣势：无探索能力（只能优化已有数据覆盖的行为）、离线方法导致分布偏移、数据质量敏感（逐对记忆噪声标签）、可能出现 likelihood collapse。当需要在线探索或任务有丰富环境反馈时，PPO 仍不可替代。

Q2：DPO 推导中配分函数 $Z(x)$ 为什么能完美消去？

Bradley-Terry 偏好模型 $P(y_w \succ y_l) = \sigma(r_w - r_l)$ 只关心两个回复的奖励差值。将闭式解的奖励表达式 $r(x,y) = \beta\log(\pi^*/\pi_{\text{ref}}) + \beta\log Z(x)$ 代入后，$+\beta\log Z(x)$ 在 $r_w$ 和 $r_l$ 中各出现一次，做差后完美抵消：$r_w - r_l = \beta\log(\pi^*(y_w)/\pi_{\text{ref}}(y_w)) - \beta\log(\pi^*(y_l)/\pi_{\text{ref}}(y_l))$。这是 DPO 能绕过 intractable partition function 的核心数学巧妙之处。

Q3：$\beta$ 具体控制什么？为什么不能太大也不能太小？

$\beta$ 控制 KL 惩罚强度：
• $\beta$ 太大：隐式奖励 $\hat{r} = \beta \cdot \text{log-ratio}$ 被放大 → sigmoid $\sigma(\beta h_\theta)$ 快速饱和 → 梯度 $\sigma(-\beta h_\theta) \to 0$ → 训练停滞
• $\beta$ 太小：梯度 $\propto \beta \cdot \sigma(\cdot)$ 本身极小 → loss landscape 平坦 → 收敛极慢，需要极多步才能建立 margin
最优 $\beta$ 需要让大部分训练样本的 $\beta h_\theta$ 落在 sigmoid 的线性区间 $[-2, 2]$ 内。实践起点 0.1。

Q4：什么是 Likelihood Collapse？如何检测和解决？

定义：DPO loss 只关心隐式奖励差 $\hat{r}_w - \hat{r}_l$。模型可以通过同时降低两者的绝对log 概率来满足 loss——只要 rejected 降得更多即可。结果是 chosen 的生成质量退化。

检测：监控 train/rewards/chosen。正常训练中应该上升或持平；若持续下降 → collapse。

解决方案：
• NCA：加入绝对似然项，惩罚 $y_w$ 概率下降
• RPO：加 NLL 项强制模型学会生成 $y_w$
• 增大 $\beta$：限制策略偏移幅度
• 使用更高质量的数据：减少模型需要"大幅调整"的压力

Q5：SimPO 如何做到无需参考模型？有什么代价？

SimPO 将隐式奖励定义为策略本身的长度归一化平均 log-prob：$r = (\beta/|y|)\log\pi_\theta(y|x)$。这完全由当前策略决定，无需与参考对比。为防止优化退化（所有概率趋于均匀），加入 margin $\gamma$ 强制 chosen 奖励高于 rejected 至少 $\gamma$。

代价：失去了 KL 约束的理论保证——没有参考模型"锚定"，策略可能偏移得更远。实践中需要更仔细地监控生成质量和多样性。

Q6：预计算参考 log-prob 有什么限制？

• 只适用于 $\pi_{\text{ref}}$ 全程不变的标准 DPO。TR-DPO（动态更新参考）不能用。
• 数据增强（如 random prompt augmentation）如果改变了输入序列，缓存会失效。
• 若数据集更新（新增样本），需要重新跑一遍预计算。
• 好处极大：70B 模型可节省 ~140GB 显存，$B_{\text{micro}}$ 可提升 2-4 倍。

Q7：在什么情况下应该使用 RPO 而不是标准 DPO？

推理密集型任务（数学、代码、逻辑）。标准 DPO 只训练判别能力（区分好坏），但推理任务需要生成能力（写出正确推理链）。RPO 通过额外的 NLL 项保证模型不仅"知道哪个好"，还"能写出好的"。特别适合 iterative pipeline：生成 rollouts → 验证器标注 → RPO 训练 → 刷新数据 → 重复。

Q8：DPO 和 RLHF/PPO 在计算效率上具体差多少？

对 7B 模型的典型对比：
• 显存：PPO 需要 ~56GB（4 模型），DPO 需要 ~28GB（2 模型），SimPO 只需 ~14GB（1 模型）
• 训练速度：DPO 比 PPO 快 2-3×（无需 rollout 采样和多次前向）
• 代码复杂度：DPO 用 TRL 约 50 行代码即可完成，PPO 需要 200+ 行
• 超参调优：DPO 主要调 $\beta$ + lr，PPO 需要调 7-8 个耦合超参
