第16章：Retrieval-Augmented Generation (RAG)

检索增强生成——从基础架构到Agentic RAG的完整技术体系

来源：The Hitchhiker's Guide to Agentic AI · 第16章（pp. 295–318） · 阅读笔记

章节摘要

本章系统性地介绍了检索增强生成（RAG）的完整技术栈。从LLM为何需要外部知识开始，经过核心RAG架构（索引、检索、生成），到各种检索方法的详细对比（BM25、DPR、SPLADE、ColBERT），再到分块策略、高级RAG模式（Self-RAG、CRAG、Graph RAG），以及效率优化（REFRAG）。本章重点介绍了Agentic RAG——将检索框定为序列决策问题，以及Search-R1通过强化学习训练模型学习何时、如何检索。最终覆盖评估框架、生产部署考量和RAG+Fine-Tuning协同策略，共11节24页。

16.1 Motivation and Problem Statement

RAG已成为生产环境中部署LLM最具实际影响力的技术之一。它不再仅依赖训练时编码在模型权重中的知识，而是为LLM配备动态、可更新的外部记忆，使其能够在知识密集型任务中生成准确、有据可查且可验证的回答。

LLM需要外部知识的三大根本限制

  1. 幻觉（Hallucination）：模型在超出可靠知识边界时，会自信地生成听起来合理但事实上错误的陈述。
  2. 知识过时（Knowledge Staleness）：训练数据有截止日期；模型无法知道训练后发生的事件。
  3. 领域特异性（Domain Specificity）：通用模型缺乏对专有代码库、内部文档、专业法规的深度知识。

16.1.1 参数化 vs 非参数化知识

设 $M_\theta$ 为参数为 $\theta$ 的语言模型，$\mathcal{D} = \{d_1, d_2, \ldots, d_N\}$ 为外部文档语料库。两种范式下生成答案 $a$ 的概率：

$$P_{\text{parametric}}(a \mid q) = P_{M_\theta}(a \mid q)$$ $$P_{\text{RAG}}(a \mid q, \mathcal{D}) = \sum_{d \in \mathcal{D}} P_{M_\theta}(a \mid q, d) \cdot P_{\text{ret}}(d \mid q, \mathcal{D})$$

其中 $P_{\text{ret}}(d \mid q, \mathcal{D})$ 是文档的检索分布。RAG通过对检索到的证据进行边缘化，将生成过程锚定在非参数化知识上。参数化模型像是一位毕业多年的学者（记忆丰富但过时），而RAG为其提供了"图书馆借阅证"——可以实时查找、引用来源。

常见误解：RAG不是Fine-Tuning的替代品。Fine-Tuning教模型如何推理和回答；RAG提供关于什么进行推理的材料。它们是互补的——经过Fine-Tuning的模型能更有效地利用检索到的上下文。

16.2 Core RAG Architecture

标准RAG系统由两个阶段组成：离线索引管线（处理和存储文档）和在线检索-生成管线（服务查询）。

16.2.1 索引管线（Indexing Pipeline）

  1. 文档加载（Document Loading）：从PDF、HTML、Markdown、DOCX、代码等异构格式中提取纯文本，保留元数据（来源URL、页码、章节标题、时间戳）。
  2. 分块（Chunking）：将长文档拆分为适合嵌入模型上下文窗口（通常512 tokens）且语义连贯的块。这是RAG系统设计中影响最大的决策之一。
  3. 嵌入（Embedding）：每个块 $c_i$ 被编码为稠密向量 $e_i = f_\phi(c_i) \in \mathbb{R}^d$，与原始文本和元数据一起存储在向量数据库中。

16.2.2 检索（Retrieval）

给定查询 $q$，检索步骤将其编码为 $\mathbf{q} = f_\phi(q)$，通过余弦相似度找到最相似的 $k$ 个块：

$$\text{sim}(\mathbf{q}, \mathbf{e}_i) = \frac{\mathbf{q} \cdot \mathbf{e}_i}{\|\mathbf{q}\| \|\mathbf{e}_i\|}$$

返回相似度最高的 $k$ 个块 $C_k = \{c^{(1)}, \ldots, c^{(k)}\}$ 作为生成上下文。

16.2.3 生成（Generation）

检索到的块被注入到提示模板中，系统指令要求模型仅使用提供的上下文回答，并使用 [Doc N] 标注引用来源。若上下文不足，需明确说明。

SYSTEM_PROMPT = """You are a helpful assistant. Answer the question using ONLY
the provided context. If the context does not contain enough information,
say so explicitly. Cite your sources using [Doc N] notation."""

def build_rag_prompt(query: str, chunks: list[dict]) -> str:
    context_str = "\n\n".join(
        f"[Doc {i+1}] (Source: {c['source']}, Page: {c.get('page','N/A')})\n{c['text']}"
        for i, c in enumerate(chunks)
    )
    return f"""{SYSTEM_PROMPT}\nContext:\n{context_str}\nQuestion: {query}\nAnswer:"""

16.3 Retrieval Methods

16.3.1 稀疏检索：BM25 和 TF-IDF

稀疏检索方法将文档和查询表示为词汇表上的高维稀疏向量。经典的BM25评分函数：

$$\text{BM25}(d, q) = \sum_{i=1}^{n} \text{IDF}(t_i) \cdot \frac{f(t_i, d) \cdot (k_1 + 1)}{f(t_i, d) + k_1 \cdot \left(1 - b + b \cdot \frac{|d|}{\text{avgdl}}\right)}$$

其中 $f(t_i, d)$ 是词频，$|d|$ 是文档长度，$\text{avgdl}$ 是平均文档长度，$k_1 \in [1.2, 2.0]$、$b = 0.75$ 是调优参数。IDF项衡量词的区分度，分母中的长度归一化防止长文档获得不公平的优势。

稀疏检索仍然获胜的场景：精确关键词匹配（产品代码、错误代码、专有名词）、低资源领域（不足以训练密集模型）、可解释性（易于调试）、速度（无需GPU，亿级文档规模的倒排索引）、词汇外术语。

16.3.2 稠密检索：DPR

Dense Passage Retrieval (DPR) 使用两个独立的BERT编码器——查询编码器 $E_Q$ 和段落编码器 $E_P$——通过对比损失训练，使相关的查询-段落对在嵌入空间中距离更近。

$$\text{sim}(q, p) = E_Q(q)^\top E_P(p)$$

双编码器架构：查询和段落分别编码为单向量，通过内积计算相似度。

In-Batch Negatives 训练：给定批次中 $B$ 个查询-段落对 $\{(q_i, p_i^+)\}_{i=1}^B$，对比损失将同批其他段落视为负样本：

$$\mathcal{L}_{\text{DPR}} = -\frac{1}{B}\sum_{i=1}^{B} \log \frac{\exp\left(E_Q(q_i)^\top E_P(p_i^+)/\tau\right)}{\sum_{j=1}^{B} \exp\left(E_Q(q_i)^\top E_P(p_j)/\tau\right)}$$

其中 $\tau$ 是温度超参数。Hard negatives（词汇相似但语义无关的段落）对训练强检索器至关重要。

近似最近邻搜索（ANN）：规模化时穷举搜索不可行，FAISS提供高效ANN搜索：

  • IVF（倒排文件索引）：将向量聚类到Voronoi单元，只搜索邻近单元
  • HNSW（层次可导航小世界图）：图索引，$O(\log N)$ 搜索复杂度
  • PQ（乘积量化）：压缩向量以减少内存占用

16.3.3 混合检索：Reciprocal Rank Fusion (RRF)

混合检索结合稀疏和稠密分数。简单线性组合为：

$$s_{\text{hybrid}}(d, q) = \alpha \cdot s_{\text{dense}}(d, q) + (1-\alpha) \cdot s_{\text{sparse}}(d, q)$$

但不同系统的分数不可直接比较。Reciprocal Rank Fusion 通过操作排名而非分数来解决这个问题：

$$\text{RRF}(d) = \sum_{r \in R} \frac{1}{k + \text{rank}_r(d)}$$

其中 $R$ 是多个排序列表的集合（如BM25排名和Dense排名），$\text{rank}_r(d)$ 是文档 $d$ 在列表 $r$ 中的排名，$k=60$ 是平滑常数，减少极高排名文档的影响。例：BM25排名第3、Dense排名第7的文档 → $\text{RRF}(d) = \frac{1}{63} + \frac{1}{67} \approx 0.0308$。

16.3.4 学习型稀疏检索：SPLADE

核心动机：BM25依赖精确词汇匹配（"car"无法匹配"automobile"）；DPR捕获语义但失去可解释性且需GPU。SPLADE兼得两者优势：稀疏向量（快速倒排索引查找）+ 学习的语义扩展。

SPLADE v1 架构：使用预训练MLM（如BERT）为每个文档/查询产生词汇表上的稀疏向量。MLM头已知哪些词与文本中每个位置语义相关——SPLADE将此知识重新用作词项重要性权重：

$$w_t(x) = \log\left(1 + \text{ReLU}\left(\max_{i \in [1,n]} H_i[t]\right)\right)$$

其中 $H_i[t]$ 是输入位置 $i$ 处词汇token $t$ 的MLM logit。$\log(1+\cdot)$ 饱和防止单词主导（类似BM25中的TF饱和）；ReLU确保稀疏性；max pooling跨位置捕获最强信号；扩展：原文中不存在的token也可获得非零权重（如"neural networks"文档可获得"deep learning"的权重）。

评分：查询和文档各映射为稀疏向量 $w^q, w^d \in \mathbb{R}^{|V|}$，相关性分数为点积：

$$s(q, d) = \sum_{t \in V} w_t^q \cdot w_t^d$$

由于两个向量都是稀疏的（通常30K词汇中仅20-200个非零项），可用标准倒排索引高效计算——查询时无需GPU。

训练损失（含稀疏正则化）：

$$\mathcal{L} = \mathcal{L}_{\text{contrastive}} + \lambda_q \|w^q\|_1 + \lambda_d \|w^d\|_1$$

L1惩罚鼓励稀疏性——没有它们模型会学习密集表示，失去效率优势。

SPLADEv2 关键改进：

  1. Cross-encoder蒸馏：使用MonoT5等交叉编码器教师提供软相关分数 → $\mathcal{L}_{\text{distill}} = \text{KL}(\sigma(s_{\text{student}}) \| \sigma(s_{\text{teacher}}))$
  2. 非对称编码器：查询更稀疏（快速查找），文档可稍密集（离线预计算）→ $\lambda_q > \lambda_d$
  3. FLOPS正则化：直接惩罚预期检索成本 → $\mathcal{L}_{\text{FLOPS}} = \sum_{t \in V}(\bar{a}_t^q)^2 + \sum_{t \in V}(\bar{a}_t^d)^2$
  4. 高效骨干：DistilBERT (66M) 替代 BERT-base (110M)，编码时间减半

16.3.5 ColBERT：Late Interaction

ColBERT将查询和文档编码为token级嵌入集合，使用MaxSim算子评分：

$$s(q, d) = \sum_{i \in |q|} \max_{j \in |d|} \mathbf{q}_i^\top \mathbf{d}_j$$

对每个查询token，找到与之最相似的文档token并取内积，然后将所有查询token的最大相似度求和。这种"晚期交互"机制比单向量双编码器更有表达力，同时比交叉编码器快得多（文档嵌入离线预计算）。

架构细节：查询/文档编码器都是BERT，输出per-token嵌入（非单个[CLS]向量），投影到低维（128维）：

$$\mathbf{q}_i = \text{Linear}(E_Q(q)_i) \in \mathbb{R}^{128}, \quad \mathbf{d}_j = \text{Linear}(E_D(d)_j) \in \mathbb{R}^{128}$$

训练损失（pairwise softmax交叉熵）：

$$\mathcal{L}_{\text{ColBERT}} = -\log \frac{\exp(s(q, d^+))}{\exp(s(q, d^+)) + \sum_{k=1}^{N} \exp(s(q, d_k^-))}$$

负样本来源：in-batch negatives（免费、充足）、BM25 hard negatives（对质量影响最大）、ColBERTv2中的蒸馏negatives。

索引与服务：PLAID索引——聚类文档嵌入，用质心初筛候选，仅对候选计算精确MaxSim，延迟降低5-10×。索引大小：每文档 $|d| \times 128$ 浮点数（可通过残差量化压缩至~2 bytes/维度）。

16.4 Chunking Strategies

分块是将文档拆分为以下三方面平衡的片段的过程：(1) 足够小以适配嵌入模型的上下文窗口，(2) 语义连贯，(3) 单独检索时包含足够上下文。

16.4.1 固定大小分块（带重叠）

最简单策略：每 $W$ 个token切分，连续块间有 $O$ 个token重叠。

$$N_{\text{chunks}} = \left\lceil \frac{L - O}{W - O} \right\rceil$$

其中 $L$ 是文档长度（token数），$W$ 是块大小，$O$ 是重叠大小。重叠确保跨边界的上下文不丢失。

16.4.2 语义分块（Semantic Chunking）

不在固定间隔切分，而是在通过测量连续句子间嵌入相似度检测到的主题边界处切分。当相邻句子的embedding余弦相似度低于阈值（如第95百分位的不相似度）时断开。

16.4.3 文档结构感知分块

  • Markdown：在 ## 标题处切分，保留章节上下文
  • HTML：在 <section>、<article>、<p> 标签处切分
  • 代码：在函数/类定义处切分，每块保留import语句
  • 表格：整表作为单个块；永远不在行中间切分

16.4.4 父子分块（Parent-Child Chunking）

一种将检索粒度与生成上下文解耦的强大模式：

  1. 索引小的子块（如128 tokens）用于精确检索
  2. 返回大的父块（如512 tokens）给LLM以提供更丰富的上下文

16.5 Advanced RAG Patterns

16.5.1 Query Transformation

原始用户查询往往模糊、过短或与文档语言不匹配。查询变换技术在搜索步骤之前提升检索质量。

HyDE（Hypothetical Document Embeddings）：不直接嵌入查询，而是先让LLM生成假设性答案，然后嵌入该答案：

$$\hat{d} = \text{LLM}(q), \quad \mathbf{e}_{\text{query}} = f_\phi(\hat{d})$$

直觉：假设性答案与真实文档处于相同的语言寄存器（linguistic register），减少查询-文档分布差距。

Step-Back Prompting：对具体问题先生成更一般性的"后退"问题，对两者都检索并组合上下文。例："乙醇在2 atm下的沸点是多少？" → 后退："什么因素影响液体的沸点？"

Multi-Query Generation：生成 $M$ 个多样化的查询重写，分别检索，对结果取并集去重。

16.5.2 Re-Ranking（重排）

初始检索top-k候选后，交叉编码器对每个query-document对联合评分（同时关注两者），产生更精确的相关性分数：

$$s_{\text{cross}}(q, d) = \text{CrossEncoder}([q; d])$$

交叉编码器不能用于一阶检索（无预计算文档嵌入），但非常适合重排小候选集（通常 $k=20\text{-}100$）。典型选择：BAAI/bge-reranker-large。

16.5.3 Contextual Compression（上下文压缩）

检索到的块通常包含围绕相关段落的无关句子。上下文压缩使用LLM仅提取相关部分，减少噪声并节省上下文窗口。

16.5.4 Self-RAG

Self-RAG训练单一模型同时完成三个决策：(1) 决定是否检索，(2) 带/不带检索生成，(3) 使用特殊反思token自我批评输出：

  • [Retrieve]：模型是否应该检索额外段落？
  • [IsRel]：检索到的段落是否与查询相关？
  • [IsSup]：生成的陈述是否源自检索段落？
  • [IsUse]：整体回答是否有用？

模型端到端训练以预测这些token和回答，实现对检索和自评分的细粒度控制。

16.5.5 CRAG：Corrective RAG

CRAG添加检索评估器，对检索文档评分并触发纠正动作：

  1. 检索top-k文档
  2. 对每个文档评级：Correct / Ambiguous / Incorrect
  3. 若所有文档不正确或模糊 → 回退到Web搜索
  4. 若部分文档正确 → 使用知识精炼（剥离无关句子）
  5. 从精炼后的上下文生成答案

16.5.6 Adaptive RAG

根据预测的查询复杂度路由到不同检索策略：

  • 无检索：简单事实查询，模型可从参数知识回答
  • 单步RAG：标准检索-生成，适合中等查询
  • 多步RAG：迭代检索，适合复杂多跳问题

一个轻量级分类器（基于查询复杂度标签训练）路由每个传入查询。

16.5.7 Graph RAG

微软的Graph RAG从文档语料库构建知识图谱，使用社区检测生成层次化摘要：

  1. 实体提取：LLM从每个块中提取实体和关系
  2. 图构建：构建图 $G = (V, E)$，节点为实体，边为关系
  3. 社区检测：应用Leiden算法在多个分辨率下发现社区
  4. 社区摘要：LLM为每个社区生成摘要
  5. 查询：全局查询→对社区摘要做map-reduce；局部查询→标准向量搜索

何时使用Graph RAG：擅长需要跨多文档综合信息的全局查询（"这个语料库的主要主题是什么？"），但构建和维护成本高。标准RAG更适合局部查询（"文档X关于主题Y说了什么？"）。

16.5.8 RAG-Fusion

RAG-Fusion从原始查询生成多个搜索查询，分别检索，然后使用RRF融合排名列表。将Multi-Query Generation与RRF评分相结合，实现多视角检索的统一排名。

16.6 Efficient RAG Decoding: REFRAG

RAG的实际瓶颈是解码延迟：检索到的段落拼接入LLM上下文往往很长但稀疏相关，膨胀了TTFT（Time-to-First-Token）和KV-cache内存。REFRAG观察到检索段落是独立来源的（经多样性/去重重排），其注意力模式呈块对角——大部分跨段落注意力接近零。

Compress–Sense–Expand 框架

  1. Compress：用紧凑摘要（如每段落块的mean-pooled keys/values）替换完整KV表示，大幅减少内存
  2. Sense：每个解码步骤，对压缩表示做轻量注意力，识别哪些段落块与当前token相关
  3. Expand：仅对选中的块重建完整KV条目，在稀疏活跃集上执行精确注意力

性能结果：在LLaMA模型上，REFRAG实现高达30.85× TTFT加速（比先前稀疏注意力基线提升3.75×），无困惑度损失。在固定内存预算下将有效上下文长度扩展16×。对Agentic RAG尤其重要——多轮检索会累积延迟，REFRAG使每轮解码成本与上下文长度呈亚线性关系。

16.7 Agentic RAG

16.7.1 Motivation：静态RAG的局限

标准RAG遵循固定的retrieve-then-generate模式，在以下场景失败：

  • 多跳问题："谁创立了2023年收购OpenAI主要竞争对手的公司？"——需要链式多次检索
  • 模糊查询：正确的检索策略取决于找到了什么
  • 异构源：不同子问题需要不同知识库
  • 迭代精炼：初始检索可能揭示需要不同查询

RAG作为MDP：Agentic RAG将检索框定为序列决策问题。状态是当前上下文（查询+已检索文档）；动作包括retrieve、reason、generate、stop；奖励是答案正确性。智能体学习一个决策策略：何时检索、检索什么。

16.7.2 Agentic RAG 架构

Agent迭代执行：计划 → 检索 → 评估充分性 → 自检grounding，然后返回答案。关键设计模式是条件循环：评估后，agent要么继续生成（上下文充分或迭代预算耗尽），要么带精炼的子查询返回检索。

16.7.3 Multi-Source Routing（多源路由）

核心洞察：不同问题类型需要不同的检索后端——没有单一索引能胜任一切。

  • "我们公司的PTO政策是什么？" → 向量数据库（内部文档）
  • "美联储昨天宣布了什么？" → Web搜索（实时信息）
  • "显示Q3各地区营收" → SQL数据库（结构化数据）
  • "我们的auth中间件如何验证token？" → 代码索引（代码库）

三种路由策略（复杂度递增）：

  1. 规则路由：关键词触发（如SQL关键词→数据库）。快速可解释但对模糊查询脆弱。
  2. 分类器路由：轻量模型（fine-tuned BERT或查询嵌入上的逻辑回归）预测最佳源。延迟<10ms，可从路由日志训练。
  3. LLM路由：LLM在结构化输出调用中自行决定源。最灵活——处理新查询类型并可解释推理——但增加一次LLM调用延迟。

16.7.4 完整Agentic RAG实现（LangGraph）

使用LangGraph将四个节点串联为有状态图：

  1. Plan：将用户查询分解为子查询
  2. Retrieve：路由每个子查询到合适的源并获取文档
  3. Evaluate：判断累积上下文是否足以回答原始查询
  4. Generate：从检索上下文合成带引用的最终答案

16.7.5 Tool-Augmented RAG

Agentic RAG可将检索与计算工具结合：向量搜索、SQL查询、Web搜索、Python执行等注册为工具，由LLM Agent根据需求调用。

16.7.6 Search-R1：RL训练的Agentic RAG

上述方法依赖提示工程编排。Search-R1采用根本不同的方法：通过强化学习训练LLM学习何时、什么、多少次搜索作为其推理过程的一部分。

核心思想：扩展DeepSeek-R1推理框架，将搜索引擎查询视为RL训练循环中的动作。模型在CoT生成中可发出特殊token <search>query</search> 触发实时检索，结果注入推理上下文后继续生成：

$$\text{think}_1 \to \underbrace{\langle\text{search}\rangle q_1 \langle/\text{search}\rangle}_{\text{action}} \to \underbrace{[\text{results}_1]}_{\text{observation}} \to \text{think}_2 \to \cdots \to \text{answer}$$

整个轨迹（推理+搜索+最终答案）由终端奖励评分：最终答案相对于ground-truth的正确性。

训练算法（GRPO）：

  1. 每个问题采样 $N$ 条轨迹，每条可能包含0-5次搜索
  2. 实时执行搜索——环境返回真实搜索引擎结果
  3. 评分最终答案正确性（精确匹配或F1）
  4. 计算组相对优势：$\hat{A}_i = (R_i - \mu_G)/\sigma_G$
  5. 用GRPO裁剪目标更新策略——强化有效搜索的轨迹

模型学会：不确定时搜索（避免已知知识的无效搜索）、制定有效查询、多次搜索（基于初始结果迭代精炼）、整合检索上下文。

Search-R1核心结果：7B模型在NQ、TriviaQA、HotpotQA上超越标准RAG 15-20%准确率，超越提示式Agentic RAG (ReAct风格) 8-12%，接近70B模型+标准RAG的表现。关键洞察：学习何时和如何搜索比拥有更大模型更有价值——一个搜索得好的小模型胜过不搜索的大模型。

范式转变：传统RAG问的是"给定这个查询，我应该检索什么？"（生成前的管线决策）。Search-R1问的是"给定我迄今的推理，我需要更多信息吗？如果需要，什么具体问题能填补这个空白？"（生成中的学习决策）。这是考试前查课本的学生 vs. 做题时卡住才查参考资料的学生之间的区别——后者更高效、更有针对性。

16.8 Evaluation

评估RAG系统比单独评估检索或生成更难——错误可能来自管线的任何阶段且会累积。完美的生成器无法补偿无关的检索，完美的检索器若生成器幻觉则浪费。有效评估在三个层面运作：

16.8.1 检索指标

设 $R_K$ 为排名前K的检索文档集合，$R^*$ 为相关文档集合：

$$\text{Recall@K} = \frac{|R_K \cap R^*|}{|R^*|}$$ $$\text{Precision@K} = \frac{|R_K \cap R^*|}{K}$$

Recall@K衡量相关文档被检索到的比例；Precision@K衡量检索结果中相关文档的比例。

$$\text{MRR} = \frac{1}{|Q|}\sum_{i=1}^{|Q|} \frac{1}{\text{rank}_i}$$

Mean Reciprocal Rank：$\text{rank}_i$ 是查询 $i$ 的第一个相关文档的排名。衡量"找到第一个正确答案有多快"。

$$\text{NDCG@K} = \frac{\text{DCG@K}}{\text{IDCG@K}}, \quad \text{DCG@K} = \sum_{i=1}^{K} \frac{\text{rel}_i}{\log_2(i+1)}$$

$\text{rel}_i \in \{0, 1, 2, \ldots\}$ 是第 $i$ 个结果的分级相关度，IDCG是理想（完美排序）的DCG。NDCG考虑位置折扣和多级相关性。

16.8.2 生成指标

$$\text{Faithfulness} = \frac{\text{上下文支持的声明数}}{\text{答案中的总声明数}}$$

衡量生成答案是否基于检索上下文——答案中的每个声明是否可归因于检索文档。由LLM评判。

$$\text{AnswerRelevance} = \frac{1}{N}\sum_{i=1}^{N} \cos(E(q), E(\hat{q}_i))$$

从答案反向生成问题 $\hat{q}_i$，衡量其与原始查询的嵌入相似度。答案越相关，反向生成的问题越接近原查询。

$$\text{ContextPrecision@K} = \frac{1}{K}\sum_{k=1}^{K} \text{Precision@k} \cdot \mathbf{1}[\text{doc}_k \text{ is relevant}]$$ $$\text{ContextRecall} = \frac{\text{可归因于上下文的ground-truth声明数}}{\text{总ground-truth声明数}}$$

16.8.3 RAGAs 框架

RAGAs (Retrieval Augmented Generation Assessment) 提供无参考评估框架，使用LLM作为评判者，覆盖faithfulness、answer_relevancy、context_precision、context_recall、answer_correctness五个维度。

16.9.3 延迟优化

  1. Pre-filtering：用元数据过滤（日期、类别、来源）在ANN搜索前缩小搜索空间
  2. Approximate NN：使用HNSW或IVF索引，接受~1%召回损失换取10×加速
  3. Embedding缓存：缓存频繁重复查询的嵌入
  4. 异步检索：并行从多个源检索
  5. 流式生成：检索完成时流式输出LLM结果
  6. 量化：int8或binary量化嵌入减少内存、提升吞吐量

16.9.4 增量索引与版本管理

生产中文档语料不是静态的。增量索引通过文档级变更避免全量重建：

  • Upsert：文档创建/更新时删除该doc_id的所有现有块，重新分块、嵌入、插入
  • Delete/Expire：按doc_id删除或按TTL自动垃圾回收
  • Version tracking：在块元数据中存储version和indexed_at时间戳，支持回滚和审计

一致性挑战：嵌入模型漂移（升级模型时新旧向量不兼容→维护独立索引或用Matryoshka兼容模型）、块边界偏移（改变分块策略使现有块失效）、最终一致性（分布式向量数据库中新插入的向量可能不立即可搜索）。

16.10 RAG + Fine-Tuning Synergy

16.10.1 何时结合RAG与Fine-Tuning

  • 仅Fine-Tuning：模型学习风格和格式但可能幻觉事实
  • 仅RAG：模型有事实访问但可能不知如何最优使用
  • 组合：微调模型以善用检索上下文——引用来源、承认不确定性、忽略无关上下文

16.10.2 RAFT：Retrieval-Augmented Fine-Tuning

RAFT训练模型在混合相关和干扰文档的情况下回答问题，教模型识别并仅使用相关上下文：

  1. 对每个训练样本 $(q, a, d^*)$，采样 $k-1$ 个干扰文档 $\{d_i^-\}$
  2. 微调输入：$[q, d^*, d_1^-, \ldots, d_{k-1}^-] \to [\text{chain-of-thought} + a]$
  3. CoT显式引用 $d^*$，教模型将答案grounding
$$\mathcal{L}_{\text{RAFT}} = -\mathbb{E}_{(q, a, d^*, \{d_i^-\})} \left[\log P_\theta\left(\text{CoT}(d^*) \oplus a \mid q, d^*, \{d_i^-\}\right)\right]$$

通过在训练中混入干扰文档，模型学会从噪声上下文中识别真正相关的文档并基于其生成答案，这直接模拟了RAG系统的实际使用场景。

16.10.3 联合检索器-生成器训练

为获得最大性能，检索器和生成器可联合训练，梯度流经检索步骤：

$$\nabla_\theta \mathcal{L} = \nabla_\theta \left[-\log \sum_{d \in \mathcal{D}} P_\theta(a \mid q, d) \cdot P_\phi(d \mid q)\right]$$

检索器参数 $\phi$ 通过REINFORCE估计器更新，或将 $P_\phi(d|q)$ 视为文档上的可微注意力。挑战：(1) 文档索引须随 $\phi$ 变化定期刷新，(2) 训练信号稀疏（仅top-k文档贡献），(3) 无预训练检索器良好初始化时训练不稳定。

Q&A 自测

Q1：RAG的参数化与非参数化知识有何本质区别？为什么需要对检索文档进行边缘化？

参数化知识压缩在模型权重中（$P_{M_\theta}(a|q)$），静态且训练后不变；非参数化知识存储在外部语料库中，可动态更新。RAG通过对检索文档边缘化 $P_{\text{RAG}}(a|q,\mathcal{D}) = \sum_d P_{M_\theta}(a|q,d) \cdot P_{\text{ret}}(d|q,\mathcal{D})$，将生成过程锚定在可验证的外部证据上。这使得模型可以引用来源、承认不确定性，而非仅依赖可能过时或错误的参数记忆。

Q2：BM25为什么在某些场景仍然优于密集检索？RRF如何统一异质评分？

BM25在以下场景胜出：(1) 精确关键词匹配（产品代码、错误代码）；(2) 词汇外术语（嵌入模型训练未见的新词）；(3) 无需GPU的大规模部署；(4) 可解释性。RRF通过操作排名而非原始分数解决异质评分问题：$\text{RRF}(d) = \sum_{r \in R} \frac{1}{k + \text{rank}_r(d)}$，不同系统的分数量纲不同但排名可直接比较，$k=60$的平滑常数减少极端排名的过大影响。

Q3：SPLADE如何兼具稀疏检索的效率和密集检索的语义能力？

SPLADE利用预训练MLM头的知识：MLM头已学会每个位置哪些词语义相关。通过$w_t(x) = \log(1+\text{ReLU}(\max_i H_i[t]))$产生词汇表上的稀疏向量。关键：(1) 不在原文中的词也可获得非零权重（语义扩展，如"car"→"automobile"）；(2) ReLU确保大部分权重为零（稀疏性→可用倒排索引）；(3) log饱和防止单词主导（类比BM25的TF饱和）。结果：查询时无需GPU，可用Lucene/Elasticsearch，同时捕获同义词和相关概念。

Q4：ColBERT的MaxSim为什么比单向量bi-encoder更有表达力？代价是什么？

单向量bi-encoder将整个文档压缩为一个向量，丢失细粒度token级信息。ColBERT保留所有token嵌入并通过MaxSim $s(q,d)=\sum_{i\in|q|}\max_{j\in|d|}\mathbf{q}_i^\top\mathbf{d}_j$ 做晚期交互——每个查询token独立找最佳匹配的文档token。这使其能捕获局部对齐和多方面匹配。代价：索引大小为$|d|\times 128$浮点数/文档（远大于单向量），但可通过残差量化（ColBERTv2的PLAID索引）压缩至~2 bytes/维度。

Q5：Self-RAG和CRAG在处理检索质量问题时有何不同策略？

Self-RAG在模型内部解决：训练单一模型预测反思token（[Retrieve]、[IsRel]、[IsSup]、[IsUse]），实现对"是否检索"和"检索是否有用"的细粒度自我控制。CRAG在管线外部解决：添加一个独立的检索评估器对文档评级（Correct/Ambiguous/Incorrect），然后触发纠正动作（不正确→回退到Web搜索；部分正确→知识精炼剥离无关句子）。Self-RAG更端到端但需特殊训练；CRAG更模块化可插拔到现有系统。

Q6：REFRAG的Compress-Sense-Expand如何实现30×TTFT加速？

REFRAG利用关键观察：检索段落是独立来源的，其注意力模式呈块对角——跨段落注意力接近零。(1) Compress：将每个段落块的完整KV替换为紧凑摘要（如mean-pooled keys/values）；(2) Sense：每步解码用轻量注意力在压缩表示上识别相关块；(3) Expand：仅对选中块重建完整KV做精确注意力。由于大部分块在大部分解码步骤中不被需要，这使解码成本与上下文长度呈亚线性而非线性关系，实现30.85×加速且无困惑度损失。

Q7：Search-R1相比提示式Agentic RAG的本质优势在哪里？

本质区别是学习决策 vs. 工程决策。提示式方法依赖人工设计的启发式（何时搜索、如何重写查询、搜几次），对未见场景泛化差。Search-R1通过GRPO强化学习让模型从正确性奖励中学习：(1) 不确定时才搜索（避免冗余）；(2) 学会制定有效查询（不是简单重写）；(3) 学会最优搜索次数和失败退避策略；(4) 搜索作为推理的一部分交织在CoT中而非管线外部步骤。结果：7B模型搜索良好可媲美70B模型不搜索。

Q8：RAG评估中为什么"Lost-in-the-Middle"和"Over-Retrieval"问题经常同时出现？

两者存在因果关系：Over-Retrieval（K值过大）导致大量边缘相关文档被纳入上下文，上下文变长后触发Lost-in-the-Middle效应——LLM注意力偏向首尾，中间段落（可能包含最关键信息）被忽视。更糟的是，过多块还增加latency和cost。解决方案：(1) 控制K值（通常5-10即可）；(2) 使用re-ranking只保留最相关的子集；(3) 使用contextual compression提取精华；(4) 将最相关文档放在上下文首尾。

Q9：RAFT如何解决RAG系统中"模型不会用检索结果"的问题？

RAFT模拟RAG的真实使用场景训练：每个样本包含1个相关文档$d^*$和$k-1$个干扰文档$\{d_i^-\}$，目标是生成CoT+答案，其中CoT必须显式引用$d^*$。这教会模型三个能力：(1) 从噪声上下文中识别哪个文档相关；(2) 引用相关文档中的具体内容而非凭记忆生成；(3) 忽略干扰文档即使它们看起来相关。相当于开卷考试训练——不是给标准答案，而是教学生如何在参考资料中找到答案。

Q10：设计生产RAG系统的推荐"最小可行方案"是什么？何时升级到Agentic RAG？

最小可行方案：(1) 语义分块（512 tokens, 64 overlap）+ 结构感知；(2) BM25 + Dense混合检索 + RRF融合；(3) Cross-encoder重排top-20→取top-5；(4) 标准RAG prompt + citation要求。升级到Agentic RAG的信号：(1) 频繁出现需要多步推理的查询；(2) 需要从异构源（向量库+SQL+Web）获取信息；(3) 初始检索经常不充分需要精炼查询；(4) 用户满意度瓶颈在于"没找到正确信息"而非"找到了但答不好"。先确保基础RAG的分块和检索质量过关，再考虑复杂架构。
