第26章：Agentic UI Frameworks

智能体UI框架——从聊天框到透明协作者的界面设计革新

来源：The Hitchhiker's Guide to Agentic AI · 第26章（pp. 490–511） · 阅读笔记

章节摘要

本章系统梳理了Agentic UI的设计范式、核心组件、框架生态与实现模式。随着LLM从被动文本生成器转变为具备规划、工具使用和多步推理能力的主动Agent，人机交互界面必须同步演进。传统聊天界面无法满足长时间运行任务、分支决策树、并行工具调用和人类监督的需求。本章从动机出发，覆盖六大UI范式、七类关键组件、主流框架对比、生成式UI、流式传输、人在环中设计到可信赖性设计，最终以完整的FastAPI+React全栈实现收尾。

26.1 Motivation: Beyond the Chat Box

聊天气泡传达的是结果，而Agentic UI传达的是过程——推理路径、调用的工具、做出的决策、以及需要人类判断的节点。没有这种可见性，用户无法信任、纠正或从Agent中学习。

聊天界面与Agentic界面之间的差距，如同自动贩卖机与熟练协作者之间的差距。当Agent执行20步研究任务时，用户需要回答以下问题：

  • Agent现在在做什么？ 长时间运行的任务需要进度反馈；沉默滋生不信任
  • Agent为什么做这个决定？ 推理透明性使用户能及早发现错误
  • 使用了哪些工具，输入了什么？ 工具溯源对验证事实和审计行为至关重要
  • 我应该在哪里介入？ Agent需要呈现需要人类判断的决策点
  • 我能撤销吗？ 不可逆操作需要明确确认和回滚路径

自动化偏见风险（Automation Bias）：研究一致表明，用户对自动化系统过度信任，尤其当系统自信且无不确定性信号时。Agentic UI必须主动对抗自动化偏见——呈现不确定性、展示推理过程、让用户容易质疑或覆盖Agent决策。

核心设计目标

  1. 透明性（Transparency）：使Agent内部状态对用户可读
  2. 控制（Control）：提供有意义的干预点，无需持续监督
  3. 信任校准（Trust Calibration）：帮助用户建立Agent能力与限制的准确心智模型
  4. 效率（Efficiency）：最小化认知负荷；在正确的时间呈现正确的信息
  5. 可恢复性（Recoverability）：使错误易于发现和逆转

26.2 UI Paradigms for Agents

没有单一UI范式适合所有Agentic场景。适当的界面取决于任务持续时间、所需人类参与度、输出类型和用户专业水平。

26.2.1 Chat-Based Interfaces（聊天界面）

聊天范式仍是LLM交互最熟悉的入口。针对Agentic使用进行增强：

  • Streaming响应：Token逐个出现，提供即时反馈（通过SSE或WebSocket）
  • 内联工具指示器：消息流中的小徽章显示工具调用
  • 状态消息："Agent正在思考…"、"正在运行Python代码…"
  • 消息线程：多轮任务中可折叠子线程包含中间步骤

局限性：聊天界面将本质上并行的过程串行化。当Agent同时扇出到5个工具时，线性消息流歪曲了实际执行图。

26.2.2 Canvas and Artifact-Based Interfaces（画布/工件界面）

画布范式（Claude Artifacts、ChatGPT Canvas）引入分窗布局：左窗对话，右窗显示生成内容。

  • 持久化工件：生成内容跨轮次持续，可通过自然语言迭代精炼
  • 原地编辑：用户可直接编辑工件，Agent能观察并响应
  • 版本历史：支持回滚到任意先前状态
  • 多工件工作空间：支持多个同时工件（代码+测试+文档）

特别适合共创任务：写作、编程、数据分析和设计。

26.2.3 Workflow Visualization（工作流可视化）

对于执行结构化计划的Agent，工作流可视化UI使计划显性化且可追踪：

  • Agentic Pipeline（LangGraph, AutoGen, CrewAI）：执行图渲染为DAG
  • 任务分解视图：高层计划显示为清单或甘特图，子任务可展开
  • 实时进度追踪：节点变色/加载；完成显示输出；失败显示错误

26.2.4 Dashboard and Monitoring（仪表盘监控）

面向长时间运行或生产环境Agent的操作视图：

  • 实时状态：Agent运行/空闲/失败状态
  • 资源指标：Token消耗、API调用、延迟、成本
  • 队列管理：待处理任务、优先级、速率限制
  • 告警与异常检测：异常行为通知
  • 历史分析：任务完成率、平均时长、错误频率

26.2.5 Collaborative Interfaces（协作界面）

Agent作为共享工作空间中的对等贡献者：

  • 存在指示器：Agent作为命名光标或头像出现
  • 变更归属：Agent编辑与人类编辑视觉区分
  • 内联建议：Agent以跟踪编辑或评论提出更改
  • 冲突解决：同时编辑时UI呈现冲突并促进解决

代表：Cursor、Notion AI、Google Docs with Gemini。

26.2.6 Autonomous with Checkpoints（自主+检查点）

Agent大部分独立运行，仅在预定义检查点需要人类批准：

  • Computer-use agents（Anthropic Computer Use, OpenAI Operator）
  • 带门的自动化管线：CI/CD风格，完成阶段后等待人类"merge"
  • 定时Agent：按计划运行并异步报告结果

实践示例：Agent清理邮箱时自主归档500封邮件后暂停："我发现23封来自您6个月未打开的邮件列表。是否退订？"——自主执行 + 人类决策点间断平衡效率与控制。

26.3 Key UI Components for Agents

26.3.1 Thought and Reasoning Display

现代LLM（o1/o3、Claude extended thinking）在产生最终响应前生成大量内部推理。展示推理是双刃剑：增加透明度但可能淹没用户。

  • 可折叠推理块：摘要（"思考了12秒"）+ 展开切换
  • 渐进式披露：默认仅显示最终结论
  • 结构化推理：假设→证据→结论的视觉层级
  • 推理vs响应区分：视觉区分内部推理与最终响应

26.3.2 Tool Use Visualization

  • 内联工具卡：工具名+输入摘要+状态，可展开详情
  • 工具时间线：水平时间线显示所有调用及持续时间
  • 输入/输出Diff：修改状态工具的前/后差异
  • 工具图标：常见工具可识别图标
  • 错误高亮：失败调用红色显示

26.3.3 Progress Indicators

  • 步骤级进度：编号步骤列表+复选标记
  • Token流式指示器：闪烁光标或token/秒计数器
  • 预估完成时间：ETA（"大约2-5分钟"）
  • 子任务嵌套：树形结构进度视图
  • 取消按钮：优雅停止并汇总已完成工作

26.3.4 Approval Gates

Alert Fatigue：频繁请求批准导致用户反射性不阅读就批准。分层审批策略至关重要。

  • 操作摘要：纯文字描述Agent想做什么
  • 风险指示器：绿=易撤销、黄=难撤销、红=不可逆
  • 批准/拒绝/修改：三选项界面
  • 上下文面板：展示Agent为何要执行此操作
  • 超时行为：不响应时的默认处理

26.3.5 Context Display

  • 记忆面板：Agent当前记住的内容，用户可编辑
  • 活跃工具列表：可用工具附启用/禁用开关
  • 检索上下文：上下文窗口中的文档附来源引用
  • Token预算指示器：上下文窗口消耗量

26.3.6 Error and Recovery UI

  • 错误卡片：内联显示错误类型+消息+Agent解释
  • 重试控件：手动重试附可选参数调整
  • 替代方案：主方案失败时提出可选替代
  • 部分结果：中途失败显示已完成步骤
  • 升级路径：通往人类支持的清晰路径

26.3.7 Confidence Indicators

  • 言语对冲：高亮"我不确定"等短语
  • 来源质量：时效性、权威性、相关性分数
  • 显式不确定性请求："你有多确定？"按钮
  • 验证建议：主动建议验证步骤

26.4 Frameworks and Libraries

26.4.1 Vercel AI SDK

TypeScript/JavaScript库，支持React、Next.js、Svelte、Vue。最广泛使用的生产Web Agent UI框架。

核心抽象：

  • useChat：管理聊天对话的React Hook（流式+消息历史+加载状态）
  • useCompletion：单轮文本补全Hook
  • useObject：流式结构化JSON对象，渐进式渲染
  • streamText / streamObject：服务端HTTP流式
  • Generative UI（AI SDK RSC）：LLM工具结果渲染为React组件

26.4.2 Chainlit

Python框架，LangChain/LlamaIndex生态中流行。

  • Step可视化：原生渲染执行步骤为可折叠树
  • 多模态支持：文件、图像、音频、PDF开箱即用
  • 认证与会话：内置认证、持久化历史、多用户
  • 自定义元素：Python中注册React组件
  • 反馈收集：赞/踩+可选评论

26.4.3 Gradio

Python库，快速构建ML演示。gr.ChatInterface + gr.Blocks。

  • 零配置部署（Hugging Face Spaces一行分享）
  • 自定义组件系统（React集成Python后端）
  • 多模态输入（文件、图像、音频、视频、摄像头）
  • 原生generator流式支持

局限：布局不如React灵活，状态管理会话级别。

26.4.4 Streamlit

Python数据应用框架。响应式模型（每次交互整个脚本重新运行）。

  • st.metric/st.dataframe/st.status：实时指标
  • st.session_state：跨重运行持久化
  • st.write_stream：渐进式输出
  • @st.fragment：部分重运行提升性能

26.4.5 OpenAI Assistants Playground

Agentic UI设计的参考实现（非构建框架）：Thread对话管理、文件检索可视化、Code Interpreter执行、Function Call显示、Run Step可视化。

26.4.6 LangGraph Studio

桌面应用，LangGraph Agent的可视化IDE。最先进的工具使用和工作流可视化环境。

  • 图可视化：Agent状态机交互式渲染
  • 状态检查：任意执行点的完整状态JSON
  • 时间旅行调试：重放+修改+重运行
  • HITL集成：任意节点设断点
  • 多Agent支持：supervisor-subagent层级可视化

26.5 Generative UI

传统LLM界面渲染文本/Markdown。Generative UI颠覆模式：模型工具调用生成UI组件。模型不仅决定说什么，还决定如何呈现——图表、表单、地图、日历等。

范式转换：不再由开发者预定义所有UI状态，而是模型动态选择并参数化适合当前上下文的UI组件。

26.5.1 React Server Components for Dynamic Interfaces

Vercel AI SDK RSC架构流程：

  1. 用户发消息到Next.js server action
  2. 服务器调LLM，每个工具关联React组件
  3. LLM调工具时服务器渲染对应组件
  4. 渲染组件作为RSC流式传输到客户端
// app/actions.tsx (Server Action)
import { streamUI } from 'ai/rsc';
import { openai } from '@ai-sdk/openai';
import { WeatherCard } from '@/components/WeatherCard';
import { StockChart } from '@/components/StockChart';

export async function chat(userMessage: string) {
  const result = await streamUI({
    model: openai('gpt-4o'),
    messages: [{ role: 'user', content: userMessage }],
    tools: {
      show_weather: {
        description: 'Display current weather for a location',
        parameters: z.object({
          location: z.string(),
          unit: z.enum(['celsius', 'fahrenheit']),
        }),
        generate: async ({ location, unit }) => {
          const data = await fetchWeather(location, unit);
          return <WeatherCard data={data} />;
        },
      },
      show_stock: {
        description: 'Display stock price chart',
        parameters: z.object({ ticker: z.string() }),
        generate: async ({ ticker }) => {
          const data = await fetchStockData(ticker);
          return <StockChart ticker={ticker} data={data} />;
        },
      },
    },
  });
  return result.value;
}

Listing 26.2：Vercel AI SDK RSC Generative UI——LLM工具调用直接渲染为React组件流式传输到客户端。

26.5.2 Adaptive Interfaces Based on Content Type

  • 表格数据 → 可排序可过滤数据表+导出
  • 地理数据 → 交互式地图+标记+图层
  • 时间序列 → 可缩放折线图+注释
  • 代码 → 语法高亮编辑器+运行按钮
  • 文档 → 格式化查看器+注释工具
  • 表单 → 动态生成表单字段

Generative UI的限制：完全模型驱动的UI存在不一致性、无障碍性失败和安全漏洞风险。最佳实践：模型从预构建的安全组件库中选择，而非生成任意HTML/JSX。

26.6 Streaming and Real-Time Patterns

流式传输是Agentic UI的基础：将体验从"等待结果"转变为"观看Agent工作"。

26.6.1 Token Streaming

两种传输机制：

  • SSE：单向HTTP流，简单、标准HTTP/1.1、自动重连。LLM API的主导机制。
  • WebSocket：双向持久连接，支持中途发送数据（中断Agent、生成中反馈）。
# SSE Token Streaming with FastAPI
from fastapi import FastAPI
from fastapi.responses import StreamingResponse
from openai import AsyncOpenAI
import json

app = FastAPI()
client = AsyncOpenAI()

async def token_stream(prompt: str):
    """Generator that yields SSE-formatted token chunks."""
    stream = await client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}],
        stream=True,
    )
    async for chunk in stream:
        delta = chunk.choices[0].delta
        if delta.content:
            yield f"data: {json.dumps({'token': delta.content})}\n\n"
        elif chunk.choices[0].finish_reason:
            yield f"data: {json.dumps({'done': True})}\n\n"

@app.get("/stream")
async def stream_endpoint(prompt: str):
    return StreamingResponse(
        token_stream(prompt),
        media_type="text/event-stream",
        headers={"Cache-Control": "no-cache", "X-Accel-Buffering": "no"},
    )

Listing 26.3：FastAPI SSE token streaming——每个token作为JSON事件增量推送到客户端。

26.6.2 Tool Call Streaming

工具名和参数增量流式传输，UI可在调用前就显示进度。

  • 渐进式参数显示：参数流入时即显示
  • 并行工具调用指示器：同时调用多工具全显示pending
  • 工具结果流式：代码执行/网页抓取本身可流式

26.6.3 Multi-Agent Streaming

  • Agent标记流：每流标记Agent身份，单独车道渲染
  • 流合并：supervisor与subagent流交错时维持连贯排序
  • Backpressure：UI跟不上时丢弃中间token、批量更新或暂停

26.6.4 Optimistic UI Updates

  • 用户发消息立即出现在历史（乐观），请求在飞行中
  • 审批接受时UI立即显示"已批准"并开始下一步
  • 服务器返错时乐观更新被回滚

26.6.5 Backpressure Handling

  • Token批处理：缓冲50-100ms批量渲染
  • 虚拟滚动：仅渲染可见部分
  • 节流更新：固定速率（10Hz）更新
  • 渐进细节：高吞吐时摘要视图

26.7 Human-in-the-Loop UI Design

目标：维持有意义的人类监督而不创建瓶颈。

26.7.1 When to Interrupt the Agent

  • 可逆性：不可逆→始终批准；可逆→通常不需
  • 范围：影响外部系统/他人→更多审视
  • 置信度：低置信→请求澄清
  • 成本：高成本→需批准
  • 新颖性：未执行过→更多审视

26.7.2 Tiered Approval Workflows

三层审批模型（Three-Tier Approval Model）

  • Tier 1（Auto-approve）：低风险可逆常规操作（网页搜索、读文件、只读API）。无需中断，记录用于审计。
  • Tier 2（Notify）：中风险。非阻塞通知+30秒取消窗口。
  • Tier 3（Require approval）：高风险不可逆高成本。阻塞审批门，必须显式操作。

阈值可由用户配置或从行为学习。

26.7.3 Feedback Mechanisms

  • Thumbs up/down：二元反馈→RLHF/偏好学习
  • 内联修正：用户编辑Agent输出→delta作为训练信号
  • 偏好选择：多选项中用户选择→偏好信号
  • 显式指令："不要再这样做"→更新行为策略
  • 附理由评分：可选文本解释

26.7.4 Teaching the Agent Through UI Interaction

  • 示范：用户手动执行→Agent观察学习
  • 带泛化的修正："我是否应该始终这样做？"
  • 偏好引出：定期比较两种行为
  • 行为档案：可见"偏好"档案，用户可审查编辑

26.8 Accessibility and Trust

信任不是一个功能——是涌现属性，来自系统持续按预期行为、清晰解释、优雅恢复。

26.8.1 Explaining Agent Decisions

  • 决策理由：不仅做了什么，还有为什么
  • 来源归因：主张链接到来源
  • 反事实解释："如果你说X而非Y，我会做Z"
  • 不确定性量化：明确置信度+驱动因素

26.8.2 Showing Confidence Levels

  • 言语置信度：自然语言表达比数值概率更可解释
  • 视觉置信度：颜色编码（绿/黄/红）、图标、字体粗细
  • 按主张置信度：每个主张独立置信度指标

26.8.3 Undo and Rollback

  • 操作日志+撤销：时间顺序日志附"撤销"按钮
  • 快照回滚：定期快照支持回滚
  • Dry-run模式：执行前模拟并显示预测变化
  • 优雅降级：不可撤销时清晰沟通+最佳替代

26.8.4 Audit Trails

  • 不可变操作日志：时间戳+用户身份+完整参数
  • 可导出历史：JSON/CSV/PDF合规报告
  • Diff视图：修改包含前/后diff
  • 会话回放：逐步重放用于调试/合规

26.8.5 Managing User Expectations

  • 能力披露：能做/不能做的清晰文档
  • 限制承认：超出能力时明确说明
  • 不确定性沟通：主动沟通而非等用户发现
  • 一致人格：一致身份和风格建立可预测性

信任建设案例（航班预订）：高信任UI呈现：(1)搜索参数，(2)替代方案及选择原因，(3)确切操作（API调用），(4)确认+链接，(5)24小时撤销选项，(6)Agent不能做什么的说明。

26.9 Implementation Example: Full-Stack Agentic UI

后端FastAPI+LangGraph，前端React。结合流式传输、工具可视化和审批门。

26.9.1 Backend: FastAPI + Streaming + Approval Gates

# backend/main.py
import asyncio, json
from typing import AsyncGenerator
from fastapi import FastAPI, HTTPException
from fastapi.responses import StreamingResponse
from pydantic import BaseModel
from langchain_core.tools import tool

app = FastAPI()

@tool
def web_search(query: str) -> str:
    """Search the web for information."""
    return f"Search results for '{query}': [simulated results]"

@tool
def send_email(to: str, subject: str, body: str) -> str:
    """Send an email. REQUIRES HUMAN APPROVAL."""
    return f"Email sent to {to} with subject '{subject}'"

APPROVAL_REQUIRED_TOOLS = {"send_email"}
approval_store: dict[str, asyncio.Event] = {}
approval_results: dict[str, dict] = {}

async def agent_stream(session_id: str, message: str) -> AsyncGenerator:
    def sse(event_type: str, data: dict) -> str:
        return f"data: {json.dumps({'type': event_type, **data})}\n\n"

    yield sse("status", {"message": "Starting agent..."})
    yield sse("thinking", {"content": "Analyzing the request..."})

    # Tier 1: Auto-approved tool call
    yield sse("tool_call", {"tool": "web_search",
        "input": {"query": message}, "tier": 1})
    await asyncio.sleep(0.5)
    yield sse("tool_result", {"tool": "web_search",
        "output": "Found relevant results...", "duration_ms": 245})

    # Tier 3: Requires human approval
    approval_id = f"approval_{session_id}_{id(message)}"
    approval_event = asyncio.Event()
    approval_store[approval_id] = approval_event

    yield sse("approval_required", {
        "approval_id": approval_id, "tool": "send_email", "tier": 3,
        "risk": "irreversible",
        "action_summary": "Send research summary to team@example.com",
        "parameters": {"to": "team@example.com", "subject": "Research"},
    })

    # Block until human approves (5min timeout)
    try:
        await asyncio.wait_for(approval_event.wait(), timeout=300)
        result = approval_results.get(approval_id, {})
        if result.get("approved"):
            yield sse("tool_call", {"tool": "send_email",
                "input": result.get("parameters", {}),
                "tier": 3, "approved_by": "human"})
            yield sse("tool_result", {"tool": "send_email",
                "output": "Email sent successfully", "duration_ms": 128})
        else:
            yield sse("action_rejected", {"tool": "send_email",
                "reason": result.get("reason", "User rejected")})
    except asyncio.TimeoutError:
        yield sse("approval_timeout", {"approval_id": approval_id,
            "message": "Approval timed out; action skipped"})

    yield sse("token", {"content": "I've completed the research. "})
    yield sse("done", {"total_tokens": 847, "duration_ms": 2341})

@app.get("/chat/stream")
async def chat_stream(session_id: str, message: str):
    return StreamingResponse(agent_stream(session_id, message),
        media_type="text/event-stream",
        headers={"Cache-Control": "no-cache", "X-Accel-Buffering": "no"})

class ApprovalRequest(BaseModel):
    approval_id: str
    approved: bool
    parameters: dict | None = None
    reason: str | None = None

@app.post("/chat/approve")
async def handle_approval(req: ApprovalRequest):
    if req.approval_id not in approval_store:
        raise HTTPException(status_code=404, detail="Approval not found")
    approval_results[req.approval_id] = {
        "approved": req.approved,
        "parameters": req.parameters, "reason": req.reason}
    approval_store[req.approval_id].set()
    return {"status": "ok"}

26.9.2 Frontend: React with Streaming and Tool Visualization

// frontend/AgentChat.tsx
import { useState, useRef } from 'react';

type AgentEvent =
  | { type: 'status'; message: string }
  | { type: 'thinking'; content: string }
  | { type: 'token'; content: string }
  | { type: 'tool_call'; tool: string; input: object; tier: number }
  | { type: 'tool_result'; tool: string; output: string; duration_ms: number }
  | { type: 'approval_required'; approval_id: string; tool: string;
      tier: number; risk: string; action_summary: string; parameters: object }
  | { type: 'action_rejected'; tool: string; reason: string }
  | { type: 'done'; total_tokens: number; duration_ms: number };

function ToolCard({ event }: { event: AgentEvent & { type: 'tool_call' } }) {
  const [expanded, setExpanded] = useState(false);
  const tierColors = { 1: '#22c55e', 2: '#f59e0b', 3: '#ef4444' };
  const color = tierColors[event.tier] || '#6b7280';
  return (
    <div style={{ border: `1px solid ${color}`, borderRadius: 8,
                  padding: 8, margin: '4px 0' }}>
      <span style={{ color, fontWeight: 600 }}>⚙ {event.tool}</span>
      <span style={{ color: '#6b7280', fontSize: 11 }}>
        Tier {event.tier}</span>
      <button onClick={() => setExpanded(!expanded)}>
        {expanded ? 'Hide' : 'Details'}</button>
      {expanded && <pre>{JSON.stringify(event.input, null, 2)}</pre>}
    </div>
  );
}

function ApprovalGate({ event, onDecision }: {
  event: AgentEvent & { type: 'approval_required' };
  onDecision: (approved: boolean, params?: object) => void;
}) {
  const riskColors = { reversible: '#22c55e',
    'hard-to-undo': '#f59e0b', irreversible: '#ef4444' };
  const riskColor = riskColors[event.risk] || '#6b7280';
  return (
    <div style={{ border: `2px solid ${riskColor}`, borderRadius: 8,
                  padding: 16, background: '#fef9f0' }}>
      <div style={{ fontWeight: 700, color: riskColor }}>
        ⚠ Approval Required: {event.tool}</div>
      <div>{event.action_summary}</div>
      <div>Risk: <span style={{color: riskColor}}>{event.risk}</span></div>
      <button onClick={() => onDecision(true, event.parameters)}
        style={{background:'#22c55e',color:'white'}}>✓ Approve</button>
      <button onClick={() => onDecision(false)}
        style={{background:'#ef4444',color:'white'}}>✗ Reject</button>
    </div>
  );
}

export function AgentChat() {
  const [events, setEvents] = useState<AgentEvent[]>([]);
  const [response, setResponse] = useState('');
  const [isStreaming, setIsStreaming] = useState(false);
  const [input, setInput] = useState('');
  const sessionId = useRef(`session_${Date.now()}`);

  const sendMessage = async () => {
    if (!input.trim() || isStreaming) return;
    setEvents([]); setResponse(''); setIsStreaming(true);
    const url = `/chat/stream?session_id=${sessionId.current}`
      + `&message=${encodeURIComponent(input)}`;
    const es = new EventSource(url);
    es.onmessage = (e) => {
      const event: AgentEvent = JSON.parse(e.data);
      if (event.type === 'token') setResponse(p => p + event.content);
      else if (event.type === 'done') { setIsStreaming(false); es.close(); }
      else setEvents(prev => [...prev, event]);
    };
    es.onerror = () => { setIsStreaming(false); es.close(); };
    setInput('');
  };

  const handleApproval = async (approvalId: string, approved: boolean,
      parameters?: object) => {
    await fetch('/chat/approve', { method: 'POST',
      headers: {'Content-Type': 'application/json'},
      body: JSON.stringify({approval_id: approvalId, approved, parameters})});
  };

  return (
    <div style={{ maxWidth: 800, margin: '0 auto', padding: 16 }}>
      {events.map((event, i) => {
        if (event.type === 'tool_call')
          return <ToolCard key={i} event={event} />;
        if (event.type === 'approval_required')
          return <ApprovalGate key={i} event={event}
            onDecision={(a, p) =>
              handleApproval(event.approval_id, a, p)} />;
        return null;
      })}
      {response && <div>{response}</div>}
      <input value={input} onChange={e => setInput(e.target.value)}
        onKeyDown={e => e.key==='Enter' && sendMessage()}
        placeholder="Ask the agent..." />
      <button onClick={sendMessage} disabled={isStreaming}>
        {isStreaming ? 'Running...' : 'Send'}</button>
    </div>
  );
}

26.10 Summary

核心洞见

  1. 范式选择很重要：适当UI范式取决于任务结构、人类参与和输出类型。大多数生产系统组合多种范式。
  2. 透明性不可协商：用户无法信任看不到的东西。思维展示、工具可视化和上下文面板是可信赖系统的基础。
  3. 流式是基线：用户期望实时看到Agent工作。Token/tool call/multi-agent streaming是table-stakes。
  4. 审批门必须分层：扁平策略失败。自动批准安全操作+门控危险操作。
  5. Generative UI是前沿：LLM生成UI组件使界面适应内容而非反过来。
  6. 信任通过一致性和可恢复性赢得：撤销、审计轨迹、校准置信度指标。

设计北极星：Agent as a Transparent Collaborator
行动始终可见、推理始终可访问、错误始终可恢复、能力与限制始终清晰。每个UI决策都应按此标准评估。

Q&A 复习

Q1：为什么传统聊天界面不适合Agentic工作流？

聊天界面将本质上并行的过程串行化。当Agent同时扇出到多个工具时，线性消息流歪曲了实际执行图。此外无法有效呈现进度、分支决策树、并行工具调用状态以及需要人类判断的决策点。

Q2：什么是Generative UI？它与传统渲染有何不同？

Generative UI颠覆传统模式：模型工具调用直接生成UI组件。模型决定不仅说什么还决定如何呈现。以Vercel AI SDK RSC为例，LLM调用工具后服务器渲染对应React组件流式传输。最佳实践是模型从预构建安全组件库中选择。

Q3：三层审批模型各层是什么？为什么需要分层？

Tier 1：低风险可逆→自动批准。Tier 2：中风险→非阻塞通知+30秒取消窗口。Tier 3：高风险不可逆→阻塞审批门。分层避免Alert Fatigue——频繁请求导致用户反射性批准，违背监督目的。

Q4：SSE与WebSocket各自适用什么场景？

SSE：单向HTTP流，简单、自动重连，适合大多数只需服务端推送token的场景（LLM API主导）。WebSocket：双向持久连接，适合需中途发送数据的交互场景（中断Agent、生成中反馈）。

Q5：如何处理多Agent系统中的Backpressure？

(1)Token批处理：缓冲50-100ms批量渲染；(2)虚拟滚动：仅渲染可见部分；(3)节流更新：10Hz固定速率；(4)渐进细节：高吞吐时摘要视图；(5)丢弃中间token或暂停较慢流。

Q6：Automation Bias是什么？如何对抗？

人类对自动化系统过度信任。对抗方式：(1)呈现不确定性和置信度；(2)展示推理过程；(3)使覆盖决策容易；(4)提供撤销回滚；(5)来源归因和反事实解释帮助独立验证。

Q7：asyncio.Event如何协调前端审批与后端流式？

后端需审批时创建asyncio.Event并await暂停流，同时发送approval_required事件到前端。前端渲染ApprovalGate，用户操作后POST到/chat/approve。后端收到POST后event.set()唤醒流。5分钟超时防无限等待。干净解耦审批UI与流式逻辑。

Q8：六种UI范式分别最适合什么场景？

(1)Chat：简单问答。(2)Canvas：共创（写作/编程/分析）。(3)Workflow：结构化Pipeline追踪。(4)Dashboard：生产Agent运营监控。(5)Collaborative：对等贡献共享工作空间。(6)Autonomous+Checkpoints：高度自主仅关键点暂停。多数生产系统组合多种。
