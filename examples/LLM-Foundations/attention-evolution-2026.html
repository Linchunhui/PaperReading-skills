导读：注意力到底在贵什么

标准 MHA 同时承担两件事：它既把每个历史 token 的 K/V 原样保存，又让每个新 Query 扫描全部历史。上下文变长后，Prefill 的两两比较、Decode 的 KV 读取带宽、缓存容量会一起放大。后来的注意力变体并不是朝同一个方向优化，而是分别砍掉不同的成本。

缓存压缩线
store ↓

MQA、GQA、MLA 让每个历史 token 存得更少，但通常仍读取全部历史。

稀疏注意力线
read ↓

窗口、block 或 indexer 让当前 Query 只访问少量 token；显式 token 地址仍在。

线性注意力线
state = O(1)

不保存长度为 n 的历史列表，而把过去压进固定大小递归状态。

全文最重要的判断：MLA 不是稀疏注意力，稀疏注意力也不是线性注意力。MLA 减少“每个 token 存多少”，Sparse 减少“每次读多少”，Linear 改变“历史以什么形式存在”。

这条结构时间线有意没有把 FlashAttention 放进去。FlashAttention 是 exact attention 的 IO-aware 实现：它改变分块和 HBM/SRAM 数据搬运，不改变注意力允许访问哪些 token，也不改变模型学到的注意力函数。它属于 Kernel 层而非结构分支，下面用独立小节说明 v1/v2。

另一个边界：Mamba、Mamba‑2/3 属于选择性状态空间模型（SSM），同样能做线性时间序列建模，但不是由 Q/K/V 特征映射得到的线性注意力。它们会和 GLA、DeltaNet 互相借鉴，但本文不把 SSM 直接改名为 attention。

1. MHA：完整交互是质量上限，也是成本起点

每个 head 独立检索，所有 token 两两相看。

Attention(Q,K,V)= softmax(QKTdh)V

白话翻译：每个 Query 先和全部历史 Key 算相似度，Softmax 把它们变成权重，再对 Value 做加权求和。平方复杂度来自 Query 数和 Key 数同时随序列长度增长。

为什么训练和推理会遇到不同瓶颈

Prefill 一次处理整段输入。n 个 Query 与 n 个 Key 形成 n×n 分数矩阵，所以注意力 FLOPs 和中间激活随 n² 增长。FlashAttention 能避免把整张矩阵写回 HBM，却没有消除这些点积。

Decode 每次只有一个新 Query。单步算量从 n² 变成 n，但模型需要逐层读取全部历史 K/V。大批量服务时，GPU 往往等数据而不是等矩阵乘法，KV Cache 的体积和内存带宽便成为主瓶颈。

M≈2·L·n·hkv·dh·b

白话翻译：KV Cache 约等于 K/V 两份 × 层数 L × token 数 n × KV head 数 × 每头维度 × 每个数的字节数。MQA/GQA 直接缩小的是其中的 KV head 数。

白话翻译：每读入一个新的 Key/Value 块 B，就更新这一行见过的最大分数 m，并把旧的指数和 ℓ 与输出分子 õ 换算到新基准后继续累加。全部块处理完才做一次 õ/ℓ，因此无需保存完整 score 或 probability 矩阵，结果仍与标准 Softmax 完全相同。

v1：把完整注意力变成片上分块流式计算

常规实现会先生成分数矩阵 S=QKᵀ，把 S 写入 HBM，再读回做 Softmax 得到概率矩阵 P；P 往往还要再次写回、读出后与 V 相乘。长序列下，两张 n×n 中间矩阵的显存流量和峰值激活会非常昂贵。FlashAttention v1 将 Q、K、V 切成适合片上 SRAM 的 tiles：每次只加载 Qᵢ 与 Kⱼ/Vⱼ，算出当前 score tile 后立刻更新输出，不让完整 S 或 P 落到 HBM。

难点是 Softmax 需要整行最大值与归一化分母。在线递推保存行最大值 m、指数和 ℓ 与未归一化输出分子 õ；新块若出现更大 score，就用 exp(m−m′) 把旧统计量重标定，再与新块合并。它不是近似：忽略浮点累加顺序差异，最终等价于一次性对整行 Softmax。

反向传播也不保存 n×n attention probabilities，而是保存输出和每行归一化统计，在片上按块重算 score/probability。这个 selective recomputation 增加了一部分 FLOPs，却省下大量 HBM IO。v1 论文在其内存模型中给出的 HBM 访问量为 O(n²d²/M)，其中 M 是片上 SRAM 容量；算术复杂度仍是 O(n²d)，额外中间存储则不再随 n² 增长。

v2：相同在线 Softmax，重新安排 GPU 的工作

  1. 减少非矩阵乘法。GPU 的 Tensor Core 矩阵乘法吞吐远高于标量 FP32 运算。FA2 维护未缩放的输出分子，在循环结束才除以 ℓ，并把前向保存量整理为 log-sum-exp，减少反复 rescale、除法与其他非 matmul FLOPs。
  2. 让 thread blocks 也沿序列维并行。FA1 主要按 batch×heads 划分 thread blocks；小 batch、少 heads、长序列时并行度不足。FA2 将不同 Query row blocks 分给不同 thread blocks，使这些形状也能占满更多 SM。
  3. 从 sliced‑K 改为 sliced‑Q。FA1 让一个 thread block 内的 warps 共享 Q、各自处理 K/V 子块，最后必须通过 shared memory 汇总部分输出。FA2 让 warps 共享 K/V、各自处理不同 Q 行；每个 warp 写不重叠的输出，显著减少 warp 间归约与 shared-memory 通信。

它对“推理加速”的意义要分 Prefill 与 Decode

训练与长提示 Prefill 中，Query 长度和 KV 长度都很大，n×n 精确注意力是主工作量，FA1/FA2 的分块、融合与低 IO 能直接改善显存占用和墙钟时间。单 token 自回归 Decode 中，Query 长度只有 1，本来就没有完整 n×n 激活；瓶颈通常转为读取不断增长的 KV Cache。FA2 家族可以成为带 KV Cache 推理 kernel 的组成部分，但此时 paged KV、缓存布局、MQA/GQA/MLA 与专门的 Decode 调度往往比“是否避免 n×n 矩阵”更关键。

归类边界：FlashAttention 不减少可见 token、不压缩 KV Cache，也不把历史压成固定状态。它能与 MHA、GQA、MLA 以及块稀疏注意力组合；所以它应该画在“工程实现层”，而不是 MHA→Sparse/Linear 的结构替代链上。

MQA / GQA：先砍 KV heads

MQA 保留多个 Query heads，却让全部 Query 共享一组 K/V。它大幅减少 Decode 时的缓存读取，但共享过强可能损失表达能力。GQA 让一组 Query heads 共享一组 K/V，在 MHA 与 MQA 之间取折中。GQA 论文还给出了从既有 MHA checkpoint 上训练转换的方案。

容易误解的点：MQA/GQA 显著减少 KV Cache 和内存带宽，但 Query heads 仍要和全部历史位置做 Softmax 注意力；它们没有把 Prefill 的序列复杂度从 O(n²) 变成 O(n)。

2. MLA：不再按 head 缓存 K/V，而是缓存联合 latent

压缩的是表示维，而不是序列维。

ctKV=WDKVht ktC=WUKctKV,vtC=WUVctKV

白话翻译：先把一个 token 的隐藏状态压成低维联合 latent c，K 与 V 都从它恢复。推理时只缓存 c；上投影还能通过矩阵结合律吸收到 Query 与输出投影。

  1. 联合下投影。同一个 hidden state 先映射到低维 cKV，K/V 不再各自保存完整多头向量。
  2. 推理缓存 latent。每个历史 token 只存 cKV；DeepSeek‑V2 报告的具体配置相对 DeepSeek 67B 将 KV Cache 减少 93.3%，这个数字不是 MLA 的固定压缩率。
  3. 权重吸收。利用矩阵乘法结合律，把 K 上投影吸进 Query 路径，把 V 上投影吸进输出路径，避免 Decode 时为所有历史 token 反复还原完整 K/V。
  4. 解耦 RoPE。位置旋转矩阵随位置变化，不能直接被固定权重吸收。MLA 因此把内容 K/Q 和较小的位置 K/Q 分支拆开。

MLA 的关键收益集中在 Decode 带宽与缓存容量。当前 Query 依旧会和全部历史 latent 交互，所以它是“低维缓存的 Dense Attention”，不是 Sparse，也不是 Linear。后续 TPA 等方法继续从张量分解角度压缩 Q/K/V，并尝试更自然地兼容 RoPE，但工程采用广度仍要和 MLA/GQA 分开看。

DeepSeek‑V2 同时报告 5.76× 最大生成吞吐提升，但它来自整套模型与部署配置，不能把 5.76× 当作换上 MLA 就必然得到的通用倍率。

3. 稀疏注意力：历史 token 还在，但每次只读一部分

核心仍是 Softmax；变化的是可见集合与数据访问方式。

ot=Attention(qt,KSt,VSt),|St|=k≪n

白话翻译：历史 K/V 通常还在，但当前 Query 只读取选择集合 Sₜ 中的 k 个 token 或 block。省下的是主注意力读取量；选择器本身也有成本。

第一阶段：固定稀疏模式

Longformer 用局部窗口加任务相关的全局 token；BigBird 组合局部、随机和全局连接。规则固定后，复杂度可写成 O(nw)，实现也相对规整。缺点同样直接：如果重要远程 token 没落在规则覆盖范围里，它就没有机会被读取。

DSA：token 级 Lightning Indexer + Sparse MLA

It,s=∑j=1HIwt,jIReLU(qt,jIksI,T) St=TopKs(It,s,k),Lindex=KL(At∥softmax(It))

白话翻译：每个 Query 产生多个低维索引头，和历史共享 Index Key 做 ReLU 点积，再由查询相关权重合成分数。Top‑k 是离散选择，因此 Indexer 用 KL 辅助目标去模仿主注意力的跨 head 汇总分布。

1. Indexer 怎样打分

DSA 为当前 token 生成 HI 个低维 Index Query heads，却只为每个历史 token 生成一个共享 Index Key。每个 head 先做点积与 ReLU，再由当前 Query 产生的权重 wt,j 加权求和。与单个余弦 router 相比，多头能用不同子空间提取“值得精算”的候选；共享 Key 又把历史端缓存压得很小。

Indexer 得到全部因果历史位置的分数后选择 Top‑k。DeepSeek‑V3.2 的公开配置是 k=2048。随后不是把普通 MHA 直接 mask，而是在 MLA 的 MQA mode 中让多个 Query heads 共享被选 MLA latent 的 K/V 表示，再由 Sparse MLA kernel 做正式 Softmax。

2. 为什么需要两阶段训练

Top‑k 的离散索引不能把主任务梯度自然传回所有候选。DSA 因此先做 Dense warm‑up：冻结主模型，只训练 Indexer，让其 Softmax 分布用 KL loss 模仿主注意力跨 heads 汇总、L1 归一化后的目标。官方配方为 1000 steps、每步 16×128K 序列，共约 2.1B tokens。

第二阶段进入 Sparse adaptation：主模型用 Top‑2048 稀疏注意力适配，Indexer 仍只由辅助 KL 目标更新；其输入 hidden state 会 detach，防止辅助目标反向扭曲主干。官方报告给出 15000 steps、每步 480×128K 序列、累计 943.7B tokens。也就是说，DSA 不是可随手插入已有 checkpoint 的无训练 mask，而是一套结构、目标和 Kernel 联合训练方案。

3. 复杂度与真正瓶颈

被选后的主注意力是 O(Lk)，但低维 Indexer 仍让每个 Query 扫描全部历史，其渐进复杂度是 O(L²)。DSA 的工程赌注是：Indexer head 少、维度小、可用 FP8，而昂贵的 MLA 内容计算只留给 2048 个 token。代价是 token 级地址较离散，KV gather、排序与 Indexer recall 都会影响端到端延迟和质量。

MoBA：把 KV block 当作 MoE 专家

bi=1|Ii|∑s∈Iiks,si=qtTbi St=TopKi<current(si,k−1)∪{current}

白话翻译：每个 KV block 用 Key 均值当路由代表；Query 选 k−1 个历史块，并总是加上自己的当前块。当前块不能靠均值参与选择，而且块内仍需因果 mask，否则均值会泄露未来 token。

1. 路由器没有额外参数

MoBA 把连续 KV 序列切成大小为 B 的 blocks，用每块 Key 的均值充当路由表示。Query 与这些均值做点积，选出 k−1 个历史 blocks，再无条件加入 Query 所在的当前 block。正式注意力仍使用原始 token 级 K/V，因此路由阶段是粗粒度判断，内容计算仍保留块内细节；它和 Full Attention 共用同一套 Q/K/V 参数，可以按阶段或按层切换。

2. 当前块为何必须特殊处理

当前 block 的 Key 均值可能包含 Query 之后的 token，不能拿来参与普通历史路由，否则会泄露未来信息。MoBA 将当前 block 视为类似 MoE 的 shared expert：始终激活，但正式块内 attention 继续使用 causal mask；未来 blocks 完全禁止，历史 blocks 才参与 Top‑k。

3. 从稀疏图到 GPU Kernel

对每个 Query 直接 gather 多个 blocks 仍不理想。MoBA 的实现反过来按被选 KV block 对 Queries 分组和重排：同一块 K/V 只需连续加载，当前块与历史块分别调用 variable‑length FlashAttention，最后通过 online Softmax 把局部归一化结果合并。这样把“动态路由”变成了更规整的 block 级批处理。

4. 复杂度与训练折中

主注意力访问 k 个、每个 B tokens 的块，约为 O(nkB)；但 Query 对 n/B 个块摘要的路由约为 O(n²/B)。固定 B、k 时，主干随 n 线性，router 仍有二次/B 项；若为了固定稀疏率而让 B 随 n 增大，主干本身也会恢复二次增长，只是常数更小。

论文示例 B=512、k=3，对 8K 和 32K 上下文的最大可见比例分别为 18.75% 与 4.69%。预训练配方用前 90% tokens 的 MoBA，再用末 10% Full Attention；SFT 中还讨论了按层混合，因为 prompt loss masking 会进一步减少稀疏层收到的监督。这些是论文设置，不是所有模型的固定超参数。

NSA：压缩、选择、窗口三路原生稀疏

ot*=∑c∈{cmp,slc,win}gtc·Attention(qt,K~tc,V~tc)

白话翻译：cmp 看压缩后的全局概览，slc 取回被选 block 的原始 K/V，win 始终保留近期窗口。三个分支不是拼在一张 mask 里，而是分别计算后由输入相关 gate 加权。

1. Compression：先建立可学习的全局概览

NSA 用长度 l、步长 d 的滑动块压缩历史，块内不做简单平均，而是用带位置编码的 MLP 学习聚合 K/V；常见 d<l，因此相邻压缩块重叠。当前 Query 对压缩 K 做注意力，直接得到粗粒度全局输出，同时产生后续 selection 可复用的注意力分数。

2. Selection：用概览分数定位，再取回原始细节

压缩块与细粒度选择块可以使用不同边界。NSA 根据两者在序列上的空间覆盖关系，把压缩注意力分数映射、汇总成原始 block importance；在同一 GQA group 内再跨 Query heads 求和，选择 Top‑n blocks，并从显存取回这些 blocks 的原始 K/V 做精确 attention。它省掉了独立 router 的一套相似度计算，但 selection 质量受 compression 分支能否正确概览影响。

3. Window 与 gate：为什么近期信息要单独成支

第三条分支始终读取最近 w 个原始 tokens。把它单列出来，不仅保证局部语法和短程模式，也避免 compression/selection 通过反复选择近期块“走捷径”。三支分别 Softmax 后，由 Query 产生的三个 sigmoid gate 加权求和；它们不是简单合并成一张稀疏 mask。

4. Native 的含义：从训练到 Kernel 一起设计

论文 27B 配置使用 l=32、d=16、选择块 l′=64、n=16、窗口 w=512，并在 GQA 组内共享选择。Triton kernel 以 block 为单位加载共享的连续 KV 到 SRAM，让多个 Query heads 复用。论文自身训练设置下，NSA 在其通用评测平均分和 LongBench 平均分上分别报告 0.456 与 0.469，对应 Full Attention 基线为 0.443 与 0.437；这只能说明原生训练的 NSA 在该设置下没有出现明显质量坍塌，不能推导成对任意 Dense checkpoint 的无损替换。

复杂度同样要逐支看：窗口约 O(nw)，selection 主干约 O(n·nsel·l′)，compression 若固定步长 d 仍可能带 O(n²/d) 项。NSA 的收益来自低分辨率全局扫描、有限细粒度 blocks 与硬件友好访问的组合，而不是数学上把整层严格化为 O(n)。

第三阶段：DeepSeek‑V4 先压缩序列，再做稀疏与稠密混合

V4 的 CSA 每 4 个 token 形成一个加权压缩 KV，Indexer 只在压缩条目上打分，然后读取 Top‑512（Flash）或 Top‑1024（Pro）。HCA 每 128 个 token 压成一个 KV，不做 Top‑k，而是对全部压缩 KV 做 Dense MQA。两者都再接一条最近 128 token 的滑动窗口。

所以 V4 不是“DSA 原样升级”，更准确的说法是：时间维压缩 + 压缩条目稀疏检索 + 重压缩全局稠密读取 + 局部窗口。它也不是严格线性复杂度：当压缩率固定，CSA Indexer 约为 O(n²/4)，HCA 约为 O(n²/128)。它通过巨大的常数压缩、较小 Top‑k、FP4/FP8 与专用 kernel 获得实际效率。

4. 固定状态路线：线性注意力与 SSM 在 Mamba‑2 / SSD 处汇流

两条研究路线共享“固定状态”，但起点、状态含义与更新规则并不相同。

先回答“Mamba 是否是线性注意力起点”：不是。Linear Transformer 与 Performer 在 2020 年已经建立核技巧 / fast-weight 路线；Mamba 于 2023 年从结构化状态空间模型（SSM）路线发展而来。2024 年 Mamba‑2 的 Structured State Space Duality（SSD）证明了某些 SSM 与结构化掩码注意力可以是同一序列算子的不同计算形式。这是“理论桥梁”，不是“Mamba 属于线性注意力”或“DeltaNet 继承自 Mamba”。

第一步：核线性注意力用乘法结合律消掉 n² 中间矩阵

St=St−1+φ(kt)vtT zt=zt−1+φ(kt) ot=φT(qt)StφT(qt)zt

白话翻译：每到一个 token，就把它的 Key–Value 外积写进状态 S，并累计归一化向量 z；当前 Query 只读这两个固定大小状态，不再逐个扫描历史 token。

经典 Linear Transformer 用正值特征映射 φ 把相似度写成 φ(Q)φ(K)T。原本先算 QKT 会产生 n×n 矩阵；改成先累计 φ(K)TV，就只需维护一个与序列长度无关的矩阵状态。因果生成时，这个结合律自然变成逐 token 递推。

Performer 的 FAVOR+ 用正交随机特征近似 Softmax kernel。它们把 Prefill 对序列长度的增长降为线性，也让 Decode 不再扫描整段 KV Cache；代价是所有历史关联被压入有限状态，精确复制、多 Key 检索和复杂 in-context learning 容易发生干扰。这里的“线性”指对序列长度 n 的复杂度，不代表状态矩阵本身很小：每个 head 常需 Dk×Dv 个元素。

第二步：Mamba 是并行 SSM 路线；Mamba‑2 / SSD 才是对偶桥梁

(Δt,Bt,Ct)=fθ(xt) A¯t=exp(ΔtA),B¯t=discretize(Δt,A,Bt) ht=A¯tht−1+B¯txt,yt=Ctht

白话翻译：Mamba 仍是状态空间递推，但步长 Δ、写入 B、读取 C 会随当前输入变化；模型因此能选择“哪些内容进入状态、保留多久、怎样读出”。这里没有 QKT 或 Key–Value 外积，所以不能仅凭“固定状态、线性时间”就把它叫作线性注意力。

1. Mamba 的选择性到底是什么

传统线性时不变 SSM 用固定 A、B、C 推进状态，适合卷积式并行，却难以根据内容决定何时记住或忽略。Mamba 让离散步长 Δ、输入映射 B 和读出映射 C 依赖当前 token；同一个词在不同上下文中可以触发不同的写入与遗忘强度。由于这些参数随时间变化，模型不能再直接使用一条固定全局卷积核，Mamba 因而设计 hardware-aware selective scan，在不物化全部中间状态的情况下计算递推。

关键边界是：Mamba 状态通常写成 ht=Ātht−1+B̄txt，状态通道来自动力系统；核线性注意力则显式把 ktvtT 写入关联记忆，再由 qt 读取。二者都有 O(n) scan 和 O(1) 随上下文增长的状态，却不是同一个机制。

2. Mamba‑2 / SSD 为什么让两边看起来越来越像

Mamba‑2 的 SSD 框架先把 SSM 展开成作用于序列维的半可分离（semiseparable）矩阵。于是同一个结构化算子可以有两种执行顺序：递归形式逐步传播状态，时间为 O(n)；二次形式显式表现为带结构化 mask 的 token×token 交互，更像 attention。反过来，特定的 1-semiseparable structured masked attention 也能收缩成线性递推。

准确结论：SSD 证明的是“特定 scalar-identity SSM 与特定 1-semiseparable masked attention 的交集”。它提供统一数学语言与块并行算法，但没有证明所有 SSM 都是 attention，也没有把 Softmax MHA、Mamba、DeltaNet 三者变成同一架构。

第三步：RetNet / GLA 给关联状态加入可学习遗忘

简单累加会让旧信息永远留在状态里。RetNet 提供 parallel、recurrent、chunkwise recurrent 三种计算视角；GLA 引入输入相关的逐通道门控，并设计硬件友好的 chunkwise 算法。门控让模型知道哪些状态通道该变淡，但“当前 Key 已经映射到旧 Value 时应如何更新”仍需要更明确的规则。

第四步：DeltaNet / Gated DeltaNet 把状态变成可纠错的键值表

St¯=αtSt−1 pt=S¯tTkt,δt=βt(vt−pt) St=St¯+ktδtT

白话翻译：α 控制整体保留多少旧记忆；先用 Key 从旧状态读出预测，再只把“真实 Value − 旧预测”的误差按 β 写回。这样同一 Key 再出现时更像改写，而不是叠加冲突。

DeltaNet 可从在线学习理解：令状态 S 是一个把 Key 映射到 Value 的快速权重矩阵，当前重构损失为 ½‖STkt−vt‖²；沿负梯度走一步，就得到 rank‑1 Delta update。它不是把 ktvtT无条件累加，而是先查询当前映射 pt，只写 βt(vt−pt)。

Gated DeltaNet（GDN） 再加每 token、每 head 的标量 αt，在纠错之前整体衰减旧状态。矩阵形式为 St=αt(I−βtktktT)St−1+βtktvtT：α 管“整块记忆活多久”，β 管“当前映射改多少”。DeltaNet 论文还给出基于 Householder 矩阵乘积的序列并行算法，使这种递推可用于常规语言模型训练，而不必真的用 Python 从头循环到尾。

第五步：Kimi Delta Attention（KDA）单开一节——逐通道衰减 + 受约束 DPLR

St¯=Diag(α→t)St−1 pt=S¯tTkt,δt=βt(vt−pt) St=St¯+ktδtT At=Diag(α→t)−βtkt(kt⊙α→t)T

白话翻译：GDN 的 α 是“整个 head 一只总闸”，KDA 的 α⃗ 是一排 key-channel 闸门。先逐通道衰减，再读旧预测并写误差；展开后的状态转移是“对角矩阵减一个 rank‑1 项”，因此既比标量门细，也保留了专用 DPLR chunk kernel 的实现空间。

1. 它具体改了 GDN 的哪一个门

GDN 的 αt 是标量：一个 head 中所有 key channels 以同一速度衰减。KDA 把它改成 α⃗t∈[0,1]Dk，并以 Diag(α⃗t) 左乘状态。状态的每一行对应一个 key/address 通道，因此模型可以长期保留某些地址、快速清理另一些地址，而不是整块一起淡出。论文使用低秩投影从 xt 生成这组衰减，Q/K 经过短卷积、Swish 与 L2 normalization，β 仍是每 head 的标量 Delta 学习率。

2. 为什么它叫受约束的 DPLR 转移

把 KDA 递推展开，旧状态前的转移矩阵为 At=Diag(α⃗t)−βtkt(kt⊙α⃗t)T：一个对角矩阵减一个 rank‑1 项，即 diagonal-plus-low-rank。通用 DPLR 可以使用彼此独立的低秩向量，表达力更自由但 chunkwise 计算代价高。KDA 把两个低秩方向约束到同一个 Key 结构，既贴近经典 Delta rule，也让累积衰减可以提出公因子，减少二级分块与若干矩阵乘法。

3. 训练、Prefill 与 Decode 为什么不是同一个 kernel

Decode 最自然：每个 head 保存一个 Dk×Dv 状态，每来一个 token 就做逐通道衰减、一次读取和一次 rank‑1 更新，成本与历史长度无关。Prefill / 训练则把序列分块，块内把一串对角加 rank‑1 转移压成适合 Tensor Core 的稠密运算，块间只传状态。Kimi Linear 论文给出的单头、chunk size C=64 理论式为 6nDh²+3nCDh+nC²；它对 n 线性，但常数仍取决于状态维和 chunk 大小。

4. KDA 仍然为什么要与 MLA 混合

逐通道门提高了有限状态的记忆管理能力，却没有恢复逐 token 精确地址。Kimi Linear 因而采用层间 3 个 KDA : 1 个 full MLA：多数层用固定状态混合，周期性 MLA 层重新访问完整显式历史。论文在其 48B、相同训练配方的比较中报告 1M 上下文下相对 full MLA 最多约 75% KV Cache 降低与最高约 6× Decode 吞吐提升；这些是该模型、kernel、硬件与 batch 设置下的结果，不是 KDA 的固定倍率。

5. 教学代码实现了什么，省略了什么

KimiDeltaAttention 严格按“Diag(α⃗) 衰减 → k 读预测 → β(v−prediction) 纠错”的 recurrent 方程实现，并用低秩投影产生逐通道 α⃗。它故意省略 ShortConv、head-wise RMSNorm、输出 gate 与生产 chunkwise DPLR kernel，以便逐行对应公式；因此可用于理解、因果性与梯度检查，不能作为 Kimi Linear 性能复现。

2026 年的 Gated DeltaNet‑2 沿另一方向继续细化：把“擦除旧关联”和“提交新 Value”拆成独立逐通道 gate。它与 KDA 都是在提高固定状态的可编辑性，但参数化和状态转移并不相同，也不应把两者视为别名。

Qwen3.5 的“GDA”：官方实现名是 Gated DeltaNet（GDN）

gt=−exp(Alog)·softplus(at+bdt),αt=exp(gt) St¯=αtSt−1,δt=βt(vt−ktTSt¯) St=St¯+ktδtT,ot=qtTSt

白话翻译：a 决定整块记忆衰减多快，b 经 sigmoid 得到 Delta 写入强度 β；先衰减、再读取旧映射、最后只写预测误差。矩阵转置方向可因实现布局不同而反过来，但“衰减—读旧值—写误差”的语义相同。

先校正术语：Qwen3.5 官方博客、模型卡、配置和 Transformers 类名都写 Gated DeltaNet / GDN。社区有时口头写成 GDA，可理解为“Gated Delta Attention”，但它不是 Qwen3.5 中另一个独立模块；本文代码类名因此使用 Qwen35GatedDeltaNet。

1. 先用短卷积补局部顺序，再进入固定状态

单层先做联合 Q/K/V 投影，再对所有通道做 kernel size 4 的 depthwise causal Conv1d 和 SiLU。线性状态善于长程汇总，却没有 Softmax 局部邻接那样直接的短程归纳偏置；短卷积以常数成本补入最近几个 token 的顺序模式。z、a、b 从原始层输入独立投影，分别控制输出、衰减时间尺度和 Delta 写入强度。

2. α 与 β 分别解决什么

g=−exp(Alog)·softplus(a+dt_bias) 恒为非正，所以 α=exp(g) 位于 (0,1]：它决定整个 Value head 的旧状态保留多少。β=sigmoid(b) 决定当前误差写入多少。状态先乘 α，再以归一化 Key 读旧 Value，最后写入 β×(新 Value−旧预测)。因此 α 是“多久忘”，β 是“这次改多少”，两者不能合成一个含义。

3. 为什么 Q/K heads 与 Value heads 数量不同

Qwen3.5‑4B 的 GDN 使用 16 个 QK heads、32 个 Value heads，Key/Value head dim 都是 128。实现按组把 Q/K 重复到 Value head 数，每个 Value head 维护一个 [Dk,Dv] 状态；Q/K 先 L2 normalize，Q 再按 √Dk 缩放。这样可以降低生成地址的投影宽度，又保留更宽的 Value/状态容量。状态总大小随 heads 与 DkDv 增长，但与上下文长度 n 无关。

4. 输出端为什么还有 z gate

状态读取结果先沿 Value 维做 RMSNorm，再逐元素乘 SiLU(z)，最后经输出投影回到模型维度。这个 gate 控制当前 token 从线性记忆读出的内容有多少进入残差流；它和 α 的状态遗忘、β 的状态写入处在三个不同位置。

5. Qwen3.5 不是纯线性模型

以官方 Qwen3.5‑4B 为例，32 层按 8×(3 个 GDN 层 + 1 个 Gated Attention 层) 排布，full_attention_interval=4。完整注意力层采用 16 个 Query heads、4 个 KV heads、head dim 256，并只在部分通道施加 RoPE。GDN 让 75% 的混合层用固定 recurrent state；每第 4 层的显式 GQA attention 保留精确 token 地址，因此整个模型仍有随 n 增长的 KV Cache，也不能把全模型 Prefill 宣称为严格 O(n)。

上面的公式最适合解释自回归 Decode：每步更新一次状态。训练若逐 token Python 循环会很慢，实际实现使用 chunkwise parallel / fused recurrent kernel，在块内并行、块间传递状态。配套 Python 代码故意使用顺序循环来暴露每次衰减、读取与改写，并明确标注它不是性能实现。

5. 为什么 2026 年前沿都走向混合

固定状态负责便宜地传播，显式注意力负责偶尔精确地查。

Kimi Linear 先采用 3 层 KDA + 1 层 full MLA 的层间比例；Kimi K3 延续为每个 block 3 层 KDA + 1 层 Gated MLA，骨干末尾还保证有一层全局 Gated MLA。KDA 让长序列混合与 Decode 状态保持固定；MLA 周期性保留不受固定状态容量约束的全局交互。

Qwen3.5 也采用 3:1 节奏，但原语不同：3 层 Gated DeltaNet 后接 1 层 Gated Attention。短卷积 + GDN 负责局部与固定状态混合，周期性 GQA attention 重新访问显式 token 地址。这解释了它为什么既能让多数层的 Decode 状态不随 n 增长，又仍保留长上下文精确检索的校准层。

DeepSeek‑V4 选择的是另一种混合：CSA 保留较细的远程条目并做动态稀疏检索，HCA 提供更粗但无 Top‑k 漏选的全局背景，SWA 保留最近细节。三者共同说明：高效注意力的设计重点，已经从“发明一个统一替代品”转为“给不同类型的记忆分配不同预算”。

from __future__ import annotations

import math
from dataclasses import dataclass
from typing import Callable

import torch
from torch import Tensor, nn
import torch.nn.functional as F


def _split_heads(x: Tensor, num_heads: int) -> Tensor:
    """[B, T, H*D] -> [B, H, T, D]."""
    batch, seq_len, width = x.shape
    if width % num_heads != 0:
        raise ValueError(f"width={width} must be divisible by heads={num_heads}")
    head_dim = width // num_heads
    return x.view(batch, seq_len, num_heads, head_dim).transpose(1, 2)


def _merge_heads(x: Tensor) -> Tensor:
    """[B, H, T, D] -> [B, T, H*D]."""
    batch, heads, seq_len, head_dim = x.shape
    return x.transpose(1, 2).contiguous().view(batch, seq_len, heads * head_dim)


def _causal_forbidden(seq_len: int, device: torch.device) -> Tensor:
    """布尔 mask；True 表示该 query-key 对不可见。"""
    return torch.ones(seq_len, seq_len, dtype=torch.bool, device=device).triu(1)


def _masked_softmax_attention(q: Tensor, k: Tensor, v: Tensor, forbidden: Tensor) -> Tensor:
    """显式缩放点积注意力，供教学实现复用。"""
    scale = 1.0 / math.sqrt(q.shape[-1])
    scores = torch.matmul(q, k.transpose(-2, -1)) * scale
    scores = scores.masked_fill(forbidden, float("-inf"))
    weights = torch.softmax(scores.float(), dim=-1)
    # 某些稀疏分支在序列开头可能一个历史块都没有。全 -inf 的一行会产生
    # NaN；这里把它变成全 0，使该分支在这个位置贡献 0。
    weights = torch.nan_to_num(weights, nan=0.0).to(scores.dtype)
    return torch.matmul(weights, v)


class MultiHeadAttention(nn.Module):
    """标准因果 MHA：每个 Query head 都有独立的 K/V head。"""

    def __init__(self, d_model: int, num_heads: int) -> None:
        super().__init__()
        if d_model % num_heads != 0:
            raise ValueError("d_model must be divisible by num_heads")
        self.num_heads = num_heads
        self.qkv = nn.Linear(d_model, 3 * d_model, bias=False)
        self.out_proj = nn.Linear(d_model, d_model, bias=False)

    def forward(self, x: Tensor) -> Tensor:
        _, seq_len, _ = x.shape
        q, k, v = self.qkv(x).chunk(3, dim=-1)
        q = _split_heads(q, self.num_heads)
        k = _split_heads(k, self.num_heads)
        v = _split_heads(v, self.num_heads)

        # [T, T] 会自动广播到 batch 和 head 两个维度。
        forbidden = _causal_forbidden(seq_len, x.device)
        y = _masked_softmax_attention(q, k, v, forbidden)
        return self.out_proj(_merge_heads(y))


class FlashAttentionReference(nn.Module):
    """FlashAttention v1/v2 核心数学的可读参考实现。

    它把 Query 和 KV 切成小块，并为每个 Query 行维护三项在线 Softmax 统计：

    * ``row_max``：目前见过的最大 score；
    * ``row_sum``：在 ``row_max`` 基准下的指数和；
    * ``numerator``：尚未除以 ``row_sum`` 的加权 Value 和。

    因此无需在任一时刻生成完整 ``[T, T]`` score / probability 矩阵，输出却与
    标准 Softmax attention 等价。FlashAttention v1 的核心贡献是 IO-aware
    tiling、online Softmax 与反向重计算；v2 沿用同一结果，进一步减少非矩阵
    乘法、把 thread blocks 扩展到序列维，并用 sliced-Q 降低 warp 间通信。

    注意：这里的高层 PyTorch 循环不会更快。真正的加速来自 fused CUDA/Triton
    kernel 将这些块和统计量留在寄存器 / SRAM 中，并避免往返 HBM。
    """

    def __init__(
        self,
        d_model: int,
        num_heads: int,
        q_block_size: int = 64,
        kv_block_size: int = 64,
    ) -> None:
        super().__init__()
        if d_model % num_heads != 0:
            raise ValueError("d_model must be divisible by num_heads")
        if q_block_size <= 0 or kv_block_size <= 0:
            raise ValueError("block sizes must be positive")
        self.num_heads = num_heads
        self.q_block_size = q_block_size
        self.kv_block_size = kv_block_size
        self.qkv = nn.Linear(d_model, 3 * d_model, bias=False)
        self.out_proj = nn.Linear(d_model, d_model, bias=False)

    def forward(self, x: Tensor) -> Tensor:
        _, seq_len, _ = x.shape
        q, k, v = self.qkv(x).chunk(3, dim=-1)
        q = _split_heads(q, self.num_heads)
        k = _split_heads(k, self.num_heads)
        v = _split_heads(v, self.num_heads)
        scale = 1.0 / math.sqrt(q.shape[-1])

        output_blocks: list[Tensor] = []
        for q_start in range(0, seq_len, self.q_block_size):
            q_end = min(q_start + self.q_block_size, seq_len)
            q_block = q[:, :, q_start:q_end].float()

            # FP32 累加对应生产 kernel 中对 Softmax 统计量的高精度维护。
            row_max = torch.full(
                (*q_block.shape[:-1],),
                -torch.inf,
                dtype=torch.float32,
                device=x.device,
            )
            row_sum = torch.zeros_like(row_max)
            numerator = torch.zeros(
                *q_block.shape[:-1],
                v.shape[-1],
                dtype=torch.float32,
                device=x.device,
            )

            # 因果注意力中，本 Query block 不可能读取 q_end 之后的 Key block。
            for kv_start in range(0, q_end, self.kv_block_size):
                kv_end = min(kv_start + self.kv_block_size, q_end)
                k_block = k[:, :, kv_start:kv_end].float()
                v_block = v[:, :, kv_start:kv_end].float()
                scores = torch.matmul(q_block, k_block.transpose(-2, -1)) * scale

                # 使用全局 token 位置做块内因果 mask，而不是假设两类 block 对齐。
                q_pos = torch.arange(q_start, q_end, device=x.device)
                kv_pos = torch.arange(kv_start, kv_end, device=x.device)
                future = kv_pos.unsqueeze(0) > q_pos.unsqueeze(1)
                scores = scores.masked_fill(future, -torch.inf)

                # Online Softmax：新块出现更大 score 时，先把旧统计量换基准。
                block_max = scores.max(dim=-1).values
                new_max = torch.maximum(row_max, block_max)
                old_scale = torch.exp(row_max - new_max)
                exp_scores = torch.exp(scores - new_max.unsqueeze(-1))
                exp_scores = torch.nan_to_num(exp_scores, nan=0.0)

                row_sum = old_scale * row_sum + exp_scores.sum(dim=-1)
                numerator = (
                    old_scale.unsqueeze(-1) * numerator
                    + torch.matmul(exp_scores, v_block)
                )
                row_max = new_max

            output_blocks.append((numerator / row_sum.unsqueeze(-1)).to(q.dtype))

        y = torch.cat(output_blocks, dim=2)
        return self.out_proj(_merge_heads(y))


class GroupedQueryAttention(nn.Module):
    """GQA；令 ``num_kv_heads=1`` 就得到 MQA。

    Query head 被分组，每组共享一个 K/V head。这里用 ``repeat_interleave``
    只是为了把张量关系写清楚；优化 kernel 不会真的复制共享 K/V。
    """

    def __init__(self, d_model: int, num_q_heads: int, num_kv_heads: int) -> None:
        super().__init__()
        if d_model % num_q_heads != 0:
            raise ValueError("d_model must be divisible by num_q_heads")
        if num_q_heads % num_kv_heads != 0:
            raise ValueError("num_q_heads must be divisible by num_kv_heads")

        self.num_q_heads = num_q_heads
        self.num_kv_heads = num_kv_heads
        self.head_dim = d_model // num_q_heads
        self.q_proj = nn.Linear(d_model, num_q_heads * self.head_dim, bias=False)
        self.k_proj = nn.Linear(d_model, num_kv_heads * self.head_dim, bias=False)
        self.v_proj = nn.Linear(d_model, num_kv_heads * self.head_dim, bias=False)
        self.out_proj = nn.Linear(d_model, d_model, bias=False)

    def forward(self, x: Tensor) -> Tensor:
        _, seq_len, _ = x.shape
        q = _split_heads(self.q_proj(x), self.num_q_heads)
        k = _split_heads(self.k_proj(x), self.num_kv_heads)
        v = _split_heads(self.v_proj(x), self.num_kv_heads)

        repeats = self.num_q_heads // self.num_kv_heads
        k = k.repeat_interleave(repeats, dim=1)
        v = v.repeat_interleave(repeats, dim=1)

        forbidden = _causal_forbidden(seq_len, x.device)
        y = _masked_softmax_attention(q, k, v, forbidden)
        return self.out_proj(_merge_heads(y))


class LatentKVAttention(nn.Module):
    """MLA 联合低秩 K/V 压缩的教学版。

    真正需要缓存的是 ``c_kv = kv_down(x)``，形状为 [B, T, R]，其中 R 远小于
    ``2 * H * D``。为了易读，这里显式还原 K/V；生产 MLA 会把上投影吸收到
    Query/输出投影里，并用独立位置分支承载 RoPE。
    """

    def __init__(self, d_model: int, num_heads: int, latent_dim: int) -> None:
        super().__init__()
        if d_model % num_heads != 0:
            raise ValueError("d_model must be divisible by num_heads")
        if latent_dim >= 2 * d_model:
            raise ValueError("latent_dim should be smaller than the full K/V width")

        self.num_heads = num_heads
        self.q_proj = nn.Linear(d_model, d_model, bias=False)
        self.kv_down = nn.Linear(d_model, latent_dim, bias=False)
        self.k_up = nn.Linear(latent_dim, d_model, bias=False)
        self.v_up = nn.Linear(latent_dim, d_model, bias=False)
        self.out_proj = nn.Linear(d_model, d_model, bias=False)

    def cache_latent(self, x: Tensor) -> Tensor:
        """返回自回归服务端可按 token 缓存的低维 latent。"""
        return self.kv_down(x)

    def forward(self, x: Tensor) -> Tensor:
        _, seq_len, _ = x.shape
        c_kv = self.cache_latent(x)
        q = _split_heads(self.q_proj(x), self.num_heads)
        k = _split_heads(self.k_up(c_kv), self.num_heads)
        v = _split_heads(self.v_up(c_kv), self.num_heads)

        forbidden = _causal_forbidden(seq_len, x.device)
        y = _masked_softmax_attention(q, k, v, forbidden)
        return self.out_proj(_merge_heads(y))


class SlidingWindowAttention(nn.Module):
    """固定窗口的因果局部注意力。

    本实现仍生成稠密分数；生产 kernel 只遍历局部块，才会把真实工作量从
    O(T^2) 降到 O(TW)。
    """

    def __init__(self, d_model: int, num_heads: int, window: int) -> None:
        super().__init__()
        if window < 1:
            raise ValueError("window must be positive")
        if d_model % num_heads != 0:
            raise ValueError("d_model must be divisible by num_heads")
        self.num_heads = num_heads
        self.window = window
        self.qkv = nn.Linear(d_model, 3 * d_model, bias=False)
        self.out_proj = nn.Linear(d_model, d_model, bias=False)

    def forward(self, x: Tensor) -> Tensor:
        _, seq_len, _ = x.shape
        q, k, v = self.qkv(x).chunk(3, dim=-1)
        q = _split_heads(q, self.num_heads)
        k = _split_heads(k, self.num_heads)
        v = _split_heads(v, self.num_heads)

        pos = torch.arange(seq_len, device=x.device)
        query_pos = pos[:, None]
        key_pos = pos[None, :]
        allowed = (key_pos <= query_pos) & (key_pos > query_pos - self.window)
        forbidden = ~allowed

        y = _masked_softmax_attention(q, k, v, forbidden)
        return self.out_proj(_merge_heads(y))


class TopKSparseAttention(nn.Module):
    """用轻量可学习 router 为主注意力选择历史 token。

    所有 Query head 共享选择结果，便于形成更连续、更适合硬件的 KV 访问。
    这是算法示意，不是高性能稀疏 kernel。
    """

    def __init__(self, d_model: int, num_heads: int, router_dim: int, top_k: int) -> None:
        super().__init__()
        if d_model % num_heads != 0:
            raise ValueError("d_model must be divisible by num_heads")
        if top_k < 1:
            raise ValueError("top_k must be positive")
        self.num_heads = num_heads
        self.top_k = top_k
        self.router_q = nn.Linear(d_model, router_dim, bias=False)
        self.router_k = nn.Linear(d_model, router_dim, bias=False)
        self.qkv = nn.Linear(d_model, 3 * d_model, bias=False)
        self.out_proj = nn.Linear(d_model, d_model, bias=False)

    def forward(self, x: Tensor) -> Tensor:
        batch, seq_len, _ = x.shape
        causal_forbidden = _causal_forbidden(seq_len, x.device)

        # 低维 indexer/router。DSA 类真实系统会用辅助目标训练它，并以低精度运行。
        rq = F.normalize(self.router_q(x), dim=-1)
        rk = F.normalize(self.router_k(x), dim=-1)
        router_scores = torch.matmul(rq, rk.transpose(-2, -1))
        router_scores = router_scores.masked_fill(
            causal_forbidden, torch.finfo(router_scores.dtype).min
        )

        k_eff = min(self.top_k, seq_len)
        chosen = router_scores.topk(k_eff, dim=-1).indices
        selected = torch.zeros(
            batch, seq_len, seq_len, dtype=torch.bool, device=x.device
        )
        selected.scatter_(-1, chosen, True)
        selected &= ~causal_forbidden.unsqueeze(0)

        q, k, v = self.qkv(x).chunk(3, dim=-1)
        q = _split_heads(q, self.num_heads)
        k = _split_heads(k, self.num_heads)
        v = _split_heads(v, self.num_heads)

        # [B, 1, T, T] 会把共享稀疏模式广播给全部 Query head。
        forbidden = ~selected[:, None, :, :]
        y = _masked_softmax_attention(q, k, v, forbidden)
        return self.out_proj(_merge_heads(y))


class LightningIndexer(nn.Module):
    """DSA 论文中 Lightning Indexer 的可读实现。

    对每个 query token 产生多个低维 indexer query heads，以及每个 head 的
    混合权重；历史 token 只产生一个共享 index key：

        I[t,s] = sum_j w[t,j] * ReLU(q_index[t,j] dot k_index[s])

    DSA 的正式训练会让这个分布模仿主注意力分布。这里显式构造 [T,T]
    分数，只用于理解公式。
    """

    def __init__(self, d_model: int, num_index_heads: int, index_head_dim: int) -> None:
        super().__init__()
        self.num_index_heads = num_index_heads
        self.index_head_dim = index_head_dim
        self.q_proj = nn.Linear(
            d_model, num_index_heads * index_head_dim, bias=False
        )
        self.k_proj = nn.Linear(d_model, index_head_dim, bias=False)
        self.weight_proj = nn.Linear(d_model, num_index_heads, bias=False)

    def forward(self, x: Tensor) -> Tensor:
        batch, seq_len, _ = x.shape
        q = self.q_proj(x).view(
            batch, seq_len, self.num_index_heads, self.index_head_dim
        )
        k = self.k_proj(x)
        w = self.weight_proj(x).permute(0, 2, 1).unsqueeze(-1)

        # [B, H_index, T_query, T_key]
        per_head = torch.einsum("bthd,bsd->bhts", q, k)
        scores = (w * F.relu(per_head)).sum(dim=1)
        scores = scores.masked_fill(
            _causal_forbidden(seq_len, x.device).unsqueeze(0),
            torch.finfo(scores.dtype).min,
        )
        return scores

    @staticmethod
    def distillation_loss(
        index_scores: Tensor,
        dense_attention_weights: Tensor,
        selected_mask: Tensor | None = None,
    ) -> Tensor:
        """KL 目标：让 indexer 模仿跨主注意力 heads 汇总后的分布。

        ``dense_attention_weights`` 的形状为 [B, H, T, T]，应是已经做过
        causal Softmax 的概率。DSA 的稀疏训练阶段可额外传入 [B,T,T] 的
        ``selected_mask``，只在已选 token 集合上对齐。
        """

        teacher = dense_attention_weights.detach().sum(dim=1)
        student = index_scores
        if selected_mask is not None:
            teacher = teacher * selected_mask
            student = student.masked_fill(
                ~selected_mask, torch.finfo(student.dtype).min
            )

        teacher = teacher / teacher.sum(dim=-1, keepdim=True).clamp_min(1e-9)
        log_student = torch.log_softmax(student.float(), dim=-1)
        return F.kl_div(log_student, teacher.float(), reduction="batchmean")


class DSASparseAttention(nn.Module):
    """DeepSeek Sparse Attention（DSA）风格的教学实现。

    - Lightning Indexer 在 token 粒度选 Top-k；
    - 主注意力使用 MLA latent 恢复一组共享 K/V，再广播给多个 Query heads，
      对应论文所说的 MLA MQA mode；
    - indexer 输入默认 detach，体现论文中 indexer 与主模型分开优化的做法。

    真实 DeepSeek-V3.2 会用 FP8 低维 indexer、2048 个被选 token 和专用
    sparse MLA kernel。本实现仍是稠密 mask 参考。
    """

    def __init__(
        self,
        d_model: int,
        num_q_heads: int,
        latent_dim: int,
        num_index_heads: int,
        index_head_dim: int,
        top_k: int,
    ) -> None:
        super().__init__()
        if d_model % num_q_heads != 0:
            raise ValueError("d_model must be divisible by num_q_heads")
        if top_k < 1:
            raise ValueError("top_k must be positive")

        self.num_q_heads = num_q_heads
        self.head_dim = d_model // num_q_heads
        self.top_k = top_k
        self.indexer = LightningIndexer(
            d_model, num_index_heads, index_head_dim
        )
        self.q_proj = nn.Linear(d_model, d_model, bias=False)
        self.kv_down = nn.Linear(d_model, latent_dim, bias=False)
        self.k_up_shared = nn.Linear(latent_dim, self.head_dim, bias=False)
        self.v_up_shared = nn.Linear(latent_dim, self.head_dim, bias=False)
        self.out_proj = nn.Linear(d_model, d_model, bias=False)

    def forward(
        self, x: Tensor, return_index_scores: bool = False
    ) -> Tensor | tuple[Tensor, Tensor]:
        batch, seq_len, _ = x.shape

        # detach 后，indexer 参数仍可从辅助 KL loss 得到梯度，但它的梯度不会
        # 反向改动主干 hidden state。
        index_scores = self.indexer(x.detach())
        chosen = index_scores.topk(min(self.top_k, seq_len), dim=-1).indices
        selected = torch.zeros(
            batch, seq_len, seq_len, dtype=torch.bool, device=x.device
        )
        selected.scatter_(-1, chosen, True)
        selected &= ~_causal_forbidden(seq_len, x.device).unsqueeze(0)

        q = _split_heads(self.q_proj(x), self.num_q_heads)
        latent = self.kv_down(x)
        k = self.k_up_shared(latent)[:, None].expand(
            -1, self.num_q_heads, -1, -1
        )
        v = self.v_up_shared(latent)[:, None].expand(
            -1, self.num_q_heads, -1, -1
        )
        y = _masked_softmax_attention(q, k, v, ~selected[:, None])
        output = self.out_proj(_merge_heads(y))
        if return_index_scores:
            return output, index_scores
        return output


class MoBABlockSparseAttention(nn.Module):
    """Mixture of Block Attention（MoBA）风格的教学实现。

    KV 被切成连续 blocks。每个 Query 用 ``q dot mean(K_block)`` 给已经完整
    出现的历史 blocks 打分，读取 Top-k 历史 blocks，并无条件读取当前 block。
    当前 block 内仍使用 causal mask，避免 block mean 看见未来造成泄漏。

    ``top_k_blocks`` 按论文口径包含当前 block，因此设为 3 时至多读取
    2 个历史 blocks + 当前 block。
    """

    def __init__(
        self, d_model: int, num_heads: int, block_size: int, top_k_blocks: int
    ) -> None:
        super().__init__()
        if d_model % num_heads != 0:
            raise ValueError("d_model must be divisible by num_heads")
        if block_size < 1 or top_k_blocks < 1:
            raise ValueError("block_size and top_k_blocks must be positive")
        self.num_heads = num_heads
        self.block_size = block_size
        self.top_k_blocks = top_k_blocks
        self.qkv = nn.Linear(d_model, 3 * d_model, bias=False)
        self.out_proj = nn.Linear(d_model, d_model, bias=False)

    def forward(self, x: Tensor) -> Tensor:
        batch, seq_len, _ = x.shape
        q, k, v = self.qkv(x).chunk(3, dim=-1)
        q = _split_heads(q, self.num_heads)
        k = _split_heads(k, self.num_heads)
        v = _split_heads(v, self.num_heads)

        block_ranges = [
            (start, min(start + self.block_size, seq_len))
            for start in range(0, seq_len, self.block_size)
        ]
        block_keys = torch.stack(
            [k[:, :, start:end].mean(dim=2) for start, end in block_ranges],
            dim=2,
        )
        num_blocks = block_keys.shape[2]
        block_scores = torch.einsum("bhtd,bhmd->bhtm", q, block_keys)
        block_scores = block_scores / math.sqrt(q.shape[-1])

        token_pos = torch.arange(seq_len, device=x.device)
        current_block = token_pos // self.block_size
        block_ids = torch.arange(num_blocks, device=x.device)
        historical = block_ids[None, :] < current_block[:, None]
        block_scores = block_scores.masked_fill(
            ~historical[None, None], float("-inf")
        )

        selected_blocks = torch.zeros(
            batch,
            self.num_heads,
            seq_len,
            num_blocks,
            dtype=torch.bool,
            device=x.device,
        )
        history_budget = min(max(self.top_k_blocks - 1, 0), num_blocks)
        if history_budget:
            chosen = block_scores.topk(history_budget, dim=-1).indices
            selected_blocks.scatter_(-1, chosen, True)
            selected_blocks &= historical[None, None]

        # 当前 block 类似 MoE 的 shared expert：始终激活。
        current_one_hot = F.one_hot(current_block, num_blocks).bool()
        selected_blocks |= current_one_hot[None, None]

        token_block_ids = token_pos // self.block_size
        selected_tokens = selected_blocks.index_select(-1, token_block_ids)
        causal_allowed = token_pos[None, :] <= token_pos[:, None]
        allowed = selected_tokens & causal_allowed[None, None]
        y = _masked_softmax_attention(q, k, v, ~allowed)
        return self.out_proj(_merge_heads(y))


class NSAStyleAttention(nn.Module):
    """Native Sparse Attention（NSA）三分支结构的简化教学版。

    1. compression：把连续 block 学习池化成粗粒度 K/V；
    2. selection：复用 compression 注意力分数，选 Top-n blocks，再读取其中
       的原始 token；
    3. window：单独处理最近的局部 token；
    4. 三条输出由输入相关 gate 混合。

    为了让代码紧凑，这里让压缩块与选择块使用同一非重叠分块。论文正式版
    支持压缩长度 l、步长 d、选择块长度 l' 三套参数，并用专用 Triton kernel
    让同一 GQA group 共享连续 KV block 读取。
    """

    def __init__(
        self,
        d_model: int,
        num_heads: int,
        block_size: int,
        top_blocks: int,
        window: int,
    ) -> None:
        super().__init__()
        if d_model % num_heads != 0:
            raise ValueError("d_model must be divisible by num_heads")
        if min(block_size, top_blocks, window) < 1:
            raise ValueError("block_size, top_blocks and window must be positive")
        self.num_heads = num_heads
        self.head_dim = d_model // num_heads
        self.block_size = block_size
        self.top_blocks = top_blocks
        self.window = window
        self.qkv = nn.Linear(d_model, 3 * d_model, bias=False)
        self.compression_score = nn.Linear(self.head_dim, 1, bias=False)
        self.branch_gate = nn.Linear(d_model, 3, bias=True)
        self.out_proj = nn.Linear(d_model, d_model, bias=False)

    def forward(self, x: Tensor) -> Tensor:
        batch, seq_len, _ = x.shape
        q, k, v = self.qkv(x).chunk(3, dim=-1)
        q = _split_heads(q, self.num_heads)
        k = _split_heads(k, self.num_heads)
        v = _split_heads(v, self.num_heads)

        block_ranges = [
            (start, min(start + self.block_size, seq_len))
            for start in range(0, seq_len, self.block_size)
        ]
        compressed_k: list[Tensor] = []
        compressed_v: list[Tensor] = []
        for start, end in block_ranges:
            k_chunk = k[:, :, start:end]
            v_chunk = v[:, :, start:end]
            pool = torch.softmax(
                self.compression_score(k_chunk).squeeze(-1).float(), dim=2
            ).to(k.dtype)
            compressed_k.append((pool.unsqueeze(-1) * k_chunk).sum(dim=2))
            compressed_v.append((pool.unsqueeze(-1) * v_chunk).sum(dim=2))

        ck = torch.stack(compressed_k, dim=2)
        cv = torch.stack(compressed_v, dim=2)
        num_blocks = ck.shape[2]

        token_pos = torch.arange(seq_len, device=x.device)
        block_ends = torch.tensor(
            [end - 1 for _, end in block_ranges], device=x.device
        )
        completed = block_ends[None, :] <= token_pos[:, None]

        compression_scores = torch.einsum("bhtd,bhmd->bhtm", q, ck)
        compression_scores = compression_scores / math.sqrt(self.head_dim)
        compression_scores = compression_scores.masked_fill(
            ~completed[None, None], float("-inf")
        )
        compression_probs = torch.softmax(
            compression_scores.float(), dim=-1
        )
        compression_probs = torch.nan_to_num(compression_probs, nan=0.0).to(
            q.dtype
        )
        compression_out = torch.matmul(compression_probs, cv)

        # 论文会在同一 GQA group 内汇总 importance，使多个 Query heads 共享
        # block 选择。这里为简单起见让全部 heads 共享。
        block_importance = compression_probs.sum(dim=1)
        selected_blocks = torch.zeros(
            batch, seq_len, num_blocks, dtype=torch.bool, device=x.device
        )
        chosen = block_importance.topk(
            min(self.top_blocks, num_blocks), dim=-1
        ).indices
        selected_blocks.scatter_(-1, chosen, True)
        selected_blocks &= completed[None]

        token_block_ids = token_pos // self.block_size
        selected_tokens = selected_blocks.index_select(-1, token_block_ids)
        causal_allowed = token_pos[None, :] <= token_pos[:, None]
        selection_allowed = selected_tokens & causal_allowed[None]
        selection_out = _masked_softmax_attention(
            q, k, v, ~selection_allowed[:, None]
        )

        window_allowed = causal_allowed & (
            token_pos[None, :] > token_pos[:, None] - self.window
        )
        window_out = _masked_softmax_attention(q, k, v, ~window_allowed)

        gates = torch.sigmoid(self.branch_gate(x))
        y = (
            compression_out * gates[..., 0][:, None, :, None]
            + selection_out * gates[..., 1][:, None, :, None]
            + window_out * gates[..., 2][:, None, :, None]
        )
        return self.out_proj(_merge_heads(y))


def elu_plus_one(x: Tensor) -> Tensor:
    """经典 Linear Transformer 示例采用的正值特征映射。"""
    return F.elu(x) + 1.0


class CausalLinearAttention(nn.Module):
    """写成因果递归扫描的 kernel linear attention。

    每个 head 不再保存所有历史 K/V，而只保存：

        S_t = sum_i phi(k_i) outer-product v_i
        z_t = sum_i phi(k_i)

    两个状态的大小都不随序列长度 T 增长。
    """

    def __init__(
        self,
        d_model: int,
        num_heads: int,
        feature_map: Callable[[Tensor], Tensor] = elu_plus_one,
        eps: float = 1e-6,
    ) -> None:
        super().__init__()
        if d_model % num_heads != 0:
            raise ValueError("d_model must be divisible by num_heads")
        self.num_heads = num_heads
        self.feature_map = feature_map
        self.eps = eps
        self.qkv = nn.Linear(d_model, 3 * d_model, bias=False)
        self.out_proj = nn.Linear(d_model, d_model, bias=False)

    def forward(self, x: Tensor) -> Tensor:
        batch, seq_len, _ = x.shape
        q, k, v = self.qkv(x).chunk(3, dim=-1)
        q = self.feature_map(_split_heads(q, self.num_heads))
        k = self.feature_map(_split_heads(k, self.num_heads))
        v = _split_heads(v, self.num_heads)

        key_dim = k.shape[-1]
        value_dim = v.shape[-1]
        state = x.new_zeros(batch, self.num_heads, key_dim, value_dim)
        normalizer_state = x.new_zeros(batch, self.num_heads, key_dim)
        outputs: list[Tensor] = []

        for t in range(seq_len):
            k_t, v_t, q_t = k[:, :, t], v[:, :, t], q[:, :, t]
            state = state + torch.einsum("bhd,bhe->bhde", k_t, v_t)
            normalizer_state = normalizer_state + k_t

            numerator = torch.einsum("bhd,bhde->bhe", q_t, state)
            denominator = torch.einsum("bhd,bhd->bh", q_t, normalizer_state)
            outputs.append(numerator / denominator.clamp_min(self.eps).unsqueeze(-1))

        y = torch.stack(outputs, dim=2)
        return self.out_proj(_merge_heads(y))


class GatedDeltaAttention(nn.Module):
    """易读的标量门控 Delta-rule 线性注意力。

    对每个 token、每个 head：

        S_bar = alpha_t * S_{t-1}
        prediction = k_t^T S_bar
        S_t = S_bar + k_t [beta_t * (v_t - prediction)]^T
        o_t = q_t^T S_t

    减去 prediction 相当于“先读旧值，再写误差”，避免同一地址无脑累加。
    KDA 把 retention 扩成逐通道向量；Gated DeltaNet-2 又把逐通道 erase 与
    write gate 分开。
    """

    def __init__(self, d_model: int, num_heads: int) -> None:
        super().__init__()
        if d_model % num_heads != 0:
            raise ValueError("d_model must be divisible by num_heads")
        self.num_heads = num_heads
        self.head_dim = d_model // num_heads
        self.q_proj = nn.Linear(d_model, d_model, bias=False)
        self.k_proj = nn.Linear(d_model, d_model, bias=False)
        self.v_proj = nn.Linear(d_model, d_model, bias=False)
        self.alpha_proj = nn.Linear(d_model, num_heads, bias=True)
        self.beta_proj = nn.Linear(d_model, num_heads, bias=True)
        self.out_proj = nn.Linear(d_model, d_model, bias=False)

        # 初始化为较长记忆、适中的写入强度。
        nn.init.constant_(self.alpha_proj.bias, 2.0)
        nn.init.constant_(self.beta_proj.bias, 0.0)

    def forward(self, x: Tensor) -> Tensor:
        batch, seq_len, _ = x.shape
        q = F.normalize(_split_heads(self.q_proj(x), self.num_heads), dim=-1)
        k = F.normalize(_split_heads(self.k_proj(x), self.num_heads), dim=-1)
        v = _split_heads(self.v_proj(x), self.num_heads)
        alpha = torch.sigmoid(self.alpha_proj(x)).transpose(1, 2)
        beta = torch.sigmoid(self.beta_proj(x)).transpose(1, 2)

        state = x.new_zeros(
            batch, self.num_heads, self.head_dim, self.head_dim
        )
        outputs: list[Tensor] = []

        for t in range(seq_len):
            q_t, k_t, v_t = q[:, :, t], k[:, :, t], v[:, :, t]
            alpha_t = alpha[:, :, t, None, None]
            beta_t = beta[:, :, t, None]

            decayed = alpha_t * state
            prediction = torch.einsum("bhd,bhde->bhe", k_t, decayed)
            correction = beta_t * (v_t - prediction)
            state = decayed + torch.einsum("bhd,bhe->bhde", k_t, correction)
            outputs.append(torch.einsum("bhd,bhde->bhe", q_t, state))

        y = torch.stack(outputs, dim=2)
        return self.out_proj(_merge_heads(y))


class KimiDeltaAttention(nn.Module):
    """Kimi Delta Attention（KDA）核心递推的教学实现。

    KDA 把 Gated DeltaNet 的每 head 标量衰减 ``alpha_t``，细化为 key
    channel 级向量 ``alpha_t[d_k]``。论文中的更新为：

        S_decay = Diag(alpha_t) @ S_{t-1}
        prediction = k_t^T @ S_decay
        S_t = S_decay + k_t @ [beta_t * (v_t - prediction)]^T
        o_t = q_t^T @ S_t

    展开后等价于：

        S_t = (I - beta_t k_t k_t^T) Diag(alpha_t) S_{t-1}
              + beta_t k_t v_t^T

    其中转移矩阵是受约束的 diagonal-plus-low-rank（DPLR）结构。标量 GDN
    只能让一个 head 的所有地址一起变淡；KDA 可以让不同 key channels 拥有
    不同记忆寿命。

    为保持代码可读，本类使用低秩 MLP + sigmoid 产生逐通道 alpha，并省略论文
    模型中的 ShortConv、head-wise RMSNorm、输出门及 chunkwise DPLR kernel。
    因而它复现的是 KDA 状态方程，不是 Kimi Linear 的生产算子。
    """

    def __init__(
        self,
        d_model: int,
        num_heads: int,
        gate_rank: int | None = None,
    ) -> None:
        super().__init__()
        if d_model % num_heads != 0:
            raise ValueError("d_model must be divisible by num_heads")
        self.num_heads = num_heads
        self.head_dim = d_model // num_heads
        gate_rank = self.head_dim if gate_rank is None else gate_rank
        if gate_rank < 1:
            raise ValueError("gate_rank must be positive")

        self.q_proj = nn.Linear(d_model, d_model, bias=False)
        self.k_proj = nn.Linear(d_model, d_model, bias=False)
        self.v_proj = nn.Linear(d_model, d_model, bias=False)

        # 论文用低秩投影产生每个 head、每个 key channel 的衰减。
        self.alpha_down = nn.Linear(d_model, gate_rank, bias=False)
        self.alpha_up = nn.Linear(gate_rank, d_model, bias=True)
        self.beta_proj = nn.Linear(d_model, num_heads, bias=True)
        self.out_proj = nn.Linear(d_model, d_model, bias=False)

        # sigmoid(2)≈0.88：让演示模型初始时保留相对较长的记忆。
        nn.init.zeros_(self.alpha_up.weight)
        nn.init.constant_(self.alpha_up.bias, 2.0)
        nn.init.constant_(self.beta_proj.bias, 0.0)

    def forward(self, x: Tensor) -> Tensor:
        batch, seq_len, _ = x.shape
        q = F.normalize(_split_heads(self.q_proj(x), self.num_heads), dim=-1)
        k = F.normalize(_split_heads(self.k_proj(x), self.num_heads), dim=-1)
        v = _split_heads(self.v_proj(x), self.num_heads)

        # alpha: [B,H,T,Dk]，每个 key channel 都有独立衰减；
        # beta:  [B,H,T]，每个 head/token 一个 Delta 学习率。
        alpha_logits = self.alpha_up(self.alpha_down(x))
        alpha = torch.sigmoid(alpha_logits)
        alpha = _split_heads(alpha, self.num_heads)
        beta = torch.sigmoid(self.beta_proj(x)).transpose(1, 2)

        state = x.new_zeros(
            batch, self.num_heads, self.head_dim, self.head_dim
        )
        outputs: list[Tensor] = []

        for t in range(seq_len):
            q_t, k_t, v_t = q[:, :, t], k[:, :, t], v[:, :, t]
            alpha_t = alpha[:, :, t]
            beta_t = beta[:, :, t, None]

            # 左乘 Diag(alpha_t)：按 key/address 维缩放状态的每一行。
            decayed = alpha_t.unsqueeze(-1) * state
            prediction = torch.einsum("bhd,bhde->bhe", k_t, decayed)
            correction = beta_t * (v_t - prediction)
            state = decayed + torch.einsum("bhd,bhe->bhde", k_t, correction)
            outputs.append(torch.einsum("bhd,bhde->bhe", q_t, state))

        y = torch.stack(outputs, dim=2)
        return self.out_proj(_merge_heads(y))


class RMSNormGated(nn.Module):
    """Qwen3.5 Gated DeltaNet 输出端的 RMSNorm + SiLU(z) 门。"""

    def __init__(self, width: int, eps: float = 1e-6) -> None:
        super().__init__()
        self.weight = nn.Parameter(torch.ones(width))
        self.eps = eps

    def forward(self, x: Tensor, z: Tensor) -> Tensor:
        variance = x.float().square().mean(dim=-1, keepdim=True)
        normalized = x * torch.rsqrt(variance + self.eps).to(x.dtype)
        return normalized * self.weight * F.silu(z)


class Qwen35GatedDeltaNet(nn.Module):
    """Qwen3.5 风格 Gated DeltaNet（GDN）的逐 token 教学实现。

    官方模块先对联合 Q/K/V 投影做深度可分离因果短卷积和 SiLU，再用
    ``alpha=exp(g)`` 衰减整个状态，并以 Delta rule 定向改写被 key 命中的
    地址：

        g_t = -exp(A_log) * softplus(a_t + dt_bias)
        S_bar = exp(g_t) * S_{t-1}
        delta = sigmoid(b_t) * (v_t - k_t^T S_bar)
        S_t = S_bar + k_t outer-product delta
        y_t = q_t^T S_t

    Qwen3.5 还允许 Q/K heads 少于 Value heads；这里按组复制 Q/K 以匹配
    Value heads。真实训练使用 chunkwise 并行 kernel，解码使用融合 recurrent
    kernel；下面的 Python 循环只用于看清状态更新。
    """

    def __init__(
        self,
        d_model: int,
        num_qk_heads: int,
        num_value_heads: int,
        key_head_dim: int,
        value_head_dim: int,
        conv_kernel_size: int = 4,
    ) -> None:
        super().__init__()
        if num_value_heads % num_qk_heads != 0:
            raise ValueError("num_value_heads must be divisible by num_qk_heads")
        if min(
            num_qk_heads,
            num_value_heads,
            key_head_dim,
            value_head_dim,
            conv_kernel_size,
        ) < 1:
            raise ValueError("all head dimensions and conv_kernel_size must be positive")

        self.num_qk_heads = num_qk_heads
        self.num_value_heads = num_value_heads
        self.key_head_dim = key_head_dim
        self.value_head_dim = value_head_dim
        self.conv_kernel_size = conv_kernel_size

        qk_width = num_qk_heads * key_head_dim
        value_width = num_value_heads * value_head_dim
        conv_width = 2 * qk_width + value_width
        self.qkv_proj = nn.Linear(d_model, conv_width, bias=False)
        self.conv1d = nn.Conv1d(
            conv_width,
            conv_width,
            kernel_size=conv_kernel_size,
            groups=conv_width,
            padding=conv_kernel_size - 1,
            bias=True,
        )
        self.z_proj = nn.Linear(d_model, value_width, bias=False)
        self.a_proj = nn.Linear(d_model, num_value_heads, bias=False)
        self.b_proj = nn.Linear(d_model, num_value_heads, bias=False)

        # 每个 Value head 一组时间尺度参数。g 始终为负，所以 alpha 位于 (0,1]。
        self.A_log = nn.Parameter(torch.zeros(num_value_heads))
        self.dt_bias = nn.Parameter(torch.zeros(num_value_heads))
        self.output_norm = RMSNormGated(value_head_dim)
        self.out_proj = nn.Linear(value_width, d_model, bias=False)

    def forward(
        self,
        x: Tensor,
        initial_state: Tensor | None = None,
        return_state: bool = False,
    ) -> Tensor | tuple[Tensor, Tensor]:
        batch, seq_len, _ = x.shape
        qk_width = self.num_qk_heads * self.key_head_dim
        value_width = self.num_value_heads * self.value_head_dim

        # Conv1d 的双侧 padding 后裁掉末端；输出 t 只依赖输入 [t-K+1, t]。
        qkv = self.qkv_proj(x).transpose(1, 2)
        qkv = self.conv1d(qkv)[..., :seq_len].transpose(1, 2)
        qkv = F.silu(qkv)
        q, k, v = qkv.split([qk_width, qk_width, value_width], dim=-1)

        q = q.view(batch, seq_len, self.num_qk_heads, self.key_head_dim)
        k = k.view(batch, seq_len, self.num_qk_heads, self.key_head_dim)
        v = v.view(batch, seq_len, self.num_value_heads, self.value_head_dim)
        q = q.transpose(1, 2)
        k = k.transpose(1, 2)
        v = v.transpose(1, 2)

        repeats = self.num_value_heads // self.num_qk_heads
        q = q.repeat_interleave(repeats, dim=1)
        k = k.repeat_interleave(repeats, dim=1)
        q = F.normalize(q, dim=-1) / math.sqrt(self.key_head_dim)
        k = F.normalize(k, dim=-1)

        z = self.z_proj(x).view(
            batch, seq_len, self.num_value_heads, self.value_head_dim
        ).transpose(1, 2)
        beta = torch.sigmoid(self.b_proj(x)).transpose(1, 2)
        a = self.a_proj(x).transpose(1, 2)
        g = -torch.exp(self.A_log)[None, :, None] * F.softplus(
            a + self.dt_bias[None, :, None]
        )
        alpha = torch.exp(g)

        expected_state_shape = (
            batch,
            self.num_value_heads,
            self.key_head_dim,
            self.value_head_dim,
        )
        if initial_state is None:
            state = x.new_zeros(expected_state_shape)
        else:
            if tuple(initial_state.shape) != expected_state_shape:
                raise ValueError(
                    f"initial_state must have shape {expected_state_shape}, "
                    f"got {tuple(initial_state.shape)}"
                )
            state = initial_state

        outputs: list[Tensor] = []
        for t in range(seq_len):
            q_t, k_t, v_t = q[:, :, t], k[:, :, t], v[:, :, t]
            state = alpha[:, :, t, None, None] * state
            old_value = torch.einsum("bhd,bhde->bhe", k_t, state)
            delta = beta[:, :, t, None] * (v_t - old_value)
            state = state + torch.einsum("bhd,bhe->bhde", k_t, delta)
            outputs.append(torch.einsum("bhd,bhde->bhe", q_t, state))

        y = torch.stack(outputs, dim=2)
        y = self.output_norm(y, z)
        output = self.out_proj(_merge_heads(y))
        if return_state:
            return output, state
        return output

    seq_len: int = 12

def _assert_causal(module: nn.Module, x: Tensor, split: int = 6) -> None:
    """修改未来 token，不应影响 ``split`` 之前的输出。"""
    module.eval()
    changed = x.detach().clone()
    changed[:, split:] = torch.randn_like(changed[:, split:]) * 3.0
    with torch.no_grad():
        prefix_a = module(x.detach())[:, :split]
        prefix_b = module(changed)[:, :split]
    torch.testing.assert_close(prefix_a, prefix_b, atol=2e-5, rtol=2e-5)

代码解析：每段对应哪条理论

_split_heads
把 [B,T,H×D] 重排为 [B,H,T,D]。所有注意力实现先统一到这个布局，便于直接看到 head 维与序列维。
MultiHeadAttention
显式生成 T×T 分数、加因果 mask、Softmax、乘 V。它是最接近公式的基线，也故意暴露二次矩阵。
FlashAttentionReference
同时切 Query 与 KV blocks；每个 Query 行只维护 row_max、row_sum 和未归一化 numerator。每读一个 KV block 就重标定旧统计量并累加，最后一次归一化；不构造完整 T×T，但高层循环不等同于 fused FA2 kernel。
GroupedQueryAttention
Q 使用 Hq 个 head，K/V 只投影出 Hkv 个 head。示例用 repeat_interleave 展开共享关系；生产 kernel 不会真的复制。
LatentKVAttention
kv_down 先得到每 token 的低维 latent；k_up/v_up 只是教学期显式还原。cache_latent() 直接展示真正可缓存对象。
SlidingWindowAttention
mask 只允许 j≤i 且 i−j<window。算法可达到 O(TW)，但本实现仍用 Dense score，因此只验证语义。
TopKSparseAttention
低维 router 先在因果范围内 Top‑k，选择模式再广播给所有 Query heads。离散索引本身不可微，真实 DSA 需额外 indexer 训练目标。
LightningIndexer
多个低维 Index Query heads 与共享历史 Index Key 做 ReLU 点积，再由 query 相关权重求和；distillation_loss() 提供对齐主注意力分布的 KL 辅助目标。
DSASparseAttention
先按 token Top‑k，再从 MLA latent 恢复一组共享 K/V 并广播给 Query heads，明确复现 DSA 的 MLA MQA mode；Indexer 输入 detach，主模型和索引辅助目标分路。
MoBABlockSparseAttention
按 mean(K_block) 路由历史 blocks，当前 block 强制加入且只在正式注意力中做 causal mask。示例保留 Dense mask，未实现生产版 Query 重排。
NSAStyleAttention
学习池化 block K/V，复用 compression 概率选择原始 blocks，再与固定 window 分支通过三个 sigmoid gates 融合。为易读，把论文的 l、d、l′ 简化为同一非重叠分块。
CausalLinearAttention
循环维护矩阵 state 和向量 normalizer_state；每步只做外积写入和一次状态读取，历史长度不进入状态 shape。
GatedDeltaAttention
先用 α 衰减状态，再以 k 读取 prediction，最后只写入 β×(v−prediction)。代码实现的是标量 gate 教学版，不冒充逐通道 KDA。
KimiDeltaAttention
低秩门网络产生 [B,H,T,Dk] 的逐 key-channel α⃗；alpha.unsqueeze(-1) * state 正对应 Diag(α⃗)S。随后用同一个 k 读取旧预测并做 rank‑1 Delta correction，复现 KDA 的受约束 DPLR recurrent 核心。
Qwen35GatedDeltaNet
联合 QKV 投影经过 K=4 的 depthwise causal Conv1d+SiLU；a/A_log/dt_bias 产生 α，b 产生 β；固定状态经 Delta update 后再走 RMSNorm×SiLU(z) 输出门。Q/K heads 可少于 Value heads。
smoke_test
逐模块检查 shape、NaN/Inf、梯度和因果隔离。它是正确性烟测，不是速度 benchmark。

逐段看几个最关键的张量

① 为什么 FlashAttentionReference 数学相同，却不会真的更快？

它已经用 online Softmax 避免完整 T×T 中间矩阵，并在自测中与 Dense 输出逐元素对齐；但每个 block 都是单独的 PyTorch 调用，数据仍会经过通用调度与显存。FA1/FA2 的速度来自一个融合 GPU kernel 把 tile、最大值、指数和与输出分子常驻寄存器/SRAM。v2 的 thread-block/warp 分工更是 CUDA 调度属性，不能靠 Python 公式本身表达。

② GQA 为什么只省缓存，不自动省掉全部注意力点积？

代码把 K/V 从 Hkv 个 head 扩展到 Hq 个 Query heads 后仍产生 [B,Hq,T,T] 分数。真实 kernel 会避免复制 K/V，却仍需让每个 Query head 与全部位置计算相似度。因此 GQA 的主要收益是 KV Cache 与内存带宽。

③ MLA-style 为何必须区分“缓存 latent”和“恢复 K/V”？

如果只看训练公式，会误以为每个 Decode 步仍要为全部历史 token 做 k_up/v_up。生产 MLA 通过权重吸收避免这件事。示例保留显式恢复，是为了让低秩分解可读；它不代表最佳推理实现。

④ 为什么 Top‑k mask 版不会加速？

因为 router 和主注意力都已经先构造了 T×T 张量，之后把大多数格子设成负无穷，只是数值上变稀疏。真正稀疏 kernel 必须在加载 K/V 和做矩阵乘法前就知道要访问哪些连续 block。

⑤ DSA、MoBA、NSA 的代码为什么不能共用一个 Top‑k 类？

三者的选择对象和训练信号不同：DSA 独立训练 token Indexer；MoBA 用当前 Q/K 参数的 block mean 路由且强制当前块；NSA 复用 compression 分数并保持三条独立输出分支。把它们都写成一张 mask 会丢掉核心机制与 Kernel 约束。

⑥ 线性注意力的固定状态为什么仍可能很大？

状态通常是 [H,Dk,Dv]，虽然不随 T 增长，却随 head 与通道维乘积增长。它消除的是“上下文长度维”，不是让内存凭空消失。状态维太小会冲突，太大又会损失硬件优势。

⑦ Delta rule 为什么比直接累加更像关联记忆？

对同一个 Key，直接累加会把多个 Value 混在一起。Delta 先读出该 Key 当前预测，再只写误差，相当于把映射修到更接近新 Value；门控则决定旧状态先保留多少。

⑧ KDA 的逐通道 α 与 GDN 标量 α 在张量上差在哪里？

标量 GDN 的 α shape 是 [B,H,T]，广播后同时缩放状态 [B,H,Dk,Dv] 的所有行；KDA 的 α⃗ shape 是 [B,H,T,Dk]，unsqueeze(-1) 后每个 key/address 行得到独立衰减。β 仍是 [B,H,T]，只控制本次 Delta correction 的整体步长。这个一维差异就是“整 head 一起忘”和“按地址分别忘”的核心区别。

⑨ Qwen3.5 GDN 中 α、β、z 三个 gate 有何区别？

α 在读取前衰减旧状态，决定记忆时间尺度；β 只缩放本次 Delta correction，决定写入强度；z 在状态读取和 RMSNorm 后控制输出进入残差流。代码把三个位置分开，避免把“忘、写、输出”混为一个门。

若要改成生产实现，还缺什么

  • MHA/GQA / Flash reference：改用经过硬件与 shape 验证的 SDPA/FlashAttention‑2 或推理框架 fused kernel；Decode 另接 paged KV cache 与 KV-aware 调度。
  • MLA：补 decoupled RoPE、权重吸收、latent cache layout、FP8/BF16 混合存储与 FlashMLA。
  • DSA：实现 FP8 Lightning Indexer 蒸馏、Top‑k token gather、Sparse MLA 前反向 kernel，并单测 Indexer recall。
  • MoBA / NSA：实现 block 路由后的 Query regrouping、变长 FlashAttention或 GQA-group 共享连续 KV 读取，以及 online Softmax/三分支融合。
  • Linear / Delta / KDA / GDN：把 token 循环改为 chunkwise parallel scan / WY 或专用 DPLR 算法，融合因果短卷积、状态归一化、输出门和混合精度更新。
  • Benchmark：分别测 Prefill、Decode、batch 扩展、不同上下文长度、KV HBM 占用和长上下文检索质量，不能只比理论 FLOPs。

8. 工程上如何选择

追求最稳质量与生态

优先 GQA + FlashAttention。Kernel、量化、推理框架和硬件支持最成熟，适合作为任何新架构的基线。

Decode 受 KV Cache 限制

考虑更少 KV heads、MLA/TPA 类表示压缩。先算真实 batch、层数、上下文下的缓存，而不是只看论文比例。

长上下文仍需精确远程检索

优先 block/token sparse + 局部窗口；要求 Indexer recall 和专用 kernel 同时过关。

超长 Decode / 流式状态最关键

评估 GLA、Delta/KDA 或 SSM 类架构，但必须单测多 Key 检索、复制、状态跟踪和 ICL。

从头预训练下一代模型

混合层通常比全替换更现实：多数层用廉价状态或稀疏模块，周期插入全局显式注意力。

只做推理侧改造

不要假定可把既有 Dense checkpoint 无损换成原生 Sparse/Linear；优先做 Kernel、KV 管理或经验证的 post-hoc 稀疏方案。

建议的实验顺序：同参数 Dense GQA 基线 → 加 FlashAttention/分页缓存 → 测 KV 压缩 → 再测原生 block sparse → 最后才比较 linear/hybrid。从简单基线开始，才能知道收益究竟来自结构、Kernel 还是训练配方。

三句话总结

  1. 1. FlashAttention v1/v2 优化“精确注意力怎样在 GPU 上搬和算”；MQA、GQA、MLA 才是在解决“每个 token 存多少”。前者不改变模型可见性或理论 O(n²)。
  2. 2. 稀疏注意力保留显式 token 记忆并少读；线性注意力把历史压进固定状态。Mamba 是并行 SSM 路线，Mamba‑2 / SSD 提供对偶桥梁；DeltaNet 与 KDA 则沿关联记忆路线把状态变得可纠错、可逐通道遗忘。
  3. 3. Qwen3.5、DeepSeek‑V4、Kimi Linear/K3 展示的主线都是混合：把精确全局交互当作稀缺预算，而不是把它彻底删除。
