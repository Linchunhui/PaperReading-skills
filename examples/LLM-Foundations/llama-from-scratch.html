01 · 先补齐会反复用到的 PyTorch

张量不是神秘东西，就是有多条轴的数组

一批句子可以写成 [B,T,D]：B 条句子，每条 T 个 token，每个 token 用 D 个数表示。后文始终沿用这一套符号。

符号 含义 手算例子 默认微型模型
B batch size，一批几条序列 2 由输入决定
T sequence length，本次输入几位 5 训练默认 32
D model dimension，每个 token 的特征维度 32 64
H / Hq Query 头数 4 4
Hkv Key/Value 头数 4 主线 4；训练示例 2
d head dimension，单头维度 8 16
F FFN hidden dimension，前馈中间维度 88 176
Vocab 词表大小 20 配置占位 64；实际由分词器决定
P cache 中已有多少个 token 3 无 cache 时为 0

关键关系是 D = H × d。V 常被用于表示 Value，为避免歧义，本教程用 Vocab 表示词表大小。

import math
from dataclasses import dataclass
import torch
from torch import nn

x = torch.randn(2, 5, 32)       # 2 条序列，每条 5 个 token

print(y.shape)                 # torch.Size([2, 5, 24])
print(projection.weight.shape) # torch.Size([24, 32])

nn.Linear 对最后一维做线性变换，在所有 batch 和时间位置共享同一组权重。数学里常写 Y = XW，但 PyTorch 存的是 [out_features,in_features]，实际相当于 X @ weight.T。不要为了“对齐公式”再把输入转置一次。

六个操作，先会这六个就够往下走

操作 用处 容易犯的错
reshape(B,T,H,d) 将特征维度拆成头数和单头维度 用 reshape 代替轴交换
transpose(1,2) 把 [B,T,H,d] 变成 [B,H,T,d] 直接 reshape 到目标形状，元素分组变了
@ / matmul 最后两维做矩阵乘法；前面的维度批处理 把 T 和 d 的含义弄反
mean(-1, keepdim=True) 在每个 token 内求均值，保留长度为 1 的轴 不小心跨 token 求统计量
softmax(-1) 在最后一维归一化成概率 在 query 轴上归一化
masked_fill(mask, -inf) 将指定位置排除出后续 softmax 忘记这里 True 表示“要填充”

transpose 后的张量通常不连续。随后用 .reshape(...)，PyTorch 会在需要时复制；也可以 .contiguous().view(...)。reshape 能处理内存布局问题，但不能替你猜正确的轴顺序。

nn.Module、参数、反向传播

__init__ 中定义层和可训练参数，forward 中定义运算。model(x) 会调用前向流程；loss.backward() 计算梯度，优化器的 step() 才真正更新参数。梯度默认累积，所以一般每次更新前先清空。

PYTHON · 解释 / 运行片段9 行
model = nn.Linear(3, 1)
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3)
x = torch.randn(4, 3)

optimizer.zero_grad(set_to_none=True)

loss.backward()
optimizer.step()

普通 Tensor 不会自动变成模型参数。可训练向量用 nn.Parameter；不训练但要随模型迁移设备的固定表可以用 register_buffer。重复的层放在 nn.ModuleList，这样参数会被注册、保存并交给优化器。

动手题：D=48、H=6，拆头后的形状是什么？

从 [B,T,48] 先变成 [B,T,6,8]，再变成 [B,6,T,8]。每个头仍然看见全部 T 个 token，只看不同的特征投影。不是把句子切成 6 段。

02 · 文本如何进入模型：Tokenizer 与 Embedding

从“字符”到“编号”，再到“向量”

模型不能直接对字符串做矩阵乘法。第一步由 tokenizer 把文本变成整数编号。为了把重点放在模型结构上，我们先用字符级分词：一个汉字、一个标点、一个换行都各自是一个 token。实际 Llama 分词器和词表需要按照具体版本匹配；这里的字符分词器不能拿去替代官方分词器加载官方模型。

文本 我 爱 学 习
示例 ID（仅为演示） 2 5 7 9
Embedding 查表 E[2] E[5] E[7] E[9]

编号只是索引，9 不意味着比 2 更重要或语义更大。Embedding 是一个 [Vocab,D] 的可训练表：查出每个编号对应的向量，得到 [B,T,D]。查表本身不处理词序，也不考虑前后文；上下文信息由后面的层逐步融合。

PYTHON · 解释 / 运行片段8 行
import torch
from torch import nn

input_ids = torch.tensor([[2, 5, 7, 9]], dtype=torch.long)
embedding = nn.Embedding(20, 32)
x = embedding(input_ids)
assert x.shape == (1, 4, 32)
# 同一个 ID 的初始向量来自同一行；后面的上下文表示可以不同。

字符分词器的完整实现如下。<unk> 用于训练词表中没有出现过的字符；本教程不在主线加入 BOS/EOS/PAD，文末会说明这些组件在哪里补。

组件 · CharTokenizer10 行
class CharTokenizer:
    def __init__(self, training_text=None, tokens=None):
        self.tokens = ["<unk>"] + sorted(set(training_text)) if tokens is None else tokens
        self.stoi = {char: i for i, char in enumerate(self.tokens)}

    def encode(self, text):
        return [self.stoi.get(char, 0) for char in text]

    def decode(self, ids):
        return "".join(self.tokens[i] for i in ids)

语言模型到底预测什么？

给定“我爱学”，模型输出一个词表大小的分数向量。每个分数对应“下一个 token 是这个词”的倾向。我们通过训练让真实下一个 token“习”的概率更高。

p(x₁, …, xT) = ∏t=1…T p(xt | x<t)

这就是自回归分解：每次根据已经出现的内容预测下一位。“一次只生成一位”描述的是常规生成过程；训练时知道完整文本，可以同时训练很多位置，但每个位置都必须看不到未来答案。

先建立一个直觉：模型的输入是 ID，层与层之间流动的是向量，模型最后输出的是 logits。分词器、隐藏向量、概率分布是三个不同阶段。

03 · 单头 Self-Attention：先写最小版本

Q、K、V 是同一输入的三种投影

假设输入 X:[B,T,D]。我们用三个不同的权重矩阵产生 Q、K、V。Self-Attention 的“self”是说它们都来自同一条输入序列，不意味着三个矩阵相同。

名称 初学时可以这样理解 实际作用
Q / Query 当前 token 想找什么 与所有 Key 计算匹配分数
K / Key 每个 token 提供什么检索线索 被 Query 匹配
V / Value 每个 token 带来的内容 按注意力权重进行加权求和

这些比喻帮助入门，但模型并不被强制把某一维学成具体语义。真正需要掌握的是下面的运算。

Q = XWQ，K = XWK，V = XWV
A = softmaxkey(QKᵀ / √d + M)
Y = AV

QKᵀ 的第 i 行第 j 列是：位置 i 对位置 j 的读取分数。在每一行沿 Key 方向做 softmax，得到和为 1 的读取权重。再用这行权重对所有 Value 求加权和。

为什么除以 √d？在各分量近似独立、零均值、方差为 1 的简单假设下，d 项乘积之和的方差随 d 增长；除以 √d 可以控制分数尺度，降低 softmax 过早饱和的风险。这是初始化尺度的解释，不是训练中始终成立的统计定律。缩放点积注意力与多头结构见 Attention Is All You Need。

组件 · single_head_attention9 行
def single_head_attention(q, k, v, causal=True):
    """q/k/v: [B, T, d]；返回输出和可检查的注意力权重。"""
    scores = (q @ k.transpose(-2, -1)) / math.sqrt(q.size(-1))
    if causal:
        t = q.size(-2)
        allowed = torch.ones(t, t, device=q.device, dtype=torch.bool).tril()
        scores = scores.masked_fill(~allowed, float("-inf"))
    weights = torch.softmax(scores, dim=-1)
    return weights @ v, weights

一次手算：只看第一行就能检查方向

设置三行 Q=K=[[1,0],[0,1],[1,1]]，V=[[10,0],[0,20],[30,30]]，单头维度 d=2。第二个位置只能读前两行：

scores₂ = [0, 1/√2, −∞]
weights₂ ≈ [0.3302, 0.6698, 0]
output₂ ≈ 0.3302·[10,0] + 0.6698·[0,20] = [3.302, 13.395]

第一个位置只能读自己，因此输出恰好是第一个 Value：[10,0]。如果第一行还混入了第二、第三行的内容，先检查 mask，而不是调整学习率。

动手题：如果 Q、K 全是 0，输出会是什么？

可见位置的分数完全相同，softmax 变成均匀权重。因果注意力中，第 t 行输出就是前 t+1 个 Value 的平均值。用这个手算结果就能检查实现是否正确。

04 · Causal mask：让模型看不到未来

训练输入“我爱学习”时，位置“爱”只能读“我、爱”，不能读“学、习”。允许读当前位置本身是正确的，因为这个位置的训练目标是下一个 token，而不是重建当前 token。

Query \ Key 我（0） 爱（1） 学（2） 习（3）
我（0） 可见 屏蔽 屏蔽 屏蔽
爱（1） 可见 可见 屏蔽 屏蔽
学（2） 可见 可见 可见 屏蔽
习（3） 可见 可见 可见 可见

这个表是保留下三角、遮住上三角。代码里先构造 allowed=True 表示可读，再用 ~allowed 表示需要填成 -inf 的位置。exp(-inf)=0，softmax 后未来权重为 0。不能用 0 替代 -inf，因为分数 0 仍会得到正的概率。

亲手切换：没有 cache 和有 cache 时，mask 有什么不同？

“可见”对应加 0，“×”对应加 −∞。行是本次的 Query，列是所有可用的 Key。

为什么训练可以并行？

所有位置的真实 token 已知，Embedding 和每层中的矩阵运算可以同时计算整段序列。mask 切断未来 token 到较早位置的注意力路径，因此每个位置仍只依赖自己的前缀。并行训练不等于提前偷看答案。

注意不要混用不同 API 的布尔掩码约定：本教程的 allowed=True 和 scaled_dot_product_attention 的布尔 mask 都表示“参与注意力”；nn.MultiheadAttention 的 key_padding_mask=True 表示“遮住”。见 PyTorch SDPA 文档。

05 · 从单头变多头：完整手写 MHA

单头只有一组匹配和混合规则。多头用不同的投影子空间，同时形成多组注意力。可以把它理解为同一段文字被多种方式读取，但不要预先认定“第一个头一定负责语法、第二个头一定负责指代”。

先投影，再拆头，不是切句子

设 B=2,T=5,D=32,H=4,d=8。四个头中的每一个都拥有 5 个位置。

步骤 操作 输出形状
1 输入 X [2,5,32]
2 Q/K/V 线性投影 各 [2,5,32]
3 reshape(B,T,H,d) 各 [2,5,4,8]
4 transpose(1,2) 各 [2,4,5,8]
5 Q @ K.transpose(-2,-1) [2,4,5,5]
6 缩放、mask、沿最后维 softmax [2,4,5,5]
7 weights @ V [2,4,5,8]
8 交换回 [B,T,H,d]，再合并头 [2,5,32]
9 输出投影 o_proj [2,5,32]
组件 · CausalMHA26 行
class CausalMHA(nn.Module):
    def __init__(self, dim, n_heads):
        super().__init__()
        if dim % n_heads != 0:
            raise ValueError("dim 必须能被 n_heads 整除")
        self.n_heads = n_heads
        self.head_dim = dim // n_heads
        self.q_proj = nn.Linear(dim, dim, bias=False)
        self.k_proj = nn.Linear(dim, dim, bias=False)
        self.v_proj = nn.Linear(dim, dim, bias=False)
        self.o_proj = nn.Linear(dim, dim, bias=False)

    def forward(self, x):
        b, t, d_model = x.shape
        # 先拆最后一维，再交换 T 和 H 两个轴。
        q = self.q_proj(x).reshape(b, t, self.n_heads, self.head_dim).transpose(1, 2)
        k = self.k_proj(x).reshape(b, t, self.n_heads, self.head_dim).transpose(1, 2)
        v = self.v_proj(x).reshape(b, t, self.n_heads, self.head_dim).transpose(1, 2)
        # [B,H,T,d] @ [B,H,d,T] = [B,H,T,T]
        scores = (q.float() @ k.float().transpose(-2, -1)) / math.sqrt(self.head_dim)
        allowed = torch.ones(t, t, dtype=torch.bool, device=x.device).tril()
        scores = scores.masked_fill(~allowed, float("-inf"))
        weights = torch.softmax(scores, dim=-1).to(v.dtype)
        mixed = weights @ v                         # [B,H,T,d]
        merged = mixed.transpose(1, 2).reshape(b, t, d_model)
        return self.o_proj(merged)                  # [B,T,D]

逐段解释

q_proj/k_proj/v_proj 看上去各自是一个大 Linear，但它们的输出维度可以分成 H 段；每一段就是一个头的投影结果。不需要 Python for 循环逐头计算，矩阵乘法可以把 B 和 H 两个轴都当批处理轴。

scores:[B,H,T,T] 的两个 T 含义不同：倒数第二维是“谁来问”，最后一维是“向谁读”。所以 softmax(dim=-1) 才是在每个 Query 内对所有 Key 分配权重。

o_proj 将各头拼接后的特征重新混合。合头是拼接特征，不是对 H 个头取平均；输出还保持 [B,T,D]，才能与输入做残差相加。

代码为了让小例子的数值更稳定，在 FP32 中计算 QK 和 softmax。大模型会更仔细地选择混合精度与融合内核；当前版本优先展示运算逻辑。

改一改维度，检查形状

固定 B=2、T=5。Hkv=Hq 是 MHA；减少 Hkv 的意义会在 GQA 章节解释。

这一版应该怎么测？

输出形状对了还不够。至少验证：输出有限；改变输入后半段，前半段输出不变；同样的 Q/K/V 交给 PyTorch 的 SDPA，输出数值相近。可先在 FP32 小尺寸算例上以 atol=1e-6, rtol=1e-5 对照 MHA 与参考算子。

动手题：为什么不能直接把 [B,T,D] reshape 成 [B,H,T,d]？

reshape 不交换轴，只重新解释线性内存里的元素分组。直接这样写会把原来不同 token 的特征混在错误位置。正确顺序是 [B,T,D] → [B,T,H,d] → transpose → [B,H,T,d]。

06 · 给 Attention 加上 RoPE

为什么还需要位置编码？

Embedding 本身只由 token ID 决定。注意力分数若只取决于 Q、K 的内容，就没有显式表示“相隔几位”的机制。因果 mask 给出前后可见性的约束，但没有像位置编码一样，直接在内容匹配中表达距离。Llama 风格主干把 RoPE 加在 Q、K 上。

RoPE 不是把一个位置向量加到 Embedding 上，而是根据 token 的位置，旋转 Q、K 的特征对。本教程采用相邻维度配对：(0,1),(2,3),…。每对二维向量的旋转速度不同。

从一对数开始理解旋转

设当前位置为 m，一对特征是 (a,b)，旋转角为 α：

a′ = a cos α − b sin α
b′ = a sin α + b cos α

比如 (1,0) 旋转 90° 后变成 (0,1)。向量长度不变，方向改变。RoPE 中不是所有位置都转 90°，而是使用位置乘上频率：

ωi = θ−2i/d，i = 0, …, d/2−1
αm,i = m · ωi

d 是每个头的维度，不是模型总维度 D；θ 是基底，教学配置使用 10000。不同模型/版本可能采用不同 θ 或缩放规则，不能把它当所有 Llama 的统一配置。

看见“位置变了，方向也变了”

固定 d=8、θ=10000，原向量为 (1,0)。横轴为第一维分量，纵轴为第二维分量；角度使用弧度。

为什么能表达相对位置？

把每对的二维旋转合成矩阵 R。Query 在位置 m，Key 在位置 n：

(R(m)q)ᵀ(R(n)k) = qᵀR(m)ᵀR(n)k = qᵀR(n−m)k

关键是中间的旋转合成为 n−m。所以在原始 q/k 保持不变时，同时平移它们的位置不会改变这个点积。它不是说“任意两对相同距离的 token 分数都一样”：分数依旧取决于 q、k 的内容。这里采用列向量记法；其他记法可能出现符号反向，但实现必须整体一致。方法来源见 RoFormer。

组件 · apply_rope14 行
def apply_rope(x, positions, theta=10000.0):
    """x: [B,H,T,d]；positions: [T]；使用相邻偶/奇维度配对。"""
    d = x.size(-1)
    if d % 2 or positions.numel() != x.size(-2):
        raise ValueError("检查 head_dim 和 positions 长度")
    inv_freq = theta ** (-torch.arange(0, d, 2, device=x.device, dtype=torch.float32) / d)
    angles = positions.to(device=x.device, dtype=torch.float32)[:, None] * inv_freq[None, :]
    cos = angles.cos()[None, None, :, :]         # [1,1,T,d/2]
    sin = angles.sin()[None, None, :, :]
    even = x.float()[..., 0::2]                  # [B,H,T,d/2]
    odd = x.float()[..., 1::2]
    rotated_even = even * cos - odd * sin
    rotated_odd = even * sin + odd * cos
    return torch.stack((rotated_even, rotated_odd), dim=-1).flatten(-2).to(x.dtype)

inv_freq:[d/2] 存每对的频率；positions:[T] 与频率外积得到 [T,d/2]。cos/sin 增加两个长度为 1 的维度以后变成 [1,1,T,d/2]，即可广播给所有 batch 和所有头。stack(...).flatten(-2) 把旋转后的偶/奇维重新交错拼回去。

四个必须避开的坑

  1. 旋转位置错了。这里旋转 Q、K，不旋转 V，也不是旋转最后输出。
  2. 配对约定混了。相邻配对和“前半/后半配对”都可实现旋转，但预训练权重的维度排列必须匹配；不能直接换公式后假定 checkpoint 仍兼容。
  3. 缓存后仍从 0 编号。新 token 应从 cache 长度 P 开始，用 P,P+1,…；第 13 章会实现。
  4. 误以为能任意外推。RoPE 公式能算出更远位置，不代表模型在未训练过的长度上仍然可靠。长上下文扩展还涉及训练分布和具体缩放方法。

本实现每次前向即时计算 cos/sin，便于阅读。实际推理可以预计算并缓存频率表；使用低精度权重时也要注意位置与频率计算的精度。

动手题：为什么 d 必须是偶数？如何验证 RoPE 没写反？

因为每两维组成一对二维向量。可以验证位置 0 不改变输入、旋转前后平方范数不变、二维 (1,0) 在 π/2 处变为 (0,1)，以及同时平移 q/k 的位置后点积不变。这些性质能帮助你检查实现，避免只检查形状。

07 · RMSNorm：对一个 token 的特征做尺度调整

经过多个线性层和残差相加，隐藏向量的尺度会变化。归一化给后续子层提供更可控的输入尺度。这里的 Norm 是对每个 token 的最后一维做统计，不是对整句话或整个 batch 做统计。

RMSNorm(x)i = γi · xi / √((1/D)∑j=1…Dxj² + ε)

γ:[D] 是可训练的缩放向量，初始为全 1；ε 用于数值稳定。本实现把 ε 放在平方根内，与本文对照的模型实现保持一致。它不减均值，也没有平移参数 β。方法来源见 RMSNorm。

组件 · RMSNorm11 行
class RMSNorm(nn.Module):
    def __init__(self, dim, eps=1e-6):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(dim))
        self.eps = eps

    def forward(self, x):
        xf = x.float()                          # 在 FP32 中计算统计量
        mean_square = xf.square().mean(dim=-1, keepdim=True)
        normalized = xf * torch.rsqrt(mean_square + self.eps)
        return (normalized * self.weight.float()).to(x.dtype)

手算一下就知道区别

x=[3,4]，忽略 ε、令 γ 全 1，均方为 (9+16)/2=12.5，RMS 约为 3.5355。输出约为 [0.8485,1.1314]。均值没有变成 0；输出每个元素也不等于 1。此时输出的均方约为 1，这是另一回事。

代码中的 keepdim=True 保留 [B,T,1]，才能广播回 [B,T,D]。先转成 FP32 计算平方和，最后转回输入 dtype；γ 仍然参与梯度计算，.float() 不会自动切断梯度。

动手题：把 mean(dim=-1) 改成 mean(dim=1) 会怎样？

你会沿序列轴做统计，把不同 token 混起来。在完整训练中还可能让较早位置的归一化结果依赖未来内容，破坏因果性。形状能广播不代表归一化方向正确。

08 · FFN 与 SwiGLU：注意力之外还需要什么

Attention 沿 token 维度交换信息，FFN 则对每个位置的特征进行非线性变换。FFN 的权重在各位置共享，但不会像 Attention 一样直接跨位置加权求和。两者都不可省略：只有注意力并不是完整的 Llama Block。

普通两层 FFN 常写成 W_down · activation(W_up · x)。SwiGLU 增加一条门控分支，让两条上投影的结果逐元素相乘，然后再降回 D。

SiLU(z) = z · sigmoid(z)
SwiGLU(x) = Wdown(SiLU(Wgatex) ⊙ Wupx)

⊙ 是对应元素相乘，不是矩阵乘法。SiLU 门控值不是限定在 0 到 1 的概率，不能按“保留百分之多少”作严格解释。门控 FFN 变体见 GLU Variants Improve Transformer。

组件 · SwiGLU11 行
class SwiGLU(nn.Module):
    def __init__(self, dim, hidden_dim):
        super().__init__()
        self.gate_proj = nn.Linear(dim, hidden_dim, bias=False)
        self.up_proj = nn.Linear(dim, hidden_dim, bias=False)
        self.down_proj = nn.Linear(hidden_dim, dim, bias=False)

    def forward(self, x):
        gate = F.silu(self.gate_proj(x))         # [B,T,F]
        content = self.up_proj(x)               # [B,T,F]
        return self.down_proj(gate * content)   # [B,T,D]
分支 变换 形状
gate Linear + SiLU [B,T,D] → [B,T,F]
up Linear [B,T,D] → [B,T,F]
elementwise product gate × up [B,T,F]
down Linear [B,T,F] → [B,T,D]

为什么经常看到中间维度约为 8D/3？

忽略 bias，普通 D→4D→D 的两层 FFN 有 8D² 个参数。SwiGLU 的三个矩阵有 3DF 个参数。若想保持相近参数量，令 3DF≈8D²，得到 F≈8D/3。

这是配平参数量的一种选择，不是 SwiGLU 的数学要求。实际模型可能再乘一个系数，或者对齐到某个整数倍；加载模型必须使用对应配置。本教程 D=64,F=176 是便于小实验的选值，不能据此推断官方各尺寸的 FFN 大小。

动手题：D=64、F=176，这个 FFN 有多少参数？

三个无 bias 矩阵合计 3×64×176=33792。gate/up 的 PyTorch 权重都是 [176,64]，down 的权重是 [64,176]。

09 · 组装 Decoder Block：两次 Norm，两次残差

现在有了带 RoPE 的 Attention、RMSNorm 和 SwiGLU，可以组装一个 Llama 风格 Decoder Block。它采用 Pre-Norm：先归一化再进入子层，子层的结果加回原来的残差流。

h = x + Attention(RMSNorm₁(x))
y = h + SwiGLU(RMSNorm₂(h))
组件 · DecoderBlock12 行
class DecoderBlock(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.attn_norm = RMSNorm(cfg.dim, cfg.norm_eps)
        self.attn = LlamaAttention(cfg)
        self.ffn_norm = RMSNorm(cfg.dim, cfg.norm_eps)
        self.ffn = SwiGLU(cfg.dim, cfg.hidden_dim)

    def forward(self, x):
        x = x + self.attn(self.attn_norm(x))
        x = x + self.ffn(self.ffn_norm(x))
        return x

上面 LlamaAttention 是主线正式使用的注意力类：它把第 5、6 章的 MHA 与 RoPE 合起来，并把 n_kv_heads 留作第 12 章的扩展入口。第一次阅读让 n_kv_heads=n_heads 即可，此时每个 Query 头拥有自己的 K/V，仍然是 MHA。

为什么保留残差？

x + f(x) 让子层在现有表示上增加一份更新，也为梯度提供直接通路。从局部导数看会出现 I + ∂f/∂x。它有助于深层优化，但并不保证任意深度、任意学习率都能稳定训练。

别把第一行写成 x = attn(norm(x))：那样丢掉了残差。也别把第二个 Norm 套在最初的 x 上：第二个子层应当接收第一轮更新后的 h。

Decoder-only 为什么没有 Cross-Attention？

经典 Encoder–Decoder Transformer 的 Decoder 会额外读取 Encoder 的输出，因而包含 Cross-Attention。我们做的是纯文本 Decoder-only：prompt 和后续文本在同一个因果序列里处理，不需要单独的 Encoder 输出。本教程的 Block 因此只有因果 Self-Attention 和 FFN 两个子层。

架构 核心注意力可见性 是否要读独立 Encoder 输出
Encoder-only 的常见形式 双向 Self-Attention 否
Encoder–Decoder 的 Decoder 因果 Self-Attention + Cross-Attention 是
本教程 Llama 风格 Decoder-only 因果 Self-Attention 否

这个选择与 Meta Llama 3 的经典稠密主干实现 相符。本文简化了并行、缓存管理及模型规模，便于先在一台普通机器上完成训练闭环。

组件 · LlamaAttention30 行
class LlamaAttention(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.n_heads = cfg.n_heads
        self.n_kv_heads = cfg.n_kv_heads
        self.head_dim = cfg.dim // cfg.n_heads
        self.theta = cfg.rope_theta
        self.q_proj = nn.Linear(cfg.dim, cfg.n_heads * self.head_dim, bias=False)
        self.k_proj = nn.Linear(cfg.dim, cfg.n_kv_heads * self.head_dim, bias=False)
        self.v_proj = nn.Linear(cfg.dim, cfg.n_kv_heads * self.head_dim, bias=False)
        self.o_proj = nn.Linear(cfg.dim, cfg.dim, bias=False)

    def forward(self, x):
        b, t, dim = x.shape
        q = self.q_proj(x).reshape(b, t, self.n_heads, self.head_dim).transpose(1, 2)
        k = self.k_proj(x).reshape(b, t, self.n_kv_heads, self.head_dim).transpose(1, 2)
        v = self.v_proj(x).reshape(b, t, self.n_kv_heads, self.head_dim).transpose(1, 2)
        positions = torch.arange(t, device=x.device)
        q = apply_rope(q, positions, self.theta)
        k = apply_rope(k, positions, self.theta)  # V 不旋转
        repeat = self.n_heads // self.n_kv_heads
        k = k.repeat_interleave(repeat, dim=1)
        v = v.repeat_interleave(repeat, dim=1)
        scores = (q.float() @ k.float().transpose(-2, -1)) / math.sqrt(self.head_dim)
        allowed = torch.ones(t, t, device=x.device, dtype=torch.bool).tril()
        scores = scores.masked_fill(~allowed, float("-inf"))
        weights = F.softmax(scores, dim=-1).to(v.dtype)
        mixed = weights @ v
        merged = mixed.transpose(1, 2).reshape(b, t, dim)
        return self.o_proj(merged)

先忽略 repeat_interleave 那两行：当 Hkv=H 时，repeat=1，它们不改变头数。Q/K 使用同一组 position 编号，V 不旋转。后面的过程与第 5 章相同。

组件 · MiniLlama22 行
class MiniLlama(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.cfg = cfg
        self.embedding = nn.Embedding(cfg.vocab_size, cfg.dim)
        self.layers = nn.ModuleList([DecoderBlock(cfg) for _ in range(cfg.n_layers)])
        self.final_norm = RMSNorm(cfg.dim, cfg.norm_eps)
        self.lm_head = nn.Linear(cfg.dim, cfg.vocab_size, bias=False)
        self.apply(self._init_weights)

    @staticmethod
    def _init_weights(module):
        if isinstance(module, (nn.Linear, nn.Embedding)):
            nn.init.normal_(module.weight, mean=0.0, std=0.02)

    def forward(self, input_ids):
        if input_ids.ndim != 2 or not 0 < input_ids.size(1) <= self.cfg.max_seq_len:
            raise ValueError("input_ids 需要是 [B,T]，且 1 <= T <= max_seq_len")
        hidden = self.embedding(input_ids)      # [B,T] -> [B,T,D]
        for layer in self.layers:
            hidden = layer(hidden)
        return self.lm_head(self.final_norm(hidden)).float()  # [B,T,Vocab]

逐行理解组装部分：embedding 将 ID 变成向量；ModuleList 注册所有层；for 循环依次更新隐藏状态；最后的 RMSNorm 调整残差流，再由 lm_head 将 D 维映射成词表大小的分数。

这里输出的是 logits，不是概率。如果 input_ids:[2,8]，词表大小为 64，输出就是 [2,8,64]。第 t 个位置的 64 个分数用于预测 t+1 位置的 token。最后一位 logits 才用于接着整个 prompt 生成下一位。

本模型的 Embedding 与 LM Head 权重没有共享。Weight tying 可以作为后续练习，但是否共享是架构配置，不是所有模型通用的规定。初始化使用均值 0、标准差 0.02 的正态分布作为教学设置，没有复刻官方完整训练配方。

组件 · get_batch7 行
def get_batch(data, batch_size, seq_len, device, generator=None):
    # 取 T+1 个 token；最后一个 token 只用于提供最后位置的答案。
    starts = torch.randint(len(data) - seq_len, (batch_size,), generator=generator)
    windows = torch.stack([data[i:i + seq_len + 1] for i in starts.tolist()])
    x = windows[:, :-1].to(device)
    y = windows[:, 1:].to(device)
    return x, y

注意本项目选择“数据侧 shift”。所以 next_token_loss 直接比较 logits 与 targets，内部不能再次平移。另一种常见 API 会接收未 shift 的 labels，在模型内部移动；两种约定都可以，但不能叠加。

Cross-Entropy 在做什么？

假设正确下一词的预测概率为 p，损失就是 −log(p)。正确答案越有把握，loss 越低。对整批所有有效位置求平均，就得到训练目标。

L = − (1 / Nvalid) ∑有效 b,t log softmax(logitsb,t)[targetb,t]
组件 · next_token_loss4 行
def next_token_loss(logits, targets):
    """targets 已经由数据侧右移一位；这里不能再 shift 一次。"""
    return F.cross_entropy(logits.reshape(-1, logits.size(-1)),
                           targets.reshape(-1), ignore_index=-100)

[B,T,Vocab] → [B×T,Vocab]，把每个位置都看成一次 Vocab 分类。目标从 [B,T] 展平成 [B×T] 的整数类别编号。将原始 logits 直接交给 Cross-Entropy；不要在前面再做 softmax，它内部会以稳定方式完成相应计算。见 PyTorch CrossEntropyLoss。

均匀猜测时，loss 为 ln(Vocab)，不是 0。本次字符词表大小为 80，ln(80)≈4.382，因此初始 loss 约 4.41 合理。用自然对数计算的 token 平均 loss，可转换为 perplexity=exp(loss)；不同分词器下的 perplexity 不能简单横比。

12 · GQA：让多个 Query 头共享 K/V

前面先保持 Hkv=Hq 来理解 MHA。现在令 Query 头数不变，只减少 Key/Value 头数，就得到了共享程度不同的注意力结构。

形式 Hq=8 时的 Hkv 例子 共享方式
MHA 8 每个 Q 头各有一组 K/V
GQA 2 每 4 个 Q 头共享一组 K/V
MQA 1 所有 Q 头共享一组 K/V

GQA 可视为从 MHA 到 MQA 的一类分组设计；常用狭义写法指 1<Hkv<Hq 的中间情况。方法来源见 GQA。

与 MHA 相比，改哪几处？

  1. Query 的投影输出仍是 Hq×d=D；K/V 的投影输出改成 Hkv×d。
  2. Q 拆成 [B,Hq,T,d]；K/V 拆成 [B,Hkv,T,d]。
  3. 在教学版矩阵乘法前，将每组 K/V 连续重复 Hq/Hkv 次，匹配 Query 头数。

13 · KV cache：先写对，再加速

不缓存时浪费了什么？

给定长度为 P 的 prompt，先跑整段得到下一 token；接上新 token 后，又把长度 P+1 的整段跑一遍。前 P 个位置的许多计算重复了。因果模型中，这些旧位置不能读取新位置，在固定权重、确定性推理及相同位置约定下，它们的历史表示可以复用。

KV cache 为每一层保存历史 Key 和 Value。下一步只为新 token 计算 Q/K/V，再用新 Query 读取历史与当前的 K/V。Q 不需要作为历史记忆保存，因为未来的读取只需要过去的 K 和 V。

阶段 本次输入 Query 长度 Key/Value 总长度
Prefill 整个 prompt，长度 P P P
第一次 Decode 前向 新生成的一个 token 1 P+1
下一次 Decode 前向 再新生成的一个 token 1 P+2

Prefill 的最后一位 logits 已经能产生第一个新 token；不是先把 prompt 全部处理完，还要额外凭空输入一个 token 才能开始生成。

两个最容易错的地方：位置与矩形 mask

已有 3 个 token，本次一次送入 2 个新 token，位置应为 [3,4]，K/V 总长度为 5。允许读取的范围是：

Query 绝对位置 \ Key 位置 0 1 2 3 4
3 可见 可见 可见 可见 屏蔽
4 可见 可见 可见 可见 可见

通用规则是 key_position <= query_position。不要对 [2,5] 直接套一个无偏移下三角，那会让第一行只看到第 0 列。第 4 章的小演示可以切换 P=3、T=2 查看。

缓存的 K 在第一次产生时已经应用 RoPE；每一步只旋转新产生的 K，然后拼上旧 K。不能把整个历史 K 再旋转一遍。

缓存 Attention 的代码

组件 · CachedAttention25 行
class CachedAttention(LlamaAttention):
    def forward(self, x, past=None):
        b, t, dim = x.shape
        past_len = 0 if past is None else past[0].size(-2)
        q = self.q_proj(x).reshape(b, t, self.n_heads, self.head_dim).transpose(1, 2)
        k = self.k_proj(x).reshape(b, t, self.n_kv_heads, self.head_dim).transpose(1, 2)
        v = self.v_proj(x).reshape(b, t, self.n_kv_heads, self.head_dim).transpose(1, 2)
        positions = torch.arange(past_len, past_len + t, device=x.device)
        q = apply_rope(q, positions, self.theta)
        k = apply_rope(k, positions, self.theta)
        if past is not None:
            k = torch.cat((past[0], k), dim=-2)
            v = torch.cat((past[1], v), dim=-2)
        new_cache = (k, v)                     # 紧凑存储 Hkv 个头，K 已旋转
        repeat = self.n_heads // self.n_kv_heads
        keys = k.repeat_interleave(repeat, dim=1)
        values = v.repeat_interleave(repeat, dim=1)
        scores = (q.float() @ keys.float().transpose(-2, -1)) / math.sqrt(self.head_dim)
        key_positions = torch.arange(k.size(-2), device=x.device)
        # 例：past_len=3、t=2 时，两行可见列数分别是 4 和 5。
        allowed = key_positions[None, :] <= positions[:, None]
        scores = scores.masked_fill(~allowed[None, None, :, :], float("-inf"))
        weights = torch.softmax(scores, dim=-1).to(values.dtype)
        mixed = (weights @ values).transpose(1, 2).reshape(b, t, dim)
        return self.o_proj(mixed), new_cache

CachedAttention 继承前面的投影层，复用相同参数名称；新增的 past 是 (K,V)。new_cache 在 repeat_interleave 之前创建，因此只保存 Hkv 个头，避免失去 GQA 的缓存优势。

模型外层还需要维护一个“每层一个 cache”的列表：每层取到自己的 cache，处理新 token，再把更新后的 cache 收集回来。完整实现位于第 16 章的 CachedLlama。它是推理专用实现，前向禁止记录梯度；训练继续使用无 cache 的 MiniLlama。

缓存能省多少内存？

KV cache 大小约为：

2 × L × B × T × Hkv × d × 每元素字节数

2 表示 K 和 V，L 是层数。例：L=32,B=1,T=8192,Hkv=8,d=128，BF16 每元素 2 字节，缓存为 1,073,741,824 字节，即 1 GiB。同样条件 Hkv=32 则是 4 GiB。这里只算 K/V 张量，不含权重、激活、临时 buffer 或缓存管理开销。

本实现用 torch.cat 动态拼接，每步会复制缓存，适合教学而非生产性能。生产系统会使用预分配、分页管理及专门的注意力内核。KV cache 避免重复计算旧 token，但新 Query 仍需读取历史，因此普通密集注意力的单步读取开销仍随上下文长度增长。

先约定清楚这个 cache 的边界

本教程支持同一 batch 中等长、连续位置的序列，以及逐 token 或多 token 分块续接；没有 padding、滑动窗口和中途删除缓存。换一条 prompt 要从 caches=None 开始。位置偏移按缓存长度推导，仅在这些边界下成立。

动手题：为什么“已有 cache，T=1”时不能直接照搬 is_causal=True？

PyTorch SDPA 对非方阵的 is_causal=True 使用左上对齐的因果规则。对于长度为 1 的新 Query 和较长的完整 K/V，它并不自动知道这个 Query 的绝对位置在最后。这个场景可在确认所有 Key 都合法时不加 mask；更通用的写法是显式传入按绝对位置构造的 allowed mask，并设置 is_causal=False。

14 · 自回归生成：将最后一位分数变成新 token

前向负责“给出下一位的分数”，采样负责“选哪一个 token”。这两件事要分开理解。训练 loss 不会调用采样；它直接比较所有有效位置的 logits 与真实目标。

先写最简单的贪心生成

每次把已有 tokens 送进模型，取 logits[:, -1, :]，选择最大分数的 token，拼回序列。取的是最后一个时间位置，不是最后一个词表类别。

Temperature 和 Top-k

选择方法 规则 本教程用法
贪心 选最大 logits temperature=0
温度采样 对 logits/temperature 做 softmax，再随机选 temperature>0
Top-k 只保留分数最高的 k 个候选，再采样 top_k=20 等

温度较低时分布更尖，较高时更平，但不是“值越高效果越好”。temperature=0 不能真的拿来做除法，因此代码用独立的 argmax 分支。Top-k 在贪心分支不产生额外作用。

组件 · sample_next13 行
def sample_next(logits, temperature=0.0, top_k=None):
    """输入 [B,Vocab]；输出 [B,1]。temperature=0 表示贪心生成。"""
    if temperature < 0 or not math.isfinite(temperature):
        raise ValueError("temperature 必须是有限非负数")
    if temperature == 0:
        return logits.argmax(dim=-1, keepdim=True)
    scores = logits.float() / temperature
    if top_k is not None:
        if top_k < 1:
            raise ValueError("top_k 必须 >= 1")
        values, indices = scores.topk(min(top_k, scores.size(-1)), dim=-1)
        scores = torch.full_like(scores, float("-inf")).scatter(-1, indices, values)
    return torch.multinomial(F.softmax(scores, dim=-1), num_samples=1)

Top-k 使用 topk 返回的具体下标，再散射到全为 -inf 的张量中，保留明确的 k 个候选。之后 multinomial 在归一化分布中抽样。这里没有实现 Top-p、重复惩罚、Beam Search 等解码策略，先掌握这两个即可。

15 · 手撕 FlashAttention-2：分块前向与重计算反向

到这里，你已经会写 QKᵀ → mask → softmax → PV。本章保持同一个注意力公式，改变的是计算顺序、保存哪些中间量，以及怎样组织并行工作。这里用 N 表示序列长度，与前文的 T 相同。

本章交付的代码范围
下面是可以在 CPU 上运行、可以接入前文模型训练的 FlashAttention-2 算法级教学实现：分块、在线 Softmax、末尾归一化、自定义反向与重计算都亲手写出。GPU 版的线程块调度、warp 内分工和 SRAM 复用不由 Python 循环实现，因此这段代码不提供生产内核的加速效果。它的用途是把 FA2 的数学与数据流拆开看懂。

15.1 为什么先解决“存不下”，而不是改注意力公式？

显式实现会建立 [B,H,N,N] 的分数或概率矩阵。只算一个这样的 FP32 矩阵，B=1、H=32、N=8192 时就要 1×32×8192²×4 = 8 GiB；这还没有计算其余激活和梯度。

FlashAttention 按块计算分数，在小块内完成 Softmax 的统计与 Value 累加，避免把完整的 N×N 中间结果写入显存。它仍是精确的标准注意力算法，浮点舍入误差除外；没有用稀疏或低秩近似替换公式。 计算复杂度仍是 O(N²d)。本教学版的额外分数工作区是 O(BH·Bq·Bk)，另需 O(BHNd) 的输入、输出和梯度存储。

变量 形状 存什么
qi [B,H,Bq,d] 当前 Query 行块
kj, vj [B,H,Bk,d] 当前 Key / Value 块
scores, p_tilde [B,H,Bq,Bk] 当前块的分数与未归一化权重
row_max, row_sum [B,H,Bq,1] 每行最大值与指数和
acc [B,H,Bq,d] 每行 Value 的加权累加器
lse [B,H,N] 每行 log-sum-exp，反向时恢复概率

表里的 Bq/Bk 表示块容量；序列末尾不足一整块时，用实际剩余长度。

15.2 在线 Softmax：每次多看一块，怎样保持答案不变？

普通稳定 Softmax 先减去整行最大值 m。分块后你还没看到所有 Key，就不知道最终 m。因此每看一个新块，需要把旧结果换到新的“指数基准”下。

m′ = max(m, max(Sij))
α = exp(m − m′)，  P̃ = exp(Sij − m′)
ℓ′ = αℓ + rowsum(P̃)
A′ = αA + P̃Vj
全部 Key 块处理完：Oi = A / ℓ，  Li = m + log(ℓ)

其中 S 已经除以 √d，并加上因果 mask。m、ℓ 都是“每行一个数”，A 是“每行一个 d 维向量”。初始化 m=-∞, ℓ=0, A=0。代码中的 row_max / row_sum / acc / lse 分别对应 m / ℓ / A / L。

α 为什么必须乘两次？ 旧的分母和分子都使用旧最大值 m。最大值变为 m′ 后，旧的每个指数项都少乘一个 exp(m′−m)，所以要同时把 ℓ 和 A 乘上 exp(m−m′)。只改分母、忘了改累加器，输出一定不对。

手算一行：分数为 [1,2,3]，Value 为 [10,20,30]。先读前两项，有 m=2, ℓ=e⁻¹+1, A=10e⁻¹+20；再读第三项，m′=3, α=e⁻¹。最后分母为 e⁻²+e⁻¹+1，分子为 10e⁻²+20e⁻¹+30，与一次性做 Softmax 的结果相同，输出约 25.7521。

15.3 FA2 相比第一代，还改了哪些地方？

在线 Softmax 和分块思想来自 FlashAttention；只写分块循环还不足以说明 FA2 的性能来源。

FA2 的改动 为什么有用 本文如何体现
减少非矩阵乘运算 GPU 的矩阵乘吞吐很高，其余操作容易成为瓶颈 累加未归一化的 A，遍历结束才做一次 A/ℓ
让不同 Query 行块独立计算 短 batch、少头数时，也能产生足够多并行任务 前向把 Query 块放在外层；各块写自己的输出行
warp 之间切分 Q，复用 K/V 减少 warp 之间交换和归约中间结果 Python 版只表达算法；实际分工需 CUDA/Triton 内核

在 GPU 前向内核中，可以把任务理解为 (batch, head, query_block)，任务内部遍历 K/V 块。下面的 Python 外层循环是串行执行的，不会自动变成这样的 GPU 线程块调度。同样，反向的 += 是顺序累加；真正在多个线程块中并行累加时，还要安排梯度归约，不能直接照搬。

15.4 手写前向：每次只保留一个分数块

先固定边界，避免把缓存和 padding 的难点混进来：Q/K/V 都是同形的 [B,H,N,d]，支持 FP32/FP64，序列等长、没有 padding 和 dropout。传入的是已做 RoPE 的 Q/K、未旋转的 V；GQA 在进入本函数前按第 12 章扩展 K/V 头数。

def fa2_forward(q, k, v, block_q, block_k, causal):
    # q/k/v: [B,H,N,d]，本教程限定 FP32/FP64、等长、无 padding。
    n, d = q.shape[-2:]
    scale = 1.0 / math.sqrt(d)
    out = torch.empty_like(q)
    lse = torch.empty(q.shape[:-1], device=q.device, dtype=q.dtype)
    for qs in range(0, n, block_q):
        qe = min(qs + block_q, n)
        qi = q[..., qs:qe, :]
        q_pos = torch.arange(qs, qe, device=q.device)
        row_max = torch.full_like(qi[..., :1], -torch.inf)
        row_sum = torch.zeros_like(row_max)
        acc = torch.zeros_like(qi)
        # 因果模式只访问可能可见的 K/V 块。
        stop = qe if causal else n
        for ks in range(0, stop, block_k):
            ke = min(ks + block_k, n)
            kj, vj = k[..., ks:ke, :], v[..., ks:ke, :]
            scores = (qi @ kj.transpose(-2, -1)) * scale
            if causal:
                k_pos = torch.arange(ks, ke, device=q.device)
                allowed = k_pos[None, :] <= q_pos[:, None]
                scores = scores.masked_fill(~allowed, -torch.inf)
            new_max = torch.maximum(
                row_max, scores.amax(dim=-1, keepdim=True)
            )
            alpha = torch.exp(row_max - new_max)
            p_tilde = torch.exp(scores - new_max)
            row_sum = alpha * row_sum + p_tilde.sum(-1, keepdim=True)
            acc = alpha * acc + p_tilde @ vj
            row_max = new_max
        out[..., qs:qe, :] = acc / row_sum
        lse[..., qs:qe] = (row_max + row_sum.log()).squeeze(-1)
    return out, lse

读代码时按下面四步跟踪一个 Query 块：

  1. qi 取出几行 Query，初始化这几行的 m、ℓ、A。
  2. 每次读一块 K/V，用 qi @ kjᵀ 得到一个 Bq×Bk 的分数块。
  3. 先更新最大值，再同步缩放旧的分子和分母；当前块的 Value 贡献加入 A。
  4. 遍历结束做 A/ℓ，写出这几行 O，并保存 L 供反向使用。

因果模式下，stop=qe 跳过整个落在未来的 Key 块；与当前 Query 块交叠的块仍需逐元素 mask。最后一个块用 min(...) 截断，所以 N 不必被块大小整除。当前实现从 Key 位置 0 开始，且每个 Query 都能看到自己，因此第一块中每行至少有一个有效 Key；若日后加入 padding，必须另行处理整行都被 mask 的情况，避免 −∞ − (−∞) 产生 NaN。

15.5 手写反向：不保存 P，使用 L 把当前块重算出来

如果只把分块循环写成普通 PyTorch 函数，然后直接调用 .backward()，自动求导可能保留每个块的中间量，失去节省激活存储的目的。因此下一步是自定义反向，只保存 Q、K、V、O、L。

先把一个头的公式写清楚。设上游梯度为 dO，分数 S=QKᵀ/√d，概率 P=softmax(S)：

dV = PᵀdO，  dP = dOVᵀ
Δi = ∑j PijdPij = ∑r OirdOir
dS = P ⊙ (dP − Δ)
dQ = dSK / √d，  dK = dSᵀQ / √d
每个块的概率：Pij = exp(Sij − Li)

这里 ⊙ 是逐元素乘法；Δ 沿 Key 维广播。为什么 Δ 可以由 O 计算？把 Oᵢ=ΣⱼPᵢⱼVⱼ 代入 Oᵢ·dOᵢ，展开就是 ΣⱼPᵢⱼ(Vⱼ·dOᵢ)，括号里恰好是 dPᵢⱼ。

def fa2_backward(q, k, v, out, lse, grad_out, block_q, block_k, causal):
    n, d = q.shape[-2:]
    scale = 1.0 / math.sqrt(d)
    dq, dk, dv = [torch.zeros_like(x) for x in (q, k, v)]
    # 每一行的 delta = sum_j(P_ij * dP_ij) = dot(O_i, dO_i)。
    delta = (out * grad_out).sum(dim=-1, keepdim=True)
    for qs in range(0, n, block_q):
        qe = min(qs + block_q, n)
        qi = q[..., qs:qe, :]
        doi = grad_out[..., qs:qe, :]
        li = lse[..., qs:qe, None]
        di = delta[..., qs:qe, :]
        q_pos = torch.arange(qs, qe, device=q.device)
        stop = qe if causal else n
        for ks in range(0, stop, block_k):
            ke = min(ks + block_k, n)
            kj, vj = k[..., ks:ke, :], v[..., ks:ke, :]
            scores = (qi @ kj.transpose(-2, -1)) * scale
            if causal:
                k_pos = torch.arange(ks, ke, device=q.device)
                allowed = k_pos[None, :] <= q_pos[:, None]
                scores = scores.masked_fill(~allowed, -torch.inf)
            # 只重建当前 tile 的 P，不保存整个 [N,N] 矩阵。
            p = torch.exp(scores - li)
            dv[..., ks:ke, :] += p.transpose(-2, -1) @ doi
            dp = doi @ vj.transpose(-2, -1)
            ds = p * (dp - di)
            dq[..., qs:qe, :] += (ds @ kj) * scale
            dk[..., ks:ke, :] += (ds.transpose(-2, -1) @ qi) * scale
    return dq, dk, dv

注意三处梯度都用 +=：同一 Query 行会从多个 Key 块收到贡献，同一 Key/Value 行也会从多个 Query 块收到贡献。scale 在 dQ 和 dK 中各乘一次，因为 dS 是相对于缩放后分数 S 的梯度。

def single_head_attention(q, k, v, causal=True):
    """q/k/v: [B, T, d]；返回输出和可检查的注意力权重。"""
    scores = (q @ k.transpose(-2, -1)) / math.sqrt(q.size(-1))
    if causal:
        t = q.size(-2)
        allowed = torch.ones(t, t, device=q.device, dtype=torch.bool).tril()
        scores = scores.masked_fill(~allowed, float("-inf"))
    weights = torch.softmax(scores, dim=-1)
    return weights @ v, weights


class CausalMHA(nn.Module):
    def __init__(self, dim, n_heads):
        super().__init__()
        if dim % n_heads != 0:
            raise ValueError("dim 必须能被 n_heads 整除")
        self.n_heads = n_heads
        self.head_dim = dim // n_heads
        self.q_proj = nn.Linear(dim, dim, bias=False)
        self.k_proj = nn.Linear(dim, dim, bias=False)
        self.v_proj = nn.Linear(dim, dim, bias=False)
        self.o_proj = nn.Linear(dim, dim, bias=False)

    def forward(self, x):
        b, t, d_model = x.shape
        # 先拆最后一维，再交换 T 和 H 两个轴。
        q = self.q_proj(x).reshape(b, t, self.n_heads, self.head_dim).transpose(1, 2)
        k = self.k_proj(x).reshape(b, t, self.n_heads, self.head_dim).transpose(1, 2)
        v = self.v_proj(x).reshape(b, t, self.n_heads, self.head_dim).transpose(1, 2)
        # [B,H,T,d] @ [B,H,d,T] = [B,H,T,T]
        scores = (q.float() @ k.float().transpose(-2, -1)) / math.sqrt(self.head_dim)
        allowed = torch.ones(t, t, dtype=torch.bool, device=x.device).tril()
        scores = scores.masked_fill(~allowed, float("-inf"))
        weights = torch.softmax(scores, dim=-1).to(v.dtype)
        mixed = weights @ v                         # [B,H,T,d]
        merged = mixed.transpose(1, 2).reshape(b, t, d_model)
        return self.o_proj(merged)                  # [B,T,D]


class RMSNorm(nn.Module):
    def __init__(self, dim, eps=1e-6):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(dim))
        self.eps = eps

    def forward(self, x):
        xf = x.float()                          # 在 FP32 中计算统计量
        mean_square = xf.square().mean(dim=-1, keepdim=True)
        normalized = xf * torch.rsqrt(mean_square + self.eps)
        return (normalized * self.weight.float()).to(x.dtype)


def apply_rope(x, positions, theta=10000.0):
    """x: [B,H,T,d]；positions: [T]；使用相邻偶/奇维度配对。"""
    d = x.size(-1)
    if d % 2 or positions.numel() != x.size(-2):
        raise ValueError("检查 head_dim 和 positions 长度")
    inv_freq = theta ** (-torch.arange(0, d, 2, device=x.device, dtype=torch.float32) / d)
    angles = positions.to(device=x.device, dtype=torch.float32)[:, None] * inv_freq[None, :]
    cos = angles.cos()[None, None, :, :]         # [1,1,T,d/2]
    sin = angles.sin()[None, None, :, :]
    even = x.float()[..., 0::2]                  # [B,H,T,d/2]
    odd = x.float()[..., 1::2]
    rotated_even = even * cos - odd * sin
    rotated_odd = even * sin + odd * cos
    return torch.stack((rotated_even, rotated_odd), dim=-1).flatten(-2).to(x.dtype)

        qe = min(qs + block_q, n)
        qi = q[..., qs:qe, :]
        q_pos = torch.arange(qs, qe, device=q.device)
        row_max = torch.full_like(qi[..., :1], -torch.inf)
        row_sum = torch.zeros_like(row_max)
        acc = torch.zeros_like(qi)
        # 因果模式只访问可能可见的 K/V 块。
        stop = qe if causal else n
        for ks in range(0, stop, block_k):
            ke = min(ks + block_k, n)
            kj, vj = k[..., ks:ke, :], v[..., ks:ke, :]
            scores = (qi @ kj.transpose(-2, -1)) * scale
            if causal:
                k_pos = torch.arange(ks, ke, device=q.device)
                allowed = k_pos[None, :] <= q_pos[:, None]
                scores = scores.masked_fill(~allowed, -torch.inf)
            new_max = torch.maximum(
                row_max, scores.amax(dim=-1, keepdim=True)
            )
            alpha = torch.exp(row_max - new_max)
            p_tilde = torch.exp(scores - new_max)
            row_sum = alpha * row_sum + p_tilde.sum(-1, keepdim=True)
            acc = alpha * acc + p_tilde @ vj
            row_max = new_max
        out[..., qs:qe, :] = acc / row_sum
        lse[..., qs:qe] = (row_max + row_sum.log()).squeeze(-1)
    return out, lse


def fa2_backward(q, k, v, out, lse, grad_out, block_q, block_k, causal):
    n, d = q.shape[-2:]
    scale = 1.0 / math.sqrt(d)
    dq, dk, dv = [torch.zeros_like(x) for x in (q, k, v)]
    # 每一行的 delta = sum_j(P_ij * dP_ij) = dot(O_i, dO_i)。
    delta = (out * grad_out).sum(dim=-1, keepdim=True)
    for qs in range(0, n, block_q):
        qe = min(qs + block_q, n)
        qi = q[..., qs:qe, :]
        doi = grad_out[..., qs:qe, :]
        li = lse[..., qs:qe, None]
        di = delta[..., qs:qe, :]
        q_pos = torch.arange(qs, qe, device=q.device)
        stop = qe if causal else n
        for ks in range(0, stop, block_k):
            ke = min(ks + block_k, n)
            kj, vj = k[..., ks:ke, :], v[..., ks:ke, :]
            scores = (qi @ kj.transpose(-2, -1)) * scale
            if causal:
                k_pos = torch.arange(ks, ke, device=q.device)
                allowed = k_pos[None, :] <= q_pos[:, None]
                scores = scores.masked_fill(~allowed, -torch.inf)
            # 只重建当前 tile 的 P，不保存整个 [N,N] 矩阵。
            p = torch.exp(scores - li)
            dv[..., ks:ke, :] += p.transpose(-2, -1) @ doi
            dp = doi @ vj.transpose(-2, -1)
            ds = p * (dp - di)
            dq[..., qs:qe, :] += (ds @ kj) * scale
            dk[..., ks:ke, :] += (ds.transpose(-2, -1) @ qi) * scale
    return dq, dk, dv


class FlashAttention2Teaching(torch.autograd.Function):
    @staticmethod
    def forward(ctx, q, k, v, block_q, block_k, causal):
        out, lse = fa2_forward(q, k, v, block_q, block_k, causal)
        # 自定义 Function 的 forward 不记录内部算子图。
        ctx.save_for_backward(q, k, v, out, lse)
        ctx.settings = (block_q, block_k, causal)
        return out

    @staticmethod
    @once_differentiable
    def backward(ctx, grad_out):
        q, k, v, out, lse = ctx.saved_tensors
        dq, dk, dv = fa2_backward(
            q, k, v, out, lse, grad_out, *ctx.settings
        )
        return dq, dk, dv, None, None, None


def flash_attention_2(q, k, v, block_q=32, block_k=32, causal=True):
    """同形 [B,H,N,d]，FP32/FP64，仅一阶梯度；CPU/GPU 均可执行。"""
    if q.ndim != 4 or q.shape != k.shape or q.shape != v.shape:
        raise ValueError("q/k/v 必须同形，且为 [B,H,N,d]")
    if min(q.shape) < 1 or block_q < 1 or block_k < 1:
        raise ValueError("张量各维和分块大小必须为正数")
    if q.dtype not in (torch.float32, torch.float64):
        raise ValueError("教学版只支持 FP32/FP64")
    if not (q.dtype == k.dtype == v.dtype and q.device == k.device == v.device):
        raise ValueError("q/k/v 的 dtype 和 device 必须一致")
    return FlashAttention2Teaching.apply(q, k, v, block_q, block_k, causal)

class LlamaAttention(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.n_heads = cfg.n_heads
        self.n_kv_heads = cfg.n_kv_heads
        self.head_dim = cfg.dim // cfg.n_heads
        self.theta = cfg.rope_theta
        self.backend = cfg.attention_backend
        self.q_proj = nn.Linear(cfg.dim, cfg.n_heads * self.head_dim, bias=False)
        self.k_proj = nn.Linear(cfg.dim, cfg.n_kv_heads * self.head_dim, bias=False)
        self.v_proj = nn.Linear(cfg.dim, cfg.n_kv_heads * self.head_dim, bias=False)
        self.o_proj = nn.Linear(cfg.dim, cfg.dim, bias=False)

    def forward(self, x):
        b, t, dim = x.shape
        q = self.q_proj(x).reshape(b, t, self.n_heads, self.head_dim).transpose(1, 2)
        k = self.k_proj(x).reshape(b, t, self.n_kv_heads, self.head_dim).transpose(1, 2)
        v = self.v_proj(x).reshape(b, t, self.n_kv_heads, self.head_dim).transpose(1, 2)
        positions = torch.arange(t, device=x.device)
        q = apply_rope(q, positions, self.theta)
        k = apply_rope(k, positions, self.theta)  # V 不旋转
        repeat = self.n_heads // self.n_kv_heads
        k = k.repeat_interleave(repeat, dim=1)
        v = v.repeat_interleave(repeat, dim=1)
        if self.backend == "fa2":
            mixed = flash_attention_2(q, k, v, block_q=16, block_k=16)
        else:
            scores = (q.float() @ k.float().transpose(-2, -1)) / math.sqrt(self.head_dim)
            allowed = torch.ones(t, t, device=x.device, dtype=torch.bool).tril()
            scores = scores.masked_fill(~allowed, float("-inf"))
            weights = F.softmax(scores, dim=-1).to(v.dtype)
            mixed = weights @ v
        merged = mixed.transpose(1, 2).reshape(b, t, dim)
        return self.o_proj(merged)


class DecoderBlock(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.attn_norm = RMSNorm(cfg.dim, cfg.norm_eps)
        self.attn = LlamaAttention(cfg)
        self.ffn_norm = RMSNorm(cfg.dim, cfg.norm_eps)
        self.ffn = SwiGLU(cfg.dim, cfg.hidden_dim)

    def forward(self, x):
        x = x + self.attn(self.attn_norm(x))
        x = x + self.ffn(self.ffn_norm(x))
        return x


class MiniLlama(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.cfg = cfg
        self.embedding = nn.Embedding(cfg.vocab_size, cfg.dim)
        self.layers = nn.ModuleList([DecoderBlock(cfg) for _ in range(cfg.n_layers)])
        self.final_norm = RMSNorm(cfg.dim, cfg.norm_eps)
        self.lm_head = nn.Linear(cfg.dim, cfg.vocab_size, bias=False)
        self.apply(self._init_weights)

    @staticmethod
    def _init_weights(module):
        if isinstance(module, (nn.Linear, nn.Embedding)):
            nn.init.normal_(module.weight, mean=0.0, std=0.02)

    def forward(self, input_ids):
        if input_ids.ndim != 2 or not 0 < input_ids.size(1) <= self.cfg.max_seq_len:
            raise ValueError("input_ids 需要是 [B,T]，且 1 <= T <= max_seq_len")
        hidden = self.embedding(input_ids)      # [B,T] -> [B,T,D]
        for layer in self.layers:
            hidden = layer(hidden)
        return self.lm_head(self.final_norm(hidden)).float()  # [B,T,Vocab]


def next_token_loss(logits, targets):
    """targets 已经由数据侧右移一位；这里不能再 shift 一次。"""
    return F.cross_entropy(logits.reshape(-1, logits.size(-1)),
                           targets.reshape(-1), ignore_index=-100)

def sample_next(logits, temperature=0.0, top_k=None):
    """输入 [B,Vocab]；输出 [B,1]。temperature=0 表示贪心生成。"""
    if temperature < 0 or not math.isfinite(temperature):
        raise ValueError("temperature 必须是有限非负数")
    if temperature == 0:
        return logits.argmax(dim=-1, keepdim=True)
    scores = logits.float() / temperature
    if top_k is not None:
        if top_k < 1:
            raise ValueError("top_k 必须 >= 1")
        values, indices = scores.topk(min(top_k, scores.size(-1)), dim=-1)
        scores = torch.full_like(scores, float("-inf")).scatter(-1, indices, values)
    return torch.multinomial(F.softmax(scores, dim=-1), num_samples=1)

class CachedAttention(LlamaAttention):
    def forward(self, x, past=None):
        b, t, dim = x.shape
        past_len = 0 if past is None else past[0].size(-2)
        q = self.q_proj(x).reshape(b, t, self.n_heads, self.head_dim).transpose(1, 2)
        k = self.k_proj(x).reshape(b, t, self.n_kv_heads, self.head_dim).transpose(1, 2)
        v = self.v_proj(x).reshape(b, t, self.n_kv_heads, self.head_dim).transpose(1, 2)
        positions = torch.arange(past_len, past_len + t, device=x.device)
        q = apply_rope(q, positions, self.theta)
        k = apply_rope(k, positions, self.theta)
        if past is not None:
            k = torch.cat((past[0], k), dim=-2)
            v = torch.cat((past[1], v), dim=-2)
        new_cache = (k, v)                     # 紧凑存储 Hkv 个头，K 已旋转
        repeat = self.n_heads // self.n_kv_heads
        keys = k.repeat_interleave(repeat, dim=1)
        values = v.repeat_interleave(repeat, dim=1)
        scores = (q.float() @ keys.float().transpose(-2, -1)) / math.sqrt(self.head_dim)
        key_positions = torch.arange(k.size(-2), device=x.device)
        # 例：past_len=3、t=2 时，两行可见列数分别是 4 和 5。
        allowed = key_positions[None, :] <= positions[:, None]
        scores = scores.masked_fill(~allowed[None, None, :, :], float("-inf"))
        weights = torch.softmax(scores, dim=-1).to(values.dtype)
        mixed = (weights @ values).transpose(1, 2).reshape(b, t, dim)
        return self.o_proj(mixed), new_cache


class CachedLlama(MiniLlama):
    def __init__(self, cfg):
        super().__init__(cfg)
        for layer in self.layers:
            layer.attn = CachedAttention(cfg)
        self.apply(self._init_weights)

    @torch.no_grad()
    def forward(self, input_ids, caches=None):
        if input_ids.ndim != 2 or input_ids.size(1) < 1:
            raise ValueError("input_ids 需要是非空 [B,T]")
        if caches is None:
            caches = [None] * self.cfg.n_layers
        if len(caches) != self.cfg.n_layers:
            raise ValueError("每层都需要一个 cache 槽位")
        populated = [c is not None for c in caches]
        if any(populated) and not all(populated):
            raise ValueError("cache 必须全部为空或全部有效")
        lengths = [0 if c is None else c[0].size(-2) for c in caches]
        if len(set(lengths)) != 1:
            raise ValueError("各层 cache 长度必须相等")
        for c in caches:
            if c is not None:
                expected = (input_ids.size(0), self.cfg.n_kv_heads,
                            lengths[0], self.cfg.dim // self.cfg.n_heads)
                if tuple(c[0].shape) != expected or tuple(c[1].shape) != expected:
                    raise ValueError("cache 的 batch/head/length/dim 不匹配")
        if lengths[0] + input_ids.size(1) > self.cfg.max_seq_len:
            raise ValueError("输入与 cache 总长度超出 max_seq_len")
        hidden = self.embedding(input_ids)
        updated = []
        for layer, past in zip(self.layers, caches):
            attn_out, cache = layer.attn(layer.attn_norm(hidden), past)
            hidden = hidden + attn_out
            hidden = hidden + layer.ffn(layer.ffn_norm(hidden))
            updated.append(cache)
        logits = self.lm_head(self.final_norm(hidden)).float()
        return logits, updated


@torch.no_grad()
def generate_cached(model, input_ids, max_new_tokens=20, temperature=0.0, top_k=None):
    if input_ids.ndim != 2 or input_ids.size(1) < 1 or max_new_tokens < 0:
        raise ValueError("需要非空 [B,T] 输入，且 max_new_tokens >= 0")
    if input_ids.size(1) + max_new_tokens > model.cfg.max_seq_len:
        raise ValueError("教学版不滑动窗口；请缩短输入/输出长度")
    was_training = model.training
    model.eval()
    try:
        tokens = input_ids.clone()
        if max_new_tokens == 0:
            return tokens
        logits, caches = model(tokens)          # prefill：一次处理整个 prompt
        for step in range(max_new_tokens):
            new_token = sample_next(logits[:, -1, :], temperature, top_k)
            tokens = torch.cat((tokens, new_token), dim=1)
            if step + 1 < max_new_tokens:
                logits, caches = model(new_token, caches)  # decode：只传一个新 token
        return tokens
    finally:
        model.train(was_training)

不要把四个概念混成一种“更快的 Attention”

  • FlashAttention-2仍然计算同一个稠密 softmax 注意力，主要改变 GPU 上的分块、访存和并行方式。
  • 稀疏注意力改变可读位置集合，主注意力只读被选中的槽位；选哪些位置本身也有成本。
  • 线性注意力把历史压进固定大小状态，改变了计算形式；不能默认与 softmax 注意力严格等价。
  • 混合结构让状态记忆与显式检索合作。Qwen 和 Kimi 都保留周期性的检索层，并非把所有层一律换成线性注意力。

学习路线：先写“选少量位置”的共同接口，再写“记住历史”的状态递推，最后替换残差和 FFN。每一步都能与前一步做数值对照。

18 · 从 causal mask 到真的稀疏读取

先定位旧代码中昂贵的那一步

第 5 章的 Q @ K.transpose(-1, -2) 产生 [B,H,T,T] 分数。即使随后把绝大多数位置 mask 掉，这个矩阵也已经计算出来了。现在约定每个 query 带一个位置列表 ids[b,t,:]，直接取出少量 K/V，再相乘。

稠密：qt × 全部 K → T 个分数
稀疏：选 S 个索引 → gather K/V → qt × Kselected → S 个分数

进阶篇统一把多头张量放成 [B,T,H,d]；基础篇部分代码使用 [B,H,T,d]。只要先确认轴，公式没有变化。ids=-1 表示补齐占位，必须先过滤再索引，不能让 Python 把它解释成“最后一个 token”。

selected_attention · 摘自第 32 章24 行
def selected_attention(q, k, v, ids, sink=None):
    """只读取 ids 指定的位置，ids=[B,T,S]，-1 表示填充，不构造 T×T 主注意力。

    k/v 已扩展到和 q 相同的头数。sink 是逐头的零 value 虚拟槽。
    """
    B, T, H, d = q.shape
    outputs = []
    for b in range(B):
        rows = []
        for t in range(T):
            visible = ids[b, t]
            visible = visible[visible >= 0]
            assert visible.numel() > 0, '每个 query 至少要有一个可见位置'
            keys = k[b, visible]                  # [S,H,d]：真正读取少量 K
            values = v[b, visible]              # [S,H,dv]
            score = torch.einsum('hd,shd->hs', q[b, t], keys) / math.sqrt(d)
            if sink is not None:
                score = torch.cat((score, sink[:, None]), -1)
                prob = score.softmax(-1)[..., :-1]  # sink 的 value 为零
            else:
                prob = score.softmax(-1)
            rows.append(torch.einsum('hs,shv->hv', prob, values))
        outputs.append(torch.stack(rows))
    return torch.stack(outputs)

读一遍内部形状

  1. keys 是 [S,H,d]，当前 query 是 [H,d]。
  2. einsum('hd,shd->hs') 对特征维求和，得到每头 S 个分数。
  3. softmax 沿 S 轴；再与 [S,H,dv] 的 value 加权求和，得到 [H,dv]。
  4. 可选的 sink 是一个可学习分数、零 value 的虚拟槽。它只参与归一化分母，不代表某个真实 token。
先建立验收标准

把同一组 ids 变成 dense boolean mask，两个版本的输出以及 q/k/v 梯度必须一致。否则，后面 QSA 或 CSA2 出错时，很难知道问题出在选择策略还是注意力内核。

这里使用 Python 循环保留可读性。主注意力确实只 gather 被选中的值，但这不等于在 GPU 上一定更快；生产实现还要解决不规则访存、分块和融合。

动手想一想：位置 7 选了 [0, 3, 7]，位置 3 能选 7 吗？

不能。稀疏选择是 causal 约束的子集，不是替代品。必须先确定允许范围，再在范围内 top-k；重复选同一槽位也会改变 softmax 权重。

19 · 从 KV 列表变成一张“可更新的记忆表”

稀疏注意力仍保存可检索的历史。另一条路线是每来一个 token，就更新一份固定大小的状态。先不用 DeltaNet，写最容易理解的累加型线性注意力。

φ(x) = ELU(x) + 1
St = St−1 + φ(kt) vt⊤
zt = zt−1 + φ(kt)
ot = φ(qt)⊤St / [φ(qt)⊤zt]

先看乘法：一个 K 维 key 和一个 V 维 value 做外积，得到 [K,V] 的表。查询时，query 对这张表的行做加权求和，就读出 V 维结果。分母的 z 用于这个特定正核公式的归一化。

linear_scan · 摘自第 32 章14 行
def linear_scan(q, k, v):
    """入门公式：正特征映射 + S/z 两个累加器；这还不是 GDN/KDA。"""
    q, k = F.elu(q) + 1, F.elu(k) + 1
    B, T, H, K = q.shape
    S = q.new_zeros(B, H, K, v.shape[-1])
    z = q.new_zeros(B, H, K)
    out = []
    for t in range(T):
        S = S + k[:, t, :, :, None] * v[:, t, :, None, :]
        z = z + k[:, t]
        numerator = torch.einsum('bhk,bhkv->bhv', q[:, t], S)
        denominator = (q[:, t] * z).sum(-1, keepdim=True).clamp_min(1e-8)
        out.append(numerator / denominator)
    return torch.stack(out, 1)

这段递推与显式计算 φ(Q)φ(K)ᵀ、加因果 mask 后归一化，结果相同。它不等于把 softmax 从原 Attention 中直接删除。测试会对照这两种计算顺序。

机制单层推理状态每新增 token 的主要成本换来了什么
稠密 GQA约 O(T·Hkv·d)读取越来越长的历史直接访问历史 token
矩阵状态递推O(H·K·V)，另加短卷积状态O(H·K·V)状态大小不随 T 增长
混合模型整体递推状态 + 检索层 KV两类层共同决定不能声称整个模型缓存恒定

“线性”主要指固定头维时，序列计算随 T 线性增长；K×V 这张表并不免费。而且，这里循环版训练仍会让 autograd 保存中间状态，不能据此宣称训练显存 O(1)。生产 chunk 算法另有并行与重计算设计。

20 · Gated DeltaNet：先遗忘，再纠正，再读取

累加的缺点：同一个 key 被反复写入，会互相叠加

想象记忆已经认为“北京 → 中国”，新样本又写来同一个关联。无条件累加会不断抬高这条记忆的幅值。Delta Rule 换一个问题：先用旧状态预测当前 value，只写入预测误差。

S̄t = αtSt−1
v̂t = kt⊤S̄t
Δvt = βt(vt − v̂t)
St = S̄t + ktΔvt⊤
ot = qt⊤St / √K

α 决定旧记忆保留多少，β 决定这次误差写入多少。本程序中 q/k 先做 L2Norm。以单头、单位长度的 k、α=1、β=1 为例，更新后沿 k 方向读出的内容正好变成当前 v；β 小则只修正一部分。

delta_scan · 摘自第 32 章14 行
def delta_scan(q, k, v, alpha, beta, state=None):
    """q/k 已做 L2Norm；S=[B,H,K,V]，alpha 的末维为 1(GDN) 或 K(KDA)。"""
    B, T, H, K = q.shape
    S = q.new_zeros(B, H, K, v.shape[-1]) if state is None else state
    out = []
    for t in range(T):
        # 先遗忘：KDA 缩放 S 的 key 轴各行，不能误缩放 value 轴。
        old = S * alpha[:, t, :, :, None]
        prediction = torch.einsum('bhk,bhkv->bhv', k[:, t], old)
        correction = beta[:, t, :, None] * (v[:, t] - prediction)
        # 只写入当前 key 方向上的预测误差，而不是无条件累加整个 value。
        S = old + k[:, t, :, :, None] * correction[:, :, None, :]
        out.append(torch.einsum('bhk,bhkv->bhv', q[:, t], S) / math.sqrt(K))
    return torch.stack(out, 1), S

按代码顺序理解四行

  1. old = S * alpha：先衰减再预测。把预测放在衰减之前，会变成另一条递推。
  2. prediction：key 与状态的 K 轴收缩，得到 [B,H,V]。
  3. correction：真实 value 减预测值，乘写入强度；外积仍回到 [B,H,K,V]。
  4. 用 query 读取更新后的状态。GDN/KDA 没有上一章正核线性注意力里的 z 分母。

一个完整 GDN 子层还需要什么？

投影 Q/K/V → 因果 ShortConv → SiLU → q/k 的 L2Norm → 门控递推 → 逐头 RMSNorm → sigmoid 输出门 → 输出投影。ShortConv 只看当前及左侧几个 token，提供局部时序信息；它也必须有自己的推理缓存。

ShortConv · 摘自第 32 章13 行
class ShortConv(nn.Module):
    def __init__(self, channels, kernel=4):
        super().__init__()
        self.kernel = kernel
        self.conv = nn.Conv1d(channels, channels, kernel, groups=channels, bias=False)

    def forward(self, x, history=None):
        # 左侧补零模拟过去；右侧不补未来。history 缓存卷积前的投影值。
        if history is None:
            history = x.new_zeros(x.shape[0], self.kernel - 1, x.shape[-1])
        joined = torch.cat((history, x), 1)
        y = self.conv(joined.transpose(1, 2)).transpose(1, 2)
        return F.silu(y), joined[:, -(self.kernel - 1):]

第 21 章的 DeltaMixer(kind='gdn') 是这一整套包装。GDN 令 log_alpha = -exp(A_log) * softplus(z)，每个头只有一个遗忘量。Qwen 允许 value 头更多，代码会沿头轴重复 q/k，而不是复制时间位置。

自测：为什么只传 S，分块结果仍可能不一致？

因为 ShortConv 也依赖之前的投影值。必须同时传递矩阵状态和 q/k/v 的卷积状态。完整测试把长度 11 的序列分成 3、4、4 个 token，检查拼接结果。

21 · Kimi K3 KDA：把遗忘门细化到每个 key 通道

GDN 用一个标量同时缩放整个头的状态。如果一部分信息要长久保留、另一部分应该迅速遗忘，同一个旋钮不够精细。KDA 把 α 从 [B,T,H,1] 变成 [B,T,H,K]，分别控制状态每一行。

S̄t = Diag(αt) St−1
Kimi K3：gt = −5 · sigmoid(exp(A) · zt)，αt = exp(gt)
因此 −5 < gt,j < 0，e−5 < αt,j < 1

这就是上章 old = S * alpha[..., None] 的广播含义：新添的最后一维是 value 轴，衰减作用在 key 轴。K3 的有界 log-decay 是对旧 Kimi Linear 的更新；不能把旧版无下界的负 softplus 门直接标成 K3。

DeltaMixer · 摘自第 32 章45 行
class DeltaMixer(nn.Module):
    def __init__(self, dim=32, heads=4, key_heads=None, kind='gdn'):
        super().__init__()
        self.h, self.d, self.kind = heads, dim // heads, kind
        self.hk = key_heads or heads
        assert dim % heads == 0 and heads % self.hk == 0
        qk_dim = self.hk * self.d
        self.qk = nn.Linear(dim, 2 * qk_dim, bias=False)
        self.value = nn.Linear(dim, dim, bias=False)
        self.qconv, self.kconv = ShortConv(qk_dim), ShortConv(qk_dim)
        self.vconv = ShortConv(dim)
        self.beta_proj = nn.Linear(dim, heads, bias=False)
        self.A_log = nn.Parameter(torch.zeros(heads))
        self.decay_bias = nn.Parameter(torch.full((heads, self.d if kind == 'kda' else 1), -2.0))
        self.decay = (nn.Sequential(nn.Linear(dim, self.d, bias=False),
                                   nn.Linear(self.d, dim, bias=False))
                      if kind == 'kda' else nn.Linear(dim, heads, bias=False))
        self.output_gate = nn.Linear(dim, dim, bias=False)
        self.norm = RMSNorm(self.d)
        self.output = nn.Linear(dim, dim, bias=False)

    def forward(self, x, cache=None):
        cache = {} if cache is None else cache
        B, T, D = x.shape
        q0, k0 = self.qk(x).chunk(2, -1)
        q, cq = self.qconv(q0, cache.get('qconv'))
        k, ck = self.kconv(k0, cache.get('kconv'))
        v, cv = self.vconv(self.value(x), cache.get('vconv'))
        q = F.normalize(q.reshape(B, T, self.hk, self.d), dim=-1)
        k = F.normalize(k.reshape(B, T, self.hk, self.d), dim=-1)
        # Qwen 的 value 头可以多于 query/key 头；重复的是头，不是时间。
        q = q.repeat_interleave(self.h // self.hk, dim=2)
        k = k.repeat_interleave(self.h // self.hk, dim=2)
        v = v.reshape(B, T, self.h, self.d)
        z = self.decay(x).reshape(B, T, self.h, -1) + self.decay_bias
        scale = self.A_log.exp()[None, None, :, None]
        if self.kind == 'kda':
            log_alpha = -5.0 * torch.sigmoid(scale * z)  # K3：每通道，限制在 (-5,0)
        else:
            log_alpha = -scale * F.softplus(z)          # GDN：每头一个遗忘值
        beta = self.beta_proj(x).sigmoid()
        y, S = delta_scan(q, k, v, log_alpha.exp(), beta, cache.get('state'))
        gate = self.output_gate(x).reshape(B, T, self.h, self.d).sigmoid()
        y = self.output((self.norm(y) * gate).flatten(-2))
        return y, {'state': S, 'qconv': cq, 'kconv': ck, 'vconv': cv}

一个类里怎样看出两种模型的差别？

  • kind='gdn'：每头一个衰减量；decay 输出 H 个数。
  • kind='kda'：低秩投影输出 H×K 个衰减量；采用 K3 的 −5 下界。
  • 两者共用 delta_scan；差别进入的是 α 的形状与参数化，不能只改类名。
  • K3 的输出门使用全秩投影，作用在递推输出的逐通道 RMSNorm 之后。这里同样显式写出。
为什么要限制 log-decay 的范围？

chunk 并行会用到多步衰减的累计积及其倒数。范围受控能改善数值可表示性，并支持更整齐的矩阵计算。本文用逐 token 递推来说明数学；没有实现 KDA 的 UT 变换和 GPU chunk kernel，也没有用这个循环声称达到官方速度。

核对位置：Kimi K3 报告 §2.1.1，官方代码 KimiDeltaAttention；配置中的 gate_lower_bound=-5、use_full_rank_gate=true。见来源。

22 · QSA：用小索引器选微块，再读原始 K/V

GDN 把历史变成状态，但压缩会损失逐 token 的细节。Qwen 每隔几层安排一次显式检索：先用便宜的小索引器决定读哪里，再让主注意力读取被选中的原始 token。

沿着 4 个 token 一组走一遍

  1. 从 x 投影出小尺寸 index query 和 raw index key。
  2. 对已经完整出现的每 4 个 raw index key 求平均，再做 RMSNorm 和位置旋转；位置取该块起点。
  3. 各 index query 头与块键点积，经过 ReLU 后合并成每个块的分数。
  4. 选若干块，把块 ID 展开成原始 token ID；未完整的尾部 token 直接追加。
  5. 主 GQA 使用这些 ID 读取未压缩的 K/V，最后乘 sigmoid 输出门。

                    if self.training and n > 1:
                        # 教学监督：dense 主注意力的块质量作为 stop-gradient 软标签。
                        # hard top-k 的位置 ID 没有梯度；只用 LM loss 不能训练索引器。
                        with torch.no_grad():
                            target = torch.einsum('hd,shd->hs', q[b, t], k[b, :n * self.block]) / math.sqrt(self.d)
                            target = target.softmax(-1).mean(0).reshape(n, self.block).sum(-1)
                        losses.append(F.kl_div(score.log_softmax(0), target, reduction='sum'))
                chosen += list(range(n * self.block, t + 1))
                batch.append(chosen)
            rows.append(batch)
        ids = pack_ids(rows, x.device)
        y = selected_attention(q, k, v, ids).flatten(-2)
        aux = torch.stack(losses).mean() if losses else x.new_zeros(())
        return self.out(y * self.gate(x).sigmoid()), aux, ids

三个初学者很容易忽略的问题

第一，压缩的对象不同。QSA 在索引阶段把微块压成一个小键；主注意力仍读原 token。后面的 CSA2 则会压缩主 KV，检索出来的本身就是压缩槽。

第二，压缩不能看到未来。假设 query 在位置 5，块 [4,5,6,7] 还没有完整出现。不能先把 4 个位置求平均再 mask，它已经混入了 6、7 的信息。代码只对完整前缀求块平均，把 [4,5] 单独作为尾部。

第三，top-k 的整数 ID 不可微。LM loss 能更新被选中的主 K/V，却无法沿离散选择传回索引器。程序增加一个教学蒸馏项：用 dense 主注意力的块概率作停止梯度的目标，对 index score 做 KL。它让小实验可训练，但不等同于官方分阶段稀疏训练配方。

本文为了演示索引监督，会在训练时额外计算 dense 教师分数。由此产生的开销不能计入“稀疏推理加速”。推理时没有这条监督分支；第一遍索引扫描本身仍随上下文长度增长。

23 · CSA2 与 CED：压缩时间，再复用层间缓存

现在换成 DeepSeek 的问题：不仅少读一些位置，还要减少“每个位置存多少”和“多少层各存一份”。先把连续 r 个 token 压成一个主 KV 槽，再允许后续层共享这份槽位表。

第一步：写一个可学习的因果压缩器

每个 token 投影出 value 和压缩 logit，对同组 r 个位置的 logit 做 softmax，加权合成一个向量。权重可以逐通道不同。组的起点用于旋转位置，组的终点用于判断何时可见：只有 end ≤ query_position 才能读取。

Compressor · 摘自第 32 章19 行
class Compressor(nn.Module):
    def __init__(self, dim, latent, ratio):
        super().__init__()
        self.ratio = ratio
        self.value = nn.Linear(dim, latent, bias=False)
        self.gate = nn.Linear(dim, latent, bias=False) if ratio > 1 else None
        self.norm = RMSNorm(latent)

    def forward(self, x):
        B, T, _ = x.shape
        r, n = self.ratio, T // self.ratio
        values = self.value(x[:, :n * r]).reshape(B, n, r, self.value.out_features)
        if r > 1:
            weights = self.gate(x[:, :n * r]).reshape_as(values).softmax(2)
            values = (values * weights).sum(2)
        else:
            values = values.squeeze(2)
        starts = torch.arange(n, device=x.device) * r
        return self.norm(values), starts, starts + r - 1

r=1 表示不合并时间位置，只做投影和归一化。r=2 时，第一个 token 到来还没有完整槽位，必须允许长度为 0 的 global KV；窗口分支仍可处理它。

第三步：让较深层只在候选池里重新选

decoder 的第一个 Full 层扫描可见的全局槽位，先按块内最大分数选粗块，展开成候选池。Reindex 只从这个池中计算新分数并选细粒度 top-k。候选池通常比最终集合大，两个预算不能混为一谈。

candidate_pool · 摘自第 32 章6 行
def candidate_pool(score, block_size=2, keep_blocks=2):
    # 先按块内最大分数选粗块，再展开成位置池；未满尾块也参与。
    blocks = list(range(0, score.numel(), block_size))
    maxima = torch.stack([score[s:s + block_size].max() for s in blocks])
    selected = maxima.topk(min(keep_blocks, len(blocks))).indices.tolist()
    return [j for i in selected for j in range(blocks[i], min(blocks[i] + block_size, score.numel()))]

代码在 Reindex 中先 gather shared.candidates 再点积。若先对全部历史算完分数再 mask，就没有演示出这项计算节省。最早的 Full 层仍需扫描可见范围；“固定候选池”只限制后续重索引。

            self.iweight = nn.Linear(dim, self.ih, bias=False)

        pos = torch.arange(T, device=x.device)
        q = rope(self.q(x).reshape(B, T, self.h, self.d), pos, self.rd)

第四步：CED 到底把 Encoder 放在哪里？

这里的 encoder 是因果 encoder，对同一条自回归 token 序列工作。它不是读完未来句子的双向翻译 encoder。下半段层得到 encoder_source，上半段 Full 层的 global KV 从它投影；上半段每层的 local KV 仍来自本层输入。

报告与代码各负责说明什么

CED 的 global KV 来源切换依据 DeepSeek V4.1 报告 §2.2；官方公开的最小推理 Transformer.forward 仍是顺序执行层，不能单凭 kv_source_layers 就把跨层复用称为完整 CED。本教程在模型骨架中显式传入 encoder_source，但不实现 SWA Bounded Replay、异步预填充、FP4 KV 或部署流水线。

CSA2 示例保留共用 KV latent、注意力 sink、输出逆旋转；输出投影改为普通 Linear，使用 FP32、普通 RoPE。量化、YaRN 和分组低秩输出属于明确省略项。

24 · mHC：把一条残差流拓宽为 R 条

先暂时把 Attention 当作普通函数 F。原来输入是 [B,T,D]，现在维护 X=[B,T,R,D]。每个 token 携带 R 条支路，但 F 仍只接收 D 维输入，因此要分别写“读入”“混合残差”“写回”。

a = Hpre(X)，b = Hpost(X)，M = Hres(X)
u = Σr arXr
Yi = ΣjMijXj + bi F(Norm(u))

a 的形状是 [B,T,R]，b 也是；M 是 [B,T,R,R]。M 只混合同一 token 的不同支路，不混时间位置。mHC 对 M 使用近似双随机约束：每行、每列的和接近 1。行约束控制混合尺度，列约束避免某一条输入被任意放大复制。

sinkhorn · 摘自第 32 章8 行
def sinkhorn(logits, steps=20, eps=1e-6):
    # 非负 + 交替归一化；有限轮数只近似双随机，不保证所有输入上精确相等。
    m = logits.softmax(-1) + eps
    m = m / (m.sum(-2, keepdim=True) + eps)
    for _ in range(steps - 1):
        m = m / (m.sum(-1, keepdim=True) + eps)
        m = m / (m.sum(-2, keepdim=True) + eps)
    return m

先将每行变成正概率，再交替归一化列和行。这是有限迭代的 Sinkhorn；浮点误差和迭代轮数都影响精度，不应把“20 轮”理解为数学上的精确投影。

MHC · 摘自第 32 章28 行
class MHC(nn.Module):
    def __init__(self, dim=32, streams=4):
        super().__init__()
        self.r = streams
        self.project = nn.Linear(streams * dim, streams * streams + 2 * streams, bias=False)
        self.base = nn.Parameter(torch.zeros(streams * streams + 2 * streams))
        self.scale = nn.Parameter(torch.full((3,), 0.01))
        with torch.no_grad():
            self.base[2 * streams:].copy_((torch.eye(streams) * 2).flatten())
        self.norm = RMSNorm(dim)

    def mixes(self, x):
        # x=[B,T,R,D]；这里的 RMS 是跨 R*D，和 Qwen 的逐支路 RMS 不同。
        r = self.r
        z = self.project(rms(x.flatten(-2)))
        read = (self.scale[0] * z[..., :r] + self.base[:r]).sigmoid() + 1e-6
        write = 2 * (self.scale[1] * z[..., r:2 * r] + self.base[r:2 * r]).sigmoid()
        mix = sinkhorn((self.scale[2] * z[..., 2 * r:] + self.base[2 * r:]).reshape(*x.shape[:2], r, r))
        return read, write, mix

    def forward(self, x, function, previous_read=None):
        read, write, mix = self.mixes(x)
        # 普通 mHC 读取本层系数；V4.1 Single-Pass 读取上一子层系数。
        active_read = read if previous_read is None else previous_read
        collapsed = (x * active_read[..., None]).sum(-2)
        y = function(self.norm(collapsed))
        mixed = torch.einsum('btij,btjd->btid', mix, x)
        return mixed + write[..., None] * y.unsqueeze(-2), read

为什么 RMS 的轴又要强调一次？

mHC 的系数预测器先把 [R,D] 展成 [R·D]，在整个扁平向量上归一化，再投影出 a、b、M。真正进入 F 之前，还会对读出的 D 维向量做一次 pre-norm。它与第 26 章 Qwen 的逐支路 RMS 不是同一个位置。

小实验：让 F 输出 0，会发生什么？

mHC 仍得到 M·X，因为支路还会互相混合；只有 M 为单位矩阵时才等于 X。下一章 Qwen GR 没有这一项，所以它在 F=0 时恰好保留 X。

25 · Single-Pass mHC：这次输入用上次的读取系数

先看普通 mHC 的数据依赖：必须读完本次 X，预测出本次 a，才能再次读取 X 并做加权。DeepSeek V4.1 把 a 的使用向后移一个子层，使读取与本次系数预测可以并行准备。

普通 mHC：Xl+1 = MlXl + bl Fl(alXl)
Single-Pass：Xl+1 = MlXl + bl Fl(al−1Xl)

改动只有下标，执行顺序却不同。上章 MHC.forward(..., previous_read=...) 已实现这一选择；新的 read 随更新后的 X 返回，供下一个子层使用。

当前子层读取 X 用哪个系数当前新算系数留给谁
第一层 Attention初始化的 1/R第一层 MoE
第一层 MoE第一层 Attention 的 read第二层 Attention
第二层 Attention第一层 MoE 的 read第二层 MoE

不要在 Attention 与 MoE 之间重新设回均匀权重，也不要把当前刚算出的 read 提前用于当前 F。模型实现中显式保留 previous_read，每个子层结束再更新。

26 · Qwen Gated Residual：逐元素读取，逐支路写回

Qwen 也维护四条支路，但不用 mHC 的 R×R 混合矩阵。它先逐支路归一化，从拼接后的向量预测一个 [R,D] 读取门，取加权均值；写回时再为每条支路预测一个标量门。

u = meanr(Gr ⊙ Nr)
b = 2 · sigmoid(Wwrite · flatten(N) / R)

GatedResidual · 摘自第 32 章19 行
class GatedResidual(nn.Module):
    def __init__(self, dim=32, streams=4, rank=8):
        super().__init__()
        self.r, self.d = streams, dim
        self.weight = nn.Parameter(torch.ones(streams, dim))
        self.down = nn.Linear(streams * dim, rank, bias=False)
        self.up = nn.Linear(rank, streams * dim, bias=False)
        self.inject = nn.Linear(streams * dim, streams, bias=False)

    def read(self, x):
        n = rms(x) * self.weight  # 每支路独立 RMS；gate 看全部支路
        gate = self.up(F.silu(self.down(n.flatten(-2)) / self.r)).sigmoid().reshape_as(x)
        # gate=[B,T,R,D]，每个特征都能有不同读取权重；不是对 R 做 softmax。
        return (n * gate).mean(-2), n

    def forward(self, x, function):
        z, n = self.read(x)
        write = 2 * self.inject(n.flatten(-2) / self.r).sigmoid()
        return x + write[..., None] * function(z).unsqueeze(-2)

逐元素读取让一个支路的“语法特征”被多读一些、另一个支路的“实体特征”被多读一些。这里是 sigmoid 门和均值，不是把支路分数 softmax 成一个凸组合。写门范围为 (0,2)，也不是把读取门原样重复使用。

最终输出还需要一次学习到的读取，把 [B,T,R,D] 收回 [B,T,D]；不能直接交给 LM head。代码中的 final_read.read 专门负责这个收束。

27 · Attention Residuals：让当前层选择历史来源

现在把视角从 R 条固定支路移到“经过的层”。原始残差不断求和，所有旧输出被揉在一起。AttnRes 给每个子层一个可学习向量作为 pseudo-query，向 embedding 和历史输出询问：这次需要哪些来源？

scorei→l = wl⊤RMSNorm(vi)
αi→l = softmax来源 i(score)
hl = Σi αi→l vi

这里的 value 是原始来源向量，RMSNorm 只用于计算 key 分数。query 是每层学习到的参数，不必从当前 token 再投影一个 Q；权重仍能随 token 变化，因为该 token 的各来源向量不同。

AttnRes · 摘自第 32 章11 行
class AttnRes(nn.Module):
    def __init__(self, dim=32):
        super().__init__()
        self.query = nn.Parameter(torch.zeros(dim))  # 子层自己的可学习 pseudo-query
        self.key_norm = RMSNorm(dim)

    def forward(self, sources):
        values = torch.stack(sources, dim=2)         # [B,T,来源数,D]
        score = (self.key_norm(values) * self.query).sum(-1)
        weights = score.softmax(dim=2)             # 沿深度来源，绝不是沿 token 轴
        return (weights[..., None] * values).sum(2), weights

Full AttnRes 很直接，为什么还要 Block？

Full 版保留所有子层输出，深度增加时存储和通信也增加。Block 版把一段层的 F 输出加起来，变成一个块摘要；当前未结束块只维护 partial sum。每次读取的来源是：embedding、已完成块、当前块的部分和。

  1. 初始化 completed=[embedding]，current=None。
  2. 读取这些来源，经过 Norm 和 Attention，把 Attention 输出加到 current。
  3. 再次读取来源，经过 Norm 和 MoE，把 MoE 输出加到 current。
  4. 到了块边界，把 current 放入 completed，然后清空 current。
  5. 最后再做一次 AttnRes 聚合所有块，再接 norm 和输出头。

来源权重演示：看“层”而不是“时间”

合成分数上的 softmax 演示。真实模型分数来自该 token 各来源的 RMSNorm 向量与层级 pseudo-query 点积。

最容易写错的地方是把读取后的混合向量也累加进 current。这会重复计入历史。current 只累加本块各个 F 的输出。完整 Kimi 骨架会显式写这几步，不藏进一个含糊的 residual() 调用。

为什么 query 初始化为 0？

所有来源分数开始相同，softmax 得到平均权重，便于稳定起步。训练可以逐渐学出不同读取偏好。测试会检查零 query 的输出是否确实等于来源均值。

28 · 从 SwiGLU 到 MoE，再到 Stable LatentMoE

前面改的是 token 混合与深度混合，FFN 也要升级。MoE 为每个 token 选少量专家。共享专家处理常见变换，路由专家处理差异化变换；两条路径最终相加。

先把第 8 章 FFN 当作一个专家

Kimi K3 的 SiTU-GLU 对 SwiGLU 的两条乘法分支分别做平滑限幅：gate 使用 β₁·tanh(g/β₁)·sigmoid(g)，up 使用 β₂·tanh(u/β₂)。公开配置 β₁=4、β₂=25，因此乘法中间值绝对值受 100 限制；后面的输出 Linear 不受这个界限制。

class Expert(nn.Module):
    def __init__(self, dim, middle=None, situ=False):
        super().__init__()
        middle = middle or dim * 2
        self.gate, self.up = nn.Linear(dim, middle, bias=False), nn.Linear(dim, middle, bias=False)
        self.down, self.situ = nn.Linear(middle, dim, bias=False), situ

    def forward(self, x):
        g, u = self.gate(x), self.up(x)
        if self.situ:
            hidden = (4 * torch.tanh(g / 4) * g.sigmoid()) * (25 * torch.tanh(u / 25))
        else:
            hidden = F.silu(g) * u
        return self.down(hidden)

路由需要分清：用什么选，用什么加权

教学版保留三种不同分数函数：Qwen softmax、DeepSeek sqrt(softplus)、Kimi sigmoid。DeepSeek/Kimi 的选择偏置只用于排名，合成权重仍从无偏置分数中取出并归一化。不能把校正偏置当成专家贡献本身。

TinyMoE · 摘自第 32 章46 行
class TinyMoE(nn.Module):
    def __init__(self, dim=32, experts=4, topk=2, kind='qwen'):
        super().__init__()
        self.kind, self.topk, self.count = kind, topk, experts
        self.router = nn.Linear(dim, experts, bias=False)
        self.register_buffer('selection_bias', torch.zeros(experts))
        latent = dim // 2 if kind == 'kimi' else dim
        self.down = nn.Linear(dim, latent, bias=False) if kind == 'kimi' else nn.Identity()
        self.up = nn.Linear(latent, dim, bias=False) if kind == 'kimi' else nn.Identity()
        self.norm = RMSNorm(latent) if kind == 'kimi' else nn.Identity()
        self.experts = nn.ModuleList([Expert(latent, situ=kind == 'kimi') for _ in range(experts)])
        self.shared = nn.ModuleList([Expert(dim, situ=kind == 'kimi') for _ in range(2 if kind == 'kimi' else 1)])
        self.shared_gate = nn.Linear(dim, 1, bias=False) if kind == 'qwen' else None

    def forward(self, x):
        flat = x.reshape(-1, x.shape[-1])
        logits = self.router(flat)
        if self.kind == 'qwen':
            score = logits.softmax(-1)
        elif self.kind == 'deepseek':
            score = F.softplus(logits).sqrt()
        else:
            score = logits.sigmoid()
        # bias 只参与选专家；权重仍从无 bias 的 score 读取。
        ids = (score + self.selection_bias).topk(self.topk, -1).indices
        weight = score.gather(1, ids)
        weight = weight / weight.sum(-1, keepdim=True).clamp_min(1e-9)
        if self.kind == 'deepseek':
            weight = 1.5 * weight
        z = self.down(flat)
        routed = torch.zeros_like(z)
        for i, expert in enumerate(self.experts):
            token, slot = torch.where(ids == i)
            if token.numel():
                # 只让选中该专家的 token 进入它；不要先把所有专家全算一遍。
                contribution = expert(z[token]) * weight[token, slot, None]
                routed = routed.index_add(0, token, contribution)
        routed = self.up(self.norm(routed))
        shared = sum(expert(flat) for expert in self.shared)
        if self.shared_gate is not None:
            shared = shared * self.shared_gate(flat).sigmoid()
        # 教学统一负载辅助项，不声称复现 Qwen 训练配方或 K3 Quantile Balancing。
        frequency = F.one_hot(ids, self.count).float().mean((0, 1)).detach()
        probability = score / score.sum(-1, keepdim=True)
        balance = self.count * (frequency * probability.mean(0)).sum()
        return (routed + shared).reshape_as(x), balance

torch.where(ids == i) 找出本次真正去专家 i 的 token。index_add 把处理后的结果加回原位置；同一个 token 去两个专家，就会累加两次各自的加权贡献。

LatentMoE 比普通 MoE 多哪两步？

共享路径：x ∈ ℝD → shared experts → ℝD
路由路径：x → W↓x ∈ ℝℓ → selected experts → 加权合成 u → RMSNorm(u) → W↑ → ℝD

只压缩路由路径；共享专家仍读全宽 x。Kimi 的稳定化 norm 在专家结果聚合后、升维投影前。把它放在 down-projection 前面并不能替代这一层。

本程序为三条路线统一使用一个小规模负载辅助项，偏置初始化为零；没有实现 DeepSeek 的完整无辅助损失平衡配方或 Kimi Quantile Balancing 的动态偏置更新。它能训练 toy 网络，但不是生产训练策略复现。DeepSeek 专家内部的官方激活裁剪也在简化范围内。

29 · 别漏掉条件记忆：N-gram Embedding 与 Engram

注意力与专家并不是容量增长的全部。对于常见的短词组，可以把过去 2–3 个 token 组成一个键，去大表里查询向量，再根据当前 hidden state 决定注入多少。这给计算路径增加的主要是查表与小投影。

用很小的表先写出基本动作

  1. 当前、前一、前二个 token 分别记作 t、p₁、p₂。
  2. 用确定性的整数函数计算 bigram/trigram bucket ID。
  3. 查出两份向量，加成 memory。
  4. 用 memory 的 key 与当前上下文做匹配，生成 gate。
  5. value 乘 gate，再加因果短卷积分支，最后注入模型。
HashMemoryTeaching · 摘自第 32 章23 行
class HashMemoryTeaching(nn.Module):
    """教学简化：bigram/trigram 哈希 + 内容门 + 因果短卷积。
    不是官方 Engram 的 hash/tokenizer 格式；不用它装载真实词表权重。
    """
    def __init__(self, dim=32, buckets=257):
        super().__init__()
        self.buckets = buckets
        self.tables = nn.ModuleList([nn.Embedding(buckets, dim) for _ in range(2)])
        self.key, self.value = nn.Linear(dim, dim, bias=False), nn.Linear(dim, dim, bias=False)
        self.conv = ShortConv(dim)

    def forward(self, ids, context):
        # 只读当前位置和左边。+1 为真实 token 留出 0 号“无历史”标记。
        token = ids + 1
        p1, p2 = F.pad(token, (1, 0))[:, :-1], F.pad(token, (2, 0))[:, :-2]
        h2 = (token + 31 * p1) % self.buckets
        h3 = (token + 31 * p1 + 997 * p2) % self.buckets
        memory = self.tables[0](h2) + self.tables[1](h3)
        gate = ((rms(self.key(memory)) * rms(context)).sum(-1, keepdim=True)
                / math.sqrt(context.shape[-1])).sigmoid()
        value = gate * self.value(memory)
        local, _ = self.conv(rms(value))
        return value + local

这里的记忆表是训练参数，不是向量数据库检索，也不是生成阶段积累的 KV cache。训练更新表项；推理只是按 ID 访问它们。表变大增加的是参数存储，即使每 token 查表计算量很低，也不能称为零存储成本。

这一章明确采用机制简化

HashMemoryTeaching 用 257 个 bucket 和两路单哈希演示碰撞、查表和内容门。官方还有多头哈希、大词表分片、特定 tokenizer 映射、分支投影和预取。Qwen N-gram 与 DeepSeek Engram 并非同一个权重格式，本文没有把二者伪装成完全相同的实现。

如果要继续扩展完整工程，优先补：缓存的生命周期与重置、prefill/decode 两种执行方式、MoE 专家并行和负载平衡、索引训练配方。再学习 MTP / DSpark、量化缓存与多模态输入；这些模块不会因为一个 toy forward 能跑通就自动得到。

        x, _ = self.final_read.read(x)

        for i, (attn, ffn, ra, rf) in enumerate(zip(self.attn, self.ffn, self.ra, self.rf)):

class GatedMLATeaching(nn.Module):
    def __init__(self, dim=32, heads=4, latent=8):
        super().__init__()
        self.h, self.d = heads, dim // heads
        self.q = nn.Sequential(nn.Linear(dim, dim // 2, bias=False), RMSNorm(dim // 2),
                               nn.Linear(dim // 2, dim, bias=False))
        self.compress = nn.Sequential(nn.Linear(dim, latent, bias=False), RMSNorm(latent))
        self.expand_kv = nn.Linear(latent, 2 * dim, bias=False)
        self.gate, self.out = nn.Linear(dim, dim, bias=False), nn.Linear(dim, dim, bias=False)

    def forward(self, x):
        B, T, D = x.shape
        latent = self.compress(x)  # 实际缓存可只存此低秩向量；教学 forward 显式展开
        k, v = self.expand_kv(latent).reshape(B, T, self.h, 2 * self.d).chunk(2, -1)
        q = self.q(x).reshape(B, T, self.h, self.d)
        y = dense_attention(q, k, v).flatten(-2)  # K3 的 MLA 不加 RoPE：NoPE
        return self.out(y * self.gate(x).sigmoid())

        self.ffn = nn.ModuleList([Expert(dim, situ=True) if i == 0 else TinyMoE(dim, kind='kimi')
                                  for i in range(layers)])
        self.ra = nn.ModuleList([AttnRes(dim) for _ in range(layers)])
        self.rf = nn.ModuleList([AttnRes(dim) for _ in range(layers)])
        self.na = nn.ModuleList([RMSNorm(dim) for _ in range(layers)])
        self.nf = nn.ModuleList([RMSNorm(dim) for _ in range(layers)])
        self.final_read, self.norm, self.head = AttnRes(dim), RMSNorm(dim), nn.Linear(dim, vocab, bias=False)

        completed, current = [embedding], None       # embedding 永远是独立来源
        aux = embedding.new_zeros(())
        for i, (attn, ffn) in enumerate(zip(self.attn, self.ffn)):

                current = None                      # 开始新块，不能把历史混合结果重复累加
            sources = completed + ([] if current is None else [current])
            z, _ = self.ra[i](sources)
            z = self.na[i](z)

            current = y if current is None else current + y
            z, _ = self.rf[i](completed + [current])
            z = self.nf[i](z)

            else:
                y = ffn(z)
            current = current + y                   # 只累加子层输出，形成块内 partial sum
        z, _ = self.final_read(completed + [current])
        return self.head(self.norm(z)), aux

31 · 不只看 shape：怎样证明没有偷偷看未来？

从便宜的组件测试走到整模型测试

  1. 线性公式对照：累加状态 vs 显式正核注意力矩阵。
  2. 稀疏输出与梯度：同一选择集合，gather vs dense mask；同时比较 q/k/v 梯度。
  3. Delta 公式：逐步误差更新 vs 显式矩阵 (I−βkkᵀ)Diag(α)S + βkvᵀ。
  4. 状态连续性：GDN/KDA 整段运行 vs 携带 S 和卷积状态分段运行。
  5. 残差不变量：Sinkhorn 行列和、GR 零输出恒等、零 query 的 AttnRes 来源均值。
  6. 索引约束：QSA 尾部保留，CSA Reindex 限于候选池，Reuse 不新建全局 KV。
  7. 整模型因果性：先算整句，再单独算多个前缀；前缀 logits 必须相同。

# === 01: 共同语言：形状、归一化、RoPE、稀疏读取 ===
def rms(x, eps=1e-6):
    # 沿特征轴归一化；保留 double 便于数值梯度检查。
    work = x if x.dtype == torch.float64 else x.float()
    return (work * torch.rsqrt(work.square().mean(-1, keepdim=True) + eps)).to(x.dtype)


class RMSNorm(nn.Module):
    def __init__(self, dim):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(dim))

    def forward(self, x):
        return rms(x) * self.weight


def rope(x, positions, rotary_dim, inverse=False, theta=10000.0):
    """x=[B,T,H,d]；只旋转最后 rotary_dim 维，相邻两维组成一对。"""
    assert rotary_dim % 2 == 0 and 0 <= rotary_dim <= x.shape[-1]
    if rotary_dim == 0:
        return x
    freq = theta ** (-torch.arange(0, rotary_dim, 2, device=x.device).to(x.dtype) / rotary_dim)
    angle = positions.to(x.dtype)[:, None] * freq[None, :]
    if inverse:
        angle = -angle
    c, s = angle.cos()[None, :, None], angle.sin()[None, :, None]
    prefix, tail = x[..., :-rotary_dim], x[..., -rotary_dim:]
    a, b = tail[..., 0::2], tail[..., 1::2]
    rotated = torch.stack((a * c - b * s, a * s + b * c), -1).flatten(-2)
    return torch.cat((prefix, rotated), -1)


def dense_attention(q, k, v, mask=None):
    # q/k/v=[B,T,H,d]；先转为逐头的分数 [B,H,T,T]。
    scores = torch.einsum('bthd,bshd->bhts', q, k) / math.sqrt(q.shape[-1])
    if mask is None:
        mask = torch.ones(q.shape[1], k.shape[1], device=q.device, dtype=torch.bool).tril()
    scores = scores.masked_fill(~mask, -torch.inf)
    return torch.einsum('bhts,bshv->bthv', scores.softmax(-1), v)


def selected_attention(q, k, v, ids, sink=None):
    """只读取 ids 指定的位置，ids=[B,T,S]，-1 表示填充，不构造 T×T 主注意力。

    k/v 已扩展到和 q 相同的头数。sink 是逐头的零 value 虚拟槽。
    """
    B, T, H, d = q.shape
    outputs = []
    for b in range(B):
        rows = []
        for t in range(T):
            visible = ids[b, t]
            visible = visible[visible >= 0]
            assert visible.numel() > 0, '每个 query 至少要有一个可见位置'
            keys = k[b, visible]                  # [S,H,d]：真正读取少量 K
            values = v[b, visible]              # [S,H,dv]
            score = torch.einsum('hd,shd->hs', q[b, t], keys) / math.sqrt(d)
            if sink is not None:
                score = torch.cat((score, sink[:, None]), -1)
                prob = score.softmax(-1)[..., :-1]  # sink 的 value 为零
            else:
                prob = score.softmax(-1)
            rows.append(torch.einsum('hs,shv->hv', prob, values))
        outputs.append(torch.stack(rows))
    return torch.stack(outputs)


def pack_ids(rows, device):
    # rows[b][t] 是变长的位置列表；使用 -1 统一补齐，不重复有效位置。
    width = max(len(x) for batch in rows for x in batch)
    out = torch.full((len(rows), len(rows[0]), width), -1, device=device, dtype=torch.long)
    for b, batch in enumerate(rows):
        for t, ids in enumerate(batch):
            out[b, t, :len(ids)] = torch.as_tensor(ids, device=device)
    return out

# === 02: 从累加型线性注意力到 Delta Rule ===
def linear_scan(q, k, v):
    """入门公式：正特征映射 + S/z 两个累加器；这还不是 GDN/KDA。"""
    q, k = F.elu(q) + 1, F.elu(k) + 1
    B, T, H, K = q.shape
    S = q.new_zeros(B, H, K, v.shape[-1])
    z = q.new_zeros(B, H, K)
    out = []
    for t in range(T):
        S = S + k[:, t, :, :, None] * v[:, t, :, None, :]
        z = z + k[:, t]
        numerator = torch.einsum('bhk,bhkv->bhv', q[:, t], S)
        denominator = (q[:, t] * z).sum(-1, keepdim=True).clamp_min(1e-8)
        out.append(numerator / denominator)
    return torch.stack(out, 1)


def delta_scan(q, k, v, alpha, beta, state=None):
    """q/k 已做 L2Norm；S=[B,H,K,V]，alpha 的末维为 1(GDN) 或 K(KDA)。"""
    B, T, H, K = q.shape
    S = q.new_zeros(B, H, K, v.shape[-1]) if state is None else state
    out = []
    for t in range(T):
        # 先遗忘：KDA 缩放 S 的 key 轴各行，不能误缩放 value 轴。
        old = S * alpha[:, t, :, :, None]
        prediction = torch.einsum('bhk,bhkv->bhv', k[:, t], old)
        correction = beta[:, t, :, None] * (v[:, t] - prediction)
        # 只写入当前 key 方向上的预测误差，而不是无条件累加整个 value。
        S = old + k[:, t, :, :, None] * correction[:, :, None, :]
        out.append(torch.einsum('bhk,bhkv->bhv', q[:, t], S) / math.sqrt(K))
    return torch.stack(out, 1), S


class ShortConv(nn.Module):
    def __init__(self, channels, kernel=4):
        super().__init__()
        self.kernel = kernel
        self.conv = nn.Conv1d(channels, channels, kernel, groups=channels, bias=False)

    def forward(self, x, history=None):
        # 左侧补零模拟过去；右侧不补未来。history 缓存卷积前的投影值。
        if history is None:
            history = x.new_zeros(x.shape[0], self.kernel - 1, x.shape[-1])
        joined = torch.cat((history, x), 1)
        y = self.conv(joined.transpose(1, 2)).transpose(1, 2)
        return F.silu(y), joined[:, -(self.kernel - 1):]

# === 03: 两种线性混合器：GDN 和 Kimi K3 KDA ===
class DeltaMixer(nn.Module):
    def __init__(self, dim=32, heads=4, key_heads=None, kind='gdn'):
        super().__init__()
        self.h, self.d, self.kind = heads, dim // heads, kind
        self.hk = key_heads or heads
        assert dim % heads == 0 and heads % self.hk == 0
        qk_dim = self.hk * self.d
        self.qk = nn.Linear(dim, 2 * qk_dim, bias=False)
        self.value = nn.Linear(dim, dim, bias=False)
        self.qconv, self.kconv = ShortConv(qk_dim), ShortConv(qk_dim)
        self.vconv = ShortConv(dim)
        self.beta_proj = nn.Linear(dim, heads, bias=False)
        self.A_log = nn.Parameter(torch.zeros(heads))
        self.decay_bias = nn.Parameter(torch.full((heads, self.d if kind == 'kda' else 1), -2.0))
        self.decay = (nn.Sequential(nn.Linear(dim, self.d, bias=False),
                                   nn.Linear(self.d, dim, bias=False))
                      if kind == 'kda' else nn.Linear(dim, heads, bias=False))
        self.output_gate = nn.Linear(dim, dim, bias=False)
        self.norm = RMSNorm(self.d)
        self.output = nn.Linear(dim, dim, bias=False)

    def forward(self, x, cache=None):
        cache = {} if cache is None else cache
        B, T, D = x.shape
        q0, k0 = self.qk(x).chunk(2, -1)
        q, cq = self.qconv(q0, cache.get('qconv'))
        k, ck = self.kconv(k0, cache.get('kconv'))
        v, cv = self.vconv(self.value(x), cache.get('vconv'))
        q = F.normalize(q.reshape(B, T, self.hk, self.d), dim=-1)
        k = F.normalize(k.reshape(B, T, self.hk, self.d), dim=-1)
        # Qwen 的 value 头可以多于 query/key 头；重复的是头，不是时间。
        q = q.repeat_interleave(self.h // self.hk, dim=2)
        k = k.repeat_interleave(self.h // self.hk, dim=2)
        v = v.reshape(B, T, self.h, self.d)
        z = self.decay(x).reshape(B, T, self.h, -1) + self.decay_bias
        scale = self.A_log.exp()[None, None, :, None]
        if self.kind == 'kda':
            log_alpha = -5.0 * torch.sigmoid(scale * z)  # K3：每通道，限制在 (-5,0)
        else:
            log_alpha = -scale * F.softplus(z)          # GDN：每头一个遗忘值
        beta = self.beta_proj(x).sigmoid()
        y, S = delta_scan(q, k, v, log_alpha.exp(), beta, cache.get('state'))
        gate = self.output_gate(x).reshape(B, T, self.h, self.d).sigmoid()
        y = self.output((self.norm(y) * gate).flatten(-2))
        return y, {'state': S, 'qconv': cq, 'kconv': ck, 'vconv': cv}

class QSATeaching(nn.Module):
    def __init__(self, dim=32, heads=4, kv_heads=2, block=4, top_blocks=2):
        super().__init__()
        self.h, self.hk, self.d = heads, kv_heads, dim // heads
        self.block, self.top_blocks, self.ih, self.idim = block, top_blocks, 2, 8
        self.rd = max(2, (self.d // 4) // 2 * 2)
        self.q = nn.Linear(dim, dim, bias=False)
        self.kv = nn.Linear(dim, 2 * kv_heads * self.d, bias=False)
        self.qnorm, self.knorm = RMSNorm(self.d), RMSNorm(self.d)
        self.iq = nn.Linear(dim, self.ih * self.idim, bias=False)
        self.ik = nn.Linear(dim, self.idim, bias=False)
        self.iqn, self.ikn = RMSNorm(self.idim), RMSNorm(self.idim)
        self.gate, self.out = nn.Linear(dim, dim, bias=False), nn.Linear(dim, dim, bias=False)

    def forward(self, x):
        B, T, D = x.shape
        pos = torch.arange(T, device=x.device)
        q = rope(self.qnorm(self.q(x).reshape(B, T, self.h, self.d)), pos, self.rd)
        k, v = self.kv(x).reshape(B, T, self.hk, 2 * self.d).chunk(2, -1)
        k = rope(self.knorm(k), pos, self.rd).repeat_interleave(self.h // self.hk, 2)
        v = v.repeat_interleave(self.h // self.hk, 2)
        iq = rope(self.iqn(self.iq(x).reshape(B, T, self.ih, self.idim)), pos, self.rd)
        raw_ik = self.ik(x)
        rows, losses = [], []
        for b in range(B):
            batch = []
            for t in range(T):
                # 只能把已经完整出现的微块做平均；尾块直接保留。
                n = (t + 1) // self.block
                chosen = []
                if n:
                    pooled = raw_ik[b, :n * self.block].reshape(n, self.block, self.idim).mean(1)
                    starts = torch.arange(n, device=x.device) * self.block
                    ik = rope(self.ikn(pooled)[None, :, None], starts, self.rd)[0, :, 0]
                    score = (iq[b, t] @ ik.T).relu().sum(0) / math.sqrt(self.idim)
                    blocks = score.topk(min(n, self.top_blocks)).indices
                    chosen = (blocks[:, None] * self.block + torch.arange(self.block, device=x.device)).flatten().tolist()
                    if self.training and n > 1:
                        # 教学监督：dense 主注意力的块质量作为 stop-gradient 软标签。
                        # hard top-k 的位置 ID 没有梯度；只用 LM loss 不能训练索引器。
                        with torch.no_grad():
                            target = torch.einsum('hd,shd->hs', q[b, t], k[b, :n * self.block]) / math.sqrt(self.d)
                            target = target.softmax(-1).mean(0).reshape(n, self.block).sum(-1)
                        losses.append(F.kl_div(score.log_softmax(0), target, reduction='sum'))
                chosen += list(range(n * self.block, t + 1))
                batch.append(chosen)
            rows.append(batch)
        ids = pack_ids(rows, x.device)
        y = selected_attention(q, k, v, ids).flatten(-2)
        aux = torch.stack(losses).mean() if losses else x.new_zeros(())
        return self.out(y * self.gate(x).sigmoid()), aux, ids

class Compressor(nn.Module):
    def __init__(self, dim, latent, ratio):
        super().__init__()
        self.ratio = ratio
        self.value = nn.Linear(dim, latent, bias=False)
        self.gate = nn.Linear(dim, latent, bias=False) if ratio > 1 else None
        self.norm = RMSNorm(latent)

    def forward(self, x):
        B, T, _ = x.shape
        r, n = self.ratio, T // self.ratio
        values = self.value(x[:, :n * r]).reshape(B, n, r, self.value.out_features)
        if r > 1:
            weights = self.gate(x[:, :n * r]).reshape_as(values).softmax(2)
            values = (values * weights).sum(2)
        else:
            values = values.squeeze(2)
        starts = torch.arange(n, device=x.device) * r
        return self.norm(values), starts, starts + r - 1

def candidate_pool(score, block_size=2, keep_blocks=2):
    # 先按块内最大分数选粗块，再展开成位置池；未满尾块也参与。
    blocks = list(range(0, score.numel(), block_size))
    maxima = torch.stack([score[s:s + block_size].max() for s in blocks])
    selected = maxima.topk(min(keep_blocks, len(blocks))).indices.tolist()
    return [j for i in selected for j in range(blocks[i], min(blocks[i] + block_size, score.numel()))]

                        batch.append([]); pool_batch.append([])
                        continue
                    # Reindex 先 gather 候选，再打分；不是打完全部分数再用 mask 假装省计算。
                    score = (iq[b, t] @ shared.index_k[b, allowed].T).relu()
                    score = (score * iw[b, t, :, None]).sum(0)
                    ids = allowed[score.topk(min(self.topk, len(allowed))).indices]
                    batch.append(ids.tolist())
                    if self.mode == 'full' and self.hierarchy:
                        pool = candidate_pool(score)
                        pool_batch.append(allowed[pool].tolist())
                    else:
                        pool_batch.append([])
                    if self.training and len(allowed) > 1:
                        with torch.no_grad():
                            target = torch.einsum('hd,sd->hs', q[b, t], shared.kv[b, allowed, 0])
                            target = (target / math.sqrt(self.d)).softmax(-1).mean(0)
                        losses.append(F.kl_div(score.log_softmax(0), target, reduction='sum'))
                rows.append(batch); pools.append(pool_batch)
            shared.ids = rows
            if self.mode == 'full' and self.hierarchy:
                shared.candidates = pools
        # global 压缩槽与 local 原始槽是不同表示，允许覆盖相同的原始 token。
        slots = local if self.mode == 'window' else torch.cat((local, shared.kv), 1)
        rows = []
        for b in range(B):
            batch = []
            for t in range(T):
                ids = list(range(max(0, t - self.window + 1), t + 1))
                if self.mode != 'window':
                    ids += [T + j for j in shared.ids[b][t]]
                batch.append(ids)
            rows.append(batch)
        ids = pack_ids(rows, x.device)
        slots = slots.expand(-1, -1, self.h, -1)
        y = selected_attention(q, slots, slots, ids, sink=self.sink)
        y = rope(y, pos, self.rd, inverse=True)  # KV 共用且 value 被旋转，输出要转回
        aux = torch.stack(losses).mean() if losses else x.new_zeros(())
        return self.out(y.flatten(-2)), shared, aux

def sinkhorn(logits, steps=20, eps=1e-6):
    # 非负 + 交替归一化；有限轮数只近似双随机，不保证所有输入上精确相等。
    m = logits.softmax(-1) + eps
    m = m / (m.sum(-2, keepdim=True) + eps)
    for _ in range(steps - 1):
        m = m / (m.sum(-1, keepdim=True) + eps)
        m = m / (m.sum(-2, keepdim=True) + eps)
    return m


class MHC(nn.Module):
    def __init__(self, dim=32, streams=4):
        super().__init__()
        self.r = streams
        self.project = nn.Linear(streams * dim, streams * streams + 2 * streams, bias=False)
        self.base = nn.Parameter(torch.zeros(streams * streams + 2 * streams))
        self.scale = nn.Parameter(torch.full((3,), 0.01))
        with torch.no_grad():
            self.base[2 * streams:].copy_((torch.eye(streams) * 2).flatten())
        self.norm = RMSNorm(dim)

    def mixes(self, x):
        # x=[B,T,R,D]；这里的 RMS 是跨 R*D，和 Qwen 的逐支路 RMS 不同。
        r = self.r
        z = self.project(rms(x.flatten(-2)))
        read = (self.scale[0] * z[..., :r] + self.base[:r]).sigmoid() + 1e-6
        write = 2 * (self.scale[1] * z[..., r:2 * r] + self.base[r:2 * r]).sigmoid()
        mix = sinkhorn((self.scale[2] * z[..., 2 * r:] + self.base[2 * r:]).reshape(*x.shape[:2], r, r))
        return read, write, mix

    def forward(self, x, function, previous_read=None):
        read, write, mix = self.mixes(x)
        # 普通 mHC 读取本层系数；V4.1 Single-Pass 读取上一子层系数。
        active_read = read if previous_read is None else previous_read
        collapsed = (x * active_read[..., None]).sum(-2)
        y = function(self.norm(collapsed))
        mixed = torch.einsum('btij,btjd->btid', mix, x)
        return mixed + write[..., None] * y.unsqueeze(-2), read


class GatedResidual(nn.Module):
    def __init__(self, dim=32, streams=4, rank=8):
        super().__init__()
        self.r, self.d = streams, dim
        self.weight = nn.Parameter(torch.ones(streams, dim))
        self.down = nn.Linear(streams * dim, rank, bias=False)
        self.up = nn.Linear(rank, streams * dim, bias=False)
        self.inject = nn.Linear(streams * dim, streams, bias=False)

    def read(self, x):
        n = rms(x) * self.weight  # 每支路独立 RMS；gate 看全部支路
        gate = self.up(F.silu(self.down(n.flatten(-2)) / self.r)).sigmoid().reshape_as(x)
        # gate=[B,T,R,D]，每个特征都能有不同读取权重；不是对 R 做 softmax。
        return (n * gate).mean(-2), n

    def forward(self, x, function):
        z, n = self.read(x)
        write = 2 * self.inject(n.flatten(-2) / self.r).sigmoid()
        return x + write[..., None] * function(z).unsqueeze(-2)


class AttnRes(nn.Module):
    def __init__(self, dim=32):
        super().__init__()
        self.query = nn.Parameter(torch.zeros(dim))  # 子层自己的可学习 pseudo-query
        self.key_norm = RMSNorm(dim)

    def forward(self, sources):
        values = torch.stack(sources, dim=2)         # [B,T,来源数,D]
        score = (self.key_norm(values) * self.query).sum(-1)
        weights = score.softmax(dim=2)             # 沿深度来源，绝不是沿 token 轴
        return (weights[..., None] * values).sum(2), weights

class Expert(nn.Module):
    def __init__(self, dim, middle=None, situ=False):
        super().__init__()
        middle = middle or dim * 2
        self.gate, self.up = nn.Linear(dim, middle, bias=False), nn.Linear(dim, middle, bias=False)
        self.down, self.situ = nn.Linear(middle, dim, bias=False), situ

    def forward(self, x):
        g, u = self.gate(x), self.up(x)
        if self.situ:
            hidden = (4 * torch.tanh(g / 4) * g.sigmoid()) * (25 * torch.tanh(u / 25))
        else:
            hidden = F.silu(g) * u
        return self.down(hidden)


class TinyMoE(nn.Module):
    def __init__(self, dim=32, experts=4, topk=2, kind='qwen'):
        super().__init__()
        self.kind, self.topk, self.count = kind, topk, experts
        self.router = nn.Linear(dim, experts, bias=False)
        self.register_buffer('selection_bias', torch.zeros(experts))
        latent = dim // 2 if kind == 'kimi' else dim
        self.down = nn.Linear(dim, latent, bias=False) if kind == 'kimi' else nn.Identity()
        self.up = nn.Linear(latent, dim, bias=False) if kind == 'kimi' else nn.Identity()
        self.norm = RMSNorm(latent) if kind == 'kimi' else nn.Identity()
        self.experts = nn.ModuleList([Expert(latent, situ=kind == 'kimi') for _ in range(experts)])
        self.shared = nn.ModuleList([Expert(dim, situ=kind == 'kimi') for _ in range(2 if kind == 'kimi' else 1)])
        self.shared_gate = nn.Linear(dim, 1, bias=False) if kind == 'qwen' else None

    def forward(self, x):
        flat = x.reshape(-1, x.shape[-1])
        logits = self.router(flat)
        if self.kind == 'qwen':
            score = logits.softmax(-1)
        elif self.kind == 'deepseek':
            score = F.softplus(logits).sqrt()
        else:
            score = logits.sigmoid()
        # bias 只参与选专家；权重仍从无 bias 的 score 读取。
        ids = (score + self.selection_bias).topk(self.topk, -1).indices
        weight = score.gather(1, ids)
        weight = weight / weight.sum(-1, keepdim=True).clamp_min(1e-9)
        if self.kind == 'deepseek':
            weight = 1.5 * weight
        z = self.down(flat)
        routed = torch.zeros_like(z)
        for i, expert in enumerate(self.experts):
            token, slot = torch.where(ids == i)
            if token.numel():
                # 只让选中该专家的 token 进入它；不要先把所有专家全算一遍。
                contribution = expert(z[token]) * weight[token, slot, None]
                routed = routed.index_add(0, token, contribution)
        routed = self.up(self.norm(routed))
        shared = sum(expert(flat) for expert in self.shared)
        if self.shared_gate is not None:
            shared = shared * self.shared_gate(flat).sigmoid()
        # 教学统一负载辅助项，不声称复现 Qwen 训练配方或 K3 Quantile Balancing。
        frequency = F.one_hot(ids, self.count).float().mean((0, 1)).detach()
        probability = score / score.sum(-1, keepdim=True)
        balance = self.count * (frequency * probability.mean(0)).sum()
        return (routed + shared).reshape_as(x), balance


class HashMemoryTeaching(nn.Module):
    """教学简化：bigram/trigram 哈希 + 内容门 + 因果短卷积。
    不是官方 Engram 的 hash/tokenizer 格式；不用它装载真实词表权重。
    """
    def __init__(self, dim=32, buckets=257):
        super().__init__()
        self.buckets = buckets
        self.tables = nn.ModuleList([nn.Embedding(buckets, dim) for _ in range(2)])
        self.key, self.value = nn.Linear(dim, dim, bias=False), nn.Linear(dim, dim, bias=False)
        self.conv = ShortConv(dim)

    def forward(self, ids, context):
        # 只读当前位置和左边。+1 为真实 token 留出 0 号“无历史”标记。
        token = ids + 1
        p1, p2 = F.pad(token, (1, 0))[:, :-1], F.pad(token, (2, 0))[:, :-2]
        h2 = (token + 31 * p1) % self.buckets
        h3 = (token + 31 * p1 + 997 * p2) % self.buckets
        memory = self.tables[0](h2) + self.tables[1](h3)
        gate = ((rms(self.key(memory)) * rms(context)).sum(-1, keepdim=True)
                / math.sqrt(context.shape[-1])).sigmoid()
        value = gate * self.value(memory)
        local, _ = self.conv(rms(value))
        return value + local
