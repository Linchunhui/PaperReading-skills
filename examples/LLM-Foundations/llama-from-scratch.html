01 · 先补齐会反复用到的 PyTorch

张量不是神秘东西，就是有多条轴的数组

一批句子可以写成 [B,T,D]：B 条句子，每条 T 个 token，每个 token 用 D 个数表示。后文始终沿用这一套符号。

符号 含义 手算例子 默认微型模型
B batch size，一批几条序列 2 由输入决定
T sequence length，本次输入几位 5 训练默认 32
D model dimension，每个 token 的特征维度 32 64
H / Hq Query 头数 4 4
Hkv Key/Value 头数 4 主线 4；训练示例 2
d head dimension，单头维度 8 16
F FFN hidden dimension，前馈中间维度 88 176
Vocab 词表大小 20 配置占位 64；实际由分词器决定
P cache 中已有多少个 token 3 无 cache 时为 0

关键关系是 D = H × d。V 常被用于表示 Value，为避免歧义，本教程用 Vocab 表示词表大小。

nn.Linear 对最后一维做线性变换，在所有 batch 和时间位置共享同一组权重。数学里常写 Y = XW，但 PyTorch 存的是 [out_features,in_features]，实际相当于 X @ weight.T。不要为了“对齐公式”再把输入转置一次。

六个操作，先会这六个就够往下走

操作 用处 容易犯的错
reshape(B,T,H,d) 将特征维度拆成头数和单头维度 用 reshape 代替轴交换
transpose(1,2) 把 [B,T,H,d] 变成 [B,H,T,d] 直接 reshape 到目标形状，元素分组变了
@ / matmul 最后两维做矩阵乘法；前面的维度批处理 把 T 和 d 的含义弄反
mean(-1, keepdim=True) 在每个 token 内求均值，保留长度为 1 的轴 不小心跨 token 求统计量
softmax(-1) 在最后一维归一化成概率 在 query 轴上归一化
masked_fill(mask, -inf) 将指定位置排除出后续 softmax 忘记这里 True 表示“要填充”

transpose 后的张量通常不连续。随后用 .reshape(...)，PyTorch 会在需要时复制；也可以 .contiguous().view(...)。reshape 能处理内存布局问题，但不能替你猜正确的轴顺序。

nn.Module、参数、反向传播

__init__ 中定义层和可训练参数，forward 中定义运算。model(x) 会调用前向流程；loss.backward() 计算梯度，优化器的 step() 才真正更新参数。梯度默认累积，所以一般每次更新前先清空。

从 [B,T,48] 先变成 [B,T,6,8]，再变成 [B,6,T,8]。每个头仍然看见全部 T 个 token，只看不同的特征投影。不是把句子切成 6 段。

02 · 文本如何进入模型：Tokenizer 与 Embedding

从“字符”到“编号”，再到“向量”

模型不能直接对字符串做矩阵乘法。第一步由 tokenizer 把文本变成整数编号。为了把重点放在模型结构上，我们先用字符级分词：一个汉字、一个标点、一个换行都各自是一个 token。实际 Llama 分词器和词表需要按照具体版本匹配；这里的字符分词器不能拿去替代官方分词器加载官方模型。

文本 我 爱 学 习
示例 ID（仅为演示） 2 5 7 9
Embedding 查表 E[2] E[5] E[7] E[9]

编号只是索引，9 不意味着比 2 更重要或语义更大。Embedding 是一个 [Vocab,D] 的可训练表：查出每个编号对应的向量，得到 [B,T,D]。查表本身不处理词序，也不考虑前后文；上下文信息由后面的层逐步融合。

from torch import nn

embedding = nn.Embedding(20, 32)
x = embedding(input_ids)
assert x.shape == (1, 4, 32)

字符分词器的完整实现如下。<unk> 用于训练词表中没有出现过的字符；本教程不在主线加入 BOS/EOS/PAD，文末会说明这些组件在哪里补。

组件 · CharTokenizer10 行
class CharTokenizer:
    def __init__(self, training_text=None, tokens=None):
        self.tokens = ["<unk>"] + sorted(set(training_text)) if tokens is None else tokens
        self.stoi = {char: i for i, char in enumerate(self.tokens)}

    def encode(self, text):
        return [self.stoi.get(char, 0) for char in text]

    def decode(self, ids):
        return "".join(self.tokens[i] for i in ids)

语言模型到底预测什么？

给定“我爱学”，模型输出一个词表大小的分数向量。每个分数对应“下一个 token 是这个词”的倾向。我们通过训练让真实下一个 token“习”的概率更高。

p(x₁, …, xT) = ∏t=1…T p(xt | x<t)

这就是自回归分解：每次根据已经出现的内容预测下一位。“一次只生成一位”描述的是常规生成过程；训练时知道完整文本，可以同时训练很多位置，但每个位置都必须看不到未来答案。

先建立一个直觉：模型的输入是 ID，层与层之间流动的是向量，模型最后输出的是 logits。分词器、隐藏向量、概率分布是三个不同阶段。

03 · 单头 Self-Attention：先写最小版本

Q、K、V 是同一输入的三种投影

假设输入 X:[B,T,D]。我们用三个不同的权重矩阵产生 Q、K、V。Self-Attention 的“self”是说它们都来自同一条输入序列，不意味着三个矩阵相同。

名称 初学时可以这样理解 实际作用
Q / Query 当前 token 想找什么 与所有 Key 计算匹配分数
K / Key 每个 token 提供什么检索线索 被 Query 匹配
V / Value 每个 token 带来的内容 按注意力权重进行加权求和

这些比喻帮助入门，但模型并不被强制把某一维学成具体语义。真正需要掌握的是下面的运算。

Q = XWQ，K = XWK，V = XWV
A = softmaxkey(QKᵀ / √d + M)
Y = AV

QKᵀ 的第 i 行第 j 列是：位置 i 对位置 j 的读取分数。在每一行沿 Key 方向做 softmax，得到和为 1 的读取权重。再用这行权重对所有 Value 求加权和。

为什么除以 √d？在各分量近似独立、零均值、方差为 1 的简单假设下，d 项乘积之和的方差随 d 增长；除以 √d 可以控制分数尺度，降低 softmax 过早饱和的风险。这是初始化尺度的解释，不是训练中始终成立的统计定律。缩放点积注意力与多头结构见 Attention Is All You Need。

组件 · single_head_attention9 行
def single_head_attention(q, k, v, causal=True):
    """q/k/v: [B, T, d]；返回输出和可检查的注意力权重。"""
    scores = (q @ k.transpose(-2, -1)) / math.sqrt(q.size(-1))
    if causal:
        t = q.size(-2)
        allowed = torch.ones(t, t, device=q.device, dtype=torch.bool).tril()
        scores = scores.masked_fill(~allowed, float("-inf"))
    weights = torch.softmax(scores, dim=-1)
    return weights @ v, weights

一次手算：只看第一行就能检查方向

设置三行 Q=K=[[1,0],[0,1],[1,1]]，V=[[10,0],[0,20],[30,30]]，单头维度 d=2。第二个位置只能读前两行：

scores₂ = [0, 1/√2, −∞]
weights₂ ≈ [0.3302, 0.6698, 0]
output₂ ≈ 0.3302·[10,0] + 0.6698·[0,20] = [3.302, 13.395]

第一个位置只能读自己，因此输出恰好是第一个 Value：[10,0]。如果第一行还混入了第二、第三行的内容，先检查 mask，而不是调整学习率。

动手题：如果 Q、K 全是 0，输出会是什么？

可见位置的分数完全相同，softmax 变成均匀权重。因果注意力中，第 t 行输出就是前 t+1 个 Value 的平均值。用这个手算结果就能检查实现是否正确。

04 · Causal mask：让模型看不到未来

训练输入“我爱学习”时，位置“爱”只能读“我、爱”，不能读“学、习”。允许读当前位置本身是正确的，因为这个位置的训练目标是下一个 token，而不是重建当前 token。

Query \ Key 我（0） 爱（1） 学（2） 习（3）
我（0） 可见 屏蔽 屏蔽 屏蔽
爱（1） 可见 可见 屏蔽 屏蔽
学（2） 可见 可见 可见 屏蔽
习（3） 可见 可见 可见 可见

这个表是保留下三角、遮住上三角。代码里先构造 allowed=True 表示可读，再用 ~allowed 表示需要填成 -inf 的位置。exp(-inf)=0，softmax 后未来权重为 0。不能用 0 替代 -inf，因为分数 0 仍会得到正的概率。

亲手切换：没有 cache 和有 cache 时，mask 有什么不同？

“可见”对应加 0，“×”对应加 −∞。行是本次的 Query，列是所有可用的 Key。

为什么训练可以并行？

所有位置的真实 token 已知，Embedding 和每层中的矩阵运算可以同时计算整段序列。mask 切断未来 token 到较早位置的注意力路径，因此每个位置仍只依赖自己的前缀。并行训练不等于提前偷看答案。

注意不要混用不同 API 的布尔掩码约定：本教程的 allowed=True 和 scaled_dot_product_attention 的布尔 mask 都表示“参与注意力”；nn.MultiheadAttention 的 key_padding_mask=True 表示“遮住”。见 PyTorch SDPA 文档。

05 · 从单头变多头：完整手写 MHA

单头只有一组匹配和混合规则。多头用不同的投影子空间，同时形成多组注意力。可以把它理解为同一段文字被多种方式读取，但不要预先认定“第一个头一定负责语法、第二个头一定负责指代”。

先投影，再拆头，不是切句子

设 B=2,T=5,D=32,H=4,d=8。四个头中的每一个都拥有 5 个位置。

步骤 操作 输出形状
1 输入 X [2,5,32]
2 Q/K/V 线性投影 各 [2,5,32]
3 reshape(B,T,H,d) 各 [2,5,4,8]
4 transpose(1,2) 各 [2,4,5,8]
5 Q @ K.transpose(-2,-1) [2,4,5,5]
6 缩放、mask、沿最后维 softmax [2,4,5,5]
7 weights @ V [2,4,5,8]
8 交换回 [B,T,H,d]，再合并头 [2,5,32]
9 输出投影 o_proj [2,5,32]
组件 · CausalMHA26 行
class CausalMHA(nn.Module):
    def __init__(self, dim, n_heads):
        super().__init__()
        if dim % n_heads != 0:
            raise ValueError("dim 必须能被 n_heads 整除")
        self.n_heads = n_heads
        self.head_dim = dim // n_heads
        self.q_proj = nn.Linear(dim, dim, bias=False)
        self.k_proj = nn.Linear(dim, dim, bias=False)
        self.v_proj = nn.Linear(dim, dim, bias=False)
        self.o_proj = nn.Linear(dim, dim, bias=False)

    def forward(self, x):
        b, t, d_model = x.shape
        # 先拆最后一维，再交换 T 和 H 两个轴。
        q = self.q_proj(x).reshape(b, t, self.n_heads, self.head_dim).transpose(1, 2)
        k = self.k_proj(x).reshape(b, t, self.n_heads, self.head_dim).transpose(1, 2)
        v = self.v_proj(x).reshape(b, t, self.n_heads, self.head_dim).transpose(1, 2)
        # [B,H,T,d] @ [B,H,d,T] = [B,H,T,T]
        scores = (q.float() @ k.float().transpose(-2, -1)) / math.sqrt(self.head_dim)
        allowed = torch.ones(t, t, dtype=torch.bool, device=x.device).tril()
        scores = scores.masked_fill(~allowed, float("-inf"))
        weights = torch.softmax(scores, dim=-1).to(v.dtype)
        mixed = weights @ v                         # [B,H,T,d]
        merged = mixed.transpose(1, 2).reshape(b, t, d_model)
        return self.o_proj(merged)                  # [B,T,D]

逐段解释

q_proj/k_proj/v_proj 看上去各自是一个大 Linear，但它们的输出维度可以分成 H 段；每一段就是一个头的投影结果。不需要 Python for 循环逐头计算，矩阵乘法可以把 B 和 H 两个轴都当批处理轴。

scores:[B,H,T,T] 的两个 T 含义不同：倒数第二维是“谁来问”，最后一维是“向谁读”。所以 softmax(dim=-1) 才是在每个 Query 内对所有 Key 分配权重。

o_proj 将各头拼接后的特征重新混合。合头是拼接特征，不是对 H 个头取平均；输出还保持 [B,T,D]，才能与输入做残差相加。

代码为了让小例子的数值更稳定，在 FP32 中计算 QK 和 softmax。大模型会更仔细地选择混合精度与融合内核；当前版本优先展示运算逻辑。

改一改维度，检查形状

固定 B=2、T=5。Hkv=Hq 是 MHA；减少 Hkv 的意义会在 GQA 章节解释。

这一版应该怎么测？

输出形状对了还不够。至少验证：输出有限；改变输入后半段，前半段输出不变；同样的 Q/K/V 交给 PyTorch 的 SDPA，输出数值相近。可先在 FP32 小尺寸算例上以 atol=1e-6, rtol=1e-5 对照 MHA 与参考算子。

动手题：为什么不能直接把 [B,T,D] reshape 成 [B,H,T,d]？

reshape 不交换轴，只重新解释线性内存里的元素分组。直接这样写会把原来不同 token 的特征混在错误位置。正确顺序是 [B,T,D] → [B,T,H,d] → transpose → [B,H,T,d]。

06 · 给 Attention 加上 RoPE

为什么还需要位置编码？

Embedding 本身只由 token ID 决定。注意力分数若只取决于 Q、K 的内容，就没有显式表示“相隔几位”的机制。因果 mask 给出前后可见性的约束，但没有像位置编码一样，直接在内容匹配中表达距离。Llama 风格主干把 RoPE 加在 Q、K 上。

RoPE 不是把一个位置向量加到 Embedding 上，而是根据 token 的位置，旋转 Q、K 的特征对。本教程采用相邻维度配对：(0,1),(2,3),…。每对二维向量的旋转速度不同。

从一对数开始理解旋转

设当前位置为 m，一对特征是 (a,b)，旋转角为 α：

a′ = a cos α − b sin α
b′ = a sin α + b cos α

比如 (1,0) 旋转 90° 后变成 (0,1)。向量长度不变，方向改变。RoPE 中不是所有位置都转 90°，而是使用位置乘上频率：

ωi = θ−2i/d，i = 0, …, d/2−1
αm,i = m · ωi

d 是每个头的维度，不是模型总维度 D；θ 是基底，教学配置使用 10000。不同模型/版本可能采用不同 θ 或缩放规则，不能把它当所有 Llama 的统一配置。

看见“位置变了，方向也变了”

固定 d=8、θ=10000，原向量为 (1,0)。横轴为第一维分量，纵轴为第二维分量；角度使用弧度。

为什么能表达相对位置？

把每对的二维旋转合成矩阵 R。Query 在位置 m，Key 在位置 n：

(R(m)q)ᵀ(R(n)k) = qᵀR(m)ᵀR(n)k = qᵀR(n−m)k

关键是中间的旋转合成为 n−m。所以在原始 q/k 保持不变时，同时平移它们的位置不会改变这个点积。它不是说“任意两对相同距离的 token 分数都一样”：分数依旧取决于 q、k 的内容。这里采用列向量记法；其他记法可能出现符号反向，但实现必须整体一致。方法来源见 RoFormer。

def apply_rope(x, positions, theta=10000.0):
    """x: [B,H,T,d]；positions: [T]；使用相邻偶/奇维度配对。"""
    d = x.size(-1)
    if d % 2 or positions.numel() != x.size(-2):
        raise ValueError("检查 head_dim 和 positions 长度")
    inv_freq = theta ** (-torch.arange(0, d, 2, device=x.device, dtype=torch.float32) / d)
    angles = positions.to(device=x.device, dtype=torch.float32)[:, None] * inv_freq[None, :]
    cos = angles.cos()[None, None, :, :]         # [1,1,T,d/2]
    sin = angles.sin()[None, None, :, :]
    even = x.float()[..., 0::2]                  # [B,H,T,d/2]
    odd = x.float()[..., 1::2]
    rotated_even = even * cos - odd * sin
    rotated_odd = even * sin + odd * cos
    return torch.stack((rotated_even, rotated_odd), dim=-1).flatten(-2).to(x.dtype)

inv_freq:[d/2] 存每对的频率；positions:[T] 与频率外积得到 [T,d/2]。cos/sin 增加两个长度为 1 的维度以后变成 [1,1,T,d/2]，即可广播给所有 batch 和所有头。stack(...).flatten(-2) 把旋转后的偶/奇维重新交错拼回去。

把它接进第 5 章的 MHA，只需在Q/K 拆头之后、QK 点积之前加：

四个必须避开的坑

  1. 旋转位置错了。这里旋转 Q、K，不旋转 V，也不是旋转最后输出。
  2. 配对约定混了。相邻配对和“前半/后半配对”都可实现旋转，但预训练权重的维度排列必须匹配；不能直接换公式后假定 checkpoint 仍兼容。
  3. 缓存后仍从 0 编号。新 token 应从 cache 长度 P 开始，用 P,P+1,…；第 13 章会实现。
  4. 误以为能任意外推。RoPE 公式能算出更远位置，不代表模型在未训练过的长度上仍然可靠。长上下文扩展还涉及训练分布和具体缩放方法。

本实现每次前向即时计算 cos/sin，便于阅读。实际推理可以预计算并缓存频率表；使用低精度权重时也要注意位置与频率计算的精度。

动手题：为什么 d 必须是偶数？如何验证 RoPE 没写反？

因为每两维组成一对二维向量。可以验证位置 0 不改变输入、旋转前后平方范数不变、二维 (1,0) 在 π/2 处变为 (0,1)，以及同时平移 q/k 的位置后点积不变。这些性质能帮助你检查实现，避免只检查形状。

07 · RMSNorm：对一个 token 的特征做尺度调整

经过多个线性层和残差相加，隐藏向量的尺度会变化。归一化给后续子层提供更可控的输入尺度。这里的 Norm 是对每个 token 的最后一维做统计，不是对整句话或整个 batch 做统计。

RMSNorm(x)i = γi · xi / √((1/D)∑j=1…Dxj² + ε)

γ:[D] 是可训练的缩放向量，初始为全 1；ε 用于数值稳定。本实现把 ε 放在平方根内，与本文对照的模型实现保持一致。它不减均值，也没有平移参数 β。方法来源见 RMSNorm。

是否减去均值 是 否
归一化分母 sqrt(mean((x-mean(x))²)+eps) sqrt(mean(x²)+eps)
可学习参数 通常 γ、β γ
归一化轴 指定特征轴 最后一维 D
输出形状 不变 不变
组件 · RMSNorm11 行
class RMSNorm(nn.Module):
    def __init__(self, dim, eps=1e-6):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(dim))
        self.eps = eps

    def forward(self, x):
        xf = x.float()                          # 在 FP32 中计算统计量
        mean_square = xf.square().mean(dim=-1, keepdim=True)
        normalized = xf * torch.rsqrt(mean_square + self.eps)
        return (normalized * self.weight.float()).to(x.dtype)

手算一下就知道区别

x=[3,4]，忽略 ε、令 γ 全 1，均方为 (9+16)/2=12.5，RMS 约为 3.5355。输出约为 [0.8485,1.1314]。均值没有变成 0；输出每个元素也不等于 1。此时输出的均方约为 1，这是另一回事。

代码中的 keepdim=True 保留 [B,T,1]，才能广播回 [B,T,D]。先转成 FP32 计算平方和，最后转回输入 dtype；γ 仍然参与梯度计算，.float() 不会自动切断梯度。

动手题：把 mean(dim=-1) 改成 mean(dim=1) 会怎样？

你会沿序列轴做统计，把不同 token 混起来。在完整训练中还可能让较早位置的归一化结果依赖未来内容，破坏因果性。形状能广播不代表归一化方向正确。

08 · FFN 与 SwiGLU：注意力之外还需要什么

Attention 沿 token 维度交换信息，FFN 则对每个位置的特征进行非线性变换。FFN 的权重在各位置共享，但不会像 Attention 一样直接跨位置加权求和。两者都不可省略：只有注意力并不是完整的 Llama Block。

普通两层 FFN 常写成 W_down · activation(W_up · x)。SwiGLU 增加一条门控分支，让两条上投影的结果逐元素相乘，然后再降回 D。

SiLU(z) = z · sigmoid(z)
SwiGLU(x) = Wdown(SiLU(Wgatex) ⊙ Wupx)

⊙ 是对应元素相乘，不是矩阵乘法。SiLU 门控值不是限定在 0 到 1 的概率，不能按“保留百分之多少”作严格解释。门控 FFN 变体见 GLU Variants Improve Transformer。

组件 · SwiGLU11 行
class SwiGLU(nn.Module):
    def __init__(self, dim, hidden_dim):
        super().__init__()
        self.gate_proj = nn.Linear(dim, hidden_dim, bias=False)
        self.up_proj = nn.Linear(dim, hidden_dim, bias=False)
        self.down_proj = nn.Linear(hidden_dim, dim, bias=False)

    def forward(self, x):
        gate = F.silu(self.gate_proj(x))         # [B,T,F]
        content = self.up_proj(x)               # [B,T,F]
        return self.down_proj(gate * content)   # [B,T,D]
分支 变换 形状
gate Linear + SiLU [B,T,D] → [B,T,F]
up Linear [B,T,D] → [B,T,F]
elementwise product gate × up [B,T,F]
down Linear [B,T,F] → [B,T,D]

为什么经常看到中间维度约为 8D/3？

忽略 bias，普通 D→4D→D 的两层 FFN 有 8D² 个参数。SwiGLU 的三个矩阵有 3DF 个参数。若想保持相近参数量，令 3DF≈8D²，得到 F≈8D/3。

这是配平参数量的一种选择，不是 SwiGLU 的数学要求。实际模型可能再乘一个系数，或者对齐到某个整数倍；加载模型必须使用对应配置。本教程 D=64,F=176 是便于小实验的选值，不能据此推断官方各尺寸的 FFN 大小。

动手题：D=64、F=176，这个 FFN 有多少参数？

三个无 bias 矩阵合计 3×64×176=33792。gate/up 的 PyTorch 权重都是 [176,64]，down 的权重是 [64,176]。

09 · 组装 Decoder Block：两次 Norm，两次残差

现在有了带 RoPE 的 Attention、RMSNorm 和 SwiGLU，可以组装一个 Llama 风格 Decoder Block。它采用 Pre-Norm：先归一化再进入子层，子层的结果加回原来的残差流。

h = x + Attention(RMSNorm₁(x))
y = h + SwiGLU(RMSNorm₂(h))
组件 · DecoderBlock12 行
class DecoderBlock(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.attn_norm = RMSNorm(cfg.dim, cfg.norm_eps)
        self.attn = LlamaAttention(cfg)
        self.ffn_norm = RMSNorm(cfg.dim, cfg.norm_eps)
        self.ffn = SwiGLU(cfg.dim, cfg.hidden_dim)

    def forward(self, x):
        x = x + self.attn(self.attn_norm(x))
        x = x + self.ffn(self.ffn_norm(x))
        return x

上面 LlamaAttention 是主线正式使用的注意力类：它把第 5、6 章的 MHA 与 RoPE 合起来，并把 n_kv_heads 留作第 12 章的扩展入口。第一次阅读让 n_kv_heads=n_heads 即可，此时每个 Query 头拥有自己的 K/V，仍然是 MHA。

为什么保留残差？

x + f(x) 让子层在现有表示上增加一份更新，也为梯度提供直接通路。从局部导数看会出现 I + ∂f/∂x。它有助于深层优化，但并不保证任意深度、任意学习率都能稳定训练。

别把第一行写成 x = attn(norm(x))：那样丢掉了残差。也别把第二个 Norm 套在最初的 x 上：第二个子层应当接收第一轮更新后的 h。

Decoder-only 为什么没有 Cross-Attention？

经典 Encoder–Decoder Transformer 的 Decoder 会额外读取 Encoder 的输出，因而包含 Cross-Attention。我们做的是纯文本 Decoder-only：prompt 和后续文本在同一个因果序列里处理，不需要单独的 Encoder 输出。本教程的 Block 因此只有因果 Self-Attention 和 FFN 两个子层。

架构 核心注意力可见性 是否要读独立 Encoder 输出
Encoder-only 的常见形式 双向 Self-Attention 否
Encoder–Decoder 的 Decoder 因果 Self-Attention + Cross-Attention 是
本教程 Llama 风格 Decoder-only 因果 Self-Attention 否

这个选择与 Meta Llama 3 的经典稠密主干实现 相符。本文简化了并行、缓存管理及模型规模，便于先在一台普通机器上完成训练闭环。

用同一个注意力类支持 MHA 和后续的 GQA

组件 · LlamaAttention30 行
class LlamaAttention(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.n_heads = cfg.n_heads
        self.n_kv_heads = cfg.n_kv_heads
        self.head_dim = cfg.dim // cfg.n_heads
        self.theta = cfg.rope_theta
        self.q_proj = nn.Linear(cfg.dim, cfg.n_heads * self.head_dim, bias=False)
        self.k_proj = nn.Linear(cfg.dim, cfg.n_kv_heads * self.head_dim, bias=False)
        self.v_proj = nn.Linear(cfg.dim, cfg.n_kv_heads * self.head_dim, bias=False)
        self.o_proj = nn.Linear(cfg.dim, cfg.dim, bias=False)

    def forward(self, x):
        b, t, dim = x.shape
        q = self.q_proj(x).reshape(b, t, self.n_heads, self.head_dim).transpose(1, 2)
        k = self.k_proj(x).reshape(b, t, self.n_kv_heads, self.head_dim).transpose(1, 2)
        v = self.v_proj(x).reshape(b, t, self.n_kv_heads, self.head_dim).transpose(1, 2)
        positions = torch.arange(t, device=x.device)
        q = apply_rope(q, positions, self.theta)
        k = apply_rope(k, positions, self.theta)  # V 不旋转
        repeat = self.n_heads // self.n_kv_heads
        k = k.repeat_interleave(repeat, dim=1)
        v = v.repeat_interleave(repeat, dim=1)
        scores = (q.float() @ k.float().transpose(-2, -1)) / math.sqrt(self.head_dim)
        allowed = torch.ones(t, t, device=x.device, dtype=torch.bool).tril()
        scores = scores.masked_fill(~allowed, float("-inf"))
        weights = F.softmax(scores, dim=-1).to(v.dtype)
        mixed = weights @ v
        merged = mixed.transpose(1, 2).reshape(b, t, dim)
        return self.o_proj(merged)

先忽略 repeat_interleave 那两行：当 Hkv=H 时，repeat=1，它们不改变头数。Q/K 使用同一组 position 编号，V 不旋转。后面的过程与第 5 章相同。

整模型代码

组件 · MiniLlama22 行
class MiniLlama(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.cfg = cfg
        self.embedding = nn.Embedding(cfg.vocab_size, cfg.dim)
        self.layers = nn.ModuleList([DecoderBlock(cfg) for _ in range(cfg.n_layers)])
        self.final_norm = RMSNorm(cfg.dim, cfg.norm_eps)
        self.lm_head = nn.Linear(cfg.dim, cfg.vocab_size, bias=False)
        self.apply(self._init_weights)

    @staticmethod
    def _init_weights(module):
        if isinstance(module, (nn.Linear, nn.Embedding)):
            nn.init.normal_(module.weight, mean=0.0, std=0.02)

    def forward(self, input_ids):
        if input_ids.ndim != 2 or not 0 < input_ids.size(1) <= self.cfg.max_seq_len:
            raise ValueError("input_ids 需要是 [B,T]，且 1 <= T <= max_seq_len")
        hidden = self.embedding(input_ids)      # [B,T] -> [B,T,D]
        for layer in self.layers:
            hidden = layer(hidden)
        return self.lm_head(self.final_norm(hidden)).float()  # [B,T,Vocab]

逐行理解组装部分：embedding 将 ID 变成向量；ModuleList 注册所有层；for 循环依次更新隐藏状态；最后的 RMSNorm 调整残差流，再由 lm_head 将 D 维映射成词表大小的分数。

这里输出的是 logits，不是概率。如果 input_ids:[2,8]，词表大小为 64，输出就是 [2,8,64]。第 t 个位置的 64 个分数用于预测 t+1 位置的 token。最后一位 logits 才用于接着整个 prompt 生成下一位。

本模型的 Embedding 与 LM Head 权重没有共享。Weight tying 可以作为后续练习，但是否共享是架构配置，不是所有模型通用的规定。初始化使用均值 0、标准差 0.02 的正态分布作为教学设置，没有复刻官方完整训练配方。

11 · 训练目标与最小训练闭环

只右移一次：输入与答案的关系

要构造 T 个训练位置，先取 T+1 个 token。输入取前 T 个，答案取后 T 个。

位置 0 1 2 3
输入 x 我 爱 学 习
目标 y 爱 学 习 。
可见输入 我 我爱 我爱学 我爱学习

这个表也解释了 mask 为什么允许读取自己：输入位置 2 的 token 是“学”，答案是“习”。如果把 y 直接设成 x，模型可能只学会复制输入。

组件 · get_batch7 行
def get_batch(data, batch_size, seq_len, device, generator=None):
    # 取 T+1 个 token；最后一个 token 只用于提供最后位置的答案。
    starts = torch.randint(len(data) - seq_len, (batch_size,), generator=generator)
    windows = torch.stack([data[i:i + seq_len + 1] for i in starts.tolist()])
    x = windows[:, :-1].to(device)
    y = windows[:, 1:].to(device)
    return x, y

注意本项目选择“数据侧 shift”。所以 next_token_loss 直接比较 logits 与 targets，内部不能再次平移。另一种常见 API 会接收未 shift 的 labels，在模型内部移动；两种约定都可以，但不能叠加。

Cross-Entropy 在做什么？

假设正确下一词的预测概率为 p，损失就是 −log(p)。正确答案越有把握，loss 越低。对整批所有有效位置求平均，就得到训练目标。

L = − (1 / Nvalid) ∑有效 b,t log softmax(logitsb,t)[targetb,t]
组件 · next_token_loss4 行
def next_token_loss(logits, targets):
    """targets 已经由数据侧右移一位；这里不能再 shift 一次。"""
    return F.cross_entropy(logits.reshape(-1, logits.size(-1)),
                           targets.reshape(-1), ignore_index=-100)

[B,T,Vocab] → [B×T,Vocab]，把每个位置都看成一次 Vocab 分类。目标从 [B,T] 展平成 [B×T] 的整数类别编号。将原始 logits 直接交给 Cross-Entropy；不要在前面再做 softmax，它内部会以稳定方式完成相应计算。见 PyTorch CrossEntropyLoss。

均匀猜测时，loss 为 ln(Vocab)，不是 0。本次字符词表大小为 80，ln(80)≈4.382，因此初始 loss 约 4.41 合理。用自然对数计算的 token 平均 loss，可转换为 perplexity=exp(loss)；不同分词器下的 perplexity 不能简单横比。

不一定。要先看 loss 是否来自训练集、语料是否重复、labels 是否错位、采样是否过于贪心，以及验证集是否独立。只背下小语料的模型也可能有很低的 loss。结构数值测试和数据泛化评估解决的是不同问题。

12 · GQA：让多个 Query 头共享 K/V

前面先保持 Hkv=Hq 来理解 MHA。现在令 Query 头数不变，只减少 Key/Value 头数，就得到了共享程度不同的注意力结构。

形式 Hq=8 时的 Hkv 例子 共享方式
MHA 8 每个 Q 头各有一组 K/V
GQA 2 每 4 个 Q 头共享一组 K/V
MQA 1 所有 Q 头共享一组 K/V

GQA 可视为从 MHA 到 MQA 的一类分组设计；常用狭义写法指 1<Hkv<Hq 的中间情况。方法来源见 GQA。

与 MHA 相比，改哪几处？

  1. Query 的投影输出仍是 Hq×d=D；K/V 的投影输出改成 Hkv×d。
  2. Q 拆成 [B,Hq,T,d]；K/V 拆成 [B,Hkv,T,d]。
  3. 在教学版矩阵乘法前，将每组 K/V 连续重复 Hq/Hkv 次，匹配 Query 头数。

13 · KV cache：先写对，再加速

不缓存时浪费了什么？

给定长度为 P 的 prompt，先跑整段得到下一 token；接上新 token 后，又把长度 P+1 的整段跑一遍。前 P 个位置的许多计算重复了。因果模型中，这些旧位置不能读取新位置，在固定权重、确定性推理及相同位置约定下，它们的历史表示可以复用。

KV cache 为每一层保存历史 Key 和 Value。下一步只为新 token 计算 Q/K/V，再用新 Query 读取历史与当前的 K/V。Q 不需要作为历史记忆保存，因为未来的读取只需要过去的 K 和 V。

阶段 本次输入 Query 长度 Key/Value 总长度
Prefill 整个 prompt，长度 P P P
第一次 Decode 前向 新生成的一个 token 1 P+1
下一次 Decode 前向 再新生成的一个 token 1 P+2

Prefill 的最后一位 logits 已经能产生第一个新 token；不是先把 prompt 全部处理完，还要额外凭空输入一个 token 才能开始生成。

两个最容易错的地方：位置与矩形 mask

已有 3 个 token，本次一次送入 2 个新 token，位置应为 [3,4]，K/V 总长度为 5。允许读取的范围是：

Query 绝对位置 \ Key 位置 0 1 2 3 4
3 可见 可见 可见 可见 屏蔽
4 可见 可见 可见 可见 可见

通用规则是 key_position <= query_position。不要对 [2,5] 直接套一个无偏移下三角，那会让第一行只看到第 0 列。第 4 章的小演示可以切换 P=3、T=2 查看。

缓存的 K 在第一次产生时已经应用 RoPE；每一步只旋转新产生的 K，然后拼上旧 K。不能把整个历史 K 再旋转一遍。

class CachedAttention(LlamaAttention):
    def forward(self, x, past=None):
        b, t, dim = x.shape
        past_len = 0 if past is None else past[0].size(-2)
        q = self.q_proj(x).reshape(b, t, self.n_heads, self.head_dim).transpose(1, 2)
        k = self.k_proj(x).reshape(b, t, self.n_kv_heads, self.head_dim).transpose(1, 2)
        v = self.v_proj(x).reshape(b, t, self.n_kv_heads, self.head_dim).transpose(1, 2)
        positions = torch.arange(past_len, past_len + t, device=x.device)
        q = apply_rope(q, positions, self.theta)
        k = apply_rope(k, positions, self.theta)
        if past is not None:
            k = torch.cat((past[0], k), dim=-2)
            v = torch.cat((past[1], v), dim=-2)
        new_cache = (k, v)                     # 紧凑存储 Hkv 个头，K 已旋转
        repeat = self.n_heads // self.n_kv_heads
        keys = k.repeat_interleave(repeat, dim=1)
        values = v.repeat_interleave(repeat, dim=1)
        scores = (q.float() @ keys.float().transpose(-2, -1)) / math.sqrt(self.head_dim)
        key_positions = torch.arange(k.size(-2), device=x.device)
        # 例：past_len=3、t=2 时，两行可见列数分别是 4 和 5。
        allowed = key_positions[None, :] <= positions[:, None]
        scores = scores.masked_fill(~allowed[None, None, :, :], float("-inf"))
        weights = torch.softmax(scores, dim=-1).to(values.dtype)
        mixed = (weights @ values).transpose(1, 2).reshape(b, t, dim)
        return self.o_proj(mixed), new_cache

CachedAttention 继承前面的投影层，复用相同参数名称；新增的 past 是 (K,V)。new_cache 在 repeat_interleave 之前创建，因此只保存 Hkv 个头，避免失去 GQA 的缓存优势。

模型外层还需要维护一个“每层一个 cache”的列表：每层取到自己的 cache，处理新 token，再把更新后的 cache 收集回来。完整实现位于第 16 章的 CachedLlama。它是推理专用实现，前向禁止记录梯度；训练继续使用无 cache 的 MiniLlama。

缓存能省多少内存？

KV cache 大小约为：

2 × L × B × T × Hkv × d × 每元素字节数

2 表示 K 和 V，L 是层数。例：L=32,B=1,T=8192,Hkv=8,d=128，BF16 每元素 2 字节，缓存为 1,073,741,824 字节，即 1 GiB。同样条件 Hkv=32 则是 4 GiB。这里只算 K/V 张量，不含权重、激活、临时 buffer 或缓存管理开销。

本实现用 torch.cat 动态拼接，每步会复制缓存，适合教学而非生产性能。生产系统会使用预分配、分页管理及专门的注意力内核。KV cache 避免重复计算旧 token，但新 Query 仍需读取历史，因此普通密集注意力的单步读取开销仍随上下文长度增长。

先约定清楚这个 cache 的边界

本教程支持同一 batch 中等长、连续位置的序列，以及逐 token 或多 token 分块续接；没有 padding、滑动窗口和中途删除缓存。换一条 prompt 要从 caches=None 开始。位置偏移按缓存长度推导，仅在这些边界下成立。

动手题：为什么“已有 cache，T=1”时不能直接照搬 is_causal=True？

PyTorch SDPA 对非方阵的 is_causal=True 使用左上对齐的因果规则。对于长度为 1 的新 Query 和较长的完整 K/V，它并不自动知道这个 Query 的绝对位置在最后。这个场景可在确认所有 Key 都合法时不加 mask；更通用的写法是显式传入按绝对位置构造的 allowed mask，并设置 is_causal=False。

Temperature 和 Top-k

选择方法 规则 本教程用法
贪心 选最大 logits temperature=0
温度采样 对 logits/temperature 做 softmax，再随机选 temperature>0
Top-k 只保留分数最高的 k 个候选，再采样 top_k=20 等

温度较低时分布更尖，较高时更平，但不是“值越高效果越好”。temperature=0 不能真的拿来做除法，因此代码用独立的 argmax 分支。Top-k 在贪心分支不产生额外作用。

组件 · sample_next13 行
def sample_next(logits, temperature=0.0, top_k=None):
    """输入 [B,Vocab]；输出 [B,1]。temperature=0 表示贪心生成。"""
    if temperature < 0 or not math.isfinite(temperature):
        raise ValueError("temperature 必须是有限非负数")
    if temperature == 0:
        return logits.argmax(dim=-1, keepdim=True)
    scores = logits.float() / temperature
    if top_k is not None:
        if top_k < 1:
            raise ValueError("top_k 必须 >= 1")
        values, indices = scores.topk(min(top_k, scores.size(-1)), dim=-1)
        scores = torch.full_like(scores, float("-inf")).scatter(-1, indices, values)
    return torch.multinomial(F.softmax(scores, dim=-1), num_samples=1)

Top-k 使用 topk 返回的具体下标，再散射到全为 -inf 的张量中，保留明确的 k 个候选。之后 multinomial 在归一化分布中抽样。这里没有实现 Top-p、重复惩罚、Beam Search 等解码策略，先掌握这两个即可。

15 · 手撕 FlashAttention-2：分块前向与重计算反向

到这里，你已经会写 QKᵀ → mask → softmax → PV。本章保持同一个注意力公式，改变的是计算顺序、保存哪些中间量，以及怎样组织并行工作。这里用 N 表示序列长度，与前文的 T 相同。

本章交付的代码范围
下面是可以在 CPU 上运行、可以接入前文模型训练的 FlashAttention-2 算法级教学实现：分块、在线 Softmax、末尾归一化、自定义反向与重计算都亲手写出。GPU 版的线程块调度、warp 内分工和 SRAM 复用不由 Python 循环实现，因此这段代码不提供生产内核的加速效果。它的用途是把 FA2 的数学与数据流拆开看懂。

15.1 为什么先解决“存不下”，而不是改注意力公式？

显式实现会建立 [B,H,N,N] 的分数或概率矩阵。只算一个这样的 FP32 矩阵，B=1、H=32、N=8192 时就要 1×32×8192²×4 = 8 GiB；这还没有计算其余激活和梯度。

FlashAttention 按块计算分数，在小块内完成 Softmax 的统计与 Value 累加，避免把完整的 N×N 中间结果写入显存。它仍是精确的标准注意力算法，浮点舍入误差除外；没有用稀疏或低秩近似替换公式。 计算复杂度仍是 O(N²d)。本教学版的额外分数工作区是 O(BH·Bq·Bk)，另需 O(BHNd) 的输入、输出和梯度存储。

变量 形状 存什么
qi [B,H,Bq,d] 当前 Query 行块
kj, vj [B,H,Bk,d] 当前 Key / Value 块
scores, p_tilde [B,H,Bq,Bk] 当前块的分数与未归一化权重
row_max, row_sum [B,H,Bq,1] 每行最大值与指数和
acc [B,H,Bq,d] 每行 Value 的加权累加器
lse [B,H,N] 每行 log-sum-exp，反向时恢复概率

表里的 Bq/Bk 表示块容量；序列末尾不足一整块时，用实际剩余长度。

15.2 在线 Softmax：每次多看一块，怎样保持答案不变？

普通稳定 Softmax 先减去整行最大值 m。分块后你还没看到所有 Key，就不知道最终 m。因此每看一个新块，需要把旧结果换到新的“指数基准”下。

m′ = max(m, max(Sij))
α = exp(m − m′)，  P̃ = exp(Sij − m′)
ℓ′ = αℓ + rowsum(P̃)
A′ = αA + P̃Vj
全部 Key 块处理完：Oi = A / ℓ，  Li = m + log(ℓ)

其中 S 已经除以 √d，并加上因果 mask。m、ℓ 都是“每行一个数”，A 是“每行一个 d 维向量”。初始化 m=-∞, ℓ=0, A=0。代码中的 row_max / row_sum / acc / lse 分别对应 m / ℓ / A / L。

α 为什么必须乘两次？ 旧的分母和分子都使用旧最大值 m。最大值变为 m′ 后，旧的每个指数项都少乘一个 exp(m′−m)，所以要同时把 ℓ 和 A 乘上 exp(m−m′)。只改分母、忘了改累加器，输出一定不对。

手算一行：分数为 [1,2,3]，Value 为 [10,20,30]。先读前两项，有 m=2, ℓ=e⁻¹+1, A=10e⁻¹+20；再读第三项，m′=3, α=e⁻¹。最后分母为 e⁻²+e⁻¹+1，分子为 10e⁻²+20e⁻¹+30，与一次性做 Softmax 的结果相同，输出约 25.7521。

15.3 FA2 相比第一代，还改了哪些地方？

在线 Softmax 和分块思想来自 FlashAttention；只写分块循环还不足以说明 FA2 的性能来源。

FA2 的改动 为什么有用 本文如何体现
减少非矩阵乘运算 GPU 的矩阵乘吞吐很高，其余操作容易成为瓶颈 累加未归一化的 A，遍历结束才做一次 A/ℓ
让不同 Query 行块独立计算 短 batch、少头数时，也能产生足够多并行任务 前向把 Query 块放在外层；各块写自己的输出行
warp 之间切分 Q，复用 K/V 减少 warp 之间交换和归约中间结果 Python 版只表达算法；实际分工需 CUDA/Triton 内核

在 GPU 前向内核中，可以把任务理解为 (batch, head, query_block)，任务内部遍历 K/V 块。下面的 Python 外层循环是串行执行的，不会自动变成这样的 GPU 线程块调度。同样，反向的 += 是顺序累加；真正在多个线程块中并行累加时，还要安排梯度归约，不能直接照搬。

15.4 手写前向：每次只保留一个分数块

先固定边界，避免把缓存和 padding 的难点混进来：Q/K/V 都是同形的 [B,H,N,d]，支持 FP32/FP64，序列等长、没有 padding 和 dropout。传入的是已做 RoPE 的 Q/K、未旋转的 V；GQA 在进入本函数前按第 12 章扩展 K/V 头数。

def fa2_forward(q, k, v, block_q, block_k, causal):
    # q/k/v: [B,H,N,d]，本教程限定 FP32/FP64、等长、无 padding。
    n, d = q.shape[-2:]
    scale = 1.0 / math.sqrt(d)
    out = torch.empty_like(q)
    lse = torch.empty(q.shape[:-1], device=q.device, dtype=q.dtype)
    for qs in range(0, n, block_q):
        qe = min(qs + block_q, n)
        qi = q[..., qs:qe, :]
        q_pos = torch.arange(qs, qe, device=q.device)
        row_max = torch.full_like(qi[..., :1], -torch.inf)
        row_sum = torch.zeros_like(row_max)
        acc = torch.zeros_like(qi)
        # 因果模式只访问可能可见的 K/V 块。
        stop = qe if causal else n
        for ks in range(0, stop, block_k):
            ke = min(ks + block_k, n)
            kj, vj = k[..., ks:ke, :], v[..., ks:ke, :]
            scores = (qi @ kj.transpose(-2, -1)) * scale
            if causal:
                k_pos = torch.arange(ks, ke, device=q.device)
                allowed = k_pos[None, :] <= q_pos[:, None]
                scores = scores.masked_fill(~allowed, -torch.inf)
            new_max = torch.maximum(
                row_max, scores.amax(dim=-1, keepdim=True)
            )
            alpha = torch.exp(row_max - new_max)
            p_tilde = torch.exp(scores - new_max)
            row_sum = alpha * row_sum + p_tilde.sum(-1, keepdim=True)
            acc = alpha * acc + p_tilde @ vj
            row_max = new_max
        out[..., qs:qe, :] = acc / row_sum
        lse[..., qs:qe] = (row_max + row_sum.log()).squeeze(-1)
    return out, lse

读代码时按下面四步跟踪一个 Query 块：

  1. qi 取出几行 Query，初始化这几行的 m、ℓ、A。
  2. 每次读一块 K/V，用 qi @ kjᵀ 得到一个 Bq×Bk 的分数块。
  3. 先更新最大值，再同步缩放旧的分子和分母；当前块的 Value 贡献加入 A。
  4. 遍历结束做 A/ℓ，写出这几行 O，并保存 L 供反向使用。

因果模式下，stop=qe 跳过整个落在未来的 Key 块；与当前 Query 块交叠的块仍需逐元素 mask。最后一个块用 min(...) 截断，所以 N 不必被块大小整除。当前实现从 Key 位置 0 开始，且每个 Query 都能看到自己，因此第一块中每行至少有一个有效 Key；若日后加入 padding，必须另行处理整行都被 mask 的情况，避免 −∞ − (−∞) 产生 NaN。

15.5 手写反向：不保存 P，使用 L 把当前块重算出来

如果只把分块循环写成普通 PyTorch 函数，然后直接调用 .backward()，自动求导可能保留每个块的中间量，失去节省激活存储的目的。因此下一步是自定义反向，只保存 Q、K、V、O、L。

先把一个头的公式写清楚。设上游梯度为 dO，分数 S=QKᵀ/√d，概率 P=softmax(S)：

dV = PᵀdO，  dP = dOVᵀ
Δi = ∑j PijdPij = ∑r OirdOir
dS = P ⊙ (dP − Δ)
dQ = dSK / √d，  dK = dSᵀQ / √d
每个块的概率：Pij = exp(Sij − Li)

这里 ⊙ 是逐元素乘法；Δ 沿 Key 维广播。为什么 Δ 可以由 O 计算？把 Oᵢ=ΣⱼPᵢⱼVⱼ 代入 Oᵢ·dOᵢ，展开就是 ΣⱼPᵢⱼ(Vⱼ·dOᵢ)，括号里恰好是 dPᵢⱼ。

def fa2_backward(q, k, v, out, lse, grad_out, block_q, block_k, causal):
    n, d = q.shape[-2:]
    scale = 1.0 / math.sqrt(d)
    dq, dk, dv = [torch.zeros_like(x) for x in (q, k, v)]
    # 每一行的 delta = sum_j(P_ij * dP_ij) = dot(O_i, dO_i)。
    delta = (out * grad_out).sum(dim=-1, keepdim=True)
    for qs in range(0, n, block_q):
        qe = min(qs + block_q, n)
        qi = q[..., qs:qe, :]
        doi = grad_out[..., qs:qe, :]
        li = lse[..., qs:qe, None]
        di = delta[..., qs:qe, :]
        q_pos = torch.arange(qs, qe, device=q.device)
        stop = qe if causal else n
        for ks in range(0, stop, block_k):
            ke = min(ks + block_k, n)
            kj, vj = k[..., ks:ke, :], v[..., ks:ke, :]
            scores = (qi @ kj.transpose(-2, -1)) * scale
            if causal:
                k_pos = torch.arange(ks, ke, device=q.device)
                allowed = k_pos[None, :] <= q_pos[:, None]
                scores = scores.masked_fill(~allowed, -torch.inf)
            # 只重建当前 tile 的 P，不保存整个 [N,N] 矩阵。
            p = torch.exp(scores - li)
            dv[..., ks:ke, :] += p.transpose(-2, -1) @ doi
            dp = doi @ vj.transpose(-2, -1)
            ds = p * (dp - di)
            dq[..., qs:qe, :] += (ds @ kj) * scale
            dk[..., ks:ke, :] += (ds.transpose(-2, -1) @ qi) * scale
    return dq, dk, dv

注意三处梯度都用 +=：同一 Query 行会从多个 Key 块收到贡献，同一 Key/Value 行也会从多个 Query 块收到贡献。scale 在 dQ 和 dK 中各乘一次，因为 dS 是相对于缩放后分数 S 的梯度。

def single_head_attention(q, k, v, causal=True):
    """q/k/v: [B, T, d]；返回输出和可检查的注意力权重。"""
    scores = (q @ k.transpose(-2, -1)) / math.sqrt(q.size(-1))
    if causal:
        t = q.size(-2)
        allowed = torch.ones(t, t, device=q.device, dtype=torch.bool).tril()
        scores = scores.masked_fill(~allowed, float("-inf"))
    weights = torch.softmax(scores, dim=-1)
    return weights @ v, weights


class CausalMHA(nn.Module):
    def __init__(self, dim, n_heads):
        super().__init__()
        if dim % n_heads != 0:
            raise ValueError("dim 必须能被 n_heads 整除")
        self.n_heads = n_heads
        self.head_dim = dim // n_heads
        self.q_proj = nn.Linear(dim, dim, bias=False)
        self.k_proj = nn.Linear(dim, dim, bias=False)
        self.v_proj = nn.Linear(dim, dim, bias=False)
        self.o_proj = nn.Linear(dim, dim, bias=False)

    def forward(self, x):
        b, t, d_model = x.shape
        # 先拆最后一维，再交换 T 和 H 两个轴。
        q = self.q_proj(x).reshape(b, t, self.n_heads, self.head_dim).transpose(1, 2)
        k = self.k_proj(x).reshape(b, t, self.n_heads, self.head_dim).transpose(1, 2)
        v = self.v_proj(x).reshape(b, t, self.n_heads, self.head_dim).transpose(1, 2)
        # [B,H,T,d] @ [B,H,d,T] = [B,H,T,T]
        scores = (q.float() @ k.float().transpose(-2, -1)) / math.sqrt(self.head_dim)
        allowed = torch.ones(t, t, dtype=torch.bool, device=x.device).tril()
        scores = scores.masked_fill(~allowed, float("-inf"))
        weights = torch.softmax(scores, dim=-1).to(v.dtype)
        mixed = weights @ v                         # [B,H,T,d]
        merged = mixed.transpose(1, 2).reshape(b, t, d_model)
        return self.o_proj(merged)                  # [B,T,D]


class RMSNorm(nn.Module):
    def __init__(self, dim, eps=1e-6):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(dim))
        self.eps = eps

    def forward(self, x):

        mean_square = xf.square().mean(dim=-1, keepdim=True)
        normalized = xf * torch.rsqrt(mean_square + self.eps)

def apply_rope(x, positions, theta=10000.0):
    """x: [B,H,T,d]；positions: [T]；使用相邻偶/奇维度配对。"""
    d = x.size(-1)
    if d % 2 or positions.numel() != x.size(-2):
        raise ValueError("检查 head_dim 和 positions 长度")
    inv_freq = theta ** (-torch.arange(0, d, 2, device=x.device, dtype=torch.float32) / d)
    angles = positions.to(device=x.device, dtype=torch.float32)[:, None] * inv_freq[None, :]
    cos = angles.cos()[None, None, :, :]         # [1,1,T,d/2]
    sin = angles.sin()[None, None, :, :]
    even = x.float()[..., 0::2]                  # [B,H,T,d/2]
    odd = x.float()[..., 1::2]
    rotated_even = even * cos - odd * sin
    rotated_odd = even * sin + odd * cos
    return torch.stack((rotated_even, rotated_odd), dim=-1).flatten(-2).to(x.dtype)

def fa2_forward(q, k, v, block_q, block_k, causal):
    # q/k/v: [B,H,N,d]，本教程限定 FP32/FP64、等长、无 padding。
    n, d = q.shape[-2:]
    scale = 1.0 / math.sqrt(d)
    out = torch.empty_like(q)
    lse = torch.empty(q.shape[:-1], device=q.device, dtype=q.dtype)
    for qs in range(0, n, block_q):
        qe = min(qs + block_q, n)
        qi = q[..., qs:qe, :]
        q_pos = torch.arange(qs, qe, device=q.device)
        row_max = torch.full_like(qi[..., :1], -torch.inf)
        row_sum = torch.zeros_like(row_max)
        acc = torch.zeros_like(qi)
        # 因果模式只访问可能可见的 K/V 块。
        stop = qe if causal else n
        for ks in range(0, stop, block_k):
            ke = min(ks + block_k, n)
            kj, vj = k[..., ks:ke, :], v[..., ks:ke, :]
            scores = (qi @ kj.transpose(-2, -1)) * scale
            if causal:
                k_pos = torch.arange(ks, ke, device=q.device)
                allowed = k_pos[None, :] <= q_pos[:, None]
                scores = scores.masked_fill(~allowed, -torch.inf)
            new_max = torch.maximum(
                row_max, scores.amax(dim=-1, keepdim=True)
            )
            alpha = torch.exp(row_max - new_max)
            p_tilde = torch.exp(scores - new_max)
            row_sum = alpha * row_sum + p_tilde.sum(-1, keepdim=True)
            acc = alpha * acc + p_tilde @ vj
            row_max = new_max
        out[..., qs:qe, :] = acc / row_sum
        lse[..., qs:qe] = (row_max + row_sum.log()).squeeze(-1)
    return out, lse


def fa2_backward(q, k, v, out, lse, grad_out, block_q, block_k, causal):
    n, d = q.shape[-2:]
    scale = 1.0 / math.sqrt(d)
    dq, dk, dv = [torch.zeros_like(x) for x in (q, k, v)]
    # 每一行的 delta = sum_j(P_ij * dP_ij) = dot(O_i, dO_i)。
    delta = (out * grad_out).sum(dim=-1, keepdim=True)
    for qs in range(0, n, block_q):
        qe = min(qs + block_q, n)
        qi = q[..., qs:qe, :]
        doi = grad_out[..., qs:qe, :]
        li = lse[..., qs:qe, None]
        di = delta[..., qs:qe, :]
        q_pos = torch.arange(qs, qe, device=q.device)
        stop = qe if causal else n
        for ks in range(0, stop, block_k):
            ke = min(ks + block_k, n)
            kj, vj = k[..., ks:ke, :], v[..., ks:ke, :]
            scores = (qi @ kj.transpose(-2, -1)) * scale
            if causal:
                k_pos = torch.arange(ks, ke, device=q.device)
                allowed = k_pos[None, :] <= q_pos[:, None]
                scores = scores.masked_fill(~allowed, -torch.inf)
            # 只重建当前 tile 的 P，不保存整个 [N,N] 矩阵。
            p = torch.exp(scores - li)
            dv[..., ks:ke, :] += p.transpose(-2, -1) @ doi
            dp = doi @ vj.transpose(-2, -1)
            ds = p * (dp - di)
            dq[..., qs:qe, :] += (ds @ kj) * scale
            dk[..., ks:ke, :] += (ds.transpose(-2, -1) @ qi) * scale
    return dq, dk, dv


class FlashAttention2Teaching(torch.autograd.Function):
    @staticmethod
    def forward(ctx, q, k, v, block_q, block_k, causal):
        out, lse = fa2_forward(q, k, v, block_q, block_k, causal)
        # 自定义 Function 的 forward 不记录内部算子图。
        ctx.save_for_backward(q, k, v, out, lse)
        ctx.settings = (block_q, block_k, causal)
        return out

    @staticmethod
    @once_differentiable
    def backward(ctx, grad_out):
        q, k, v, out, lse = ctx.saved_tensors
        dq, dk, dv = fa2_backward(
            q, k, v, out, lse, grad_out, *ctx.settings
        )
        return dq, dk, dv, None, None, None


def flash_attention_2(q, k, v, block_q=32, block_k=32, causal=True):
    """同形 [B,H,N,d]，FP32/FP64，仅一阶梯度；CPU/GPU 均可执行。"""
    if q.ndim != 4 or q.shape != k.shape or q.shape != v.shape:
        raise ValueError("q/k/v 必须同形，且为 [B,H,N,d]")
    if min(q.shape) < 1 or block_q < 1 or block_k < 1:
        raise ValueError("张量各维和分块大小必须为正数")
    if q.dtype not in (torch.float32, torch.float64):
        raise ValueError("教学版只支持 FP32/FP64")
    if not (q.dtype == k.dtype == v.dtype and q.device == k.device == v.device):
        raise ValueError("q/k/v 的 dtype 和 device 必须一致")
    return FlashAttention2Teaching.apply(q, k, v, block_q, block_k, causal)

class LlamaAttention(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.n_heads = cfg.n_heads
        self.n_kv_heads = cfg.n_kv_heads
        self.head_dim = cfg.dim // cfg.n_heads
        self.theta = cfg.rope_theta
        self.backend = cfg.attention_backend
        self.q_proj = nn.Linear(cfg.dim, cfg.n_heads * self.head_dim, bias=False)
        self.k_proj = nn.Linear(cfg.dim, cfg.n_kv_heads * self.head_dim, bias=False)
        self.v_proj = nn.Linear(cfg.dim, cfg.n_kv_heads * self.head_dim, bias=False)
        self.o_proj = nn.Linear(cfg.dim, cfg.dim, bias=False)

    def forward(self, x):
        b, t, dim = x.shape
        q = self.q_proj(x).reshape(b, t, self.n_heads, self.head_dim).transpose(1, 2)
        k = self.k_proj(x).reshape(b, t, self.n_kv_heads, self.head_dim).transpose(1, 2)
        v = self.v_proj(x).reshape(b, t, self.n_kv_heads, self.head_dim).transpose(1, 2)
        positions = torch.arange(t, device=x.device)
        q = apply_rope(q, positions, self.theta)
        k = apply_rope(k, positions, self.theta)  # V 不旋转
        repeat = self.n_heads // self.n_kv_heads
        k = k.repeat_interleave(repeat, dim=1)
        v = v.repeat_interleave(repeat, dim=1)
        if self.backend == "fa2":
            mixed = flash_attention_2(q, k, v, block_q=16, block_k=16)
        else:
            scores = (q.float() @ k.float().transpose(-2, -1)) / math.sqrt(self.head_dim)
            allowed = torch.ones(t, t, device=x.device, dtype=torch.bool).tril()
            scores = scores.masked_fill(~allowed, float("-inf"))
            weights = F.softmax(scores, dim=-1).to(v.dtype)
            mixed = weights @ v
        merged = mixed.transpose(1, 2).reshape(b, t, dim)
        return self.o_proj(merged)


class DecoderBlock(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.attn_norm = RMSNorm(cfg.dim, cfg.norm_eps)
        self.attn = LlamaAttention(cfg)
        self.ffn_norm = RMSNorm(cfg.dim, cfg.norm_eps)
        self.ffn = SwiGLU(cfg.dim, cfg.hidden_dim)

    def forward(self, x):
        x = x + self.attn(self.attn_norm(x))
        x = x + self.ffn(self.ffn_norm(x))
        return x


class MiniLlama(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.cfg = cfg
        self.embedding = nn.Embedding(cfg.vocab_size, cfg.dim)
        self.layers = nn.ModuleList([DecoderBlock(cfg) for _ in range(cfg.n_layers)])
        self.final_norm = RMSNorm(cfg.dim, cfg.norm_eps)
        self.lm_head = nn.Linear(cfg.dim, cfg.vocab_size, bias=False)
        self.apply(self._init_weights)

    @staticmethod
    def _init_weights(module):
        if isinstance(module, (nn.Linear, nn.Embedding)):
            nn.init.normal_(module.weight, mean=0.0, std=0.02)

    def forward(self, input_ids):
        if input_ids.ndim != 2 or not 0 < input_ids.size(1) <= self.cfg.max_seq_len:
            raise ValueError("input_ids 需要是 [B,T]，且 1 <= T <= max_seq_len")
        hidden = self.embedding(input_ids)      # [B,T] -> [B,T,D]
        for layer in self.layers:
            hidden = layer(hidden)
        return self.lm_head(self.final_norm(hidden)).float()  # [B,T,Vocab]


def next_token_loss(logits, targets):
    """targets 已经由数据侧右移一位；这里不能再 shift 一次。"""
    return F.cross_entropy(logits.reshape(-1, logits.size(-1)),
                           targets.reshape(-1), ignore_index=-100)

def sample_next(logits, temperature=0.0, top_k=None):
    """输入 [B,Vocab]；输出 [B,1]。temperature=0 表示贪心生成。"""
    if temperature < 0 or not math.isfinite(temperature):
        raise ValueError("temperature 必须是有限非负数")
    if temperature == 0:
        return logits.argmax(dim=-1, keepdim=True)
    scores = logits.float() / temperature
    if top_k is not None:
        if top_k < 1:
            raise ValueError("top_k 必须 >= 1")
        values, indices = scores.topk(min(top_k, scores.size(-1)), dim=-1)
        scores = torch.full_like(scores, float("-inf")).scatter(-1, indices, values)
    return torch.multinomial(F.softmax(scores, dim=-1), num_samples=1)

class CachedAttention(LlamaAttention):
    def forward(self, x, past=None):
        b, t, dim = x.shape
        past_len = 0 if past is None else past[0].size(-2)
        q = self.q_proj(x).reshape(b, t, self.n_heads, self.head_dim).transpose(1, 2)
        k = self.k_proj(x).reshape(b, t, self.n_kv_heads, self.head_dim).transpose(1, 2)
        v = self.v_proj(x).reshape(b, t, self.n_kv_heads, self.head_dim).transpose(1, 2)
        positions = torch.arange(past_len, past_len + t, device=x.device)
        q = apply_rope(q, positions, self.theta)
        k = apply_rope(k, positions, self.theta)
        if past is not None:
            k = torch.cat((past[0], k), dim=-2)
            v = torch.cat((past[1], v), dim=-2)
        new_cache = (k, v)                     # 紧凑存储 Hkv 个头，K 已旋转
        repeat = self.n_heads // self.n_kv_heads
        keys = k.repeat_interleave(repeat, dim=1)
        values = v.repeat_interleave(repeat, dim=1)
        scores = (q.float() @ keys.float().transpose(-2, -1)) / math.sqrt(self.head_dim)
        key_positions = torch.arange(k.size(-2), device=x.device)
        # 例：past_len=3、t=2 时，两行可见列数分别是 4 和 5。
        allowed = key_positions[None, :] <= positions[:, None]
        scores = scores.masked_fill(~allowed[None, None, :, :], float("-inf"))
        weights = torch.softmax(scores, dim=-1).to(values.dtype)
        mixed = (weights @ values).transpose(1, 2).reshape(b, t, dim)
        return self.o_proj(mixed), new_cache


class CachedLlama(MiniLlama):
    def __init__(self, cfg):
        super().__init__(cfg)
        for layer in self.layers:
            layer.attn = CachedAttention(cfg)
        self.apply(self._init_weights)

    @torch.no_grad()
    def forward(self, input_ids, caches=None):
        if input_ids.ndim != 2 or input_ids.size(1) < 1:
            raise ValueError("input_ids 需要是非空 [B,T]")
        if caches is None:
            caches = [None] * self.cfg.n_layers
        if len(caches) != self.cfg.n_layers:
            raise ValueError("每层都需要一个 cache 槽位")
        populated = [c is not None for c in caches]
        if any(populated) and not all(populated):
            raise ValueError("cache 必须全部为空或全部有效")
        lengths = [0 if c is None else c[0].size(-2) for c in caches]
        if len(set(lengths)) != 1:
            raise ValueError("各层 cache 长度必须相等")
        for c in caches:
            if c is not None:
                expected = (input_ids.size(0), self.cfg.n_kv_heads,
                            lengths[0], self.cfg.dim // self.cfg.n_heads)
                if tuple(c[0].shape) != expected or tuple(c[1].shape) != expected:
                    raise ValueError("cache 的 batch/head/length/dim 不匹配")
        if lengths[0] + input_ids.size(1) > self.cfg.max_seq_len:
            raise ValueError("输入与 cache 总长度超出 max_seq_len")
        hidden = self.embedding(input_ids)
        updated = []
        for layer, past in zip(self.layers, caches):
            attn_out, cache = layer.attn(layer.attn_norm(hidden), past)
            hidden = hidden + attn_out
            hidden = hidden + layer.ffn(layer.ffn_norm(hidden))
            updated.append(cache)
        logits = self.lm_head(self.final_norm(hidden)).float()
        return logits, updated


@torch.no_grad()
def generate_cached(model, input_ids, max_new_tokens=20, temperature=0.0, top_k=None):
    if input_ids.ndim != 2 or input_ids.size(1) < 1 or max_new_tokens < 0:
        raise ValueError("需要非空 [B,T] 输入，且 max_new_tokens >= 0")
    if input_ids.size(1) + max_new_tokens > model.cfg.max_seq_len:
        raise ValueError("教学版不滑动窗口；请缩短输入/输出长度")
    was_training = model.training
    model.eval()
    try:
        tokens = input_ids.clone()
        if max_new_tokens == 0:
            return tokens
        logits, caches = model(tokens)          # prefill：一次处理整个 prompt
        for step in range(max_new_tokens):
            new_token = sample_next(logits[:, -1, :], temperature, top_k)
            tokens = torch.cat((tokens, new_token), dim=1)
            if step + 1 < max_new_tokens:
                logits, caches = model(new_token, caches)  # decode：只传一个新 token
        return tokens
    finally:
        model.train(was_training)
