① Qwen3.8‑Flash‑Next：不是单点“线性注意力”，而是四层联合设计

这份 8 月 26 日技术报告最值得看的是评估方法：每项架构变更都同时检查下游能力、训练/prefill/decode 成本，以及最优超参数和稳定性。最终模型为 125B MoE、每 token 激活 6B，另把 51B n‑gram embedding 表放在加速器外的主存中预取。报告称，它在 14 个预训练基准中有 8 个超过 397B‑A17B 前代，其余最多落后 2.6 分，但只使用约 1/3 激活参数、1/3 训练 token 和约 1/9 训练 FLOPs。

Token mixing 仍是 3:1 的 Gated DeltaNet 与全局层混合；持续预训练阶段再把全局层替换为 Qwen Sparse Attention（QSA）。QSA 先用压缩的轻量索引器按微块筛历史，再做精确注意力，因此它属于内容稀疏，不是线性注意力。Gated Residual 把残差流扩成四个分支，并用逐元素门决定怎么读；Muon 用于二维线性权重，embedding、输出头、MoE router 与低秩门控仍留在 AdamW。报告还指出，批量 warmup 最终效果没有更好，却多花 18.8% optimizer steps，因此直接从目标 batch 开始。

② Nemotron 3.5 Lightning：把“子 Agent 执行层”做成一张卡可跑的开放模型

NVIDIA 选择了另一种效率路线：30B 总参数、3B 激活，Mamba‑2、MoE 与少量 Attention 混合，预训练超过 20T token，支持 1M context。NVFP4 模型卡明确给出单个 DGX Spark 或 H100 的部署路径，并同时提供 DSpark、DFlash 与 MTP 三种推测解码选项。后训练使用多环境 GRPO，覆盖数学、代码、科学、指令、工具、多轮与结构化输出；异步 RL 将训练与生成解耦，并用 MTP 加速 rollout。

它的定位不是替代 550B Ultra，而是承担系统中的高频执行：例如主 Agent 负责任务规划，Lightning 负责代码审查、告警分析、工具调用和批量子任务。开放权重、量化权重、评测 recipe 与部署 recipe 都给出，使“本地吞吐/复现成本”可以直接验证；但 OpenMDW‑1.1 是开放模型许可，不应自动等同于 OSI 意义上的开源软件。

③ GLM‑5.3：同一基座，后训练本身成为版本边界

GLM‑5.3 的模型卡明确写明“uses the same base model as GLM‑5.2 — every gain comes from post‑training”。这使它成为本月很干净的对照实验：744B 级 DSA/MoE 骨干、1M 上下文路线不变，变化来自复杂编码与长程 Agent 的数据、环境和训练预算。官方自报 Terminal‑Bench 3.0 从 4.6 升到 28.3、DeepSWE v1.1 从 46.2 升到 66.9；这些数字依赖 Claude Code harness、最长数小时的任务预算与指定上下文，因此只能说明该后训练配方在相同官方口径下进步，不能直接换算成裸模型能力。

DeepSeek‑V4.1‑Flash 为什么是本次累计报告最重要的结构更新

V4.1‑Flash 把“长上下文成本”拆成四张账单。第一，Causal Encoder‑Decoder（CED）让输入阶段只激活 8B、输出阶段激活 16B，适配输入远长于输出的 Agent。第二，Compressed Sparse Attention 2（CSA2）在层间复用 global KV、索引器 K 与 Top‑K 结果，并用 Full / Reindex / Reuse 三种静态模式控制重算。第三，global KV 在训练时就使用 FP4。第四，SWA Bounded Replay 不再持久化全部局部 KV，而只回放最近一个窗口近似重建状态。

报告给出的结果是：global KV 降到每 token 890 bytes，约为 V4‑Flash 的 1/4；需要长期保存在 SSD 或主存中的 persistent KV 约降至 1/8。模型有 552B backbone、40 层（20 encoder + 20 decoder）、384 routed experts，每 token 选 6 个 routed expert；训练 45T 多模态 token，并在 34T token 时把上下文扩到 1M。后训练算法本身没有新花样，仍是 SFT → RL → OPD，提升主要来自合成任务、环境构造和规模化 rollout。其多 Agent 初步实验还把任务奖励、协作 bonus 与基于关键路径的派生延迟惩罚合在一起：奖励有效并行，同时惩罚无意义同步。

本期真正的技术结论：线性注意力、内容稀疏、SWA 与 KV 量化已不再互斥。2026 年下半年的领先设计倾向于把它们分层组合：递归状态管大部分 token，内容稀疏负责精确远程跳转，SWA 保留局部连续性，FP4/FP8 与跨层复用再处理缓存和带宽。

01 · DeepSeek V4 → V4.1：从稀疏计算推进到 KV 全生命周期 CSA2 · CED · FP4 KV

V4 先压注意力 FLOPs；V4.1‑Flash 再把 HBM、主存/SSD、prefill 和 decode 分开优化，并把原生多模态与多 Agent RL 接入同一底座。

动机：Agent 每一步都把仓库、终端输出和历史状态重新塞回上下文后，瓶颈不只在注意力计算，还在 KV 常驻显存、跨层重复、持久化存储与恢复带宽。

9 月新增：V4.1‑Flash 的四层压缩链

V4.1‑Flash 使用 20 层因果 encoder 与 20 层 decoder。Encoder 将长输入压成最终隐状态，decoder 的 global KV 从这些状态投影，因此输入阶段只激活 8B、输出阶段激活 16B；对于“读一百万 token、只写几千 token”的 Agent，这比所有阶段都按同一激活预算更合算。

CSA2 将全局层分成 Full、Reindex 与 Reuse：Full 生成 global KV 并建索引；Reindex 复用 global KV 但重新打分；Reuse 连 Top‑K 索引也复用。再叠加 FP4 global KV，运行时 global KV 为每 token 890 bytes，官方报告约为 V4‑Flash 的 1/4。SWA Bounded Replay 则不再把所有局部 KV 长期写入 SSD/主存，而只回放最近一个窗口近似恢复，使 persistent KV 约降到 V4‑Flash 的 1/8。

这条路线也明确暴露边界：CSA2 的选择器可能漏掉弱相关证据，Bounded Replay 是近似恢复；报告只证明在其测试分布上退化很小，不能推出任意一百万 token 任务都无损。因此部署时应同时测远程多跳证据、前缀恢复和长轨迹重启，而不是只跑单针 NIAH。

问题：V3 之后，瓶颈从“参数够不够”转向“历史怎么被访问”

DeepSeek V4 技术报告给出两个开放权重配置：V4-Pro 为 1.6T 总参数、每 token 激活 49B；V4-Flash 为 284B 总参数、激活 13B，均支持 1M token。这个拆分很重要：Pro 不是 Flash 的简单放大版，而是同一套注意力与残差设计在不同激活预算上的两条产品曲线。

方法：五层改造共同削减“长历史税”

① CSA：先选内容，再做精确注意力

Compressed Sparse Attention（CSA）不让每个 query 与全部历史 token 做点积，而是先通过压缩表征挑出少量内容相关位置，再在候选上计算精确注意力。它属于内容稀疏注意力，不是把序列压进固定大小状态的线性注意力。

Cdense ∝ L²d　→　CCSA ∝ L·k·d，且 k ≪ L

白话翻译：全注意力让每个 token 看完整本书；CSA 先翻目录，挑出 k 页再细读。这里是复杂度直觉式，真实成本还包括索引、压缩器与内核实现。

② HCA：不是只少看，还要少存

Heavily Compressed Attention（HCA）进一步压缩需要长期保留的表示，与 CSA 组成混合路径：局部与高频交互保留足够精度，远距离历史则通过更紧凑状态进入注意力。于是长上下文优化同时作用于 FLOPs 与 KV cache，而不只是训练时的理论复杂度。

③ mHC + DeepSeekMoE：让超深稀疏网络不在残差处失稳

V4 保留 DeepSeekMoE 与多 token 预测（MTP），同时引入 mHC 残差机制、调整路由激活，并让早期 FFN 使用哈希路由。MoE 决定“本 token 调哪些参数”，mHC 决定“层与层之间的信息怎样稳定通过”；两者分别控制计算密度和优化稳定性。

④ Muon + 32T/33T token：架构节省要靠训练规模兑现

报告披露 V4-Flash 与 V4-Pro 分别使用约 32T、33T 预训练 token，并采用 Muon 优化器。长上下文结构不是在小模型上验证后直接插入，而是与大规模预训练一起共同收敛，这也是“高效注意力可以即插即用”经常失败的原因。

⑤ 专家 RL → GRPO → OPD：把多种策略重新合成一个模型

后训练先由领域专家数据与 GRPO 强化学习形成不同能力，再用 on-policy distillation（OPD）把教师策略合并进统一学生；混合 RL 阶段也由 OPD 接手。它与离线蒸馏的关键差别，是学生在自己的当前分布上采样，再向教师询问或对齐，从而减小“训练时会、自己跑就偏”的分布差。

LOPD = Ex∼πθ[ KL( πθ(·|x) ∥ πT(·|x) ) ]

白话翻译：让学生先按自己的习惯走到现场，再让教师纠偏；反向 KL 更鼓励学生集中到教师认可的高概率动作上。公式用于解释报告所述机制，具体实现还包含采样与多任务细节。

证据：节省不是“理论 O()”，而是报告中的端到端比率

报告还给出更激进的 Flash 比率：单 token 推理 FLOPs 约为 V3.2 的 10%，KV cache 约为 7%。这些数字最能说明 V4 的目标不是单项 benchmark，而是让长轨迹 Agent 的每一步不再重复支付全历史成本；不过它们来自同一报告与其测量环境，不能直接换算成任何第三方部署的吞吐。

类比：V4 像一座大型档案馆：CSA 是按内容检索的索引，HCA 是缩微胶片，MoE 是只叫来相关领域的馆员，OPD 则是把多位馆员的办事流程整理成一个统一前台。

02 · Kimi K2.5 → K3：先让 Agent 并行，再让历史成为状态 PARL · KDA

K2.5 解决“看见并行动”，K3 解决“在百万 token 中持续行动”；二者共同把模型从回答器推向任务编排器。

动机：搜索、网页、代码和视觉核验往往可以并行；若一个模型仍按单线程逐步做，智能上限可能还没到，墙钟时间已经不可接受。

方法：从原生多模态到 Agent Swarm，再到 KDA

① K2.5：视觉不是后装插件，而是继续预训练的一部分

K2.5 基于 K2 的 1.04T / 32B 激活 MoE，在其上继续进行约 15T 图文混合 token 的联合预训练。MoonViT-3D 以原生分辨率处理图像与视频，共用编码器，并通过四帧分组和时间池化把可处理视频长度扩展约 4 倍。

② 早期低比例视觉混合，反而优于后期猛灌视觉

在总 token 预算固定时，报告比较了 Early 10:90、Mid 20:80 与 Late 50:50 的视觉/文本配比。结果并不支持“视觉数据越晚越多越好”：早期、低比例、持续混合在视觉知识、OCR、文本知识与代码上都更稳，说明跨模态表征需要长时间共同塑形。

一个反直觉结果是：只用文本 Agent 轨迹做 SFT，也能激活模型对视觉工具的调用；人工编写的“视觉轨迹模板”反而可能限制泛化。随后联合多模态 RL 不仅提升视觉任务，也让 MMLU-Pro 从 84.7 升至 86.4、GPQA-Diamond 从 84.3 升至 86.4、LongBench v2 从 56.7 升至 58.9，显示视觉环境训练对文本推理存在正迁移。

④ Agent Swarm + PARL：训练编排器，而不是同时微调所有工人

K2.5 的 Agent Swarm 由一个 orchestrator 拆任务、生成多个 subagent 并汇总；Parallel-Agent Reinforcement Learning（PARL）冻结子 Agent，只训练编排器。奖励同时约束并行度、是否真正完成子任务与最终质量，防止“看似开很多 Agent，实则串行”或无意义扩张。

rPARL(x,y) = λ₁rparallel + λ₂rfinish + rperf(x,y)

白话翻译：既奖励“确实同时开工”，也奖励“开出去的任务都收回来”，最后仍由成品质量兜底；否则并行会退化成制造更多日志。

⑤ K3：2.8T / 104B、KDA 主层与 1M token Agent RL

K3 将规模推至 2.8T 总参数、104B 激活，以 Kimi Delta Attention（KDA）为主、MLA 精确全局层为辅，并配合 Attention Residuals 与 Stable LatentMoE。KDA 属于真正的线性/递归注意力：历史被写入固定大小状态，查询从状态读出；报告再把 rollout 与沙箱状态持久化，使百万 token 的 Agent 强化学习不必每次从头重放。

St = gt ⊙ St−1 + U(kt,vt)；　ot = qtTSt

白话翻译：KDA 像一本会改写的工作记忆：新信息按门控写进状态，旧信息被衰减或修正，查询无需重新扫描全部 token。公式是递归注意力的简化骨架，不等同于 KDA 的完整 delta 更新。

03 · GLM-5 → 5.3：当 Agent RL 变慢，训练系统必须异步 DSA · slime · Post-training

744B / 40B 激活的开放权重骨干只是起点；5.3 进一步证明，同一基座上的环境、轨迹与后训练规模可以单独构成一个版本代际。

动机：数学题的奖励几秒就能验证，浏览器和终端任务却可能跑几分钟；若训练 GPU 等 rollout，利用率会坍塌，若直接用旧轨迹更新，策略又会漂移。

问题：长上下文与长轨迹是两种不同的“长”

GLM-5 以 744B 总参数、40B 激活、256 专家和 80 层构建 MoE，预训练约 28.5T token，其中初始预训练约 27T；中期训练把上下文从 4K 逐步推到 200K。这里的长上下文解决“看得下”，异步 RL 解决“做得久”，两者缺一不可。

方法：从 DSA 到跨阶段 on-policy 蒸馏

① DSA：按 query 内容选历史，而不是按固定距离裁剪

DeepSeek Sparse Attention（DSA）先估计 query 与历史位置的相关性，再对 top-k 位置执行注意力。它仍保留 query-key 点积与显式历史 token，因此属于内容稀疏，与 Gated DeltaNet 把历史压为递归状态的线性注意力不同。

Ji = TopK(s(qi,K), k)；　hi = softmax(qiKJᵢT)VJᵢ

白话翻译：先用便宜的打分器找出与当前问题最相关的 k 段历史，再做标准注意力；稀疏的是访问集合，不是把记忆压成一个固定矩阵。

② 高效注意力不是插件：固定 SWA 替换在 128K 上会突然失效

报告同时测试了 Gated DeltaNet、固定 1:1 的 SWA/全注意力交错和搜索得到的 SWA 模式。一个关键消融是：不经过针对性训练便把既有全注意力替换成固定 SWA，128K 汇总结果从 75.28 降到 6.51；即使搜索布局可回到 53.95，也说明“局部窗口 + 少量全局层”必须与训练分布共同设计。

③ Reasoning RL → Agentic RL → General RL：分阶段保护能力

GLM-5 把后训练串成三段：先用可验证奖励强化推理，再进入工具与环境内 Agent RL，最后做通用偏好和对齐。阶段越多，遗忘风险越高，因此使用 On-Policy Cross-Stage Distillation：后一阶段在自己的 rollout 上继续吸收前一阶段策略，避免“会操作工具之后反而不会解题”。

④ slime 异步 RL：rollout 与优化器解耦

训练框架 slime 把推理集群、环境执行与参数更新拆开：一批轨迹还在浏览器或终端中运行时，训练 GPU 可消费已经完成的样本；系统再通过 token 级裁剪和过期样本丢弃控制策略陈旧度。异步带来吞吐，也引入 behavior policy 与当前 policy 的偏差。

ρt = πθ(at|st) / πbeh(at|st)；　仅保留或裁剪可信 ρt

白话翻译：轨迹生成后模型已经更新了，所以要检查“今天的模型还会不会做出昨天的动作”；差得太远的 token 不应强行拿来训练。这里概括异步 off-policy 控制，具体阈值与损失以报告实现为准。

⑤ 5.1 → 5.2：骨干稳定后，把产品目标推到百万上下文与长时工程

GLM-5.1 在 4 月继续提升 Agent 与编程，5.2 于 6 月开放权重并把上下文推至 1M。官方仓库报告 Terminal-Bench 2.1 从 5.1 的 62.0 提升到 81.0、SWE-bench Pro 从 58.4 到 62.1；这些数字仍依赖其指定 Agent harness，但清晰反映优化重心：从短代码生成转向跨终端、跨文件的长时任务。

④ 5.3：不换 base model，只扩大后训练的“工作半径”

8 月 27 日的 GLM‑5.3 模型卡明确说明它与 5.2 使用相同 base model，所有提升都来自 post‑training。官方自报 DeepSWE v1.1 为 66.9（5.2 为 46.2）、Terminal‑Bench 3.0 为 28.3（5.2 为 4.6）、AutomationBench 为 48.2（5.2 为 26.2）。这些分数的共同特征是任务长、工具多、最长运行数小时；因此 5.3 更像一次 Agent 行为分布升级，而不是结构升级。

模型卡把 harness、最长上下文、output budget、超时和多次 rollout 写得很细，这一点比单独报一个分数更重要：当一个模型使用 400K—1M context、64K—128K 输出和 4—10 小时任务预算时，它的榜单结果已经是“模型 × scaffold × 预算”的系统值。选型时应复用同一 harness 重测，而不是把不同厂商的最高分直接横排。

04 · Step 3.5 Flash：不追求最激进结构，追求 11B 激活的系统密度 SWA · MTP-3 · MIS-PO

196B 总参数装进 128GB 级工作站目标，揭示了另一个前沿：模型、解码器和 RL 必须为同一部署边界协同设计。

动机：线性注意力理论上更省，但若它破坏 tree drafting 和并行验证，端到端生成反而可能更慢；最优骨干必须与推测解码一起看。

方法：用保守的注意力换更激进的整机吞吐

① 196B / 11B：总容量与单 token 成本分离

Step 3.5 Flash 是 196B 总参数、11B 激活的 MoE，256K 上下文，报告评测时输出上限为 64K。总规模控制在 200B 内，是为了让 FP8 权重有机会落入 128GB 级高端工作站；每 token 仅激活约 5.6%，则把长输出成本压到可持续范围。

② 一层全局开路，之后按 3 SWA + 1 全局重复

骨干先放一个全注意力层，再重复 11 个“3 个滑窗注意力 + 1 个全注意力”的块，SWA 窗口为 512，并加入 head-wise gating。局部层承担近期语法和推理连续性，全局层周期性建立跨窗口连接，因此它不是纯局部模型。

③ 为什么没选线性注意力：推测解码的树需要可并行验证

报告明确比较过线性注意力，最终选择 SWA 的原因之一，是标准点积注意力更容易支持 tree-based drafting 与 parallel verification。递归状态通常依赖严格的时间更新顺序；同一前缀上同时验证多个候选分支时，需要复制、分叉或重算状态，内核复杂度可能抵消理论节省。

④ MTP-3：一次预测三个未来位置，为验证器准备候选树

多 token 预测（MTP）使用三层未来头生成候选，再由主模型并行验证。它既是训练辅助目标，也是推理加速接口；因此 Step 的注意力选择不能只用训练 FLOPs 判断，而要看“候选生成—并行验证—接受长度”的完整路径。

⑤ MIS-PO：不相信极端 importance weight，直接屏蔽不可信样本

MoE 在 off-policy RL 中更敏感：旧策略与新策略即使只在少量路由上变化，也可能放大概率比率。MIS-PO 用二元 mask 筛掉偏差过大的 token 或轨迹，而不是让极端 importance weight 主导梯度。

m(τ) = 1[ ρ(τ) ∈ [ρmin,ρmax] ]；　L = E[m(τ)·Lpolicy(τ)]

白话翻译：旧模型留下的经验如果和当前模型相差太大，就先不学，而不是给它一个巨大权重“硬纠正”；这是对 MIS-PO 过滤思想的简化表达。

证据：小激活预算覆盖推理、代码与工具任务

86.4%LiveCodeBench v6（报告设置）

类比：线性注意力像极省油的单轨列车，SWA + 全局层像高速公路网；Step 选择后者，是因为推测解码要让多辆候选车同时上路、同时验票，整条运输链反而更顺。

05 · 原生 VLM 底座：多模态从“接口”进入“世界模型” Early Fusion · Omni

Qwen3.5/3.8/Flash‑Next、ERNIE 5、MiniMax M3、MiMo V2.5 与 Seed 2.x 共同表明：视觉、语音和动作不再只在模型入口拼接，而要贯穿预训练、RL 与工具执行。

动机：一个电脑操作 Agent 若只在开头“看一眼截图”，之后仍以纯文本推理，它就无法持续感知页面变化、声音反馈和操作后果；多模态必须进入每一轮状态更新。

共同变化：同一骨干、同一轨迹、不同输出头

① Qwen3.5：原生视觉语言与 Gated DeltaNet 同时落地

Qwen3.5-397B-A17B 是 397B 总参数、17B 激活、60 层的原生视觉语言 MoE。其核心布局可写成 15 组 3 ×（Gated DeltaNet → MoE）+ 1 ×（Gated Attention → MoE）：四分之三是线性/递归注意力，四分之一用标准注意力补足精确全局访问；512 个专家中每 token 路由 10 个，另有 1 个共享专家。

模型卡给出 262,144 token 原生上下文，可扩到约 1,010,000；预训练与后训练覆盖 201 种语言，并在百万级 Agent 环境中进行异步 RL。它把“多模态”和“高效长上下文”放进同一底座，而不是先训练一个文本模型、再在末端挂视觉适配器。

② Qwen3.8 与 Qwen3.5-Omni：规模、音视频和开放权重分成两条支线

8 月的 Qwen3.8 延续 Qwen3.5 架构，先开放 2.4T / 95B 激活版本，再开放 27B 等配置；官方把它定位为首个 Qwen-Max 级开放权重发布，并加入可调 reasoning effort 与思考状态保留。另一条 Qwen3.5-Omni 支线以 Thinker + Talker 组织理解与语音生成，报告披露超过 1 亿小时音视频数据、256K 上下文与 ARIA 文本/语音单元对齐，目标是让实时听说、视频理解和工具调用共用一个 Agent 状态。

②b Qwen3.8‑Flash‑Next：轻量支线把“模型外参数”也纳入容量设计

Flash‑Next 不靠简单缩层得到 6B 激活。它把大部分历史压入 Gated DeltaNet 的固定状态，用每四层一个 QSA 保留精确远程检索，再把 51B n‑gram embedding 表放在主存中按需预取。这样一部分“记忆容量”不参与每 token 的 Transformer 计算，也不长期占用加速器显存。Gated Residual 的四分支残差则补偿轻量骨干的表示容量；报告的核心经验是，损失、下游准确率、真实 kernel 成本和稳定性必须一起调，单看 loss 甚至会选错 n‑gram 词表规模。

③ ERNIE 5：把四种模态统一成“下一组 token”

ERNIE 5.0 官方称总参数 2.4T，采用模态无关的超稀疏 MoE，激活率低于 3%。文本使用 NTP + MTP，视觉预测下一帧及尺度，音频预测下一组 codec token；统一的 Next-Group-of-Tokens（NGoT）目标让理解和生成不再由互不相干的模型分别承担。

LNGoT = − Σm∈{text,image,video,audio} Σg log p(xg(m) | x<g)

白话翻译：无论下一步是一个词、一组图像 patch、下一帧尺度还是一段音频 codec，都被改写成“预测下一组离散单元”；统一的是训练接口，不代表四种信号的 tokenizer 完全相同。

④ UMRL / AHRL：对不会做的题给提示，但提示要随学习退场

ERNIE 的统一多模态 RL（UMRL）加入无偏 replay、多粒度 importance sampling 与 positive masking；Adaptive Hint-based RL（AHRL）在难例上按学习进度给提示。随着某样本通过率上升，提示概率指数下降，避免模型长期依赖答案线索。

phint(xt) = pinitial · exp(−γt · passinitialx)

白话翻译：一开始不会就多给脚手架；练得越久、原本越容易通过，提示退得越快。目标不是“带答案训练”，而是把难度调到模型刚好能探索出成功轨迹。

⑤ MiniMax / MiMo / Seed：同为原生多模态，注意力却没有统一答案

MiniMax M2 的技术报告曾测试混合 SWA，因长上下文退化而坚持全注意力；到 M3，规模增至 428B / 23B 激活、上下文 1M，并改用 MiniMax Sparse Attention，同时加入原生多模态与桌面电脑操作。MiMo V2.5 Pro 则用约 1.02T / 42B 激活、1M 上下文和 SWA/全注意力混合；其较小版本披露 70 层中 60 个 SWA、10 个全局层、窗口 128，理论注意力计算约为纯全注意力的七分之一。Seed 2.0/2.1 强调多模态生产力 Agent 与低延迟，但未公开参数和注意力结构，因此只能纳入产品路线，不能加入结构比较。

⑦ Claude Fable 5.1：同一模型用安全策略和缓存经济性切分产品

Fable 5.1 与 Mythos 5.1 是同一底层模型，差别在 safeguards 与访问范围：Fable 普遍可用，Mythos 面向获批的网络安全和生命科学用户。Fable 5.1 的 cache read 从每百万 token 1 美元降到 0.25 美元，Anthropic 按 8 月真实工作负载估计典型成本约降 25%、高度 Agent 化任务可降至约 45%。这反映了新的成本中心：长轨迹反复读取同一上下文时，cache read 价格可能比标称输入价更决定总成本。

⑧ Gemini 3.8 Flash / Cyber：同一核心智能按任务风险分流

9 月 2 日的 3.8 Flash 面向长程编码和自主 Agent，Cyber 版本则只向可信防守方开放；二者共享基础智能。官方给出 HLE‑Verified 54.9%，并强调较高 effort 会增加推理步数和工具调用；低 effort 或继续使用 3.7 则偏向成本优先。和 Claude 的 Fable/Mythos 类似，模型能力、推理预算和安全访问不再是三个独立开关，而是同一产品面的联合设计。

Ttask ≈ Nsteps·(Tmodel + Ttool) + Trework

白话翻译：长时 Agent 的总耗时不是一次回答速度，而是“每一步模型延迟 + 工具延迟”重复很多次，再加上失败返工；因此小幅可靠性提升可能比单次 token/s 更值钱。该式是任务成本分解，不是任何厂商的训练公式。

横向串讲：六家公司叙事背后的四条共同主线

把发布会语言拿掉，2026 的技术演进可以归并为四个系统变量：历史访问方式、环境内学习方式、每 token 激活预算，以及模态—动作闭环。它们互相制约：线性注意力节省的延迟可能被工具调用吞掉，Agent RL 得到的可靠性又可能大幅减少返工；因此单看参数、上下文或 benchmark 任一列都会失真。

主线一：别把所有“省注意力”都叫线性注意力

Full: O(L²)　|　SWA: O(L·w)　|　Content-sparse: O(L·k)　|　Recurrent/linear: O(L·dstate)

白话翻译：全注意力重看全部历史；SWA 只看固定邻域；内容稀疏按当前 query 挑 k 个远近位置；线性/递归方法把过去压进固定状态。它们的常数、训练并行度与硬件内核差别很大，复杂度符号不能直接换成真实速度。

主线二：RL 从“答案可验证”升级为“环境可运行”

2024–2025 的推理 RL 主要依赖数学、代码单元测试等可验证奖励；2026 的新难点是奖励稀疏、轨迹极长、工具会失败、环境本身还会变化。于是优化对象从一条答案变成整个 runtime：rollout 调度、沙箱快照、过期样本、策略合并和多 Agent 编排都进入算法边界。

三句总结

8 月的核心增量是“效率配方工程化”：Qwen 从骨干与优化器降算力，GLM 用同一基座放大后训练，Nemotron 把高频 Agent 执行压到 30B/3B 激活和单机部署。

真正的选型单位不是单次 token，也不是厂商榜单，而是固定 harness、预算和授权边界后，一项真实工作能否以可接受的总时延、总成本与失败率完成。
