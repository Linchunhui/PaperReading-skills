RealCompanion：长期记忆基准真正难的不是“找得到”，而是“知道何时该找”

基座模型 / LLMarXiv:2610.01780
为什么值得看：许多长期记忆评测把“已知需要回忆”的问题交给检索器，天然绕过最难的一步。RealCompanion 用真实产品中的十段长期人机关系记录，把检索触发、证据位置、回复生成和人格重建拆开测量，揭示一个反直觉结论：总体上近邻窗口几乎总能覆盖证据，但那是因为绝大多数消息根本不需要记忆。

出发点

旧基准多由合成事实、作者问题或均衡采样构成，模型既知道“这里有一道题”，也常被保证答案存在于上下文。真实对话中，只有 3.4% 的用户消息依赖更早内容；一旦真的依赖，证据中位数却在 2,157 条消息之前。于是总体召回率和自然发生率混在一起，会让只看最近消息的系统显得异常强。

方法拆解

10 段真实长期会话（27,218 条消息、最长 120 天） → 逐条建立可解析到原消息 ID 的 profile、persona、chat 与 QA 派生层 → 对每个 probe 判断是否需要跨窗口记忆、证据位于何处，再比较近期窗口、检索结果与“无上下文”控制 → 模型先做是否取用记忆的决策，再基于证据回复；另用三类 agent 流程重建人物档案 → 输出按关系分组的检测、检索、回复和 persona/profile F1。

关键证据：摘要与 Figure 2 的诊断显示，近期窗口在全部 probes 上覆盖所需消息 95.9%，但在真正需要远期记忆的 probes 上仅 2.2%；按自然频率计算，记录证据带来的收益中 96% 来自不需要记忆的消息。Section 4 的控制实验更说明“触发”是瓶颈：不给上下文时误触发率为 0；提供为 probe 挑选的消息后升至 29.2%，随机给十条则达 60.8%；仅把同样十条称为“memories”，各人群的记忆使用率就增加 10–14 个百分点。不同档案 agent 的 persona/profile F1 接近，却可有约 31 倍成本差。

边界与复现

十个关系来自同一移动 companion 产品，其中两段占全部消息 73%；因此分布不代表开放聊天，更不支持人口群体分析。为隐私发布的是经过重写且可核验引用的版本，原文和图片不可恢复；人格层是模型推断，不是临床量表或受试者自评。论文释放五类 JSON、机械校验与评分软件，便于复算，但复现实验仍依赖多种商业 agent。论文未提供足以隔离“检索器、提示框架与底座模型”各自贡献的消融证据。

Cross-Tokenizer OPD：覆盖更多 token 不等于得到更可靠的蒸馏监督

OPD / RLarXiv:2610.08448
为什么值得看：老师与学生 tokenizer 不同时，直觉是应尽可能恢复“多 token 对多 token”的对齐。论文却以三组异构模型证明：严格的一对一 token 位置已经覆盖绝大多数学生轨迹；把不匹配 span 也强行监督，不但没补足能力，反而持续伤害数学和代码性能。

出发点

旧方法常把字节边界相同但切分不同的一段 token 合并成 span，再匹配整段 log probability，以提升 alignment coverage。问题是 span 目标只约束一个联合标量，无法保证每个学生前缀上的老师条件分布可靠；而 OPD 恰恰需要在学生访问到的前缀上提供局部、低偏差的方向。

方法拆解

学生按当前策略生成回答 → 用字符/字节边界找出老师与学生都恰好是一枚 token 的严格位置，并在共享词表上取分布 → 训练只最小化这些位置的 reverse KL；可选的 span-MSE 只用于诊断，而不是主目标 → 为节省计算，让学生从共享词表中选 top-k，再在该子集归一化老师和学生分布 → 推理时只保留蒸馏后的学生 → 输出数学、代码或具身任务答案。

关键证据：Table 1 中，静态词表 Jaccard 仅 39.49%–64.87%，但学生生成 token 的严格覆盖率仍达 85.57%–96.98%。Table 2 的 Full 平均：Qwen→Llama 基座 26.96、严格 full 32.86；Granite→Phi 为 36.55→42.49；Granite→Qwen 为 29.56→47.35，均为最佳或并列最佳。Figure 2 的 18 个正 span 权重全部比只用严格位置低 0.27–1.20 个百分点。Figure 3 还显示共享词表在严格位置保留老师 99.69%–99.90%、学生 98.99%–99.81% 的概率质量。Figure 4–5 的诊断显示 span 梯度与严格目标余弦接近零或为负，且其相对范数随训练上升；相反 top-16 仍保留至少 96% 的完整蒸馏增益。

边界与复现

结果只覆盖三组 tokenizer、数学/代码与一个 ALFWorld 附录实验；若语言含复杂形态、字节回退或共享词表极小，严格位置可能不足。梯度分析来自 100 步、固定 512 prompts 的 replay，不能证明所有 span 目标都不可靠，只能否定本文的 log-probability MSE。训练设置和算法细节完整，但未提供独立项目页或代码仓库；因此数据处理与对齐实现仍需自行复刻。论文也没有验证教师更弱、架构差异更大、需要跨 token 复制专名的多语场景；“严格匹配优先”应被看作当前实验下的可靠基线，而非永久排除更好的结构化跨词表目标。

LoGRA：用低秩梯度草图把 27B 模型 RL 塞进单节点

OPD / RLarXiv:2610.06647
为什么值得看：大模型 RL 的瓶颈不只是 rollout，密集梯度、Adam 状态和训练—推理权重同步同样吃显存与带宽。LoGRA 不改模型为 LoRA，而是在每步反向时直接累积低秩梯度草图，并用同一草图完成优化器更新和策略同步，让全参数策略保留可训练性。

出发点

GaLore 一类方法仍可能先物化密集梯度，LoRA 则把策略限制在固定低秩参数子空间；分离的 rollout 引擎还需要频繁传整套权重。RL 更新又比监督学习更易出现偶发大步，简单压缩可能放大策略漂移。因此论文同时处理“梯度以什么形态存在”和“这一步到底走多远”。

方法拆解

on-policy 回答与可验证奖励 → 对每个权重矩阵采样低秩 Rademacher 基，反向时直接累积“梯度×基转置”的草图，不保存完整梯度 → RowAdam 在草图上维护优化器状态，再乘回基得到参数更新；同步时只发送小矩阵和随机种子，rollout 端重建同一更新 → predicted-KL 用候选 token 的 logit 变化估计策略漂移，并把步长缩放到预算内 → 输出更新后的全参数策略。

关键证据：Table 1 中，7B 平均显存从 Dense Adam 的 31.82 GiB/GPU 降至 17.29 GiB，节省 45.7%，MATH-500 Pass@1/4 为 72.33/85.13；27B 的 Dense 在首次 Adam 状态分配时 OOM，LoGRA 为 51.54 GiB、Pass@1/4 71.52/81.87。Figure 4 的单条 27B 长训练超过 1,100 步，held-out verifier 从 39.7% 升至 62.9%，截断率 34.7%→13.0%。Figure 5 消融显示 rank 4/16/64/256 的 Pass@1 大致落在 67.4%–68.5%，刷新随机基优于固定基；Figure 6 中 conservative annealed KL 的尾段准确率 71.47%，无 KL 控制为 70.30%。Table 2 与 LoRA 对照时，LoGRA 平均显存 7.18 GiB 对 13.21 GiB，Pass@4 81.80 对 81.40，但每步训练 11.31 s 对 10.63 s，说明优势主要是容量而不是纯速度。

边界与复现

主要实验是数学推理、Qwen 1.5B–27B、单个 8×H100 节点；尚未验证多节点、MoE、长工具轨迹或更复杂 RL 算法。predicted-KL 是局部二阶近似，实际 KL 可偏离；27B 只有一条长期训练轨迹，稳定性结论弱于小模型三种子结果。rank、基分布和刷新频率之间仍需按任务调参，论文没有给出跨模型自动选择规则。论文明确把生成显存排除在训练显存统计之外，且同步收益依赖训练器与 rollout 分离的系统形态，端到端总成本仍需单独核算。代码已并入 Molt 的 LoGRA 分支，但复现实验仍需 8 张 80GB GPU 及自建 rollout/同步环境。

MotorMind：不训练 VLA，用通用 VLM + 执行脚手架直接控机器人

VLAarXiv:2609.38078
为什么值得看：这是一条与端到端 VLA 正交的路线：冻结通用 VLM，只让它输出短序列的中层动作，再由确定性控制器执行；规划、监控、验证和记忆各自扮演清晰角色。它证明在无任务专训、无 action expert、无运动规划器的条件下，系统工程也能把通用视觉语言能力转成强零样本操控。

出发点

端到端 VLA 需要大量机器人轨迹，跨本体和新任务迁移仍昂贵；普通 VLM agent 若直接生成底层轨迹，控制频率、几何约束和错误恢复又不可靠。旧式顺序 agent 还会在每次视觉检查时阻塞执行。MotorMind 选择一个中间粒度：VLM 决策“移动、旋转、夹爪”等参数化动作，控制器保证动作可执行。

方法拆解

相机图像、任务指令与机器人测量 → Planner 拆分子目标，Executor 让同一冻结 VLM 生成中层动作；确定性 controller 校验并转成伺服命令 → Monitor 与 Memory 在动作执行时异步运行，Verifier 用新观测和测量判断子目标是否成立；失败时局部重规划，成功才推进 ledger → 只替换 adapter 即可从 LIBERO 的 Franka 切换到真实 xArm6 → 输出闭环动作序列与可追踪执行记录。

关键证据：Table 3 中，MotorMind 在 LIBERO-PRO base 平均成功率 66.7%，扰动套件 53.8%；论文评测的最强既有零样本方法分别不超过 13.3% 与 19.2%。真实 xArm6 放置任务平均 95%。核心组件消融更有说服力：Section 6 去掉 replanning 后 base 从 66.7% 降至 36.7%，去掉 verifier 为 60.0%。Table 15 的预算诊断则显示，300 s 与默认 450 s 都是 66.7%，但平均时长 159.8 s 对 210.0 s；延长到 900 s 反而降至 50.0%，说明成功来自闭环结构，不是单纯“多给时间”。

边界与复现

系统仍依赖对象框、深度和机器人标定等接口信息，base-weight VLA 对照也使用 LIBERO 归一化统计，不能把结果理解为完全零先验。任务成功用环境 predicate 判定；项目页还揭示 300 个 episode 中 71 次“任务已完成”声明全部错误，说明高层终止判断仍脆弱。真实机器人任务数量有限，商用 VLM 的成本与延迟差异也显著。代码、LIBERO-PRO、动态任务和 xArm6 adapter 已公开，复现性较好，但真实部署需要硬件标定和安全边界。

STEPQuant：Delta-rule 模型的状态量化，要同时回答“错误活多久”和“落在哪”

基座模型 / LLMarXiv:2609.38169
为什么值得看：线性注意力把 KV cache 换成固定尺寸递归状态，但状态错误会在每一步更新里继续传播，均匀 INT8 都可能重伤推理。STEPQuant 不把所有状态值同等压缩，而是按门控衰减估计错误寿命，再按 key 行和 value 列对读出影响做双轴拟合，使 4–6 bit 状态仍接近 FP32。

出发点

普通 PTQ 假设误差局部影响一次矩阵乘法；Delta-rule/KDA 状态会不断被读写，同一误差的持续时间随 gate 不同，空间位置的重要性也由 key 与 value 的联合结构决定。仅按通道 scale 或静态离群值分配 bit，无法识别“数值不大但会活很久”的状态单元，也忽略 key 行对后续 readout 的放大。

方法拆解

少量校准序列与每层递归状态 → Temporal 模块用 gate decay 估计量化误差的有效寿命，按风险分配混合精度，并保留少数 FP16 pivot → Spatial 模块对 key 行与 value 列分别拟合 scale，让高读出影响的行优先 → 校准结果一次生成，运行时用 SGLang/Triton 打包状态并异步写回 → 每个 token 仍执行原 Delta-rule 更新，只在持久状态读写处量化/反量化 → 输出与原模型相同的 logits。

关键证据：Table 1 的七项长生成平均，Qwen3.8-27B FP32 为 80.60，均匀 INT8 71.86、INT4 12.73；STEPQuant@6/4bit 为 80.59/80.51。Kimi-Linear 对应 61.52、56.02、21.63 与 61.47/58.52。Table 4 的组件消融尤其清楚：Qwen 4-bit 三任务平均，Spatial only 73.95、Temporal only 12.87、Temporal 去 pivots 6.17，完整 STEPQuant 84.72，甚至略高于 FP32 84.61；说明两轴互补且 FP16 pivots 必要。Table 3 与 W4/AWQ 权重组合时，Qwen 的 6-bit 状态七任务平均 79.27，只比 FP32 状态 79.32 低 0.05。系统侧 6-bit 状态压缩 5.03×/5.08×，W4 场景总显存最多降 68.7%/53.7%。

边界与复现

寿命权重只是用 gate decay 近似误差持续性，没有完整建模随时间、随 key 变化的状态转移；KDA 在 BF16 权重、4-bit 状态的长生成仍掉点，Qwen 虽保持平均分却会生成更长输出。实验只覆盖两个 GDN/KDA 模型、固定 A800 与特定 serving workload，动态并发和其他线性注意力架构尚未验证；名义 4/6 bit 还包含 scale 与 FP16 pivot 开销。校准分布若与实际长对话、代码或多轮 agent 流量不一致，bit 分配是否稳健尚无压力测试；吞吐结果也不能直接外推到调度器频繁换 batch 的生产环境，跨卡通信与抢占式服务同样没有覆盖。代码、配置、复现指南和 SGLang kernel 已公开，但官方 Qwen 示例需要四张 GPU 与模型权重。

Recursive Self-Rewrite：先让多种 Agent 脚手架探索，再把成功轨迹“重写成可学习经验”

基座模型 / LLMarXiv:2610.02826
为什么值得看：Agent 训练常直接拿成功轨迹做 SFT，但轨迹里会混有死循环、冗余试探和 harness 专属指令。论文把“发现解法”和“生产训练样本”分开：三种互补 harness 负责扩大成功覆盖，再由 planner/critic/executor 递归地把原始轨迹压成通用 runbook 并在新沙箱复演。

出发点

单一 harness 只暴露一种问题求解风格，成功集有结构性盲区；而 raw trajectory 的每一步并不都值得模仿。直接 SFT 甚至可能强化卡死和绕路行为。关键不是简单增加 rollout 数，而是让不同执行机制找到互补成功，再验证性地改写成不泄露 verifier、不抄最终答案、能在通用终端接口复现的轨迹。

方法拆解

约 3,000 个复杂终端任务 → Terminus 2、Recursive Self-Reflect Terminus、StateM 分别探索；只保留至少一次通过 verifier 的任务 → Planner 从成功/失败尝试抽取无答案泄漏的 runbook，Critic 检查 verifier 信息与具体解法泄漏，不合格则递归改写 → Executor 在全新 sandbox 按 runbook 重新完成任务，验证后转成统一 harness 轨迹 → 用这些轨迹 SFT 同一 Qwen3.8-27B → 输出更通用的终端 Agent。

关键证据：Table 1 中，三 harness 并集解决 759 个任务，其中 288 个只被一种 harness 解出；相对最强单 harness，覆盖增 34.3%。2,001 条源轨迹最终扩成 11,094 条重写轨迹。Table 5 上，Base/Direct SFT/RSR 的 TB2 pass@3 为 57.0/53.4/74.2，TB4 为 1.5/4.5/9.1，TBH 为 39.0/56.0/63.0，SWR100 为 3.0/3.0/6.0；LHTB process reward 为 0.21/0.25/0.29，但三者都未完成 46 个任务中的任何一个。Table 6 的 harness 消融也显示同一 base 在 TB2 最好 StateM 58.4，而 TBH 最好 RSRT 66.0，互补性确实存在。

边界与复现

Direct SFT 与 RSR 同时改变了样本数量、轨迹形式和验证强度，现有实验不能完全隔离“重写质量”与“数据扩增”的贡献；Table 6 只各跑一次，harness 差异缺少方差。发现阶段只要求至少一次通过，可能偏向偶然成功；critic 是否会系统性丢掉不熟悉但有效的策略也未评估，递归重写还会显著增加生成与沙箱成本，成本收益尚未量化。LHTB 的改进全部来自部分进度而非完成，长时程能力仍很弱。自建 TBH/SWR100 的外部可比性有限。论文未给出独立项目页或代码仓库，使用的沙箱、重写提示和完整数据也未全部发布，因此目前只能按论文流程复现，难以逐项核对。

ProWAM：先一次性画出稀疏视觉路标，再沿路标闭环出动作

VLA世界模型arXiv:2610.02508
为什么值得看：显式视频世界模型把算力花在完整未来生成，纯动作模型又缺少可解释的长程结构。ProWAM 折中为“progress-indexed sparse sub-goals”：从初始观测和语言一次预测数个关键未来状态，把它们的特征缓存给轻量动作去噪器，不需要逐步解码整段视频。

出发点

现有 WAM 常只预测单一终点或固定短 horizon，复杂操作中无法表达“先抓、再移动、再放置”的阶段结构；多步视频滚动又产生高延迟和误差累积。普通 VLA 在视觉分布变化时容易依赖表面纹理。论文希望把无动作视频预训练获得的动态先验压成少量、按任务进度排列的视觉锚点。

方法拆解

初始多视角观测 + 语言指令 + 预设 progress 值 → 视频 backbone 先用无动作视频做预训练，WAM 阶段联合预测 K 个未来视觉 sub-goal latent → 单次 video-expert 前向产生全部 sub-goal，并缓存其 key/value 特征；无需把每个 latent 完整解码成像素 → 轻量 action expert 在闭环中读取当前观测、语言和缓存路标，以去噪目标生成 action chunk → 输出连续机器人动作。

关键证据：Table 1 中，ProWAM 在 LIBERO 为 85.8%，在严格零样本 LIBERO-Plus 为 75.7%，后者超过 MV-WAM 的 55.7% 达 20.0 点；不做视频预训练的 ProWAM-Base 为 67.4%，而 clean 反而略高 87.6%，说明预训练主要贡献是 OOD 稳健性。Figure 4(b) 的 sub-goal 数消融：K=1/2/3 的随机场景成功率约 73.8/73.7/73.7，K=4 为 75.7，clean 从 84.7/84.6/84.9 到 85.8。效率—性能图还显示方法不需完整视频滚动即可位于较低 TFLOPs、高 OOD 成功率区域。RoboCasa365 Table 3 总体 48.1、Composite-Unseen 18.2；真实机器人平均 70.0%，最佳基线 55.0%。

边界与复现

推理时 K 和 progress schedule 仍是人工指定，不会根据任务难度或现场进度自适应；Figure 3 的 cube stacking 失败显示接触几何模糊时，视觉路标仍可能导致过早松爪。缓存路标在闭环执行期间是否需要重算、错误路标如何被在线纠正，论文也没有完整消融。LIBERO 域内接近饱和，许多选择只能在 RoboTwin 上区分；RoboCasa365 未见组合仍只有 18.2%，长程组合远未解决。项目主页公开结果与演示，但论文未给出完整官方代码仓库链接；外部复现仍缺训练脚本、预训练视频配方和 checkpoint。

Long-WAM：让世界动作模型真正使用 19.2 秒历史，同时维持实时控制

VLA世界模型arXiv:2610.10528
为什么值得看：机器人需要历史来判断速度、进度和失败，但“把更多帧塞进模型”未必有效，还会拖慢动作。Long-WAM 的核心结论是：只有经过自回归视频预训练、并在适配时保留“历史→未来”因果结构，长上下文才会稳定转化为控制收益；系统侧再用流式编码和异步执行消化延迟。

出发点

单帧 VLA 看不出运动方向，短上下文也会丢失长任务进度；但双向视频模型习惯同时看前后文，直接改成控制模型后未必会利用更长历史。显式世界模型又需要生成未来视频，实时性不足。论文把问题拆为表示与系统两层：先学因果视频预测，再让 action expert 只读部分去噪的未来 latent，不解码像素。

方法拆解

最多 19.2 秒（扩展实验 38.4 秒）的观测历史 + 指令 → Video expert 从约 10,000 window-equivalent 小时机器人/第一视角视频做自回归 next-chunk 预训练 → WAM 适配保持不对称注意力：视频 query 不读动作，动作 query 同时读历史、部分去噪未来 latent 和 action chunk → 推理先预测未来 latent，再去噪动作；流式 VAE、KV 复用、NVFP4、CUDA Graph 与纯异步执行重叠计算 → 输出实时 action chunk。

关键证据：Figure 6 与 Table 4：RoboCasa GR-1 的 AR robot-video 初始化从 2.4 s 扩到 19.2 s，成功率 66.3%→78.7%；通用 AR 初始化为 65.7%→76.7%，双向初始化则没有净增益。LIBERO-Long 只加 2.4 s 就从 94.5%→99.5%。Table 3 的 DOMINO 动态微调后，Long-WAM SR 34.9、MS 45.1，强于 Fast-WAM 的 19.9/33.3。真实动态杯子堆叠 19/20，而 π0.5 与 Fast-WAM 都是 0/20；RTX 5090 完整视频后动作链为 107.4 ms/chunk。异步执行在 RoboTwin 保持 94.2%，同步为 94.4%，说明延迟隐藏几乎不损失控制质量。反诊断也很重要：38.4 s 时 GR-1 降至 75.2%，其中 80.4% 历史帧是 padding。

边界与复现

每个上下文长度分别训练，不能把收益解释为同一模型在推理时无缝伸缩；19.2 s 相对 2.4 s 的 RTX 5090 延迟由 107.4 增至 341.0 ms，长历史仍有价格。38.4 s 下跌主要被归因于训练轨迹平均仅 12.1 s，但这还是假设，不是记忆上限的严格证明。对 composite task 的高分还依赖 GPT-6 Astra 外部规划，不能归因于 WAM 单体；例如 RoboCasa365 总体由 31.4 升至 54.4。真实实验集中于两种本体和有限任务，10,000 小时视频预训练也难以低成本复现。项目页已发布演示与详细数值，代码/模型入口已列出但完整训练资产的可获得性仍需按项目发布状态核验。
