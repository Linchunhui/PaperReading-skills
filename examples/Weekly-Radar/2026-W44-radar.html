InteractiveWorld: A Verifiable Human-Centric Environment for Building Better Interactive MLLM Assistants

HF 2026-10-27 · 首次提交 2026-10-25 · 解读 v1 · 论文原文 · PDF · HF 候选

问题签名　人类执行的视觉协助 / 多轮环境变化 / 静态问答掩盖跟踪与沟通错误 / 用可验证状态测任务完成
多模态助手；闭环评测；第一视角；状态验证

背景与前作缺口

穿戴式助手看到用户眼前的画面，给出文字建议，由用户动手执行。一次识别正确仍可能因指令含糊、忘掉已完成动作或未发现执行偏差而失败；任务需要反复观察和调整。

静态 VQA 不会改变下一张图，直接输出机器人动作的评测又绕过了人与助手之间的沟通。本文要测的是视觉语言建议如何经由执行者改变环境，最终是否帮助完成任务。

解决思路

分离 Assistant、Human executor 和可验证的模拟环境。助手只通过自然语言影响执行者；评估依赖物体状态、动作先后与干预时机，而非语言 judge 的总体印象。

从输入到输出

  1. InteractiveWorld 的物理层维护人体、物体与碰撞，动作层把走路、抓取等高层请求落实成稳定动作，语义层将自由语言指导落到可执行动作序列。输入包括任务目标、第一视角帧与交互历史；Human 执行动作后，环境更新，助手接收新画面继续指导。
  2. InteractiveBench 有六类各 20 个、合计 120 个任务：Guidance、Planning、Accessibility、Decision、Prevention、Finding。测试前用仿真回放、人工审查和 Oracle/无助手对照确认任务可执行；Accessibility 还对 Human 屏蔽视觉，落实信息边界。
  3. 这是一项环境与评测工作，不训练新助手。每轮保存动作与状态收据，最后检查全部目标是否完成（Pass）及目标完成比例（MCR）；九类能力另有检查点，失败分析定位最早错误，动作成本仅在该模型成功的任务上相对 Oracle 计算。

主结果与比较条件

Table2 中 Claude Fable5.1 的总体 Pass 为 41.7%、MCR 54.8%，其余模型 Pass 不超过 33.3%。同一执行协议下 Oracle 助手可达 100%、无助手为 0%；Fable 在 Decision 为 85.0%，Guidance/Planning 只有 20.0%/25.0%，显示单场景判断与持续协助之间的差距。Figure4 的首错分析中，视觉与记忆错误占各模型首错的 70.4–85.7%；这描述最早断点，并不排除后续沟通错误。

消融与分析结论

Figure5 加入仅供后续轮使用的 Memory 字段，Fable 的 Prevention/Finding 从 50/40 到 55/50，但 Planning 从 25 到 20；GPT-5.6-sol 的 Prevention/Finding 从 15/25 到 30/40，Planning 同样下降 5 点，简单记忆并非全面改善。Appendix D/Table14 还在同一 36-task 子集比较四个模型执行者与三名真人：Fable 的模型执行者完成 13–15 个，真人完成 15、16、15 个。强弱总体模式保持，中间模型排序会变；真人是在模拟器内执行，不是现实部署研究。

代价与适用边界

任务来自有限模拟场景，固定执行者提示与已审查任务会约束行为分布。真人校准已做但只有三人、同一子集，不能据此宣称模拟用户等同真实用户；不同模型成功任务上的效率均值也不宜直接作同任务比较。

带条件总结

InteractiveWorld 最值得复用的是“指导—执行—观察—核验”的评测链与首错定位。面向人的视觉助手需要同时报告完成率和用户付出的动作成本；静态回答强、加一个记忆字段，都不足以证明闭环可靠性。

核验范围：已核对任务结构、主表、记忆诊断、信息边界与真人 executor 校准；纠正旧稿未做真人研究的暗示。

ChronoReplay: One Answer Interface Is Not Enough for Streaming Spatial Intelligence

HF 2026-10-28 · 首次提交 2026-10-25 · 解读 v1 · 论文原文 · PDF · HF 候选

问题签名　连续视觉流 / 多种空间问答接口 / 单接口训练偏科 / 同一模型保持跨接口能力
流式空间理解；因果历史；原生答案接口；任务族损失

背景与前作缺口

机器人走过一间房后，可能被问“镜子在左还是右”“离沙发多远”“何时经过植物”。三个问题共享经历，却分别要输出类别、带单位的数值与时间。单图空间训练和更大的记忆模块，都没有自动解决这几种读出之间的迁移。

作者把只对某种回答接口进步、对其他接口持平或退步的现象称为 interface lock-in。另一个缺口是历史依赖：同样向前走一步，从不同朝向出发会得到不同位置。若把多轮轨迹拆散，目标答案就可能脱离产生它的合法前缀。

解决思路

在数据与目标函数上保留空间状态所需的信息：答案沿用源任务的含义和精度，多轮样本按真实时间组成因果历史，再显式平衡类别保持与轨迹学习两族监督。这里没有新增记忆网络。

从输入到输出

  1. 先把观察、问题、原答案及接口标记放回源 episode 的时间轴。第 j 轮输入只包含截至该轮可见的图像和前序问答，后来的帧不能泄漏；数字保留单位、符号与精度，类别题保留候选语义，时间题保留时间戳。输出仍由原有自回归解码器生成。
  2. 每个答案先按 token 数归一化，轨迹族再按有效监督轮聚合；与保持族的风险分别归一化后混合。α=0.5 对应轨迹在两族总目标中占 1/3，避免长答案或样本较多的一族主导梯度。Qwen3-VL-8B-Instruct 训练一轮，更新语言模型和视觉 merger，冻结视觉编码器。
  3. 推理时同一 checkpoint 回答各接口问题。主对照固定观测访问；另外的 adaptive frame selection 是独立推理改动，会改变提供给模型的证据与视觉成本，不能与训练收益混成一个数字。

主结果与比较条件

Tables1–4 在同观测访问、场景分离协议下，OVO-S / OST / UCS 从 48.98 / 50.52 / 45.33 到 53.89 / 63.93 / 52.77，三项均值从 48.28 到 56.86。OST 保留全部题型但排除与训练重叠的场景，因此不能把不同公开协议的其他模型行当成严格同条件排名。OVO-S 的 57.98 属于额外 adaptive access，不能称为三基准均值。

消融与分析结论

顺序确实有用，但格式并非全面越原生越好。Appendix D.5/Table12 的两组成对种子中，chronological OST 为 63.93、64.52，循环移位为 61.51、62.11；保留局部样本和权重，但改变了目标前面的累积上下文。D.4 的同数据、可逆 JSON 序列化对照中，Native 的 OST/UCS 为 63.24/54.26，Canonical 为 64.72/51.34，呈交叉变化。Table10 的三组配对种子显示，显式族平衡相对自然轮权重，在 OVO-S、OST、UCS 各基准上的平均增益分别为 0.92±0.27、1.43±0.19、1.17±0.25 点（跨种子的均值±样本标准差）；单族实验因数据覆盖不同，只能诊断偏科，不能隔离格式因果。

代价与适用边界

主体结果来自单一 8B 骨干，headline 使用一个种子；部分关键控制另有配对重复。该工作研究跨接口空间监督的迁移，不是证明任意在线持续学习系统都不遗忘。

带条件总结

ChronoReplay 的可借鉴处是先检查训练是否保留了任务真正依赖的历史和读出，再增加模型复杂度。若空间答案依赖累计状态且多接口都要服务，因果前缀和族平衡有直接证据；格式与取帧策略仍需逐任务验证。

核验范围：已核对方法、场景分离协议、主表与顺序/格式/权重控制；不把公开异协议参考行当成同条件胜出。

The Trinity

The Trinity: Capability-Driven Recursive Self-Improvement for Multimodal Agents

HF 2026-10-28 · 首次提交 2026-10-26 · 解读 v1 · 论文原文 · PDF · HF 候选

问题签名　异构多模态任务 / 可验证交互 / 每任务单独维护流程成本高 / 按共享能力生成课程并复用模块
通用多模态交互；能力树；环境生成；Harness 演化

背景与前作缺口

看视频找证据、追踪迷宫状态、处理机器人任务，表面接口不同，却可能共享状态跟踪或约束检查能力。为每个任务各写一套 Agent 工作流会重复劳动，而一个全局工作流又难兼顾互相冲突的要求。

自动自改进同时受限于可验证环境的构造成本和可复用改进的组织方式。把任务按表面类别拆开，可能得到专用技巧，却难说明何种能力可以迁移。

解决思路

固定多模态骨干权重，改变其外围控制流程（Harness）。Evolver 从训练轨迹归纳共享能力，Creator 建立简化但可验证的训练世界，Explorer 沿能力树复用和改进模块；因此本篇不是神经网络 RL 优化算法。

从输入到输出

  1. 先固定训练/未见分割，统一任务的目标、可见观察、动作、反馈和预算。Explorer 用初始 Harness 收集训练轨迹；Evolver 依据任务规则与成功/失败证据归纳需求，经独立提案、判定与审核形成能力集合。按预先固定的能力顺序建立前缀树，共享前缀复用相同能力；顺序不表示因果先后。
  2. Creator 根据节点共同需求构造简化世界，验证执行与评分后形成课程；原任务用于检验迁移。Explorer 在节点上保留本地模块，比较是否继承新父模块；仅父模块替换要求同任务、同预算的严格更高验证分数，本地模块则通过接口和证据约束接纳，不能笼统说所有更新都要求分数上涨。
  3. 多轮中复用环境、更新局部模块，Creator 合并去重其经过验证的构造模块。推理时 Router 根据公开目标、初始观察和已验证历史，从固定版本的 Harness 池选分支；未见任务的隐藏能力标签不参与选择。完成后写入可核验结果，供后续路由检索。另有评估前技能准备，因此最终表现是模块与技能配置的合成效果。

主结果与比较条件

§4.3/Figure6 的固定树、固定骨干、四轮 RSI 中，28 个 Train 基准均值从 39.1 到 73.2；16 个非机器人 Unseen 基准从 42.1 到 64.1。摘要对包含两个机器人任务的 18 个未见基准给出约 +26 点，聚合范围与该图不同，不能混用。Table6 两个真实机器人任务最终各为 60%，属于带技能准备的完整配置结果，并未隔离模块演化贡献。

消融与分析结论

Table4 的 Train/Unseen 路由诊断：随机分支 52.74/46.23，只读任务信息 65.79/52.36，加入能力定义与检索经验为 71.27/60.96，事后 Oracle 为 73.16/63.61。它说明选择兼容分支有价值。Table3 的 module-only 对照将 flat Capability-Domain 49.25/39.43 提高到真实任务能力树 53.44/42.31，再用模拟课程到 56.95/47.26；首次构造成本也从 Real 的 211.56M token 到 Sim 的 405.70M，不能只写更省。

代价与适用边界

能力定义和审核包含人为选择，固定能力排序未给敏感性控制。基准间度量归一到 0–100 后均匀平均，不代表统一物理量；原任务技能准备、课程生成与模块更新也增加总预算。

带条件总结

Trinity 的贡献是让可验证的多模态交互经验按能力结构复用。任务确有共享需求、模拟世界能保持关键约束时，这种组织可能减少重复迭代；它不证明冻结模型已经获得新的参数内能力，也不保证自动演化的每个局部步骤单调进步。

核验范围：已核对冻结骨干、能力树构造、模块继承与路由、主结果聚合范围和代价；按通用多模态交互归类，移除旧 RL 标签。

LOWN

Look Only When Needed: Certificate-Guided Visual Routing for Efficient Diffusion VLMs

HF 2026-10-30 · 首次提交 2026-10-27 · 解读 v1 · 论文原文 · PDF · HF 候选

问题签名　图像问答 / 迭代文本去噪 / 每步重复处理图像 / 用预测一致性路由图像访问
VLM；文本扩散；自适应看图；无训练加速

背景与前作缺口

扩散 VLM 在生成回答时多次处理固定图像。回答一旦形成部分上下文，许多词可以由语言上下文决定，但细粒度读图词仍可能必须重新查看视觉证据。

永久裁剪视觉 token 可能丢掉后续才需要的细节；固定每几步看一次图也不适合不同问题。本文研究的对象是生成文本的扩散 VLM，效率来自决定何时访问图像。

解决思路

保存最近一次看图预测作为锚点，用便宜的纯文本前向检查当前预测是否仍与锚点一致；一致的连续候选足够多就直接提交，否则刷新看图预测。

从输入到输出

  1. 完整前向读取图像、提示与部分掩码回答，保留仍被掩码位置的预测及置信度。每一步再做去掉视觉 token、保留位置编号的纯文本前向，按锚点置信度排序，取预测一致且通过重复保护的最长前缀。
  2. 若一致前缀至少达到基线每步提交数 k，就提交整个前缀的锚点预测，跳过完整前向；不足 k 时重新看图、替换全部锚点，并优先提交纯文本与视觉预测有分歧的位置，再补足 k。
  3. 该推理算法不更新参数，也不永久丢弃图像。每步至少推进 k 个 token，但纯文本前向本身仍有成本；节省由完整前向次数、总步数和视觉 token 占比共同决定。

Table1 的 LLaDA-V、batch1、贪心、无 KV 缓存、十基准设置中，平均解码 FLOPs 为基线 0.353 倍，任务归一化分数保留 99.6%；把高于基线的分项截到 100% 后是 98.6%。例如 DocVQA 83.91→82.31、MathVista 59.10→56.00。Table2 加在 Fast-dLLM 之上还降时延 38.1–50.1%，但 LLaVA-Bench 分数从 63.00 降至 58.00。

Table4 在匹配平均完整前向次数的随机访问下，MathVista 53.40 对 LOWN 56.00，DeCapBench 30.48 对 34.43，说明时机优于随意跳步。Table5 只路由图像已减少 27–68% FLOPs，自适应提交再减少剩余成本的 21–43%。§5.3 直接审计证书：在自身轨迹上，2.2–4.7% 的纯文本提交仍会被新完整前向推翻；一阶旧锚点不是数学正确性保证。

文档与图表依赖持续视觉证据，节省相对较小；锚点越旧错误风险越高。成本依赖实际轨迹，无法在解码前固定预算。论文名中的 certificate 指经验一致性检验，不能当正确答案证明。

LOWN 将视觉访问作为独立可调的推理资源，在所测扩散 VLM 上以少量质量损失换取显著计算节省。适合先按任务审计失误和延迟，尤其不能把平均分保持等同于每个读字问题无损。

背景与前作缺口

一张文档的文字、公式和表格，不只要求回答大意，还要求输出顺序、位置与符号正确。扩展到音频和视频后，分别维护感知塔与输出约定，会增加模型与数据接口的复杂度。

解决思路

用一个共享感知 Transformer 接收不同模态，经统一结构化 schema 输出；后训练将格式与内容分开监督，让学生在自身生成前缀上从看过参考解析的教师获得局部反馈。

从输入到输出

  3. 内容位置使用 JS 反馈，键与分隔符等结构位置使用前向 KL，并做角色归一化；教师不获得学生将来输出。轮内只更新学生 LoRA，轮末合并权重并刷新模型，持续六轮。这里的自演化仍依赖参考解析，不是无数据自学。

HF 2026-10-26 · 首次提交 2026-10-14 · 解读 v1 · 论文原文 · PDF · HF 候选

问题签名　推理后训练 / 可靠反馈与显存约束 / 自教师目标漂移 / 保存历史输出而非常驻教师参数
策略优化；有验证反馈的自蒸馏；稀疏分布缓存

背景与前作缺口

只有“答对或答错”的奖励，很难告诉语言模型哪一个局部选择该改。自蒸馏让同一模型看过更强证据后给出逐 token 指导，但模型更新后，教师观点也同步变化；保存 EMA 教师又增加一整份参数。

当前特权视图能提供密集监督，却没有跨更新的稳定锚点。只重放成功答案会丢掉分布信息，长期只跟随自生成证据还会强化错误；需要同时解决目标稳定性、参考可靠性与缓存覆盖。

解决思路

把历史教师保存在函数空间：记录它在选定前缀上的稀疏 next-token 概率及尾部质量，作为暂时固定的目标。当前适应、历史巩固和可靠参考共同更新同一个 policy。

从输入到输出

  1. 每题生成一组回答，用 verifier 打分。给当前失败轨迹选示范时，优先使用另一个已验证成功的 sibling，其次用缓存里的可靠轨迹，最后回退到参考答案。同一参数模型分别在原问题和“问题＋示范”下评估同一回答前缀，特权侧停止梯度。
  2. 在学生 top-K token 加一个尾部概率桶上匹配 Jensen–Shannon 分布；对于学生相对特权视图过度偏好的 token，额外压低其概率。高分且结构互补的轨迹进入缓存，保存历史特权分布而非模型参数；重放时用原问题预测，与固定历史目标匹配。目标经延迟、分批刷新，避免每步都追着当前模型移动。
  3. 滚动成功率低的题加强参考答案交叉熵，可靠自监督形成后减弱。每个周期先偏当前适应、再增加历史巩固权重；优化直接更新共享 policy，生成也复用这套参数。部署只需正常模型生成，缓存和特权答案是训练机制，不是推理时已知答案。

主结果与比较条件

Table1 在四张 GH200、五个科学推理/工具任务、五小时训练窗口内报告最优 avg@16：Qwen3-8B 的跨任务 Avg@5h 为 76.2，对 SDPO 72.0；Olmo3-7B 为 72.4，对 SDPO 68.0。Qwen 的 Tool Use 五小时与 SDPO 同为 68.5，且一小时工具任务 SDPO 更强，不能写成全时段全任务胜出。Figure6 的作者显存核算约为 56GB 对带额外参数副本的 70GB；这是所用实现与核算条件的差异。

消融与分析结论

Table2 在 Olmo3-7B 的 Biology/Tool Use 上，完整平均 64.5%；去历史项为 60.1%，只保留当前蒸馏为 56.0%，去参考 grounding 为 61.7%。当历史和参考同时去掉、仍保留局部负修正时反降到 54.1%，说明纠错依赖稳定锚点。函数缓存 64.5% 对 EMA(0.99) 63.2%、参数快照 58.8%；反转周期为先巩固后适应则为 59.7%。这些分别改变目标、缓存或调度的控制，比主表均值更能解释设计。

代价与适用边界

两种 7–8B 骨干、五类任务与 best-within-window 指标仍是有限范围；基线数值沿用 SDPO 设置而非本轮独立复现。6T 参数省约 12TB 是参数副本会计外推，不是实机验证。方法需要可靠 verifier、参考与缓存管理，不能称为无数据自学。

带条件总结

FSPO 将历史正则的存储对象从模型参数改成带前缀的输出分布。可靠成功样本与参考可得时，它能在所测设置中兼顾适应、能力保持和显存；若反馈系统有偏，稀疏缓存也会固化偏差，需同时审计内容与覆盖。

问题签名　工具交互轨迹 / 只有终局奖励 / token 与环境决策尺度错位 / 按轮传播信用并保留局部差异
长时程 Agent RL；优势估计；turn 级重要性采样

背景与前作缺口

浏览 Agent 一次发出完整搜索或工具调用后，环境才返回新观察；模型内部却逐 token 生成这次调用。学习终局成功奖励时，必须同时回答哪一轮有帮助、这一轮里的哪些 token 有帮助。

GRPO 一类序列共享优势难以区分各轮贡献；纯 token 级 GAE 又把远期信用经过大量轮内位置传播。作者在一个搜索训练运行中观察到，turn 间均值差占轨迹内 critic 方差的中位数为 89.5%，但这只是结构诊断，不能推广为所有任务的定律。

解决思路

把完整 assistant turn 作为环境宏动作，先沿 turn 边界分配长期信用，再用去均值的轮内信号细化 token。策略更新的概率比也采用同一个完整 turn，同时用停止梯度保留每个 token 的独立信用。

从输入到输出

  1. 采样完整交互轨迹，只在末尾得到任务奖励。单个 critic 在各 token 前缀估值；把一轮内 TD 残差求和后，中间值抵消，只剩轮首、下一轮首和可能的终局奖励。对这个轮级残差做 GAE，使衰减每次交互发生一次，而不是每生成一个词发生一次。
  2. 在每轮内部另算受限的 TD trace，减去该轮平均，再乘 β 加到轮级优势上。这样同一轮各 token 的均值仍等于轮级信用，同时可以奖励关键参数、惩罚局部错误。β=0 就退化为整轮广播。
  3. 更新时完整轮概率比确实是各 token 比率的乘积。对当前 token 求梯度时，其余 token 比率停止梯度，因此每个 token 的前向权重和裁剪仍是完整轮比率，反向却乘自身 MAE 优势；这避免局部去均值项在共享求导中抵消。critic 以 λcritic=1 回归终局回报；部署照常生成与调用工具，不运行优势估计。
At,iMAE=Atturn+β(At,iintra−Atintra¯)

白话解释：t 是交互轮，i 是轮内 token。右侧第一项规定整轮的平均信用；括号把轮内 trace 去均值，再由 β 控制差异强度。因此局部信用可以不同，但不会偷偷改变该轮整体信用。对应原论文 Eq.20，批归一化前成立。

Table1 的 Qwen3-4B-Thinking 在 BrowseComp-Plus / GAIA / HLE 的 pass@1 为 48.08 / 39.47 / 9.92，相对各列最强非 MPO 基线提高 4.33 / 3.85 / 0.66 个百分点；30B-A3B 为 50.32 / 43.42 / 10.03。Search、Claw-Eval、Automation 分别单独训练 300、300、200 步；每个训练设置一轮运行，选最佳 checkpoint 后做五次离线评估。Search 训练模型的 pass@1/3 由每题 32 个 rollout 估计，GAIA/HLE 使用文本子集。

消融与分析结论

Table3 固定其他设置、单独改变 β：4B Search 的 β=0 为 41.80/34.20/7.88，β=1 为 48.08/39.47/9.92，β=1.5 回落到 46.23/38.26/8.93，支持适量局部细化。Table1 保留 MAE 但换成 token IS 时为 45.72/36.35/8.89，说明完整 turn 权重另有贡献。Table2 中跨轮 λ=0.80、轮内 λintra=0.95 最好，单纯拉长信用传播并不总有利；各消融仅一次训练。

MPO 的变化落在信用与概率分布的尺度对齐。对环境只在完整调用后变化的任务，轮级传播加去均值 token 修正值得复现；仍需检查自身 critic 的结构，并用多种子和固定选择规则验证小幅收益。

  3. 联合策略训练移除视频模型，保留直接预测头；动作流匹配、视觉语言响应监督和直接预测共同训练。进入物理模块的中间层特征停止梯度，动作损失通过最终层路径更新 VLM。推理时去掉所有预测头，把最终层特征、物理 token、本体状态输入约 150M 的 DiT 动作专家，从高斯噪声做四步 Euler 积分，输出八步动作 chunk，执行后再观察与重规划。

世界模型综述；状态一致性；理解生成协同；评估证据

背景与前作缺口

视频既是世界的部分观察，也是模型预测未来的输出。片段看起来流畅，不代表被遮挡的物体仍存在、相机回到原处时布局一致，或改变动作后结果符合因果关系。

视频理解、生成、统一模型和交互世界模型各有技术与评测，容易把共同使用视频误当成能力相同。综述的目标是区分“做什么操作”和“证据支持到哪一级”，避免只凭视觉质量宣布学会世界规律。

解决思路

把视频看作潜在世界的有损、局部时间投影，以 Reading、Writing、Sharing、Interacting 四种互补操作组织文献；再区分轨迹的时间连贯与其背后世界状态的持续一致。四操作不是逐级成熟度，也不要求一项模型全部具备。

从输入到输出

  1. Reading 从可见视频恢复语义、空间、时间、物理或因果属性，输出答案或状态估计；Writing 从文字、图像前缀、相机轨迹等条件生成未来视频。共享观察介质并不意味着两者使用同一表征。
  2. Sharing 专指理解与生成经参数、token、表示、接口或训练目标耦合；需要继续区分同一系统能做两件事、共享了组件，以及一个方向真正帮助另一个方向。它不是跨主体传知识的同义词。
  3. Interacting 在新动作与新观察到来后预测并更新状态。综述沿观察空间/潜状态、被动预测/给定动作预测/交互闭环整理模型；训练对象可能是未来像素也可能是特征，评估要对应动作可控性、长程记忆与决策用途。本文本身不训练新网络。

主结果与比较条件

本篇产出是跨任务、表征、模型与评测的分类和证据框架，不报告新模型获胜。§3/Table2 将世界相关主张分成四种证据强度：输出看似合理、忠于观察或条件、世界状态一致、带来决策效用。这使读者可以区分短视频质量、回访/遮挡测试，以及真实规划收益；某一层的分数不自动满足下一层。

消融与分析结论

这里适用的是分类与协议分析，不是组件消融。§7.4 与 §9.3 指出，理解和生成共存尚不能证明协同，应在相同数据、容量或预算下比较单向与共享版本，并检查另一方向何时有帮助。§8.2/§9 强调长回环、动作干预、物理与因果、随机未来覆盖、闭环延迟等缺口；只测帧感知质量会漏掉状态与决策失败。综述列出的代表基准并非穷尽清单，不能把汇总中的异协议分数作统一排名。

分类是分析工具，边界存在交叉，文献覆盖会随新工作变化。它提出评估要求而未建立同时度量全部属性的单一标准；引用的单篇结论仍需回到各自论文。

带条件总结

这篇综述适合作为阅读世界模型时的核查表：先问模型学什么转移，再问证据是画面、持续状态还是决策收益。对统一模型尤其要检查受控协同，而不能把共享架构本身当作互相帮助的证明。

RynnUnify

RynnUnify: Towards Unified Embodied Brain

HF 2026-10-26 · 首次提交 2026-10-23 · 解读 v1 · 论文原文 · PDF · HF 候选

问题签名　当前观察与任务 / 长程视频推演及机器人动作 / 预测缺乏状态延续 / 让理解、生成与行动共享表征
统一理解与生成；跨片段记忆；生成证据路由；世界动作模型

背景与前作缺口

整理玩具时，模型既要理解当前有几只玩具，还要判断下一只该放哪里，并记住已经放进包里的物体。单段视频看起来合理，不代表连续十几步仍能保持任务进度；把生成的视频交给问答模型，也未必产生可靠的新证据。

作者同时面对三个连接缺口：理解模型与视频生成器的表征割裂；跨片段滚动生成累积几何和历史误差；视觉预测怎样进入机器人控制。这里的目标是统一具身理解、长程视觉规划与动作学习，不能把全部贡献简化成一个视频生成模型或一套 RL 算法。

解决思路

RynnUnify 在 Cosmos3 基础上结合 8B 自回归 reasoner 与 8B rectified-flow generator。推理器先形成子任务与场景变化描述，生成器预测未来，再把预测状态送回下一步推理。跨片段场景记忆保存初始和历史视觉参照；另有 Agentic 与 WAM 两种扩展，分别学习何时使用生成证据，以及从生成隐藏特征产生动作。

从输入到输出

  1. 基础训练先更新 reasoner：输入图像/视频、指令和对话，监督 assistant 的答案、定位、子任务与视频提示 token。随后冻结 reasoner，训练 generator。视觉条件由初始帧、两张历史帧和最新端点组成四张独立编码的参考帧；连续生成还接入上一片段末尾的时间前缀，推理默认取最后13帧。输出是与子任务、预计场景变化及持续时间对应的未来视频。
  2. generator 的 flow-matching 损失只落在需要预测的视频位置，条件帧和场景记忆不计入目标。Self-forcing 包含条件图像降质、以缓存预测端点替换真值起点，以及同时替换历史与端点；当前片段的监督未来仍是真值。离线预测缓存由固定 checkpoint 一次生成，不随训练持续刷新。由此训练模型从不完美的自身历史继续预测，不能称为实时闭环环境反馈。
  3. Agentic 扩展增加一个由 reasoner 初始化的 8B 策略，冻结完整 RynnUnify。可路由问题每题采样4条直接回答 D 与4条生成辅助 G；原生多图问题用8条 D：G 先写预测指令和时长，观察生成视频，再答题。可路由题的奖励是格式有效性乘任务答案质量，原生多图题直接用其答案分数；BCPO 在每条分支内用 GSPO 优化请求和回答，同时在输出协议有效且至少一支有正反馈时，把两分支平均奖励差变成软路由目标。部署时根据原始问题与观察选择 D/G，不预先查看答案。
  4. WAM 先用子任务标注训练 reasoner，再冻结它并训练视频/原生动作 token，最后联合训练 generator 与独立 action head。输入任务、当前多视角观察和视觉历史，reasoner 产生子任务 latent；action head 跨注意力读取生成器中间视频特征，通过 flow matching 输出48×12动作块。推理复用这些特征，16步 Euler 采样后执行前16个动作；辅助相机位姿头只在训练提供几何约束，不把解码视频作为动作头的输入。

主结果与比较条件

Rynn-VP 包含200个第一视角场景，最多规划15步；Overall=0.50 PI+0.40 VR+0.10 VQ。Table4 的 RynnUnify 为54.80，高于统一模型 Cosmos 3 Nano 的45.05，但组合系统 GPT-5.6 Terra+MiniMax-H3 为65.71，因此“统一模型最佳”不等于所有系统最佳。Table3 的 Rynn-GEU 平均由直接回答44.0升到 Agentic 50.0。Table5 的 WAM 在 RoboCasa365 Composite-Seen/Unseen 为52.0/50.0，Seen 低于 Xiaomi 的57.1；作者重新评测的 Selected-20（20任务、每题10次）为51.5%，高于 CMA 的47.0%。Table6 在 Astribot S1 三任务、每题20次上的完整任务成功率平均46.7%，对照 π0.5 为25.0%、GR00T N1.7 为26.7%。

消融与分析结论

Table3 与§7.1.2提供了生成证据的独立失败分析：RynnUnify 的 Area 从35.9升至66.2、Mess 从8.5升至29.1，但 Position 38.5→36.0、Distance 52.9→51.8、Size 57.0→56.5，说明生成辅助并非逐项改善。其他 UMM 加 interleaved rollout 后，Rynn-GEU 的 BAGEL 11.9→10.8、RxBrain 31.4→28.6、Cosmos 37.3→33.5；这些是系统路径比较，且 Rynn 的 Agentic 增加了8B策略和RL训练，不能当作等算力的纯生成开关消融。Table4 的视觉质量 VQ 77.53 低于 Cosmos 的79.69，主要收益来自规划与视觉实现。已核对 v1 正文及附录，未见分别移除场景记忆、自强迫训练、持续时间预测的受控数值表；因此不把系统总增益分配给单个组件。

代价与适用边界

生成预测会扭曲细粒度几何，不能自动当作观测真值。RoboCasa 全量划分的基线来自已发表报告，Selected-20 才是作者统一重评；真实机器人只有三种任务。真实任务阶段成功率彼此独立计分，不能相乘还原完整任务成功率。长程视频规划分数与真实执行成功之间的关系仍待更广验证；交替生成成本也限制闭环控制。

带条件总结

RynnUnify 的可迁移思路是让历史状态进入预测条件，再让推理主动选择预测信息、动作头读取预测表征。对于长程具身任务，这条链值得研究；使用时要保留直接回答路径、检测几何退化，并分别评价规划、生成与实际执行，不能以一项平均分替代全部能力。

Rollback: Experience Backtracking in World Models for Policy Improvement

HF 2026-10-28 · 首次提交 2026-10-26 · 解读 v1 · 论文原文 · PDF · HF 候选

问题签名　真实轨迹 / 交互昂贵 / 反复从头 rollout 且中间决策缺对照 / 恢复同状态比较兄弟动作
世界模型；机器人策略；反事实树搜索；相对价值监督

背景与前作缺口

抽积木、投球或桌面冰壶都依赖精细接触和释放时机。真实试错贵，普通世界模型 rollout 又常重复相同前史；仅用轨迹最后的成败难以判断哪次动作值得替换。

需要在关键中间状态尝试替代动作，同时防止策略利用世界模型错误。单次模拟结果还可能受随机性影响，直接把一次成功当成高质量动作会引入标签噪声。

解决思路

保存可恢复的世界模型上下文，在同一起点分支搜索并聚合下游结果；把兄弟动作的相对质量蒸馏回策略，再用新真实轨迹持续校准世界模型。

从输入到输出

  1. 由真实或示范轨迹建立动作 chunk 边界的参考路径，GE-Sim2.0 同时预测三相机未来图像与机器人本体状态，构成下一动作可用的完整观察。在分支节点缓存模型上下文，回退后只生成不同的后续，不重做共同前史。
  2. 当前策略提出连续动作候选，MCTS 用已见成功率和探索项分配预算。对暂时落入不同价值档的兄弟子树追加访问，减少一两次随机 rollout 造成的判断。终局由按任务视频监督微调的 world judge 判成功，并将结果回传；没有额外学习中间价值 critic。
  3. 每个动作取其下游叶子的平均成功率，再相对最好兄弟归一化、离散为质量档；全同档的组被舍弃。以 π0.5 为策略，把档位写入条件，混合搜索样本、离线示范和真实轨迹做动作 flow matching。部署以最高档条件采样，搜索留在训练侧。
  4. 真实新转移进入回放集，世界模型 LoRA 学习动作条件的图像与本体状态预测，再用 DMD 恢复少步生成。搜索、策略学习、模型适应异步运行，每棵树固定其启动时版本。所谓 test-time physics grounding 指世界模型预训练后作为训练环境时继续适应，并非机器人每次部署现场求梯度。

主结果与比较条件

Table1 的真实 Genie-02 三任务成功率：Block Extraction 69.33%、Ball Tossing 40.00%、Tabletop Curling 64.44%；同 GE-Sim2 的 RISE 基线为 58.67%、28.89%、52.59%，平均 46.72%→57.93%。这说明训练内反事实搜索能够迁移到无在线搜索的物理执行；只覆盖三任务与一个机器人平台。

消融与分析结论

Table2 在相同策略初始化和计算预算下，Block Extraction 全方法 69.33%，冻结世界模型为 64.67%，把子树平均换成单 rollout 奖励监督为 59.33%；后者仍保留树搜索，因此支持聚合价值而非只归功于“用了 MCTS”。Table4 的冰壶共进化诊断中，RGB L1 全程均值 19.52→12.96；但评估轨迹也被共进化模型用于适应、冻结模型没见过，衡量的是访问分布上的拟合改善，不是未见数据泛化。另 40 个失败积木回放无奖励假阳性，只能约束这 40 个样本。

代价与适用边界

学习模拟器仍会积累误差，短分支的相对比较不是对真实反事实的因果保证。奖励模型也由任务标签训练；对未见接触、长动作链和新硬件需要继续校准。异步生成与学习的基础设施成本不可忽略。

带条件总结

Rollback 的可迁移单位是“同一恢复上下文中的兄弟动作比较”。能可靠恢复状态、预测动作影响、验证结局时，树结构能把终局回报转成细粒度动作训练数据；世界模型偏差大时，更多搜索反而可能更执着地选择错误。

L3G-World: Real-Time Infinite World Generation with Latent 3D Gaussian Memory

HF 2026-10-30 · 首次提交 2026-10-29 · 解读 v1 · 论文原文 · PDF · HF 候选

问题签名　单图与相机轨迹 / 生成可回访场景 / 密集记忆增长且重编码昂贵 / 选择性三维高斯潜记忆
世界模型；三维记忆；潜空间条件；长程一致性

背景与前作缺口

相机在生成的世界里转一圈再回到原处，房间和物体应仍然在那里。只保留短视频上下文容易遗忘；为每帧不断追加点云或高斯，又会让存储和渲染随时间增加。

显式记忆既要保存旧场景，又要快速读写。若先把记忆渲染成 RGB、再编码成视频潜变量，还会为每次生成重复付出 VAE 开销。本文直接围绕这两个系统瓶颈设计记忆。

解决思路

旧区域就地修正，新区域才添加高斯；每个高斯同时存储能直接渲染的视频 VAE 特征。记忆更新器和视频生成器按 chunk 交替工作。

从输入到输出

  1. 输入当前视频窗口、相机和 VAE 潜变量。将旧记忆渲染到当前相机，用低不透明度或较大 RGB 残差形成新增掩码；只在这些位置对几何特征做 K-means，得到少量新高斯查询，同时检索可见旧高斯的修正 token。
  2. Transformer 联合处理新建与修正流，预测新高斯及旧高斯残差；独立 lifting 分支把对齐的 VAE 特征写入高斯。训练跨连续窗口、对旧记忆停止梯度，并监督历史视角的 RGB、感知、深度、潜变量和可见性。
  3. 生成时按目标相机直接渲染潜变量与不透明度，和噪声目标潜变量拼接，固定历史参考、仅去噪新 chunk。Cosmos-Predict2.5 的 LoRA 教师以流匹配训练，少步学生再经自身轨迹蒸馏；生成结果写回记忆，开始下一轮。

Table3 在 DL3DV、batch2 的新视角重建中，去自适应新增使高斯从 41K 增至 75K，PSNR 16.52→16.26；去修正降至 15.52。去 VAE lifting 改成 RGB 再编码，潜空间渲染 943.6→2.97 FPS。Table4 独立生成消融中，去记忆修正使自一致 LPIPS 0.435→0.464、FID 48.09→50.63；这一表的全模型基线并非 Table2 的同一数值，不能混用。

所测是室内外视频数据和相机回环，不能据此保证任意长时间、动态物体或接触物理一致。RealEstate10K 上相机误差与三维一致性并非全部最佳；少步版还存在质量损失。

L3G-World 表明，世界记忆的更新粒度与存储空间同样重要。对需要回访的场景生成，选择性修正和直接潜空间渲染有明确证据；标题里的无限世界应理解为可持续扩展框架，而非已证明的无限稳定性。

Soft-MTP

Multi-Token Prediction Done Right

HF 2026-10-30 · 首次提交 2026-10-28 · 解读 v1 · 论文原文 · PDF · HF 候选

问题签名　语言预训练 / 多步草稿 / 硬目标残差干扰主干 / 回收已有 KL 梯度
LLM 基础；多 token 预测；梯度路由；自蒸馏

背景与前作缺口

多 token 预测让语言模型同时学习后面几个词，训练出的预测头还可作为自投机解码草稿器。草稿应接近自身主模型的分布，但传统训练使用单一真实 token 的硬标签。

硬标签梯度既含有靠近主模型的自蒸馏项，也包含主模型对硬标签的残差。后者噪声大，并可能干扰正常下一词预测；显式计算全词表 KL 又增加显存并破坏融合交叉熵的效率。

解决思路

利用多个预测头共享同一线性输出矩阵这一条件，从已有交叉熵梯度中准确减去残差。主干与 MTP 头得到 KL 信号，输出矩阵仍保留硬标签监督。

从输入到输出

  1. 训练序列经主干产生下一词隐状态，并由三个 MTP 头预测更远位置。先把每个 MTP 分布与预测同一目标位置的 NTP 分布对齐；共享输出头下，硬梯度分解为两分布差的 KL 梯度与 NTP 对标签的残差。
  2. 在 NTP 隐状态加数值上为零的 stop-gradient 路由项。前向输出不变，反向却向对齐的 MTP 表示注入负残差；加上普通 MTP 交叉熵后，上游只留下自蒸馏梯度，无需额外物化全词表 logits。
  3. 共享输出矩阵继续接收交叉熵梯度，普通 NTP 更新不变。推理可以丢弃 MTP 头正常生成，或用它们起草三个 token、由自身 NTP 头验证；改变训练梯度不会免除投机解码的验证步骤。

主结果与比较条件

167M–1.2B LLaMA 式模型在 FineWeb-Edu 约 31.5B token、K=3、相同 MTP 权重训练。Table3 的 1.2B 平均零样本准确率 57.31，对标准 MTP 56.80、NTP 56.75；167M 的改善仅 0.07 点。Table2 每域 256 个 512-token prompt、续写 512 token，自投机解码相对标准 MTP 的平均速度增益只有 1.4–1.5%，不能把相对 AR 的约 1.7 倍整体速度都归功于新方法。

消融与分析结论

Figure3 用 256 独立批次估计梯度信噪比，残差约低 4 倍却占主干 MTP 梯度约 80%。Figure5 在 332M、7.3B token 扫描权重与 K=3…8，Soft-MTP 的训练损失前沿持续占优。Table6 对照显式 KL：1.2B 输出映射有效秩 NTP 496、标准 MTP 131、KL 321、Soft 437；该梯度路由对照支持保留输出头交叉熵，但 KL 仍在数学微调上更好。

代价与适用边界

Table5 单 H200 中 Soft 与标准 MTP 都为 10.28 GFLOP/token、融合 CE 峰值 107GB，吞吐差小于 0.07%；这是相对 MTP 无额外开销，NTP 本身更省。实验最大 1.2B，前沿模型的长训练、数据与规模迁移仍需验证。

带条件总结

Soft-MTP 是一个定义清楚的训练梯度修改，保留投机解码收益的同时改善所测表示学习。它的速度增量温和、质量收益依规模变化，适合在已有 MTP 管线中做受控复现，而非宣传为整体生成速度突变。

RSIHub: A Composable Framework for Agent-Evolution Methods

HF 2026-10-26 · 首次提交 2026-10-23 · 解读 v1 · 论文原文 · PDF · HF 候选

问题签名　自改进实验 / 可编辑工作流 / 算法与执行设施混杂 / 固定评估协议并记录候选来源
Agent 实验基础设施；评估边界；谱系与恢复

背景与前作缺口

Agent 演化会改提示、工具、技能或调度代码。如果各算法各自实现运行器与评估器，分数差异可能来自基础设施，甚至来自验证数据污染。旧稿纳入了此文，因此在此保留核验结果；其核心是实验系统，不计入七方向正式论文。

需要让方法自由改变候选，同时确保评估器、数据分割和已认证结果不被候选反向改写，并能在中断后恢复、追溯冠军来源。

解决思路

将方法策略放进 recipe/operator，将执行、受保护评估、快照、收据、谱系和恢复放在固定框架层。该工作没有提出通用基座模型的训练改动，也不应只因使用执行反馈就标为 RL。

从输入到输出

  1. 研究者提供种子 Agent、可修改范围、固定 evaluator 和 train/gate/sealed 分割。每代选父候选、运行以取得允许反馈、分析并改写候选；框架检查修改范围及可选验证，通过后形成干净 Git commit。
  2. 冻结评估器评估已提交候选，先认证评估条件、任务、输出和运行时指纹，再由 Gate 决定是否晋级；recipe 可以决定策略，但不能篡改认证结果。sealed 数据不用于 mutation 反馈，日志与收据使中断后的恢复有据可查。
  3. AHE、Hyperagents、A-Evolve、GEPA 各作为接口适配运行，两种种子 Agent 都使用固定模型配置。本文报告固定 recipe、每代一子候选、最多十代；外层 Agent 自动改 recipe 的路径只是框架能力，未被这组效果实验验证。

这是系统协议诊断。Table2 保持种子不变，比较直接执行与框架 generation-zero，三次重复中 Codex/TerminalBench2 的跨模式 excess disagreement 为 +6.0 点，不能宣称完全等价。Table3 在两个任务活动中做七类、每类 30 次故障/边界测试，420 次均达到预设恢复或拒绝条件；这验证有限系统边界，不证明能封锁任意恶意代码。

代价与适用边界
